Teaching notes and corrections for Java
Key ideas true for all four languages
  • The CPU understands only native machine code for its own instruction set (for example x86-64 or ARM64). Bytecode and IL are never executed by the CPU directly. A virtual machine or engine (itself native code) executes them or converts them to machine code.
  • Bytecode is not one universal format. Java bytecode, Python bytecode, V8 bytecode and .NET CIL are completely different and work only with their own runtime.
  • JVM is only for Java (and other JVM languages such as Kotlin and Scala). Python uses the PVM inside CPython, JavaScript uses an engine such as V8, and C# uses the CLR.
  • A program never draws text on the screen by itself. It asks the operating system through a system call to write bytes to standard output. The terminal, the font renderer and the graphics hardware turn those bytes into pixels.
  • Output is not "translated into human language" by the virtual machine. Text is always stored as numbers (a character encoding such as UTF-8, where S = 83). A font gives each number a visible shape, called a glyph.
  • "Compiled" and "interpreted" describe an implementation, not a language. Modern runtimes mix both: compile to bytecode, interpret it, and JIT compile the busy parts.

Part A. The kitchen story: preparing Butter Chicken 🍛

Two chefs cook the same Butter Chicken with 5 ingredients. The interpreter style chef reads one recipe step, goes to the market for that one item, comes back and cooks it, then repeats. The compiler style chef first reads the whole recipe and writes a complete shopping list, makes one trip, and then cooks everything without stopping. Both chefs do one action per time tick, so the comparison is fair.

Precise facts to teach (corrections to common simplifications)
  • Simplified "A compiler converts the entire source code into bytecode, and an interpreter does the same line by line." More precise A compiler translates the whole program into a target language. That target can be machine code (C, C++, Go, Rust) or bytecode (Java, C#). An interpreter does not produce a translated program. It reads and executes the code as it goes.
  • Most modern languages use both. Java: javac compiles to bytecode, then the JVM interprets it and JIT compiles hot methods. Python: CPython compiles the whole file to bytecode, then the PVM interprets that bytecode. JavaScript: V8 compiles to bytecode, interprets it, and JIT compiles hot code. C#: Roslyn compiles to IL, then the CLR JIT compiles it to machine code.
  • Common myth "Python runs the source file line by line." Fact CPython compiles the whole file to bytecode first. That is why a SyntaxError anywhere in the file stops the program before line 1 runs. Errors such as NameError or ZeroDivisionError appear only when the bad line executes, which matches the interpreter behaviour shown in Part B.
  • "Line by line" is a teaching simplification. Real interpreters work statement by statement or bytecode instruction by instruction.
  • A JIT (Just In Time) compiler sits between the two. It compiles code to machine code while the program is running, usually only for code that runs often.
  • "Compiled language" and "interpreted language" are informal labels. The same language can have both: for example PyPy runs Python with a JIT, and there are C interpreters too.
