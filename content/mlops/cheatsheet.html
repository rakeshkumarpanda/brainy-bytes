1.1

Set up your computer for machine learning

Open chapter

Python, virtual environments, Git, VS Code, Docker and GPUs set up on macOS, Windows, Linux and ChromeOS.

Key ideas

  • The toolbox Python 3.12 or newer, terminal, .venv per project, pip or uv, Git, VS Code, later Docker and a GPU or Colab.
  • PATH The first match in PATH runs. activate puts .venv first. python -m pip keeps pip and python together.
  • Per system macOS and Linux: python3, .venv/bin. Windows: python or py, .venv\Scripts, execution policy. ChromeOS: Linux container, Debian steps.
  • Reproducible pip freeze > requirements.txt, pip install -r requirements.txt. Commit requirements, ignore .venv. Never sudo pip.
  • Docker Desktop on macOS and Windows (WSL 2), Engine on Linux, docker group, docker run hello-world.
  • GPU NVIDIA: driver, nvidia-smi, CUDA build of PyTorch. Apple silicon: MPS. Chromebook: Colab or Kaggle.

The MLOps lifecycle and reproducible projects

Open chapter

The MLOps loop and maturity levels, seeds and run records, data and model versioning, and project layout.

Key ideas

  • MLOps Version, test, deploy, monitor and retrain ML. DevOps plus data and models.
  • Levels 0 manual, 1 automated training pipeline (continuous training), 2 CI/CD for the pipeline.
  • Reproducible Fix seeds, report spread over seeds, save run records: data fingerprint, params, metrics, versions.
  • Versions Code in Git, data by hash (DVC), models in a registry, environment in requirements or images. Lineage.
  • Tests Data, features, model quality and behaviour, infrastructure. Notebooks to tested functions.
  • Why it matters Models decay as data changes. Hidden technical debt lives outside the model code.

    The first block changes every time you run it, which is the point. With the seed fixed at 42, five runs give exactly the same accuracy, 0.972, five times. Pipelines and saving models

Open chapter

Leak free scikit-learn pipelines, saving with joblib and metadata, file formats, and input contracts.

Key ideas

  • Pipeline Preprocessing plus model in one object. ColumnTransformer: numbers impute and scale, categories one hot.
  • fit and transform Steps learn on training rows only, reuse at predict. handle_unknown='ignore' for unseen categories.
  • Leakage No step may see test rows. Selection outside CV: 0.85 on noise, inside: 0.48. Split by time and group too.
  • Saving joblib.dump the whole pipeline plus JSON metadata (features, classes, versions). Load trusted files only.
  • Formats joblib for own Python services, skops for safe sharing, ONNX for other languages.
  • Input contract Check presence, type, range, unknown categories, extra fields. Reject with 422.

Tips and traps

  • In the exam
    The churn pipeline reaches a 5 fold ROC AUC of 0.751 and a test accuracy of 0.69. After preprocessing, 5 raw columns have become 9 (3 scaled numbers and 6 one hot columns, with names such as cat__plan_basic). A new customer with a missing bill and a plan called student, which the model never saw, still gets a churn probability of 0.782 instead of an error.Lesson: One pipeline from raw columns to prediction
  • In the exam
    On 100 rows of random noise with random labels, choosing the 20 best of 5000 columns before cross validation reports an accuracy of 0.85. Doing the same selection inside the pipeline reports 0.48, the honest answer for labels that are pure chance.Lesson: Leakage: why every learning step belongs inside the pipeline
  • In the exam
    The fitted iris pipeline takes about 1.5 KB on disk. After loading, its predictions match the original on every row, and the flower [5.9, 3.0, 5.1, 1.8] is predicted as virginica. The JSON file records scikit-learn 1.8.0, which the serving side should match.Lesson: Saving and loading a trained pipeline
  • Remember
    The first request passes. The second is rejected because tenure is −3 and the bill was sent as text. The third has four problems: a missing bill, 2.5 support calls where a whole number is required, an unknown plan, and an unexpected coupon field.Lesson: An input contract for the model

Serving models with Flask, FastAPI and Django

Open chapter

Model APIs in Flask, FastAPI and Django, calling them on each OS, online against batch, and production servers sized with Little's law.

Key ideas

  • Model API Load once. /health plus POST /predict. JSON in and out. 200 success, 422 bad content, 405 wrong method, 500 is a bug.
  • Frameworks Flask small. FastAPI checks Pydantic classes, docs at /docs. Django for a model inside a full web app.
  • Test then call Test client in one process. Then curl (macOS, Linux, ChromeOS) or Invoke-RestMethod and curl.exe (Windows).
  • Online or batch Online answers during the visit. Batch scores on a schedule, cheaper, less fresh. Read big files in chunks.
  • Production servers Gunicorn on macOS and Linux, Waitress on Windows, Uvicorn for FastAPI everywhere. Several workers. Never app.run in production.
  • Capacity L = λW. Workers = λ × latency / target use. M/M/1: W = 1/(μ − λ) explodes near capacity.

Formulas

LatencyExam favourite
time from request sent to response received
Report the median and the 95th or 99th percentile, not only the average.

requests per second = 1000 / latency in ms
A worker that needs 20 ms serves at most 50 requests per second.

Little’s lawExam favourite
L = λ × W
L requests in progress, λ arrivals per second, W seconds each request spends in the system.
Lesson: From the development server to production
Workers neededExam favourite
workers = λ × latency / target use
Aim for about 70 to 80 percent use so short bursts do not build a queue.
Lesson: From the development server to production
Waiting time for one worker (M/M/1 queue)
W = 1 / (μ − λ)
μ requests per second the worker can serve. W shoots up as λ nears μ.

Tips and traps

  • Remember
    The test client sends real requests to the app inside one Python process, so no port or network is needed. The good request gets 200 with virginica at 0.703. The broken one gets 422 and an error that tells the caller what to send. The model never sees bad data.Lesson: A model behind a web API
  • In the exam
    One bad request produced three precise errors at once: sepal_length must be greater than 0, sepal_width is not a number, and petal_width is missing. The batch route scored two flowers in a single predict_proba call, virginica at 0.703 and setosa at 0.981.Lesson: FastAPI: the input contract written as a class
  • Common mistake
    Django gives the same answers as Flask (200 with virginica at 0.703, 422 for bad JSON), and @require_POST turns a GET into 405 without running the view. In a real project the view lives in an app inside django-admin startproject, and the settings come from environment variables, never a SECRET_KEY written in the code.Lesson: Django: when the model joins a full web application
  • Remember
    20,000 rows are scored in 4 chunks of 5,000. The last line times both styles on your own device, so the numbers change from run to run, but one call per row is always many times slower because each call pays the same fixed overhead.Lesson: Online against batch prediction
  • In the exam
    A queue does not grow in a straight line. One worker that can serve 50 requests per second answers in 25 ms at 10 per second, 100 ms at 40 per second, and 1 full second at 49 per second. That is why services keep spare capacity.Lesson: From the development server to production
