Lesson 1 of 9

What you need and why

Source: The Python Packaging User Guide, the Python documentation on venv, and the setup guides of Git, Visual Studio Code and Docker.

What it is
A machine learning setup has six parts: Python itself, a terminal to type commands, a virtual environment per project, a package installer (pip or uv), Git to track versions, and an editor such as VS Code. For serving and deployment you add Docker, and for big models a GPU or a cloud notebook.
Why we need it
Every later chapter of this subject runs these tools. The same steps also mean that a model behaves the same on your laptop, a teammate’s laptop and a server, which is the first promise of MLOps.
How it works
Install Python, open a terminal, create one virtual environment for each project, install packages into it, and save the exact versions in requirements.txt. Then add Git, an editor and Docker. The lessons below give the steps for macOS, Windows, Linux and ChromeOS. Open only the panel for your system.

Lesson 2 of 9

Install Python and open a terminal

Source: Python documentation: Using Python on Windows, Using Python on macOS, and Using Python on Unix platforms, plus PEP 668 and Google’s help page Set up Linux on your Chromebook.

What it is
A terminal (also called a shell or command line) is a text window for running programs. Python is installed once per computer, and you can have several versions side by side. The PATH setting lists the folders the terminal searches when you type a command.
Why we need it
Most problems beginners hit are not about ML at all: the wrong Python runs, or the terminal cannot find it. Knowing where Python is installed and how PATH works saves hours.
How it works
Pick your system below and follow the steps. Finish with python3 --version (or python --version on Windows) and check that it says 3.12 or newer.
Install Python 3.14
macOS
  1. Open Terminal (press Command and Space, type Terminal, press Return).
  2. Install Apple’s command line tools. They include Git and the compilers some packages need. A window asks you to confirm.
  3. Install Python 3.14 with the official installer from python.org/downloads (a .pkg file that works on Apple silicon and Intel), or with Homebrew if you use it.
  4. On macOS the command is python3. A plain python usually does not exist until you activate a virtual environment.
Terminal (macOS)shell
xcode-select --install

# optional, with Homebrew (brew.sh) instead of the python.org installer
brew install python@3.14

python3 --version          # Python 3.14.x
uname -m                   # arm64 = Apple silicon, x86_64 = Intel
Windows 10 and 11
  1. Open PowerShell (press the Windows key, type PowerShell, press Enter). Windows Terminal is a good home for it.
  2. Install Python 3.14 from python.org/downloads, or with winget, which ships with Windows 10 and 11. In the python.org installer, tick Add python.exe to PATH.
  3. Close and reopen PowerShell so it sees the new PATH, then check the version. The py launcher also works and can pick between installed versions.
  4. If typing python opens the Microsoft Store, turn off the python.exe and python3.exe entries in Settings, Apps, Advanced app settings, App execution aliases.
PowerShell (Windows)shell
winget install Python.Python.3.14

python --version           # Python 3.14.x
py --list                  # every Python the launcher can find
Linux (Ubuntu, Debian, Fedora)
  1. Open a terminal (Ctrl, Alt and T on Ubuntu).
  2. Most distributions already have Python 3. Install the venv module, pip and Git from the package manager. Ubuntu 24.04 ships Python 3.12, which is new enough.
  3. Do not use sudo pip install. Debian, Ubuntu and Fedora mark the system Python as externally managed (PEP 668), and pip refuses to change it outside a virtual environment.
  4. For a newer Python than your distribution offers, install uv (next lesson) and run uv python install 3.14.
Terminal (Linux)shell
# Ubuntu and Debian
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git

# Fedora
sudo dnf install -y python3 python3-pip git

python3 --version
ChromeOS (Chromebook)
  1. Open Settings, choose About ChromeOS, then Developers, and turn on the Linux development environment. Give it at least 20 GB of disk if you can. A Terminal app appears.
  2. The Linux part is a Debian container, so every Linux command on this site works in it. Its Python may be older than 3.12, so install a newer one with uv.
  3. Files you want to use in Linux go in the Linux files folder of the Files app.
  4. School or work Chromebooks may have Linux turned off by the administrator. Then use Google Colab or Kaggle notebooks in the browser, and the in page Python of this site.
Terminal (ChromeOS Linux)shell
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git curl

curl -LsSf https://astral.sh/uv/install.sh | sh     # installs uv
uv python install 3.14
python3 --version
In the exam
Two names, one idea: macOS, Linux and ChromeOS call it python3, Windows calls it python or py. Inside an activated virtual environment, python works everywhere.
Lesson 3 of 9

Virtual environments and packages

Source: Python documentation, venv module, the Python Packaging User Guide, Installing packages using pip and virtual environments, and the uv documentation.

What it is
A virtual environment is a folder, usually called .venv, that holds its own copy of the Python program and its own site-packages folder for libraries. Activating it puts its folder at the front of PATH. pip installs packages from PyPI. uv is a newer, much faster tool that does the work of pip and venv and can also install Python itself. requirements.txt lists the exact versions.
Why we need it
Different projects need different versions: an old model may need NumPy 1.26 while a new one needs NumPy 2.4. One shared install can hold only one version, so installing one project breaks another. With an environment per project and pinned versions, anyone can rebuild the same set of packages, which is what makes results reproducible.
How it works
Create the environment inside the project folder, activate it every time you work on the project, install packages, and save them with pip freeze. Never commit the .venv folder to Git, commit requirements.txt instead.
Create a project environment
macOS

macOS, Linux and ChromeOS use the same commands. The environment folder is .venv and the activate script is in .venv/bin.

Terminal (macOS)shell
mkdir ml-project && cd ml-project
python3 -m venv .venv
source .venv/bin/activate      # the prompt now starts with (.venv)

python -m pip install --upgrade pip
pip install numpy pandas scikit-learn joblib
pip freeze > requirements.txt
deactivate                     # leave the environment
Windows 10 and 11

Windows keeps the scripts in .venv\Scripts. PowerShell blocks scripts by default, so allow local ones once for your account.

PowerShell (Windows)shell
mkdir ml-project; cd ml-project
py -3.14 -m venv .venv
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned   # once, answer Y
.venv\Scripts\Activate.ps1          # in Command Prompt: .venv\Scripts\activate.bat

python -m pip install --upgrade pip
pip install numpy pandas scikit-learn joblib
pip freeze > requirements.txt
deactivate
Linux (Ubuntu, Debian, Fedora)

The same as macOS. If python3 -m venv says ensurepip is not available, install the python3-venv package first.

Terminal (Linux)shell
mkdir ml-project && cd ml-project
python3 -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
pip install numpy pandas scikit-learn joblib
pip freeze > requirements.txt
ChromeOS (Chromebook)

Inside the Linux terminal the commands are the Debian ones. With uv you skip the separate pip step, and uv also installs the Python version you ask for.

Terminal (ChromeOS Linux)shell
mkdir ml-project && cd ml-project
uv venv --python 3.14          # creates .venv with Python 3.14
source .venv/bin/activate
uv pip install numpy pandas scikit-learn joblib
uv pip freeze > requirements.txt
Run this one on your own computer. It creates a real virtual environment and starts a second python program, which the browser version of Python cannot do. The output above comes from a real run with CPython when this page was built.

Lesson 4 of 9

Git, VS Code and Jupyter

Source: Pro Git, chapter 1.6 First time Git setup, and the Visual Studio Code documentation for Python and Jupyter.

What it is
Git records every change to your code so you can go back, branch and work with others. VS Code is a free editor with a Python extension (running, debugging, picking the environment) and a Jupyter extension for notebooks. Jupyter notebooks mix code, output and notes, which suits exploring data.
Why we need it
MLOps starts with version control: the training code, the configs and the requirements must all be in Git so a model can be traced back to the exact code that made it. Notebooks are great for exploring, and scripts in Git are better for anything that must run again.
How it works
Install Git and VS Code, set your name and email once, install the Python and Jupyter extensions, and choose your .venv as the interpreter (VS Code asks, or use the command Python: Select Interpreter). Add .venv to .gitignore.
Install Git and VS Code
macOS
Terminal (macOS)shell
git --version                                  # came with xcode-select
brew install --cask visual-studio-code         # or download from code.visualstudio.com
Windows 10 and 11
PowerShell (Windows)shell
winget install Git.Git
winget install Microsoft.VisualStudioCode
# close and reopen PowerShell, then
git --version
Linux (Ubuntu, Debian, Fedora)
Terminal (Linux)shell
git --version                                  # installed with the python packages above
sudo snap install code --classic               # Ubuntu, or the .deb or .rpm from code.visualstudio.com
ChromeOS (Chromebook)

Download the .deb build of VS Code for your Chromebook’s processor (x64 for Intel and AMD, Arm64 for Arm) into Linux files, then install it. It appears in the launcher under Linux apps.

Terminal (ChromeOS Linux)shell
git --version
sudo apt install -y ./code_*.deb
Every system, inside the project foldershell
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git init
echo ".venv/" >> .gitignore
pip install jupyterlab ipykernel     # notebooks inside the project environment
jupyter lab

Lesson 5 of 9

Docker on each system

Source: Docker documentation: Install Docker Desktop on Mac, Install Docker Desktop on Windows, Install Docker Engine (convenience script), and Microsoft Learn, How to install Linux on Windows with WSL.

What it is
Docker packages an app with its Python, libraries and files into an image, and runs it as a container, which behaves the same on any computer with Docker. Docker Desktop is the app for macOS and Windows. Linux runs Docker Engine directly.
Why we need it
A model that works on your laptop often fails on a server because of a different Python, library or system package. A container fixes that by shipping the whole environment. Chapter 2.3 of this subject builds a container for a model API.
How it works
Install Docker for your system as below, start it, and run the hello-world container to check. Containers are Linux programs, so macOS and Windows run them inside a small Linux virtual machine, and on Windows that is WSL 2.
Install Docker
macOS

Install Docker Desktop for Mac, choosing the Apple silicon or Intel download, and start it once from Applications. It runs a small Linux virtual machine for the containers.

Terminal (macOS)shell
brew install --cask docker     # or the download from docker.com
docker run hello-world
Windows 10 and 11

Docker on Windows runs Linux containers inside WSL 2, the Windows Subsystem for Linux. Install WSL first (it needs a restart), then Docker Desktop, and keep the WSL 2 based engine option on.

PowerShell (Windows)shell
wsl --install                 # in PowerShell as administrator, then restart
winget install Docker.DockerDesktop
docker run hello-world
Linux (Ubuntu, Debian, Fedora)

On Linux you install Docker Engine directly, no virtual machine needed. Docker’s script adds its package repository and installs the engine. Adding yourself to the docker group lets you run docker without sudo after you log out and back in.

Terminal (Linux)shell
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER     # then log out and back in
docker run hello-world
ChromeOS (Chromebook)

Docker Engine can be installed in the Linux container with the same script as Debian. It needs disk space, so raise the Linux disk size in Settings if needed. On a managed Chromebook this may be blocked, and a cloud machine or GitHub Codespaces is the alternative.

Terminal (ChromeOS Linux)shell
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
docker run hello-world
Remember
If hello-world prints Hello from Docker!, the install works. Permission denied on /var/run/docker.sock on Linux means you have not logged out and back in since joining the docker group.
Lesson 6 of 9

GPUs, the cloud and common problems

Source: PyTorch Get Started (install selector), PyTorch documentation for the MPS backend, NVIDIA CUDA on WSL user guide, and the NVIDIA Container Toolkit install guide.

What it is
A GPU runs thousands of small calculations at once, which is what training neural networks needs. NVIDIA GPUs use CUDA, Apple silicon uses MPS, and cloud notebooks such as Google Colab and Kaggle lend you a GPU in the browser.
Why we need it
Classical ML from the Machine Learning subject (scikit-learn, gradient boosting) runs well on any CPU. Deep learning on images or text can be 10 to 50 times faster on a GPU, so it decides whether an experiment takes minutes or a whole day.
How it works
Start on the CPU. When a model is too slow, use your own GPU if you have one (steps below) or a free cloud GPU, and only then pay for cloud machines.
Use a GPU
macOS

Macs have no NVIDIA GPU, so CUDA is not available. On Apple silicon, PyTorch uses the built in GPU through MPS (Metal Performance Shaders): move tensors to torch.device("mps"). Check with torch.backends.mps.is_available().

Windows 10 and 11

With an NVIDIA card, install the newest NVIDIA driver, then pick the CUDA build on the PyTorch install page. nvidia-smi shows the card and driver. The same driver also gives CUDA inside WSL 2, so Linux tools work too.

PowerShell (Windows)shell
nvidia-smi
python -c "import torch; print(torch.cuda.is_available())"
Linux (Ubuntu, Debian, Fedora)

Install the NVIDIA driver from your distribution (on Ubuntu: sudo ubuntu-drivers install), restart, and check with nvidia-smi. For GPUs inside Docker, add the NVIDIA Container Toolkit and run containers with --gpus all.

Terminal (Linux)shell
sudo ubuntu-drivers install
nvidia-smi
docker run --rm --gpus all ubuntu nvidia-smi    # after the NVIDIA Container Toolkit
ChromeOS (Chromebook)

Chromebooks have no GPU access for machine learning in the Linux container. Train on the CPU for small models, and use Google Colab or Kaggle, which give free GPU time in the browser, for anything larger.

Lesson 8 of 9

From beginner to expert

One idea, four depths

Install Python, open a terminal, make a folder for your project, and give it its own environment so its packages do not mix with others.

Use pip or uv with requirements.txt, Git with a .gitignore, VS Code with the right interpreter, and Docker for a first container, on your own system.

Pin versions with lock files, set up the same environment in CI and in containers, use GPUs locally and in the cloud, and fix PATH, permission and driver problems quickly.

Design reproducible environments for a team: base images, dev containers, hermetic builds, GPU drivers in clusters, and software supply chain checks for packages.

Lesson 9 of 9

Chapter summary

  1. An ML workstation needs Python 3.12 or newer, a terminal, a virtual environment per project, pip or uv, Git, an editor, and later Docker and a GPU or cloud notebook.
  2. The terminal runs the first match it finds in PATH. Activating .venv puts its folder first, so python and pip mean the project’s own copies.
  3. macOS and Linux use python3 and .venv/bin. Windows uses python or py and .venv\Scripts. ChromeOS runs a Debian container where the Linux steps apply.
  4. Save exact versions with pip freeze > requirements.txt and rebuild with pip install -r requirements.txt. Commit requirements.txt, never .venv.
  5. Docker Desktop runs containers on macOS and Windows (through WSL 2), Docker Engine runs them natively on Linux, and hello-world checks the install.
