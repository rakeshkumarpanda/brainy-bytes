The whole subject in one loop

What it is
Revision here means seeing each chapter as one stage of a model’s life, and knowing the one idea, the one number and the one trap that go with it.
Why we need it
Exams and interviews rarely ask about one chapter alone. They describe a situation, such as a model that got worse, and expect you to pick the right tool from several chapters in the right order.
How it works
Walk the loop chapter by chapter, then follow the incident path. For each stage, say the idea out loud, recall the number, and name the trap in the table below.

1.2 LifecycleSeeds, run records, data fingerprintsReporting the best seed instead of the spread

Lesson 2 of 8

MLOps maturity levels

Source: Google Cloud, MLOps: continuous delivery and automation pipelines in machine learning.

What it is
A maturity level describes how much of the ML lifecycle runs automatically. At level 0 people move data and models by hand. At level 1 an automated pipeline retrains and delivers models (continuous training). At level 2 CI/CD also tests, builds and deploys the pipeline code itself.
Why we need it
It gives teams a shared way to say where they are and what to build next. Exams use it to test whether you know which tool solves which bottleneck.
How it works
Move from level 0 to 1 when models go stale between manual retrains. Move from 1 to 2 when many people change the pipeline code and releases of the pipeline itself become risky.
LevelWhat is automatedWhat starts a new modelTools from this subject
0 ManualOnly servingA person, often months apartNotebooks, a saved model file (2.1)
1 Pipeline automationData checks, training, validation, deliverySchedule, new data or a drift alertPipelines (2.1), tracking and registry (3.1), monitoring (3.2)
2 CI/CD automationAlso testing, building and deploying the pipelineAlso every code changeDocker and GitHub Actions (2.3), registry gates (3.1)
Remember
Level 2 is not always the goal. A small team with one model retrained monthly may be well served by level 1. Match the automation to how often the data and the code change.
Lesson 3 of 8

One release gate that uses every chapter

What it is
A release gate is the list of checks a new model must pass before it can replace the champion: feature parity, a quality gain on the same holdout, fairness limits, drift of its scores and practical limits such as file size.
Why we need it
Each chapter adds a check. Putting them in one gate means no model reaches users without passing all of them, and the gate’s output is the evidence for the model card.
How it works
Run the gate in CI (MLOps 2.3) on every candidate, block promotion on any FAIL, and store the report with the registered version (MLOps 3.1).

In the exam
Challenger 1 has the higher AUC, 0.0498 above the champion, because it uses postcode and the past labels favoured group A. The gate blocks it: the equal opportunity gap is 0.227 and the disparate impact is 0.48. Challenger 2 drops postcode, still gains 0.0125 AUC, passes all six checks and is promoted. A higher score on biased labels is not a better model.

Capstone: the whole lifecycle on your computer

What it is
The capstone program runs the subject end to end in one file: data with a fingerprint, a leak free pipeline, a tracked run, a registered model with a champion alias, a validated API tested with FastAPI’s test client, a drift check and a model card.
Why we need it
Reading about each step is not the same as wiring them together. Running the capstone on your own computer, then changing it, is the best revision for a practical exam or a take home task.
How it works
Run it, read every file it writes, then try the changes listed under the panels: each one exercises a different chapter.
Run this one on your own computer. It writes a project folder with a model file, a run log and a model card that you will want to open and keep, and it needs FastAPI. The output above comes from a real run with CPython when this page was built.

The same ideas on cloud platforms

Source: Public product documentation of Google Cloud Vertex AI, Amazon SageMaker and Azure Machine Learning.

What it is
Cloud ML platforms offer managed versions of every tool in this subject. The names differ, but the ideas are the same ones you have practised with open source tools.
Why we need it
Cloud certifications, such as Google Cloud’s Professional Machine Learning Engineer, AWS’s Machine Learning Engineer Associate and Microsoft’s Azure Data Scientist Associate, ask you to pick the right managed service for a situation. Knowing the idea first makes the service names easy to learn.
How it works
Learn the idea with the open source tool, then map it to the service of the platform you use. Exam guides and service names change, so always read the current official exam guide before you book.

Lesson 6 of 8

Interview questions with model answers

Five classic MLOps interview questions
  1. Your model was great offline and poor online. Why? Check training-serving skew first (feature parity test), then leakage in the offline evaluation (fitting on all rows), then a shift between the offline data and live traffic, and finally whether the offline metric matches the business goal.
  2. How do you know when to retrain? Monitor input PSI and the score distribution daily, accuracy when labels arrive, and the business metric. Retrain on a schedule for slow drift or on a trigger when performance drops past a limit, always through the tested pipeline and the registry gate.
  3. How do you release a new model safely? Shadow first, then a canary with guardrails on errors and latency, then an A/B test with a sample size fixed in advance, keeping the old version ready for a one step rollback.
  4. How do you make results reproducible? Pin package versions, fix seeds, fingerprint the data, track every run with code version and parameters, and build the serving image from the same requirements.
  5. A regulator asks why someone was refused. What do you show? The model card, the fairness audit by group, and the SHAP explanation of that decision with the background data used, plus the version and run that produced the model.
Real world scenario: A take home task in a hiring process

A company sends a CSV file and asks for a churn model served as an API, with tests and a short report, in one weekend. A strong answer is the capstone shape: a fingerprint of the data, one pipeline, a tracked run, a FastAPI service with an input contract and tests, a Dockerfile, a drift check, and a one page model card. Reviewers mostly read the tests and the report, so keep them clear.

Chapter summary

  1. Nine chapters form one loop: setup, lifecycle, pipelines, serving, Docker and CI/CD, tracking, monitoring, explainability and fairness, system design.
  2. Maturity: level 0 is manual, level 1 retrains through an automated pipeline, level 2 also tests and deploys the pipeline with CI/CD.
