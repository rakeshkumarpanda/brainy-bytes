Lesson 1 of 8

Which features does the model use?

Source: Breiman, Random forests (2001), Strobl and colleagues, Bias in random forest variable importance measures (2007), and scikit-learn, Permutation feature importance.

What it is
Global importance ranks the features by how much the whole model relies on them. Impurity importance (feature_importances_ in a tree model) adds up how much each feature reduced impurity in the training splits. Permutation importance shuffles one column of held out data and measures how much the score drops.
Why we need it
Teams, auditors and regulators ask what drives a model. Importance also finds bugs: a model that leans on an ID column or a leaked target is wrong, however good its score looks.
How it works
Prefer permutation importance on test data. Shuffle each feature several times, report the mean drop and its spread, and treat two strongly correlated features with care, because shuffling one leaves the other to carry the same information.
Download this program (.py)Save it, open it in any editor and run it with python3 importance.py.
In the exam
Impurity importance always adds up to 1 and gives worst radius 0.442. On test data, shuffling worst radius costs 0.170 accuracy, the real dependence. The random ID column, pure noise, still got 0.018 of the impurity credit because its many distinct values offer many split points on training data. Shuffling it changed the test score by −0.008, which is just noise.

Shapley values: why this one prediction?

Source: Shapley, A value for n-person games (1953), and Lundberg and Lee, A unified approach to interpreting model predictions (2017).

What it is
A Shapley value splits one prediction among the features. Start from the base value, the average prediction. Add the features one at a time and record what each adds. Average that over every order of adding them. SHAP is the family of fast methods that compute or estimate these values for real models.
Why we need it
A loan applicant who is refused is owed a reason, and a data scientist debugging one strange prediction needs to see which inputs pushed it. Shapley values are the only way of splitting a prediction that is fair in a precise sense: contributions add up exactly, identical features get equal credit and an unused feature gets zero.
How it works
For a few features, try every order, as the program does. For tree models use SHAP’s TreeExplainer, which is exact and fast. For any other model use a sampling explainer with a background set of a few hundred typical rows.
Download this program (.py)Save it, open it in any editor and run it with python3 shapley.py.
In the exam
The base value is 0.450, the average predicted chance of repaying. This applicant’s debt ratio of 0.82 pulls the prediction down by 0.194, the low income by 0.121 and the young age by 0.052, ending at 0.083. The three contributions add up exactly from 0.450 to 0.083, which is the efficiency property.
Shapley valueExam favourite
φj = ΣS ⊆ F ∖ j [ |S|! (|F| − |S| − 1)! / |F|! ] · [ v(S ∪ j) − v(S) ]
v(S) is the average prediction when only the features in S are known.
EfficiencyExam favourite
f(x) = φ0 + Σj φj
φ0 is the base value, the average prediction.
Cost of the exact sum
2|F| coalitions
3 features need 8, 20 features already need 1,048,576.
Going deeper: Explanations are not causes

A Shapley value says how the model used a feature, not what would happen in the world if the feature changed. With correlated features the credit is split in ways that depend on the background data. Report explanations together with the background you used, and never read them as advice such as “lower your age”. For actionable advice, counterfactual explanations search for the smallest change to changeable features that flips the decision.

Lesson 3 of 8

Is the model fair to every group?

Source: Hardt, Price and Srebro, Equality of opportunity in supervised learning (2016), US EEOC Uniform Guidelines on Employee Selection Procedures (1978), and Barocas, Hardt and Narayanan, Fairness and Machine Learning (2023).

What it is
A fairness audit computes the same rates separately for each group of people, such as sex, age band or ethnicity, and compares them. Demographic parity asks for equal approval rates. Equal opportunity asks for equal true positive rates: people who would repay are approved equally often in every group. Equalized odds also asks for equal false positive rates.
Why we need it
Leaving the group column out does not make a model fair. Other features such as postcode or income carry the same information, a proxy, and the model learns the old pattern from them. Lending, hiring and housing laws in many countries forbid unjustified differences between groups.
How it works
Keep the group labels aside for auditing, even when the model may not use them. Compute selection rate, TPR and FPR per group on test data, compare them with a chosen rule, and repeat the audit whenever the model or the data changes.
Download this program (.py)Save it, open it in any editor and run it with python3 fairness_audit.py.
In the exam
With one threshold of 0.5 group B is approved 33 percent of the time against 64 percent for group A, a disparate impact of 0.52, far below the four fifths rule of 0.8. Among people who did repay, B was approved 48 percent of the time and A 75 percent. Lowering B’s threshold to 0.38 closed the TPR gap, raised the ratio to 0.92 and cost only 0.010 accuracy (0.647 to 0.637).
Disparate impact ratioExam favourite
DI = P(ŷ = 1 | B) / P(ŷ = 1 | A)
The four fifths rule flags DI below 0.8.
Equal opportunity gapExam favourite
TPRA − TPRB, with TPR = P(ŷ = 1 | y = 1)
Zero means qualified people are treated alike.
Equalized odds
TPRA = TPRB and FPRA = FPRB
Both kinds of error are shared equally.

SHAP and Fairlearn on your own computer

Source: SHAP documentation (TreeExplainer, plots), and Fairlearn documentation (MetricFrame, ThresholdOptimizer).

What it is
SHAP is the standard Python library for Shapley explanations. Fairlearn computes metrics by group with MetricFrame and offers mitigation methods such as ThresholdOptimizer, which picks a threshold per group to meet a fairness rule.
Why we need it
Hand written loops teach the idea, but real projects need tested, fast tools whose numbers others can reproduce. Both libraries are open source and work with any scikit-learn model.
How it works
Install both packages, run the program, then add the plot lines to save a beeswarm chart (every row, every feature) and a waterfall chart (one row, from base value to prediction).
Run this one on your own computer. It needs the shap and fairlearn packages, which the browser version of Python cannot install. The output above comes from a real run with CPython when this page was built.

TreeExplainer works in log odds for this model, and for the first applicant 0.027 + 0.489 + 0.027 + 0.401 = 0.943, exactly the model’s own log odds. Postcode gets a small mean |SHAP| of 0.055, yet the audit still shows a TPR gap of 0.196 between groups, because income also differs between groups. ThresholdOptimizer cut the gap to 0.018 while overall accuracy went from 0.672 to 0.665.

Fixing unfairness, and why you cannot have every kind

Source: Chouldechova, Fair prediction with disparate impact (2017), and Kleinberg, Mullainathan and Raghavan, Inherent trade-offs in the fair determination of risk scores (2017).

Three places to mitigate bias
  1. Before training (pre processing): fix the data. Collect more examples of the smaller group, reweight rows, or remove proxies that carry no real signal.
  2. During training (in processing): add a fairness constraint or penalty to the loss, for example Fairlearn’s ExponentiatedGradient.
  3. After training (post processing): choose a threshold per group, as ThresholdOptimizer did. It needs the group at decision time, which some laws do not allow.
  4. Whatever you choose, measure accuracy and every fairness metric again on fresh test data, and record the decision and its reasons.
What it is
An impossibility result says that when the groups have different base rates (shares of real positives), no imperfect classifier can be calibrated and also have equal false positive and false negative rates in every group.
Why we need it
Fairness is a choice between definitions that conflict, not a box you tick. Teams must pick the definition that fits the harm in their setting, and say so openly.
How it works
Ask which error hurts people most. Refusing a good borrower points to equal opportunity. Wrongly flagging an innocent person points to equal false positive rates. Then document the choice in the model card.
Chouldechova’s identityExam favourite
FPR = [p / (1 − p)] · [(1 − PPV) / PPV] · (1 − FNR)
p is the base rate. With equal PPV and FNR, different p forces different FPR.

Model cards and responsible release

Source: Mitchell and colleagues, Model cards for model reporting (2019), Gebru and colleagues, Datasheets for datasets (2021), the EU AI Act (Regulation 2024/1689) and GDPR Article 22.

What it is
A model card is a short document shipped with every model version. It states what the model is for and not for, the training data, metrics overall and per group, fairness results, known limits and who to contact. A datasheet does the same for a dataset.
Why we need it
People who reuse a model rarely know how it was built. Regulators increasingly ask for this record: the EU AI Act lists credit scoring and hiring among high risk uses that need documentation and human oversight, and GDPR Article 22 gives people rights around decisions made only by automated means.
How it works
Generate the card from the tracking run and the audit, so the numbers cannot drift from the real model. Store it next to the model in the registry (MLOps 3.1) and make the promotion gate fail if the card or the fairness check is missing.
Model card sectionExample for the loan model
Intended useRank loan applications for human review. Not for automatic refusal.
Training data20,000 past applications, 2019 to 2024, one country
MetricsAccuracy 0.637 overall, reported per group
FairnessEqual opportunity gap 0.00 after group thresholds, disparate impact 0.92
ExplanationsSHAP top three reasons sent with every refusal
LimitsNot tested on self employed applicants. Retrain if PSI of income passes 0.25 (MLOps 3.2).
Remember
Explainability and fairness checks belong in the same CI pipeline as accuracy tests (MLOps 2.3). A gate such as “fail if disparate impact is below 0.8 or the TPR gap is above 0.05” stops an unfair model from being promoted, in the same way as a failing unit test.

Real world scenario: A refused applicant asks why

A bank’s model refuses a loan. The applicant asks for the reason. The team computes SHAP values for that one decision: debt ratio −0.194, income −0.121, age −0.052. They send the two main reasons, debt ratio and income, in plain words. Because age is a protected attribute in many lending laws, the quarterly audit also checks that approval rates by age band pass the four fifths rule.

Chapter summary

  1. Permutation importance on test data measures real dependence (worst radius 0.170). Impurity importance is computed on training data and still credited a random ID with 0.018.
  2. Shapley values split one prediction exactly: base 0.450, then −0.121, −0.194 and −0.052, ending at 0.083. TreeExplainer computes them exactly for trees.
  3. Dropping the group column does not remove bias, because proxies carry it. One threshold gave a disparate impact of 0.52 and a TPR gap of 0.28.
  4. A per group threshold closed the TPR gap for 0.010 accuracy. With different base rates, calibration and equal error rates cannot all hold.
  5. Install shap and fairlearn per OS, save plots with the Agg backend, and ship a model card with every version.
