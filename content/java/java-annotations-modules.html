Annotations, reflection and modules

Frameworks such as JUnit and Spring seem to call your code by magic. This chapter shows the real mechanism: annotations as labels, reflection to read them, and proxies to wrap objects. Then it covers the module system that protects code from misuse, jlink for small runtimes, module imports from Java 25, and the Java 26 warning about changing final fields.

Part 1

🏷️Annotations: labels the compiler and tools can read

An annotation is a label that starts with @. It does not change what your code does by itself. The compiler, build tools or frameworks read the label and act on it, like a "fragile" sticker on a parcel that tells the courier how to handle it.

@Override catches a misspelled method · ❌ Does not compile · ☕ JDK 25
class Main {
    static class Product {
        String name = "pen";
        @Override
        public String toString() { return "Product " + name; }

        @Override
        public boolean equal(Object o) { return o == this; }     // typo: equals is spelled wrong
    }

    public static void main(String[] args) {
        System.out.println(new Product());
    }
}
❌ Compile error
Line 7: method does not override or implement a method from a supertype

Without @Override that typo would compile and silently create a new method that nothing ever calls. With it, the compiler catches the mistake at once.

Deprecated, SuppressWarnings and FunctionalInterface · ▶ Runs · ☕ JDK 25
class Main {
    static class Payments {
        /** @deprecated use {@link #pay(String, long)} with the amount in paise */
        @Deprecated(since = "2.0", forRemoval = true)
        static void pay(String user, double rupees) { pay(user, Math.round(rupees * 100)); }

        static void pay(String user, long paise) { System.out.println(user + " paid " + paise + " paise"); }
    }

    @SuppressWarnings("removal")
    public static void main(String[] args) {
        Payments.pay("asha", 49.5);          // old call, warning silenced on purpose
        Payments.pay("ravi", 4950L);
        System.out.println("@FunctionalInterface on Runnable? " + Runnable.class.isAnnotationPresent(FunctionalInterface.class));
    }
}
Output

ravi paid 4950 paise

Part 2

🧪Writing your own annotation

You declare an annotation with @interface. Two meta annotations decide how it behaves. @Retention says how long it lives: only in the source (SOURCE), in the class file (CLASS, the default), or also at run time (RUNTIME). @Target says where it may be written, such as on methods, fields, classes or record components.

A tiny test runner built from a custom annotation · ▶ Runs · ☕ JDK 25
import java.lang.annotation.*;
import java.lang.reflect.*;

class Main {
    @Retention(RetentionPolicy.RUNTIME)      // keep it in the class file and visible to reflection
    @Target(ElementType.METHOD)              // only allowed on methods
    @interface Test {
        String name() default "";
        boolean skip() default false;
    }

    static class CartTests {
        @Test(name = "empty cart has total 0")
        void emptyCart() { check(0 == 0); }

        @Test
        void addItem() { check(2 + 2 == 4); }

        @Test(name = "discount above 100 percent", skip = true)
        void hugeDiscount() { check(false); }

        @Test(name = "tax is added")
        void tax() { check(100 * 1.18 == 118); }

        void helper() { }                       // no @Test, so the runner ignores it

        static void check(boolean ok) { if (!ok) throw new AssertionError("check failed"); }
    }

    public static void main(String[] args) throws Exception {
        CartTests suite = new CartTests();
        int pass = 0, fail = 0, skip = 0;
        Method[] methods = CartTests.class.getDeclaredMethods();
        java.util.Arrays.sort(methods, java.util.Comparator.comparing(Method::getName));
        for (Method m : methods) {
            Test t = m.getAnnotation(Test.class);
            if (t == null) continue;
            String name = t.name().isEmpty() ? m.getName() : t.name();
            if (t.skip()) { System.out.println("SKIP " + name); skip++; continue; }
            try {
                m.invoke(suite);
                System.out.println("PASS " + name); pass++;
            } catch (InvocationTargetException e) {
                System.out.println("FAIL " + name + ": " + e.getCause().getMessage()); fail++;
            }
        }
        System.out.println(pass + " passed, " + fail + " failed, " + skip + " skipped");
    }
}
Output
PASS addItem
PASS empty cart has total 0
SKIP discount above 100 percent
PASS tax is added
3 passed, 0 failed, 1 skipped
JUnit 5's @Test, @DisplayName and @Disabled work exactly like this, with many more features. So do Spring's @GetMapping and Jackson's @JsonProperty.
Part 3

🔍Reflection: looking at classes while the program runs

Reflection lets code examine and use classes it did not know about when it was compiled. Every loaded class has a Class object that lists its fields, methods, constructors and, for records, its components. Frameworks use it to create objects, fill fields from JSON and call methods by name.

Looking inside a class at run time · ▶ Runs · ☕ JDK 25
import java.lang.reflect.*;
import java.util.*;

class Main {
    record Order(String id, int qty, double price) {
        double total() { return qty * price; }
    }

    public static void main(String[] args) throws Exception {
        Class<?> c = Order.class;                          // or Class.forName("Main$Order")
        System.out.println("name: " + c.getSimpleName() + ", record? " + c.isRecord());

        for (RecordComponent rc : c.getRecordComponents()) {
            System.out.println("component " + rc.getName() + " : " + rc.getType().getSimpleName());
        }

        Order o = (Order) c.getDeclaredConstructor(String.class, int.class, double.class).newInstance("A-1", 3, 49.5);
        Method total = c.getDeclaredMethod("total");
        System.out.println("total() called by name: " + total.invoke(o));

        Field qty = c.getDeclaredField("qty");
        System.out.println("field qty is " + Modifier.toString(qty.getModifiers()));
    }
}
Output
name: Order, record? true
component id : String
component qty : int
component price : double
total() called by name: 148.5
field qty is private final

Reflection is powerful but has a cost. Calls are checked at run time instead of compile time, so a typo in a method name becomes a NoSuchMethodException, and the code is harder to read. Use it in libraries and tools, not in everyday business logic.

Since Java 9 the JDK protects its own internals. Reflection may not open private parts of a module that does not allow it.

Strong encapsulation: the JDK keeps its private parts private · 💥 Crashes at run time · ☕ JDK 25
import java.lang.reflect.Field;

class Main {
    public static void main(String[] args) throws Exception {
        Field value = String.class.getDeclaredField("value");
        System.out.println("found the private field: " + value.getName());
        value.setAccessible(true);            // java.base does not open java.lang to us
        System.out.println("never printed");
    }
}
Output before the crash
found the private field: value
💥 Runtime error
Exception in thread "main" java.lang.reflect.InaccessibleObjectException: Unable to make field private final byte[] java.lang.String.value accessible: module java.base does not "opens java.lang" to unnamed module @1dbd16a6

Changing a final field with reflection still works in your own code, but Java 26 started warning about it (JEP 500, "prepare to make final mean final"). A future release will block it unless you allow it with --enable-final-field-mutation. The JVM can then trust that final fields never change and optimise better.

Java 26 and 27 warn when reflection changes a final field (JEP 500) · 🖥️ Run in a terminal · ☕ JDK 27
📄 Main.java
import java.lang.reflect.Field;

class Main {
    static class Config {
        private final String env = new String("prod");
    }

    public static void main(String[] args) throws Exception {
        Config c = new Config();
        Field f = Config.class.getDeclaredField("env");
        f.setAccessible(true);
        f.set(c, "test");                     // changing a final field
        System.out.println("env is now " + f.get(c));
    }
}
Terminal
$ java Main
$ java --illegal-final-field-mutation=deny Main

Part 4

🪞Dynamic proxies: how mocks and frameworks wrap your objects

A dynamic proxy is an object the JVM creates at run time that implements one or more interfaces. Every call on it goes to one handler method, which can log, time, check permissions or forward the call. Spring uses proxies for @Transactional, and older mocking libraries used them for mocks.

A dynamic proxy that logs every call · ▶ Runs · ☕ JDK 25
import java.lang.reflect.*;
import java.util.*;

class Main {
    interface PaymentService {
        String pay(String user, int amount);
        int balance(String user);
    }

    static class RealPayments implements PaymentService {
        public String pay(String user, int amount) { return "paid " + amount + " for " + user; }
        public int balance(String user) { return 500; }
    }

    @SuppressWarnings("unchecked")
    static <T> T logged(T target, Class<T> type) {
        InvocationHandler h = (proxy, method, args) -> {
            System.out.println("-> " + method.getName() + Arrays.toString(args));
            Object result = method.invoke(target, args);
            System.out.println("<- " + result);
            return result;
        };
        return (T) Proxy.newProxyInstance(type.getClassLoader(), new Class<?>[] { type }, h);
    }

    public static void main(String[] args) {
        PaymentService svc = logged(new RealPayments(), PaymentService.class);
        svc.pay("asha", 120);
        svc.balance("asha");
        System.out.println("is a proxy: " + Proxy.isProxyClass(svc.getClass()));
    }
}
Output
-> pay[asha, 120]
<- paid 120 for asha
-> balance[asha]
<- 500
is a proxy: true
java.lang.reflect.Proxy only works with interfaces. Libraries such as Mockito and Spring generate subclasses with bytecode tools when they need to wrap plain classes, which is one reason the Class-File API (final in Java 24) was added to the JDK.
Part 5

📦The module system (Java 9)

Before Java 9, a public class in any JAR could be used by any other JAR. Big programs ended up depending on each other's internals. A module fixes this. It is a named group of packages with a module-info.java file that says which packages it exports and which modules it requires.

Two modules: a core library and an app · 🖥️ Run in a terminal · ☕ JDK 25
📄 src/com.shop.core/module-info.java
module com.shop.core {
    exports com.shop.core.api;      // other modules may use this package
    // com.shop.core.internal is not exported, so it stays private to this module
}
📄 src/com.shop.core/com/shop/core/api/Prices.java
package com.shop.core.api;

import com.shop.core.internal.TaxTable;

public class Prices {
    public static double withTax(double amount) {
        return amount + amount * TaxTable.rate();
    }
}
📄 src/com.shop.core/com/shop/core/internal/TaxTable.java
package com.shop.core.internal;

public class TaxTable {
    public static double rate() { return 0.18; }
}
📄 src/com.shop.app/module-info.java
module com.shop.app {
    requires com.shop.core;
}
📄 src/com.shop.app/com/shop/app/Main.java
package com.shop.app;

import com.shop.core.api.Prices;

public class Main {
    public static void main(String[] args) {
        System.out.println("100 with tax = " + Prices.withTax(100));
        System.out.println("running in module " + Main.class.getModule().getName());
    }
}

Part 6

📥Module import declarations (Java 25)

A long list of imports at the top of a file is noise, especially for beginners and small scripts. Java 25 made module import declarations final (JEP 511). import module java.sql; imports every public type from every package that the java.sql module exports, and from the modules it requires transitively. Compact source files, the ones with a bare void main(), import java.base this way automatically.

import module brings in a whole module at once · ▶ Runs · ☕ JDK 25
import module java.sql;            // Java 25: every exported package of java.sql, plus java.xml and java.logging

void main() throws Exception {
    // Connection, DriverManager and SQLException come from java.sql
    // List and Map come from java.base, which compact source files import automatically
    List<String> drivers = DriverManager.drivers().map(d -> d.getClass().getSimpleName()).toList();
    System.out.println("JDBC drivers on the classpath: " + drivers.size());
    Map<String, Class<?>> types = Map.of("Connection", Connection.class, "SQLException", SQLException.class);
    types.forEach((k, v) -> System.out.println(k + " lives in " + v.getPackageName()));
}
Output
JDBC drivers on the classpath: 0
Connection lives in java.sql
SQLException lives in java.sql

If two imported modules export a class with the same simple name, using that name is an error. The fix is one ordinary import, which always beats a module import.

Two modules export a class with the same name · ❌ Does not compile · ☕ JDK 25
import module java.sql;

void main() {
    Date today = new Date(0);       // java.util.Date or java.sql.Date?
    System.out.println(today);
}
❌ Compile error
Line 4: reference to Date is ambiguous
both class java.sql.Date in java.sql and class java.util.Date in java.util match
Line 4: reference to Date is ambiguous
both class java.sql.Date in java.sql and class java.util.Date in java.util match
A single type import settles it · ▶ Runs · ☕ JDK 25
import module java.sql;
import java.sql.Date;               // a single type import wins over module imports

void main() {
    Date day = Date.valueOf("2026-10-24");
    System.out.println(day + " is a " + day.getClass().getName());
}
Output
2026-10-24 is a java.sql.Date
Your code does not need to be a module to use import module. It works in ordinary classes on the classpath too.
Part 7

🎬Real world scenario: validating a sign up form

The situationA sign up API receives a name, an email and an age. Every endpoint repeats the same if statements to check them, and the rules drift apart.
A validator in 30 lines, the idea behind Bean Validation · ▶ Runs · ☕ JDK 25
import java.lang.annotation.*;
import java.lang.reflect.*;
import java.util.*;

class Main {
    @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.RECORD_COMPONENT) @interface NotBlank { }
    @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.RECORD_COMPONENT) @interface Range { int min(); int max(); }

    record SignUp(@NotBlank String name, @NotBlank String email, @Range(min = 13, max = 120) int age) { }

    static List<String> validate(Record r) throws Exception {
        List<String> errors = new ArrayList<>();
        for (RecordComponent rc : r.getClass().getRecordComponents()) {
            Object value = rc.getAccessor().invoke(r);
            if (rc.isAnnotationPresent(NotBlank.class) && (value == null || value.toString().isBlank())) {
                errors.add(rc.getName() + " must not be blank");
            }
            Range range = rc.getAnnotation(Range.class);
            if (range != null && ((int) value < range.min() || (int) value > range.max())) {
                errors.add(rc.getName() + " must be between " + range.min() + " and " + range.max());
            }
        }
        return errors;
    }

    public static void main(String[] args) throws Exception {
        System.out.println(validate(new SignUp("Asha", "asha@shop.test", 29)));
        System.out.println(validate(new SignUp(" ", "ravi@shop.test", 9)));
    }
}
Output
[]
[name must not be blank, age must be between 13 and 120]

The rules now live next to the data as annotations, and one generic method checks any record. This is the same idea as Jakarta Bean Validation (@NotBlank, @Min, @Max), which Spring runs automatically on request bodies.
