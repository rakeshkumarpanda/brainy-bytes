Serialization

Serialization turns a live Java object into a stream of bytes that can go to a file or across a network. Deserialization rebuilds the object from those bytes. One interface and two streams do the work, and a handful of rules decide what survives the trip.

Part 1

📦What serialization means

An object lives in memory. When the program ends, it is gone. Serialization is the process of writing an object's state as bytes, so it can be stored in a file or sent over a network. Deserialization is the reverse: reading those bytes and building an equal object again.

Serialization

Java object ➜ bytes. Done by ObjectOutputStream.writeObject.

Deserialization

bytes ➜ Java object. Done by ObjectInputStream.readObject.

A class opts in by implementing java.io.Serializable. This is a marker interface: it has no methods at all. It simply tells the JVM that saving objects of this class is allowed.

Only objects of classes that implement Serializable (directly or through a parent) can be serialized. Anything else throws NotSerializableException at run time.
Part 2

💾Writing and reading an object

Save a game, load it back · ▶ Runs
import java.io.*;
class Player implements Serializable {
    String name = "Asha";
    int level = 7;
}
class Main {
    public static void main(String[] args) throws Exception {
        Player p = new Player();
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("game.ser"))) {
            out.writeObject(p);                                  // serialization
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("game.ser"))) {
            Player q = (Player) in.readObject();                 // deserialization
            System.out.println(q.name + " is on level " + q.level);
            System.out.println("same object? " + (p == q));
        }
    }
}
Output
Asha is on level 7
same object? false

The loaded object has the same state, but it is a brand new object, so p == q is false.

readObject() returns Object, so a cast is needed. It also declares ClassNotFoundException, because the bytes name a class that must be found when the object is rebuilt.

Several objects in one file

Read them in the same order you wrote them · ▶ Runs
import java.io.*;
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("many.ser"))) {
            out.writeObject("hello");
            out.writeObject(42);
            out.writeObject(new int[]{1, 2, 3});
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("many.ser"))) {
            String s = (String) in.readObject();
            Integer n = (Integer) in.readObject();
            int[] a = (int[]) in.readObject();
            System.out.println(s + " " + n + " " + java.util.Arrays.toString(a));
        }
    }
}
Output
hello 42 [1, 2, 3]
String, the wrapper classes, arrays and the collection classes are all Serializable already. Objects come back in exactly the order they were written.
Part 3

🙈The transient keyword

Some fields should never be saved, such as a password or a value that only makes sense in this run. Mark them transient. The JVM skips them while serializing and gives them their default value (0, false or null) after deserialization.

The password does not travel · ▶ Runs
import java.io.*;
class Account implements Serializable {
    String user = "ravi";
    transient String password = "secret123";
    transient int loginCount = 5;
}
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("acc.ser"))) {
            out.writeObject(new Account());
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("acc.ser"))) {
            Account a = (Account) in.readObject();
            System.out.println(a.user + " " + a.password + " " + a.loginCount);
        }
    }
}
Output
ravi null 0

transient with static and final

Static variables belong to the class, not to the object, so they are never part of an object's serialized state. A final variable with a constant value is replaced by its value when the class compiles. In both cases transient changes nothing.

transient has no effect on static and final constants · ▶ Runs
import java.io.*;
class Box implements Serializable {
    int a = 10;
    transient int b = 20;
    transient static int c = 30;
    transient final int d = 40;
}
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("box.ser"))) {
            out.writeObject(new Box());
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("box.ser"))) {
            Box x = (Box) in.readObject();
            System.out.println(x.a + " " + x.b + " " + Box.c + " " + x.d);
        }
    }
}
Output
10 0 30 40
DeclarationValue after deserialization
int a = 1010 (saved and restored)
transient int b = 200 (skipped, default value)
transient static int c = 3030 (static, comes from the class)
transient final int d = 4040 (constant, compiled into the class)
The exam favourite: transient static and transient final both compile, and in both cases transient has no effect.
Part 4

🕸️Object graphs

When an object is serialized, every object it refers to is serialized too, and every object those refer to, and so on. This set of objects is called the object graph. Every object in the graph must be Serializable.

Three objects saved with one call · ▶ Runs
import java.io.*;
class Engine implements Serializable { int hp = 120; }
class Car implements Serializable { Engine engine = new Engine(); String model = "Hatch"; }
class Garage implements Serializable { Car car = new Car(); }
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("g.ser"))) {
            out.writeObject(new Garage());
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("g.ser"))) {
            Garage g = (Garage) in.readObject();
            System.out.println(g.car.model + " with " + g.car.engine.hp + " hp");
        }
    }
}
Output
Hatch with 120 hp
One member in the graph is not Serializable · 💥 Crashes at run time

            out.writeObject(new Car());
        }
    }

💥 Runtime error
Exception in thread "main" java.io.NotSerializableException: Engine

The same object reached twice is written only once. After loading, both references point to one shared object again, so the shape of the graph is kept.

Shared references stay shared · ▶ Runs
import java.io.*;
import java.util.*;
class Main {
    public static void main(String[] args) throws Exception {
        List<String> shared = new ArrayList<>(List.of("x"));
        List<List<String>> pair = List.of(shared, shared);
        ByteArrayOutputStream bytes = new ByteArrayOutputStream();
        try (ObjectOutputStream out = new ObjectOutputStream(bytes)) { out.writeObject(pair); }
        try (ObjectInputStream in = new ObjectInputStream(new ByteArrayInputStream(bytes.toByteArray()))) {
            @SuppressWarnings("unchecked")
            List<List<String>> back = (List<List<String>>) in.readObject();
            back.get(0).add("y");
            System.out.println(back.get(1) + " " + (back.get(0) == back.get(1)));
        }
    }
}
Output
[x, y] true
Part 5

🛠️Customised serialization

Marking a password transient loses it completely. If you want to save it in a protected form, add two private methods with these exact signatures. The JVM calls them automatically during serialization and deserialization.

The two callback methods
private void writeObject(ObjectOutputStream out) throws IOException
private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException
Save an encoded password · ▶ Runs
import java.io.*;
class Account implements Serializable {
    String user = "ravi";
    transient String password = "secret123";

    private void writeObject(ObjectOutputStream out) throws IOException {
        out.defaultWriteObject();                               // normal fields first
        out.writeObject(new StringBuilder(password).reverse().toString() + "#");
    }
    private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {
        in.defaultReadObject();
        String stored = (String) in.readObject();
        System.out.println("stored on disk: " + stored);
        password = new StringBuilder(stored.substring(0, stored.length() - 1)).reverse().toString();
    }
}
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("acc.ser"))) {
            out.writeObject(new Account());
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("acc.ser"))) {
            Account a = (Account) in.readObject();
            System.out.println(a.user + " " + a.password);
        }
    }
}
Output
stored on disk: 321terces#
ravi secret123
Reversing a string is only a teaching example, not real protection. Real systems never store passwords in a serialized file. They store a salted hash in a secure place.
Whatever writeObject writes, readObject must read back in the same order and with the same types.
Part 6

👪Serialization and inheritance

Case 1: the parent is Serializable

Then every child is Serializable automatically, even without writing implements Serializable. This is why many library classes are Serializable: a parent such as Number already is.

Case 2: only the child is Serializable

The fields that come from the non-serializable parent are not saved. During deserialization, the JVM runs the parent's no-argument constructor to give them values. The child's own constructor is not run.

The parent's fields come from its constructor · ▶ Runs
import java.io.*;
class Animal {
    int legs = 10;
    Animal() { System.out.println("Animal() runs"); }
}
class Dog extends Animal implements Serializable {
    int age = 20;
    Dog() { System.out.println("Dog() runs"); }
}
class Main {
    public static void main(String[] args) throws Exception {
        Dog d = new Dog();
        d.legs = 4;
        d.age = 3;
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("dog.ser"))) {
            out.writeObject(d);
        }
        System.out.println("--- loading ---");
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("dog.ser"))) {
            Dog e = (Dog) in.readObject();
            System.out.println("legs " + e.legs + ", age " + e.age);
        }
    }
}
Output
Animal() runs
Dog() runs
--- loading ---
Animal() runs
legs 10, age 3

age was saved, so it comes back as 3. legs belongs to the non-serializable parent, so it was not saved. Animal() ran again and set it to 10.

No no-arg constructor in the non-serializable parent · 💥 Crashes at run time
import java.io.*;
class Animal {
    int legs;
    Animal(int legs) { this.legs = legs; }
}
class Dog extends Animal implements Serializable {
    Dog() { super(4); }
}
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("dog.ser"))) {
            out.writeObject(new Dog());
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("dog.ser"))) {
            in.readObject();
        }
    }
}
💥 Runtime error
Exception in thread "main" java.io.InvalidClassException: Dog; no valid constructor
Writing succeeds, reading fails with InvalidClassException. Every non-serializable parent must have an accessible no-argument constructor.
Part 7

🎛️Externalizable

Serializable saves the whole object automatically. Externalizable hands complete control to you: you decide which fields to save and how. It extends Serializable and adds two methods.

Save only what you choose · ▶ Runs
import java.io.*;
class Student implements Externalizable {
    String name;
    int marks;
    String notes;
    public Student() { System.out.println("public no-arg constructor"); }
    Student(String name, int marks, String notes) { this.name = name; this.marks = marks; this.notes = notes; }

    public void writeExternal(ObjectOutput out) throws IOException {
        out.writeUTF(name);
        out.writeInt(marks);                                    // notes are not written
    }
    public void readExternal(ObjectInput in) throws IOException {
        name = in.readUTF();
        marks = in.readInt();
    }
}
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("st.ser"))) {
            out.writeObject(new Student("Meera", 88, "likes chess"));
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("st.ser"))) {
            Student s = (Student) in.readObject();
            System.out.println(s.name + " " + s.marks + " " + s.notes);
        }
    }
}
Output
public no-arg constructor
Meera 88 null

During deserialization the JVM first creates the object with its public no-argument constructor, then calls readExternal to fill it in.

Externalizable without a public no-arg constructor · 💥 Crashes at run time
import java.io.*;
class Student implements Externalizable {
    String name = "Meera";
    Student() { }
    public void writeExternal(ObjectOutput out) throws IOException { out.writeUTF(name); }
    public void readExternal(ObjectInput in) throws IOException { name = in.readUTF(); }
}
class Main {
    public static void main(String[] args) throws Exception {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("st.ser"))) {
            out.writeObject(new Student());
        }
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("st.ser"))) {
            in.readObject();
        }
    }
}
💥 Runtime error
Exception in thread "main" java.io.InvalidClassException: Student; no valid constructor

Part 8

🔖serialVersionUID

Every Serializable class has a version number called serialVersionUID. It is written into the bytes with each object. When the bytes are read, the JVM compares that number with the one in the class it has now. If they differ, reading fails with InvalidClassException: local class incompatible.

If you do not declare one, the compiler and JVM calculate it from the class's details: its name, fields, methods and so on. Adding even one method changes it. Different compilers can also produce different values. So a file saved yesterday may refuse to load today.

Declare it yourself · ▶ Runs
import java.io.*;
class Order implements Serializable {
    private static final long serialVersionUID = 1L;
    int id = 501;
}
class Plain implements Serializable {
    int id = 502;
}
class Main {
    public static void main(String[] args) {
        System.out.println(ObjectStreamClass.lookup(Order.class).getSerialVersionUID());
        long computed = ObjectStreamClass.lookup(Plain.class).getSerialVersionUID();
        System.out.println(computed != 0 ? "Plain gets a computed number" : "zero");
    }
}
Output
1
Plain gets a computed number
Always declare private static final long serialVersionUID = 1L; in a Serializable class. Change the number only when you deliberately break compatibility with old saved data.
The javac warning -Xlint:serial reports Serializable classes that forget to declare it.
Part 9

🆕Modern advice

Records (Java 16) serialize in a simpler and safer way. Only the record's components are saved, and during loading the canonical constructor is always called, so any checks in it run again.
A record checks its data on the way back in · ▶ Runs
import java.io.*;
record Point(int x, int y) implements Serializable {
    Point {
        System.out.println("constructor checks " + x + "," + y);
        if (x < 0 || y < 0) throw new IllegalArgumentException("negative");
    }
}
class Main {
    public static void main(String[] args) throws Exception {
        ByteArrayOutputStream bytes = new ByteArrayOutputStream();
        try (ObjectOutputStream out = new ObjectOutputStream(bytes)) { out.writeObject(new Point(3, 4)); }
        try (ObjectInputStream in = new ObjectInputStream(new ByteArrayInputStream(bytes.toByteArray()))) {
            System.out.println(in.readObject());
        }
    }
}
Output
constructor checks 3,4
constructor checks 3,4
Point[x=3, y=4]
Never deserialize bytes from a source you do not trust. Crafted input can run unexpected code during loading. Since Java 9, an ObjectInputFilter can limit which classes are accepted.
A filter that accepts only one class · 💥 Crashes at run time
import java.io.*;
import java.util.*;
class Main {
    public static void main(String[] args) throws Exception {
        ByteArrayOutputStream bytes = new ByteArrayOutputStream();
        try (ObjectOutputStream out = new ObjectOutputStream(bytes)) { out.writeObject(new ArrayList<>(List.of(1))); }
        try (ObjectInputStream in = new ObjectInputStream(new ByteArrayInputStream(bytes.toByteArray()))) {
            in.setObjectInputFilter(ObjectInputFilter.Config.createFilter("java.lang.String;!*"));
            in.readObject();
        }
    }
}
💥 Runtime error
Exception in thread "main" java.io.InvalidClassException: filter status: REJECTED

For data shared with other programs or other languages, most teams prefer text formats such as JSON or compact formats such as Protocol Buffers. Java serialization is still important to understand: it appears in exams, in older systems, and inside frameworks for caching and remote calls.
