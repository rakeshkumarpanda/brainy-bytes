Part 1

📦Why methods

A method is a named block of code that performs one task. Writing the code once and calling it many times removes repetition, makes the program easier to read, and means a fix in one place fixes every call.

public static int add(int i, int j) {    // signature: modifiers, return type, name, parameters
    return i + j;                          // body
}
public abstract void test();               // abstract method: signature only, no body

Concrete method

Has a signature and a body. A class with only concrete methods is a concrete class.

Abstract method

Has only a signature, ending with a semicolon. A class with at least one abstract method must itself be declared abstract.

Part 3

↩️Parameters, return values and pass by value

Parameters are the variables in the signature, arguments are the values passed in the call. A method declared void returns nothing, any other return type must return a value of that type (Addition5 prints, Addition6 returns).

Java always passes by value. For a primitive the value is the number, so the caller's variable never changes. For an object the value is the reference, so the method can change the object's fields, but assigning a new object to the parameter does not affect the caller. Python and JavaScript behave the same way.
Part 4

🎛️Method overloading

Several methods may share a name if their parameter lists differ in number, type or order. The compiler picks the best match at compile time. A different return type alone is not enough.

Python and JavaScript have no overloading: a second definition replaces the first. They use default parameter values or check the arguments inside one function instead.
Part 5

🥞The call stack and recursion

Every call pushes a frame holding its parameters and local variables onto the call stack. Returning pops it. A method that calls itself is recursive, and it needs a base case, or the stack overflows with StackOverflowError.
