Inner Classes

Some objects only make sense inside another object: a heart inside a body, an entry inside a map. Inner classes let Java say exactly that.

Part 1

🫀Why inner classes exist

Declare a class inside another class when the inner thing cannot exist without the outer thing. A university has departments, and a map has entries. Without a Map object there is no Map.Entry.

Java snippet
class University {          // outer
    class Department { }    // inner: lives inside a university
}

1. Normal (regular) inner class

Declared directly inside a class, without static.

2. Method local inner class

Declared inside a method, visible only there.

3. Anonymous inner class

A class without a name, declared and used in one expression.

4. Static nested class

Declared inside a class with static. Not tied to an outer object.

Strictly speaking, Java calls all four "nested classes" and only the non-static ones "inner classes". Most people use "inner class" loosely for all of them.
Part 2

📥Normal inner classes

A normal inner class is declared directly inside the outer class body. Compiling produces two files: Outer.class and Outer$Inner.class.

Three ways to reach the inner class · ▶ Runs
class Outer {
    class Inner {
        void hello() { System.out.println("Hello from Inner"); }
    }
    void fromInstanceMethod() {
        Inner i = new Inner();                 // an outer object already exists (this)
        i.hello();
    }
    public static void main(String[] args) {
        Outer o = new Outer();
        Outer.Inner i = o.new Inner();         // from static code: build on an outer object
        i.hello();
        new Outer().new Inner().hello();       // the one line version
        o.fromInstanceMethod();
    }
}
Output
Hello from Inner
Hello from Inner
Hello from Inner

The inner class sees everything outside

Inner code can use every member of the outer class, static or not, even private ones.

Private outer members are visible · ▶ Runs
class Outer {
    private int x = 10;
    static int y = 20;
    class Inner {
        void show() { System.out.println(x + " " + y); }
    }
    public static void main(String[] args) { new Outer().new Inner().show(); }
}
Output
10 20

Which this

Inside the inner class, this means the inner object. To reach the outer object, write Outer.this.

Three x variables, three ways to reach them · ▶ Runs
class Outer {
    int x = 10;
    class Inner {
        int x = 100;
        void show() {
            int x = 1000;
            System.out.println(x);               // local
            System.out.println(this.x);          // inner field
            System.out.println(Outer.this.x);    // outer field
        }
    }
    public static void main(String[] args) { new Outer().new Inner().show(); }
}
Output
1000
100
10
Modifiers on a normal inner class
public, default, private, protected, final, abstract, strictfp, and static (which turns it into a static nested class)
Before Java 16 an inner class could not declare static members, so it could not have its own main. Since Java 16 static members are allowed in inner classes too. Older notes and exam books still describe the old rule.
Static member inside an inner class (Java 16 and later) · ▶ Runs
class Outer {
    class Inner {
        static int created = 0;
        Inner() { created++; }
    }
    public static void main(String[] args) {
        Outer o = new Outer();
        o.new Inner(); o.new Inner();
        System.out.println(Inner.created);
    }
}
Output
2
Part 3

🧪Method local inner classes

A class declared inside a method exists only inside that method. Use it for a helper that is needed again and again inside one method and nowhere else.

A helper that lives in one method · ▶ Runs
class Main {
    void report() {
        class Adder {
            int sum(int a, int b) { return a + b; }
        }
        Adder ad = new Adder();
        System.out.println(ad.sum(10, 20));
        System.out.println(ad.sum(100, 200));
    }
    public static void main(String[] args) { new Main().report(); }
}
Output
30
300
  • It can be used only inside the method, after its declaration.
  • Declared in an instance method, it can use every outer member. Declared in a static method, only static outer members.
  • The only modifiers allowed are final, abstract and strictfp.
  • It can read the method's local variables only if they are final or effectively final (never changed after being set, since Java 8).
Effectively final locals are allowed · ▶ Runs
class Main {
    public static void main(String[] args) {
        int bonus = 50;                        // never changed: effectively final
        class Salary {
            int total(int base) { return base + bonus; }
        }
        System.out.println(new Salary().total(1000));
    }
}
Output
1050
Changing the local breaks it · ❌ Does not compile
class Main {
    public static void main(String[] args) {
        int bonus = 50;
        bonus++;
        class Salary {
            int total(int base) { return base + bonus; }
        }
    }
}
❌ Compile error
local variables referenced from an inner class must be final or effectively final

Why the rule: the local variable dies when the method returns, but the inner object may live longer. Java gives the object its own copy, and copies only stay honest if the value never changes.

Part 4

🎭Anonymous inner classes

An anonymous class has no name. You declare it and create its one object in the same expression. It is perfect for a quick, one time change of behaviour.

1. Extending a class

One special popcorn · ▶ Runs
class Popcorn {
    void taste() { System.out.println("salty"); }
}
class Main {
    public static void main(String[] args) {
        Popcorn p = new Popcorn() {            // a child of Popcorn with no name
            void taste() { System.out.println("spicy"); }
        };
        p.taste();
        new Popcorn().taste();
        System.out.println(p.getClass().getName());
    }
}
Output
spicy
salty
Main$1

The compiler names the hidden class Main$1. It is a child of Popcorn that overrides taste().

2. Implementing an interface

A Runnable on the spot · ▶ Runs
class Main {
    public static void main(String[] args) throws Exception {
        Runnable job = new Runnable() {
            public void run() { System.out.println("child thread working"); }
        };
        Thread t = new Thread(job);
        t.start();
        t.join();
        System.out.println("main thread done");
    }
}
Output
child thread working
main thread done

3. Inside a method argument

Passed directly as an argument · ▶ Runs
class Main {
    public static void main(String[] args) throws Exception {
        Thread t = new Thread(new Runnable() {
            public void run() { System.out.println("defined inside the argument"); }
        });
        t.start();
        t.join();
    }
}
Output
defined inside the argument
When the interface has exactly one abstract method, a lambda does the same job with far less code: new Thread(() -> System.out.println("hi")).start();
A method added only in the anonymous class cannot be called through the parent reference, because the compiler only knows the parent type.

Part 6

🧊Static nested classes

A nested class declared static is not tied to any outer object. Create it with new Outer.Nested().

No outer object needed · ▶ Runs
class Outer {
    static int count = 3;
    int x = 10;
    static class Nested {
        void show() {
            System.out.println("count = " + count);       // static outer member: fine
            // System.out.println(x);                      // instance member: not allowed
        }
    }
    public static void main(String[] args) {
        Outer.Nested n = new Outer.Nested();
        n.show();
    }
}
Output
count = 3
No instance members from a static nested class · ❌ Does not compile
class Outer {
    int x = 10;
    static class Nested {
        void show() { System.out.println(x); }
    }
}
❌ Compile error
non-static variable x cannot be referenced from a static context

A static nested class can have its own main, and you can run it directly with java Outer$Nested. Map.Entry is a nested interface, and many builders are static nested classes.

A builder as a static nested class · ▶ Runs
class Pizza {
    private final String size; private final boolean cheese;
    private Pizza(Builder b) { size = b.size; cheese = b.cheese; }
    public String toString() { return size + (cheese ? " with extra cheese" : ""); }
    static class Builder {
        private String size = "medium"; private boolean cheese;
        Builder size(String s) { size = s; return this; }
        Builder cheese() { cheese = true; return this; }
        Pizza build() { return new Pizza(this); }
    }
}
class Main {
    public static void main(String[] args) {
        System.out.println(new Pizza.Builder().size("large").cheese().build());
    }
}
Output
large with extra cheese

Part 8

🧱Classes and interfaces inside each other

  • Interface inside a class: useful when the interface only makes sense together with that class. Every nested interface is automatically static.
  • Interface inside an interface: Map.Entry lives inside Map. It is automatically public and static.
  • Class inside an interface: gives the interface a default implementation it can hand out. It is automatically public and static.
Map.Entry in action · ▶ Runs
Map<String, Integer> marks = new TreeMap<>(Map.of("Asha", 91, "Ravi", 78));
for (Map.Entry<String, Integer> e : marks.entrySet())
    System.out.println(e.getKey() + " → " + e.getValue());
Output
Asha → 91
Ravi → 78
A class inside an interface · ▶ Runs
interface Shape {
    double area();
    class Unit implements Shape {                // implicitly public static
        public double area() { return 1.0; }
    }
}
class Main {
    public static void main(String[] args) {
        Shape s = new Shape.Unit();
        System.out.println(s.area());
    }
}
Output
1.0
