How Java Runs: Classes, Variables and Data Types

Before writing bigger programs, it helps to know what actually happens when you press Run. This chapter follows a Java file from source code to output, then covers the building blocks every program uses: classes, objects, variables, data types, casting, static members, the main method and access modifiers. Each idea is shown in Java with the Python and JavaScript equivalent beside it.

Part 1

⚙️From source code to output

A Java program goes through two stages. The compiler (javac) turns your .java source into bytecode in a .class file. The JVM (Java Virtual Machine) then loads that bytecode, checks it, and runs it, interpreting it at first and compiling hot code to machine code with the JIT compiler.

PartWhat it containsWho needs it
JVMClass loader, bytecode verifier, interpreter, JIT compiler, garbage collectorRuns bytecode
JREJVM plus the standard class librariesAnyone who only runs Java programs
JDKJRE plus development tools: javac, java, jar, javadoc, debuggerDevelopers and testers who write code
The same .class file runs on Windows, macOS and Linux because each has its own JVM. This is what "write once, run anywhere" means: the bytecode is platform independent, the JVM is not.
Python also compiles to bytecode (.pyc) and runs it in a virtual machine. JavaScript engines such as V8 parse the source and JIT compile it. Java makes the compile step visible and separate.
Part 2

🏗️Classes and objects

Every Java program lives inside a class: a blueprint that groups data (variables) and behaviour (methods). An object is a real thing built from that blueprint, with its own state.

<access_specifier> class <ClassName> {
    // variables (state)
    // methods (behaviour)
}

ClassName ref = new ClassName();   // instantiation
PieceMeaning
newA keyword that creates a new object every time it runs
ClassName()The constructor that initialises the new object
refA reference variable that stores the address of the object, not the object itself

int i;              // declaration
int i1, i2;         // several at once
i = 10;             // initialisation
int j = 100;        // both in one line

Identifier rules: only letters, digits, _ and $, must not start with a digit, and must not be one of Java's keywords (all keywords are lower case, such as class, int, static). Identifiers are case sensitive.

Part 5

🔀Widening, narrowing and overflow

Arithmetic on byte, short and char is done in int. So this does not compile:

byte b1 = 10, b2 = 20;
byte b3 = b1 + b2;          // error: possible lossy conversion from int to byte
int  b3 = b1 + b2;          // fix 1: use a larger type (widening)
byte b3 = (byte) (b1 + b2); // fix 2: cast explicitly (narrowing)

Widening (implicit)

Smaller type into a larger one: byte → short → int → long → float → double. No data is lost, so Java does it automatically.

Narrowing (explicit)

Larger type into a smaller one needs a cast, because data can be lost: (byte) 200 becomes 200 − 256 = −56.

Part 6

📌Static and non-static members

A static member belongs to the class and exists once. A non-static (instance) member belongs to each object. A static method such as main has no object, so it cannot use instance members directly:

public class Main {
    int a = 10;                          // instance variable
    public static void main(String[] args) {
        int sum = a + 20;                // error: non-static variable a cannot be referenced from a static context
        Main m = new Main();             // fix 1: create an object
        int ok = m.a + 20;               // 30
    }
}                                        // fix 2: declare it as static int a = 10;
Static members are loaded when the class is loaded. Use them for things that truly belong to the class, such as a counter or a constant, not as a shortcut to avoid creating objects.

Can a Java program run without a main method? A standalone application cannot: main is the entry point. Frameworks such as TestNG or JUnit provide their own main and call your annotated methods instead.
