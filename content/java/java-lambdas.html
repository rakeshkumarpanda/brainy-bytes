Lambdas, functional interfaces and method references

Lambdas let you hand a small piece of behaviour to another method: how to compare, what to keep, what to do with each item. This chapter goes from your first arrow to functional interfaces, method references, composing functions, captured variables, checked exceptions and the invokedynamic machinery the JVM uses to run them.

Part 1

💡Why lambdas exist

Before Java 8, passing a small piece of behaviour (how to compare, what to do on a click, which items to keep) meant writing a whole anonymous class. Most of those lines were ceremony. A lambda is the same behaviour written as just the inputs, an arrow and the result.

An anonymous class and the lambda that replaces it · ▶ Runs · ☕ JDK 25
import java.util.*;

class Main {
    public static void main(String[] args) {
        List<String> tests = new ArrayList<>(List.of("checkout", "login", "search", "cart"));

        // Before Java 8: an anonymous class just to say "compare by length"
        Collections.sort(tests, new Comparator<String>() {
            @Override
            public int compare(String a, String b) {
                return Integer.compare(a.length(), b.length());
            }
        });
        System.out.println(tests);

        // Java 8: the same behaviour as a lambda
        tests.sort((a, b) -> b.length() - a.length());
        System.out.println(tests);
    }
}
Output
[cart, login, search, checkout]
[checkout, search, login, cart]

Think of a lambda as a sticky note with instructions that you hand to someone else. sort does the sorting work, and your lambda only answers the one question it needs answered: "which of these two comes first?"

Java 8 (2014) added lambdas, method references, streams, Optional and java.time in one release. It is still the biggest change the language has ever had, and almost every modern Java API, from Selenium waits to Spring, expects you to pass lambdas.
Part 2

✍️Lambda syntax

A lambda is (parameters) -> body. The compiler works out the parameter types from the context, so you rarely write them.

FormExampleWhen
No input() -> System.out.println("hi")Runnable, Supplier
One inputs -> s.length()brackets are optional
Several inputs(a, b) -> a + bbrackets are required
Block bodyx -> { int y = x * 2; return y; }more than one statement, needs return
Typed or var(var s) -> s.isBlank()to add annotations such as @NonNull
The five shapes a lambda can take · ▶ Runs · ☕ JDK 25
import java.util.function.*;

class Main {
    public static void main(String[] args) {
        Runnable hello = () -> System.out.println("no inputs");
        Function<String, Integer> len = s -> s.length();               // one input, no brackets needed
        BinaryOperator<Integer> add = (a, b) -> a + b;                  // two inputs
        BiFunction<Integer, Integer, Integer> max = (Integer a, Integer b) -> {
            if (a > b) return a;                                       // a block body needs return
            return b;
        };
        Predicate<String> empty = (var s) -> s.isBlank();               // var in lambda parameters, Java 11

        hello.run();
        System.out.println(len.apply("Brainy"));
        System.out.println(add.apply(40, 2));
        System.out.println(max.apply(7, 3));
        System.out.println(empty.test("   "));
    }
}
Output
no inputs
6
42
7
true

A lambda has no type of its own. Its type comes from where you put it, called the target type. The same text can become a Supplier or a Callable, but never a plain Object.

A lambda needs a target type · ❌ Does not compile · ☕ JDK 25
import java.util.concurrent.Callable;
import java.util.function.Supplier;

class Main {
    public static void main(String[] args) throws Exception {
        // The same lambda text becomes different types, decided by where it is used (the target type)
        Supplier<String> s = () -> "ready";
        Callable<String> c = () -> "ready";
        System.out.println(s.get() + " " + c.call());

        Object o = () -> "ready";        // Object is not a functional interface
    }
}
❌ Compile error
Line 11: incompatible types: Object is not a functional interface
Part 3

🧰Functional interfaces

A functional interface is an interface with exactly one abstract method. A lambda is simply a short way to create an object of such an interface: the lambda body becomes that method. Default and static methods do not count, so an interface can have many of those and still be functional.

InterfaceMethodShapeTypical use in tests
Predicate<T>testT to booleanfilter results, wait conditions
Function<T,R>applyT to Rmap a response to a field
Consumer<T>acceptT to nothinglog, click, fill each item
Supplier<T>getnothing to Tcreate test data lazily
UnaryOperator<T> BinaryOperator<T>applyT to T, (T,T) to Tclean up a value, add two totals
BiFunction BiConsumer BiPredicatetwo inputs(T,U) to ...Map.forEach((k, v) -> ...)
IntPredicate ToIntFunction IntSupplier ...primitive versionsno boxingfast number work
The everyday interfaces in java.util.function · ▶ Runs · ☕ JDK 25
import java.util.*;
import java.util.function.*;

class Main {
    public static void main(String[] args) {
        Predicate<Integer> passed = code -> code >= 200 && code < 300;   // T -> boolean
        Function<String, String> slug = t -> t.toLowerCase().replace(' ', '-');  // T -> R
        Consumer<String> log = msg -> System.out.println("[LOG] " + msg); // T -> nothing
        Supplier<String> email = () -> "user" + new Random(7).nextInt(1000) + "@shop.test"; // nothing -> T
        UnaryOperator<String> trim = String::strip;                       // T -> T
        BiFunction<String, Integer, String> pad = (s, n) -> s + ".".repeat(n);
        IntPredicate even = n -> n % 2 == 0;                              // primitive version, no boxing

        System.out.println(passed.test(201) + " " + passed.test(404));
        System.out.println(slug.apply("Add To Cart"));
        log.accept("suite started");
        System.out.println(email.get());
        System.out.println("[" + trim.apply("  hi  ") + "]");
        System.out.println(pad.apply("Loading", 3));
        System.out.println(even.test(10));
    }
}
Output
true false
add-to-cart
[LOG] suite started
user236@shop.test
[hi]
Loading...
true

You can write your own. Add @FunctionalInterface so the compiler checks that it really has one abstract method.

Your own functional interface with default and static methods · ▶ Runs · ☕ JDK 25
@FunctionalInterface
interface Discount {
    double apply(double price);                       // exactly one abstract method

    default Discount then(Discount next) {            // default methods are allowed
        return p -> next.apply(apply(p));
    }

    static Discount percent(double pct) {             // static factory methods too
        return p -> p - p * pct / 100;
    }
}

class Main {
    public static void main(String[] args) {
        Discount festive = Discount.percent(10);
        Discount coupon = p -> p - 50;
        Discount both = festive.then(coupon);
        System.out.println(festive.apply(1000));
        System.out.println(both.apply(1000));
    }
}
Output
900.0
850.0

Part 4

🔗Method references

When a lambda only calls one existing method, a method reference says the same thing even shorter, with ::. s -> s.toUpperCase() becomes String::toUpperCase.

KindMethod referenceSame as the lambda
Static methodInteger::parseInts -> Integer.parseInt(s)
Method of a given objectSystem.out::printlnx -> System.out.println(x)
Method of the incoming objectString::lengths -> s.length()
ConstructorArrayList::new() -> new ArrayList<>()
The four kinds of method reference · ▶ Runs · ☕ JDK 25
import java.util.*;
import java.util.function.*;

class Main {
    record User(String name) {}

    static boolean isAdmin(String n) { return n.startsWith("admin"); }

    public static void main(String[] args) {
        List<String> names = List.of("admin_asha", "ravi", "admin_meera");

        // 1. Static method: ClassName::staticMethod
        Predicate<String> admin = Main::isAdmin;
        // 2. Method of one particular object: object::method
        String prefix = "Hello, ";
        Function<String, String> greet = prefix::concat;
        // 3. Instance method of whatever object comes in: ClassName::instanceMethod
        Function<String, String> upper = String::toUpperCase;
        // 4. Constructor: ClassName::new
        Function<String, User> make = User::new;

        names.stream().filter(admin).map(upper).forEach(System.out::println);
        System.out.println(greet.apply("Ravi"));
        System.out.println(make.apply("Meera"));
    }
}
Output
ADMIN_ASHA
ADMIN_MEERA
Hello, Ravi
User[name=Meera]
Use a method reference when it reads better. map(User::name) is clearer than map(u -> u.name()), but a lambda with a little logic should stay a lambda.
Part 5

🧩Composing functions

Functional interfaces come with default methods that join small pieces into bigger ones, like Lego bricks. Predicate has and, or and negate. Function has andThen and compose. Comparator has comparing, thenComparing and reversed.

and, or, negate, andThen and Comparator chains · ▶ Runs · ☕ JDK 25
import java.util.*;
import java.util.function.*;

class Main {
    record Result(String name, String status, int ms) {}

    public static void main(String[] args) {
        Predicate<Result> failed = r -> r.status().equals("FAIL");
        Predicate<Result> slow = r -> r.ms() > 1000;
        Function<String, String> trim = String::strip;
        Function<String, String> clean = trim.andThen(String::toLowerCase).andThen(s -> s.replace(' ', '_'));

        List<Result> results = new ArrayList<>(List.of(
            new Result("login", "PASS", 420), new Result("checkout", "FAIL", 2300),
            new Result("search", "PASS", 1800), new Result("cart", "FAIL", 300)));

        System.out.println(results.stream().filter(failed.or(slow)).map(Result::name).toList());
        System.out.println(results.stream().filter(failed.negate().and(slow)).map(Result::name).toList());
        System.out.println(clean.apply("  Add To Cart "));

        // Comparators compose too: by status, then slowest first
        results.sort(Comparator.comparing(Result::status).thenComparing(Result::ms, Comparator.reverseOrder()));
        results.forEach(r -> System.out.println(r.status() + " " + r.ms() + " " + r.name()));
    }
}
Output
[checkout, search, cart]
[search]
add_to_cart
FAIL 2300 checkout
FAIL 300 cart
PASS 1800 search
PASS 420 login

Real reports sort by several keys at once: failures first, then the slowest. A comparator chain says exactly that, in the order a person would say it.

Part 6

📦Capturing variables and this

A lambda can read local variables from the code around it, but only if they are effectively final: assigned once and never changed. The lambda may run later, maybe on another thread, so Java copies the value in and forbids changes that would make the copy wrong.

Lambdas capture effectively final variables only · ❌ Does not compile · ☕ JDK 25
import java.util.function.*;

class Main {
    public static void main(String[] args) {
        String env = "staging";                         // effectively final: never changed
        Supplier<String> url = () -> "https://" + env + ".shop.test";
        System.out.println(url.get());

        int count = 0;
        Runnable r = () -> count++;                     // a lambda may not change a local variable
    }
}
❌ Compile error
Line 10: local variables referenced from a lambda expression must be final or effectively final

If you truly need a changing counter, use an object such as AtomicInteger. The variable still points to the same object, only the object's contents change.

Changing state from a lambda the safe way · ▶ Runs · ☕ JDK 25
import java.util.concurrent.atomic.AtomicInteger;
import java.util.stream.IntStream;

class Main {
    public static void main(String[] args) {
        // Need a counter inside a lambda? Use an object whose contents can change.
        AtomicInteger attempts = new AtomicInteger();
        IntStream.range(0, 3).forEach(i -> attempts.incrementAndGet());
        System.out.println("attempts = " + attempts.get());

        int[] box = {0};                                // the array reference is final, its slot is not
        IntStream.range(0, 5).forEach(i -> box[0] += i);
        System.out.println("sum = " + box[0]);
    }
}
Output
attempts = 3
sum = 10

One more difference from anonymous classes: inside a lambda, this means the surrounding object. A lambda does not create a new scope for this.

this means different things in a lambda and an anonymous class · ▶ Runs · ☕ JDK 25
class Main {
    String name = "outer object";

    void demo() {
        Runnable anon = new Runnable() {
            String name = "anonymous object";
            public void run() { System.out.println("anonymous class: this.name = " + this.name); }
        };
        Runnable lambda = () -> System.out.println("lambda:          this.name = " + this.name);
        anon.run();
        lambda.run();
    }

    public static void main(String[] args) {
        new Main().demo();
    }
}
Output
anonymous class: this.name = anonymous object
lambda:          this.name = outer object
Part 7

⚠️Lambdas and checked exceptions

The methods of Function, Consumer and friends do not declare throws, so a lambda passed to them cannot throw a checked exception such as IOException. The usual fix is a small wrapper that turns it into an unchecked exception, keeping the original as the cause.

Checked exceptions and lambdas · ▶ Runs · ☕ JDK 25
import java.nio.file.*;
import java.util.*;
import java.util.function.*;

class Main {
    @FunctionalInterface
    interface ThrowingFunction<T, R> { R apply(T t) throws Exception; }

    // Wrap a function that may throw a checked exception into a plain Function
    static <T, R> Function<T, R> unchecked(ThrowingFunction<T, R> f) {
        return t -> {
            try { return f.apply(t); }
            catch (Exception e) { throw new RuntimeException(e.getMessage(), e); }
        };
    }

    public static void main(String[] args) throws Exception {
        Path dir = Files.createTempDirectory("data");
        Files.writeString(dir.resolve("a.txt"), "alpha");
        Files.writeString(dir.resolve("b.txt"), "beta");

        // Files.readString throws IOException, so it cannot be used directly in map(...)
        List<String> texts = List.of("a.txt", "b.txt").stream()
            .map(dir::resolve)
            .map(unchecked(Files::readString))
            .toList();
        System.out.println(texts);
    }
}
Output
[alpha, beta]
Do not hide exceptions with an empty catch inside a lambda. A test that swallows an IOException will pass with wrong data, which is worse than a clear failure.
Part 8

🔬How a lambda runs inside the JVM

An anonymous class becomes its own .class file (Main$1.class). A lambda does not. javac turns its body into a private method and leaves a single invokedynamic instruction where the lambda was. The first time that line runs, the JVM builds the object.

What javac really produces for a lambda · 🖥️ Run in a terminal · ☕ JDK 25
📄 Main.java
import java.util.function.Function;

class Main {
    public static void main(String[] args) {
        Function<String, Integer> len = s -> s.length();
        System.out.println(len.apply("lambda"));
    }
}
Terminal
$ javac Main.java && java Main
$ javap -p Main
$ javap -c -p Main | grep invokedynamic
Terminal output
6
--- members of Main ---
Compiled from "Main.java"
class Main {
  Main();
  public static void main(java.lang.String[]);
  private static java.lang.Integer lambda$main$0(java.lang.String);
}
--- the lambda line in main ---
         0: invokedynamic #n,  0  // InvokeDynamic #n:apply:()Ljava/util/function/Function;

This design (Java 8, JSR 335) lets the JVM choose the best way to make lambdas without changing your class files, and it is why a lambda that captures nothing costs almost nothing after the first call.

Part 9

🎬Real world scenario: a retry helper

The situationA payment sandbox sometimes answers 503 for a second or two. Tests fail at random, and people add Thread.sleep everywhere.
Real world: a retry helper for a flaky service · ▶ Runs · ☕ JDK 25
import java.util.function.*;

class Main {
    // A retry helper for flaky calls: the work and the success check are passed in as lambdas
    static <T> T retry(Supplier<T> call, Predicate<T> ok, int times) {
        T last = null;
        for (int attempt = 1; attempt <= times; attempt++) {
            last = call.get();
            System.out.println("attempt " + attempt + " -> " + last);
            if (ok.test(last)) return last;
        }
        throw new IllegalStateException("still failing after " + times + " attempts: " + last);
    }

    public static void main(String[] args) {
        int[] calls = {0};
        Supplier<Integer> flakyStatus = () -> ++calls[0] < 3 ? 503 : 200;   // fails twice, then works
        int status = retry(flakyStatus, code -> code == 200, 5);
        System.out.println("final status " + status);
    }
}
Output
attempt 1 -> 503
attempt 2 -> 503
attempt 3 -> 200
final status 200

The helper does not know what it is retrying. The work arrives as a Supplier, and the meaning of "success" arrives as a Predicate. The same helper now retries API calls, database checks or UI conditions, and it reports every attempt. This is the idea behind Awaitility's await().until(...) and Selenium's FluentWait.
