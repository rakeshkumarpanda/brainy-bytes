Generics

Generics let you say "this list holds only Strings" once, and then the compiler checks every add and every get for you. No casts, no surprise ClassCastException at midnight.

Part 1

🛡️Why generics

Generics (Java 5) solve two problems that old collections had.

1. Type safety

An old ArrayList accepted any object. Someone could put an Integer into your list of names, and you only found out when the program crashed.

2. Casting

Every get returned Object, so you had to cast it back, everywhere.

Without generics: compiles, then crashes · 💥 Crashes at run time
ArrayList names = new ArrayList();      // raw type: holds anything
names.add("Asha");
names.add(10);                          // nobody stops this
for (Object o : names) {
    String s = (String) o;              // cast needed, and it fails for 10
    System.out.println(s.toUpperCase());
}
Output before the crash
ASHA
💥 Runtime error
Exception in thread "main" java.lang.ClassCastException: class java.lang.Integer cannot be cast to class java.lang.String (java.lang.Integer and java.lang.String are in module java.base of loader 'bootstrap')
With generics: the mistake is caught at compile time · ❌ Does not compile
ArrayList<String> names = new ArrayList<String>();
names.add("Asha");
names.add(10);
❌ Compile error
incompatible types: int cannot be converted to String
And no casts are needed · ▶ Runs
ArrayList<String> names = new ArrayList<>();
names.add("Asha");
names.add("Ravi");
for (String s : names) System.out.println(s.toUpperCase());
Output
ASHA
RAVI
Arrays were always type checked, but only at run time: storing an Integer into a String[] seen through an Object[] throws ArrayStoreException. Generics move the check to compile time, which is much kinder.
Arrays check at run time · 💥 Crashes at run time
Object[] arr = new String[2];
arr[0] = "fine";
arr[1] = 10;
💥 Runtime error
Exception in thread "main" java.lang.ArrayStoreException: java.lang.Integer
Part 2

🏷️Generic classes

, multiple type parameters">

A generic class declares a type parameter in angle brackets. The caller fills it in.

A box that remembers what it holds · ▶ Runs
class Box<T> {
    private final T item;
    Box(T item) { this.item = item; }
    T get() { return item; }
    String describe() { return "Box of " + item.getClass().getSimpleName() + ": " + item; }
}
class Main {
    public static void main(String[] args) {
        Box<String> b1 = new Box<>("chocolate");     // diamond: the compiler infers String
        Box<Integer> b2 = new Box<>(42);
        String s = b1.get();                          // no cast
        int n = b2.get() + 1;
        System.out.println(b1.describe() + " | " + b2.describe() + " | " + s.length() + " " + n);
    }
}
Output
Box of String: chocolate | Box of Integer: 42 | 9 43
  • Any identifier works, but by convention: T type, E element, K key, V value, N number.
  • A class may have several parameters, like HashMap<K, V>.
  • The diamond <> (Java 7) lets the compiler infer the type on the right side.
  • Type arguments must be reference types: List<int> is not allowed, use List<Integer>.
No primitives as type arguments · ❌ Does not compile
List<int> nums = new ArrayList<>();
❌ Compile error
unexpected type
required: reference
found:    int
Two type parameters · ▶ Runs
class Pair<K, V> {
    final K key; final V value;
    Pair(K k, V v) { key = k; value = v; }
    public String toString() { return key + "=" + value; }
}
class Main {
    public static void main(String[] args) {
        Pair<String, Integer> p = new Pair<>("age", 21);
        System.out.println(p + " " + (p.value + 1));
    }
}
Output
age=21 22
Part 3

📏Bounded types

Sometimes only certain types make sense. <T extends Number> allows Number or any of its children, and lets you call Number methods on T.

Only numbers allowed · ▶ Runs
class Stats<T extends Number> {
    private final List<T> values;
    Stats(List<T> v) { values = v; }
    double average() {
        double sum = 0;
        for (T v : values) sum += v.doubleValue();     // Number's method is available
        return sum / values.size();
    }
}
class Main {
    public static void main(String[] args) {
        System.out.println(new Stats<>(List.of(1, 2, 3, 4)).average());
        System.out.println(new Stats<>(List.of(2.5, 3.5)).average());
    }
}
Output
2.5
3.0
String is not a Number · ❌ Does not compile
class Stats<T extends Number> { }
class Main {
    public static void main(String[] args) { Stats<String> s = new Stats<>(); }
}
❌ Compile error
type argument String is not within bounds of type-variable T
where T is a type-variable:
T extends Number declared in class Stats
  • The keyword is always extends, even for interfaces: <T extends Runnable>.
  • Several bounds are joined with &. At most one of them may be a class, and it must come first: <T extends Number & Comparable<T>>.
  • super cannot be used to bound a type parameter. It only appears with wildcards.
Interface before class · ❌ Does not compile
class Bad<T extends Runnable & Number> { }
❌ Compile error
interface expected here
Part 4

⚙️Generic methods

A single method can be generic too. Declare the type parameter just before the return type.

One method for every type · ▶ Runs
class Main {
    static <T> T firstOrDefault(List<T> list, T fallback) {
        return list.isEmpty() ? fallback : list.get(0);
    }
    static <T extends Comparable<T>> T max(List<T> list) {
        T best = list.get(0);
        for (T x : list) if (x.compareTo(best) > 0) best = x;
        return best;
    }
    public static void main(String[] args) {
        System.out.println(firstOrDefault(List.of("tea", "coffee"), "water"));
        System.out.println(firstOrDefault(List.<Integer>of(), -1));
        System.out.println(max(List.of(3, 9, 4)) + " " + max(List.of("kiwi", "apple", "mango")));
    }
}
Output
tea
-1
9 mango
The compiler infers T from the arguments. You rarely need to write Main.<String>firstOrDefault(...) by hand.
Part 5

🃏Wildcards: ?, ? extends and ? super

A wildcard ? stands for "some type I do not know". It is used in parameters and variables, not when creating objects.

Parameter typeAcceptsCan read asCan add
List<?>a list of anythingObjectonly null
List<? extends Number>List of Number, Integer, Double…Numberonly null
List<? super Integer>List of Integer, Number, ObjectObjectInteger values
PECS: producer extends, consumer super. If a list gives you values, use ? extends. If you put values into it, use ? super.
Read from extends, write to super · ▶ Runs
class Main {
    static double sum(List<? extends Number> nums) {            // a producer
        double s = 0;
        for (Number n : nums) s += n.doubleValue();
        return s;
    }
    static void addTens(List<? super Integer> sink) {           // a consumer
        for (int i = 1; i <= 3; i++) sink.add(i * 10);
    }
    public static void main(String[] args) {
        System.out.println(sum(List.of(1, 2, 3)) + " " + sum(List.of(1.5, 2.5)));
        List<Number> numbers = new ArrayList<>();
        List<Object> objects = new ArrayList<>();
        addTens(numbers);
        addTens(objects);
        System.out.println(numbers + " " + objects);
    }
}
Output
6.0 4.0
[10, 20, 30] [10, 20, 30]
Cannot add to ? extends · ❌ Does not compile
List<? extends Number> nums = new ArrayList<Integer>();
nums.add(10);
❌ Compile error
incompatible types: int cannot be converted to CAP#1
where CAP#1 is a fresh type-variable:
CAP#1 extends Number from capture of ? extends Number
A wildcard cannot be created · ❌ Does not compile
List<?> l = new ArrayList<?>();
❌ Compile error
unexpected type
required: class or interface without bounds
found:    ?
Part 6

🦎Generics and polymorphism

vs List, invariance, base type polymorphism">

Polymorphism applies to the base type, never to the type argument.

Base type can change · ▶ Runs
List<String> l1 = new ArrayList<String>();          // ArrayList IS-A List
Collection<String> l2 = new LinkedList<>();
System.out.println(l1.getClass().getSimpleName() + " " + l2.getClass().getSimpleName());
Output
ArrayList LinkedList
Type argument cannot change · ❌ Does not compile
List<Object> l = new ArrayList<String>();
❌ Compile error
incompatible types: ArrayList<String> cannot be converted to List<Object>

Why the rule: if a List<String> could be treated as a List<Object>, someone could add an Integer through the Object view and break the String list. Wildcards (List<? extends Object>) are the safe way to accept "a list of some kind".

Part 7

🧽Type erasure

Generics exist only for the compiler. After checking, it erases the type arguments, so at run time an ArrayList<String> and an ArrayList<Integer> are the same class.

Same class at run time · ▶ Runs
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());
System.out.println(a.getClass().getName());
Output
true
java.util.ArrayList

Consequences

  • You cannot overload methods that differ only in type arguments, because after erasure they have the same signature.
  • You cannot write new T() or new T[10].
  • x instanceof List<String> cannot be checked. x instanceof List<?> can.
Same erasure, so a name clash · ❌ Does not compile
class Main {
    void m(List<String> l) { }
    void m(List<Integer> l) { }
}
❌ Compile error
name clash: m(List<Integer>) and m(List<String>) have the same erasure
T is unknown at run time · ❌ Does not compile
class Factory<T> {
    T make() { return new T(); }
}
❌ Compile error
unexpected type
required: class
found:    type parameter T
where T is a type-variable:
T extends Object declared in class Factory
Part 8

⚠️Raw types and legacy code

A generic class used without type arguments, like plain ArrayList, is a raw type. Raw types exist so that pre Java 5 code still compiles, and the compiler only warns about them.

Heap pollution: the crash happens far from the mistake · 💥 Crashes at run time
class Main {
    static void legacyAdd(List list) { list.add(10); }        // old code, raw type
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("Asha");
        legacyAdd(names);                                      // compiles with a warning only
        System.out.println(names);                             // still fine: [Asha, 10]
        String second = names.get(1);                          // boom, here
    }
}
Output before the crash
[Asha, 10]
💥 Runtime error
Exception in thread "main" java.lang.ClassCastException: class java.lang.Integer cannot be cast to class java.lang.String (java.lang.Integer and java.lang.String are in module java.base of loader 'bootstrap')
Never ignore "unchecked" warnings. Wrap risky legacy calls, or check the contents before trusting them.
