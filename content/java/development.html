Part 1

🧱Compiling with javac

javac is the Java compiler. It reads .java source files and writes .class files containing bytecode, which any JVM can run.

Here is a tiny project with two classes in the package com.shop:

Two classes in one package · ▶ Runs
// File: com/shop/Price.java
package com.shop;
public class Price {
    public static double withTax(double amount) { return amount * 1.18; }
}
// File: com/shop/App.java
package com.shop;
public class App {
    public static void main(String[] args) {
        System.out.println("Total: " + Price.withTax(100));
    }
}
Output
Total: 118.0

The -d option tells javac where to put the class files. It creates folders that match the package names automatically.

$ javac -d out src/com/shop/*.java
$ find out -type f
out/com/shop/App.class
out/com/shop/Price.class
CommandMeaning
javac A.javacompile one file, class file goes next to it
javac A.java B.javacompile several files
javac *.javacompile every .java file in the folder
javac -d out A.javaput class files under out, in package folders
javac -cp lib.jar A.javacompile against classes found in lib.jar
javac --release 17 A.javaproduce class files that run on Java 17 and later
javac works with file names, so you write App.java. The java launcher works with class names, so you write com.shop.App.
Part 2

🚀Running with java

The java command starts a JVM, loads the class you name, and calls its main method. A class in a package must be given by its fully qualified name.

$ java -cp out com.shop.App
Total: 118.0

Command line arguments

Words after the class name arrive in main as the String[] args array. They are always Strings, so numbers must be converted.

java Main Asha 3 4 · ▶ Runs
class Main {
    public static void main(String[] args) {
        System.out.println("arguments: " + args.length);
        System.out.println("hello " + args[0]);
        int sum = Integer.parseInt(args[1]) + Integer.parseInt(args[2]);
        System.out.println("3 + 4 as numbers = " + sum + ", as text = " + args[1] + args[2]);
    }
}
Output
arguments: 3
hello Asha
3 + 4 as numbers = 7, as text = 34
An argument containing spaces needs quotes: java Main "New Delhi" passes one argument, not two.

Common launch errors

$ java Test
Error: Main method not found in class Test, please define the main method as:
   public static void main(String[] args)
or a JavaFX application class must extend javafx.application.Application

The class compiled fine, but it has no main method. That is a run time problem, not a compile time one.

$ java com.shop.App
Error: Could not find or load main class com.shop.App
Caused by: java.lang.ClassNotFoundException: com.shop.App

The class files are in out, but the JVM searched only the current folder. The next section fixes this with the classpath.

Part 3

🧭The classpath

The classpath is the list of places where javac and java look for classes: folders and JAR files. It can be set in three ways.

WayExampleScope
Command line optionjava -cp out com.shop.Appthis one command only (recommended)
Environment variableexport CLASSPATH=outevery command in that terminal
Nothing setjava Appthe current folder only
Entries are separated by : on Linux and macOS, and by ; on Windows. A single dot . means the current folder. Once you give -cp, the current folder is no longer included unless you add the dot.

A worked example

Bill.java uses com.shop.Price, which lives inside shop.jar.

$ javac Bill.java
Bill.java:1: error: package com.shop does not exist
import com.shop.Price;
               ^
Bill.java:4: error: cannot find symbol
        System.out.println("Bill: " + Price.withTax(250));
                                      ^
  symbol:   variable Price
  location: class Bill
2 errors

$ javac -cp ../lib/shop.jar Bill.java          compiles now

$ java -cp ../lib/shop.jar Bill
Error: Could not find or load main class Bill
Caused by: java.lang.ClassNotFoundException: Bill

$ java -cp .:../lib/shop.jar Bill
Bill: 295.0

$ java Bill
Exception in thread "main" java.lang.NoClassDefFoundError: com/shop/Price
	at Bill.main(Bill.java:4)
Caused by: java.lang.ClassNotFoundException: com.shop.Price

ClassNotFoundException

The class you asked for by name, such as the main class, is not on the classpath.

NoClassDefFoundError

A class was present when the code was compiled, but is missing now that it runs.

The four cases above are a favourite exam pattern: which command compiles, which runs, and which error each mistake produces.

A JAR (Java ARchive) packs many class files and resources into one file. It uses the zip format. Libraries are shared as JARs, and a whole application can be one JAR.

An executable JAR

Add a manifest line that names the main class. Then java -jar can start it without any class name or classpath.

$ cat manifest.txt
Main-Class: com.shop.App

$ jar -cvfm app.jar manifest.txt -C out .
added manifest

adding: com/shop/(in = 0) (out= 0)(stored 0%)
adding: com/shop/App.class(in = 905) (out= 511)(deflated 43%)

 inflated: com/shop/App.class
 inflated: com/shop/Price.class
The manifest file must end with a newline. Without it, the last line, often the Main-Class line, is silently ignored.
When you use java -jar, the -cp option and the CLASSPATH variable are ignored. Extra libraries must be listed in the manifest's Class-Path line.
Part 5

🏷️System properties

A system property is a name and value pair available to the whole program. The JVM sets many of them, and you can add your own with -D on the command line, before the class name.

java -Dcourse=Java -Dseats=60 Main · ▶ Runs
class Main {
    public static void main(String[] args) {
        System.out.println(System.getProperty("course"));
        System.out.println(System.getProperty("level", "beginner"));   // default when missing
        System.out.println(Integer.getInteger("seats", 30));
        System.out.println(System.getProperty("missing"));
    }
}

Part 6

🪆JDK, JRE and JVM

JVM

The Java Virtual Machine runs bytecode. There is a different JVM for each operating system and processor, which is what makes the same class file run everywhere.

JRE

The Java Runtime Environment is the JVM plus the standard library classes. Enough to run programs.

JDK

The Java Development Kit is the JRE plus the developer tools: javac, jar, javadoc, jshell, jdb and more.

JDK = JRE + development tools and JRE = JVM + library classes
Since Java 11, Oracle and most vendors ship only the JDK. To deliver a small runtime with an application, developers build one with the jlink tool instead of installing a separate JRE.

Part 7

🆕Modern shortcuts

Run a source file directly (Java 11)

For a small program you can skip javac. The launcher compiles the file in memory and runs it.

$ java Hello.java Asha
Hello, Asha

$ java -Dcourse=Java -Dseats=60 Props.java
Java
beginner
60
Java 22 extended this to programs made of several source files in the same folder tree.

jshell (Java 9)

An interactive prompt for trying code one line at a time. No class and no main method are needed.

$ jshell
jshell> int marks = 88
marks ==> 88
jshell> marks >= 35 ? "pass" : "fail"
$2 ==> "pass"
jshell> /exit

Look inside class files

$ javap -cp out com.shop.Price
Compiled from "Price.java"
public class com.shop.Price {
  public com.shop.Price();
  public static double withTax(double);
}

javap shows the members of a compiled class. It also reveals what the compiler added, such as the default constructor above.

Real projects use a build tool such as Maven or Gradle. It downloads libraries, sets the classpath, compiles, tests and builds the JAR with one command. The commands on this page are what those tools run underneath.
