Java moves fast: a release every six months and a long term support version every two years. Part 1

🚆The release train, LTS and preview features

Java ships a new version every six months, in March and September. Java 25 (September 2025) is the latest long term support (LTS) release, Java 26 came in March 2026 and Java 27 in September 2026. Most companies run an LTS in production and try the newer releases in CI.

A preview feature is complete but may still change, so javac and java refuse it unless you pass --enable-preview. Use previews to learn and give feedback, not in production code.

Preview features need a flag at compile time and at run time · 🖥️ Run in a terminal · ☕ JDK 27
📄 Main.java
void main() {
    // Java 27 preview (JEP 531): computed once, on first use, then treated as a constant by the JVM
    LazyConstant<String> config = LazyConstant.of(() -> {
        IO.println("reading config file...");
        return "env=prod";
    });
    IO.println("app started");
    IO.println(config.get());
    IO.println(config.get());
}
Terminal

$ javac --release 27 --enable-preview Main.java
$ java --enable-preview Main

Part 2

🧵Java 21 LTS: sequenced collections

Java 21 brought virtual threads, record patterns and pattern matching for switch, each covered in its own chapter. One small change you will use daily is sequenced collections. Before Java 21, getting the last element of a list was list.get(list.size() - 1), and for a LinkedHashSet there was no simple way at all.

Sequenced collections: getFirst, getLast and reversed (Java 21) · ▶ Runs · ☕ JDK 25
void main() {
    // Java 21 (JEP 431): one set of methods for every ordered collection
    List<String> queue = new ArrayList<>(List.of("login", "search", "cart"));
    queue.addFirst("health");
    queue.addLast("pay");
    IO.println(queue.getFirst() + " ... " + queue.getLast());
    IO.println("reversed view: " + queue.reversed());

    LinkedHashMap<String, Integer> visits = new LinkedHashMap<>();
    visits.put("home", 10);
    visits.put("cart", 4);
    visits.putFirst("landing", 25);              // insert at the front
    IO.println("first entry: " + visits.firstEntry() + ", last: " + visits.lastEntry());

    LinkedHashSet<String> tags = new LinkedHashSet<>(List.of("new", "sale", "eco"));
    IO.println("removed last tag: " + tags.removeLast() + ", left: " + tags);
}
Output
health ... pay
reversed view: [pay, cart, search, login, health]
first entry: landing=25, last: cart=4
removed last tag: eco, left: [new, sale]

At work: reading the latest event from an ordered log, showing recent searches newest first with reversed(), or evicting the oldest entry from a LinkedHashMap cache with pollFirstEntry().

🔗Java 22 and 23: native code, multi file launch, Markdown docs

The foreign function and memory API (JEP 454, final in Java 22) lets Java call C libraries and work with memory outside the heap safely, replacing most JNI code. Database drivers, machine learning libraries and image tools use it to reach native code.

The foreign function and memory API calls C directly (Java 22) · 🖥️ Run in a terminal · ☕ JDK 25
📄 Main.java
import java.lang.foreign.*;
import java.lang.invoke.MethodHandle;

void main() throws Throwable {
    // Java 22 (JEP 454): call the C library function strlen without writing any C or JNI code
    Linker linker = Linker.nativeLinker();
    MethodHandle strlen = linker.downcallHandle(
            linker.defaultLookup().find("strlen").orElseThrow(),
            FunctionDescriptor.of(ValueLayout.JAVA_LONG, ValueLayout.ADDRESS));

    try (Arena arena = Arena.ofConfined()) {               // native memory, freed when the block ends
        MemorySegment text = arena.allocateFrom("Hello from C");
        IO.println("strlen says " + (long) strlen.invokeExact(text));
    }
}
Terminal
$ java Main.java
$ java --enable-native-access=ALL-UNNAMED Main.java
Terminal output

Calling native code can crash the JVM, so it counts as a restricted operation. Today it prints a warning. A future release will block it unless the application allows it with --enable-native-access.

Java 11 could already run one source file with java Hello.java. Java 22 (JEP 458) extends that to programs made of several files, which is handy for scripts and small tools that grow.

Part 4

🔐Java 24: quantum safe cryptography

Big quantum computers could one day break RSA and elliptic curve keys. Attackers can record encrypted traffic today and decrypt it later. Java 24 added the NIST standard algorithms that resist this: ML-KEM for agreeing on keys (JEP 496) and ML-DSA for signatures (JEP 497).

Post quantum key exchange and signatures (Java 24) · ▶ Runs · ☕ JDK 25
import javax.crypto.*;
import java.security.*;
import java.util.*;

void main() throws Exception {
    // Java 24 (JEP 496): ML-KEM agrees on a secret key in a way quantum computers cannot break
    KeyPair server = KeyPairGenerator.getInstance("ML-KEM").generateKeyPair();
    KEM kem = KEM.getInstance("ML-KEM");
    KEM.Encapsulated sent = kem.newEncapsulator(server.getPublic()).encapsulate();   // client side
    SecretKey clientKey = sent.key();
    SecretKey serverKey = kem.newDecapsulator(server.getPrivate()).decapsulate(sent.encapsulation());   // server side
    IO.println("bytes sent over the network: " + sent.encapsulation().length);
    IO.println("both sides got the same AES key? " + Arrays.equals(clientKey.getEncoded(), serverKey.getEncoded()));

    // Java 24 (JEP 497): ML-DSA signatures
    KeyPair signer = KeyPairGenerator.getInstance("ML-DSA").generateKeyPair();
    Signature sig = Signature.getInstance("ML-DSA");
    sig.initSign(signer.getPrivate());
    sig.update("invoice 42: 1500 rupees".getBytes());
    byte[] signature = sig.sign();
    sig.initVerify(signer.getPublic());
    sig.update("invoice 42: 9500 rupees".getBytes());         // someone changed the amount
    IO.println("signature of " + signature.length + " bytes still valid after tampering? " + sig.verify(signature));
}
Output
bytes sent over the network: 1088
both sides got the same AES key? true
signature of 3309 bytes still valid after tampering? false

Java 24 also brought stream gatherers and virtual threads that no longer get pinned by synchronized, both covered in earlier chapters, the ahead of time cache from the JVM chapter, and the final removal of the Security Manager's ability to be turned on (JEP 486).

✨Java 25 LTS: simpler programs and safer constructors

Java 25 made starting with Java much simpler. Compact source files and instance main methods (JEP 512) remove the class, static and String[] args ceremony, and the new IO class reads and prints text without System.out or a Scanner.

Compact source files, instance main and IO (Java 25) · 🖥️ Run in a terminal · ☕ JDK 25
📄 Hello.java
void main() {
    String name = IO.readln("Your name: ");
    IO.println("Hello, " + name + "! This is the whole program.");
}
Terminal
$ java Hello.java
Terminal output
Your name: Hello, Asha! This is the whole program.

Flexible constructor bodies (JEP 513) allow statements before super(...). Arguments can now be checked before the parent class does any work, and fields can be set early so the parent never sees them half initialised.

Flexible constructor bodies: check arguments before super (Java 25) · ▶ Runs · ☕ JDK 25
class Person {
    final String name;
    Person(String name) {
        System.out.println("Person stores the name");
        this.name = name;
    }
}

class Employee extends Person {
    final int age;

    Employee(String name, int age) {
        if (age < 18) throw new IllegalArgumentException("too young: " + age);   // Java 25: allowed before super
        this.age = age;                    // fields of this class may be set before super too
        super(name.strip());
    }
}

void main() {
    IO.println(new Employee("  Asha ", 29).name);
    try {
        new Employee("Ravi", 15);
    } catch (IllegalArgumentException e) {
        IO.println("rejected before Person ran: " + e.getMessage());
    }
}
Output
Person stores the name
Asha
rejected before Person ran: too young: 15

The Key Derivation Function API (JEP 510) turns one master secret into many separate keys, one per tenant or per purpose, which is how modern TLS and secret managers work.

Deriving keys with the KDF API (Java 25) · ▶ Runs · ☕ JDK 25
import javax.crypto.*;
import javax.crypto.spec.HKDFParameterSpec;
import java.util.HexFormat;

void main() throws Exception {
    // Java 25 (JEP 510): the Key Derivation Function API, here with HKDF
    KDF hkdf = KDF.getInstance("HKDF-SHA256");
    var spec = HKDFParameterSpec.ofExtract()
            .addIKM("master-secret-from-the-vault".getBytes())
            .addSalt("tenant-42".getBytes())
            .thenExpand("orders-db-encryption".getBytes(), 16);   // 16 bytes = an AES-128 key
    SecretKey key = hkdf.deriveKey("AES", spec);
    IO.println(key.getAlgorithm() + " key: " + HexFormat.of().formatHex(key.getEncoded()));
    IO.println("same inputs always give the same key, so it never needs to be stored");
}
Output
AES key: cdef4f32b574c5cb632b4566d6bd4fbe
same inputs always give the same key, so it never needs to be stored

Java 25 also made scoped values (concurrency chapter), module import declarations (modules chapter) and compact object headers (JVM chapter) final.

Part 6

🧪Java 26 and 27: what is final and what to try

Java 26 added HTTP/3 to HttpClient (JDBC and HTTP chapter), warns before final fields can be changed by reflection (modules chapter), removed the old Applet API (JEP 504) and let the AOT cache work with every garbage collector (JVM chapter). Java 27 made G1 the default everywhere and compact object headers the default (JVM chapter), and switched TLS to a quantum safe hybrid key exchange:

Hybrid post quantum TLS is on by default (Java 27) · ▶ Runs · ☕ JDK 27
import javax.net.ssl.SSLContext;
import java.util.List;

void main() throws Exception {
    // Java 27 (JEP 527): TLS 1.3 offers a hybrid of X25519 and ML-KEM first
    List<String> groups = List.of(SSLContext.getDefault().getDefaultSSLParameters().getNamedGroups());
    IO.println("first choice: " + groups.getFirst());
    IO.println("all groups offered: " + groups);
}
Output
first choice: X25519MLKEM768
all groups offered: [X25519MLKEM768, x25519, secp256r1, secp384r1, secp521r1, x448, ffdhe2048, ffdhe3072, ffdhe4096]

X25519MLKEM768 combines a classic elliptic curve exchange with ML-KEM, so the connection stays safe if either one is broken. Servers that do not support it simply pick the next group, so nothing breaks. The Java 25 update used to build this page offers it first too, as Oracle has brought it to recent Java 25 updates.

The PEM API (third preview, JEP 538) reads and writes the text format of keys and certificates that every server uses, a job that needed Bouncy Castle or hand written Base64 code before.

PEM encoding without Bouncy Castle (Java 27 preview) · ▶ Runs · ☕ JDK 27 preview
import java.security.*;

void main() throws Exception {
    // Java 27 preview (JEP 538): read and write the PEM text format used by certificates and keys
    KeyPair kp = KeyPairGenerator.getInstance("EC").generateKeyPair();
    String pem = PEMEncoder.of().encodeToString(kp.getPublic());
    List<String> lines = pem.lines().toList();
    IO.println(lines.getFirst());
    IO.println("... " + (lines.size() - 2) + " lines of Base64 ...");
    IO.println(lines.getLast());

    PublicKey back = PEMDecoder.of().decode(pem, PublicKey.class);
    IO.println("same key after the round trip? " + back.equals(kp.getPublic()));
}
Terminal
$ java --enable-preview Main.java
Output

... 3 lines of Base64 ...
-----END PUBLIC KEY-----
same key after the round trip? true

🎬Real world scenario: upgrading a service from Java 17 to Java 25

The situationA payments service runs on Java 17. The team wants virtual threads, sequenced collections and the startup gains of Java 25, without surprises in production.

Step one is finding code that relies on JDK internals, because strong encapsulation and the removal of old APIs are what usually break upgrades.

Finding uses of JDK internals before an upgrade · 🖥️ Run in a terminal · ☕ JDK 25
📄 Main.java
class Main {
    public static void main(String[] args) throws Exception {
        var f = sun.misc.Unsafe.class.getDeclaredField("theUnsafe");   // an old trick many libraries used
        System.out.println("found " + f.getName());
    }
}
Terminal
$ javac Main.java
$ jdeps --jdk-internals Main.class
Terminal output
Main.java:3: warning: Unsafe is internal proprietary API and may be removed in a future release
Main.class -> jdk.unsupported
   Main                                               -> sun.misc.Unsafe                                    JDK internal API (jdk.unsupported)
StepWhy
Run jdeps --jdk-internals and jdeprscanfind internal and deprecated API use early
Upgrade build plugins, Lombok, Mockito, ByteBuddy, Springlibraries that generate bytecode must know the new class file version
Build and test with the new JDK in CI firstcatch behaviour changes before production
Read the release notes for removed optionsfor example the Security Manager can no longer be enabled since Java 24
Then adopt features one by onevirtual threads for blocking I/O, records for DTOs, pattern matching for parsing
