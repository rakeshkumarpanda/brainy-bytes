🏷️var: let the compiler write the type

var (Java 10) asks the compiler to work out the type of a local variable from the value on the right. The variable still has one fixed type. It is not like JavaScript, where a variable can hold anything.

var lets the compiler write the type for you · ▶ Runs · ☕ JDK 25
import java.util.*;

class Main {
    public static void main(String[] args) {
        var browser = "chromium";                               // String
        var retries = 3;                                        // int
        var results = new HashMap<String, List<Integer>>();     // no need to repeat the long type
        results.computeIfAbsent("login", k -> new ArrayList<>()).add(420);

        for (var entry : results.entrySet()) {
            System.out.println(entry.getKey() + " -> " + entry.getValue());
        }
        System.out.println(browser + " x" + retries);
        System.out.println(((Object) retries).getClass().getSimpleName());   // still a real, fixed type
    }
}
Output
login -> [420]
chromium x3
Integer
Where var is not allowed · ❌ Does not compile · ☕ JDK 25
class Main {
    public static void main(String[] args) {
        var nothing;                     // needs an initial value
        var empty = null;                // null has no useful type
        var x = 10;
        x = "ten";                       // the type is fixed once chosen
    }
}
❌ Compile error
Line 3: cannot infer type for local variable nothing
(cannot use 'var' on variable without initializer)
Line 4: cannot infer type for local variable empty
(variable initializer is 'null')
Line 6: incompatible types: String cannot be converted to int
Why

Fields, method parameters and return types cannot use var either. It is only for local variables.

Use var when the type is obvious from the right side, such as var users = new ArrayList<User>(). Keep the type when it helps the reader, such as int timeoutMs = config.get("timeout").
Part 2

📜Text blocks

A text block (Java 15) is a string that spans several lines between triple quotes. Indentation shared by all lines is removed, line breaks are kept, and double quotes need no escaping. It is perfect for JSON request bodies, SQL and expected HTML in tests.

Text blocks for JSON bodies and SQL · ▶ Runs · ☕ JDK 25
class Main {
    public static void main(String[] args) {
        String name = "Asha";
        int qty = 2;

        // Java 15: a text block keeps the layout, and quotes need no escaping
        String body = """
            {
              "customer": "%s",
              "items": [ { "sku": "TSHIRT-RED-M", "qty": %d } ],
              "note": "Ring the bell"
            }
            """.formatted(name, qty);
        System.out.print(body);

        String sql = """
            SELECT id, total
            FROM orders
            WHERE status = 'PAID' \
            AND total > 500
            """;                                  // a backslash at the end of a line joins it with the next
        System.out.print(sql);
        System.out.println("""
            trailing space kept here:\s|""");   // \s keeps one space that would otherwise be trimmed
    }
}
Output
{
  "customer": "Asha",
  "items": [ { "sku": "TSHIRT-RED-M", "qty": 2 } ],
  "note": "Ring the bell"
}
SELECT id, total
FROM orders
WHERE status = 'PAID' AND total > 500
trailing space kept here: |
Two escapes exist only for text blocks: a backslash at the end of a line joins it with the next line, and \s keeps a space that would otherwise be trimmed. formatted(...) fills in %s and %d placeholders.

🔀Switch expressions

The old switch statement falls through to the next case unless you remember break. That single missing word has caused many real bugs.

The old switch and its fall through bug · ▶ Runs · ☕ JDK 25
class Main {
    public static void main(String[] args) {
        int status = 404;
        String kind;
        switch (status) {                    // old statement switch: easy to forget a break
            case 200:
            case 201:
                kind = "success";
            case 404:
                kind = "not found";
                break;
            default:
                kind = "other";
        }
        System.out.println(kind);
        status = 200;
        switch (status) { case 200: case 201: kind = "success"; case 404: kind = "not found"; break; default: kind = "other"; }
        System.out.println(kind + "   <- 200 fell through into the next case");
    }
}
Output
not found
not found   <- 200 fell through into the next case

Java 14 made switch an expression: it produces a value, the arrow form never falls through, one case can list several labels, and yield returns a value from a block. Over an enum, covering every constant means no default is needed, and the compiler complains when a new constant is added.

Switch expressions: arrows, many labels, yield and exhaustive enums · ▶ Runs · ☕ JDK 25
class Main {
    enum Env { DEV, QA, STAGING, PROD }

    public static void main(String[] args) {
        for (int status : new int[]{200, 201, 404, 503}) {
            String kind = switch (status) {          // Java 14: switch is an expression with a value
                case 200, 201, 204 -> "success";     // several labels, no fall through
                case 404 -> "not found";
                default -> {
                    String range = status >= 500 ? "server error" : "other";
                    yield range;                     // yield gives the value of a block
                }
            };
            System.out.println(status + " " + kind);
        }

        Env env = Env.QA;
        int workers = switch (env) {                 // no default needed: every enum constant is covered
            case DEV -> 1;
            case QA, STAGING -> 4;
            case PROD -> 16;
        };
        System.out.println(env + " workers=" + workers);
    }
}
Output
200 success
201 success
404 not found
503 server error
QA workers=4

📇Records

A record (Java 16) is a class whose job is to carry data. From one line, Java writes the private final fields, the constructor, an accessor per field (named name(), not getName()), and equals, hashCode and toString based on all fields.

Records: data carriers with validation · 💥 Crashes at run time · ☕ JDK 25
import java.util.*;

class Main {
    // One line gives: private final fields, a constructor, accessors, equals, hashCode and toString
    record Product(String sku, String name, double price) {
        Product {                                         // compact constructor: validate the input
            if (price < 0) throw new IllegalArgumentException("price must not be negative: " + price);
            name = name.strip();                          // you may normalise parameters before they are stored
        }
        Product withPrice(double p) { return new Product(sku, name, p); }   // "withers" return a changed copy
        static Product free(String sku) { return new Product(sku, "Gift", 0); }
    }

    public static void main(String[] args) {
        Product a = new Product("TSHIRT-RED-M", "  Red T-shirt ", 499.0);
        Product b = new Product("TSHIRT-RED-M", "Red T-shirt", 499.0);
        System.out.println(a);
        System.out.println(a.name() + " costs " + a.price());
        System.out.println("equal by value: " + a.equals(b) + ", same object: " + (a == b));
        System.out.println(new HashSet<>(List.of(a, b)).size() + " product in the set");
        System.out.println(a.withPrice(399.0));
        System.out.println(Product.free("GIFT-01"));
        new Product("MUG", "Mug", -5);
    }
}
Output before the crash
Product[sku=TSHIRT-RED-M, name=Red T-shirt, price=499.0]
Red T-shirt costs 499.0
equal by value: true, same object: false
1 product in the set
Product[sku=TSHIRT-RED-M, name=Red T-shirt, price=399.0]
Product[sku=GIFT-01, name=Gift, price=0.0]
💥 Runtime error
Exception in thread "main" java.lang.IllegalArgumentException: price must not be negative: -5.0

The compact constructor (no parameter list) is where you validate and normalise. Records are final, cannot extend another class, and cannot add instance fields, but they can implement interfaces and have methods.

Records are only shallowly immutable · ▶ Runs · ☕ JDK 25
import java.util.*;

class Main {
    record Order(String id, List<String> items) {
        Order {
            items = List.copyOf(items);       // defensive copy: callers cannot change the order later
        }
    }
    record Leaky(String id, List<String> items) {}

    public static void main(String[] args) {
        List<String> cart = new ArrayList<>(List.of("mug"));
        Order safe = new Order("ORD-1", cart);
        Leaky leaky = new Leaky("ORD-2", cart);
        cart.add("laptop");                    // the caller changes its own list afterwards
        System.out.println(safe);
        System.out.println(leaky + "   <- changed from outside");
    }
}
Output
Order[id=ORD-1, items=[mug]]
Leaky[id=ORD-2, items=[mug, laptop]]   <- changed from outside
Records are ideal for API test models: request bodies, expected responses, test data rows. Jackson 2.12 and later can read JSON straight into records, and two records with the same values are equal, which makes assertions simple.

🔒Sealed classes and interfaces

A sealed type (Java 17) lists exactly which classes may extend or implement it, using permits. It is the middle ground between final (nobody) and a normal class (anybody). Because the compiler knows the full list, a switch over a sealed type can be checked for completeness.

Sealed interfaces list every allowed subtype · ▶ Runs · ☕ JDK 25
class Main {
    // Only these three may implement Payment. The compiler knows the full list.
    sealed interface Payment permits Card, Upi, Wallet {}
    record Card(String last4, double amount) implements Payment {}
    record Upi(String vpa, double amount) implements Payment {}
    record Wallet(String provider, double amount) implements Payment {}

    static double fee(Payment p) {
        return switch (p) {                     // no default: the switch is checked for completeness
            case Card c -> c.amount() * 0.02;
            case Upi u -> 0;
            case Wallet w -> w.amount() * 0.01;
        };
    }

    public static void main(String[] args) {
        System.out.println(fee(new Card("4242", 1000)));
        System.out.println(fee(new Upi("asha@okbank", 1000)));
        System.out.println(fee(new Wallet("PayFast", 1000)));
    }
}
Output
20.0
0.0
10.0
Forget a case and the compiler tells you · ❌ Does not compile · ☕ JDK 25
class Main {
    sealed interface Payment permits Card, Upi, Wallet {}
    record Card(double amount) implements Payment {}
    record Upi(double amount) implements Payment {}
    record Wallet(double amount) implements Payment {}

    static double fee(Payment p) {
        return switch (p) {                     // Wallet was forgotten
            case Card c -> c.amount() * 0.02;
            case Upi u -> 0;
        };
    }

    public static void main(String[] args) { }
}
❌ Compile error
Line 8: the switch expression does not cover all possible input values

Every permitted subclass must say what happens next: final stops there, sealed gives its own list, and non-sealed opens the hierarchy again.

final, sealed and non-sealed subclasses · ▶ Runs · ☕ JDK 25
class Main {
    sealed abstract static class Account permits Savings, Current, Business {}
    static final class Savings extends Account {}          // final: no more subclasses
    static sealed class Current extends Account permits StudentCurrent {}   // sealed again, with its own list
    static final class StudentCurrent extends Current {}
    static non-sealed class Business extends Account {}    // open again: anyone may extend it
    static class StartupBusiness extends Business {}

    public static void main(String[] args) {
        Account[] all = { new Savings(), new StudentCurrent(), new StartupBusiness() };
        for (Account a : all) System.out.println(a.getClass().getSimpleName() + " is an Account");
        System.out.println(Account.class.isSealed() + " " + java.util.Arrays.toString(
            java.util.Arrays.stream(Account.class.getPermittedSubclasses()).map(Class::getSimpleName).toArray()));
    }
}
Output
Savings is an Account
StudentCurrent is an Account
StartupBusiness is an Account
true [Savings, Current, Business]

🔍Pattern matching for instanceof

The old pattern was test, then cast, then use. Since Java 16, o instanceof String s does all three: if the test passes, s is a String variable ready to use. The variable is only in scope where the test is known to be true, a rule called flow scoping.

Pattern matching for instanceof · ▶ Runs · ☕ JDK 25
class Main {
    static String describe(Object o) {
        // Old style: test, then cast
        if (o instanceof String) {
            String s = (String) o;
            return "old: text of length " + s.length();
        }
        // Java 16: test and bind a variable in one step
        if (o instanceof Integer n && n > 100) {           // n can be used right away in the same condition
            return "big number " + n;
        }
        if (!(o instanceof java.util.List<?> list)) {
            return "something else: " + o;
        }
        return "a list with " + list.size() + " items";    // list is in scope here because of the negation above
    }

    public static void main(String[] args) {
        System.out.println(describe("hello"));
        System.out.println(describe(500));
        System.out.println(describe(java.util.List.of(1, 2)));
        System.out.println(describe(7));
    }
}
Output
old: text of length 5
big number 500
a list with 2 items
something else: 7

🎯Pattern matching for switch

Since Java 21, a switch can test the type of a value, add a condition with when (a guard), and even handle null as a case. Cases are checked from top to bottom and the first match wins.

Pattern matching for switch with guards and null · ▶ Runs · ☕ JDK 25
class Main {
    static String classify(Object o) {
        return switch (o) {
            case null -> "null, handled without a NullPointerException";
            case Integer i when i < 0 -> "negative int " + i;
            case Integer i -> "int " + i;
            case String s when s.isBlank() -> "blank text";
            case String s -> "text \"" + s + "\"";
            case int[] arr -> "int array of " + arr.length;
            default -> "other: " + o.getClass().getSimpleName();
        };
    }

    public static void main(String[] args) {
        Object[] inputs = { -4, 42, "   ", "PASS", new int[]{1, 2, 3}, 3.14, null };
        for (Object o : inputs) System.out.println(classify(o));
    }
}
Output
negative int -4
int 42
blank text
text "PASS"
int array of 3
other: Double
null, handled without a NullPointerException
Order matters: a case that can never match is an error · ❌ Does not compile · ☕ JDK 25
class Main {
    static String f(Object o) {
        return switch (o) {
            case CharSequence cs -> "chars";
            case String s -> "string";          // can never match: String is a CharSequence, and that case came first
            default -> "other";
        };
    }
    public static void main(String[] args) { }
}
❌ Compile error
Line 5: this case label is dominated by a preceding case label

🪆Record patterns and unnamed variables

A record pattern (Java 21) matches a record and pulls its fields out into variables in the same step, and patterns can be nested. Combined with sealed types and switch, this style is called data oriented programming.

Record patterns take a record apart · ▶ Runs · ☕ JDK 25
class Main {
    record Point(int x, int y) {}
    sealed interface Shape permits Circle, Rect {}
    record Circle(Point centre, int r) implements Shape {}
    record Rect(Point topLeft, Point bottomRight) implements Shape {}

    static int area(Shape s) {
        return switch (s) {
            case Circle(Point c, int r) -> (int) Math.round(Math.PI * r * r);
            // nested record pattern: pull the numbers straight out of both points
            case Rect(Point(var x1, var y1), Point(var x2, var y2)) -> Math.abs(x2 - x1) * Math.abs(y2 - y1);
        };
    }

    public static void main(String[] args) {
        System.out.println(area(new Circle(new Point(0, 0), 10)));
        System.out.println(area(new Rect(new Point(1, 1), new Point(4, 5))));

        Object o = new Point(3, 4);
        if (o instanceof Point(int x, int y) && x < y) {      // record patterns work with instanceof too
            System.out.println("point below the diagonal: " + x + "," + y);
        }
    }
}
Output
314
12
point below the diagonal: 3,4

Java 22 added the unnamed variable _ for things you must declare but never use: a loop variable, a caught exception, a lambda parameter or a record field you do not care about.

Unnamed variables and patterns with _ (Java 22) · ▶ Runs · ☕ JDK 25
import java.util.*;

class Main {
    record Order(String id, String customer, double total) {}

    public static void main(String[] args) {
        List<Order> orders = List.of(new Order("A1", "asha", 900), new Order("A2", "ravi", 120));

        int count = 0;
        for (Order _ : orders) count++;                          // Java 22: the variable is not needed
        System.out.println(count + " orders");

        for (Order o : orders) {
            if (o instanceof Order(_, var who, var total) && total > 500) {   // ignore the id
                System.out.println("big order from " + who);
            }
        }
        try {
            Integer.parseInt("12a");
        } catch (NumberFormatException _) {                      // the exception itself is not used
            System.out.println("not a number");
        }
        Map<String, Integer> hits = new TreeMap<>();
        List.of("x", "y", "x").forEach(k -> hits.merge(k, 1, (a, _) -> a + 1));
        System.out.println(hits);
    }
}
Output
2 orders
big order from asha
not a number
{x=2, y=1}

🧪Primitive patterns (preview in Java 27)

Patterns so far only worked with objects. Primitive types in patterns, instanceof and switch (JEP 532, fifth preview in Java 27) lets you write case int c when c >= 500 and ask big instanceof int, which is true only when the value fits into an int without losing anything.

Primitive types in patterns (preview in Java 27) · ▶ Runs · ☕ JDK 27 preview
void main() {
    // Java 27 preview (JEP 532): patterns over primitive types
    int[] codes = {200, 302, 404, 503, 1000};
    for (int code : codes) {
        String text = switch (code) {
            case int c when c >= 200 && c < 300 -> "success";
            case int c when c >= 300 && c < 400 -> "redirect";
            case int c when c >= 400 && c < 500 -> "client error";
            case int c when c >= 500 && c < 600 -> "server error";
            case int c -> "not an HTTP status: " + c;
        };
        IO.println(code + " " + text);
    }

    // instanceof with a primitive type checks that the value fits without losing information
    long big = 3_000_000_000L, small = 42;
    IO.println((big instanceof int) + " " + (small instanceof int));
    double d = 2.5;
    IO.println(d instanceof int i ? "whole number " + i : "has a fraction: " + d);
}
Terminal
$ java --enable-preview Main.java
Output
200 success
302 redirect
404 client error
503 server error
1000 not an HTTP status: 1000
false true
has a fraction: 2.5
Preview features can still change. They need --enable-preview to compile and run, so keep them out of production code and use them to try ideas early.

🎬Real world scenario: modelling API outcomes

The situationAn API test client returned either a body or null, and errors were thrown as exceptions. Tests forgot to handle 503s and network resets, so failures in the nightly run were hard to read.
Real world: every API outcome as a sealed type · ▶ Runs · ☕ JDK 25
import java.util.*;

class Main {
    // How a test framework can model every possible API outcome
    sealed interface ApiResult<T> permits Ok, ClientError, ServerError, NetworkError {}
    record Ok<T>(int status, T body) implements ApiResult<T> {}
    record ClientError<T>(int status, String message) implements ApiResult<T> {}
    record ServerError<T>(int status) implements ApiResult<T> {}
    record NetworkError<T>(String reason) implements ApiResult<T> {}

    record Order(String id, double total) {}

    static String report(ApiResult<Order> r) {
        return switch (r) {
            case Ok(int s, Order(var id, var total)) when total == 0 -> "WARN " + s + " order " + id + " has a zero total";
            case Ok(var s, Order(var id, var total)) -> "PASS " + s + " order " + id + " total " + total;
            case ClientError(var s, var msg) -> "FAIL " + s + " client error: " + msg;
            case ServerError(var s) when s == 503 -> "RETRY service unavailable";
            case ServerError(var s) -> "FAIL " + s + " server error";
            case NetworkError(var why) -> "RETRY network: " + why;
        };
    }

    public static void main(String[] args) {
        List<ApiResult<Order>> results = List.of(
            new Ok<>(201, new Order("ORD-7", 1499.0)), new Ok<>(200, new Order("ORD-8", 0)),
            new ClientError<>(422, "qty must be at least 1"), new ServerError<>(503), new ServerError<>(500),
            new NetworkError<>("connection reset"));
        results.forEach(r -> System.out.println(report(r)));
    }
}
Output
PASS 201 order ORD-7 total 1499.0
WARN 200 order ORD-8 has a zero total
FAIL 422 client error: qty must be at least 1
RETRY service unavailable
FAIL 500 server error
RETRY network: connection reset

Every possible outcome is now a record that implements one sealed interface. The report switch must handle them all, guards pick out special cases such as a zero total or a 503, and nested record patterns read the order fields directly. When someone adds a Timeout outcome, every switch that ignores it stops compiling.
