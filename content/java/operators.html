Operators and Assignments

Operators are the verbs of Java. They add, compare, join and decide. A few of them have sneaky rules, and those rules are exactly what interviewers love to ask about.

Part 1

➕Increment and decrement

++ adds 1 to a variable and -- takes 1 away. Each comes in two flavours.

Pre: change first, then use

y = ++x; raises x, then gives the new value to y.

Post: use first, then change

y = x++; gives the old value to y, then raises x.
Expressionx beforex aftery
y = ++x;101111
y = x++;101110
y = --x;1099
y = x--;10910
See it happen · ▶ Runs
int x = 10;
int y = x++;
System.out.println("x = " + x + ", y = " + y);
int a = 10;
int b = ++a;
System.out.println("a = " + a + ", b = " + b);
Output
x = 11, y = 10
a = 11, b = 11

Rules

  1. They work only on variables, never on plain values. ++10 does not compile.
  2. They cannot be nested. ++(++x) does not compile, because the inner part produces a value, not a variable.
  3. They cannot change a final variable.
  4. They work on every primitive type except boolean, so a char or a double can be incremented too.
Not on a plain value · ❌ Does not compile
int y = ++10;
❌ Compile error
unexpected type
required: variable
found:    value
No nesting · ❌ Does not compile
int x = 4;
int y = ++(++x);
❌ Compile error
unexpected type
required: variable
found:    value
char and double can be incremented · ▶ Runs
char ch = 'a';
ch++;
double d = 10.5;
d++;
System.out.println(ch + " " + d);
Output
b 11.5

b++ is not the same as b = b + 1

Any arithmetic on byte, short or char produces an int. So b = b + 1 tries to put an int back into a byte and fails. b++ carries a hidden cast and works.

int result does not fit in a byte · ❌ Does not compile
byte b = 10;
b = b + 1;
❌ Compile error
incompatible types: possible lossy conversion from int to byte
b++ hides the cast · ▶ Runs
byte b = 10;
b++;               // means b = (byte)(b + 1)
System.out.println(b);
Output
11

Dividing by zero

Whole numbers have no way to show infinity, so integer division by zero throws ArithmeticException. Floating point numbers do have special values: Infinity, -Infinity and NaN (not a number).

Integer division by zero · 💥 Crashes at run time
System.out.println(10 / 0);
💥 Runtime error
Exception in thread "main" java.lang.ArithmeticException: / by zero
Floating point division by zero · ▶ Runs
System.out.println(10 / 0.0);
System.out.println(-10.0 / 0);
System.out.println(0.0 / 0);

The remainder operator %

a % b gives what is left after dividing. The sign of the answer always follows the left side.

Signs follow the dividend · ▶ Runs
System.out.println(17 % 5);
System.out.println(-17 % 5);
System.out.println(17 % -5);
System.out.println(5.5 % 2);
Output
2
-2
2
1.5
a % b = a − b × (a / b), where a / b is cut towards zero −17 % 5 = −17 − 5 × (−3) = −17 + 15 = −2
Integer overflow is silent. Integer.MAX_VALUE + 1 becomes Integer.MIN_VALUE without any error. Use Math.addExact or long when numbers can grow large.
Part 3

🔗String concatenation

The + operator is the only overloaded operator in Java. If at least one side is a String it joins text, otherwise it adds numbers. Java works from left to right, so the moment a String appears, every + after it joins text.

Where the String appears changes everything · ▶ Runs
int a = 10, b = 20, c = 30;
String d = "java";
System.out.println(a + b + c + d);
System.out.println(d + a + b + c);
System.out.println(a + b + d + c);
System.out.println(d + (a + b) + c);
Output
60java
java102030
30java30
java3030
a + b + c + d = ((10 + 20) + 30) + "java" = 60 + "java" = "60java" a + b + d + c = (30 + "java") + 30 = "30java" + 30 = "30java30"
The result of a join is a String · ❌ Does not compile
String s = "java";
int a = 10;
a = a + s;
❌ Compile error
incompatible types: String cannot be converted to int
Parentheses run first, so "Sum: " + (a + b) prints Sum: 30 while "Sum: " + a + b prints Sum: 1020.

== and != work on every primitive, including boolean, and also on object references.

💡Bitwise and boolean operators

>, >>>">

The operators & | ^ work on whole numbers bit by bit, and on booleans as logic. ~ flips every bit of a whole number. ! flips a boolean.

OperatorNameGives 1 (true) when
&ANDboth bits are 1
|ORat least one bit is 1
^XORthe bits are different
~complementflips every bit (integral types only)
!NOTflips a boolean (boolean only)
Bit by bit · ▶ Runs
System.out.println(4 & 5);
System.out.println(4 | 5);
System.out.println(4 ^ 5);
System.out.println(~4);
System.out.println(true ^ false);
System.out.println(!true);
Output
4
5
1
-5
true
false
4 = 1002, 5 = 1012 → 4 & 5 = 1002 = 4, 4 | 5 = 1012 = 5, 4 ^ 5 = 0012 = 1 ~x = −x − 1, so ~4 = −5

Why ~4 is −5: flipping all 32 bits of 4 gives a number whose first bit is 1, so it is negative. Negative numbers are stored in two's complement, and reading it back gives −5.

bad operand type boolean for unary operator '~'
! needs a boolean · ❌ Does not compile
System.out.println(!4);
❌ Compile error
bad operand type int for unary operator '!'

Shift operators

  • a << n moves bits left, which multiplies by 2n.
  • a >> n moves bits right and copies the sign bit, which divides by 2n rounding down.
  • a >>> n moves bits right and fills with zeros, so negative numbers become large positive ones.
Shifting · ▶ Runs

System.out.println(40 >> 2);
System.out.println(-16 >> 2);
System.out.println(-16 >>> 28);

Part 8

⚡Short-circuit operators

&& and || are the lazy cousins of & and |. They skip the right side when the left side already decides the answer.

& and |&& and ||
Right side evaluatedalwaysonly when needed
Speedslowerfaster
Works onbooleans and whole numbersbooleans only
Count the evaluations · ▶ Runs
int x = 10, y = 15;
if (++x < 10 & ++y > 15) x++;
else y++;
System.out.println(x + " " + y);

int p = 10, q = 15;
if (++p < 10 && ++q > 15) p++;
else q++;
System.out.println(p + " " + q);
Output
11 17
11 16

With &, both ++x and ++y run. With &&, ++p < 10 is already false, so ++q never runs.

Short-circuiting is how you guard against crashes: if (s != null && s.length() > 0) never calls length() on a null reference.
Part 9

🎭Type casting

There are two kinds of casting.

Implicit (widening)

The compiler does it for you when a smaller type goes into a bigger one. No information is lost.

int x = 'a'; double d = 10;

Explicit (narrowing)

You ask for it when a bigger type goes into a smaller one. Information may be lost.

byte b = (byte) 130; int i = (int) 9.99;
What gets lost · ▶ Runs
int x = 130;
byte b = (byte) x;
System.out.println(b);
double d = 130.456;
int i = (int) d;
byte b2 = (byte) d;
System.out.println(i + " " + b2);
System.out.println((int) -9.99);
Output
-126
130 -126
-9
  • From a whole number to a smaller whole number, Java keeps only the lowest bits.
  • From a decimal number to a whole number, the decimal part is cut off, not rounded. Use Math.round to round.
130 = 1000 00102 → as a byte: −128 + 2 = −126
Part 10

📝Assignment operators

There are three kinds of assignment.

  1. Simple: int x = 10;
  2. Chained: a = b = c = d = 20; works from right to left. All variables must already be declared.
  3. Compound: += -= *= /= %= &= |= ^= <<= >>= >>>=
Cannot declare and chain at once · ❌ Does not compile
int a = b = c = d = 20;
❌ Compile error
cannot find symbol
symbol:   variable b
Chained assignment · ▶ Runs
int a, b, c, d;
a = b = c = d = 20;
System.out.println(a + b + c + d);
Output
80
Every compound assignment hides a cast back to the type on the left. b += 1 means b = (byte)(b + 1).
Compound assignment casts quietly · ▶ Runs
byte b = 127;
b += 3;            // 130 does not fit, wraps around
System.out.println(b);
Output
-126
Right to left, one step at a time · ▶ Runs
int a, b, c, d;
a = b = c = d = 20;
a += b -= c *= d /= 2;
System.out.println(a + " " + b + " " + c + " " + d);
Output
-160 -180 200 10
d /= 2 → d = 10 c *= d → c = 20 × 10 = 200 b −= c → b = 20 − 200 = −180 a += b → a = 20 + (−180) = −160
Part 11

❓The conditional operator

The only ternary operator in Java takes three parts: a condition, a value for true and a value for false. It is a compact if else that produces a value.

Choose a value · ▶ Runs
int marks = 72;
String result = marks >= 35 ? "Pass" : "Fail";
System.out.println(result);
int x = 5;
String size = x > 10 ? "big" : x > 3 ? "medium" : "small";
System.out.println(size);
Output
Pass
medium
Nest it at most once. Beyond that a normal if else is kinder to the next reader.

🧭new, [ ] and the evaluation order

new creates objects and [] declares or indexes arrays. Java has no delete operator, because the garbage collector removes unused objects.

Precedence, from strongest to weakest

GroupOperators
Unary[] x++ x--, then ++x --x ~ !, then new and casts
Multiplicative* / %
Additive+ -
Shift<< >> >>>
Relational< <= > >= instanceof
Equality== !=
Bitwise&, then ^, then |
Short-circuit&&, then ||
Conditional?:
Assignment= += -= *= and the rest
Precedence decides how the expression is grouped. The operands are still evaluated strictly from left to right.
Left to right, then precedence · ▶ Runs
class Main {
    static int m(int i) {
        System.out.print(i + " ");
        return i;
    }
    public static void main(String[] args) {
        int r = m(1) + m(2) * m(3) / m(4) * m(5) + m(6);
        System.out.println("= " + r);
    }
}
Output
1 2 3 4 5 6 = 12

The methods are called in the order 1, 2, 3, 4, 5, 6. Only after that are the values combined using precedence.

1 + ((2 × 3) / 4) × 5 + 6 = 1 + (6 / 4) × 5 + 6 = 1 + 1 × 5 + 6 = 12
