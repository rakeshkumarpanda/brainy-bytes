Collections Framework

Arrays are fixed boxes. Collections are smart containers that grow, sort, search and remove duplicates for you. Choosing the right one is half of writing fast Java.

🧺Arrays versus collections

Arrays have three big limits: their size is fixed, they hold only one type, and they come with almost no ready-made methods. Collections fix all three.

List<String> guests = new ArrayList<>();

Collection (interface)

The root interface for a group of individual objects.

Collections (class)

A utility class full of static helpers such as sort, reverse and max.

Methods every Collection has

add, addAll, remove, removeAll, retainAll, clear, contains, containsAll, isEmpty, size, toArray and iterator. Collection has no method to get an element by position, because not every collection has positions.

System.out.println(a);
a.retainAll(List.of(1, 5, 6, 9));      // keep only these
System.out.println(a + " " + a.containsAll(List.of(1, 6)));

[1, 3, 5, 6]
[1, 5, 6] true
Part 3

📋The List interface

A List keeps elements in insertion order, gives every element an index, and allows duplicates and nulls.

Index based methods · ▶ Runs
List<String> l = new ArrayList<>(List.of("a", "b", "c", "b"));
l.add(1, "X");                     // insert at index 1
l.set(0, "A");                     // replace index 0
System.out.println(l + " " + l.get(2) + " " + l.indexOf("b") + " " + l.lastIndexOf("b"));
l.remove(0);                       // remove by index
l.remove("b");                     // remove the first "b" by value
System.out.println(l);
Output
[A, X, b, c, b] b 2 4
[X, c, b]
With a List<Integer>, remove(1) removes the element at index 1. To remove the value 1, write remove(Integer.valueOf(1)).
remove(int) or remove(Object) · ▶ Runs
List<Integer> nums = new ArrayList<>(List.of(10, 1, 20, 1));
nums.remove(1);
System.out.println(nums);
nums.remove(Integer.valueOf(1));
System.out.println(nums);
Output
[10, 20, 1]
[10, 20]
Part 4

📦ArrayList

ArrayList is a resizable array. It is the most used collection in Java.

  • Duplicates, nulls and insertion order are all kept.
  • The default starting capacity is 10. When full, it grows by half: new = old + old ÷ 2, so 10, 15, 22, 33 and so on.
  • It implements RandomAccess, so get(i) takes the same short time for any index.
  • Inserting or deleting in the middle is slow, because every later element must shift.
  • Its methods are not synchronized. Use Collections.synchronizedList(list) or a concurrent collection when several threads share it.
Common ArrayList moves · ▶ Runs
ArrayList<Object> l = new ArrayList<>();
l.add("A"); l.add(10); l.add("A"); l.add(null);
System.out.println(l);
l.remove(2);
l.add(2, "M");
l.add("N");
System.out.println(l + " " + (l instanceof RandomAccess));
Output
[A, 10, A, null]
[A, 10, M, null, N] true
Best choice when you mostly read by index or add at the end. If you constantly insert and delete in the middle, consider LinkedList or a different design.
Part 5

🔗LinkedList

LinkedList is a doubly linked list: each element knows the one before it and the one after it. It implements both List and Deque.

  • Adding or removing at either end is quick, and so is removing through an iterator.
  • Reading by index is slow, because it must walk from one end.
  • It does not implement RandomAccess.
Working at both ends · ▶ Runs
LinkedList<String> l = new LinkedList<>(List.of("B", "C"));
l.addFirst("A");
l.addLast("D");
System.out.println(l + " first " + l.getFirst() + " last " + l.getLast());
l.removeFirst();
l.removeLast();
System.out.println(l);
Output
[A, B, C, D] first A last D
[B, C]
Part 6

🥞Vector and Stack

Vector (Java 1.0) is an older resizable array whose methods are all synchronized. Stack extends Vector and works last in, first out. Both are called legacy classes.

A stack of plates · ▶ Runs
Stack<String> plates = new Stack<>();
plates.push("A"); plates.push("B"); plates.push("C");
System.out.println(plates);
System.out.println(plates.pop() + " " + plates.peek());
plates.push("D");
System.out.println(plates.search("A") + " " + plates.search("Z"));
Output
[A, B, C]
C B
3 -1

search counts from the top, starting at 1, and returns −1 when the element is missing.

For new code, use ArrayDeque as a stack (push, pop, peek) and ArrayList instead of Vector. They are faster because they skip synchronization.

Remove odd numbers safely with an Iterator · ▶ Runs
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 4, 5, 6));
Iterator<Integer> it = nums.iterator();
while (it.hasNext()) if (it.next() % 2 != 0) it.remove();
System.out.println(nums);
Output
[2, 4, 6]
ListIterator edits on the way · ▶ Runs
List<String> menu = new ArrayList<>(List.of("tea", "coffee", "juice", "soda"));
ListIterator<String> li = menu.listIterator();
while (li.hasNext()) {
    String s = li.next();
    if (s.equals("coffee")) li.remove();          // drop it
    else if (s.equals("juice")) li.set("lassi");  // replace it
    else if (s.equals("soda")) li.add("water");   // add right after it
}
System.out.println(menu);
while (li.hasPrevious()) System.out.print(li.previous() + " ");
Output
[tea, lassi, soda, water]
water soda lassi tea
Changing a collection directly while a for-each loop or iterator walks over it throws ConcurrentModificationException. Iterators are fail-fast. Use the iterator's own remove, or removeIf.
Removing inside a for-each loop · 💥 Crashes at run time
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 4));
for (Integer n : nums) if (n == 2) nums.remove(n);
💥 Runtime error
Exception in thread "main" java.util.ConcurrentModificationException
removeIf does it in one line · ▶ Runs
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 4, 5, 6));
nums.removeIf(n -> n % 2 == 0);
System.out.println(nums);
Output
[1, 3, 5]

Part 9

⚖️Comparable and Comparator

Sorting needs a way to compare two objects. Java offers two.

Comparable (java.lang)

The class defines its own natural order in compareTo(other). String, the wrappers and enums already do this.

Comparator (java.util)

A separate object defines a custom order in compare(a, b). Use it for a different order, or for classes you cannot change.

compare(a, b) and a.compareTo(b) return a negative number if a comes first, a positive number if b comes first, and 0 if they are equal in that order.
compareTo on Strings · ▶ Runs
System.out.println("A".compareTo("Z"));
System.out.println("Z".compareTo("K"));
System.out.println("A".compareTo("A"));
System.out.println("apple".compareTo("apricot"));
Output
-25
15
0
-2
Natural order versus custom orders · ▶ Runs
import java.util.*;
class Employee implements Comparable<Employee> {
    String name; int salary;
    Employee(String n, int s) { name = n; salary = s; }
    public int compareTo(Employee o) { return Integer.compare(salary, o.salary); }   // natural: by salary
    public String toString() { return name + ":" + salary; }
}
class Main {
    public static void main(String[] args) {
        List<Employee> team = new ArrayList<>(List.of(
            new Employee("Ravi", 30000), new Employee("Asha", 45000), new Employee("Kiran", 30000)));
        Collections.sort(team);
        System.out.println(team);
        team.sort(Comparator.comparing((Employee e) -> e.name));
        System.out.println(team);
        team.sort(Comparator.comparingInt((Employee e) -> e.salary).reversed().thenComparing(e -> e.name));
        System.out.println(team);
    }
}
Output
[Ravi:30000, Kiran:30000, Asha:45000]
[Asha:45000, Kiran:30000, Ravi:30000]
[Asha:45000, Kiran:30000, Ravi:30000]
Strings by length, then alphabetically · ▶ Runs
TreeSet<String> t = new TreeSet<>(Comparator.comparingInt(String::length).thenComparing(Comparator.naturalOrder()));
t.addAll(List.of("kiwi", "fig", "banana", "apple", "date"));
System.out.println(t);
TreeSet<String> rev = new TreeSet<>(Comparator.reverseOrder());
rev.addAll(List.of("b", "c", "a"));
System.out.println(rev);
Output
[fig, date, kiwi, apple, banana]
[c, b, a]
If a TreeSet's comparator returns 0 for two different objects, the set treats them as duplicates and keeps only the first. Above, "kiwi" and "date" have the same length, which is why the second comparison step matters.

🗝️Map and its classes

A Map stores key → value pairs. Keys are unique, values may repeat. Each pair is a Map.Entry. Map is not a child of Collection.

🚶Queue and PriorityQueue

A Queue holds elements waiting to be processed, usually first in, first out.

ActionReturns a special valueThrows an exception
insertoffer(e) → falseadd(e)
remove the headpoll() → nullremove()
look at the headpeek() → nullelement()

A PriorityQueue always hands out the smallest element first (or the first by its Comparator). Inside, it is a binary heap, so printing it does not show sorted order.

Smallest first · ▶ Runs
PriorityQueue<Integer> pq = new PriorityQueue<>(List.of(50, 40, 30, 20, 10));
System.out.println(pq);                       // heap order, not sorted
StringBuilder out = new StringBuilder();
while (!pq.isEmpty()) out.append(pq.poll()).append(' ');
System.out.println(out);
PriorityQueue<String> longest = new PriorityQueue<>(Comparator.comparingInt(String::length).reversed());
longest.addAll(List.of("tea", "espresso", "latte"));
System.out.println(longest.peek() + " " + new LinkedList<Integer>().poll());
Output
[10, 20, 30, 50, 40]
10 20 30 40 50 
espresso null
ArrayDeque is the fastest general purpose queue and stack in Java. It works at both ends: offerFirst, offerLast, pollFirst, pollLast.

Collections

🆕Modern collection tools

List.of, Set.of and Map.of (Java 9) create small immutable collections in one line. They reject nulls, and Set.of and Map.of reject duplicates.
List.of is read-only · 💥 Crashes at run time
List<String> l = List.of("a", "b");
l.add("c");
💥 Runtime error
Exception in thread "main" java.lang.UnsupportedOperationException
Streams summarise collections · ▶ Runs
List<String> words = List.of("java", "is", "fun", "and", "java", "is", "fast");
Map<String, Long> counts = new TreeMap<>();
words.forEach(w -> counts.merge(w, 1L, Long::sum));
System.out.println(counts);
System.out.println(words.stream().filter(w -> w.length() > 2).distinct().sorted().toList());
Output
{and=1, fast=1, fun=1, is=2, java=2}
[and, fast, fun, java]
When many threads share a map, use ConcurrentHashMap. It allows safe reads and writes from many threads at once, without locking the whole map like Hashtable does.
Java 21 added sequenced collections: lists, deques, LinkedHashSet and LinkedHashMap now share methods such as getFirst(), getLast() and reversed().
Sequenced collections (Java 21) · ▶ Runs

System.out.println(l.getFirst() + " " + l.getLast() + " " + l.reversed());
