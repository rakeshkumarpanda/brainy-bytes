Pre and post increment

++i increases first, then gives the new value. i++ gives the old value, then increases. Python has no ++, it uses i += 1.

Short circuit

&& stops at the first false and || at the first true, so s != null && s.length() > 0 never fails on null.

Java's % keeps the sign of the left operand: −7 % 3 = −1. Python's % follows the right operand: −7 % 3 = 2. Programs that check "is odd" with n % 2 == 1 fail for negative numbers in Java. Use n % 2 != 0.
Part 2

🔀if, else if, nested if and switch

if (n % 2 == 0 && n % 3 == 0)      System.out.println("Divisible by both 2 and 3");
else if (n % 2 == 0)                 System.out.println("Divisible by 2");
else if (n % 3 == 0)                 System.out.println("Divisible by 3");
else                                 System.out.println("Not divisible by 2 or 3");

Conditions must be boolean expressions built from relational and logical operators. Java does not treat 0 or an empty string as false, unlike Python and JavaScript.

switch with break

Matches one value against case labels. Without break, execution falls through into the next case. default handles everything else.

switch expression (Java 14+)

String d = switch (day) { case 6, 7 -> "weekend"; default -> "weekday"; }; No fall through and it returns a value.

🔁while, do while, for and for each

All three parts of a for are optional: for (; i < 5; ) works if i is set before and changed inside. Leave out the condition and the loop never ends.

Python has while and for x in ... (a for each loop), with range(start, stop, step) for counting. It has no do while. JavaScript has all four, plus for...of for values and for...in for keys.
Part 4

⏭️break, continue and labelled loops

break

Leaves the innermost loop at once. With a label, break outer; leaves an outer loop too.

continue

Skips the rest of this pass and starts the next one.

Python has no labels. Leave nested loops with a flag, a function that returns, or the for ... else clause. JavaScript supports labels like Java.
Part 5

🔢Classic loop programs, and a prime bug

The session's three prime checks get faster: count every factor (O(n)), stop at n/2, stop at √n. But they hide boundary bugs: none of them rejects 0 and 1, the n/2 version calls 4 prime, and the √n version calls 9 and 25 prime. Testing only a few "normal" numbers such as 11 and 10 does not reveal any of this.

PrimeNumber2: for (int i = 2; i < n/2; i++)    // n = 4: the loop never runs, so 4 is "prime"
PrimeNumber3: for (int i = 2; i * i < n; i++)  // n = 9: stops before 3, so 9 is "prime"
Fixed:        if (n < 2) not prime; for (int i = 2; i * i <= n; i++)
This is boundary value analysis in practice. The edges here are 0, 1, 2, small composites such as 4, and perfect squares such as 9 and 25, exactly where < versus <= matters.
Part 6

✳️Pattern programs with nested loops

A pattern is a grid: the outer loop chooses the row, the inner loop prints the columns of that row. The trick is the inner loop's range as a function of the row number.

PatternRow r printsInner loop
Squaren starsc = 1 … n
Right triangler starsc = 1 … r
Inverted trianglen − r + 1 starsc = r … n or count down
Pyramidn − r spaces, then 2r − 1 starstwo inner loops
Two nested loops of n each run n × n times, so printing a square is O(n²). The triangle prints n(n + 1)2 stars, still O(n²).
