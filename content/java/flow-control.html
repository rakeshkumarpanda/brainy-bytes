Flow Control

Flow control decides which line runs next. Choose a road with if and switch, go round with loops, and jump out with break and continue.

Part 1

🗺️Three families of flow control

Java runs statements from top to bottom unless something changes the order. Flow control statements are those somethings, and they come in three families.

🛣️ Selection

Pick one path: if else and switch.

🔁 Iteration

Repeat: while, do while, for and the for-each loop.

🦘 Transfer

Jump: break, continue, return, try catch finally and assert.

Part 2

🛣️if else

Java snippet
if (condition) {
    // runs when condition is true
} else {
    // runs when condition is false (the else part is optional)
}
The condition must be a boolean. Java never treats 0 as false or 1 as true, unlike C.
An int is not a boolean · ❌ Does not compile
int x = 0;
if (x) System.out.println("Hello");
❌ Compile error
incompatible types: int cannot be converted to boolean
Assignment instead of comparison · ❌ Does not compile
int x = 10;
if (x = 20) System.out.println("Hello");
❌ Compile error
incompatible types: int cannot be converted to boolean
With a boolean, = compiles (and surprises) · ▶ Runs
boolean b = true;
if (b = false) System.out.println("Hello");
else System.out.println("Hi");
Output
Hi

In the last example b = false assigns false and then gives false, so the else part runs. Write b == false or simply !b.

Curly braces are optional, with one catch

Without braces, only the single next statement belongs to the if. That statement must not be a variable declaration.

A lone declaration is not allowed · ❌ Does not compile
if (true) int x = 10;
❌ Compile error
variable declaration not allowed here
Inside braces it is fine · ▶ Runs
if (true) { int x = 10; System.out.println(x); }
Output
10
An else always belongs to the nearest unmatched if, whatever the indentation says. This is the "dangling else".
Indentation lies, the compiler does not · ▶ Runs
int marks = 30;
if (marks > 35)
    if (marks > 75)
        System.out.println("Distinction");
else
    System.out.println("This else belongs to the inner if");
System.out.println("done");
Output
done

Nothing is printed except "done", because the outer if is false and the else is attached to the inner if.

Part 3

🎛️switch

When one value decides between many paths, switch is cleaner than a long chain of if else if.

Classic switch · ▶ Runs
int day = 3;
switch (day) {
    case 1: System.out.println("Monday"); break;
    case 2: System.out.println("Tuesday"); break;
    case 3: System.out.println("Wednesday"); break;
    default: System.out.println("Some other day");
}
Output
Wednesday

What can you switch on

SinceAllowed types
Java 1.0byte, short, char, int
Java 5their wrappers Byte Short Character Integer, and enum
Java 7String
Java 21any object, using pattern matching

long, float, double and boolean can never be used in a classic switch.

No long in a switch · ❌ Does not compile
long l = 10L;
switch (l) { case 10: System.out.println("ten"); }
❌ Compile error
selector type long is not allowed

Rules for case labels

  1. A case label must be a compile-time constant. A plain variable is not allowed, a final variable with a constant value is.
  2. The value must fit in the switch type. With a byte, case 1000 fails.
  3. No duplicates. Watch out: case 'a' and case 97 are the same label.
  4. Any expression is allowed, as long as it is constant: case 10 + 20 is fine.
A plain variable as a case label · ❌ Does not compile
int x = 10, y = 20;
switch (x) { case y: System.out.println("y"); }
❌ Compile error
constant expression required
A final constant is fine · ▶ Runs
int x = 20;
final int y = 20;
switch (x) {
    case 10: System.out.println("10"); break;
    case y: System.out.println("matched the final y");
}
Output
matched the final y
Out of range for byte · ❌ Does not compile
byte b = 10;
switch (b) { case 10: break; case 1000: break; }
❌ Compile error
incompatible types: possible lossy conversion from int to byte
'a' and 97 are the same label · ❌ Does not compile
int x = 97;
switch (x) { case 97: break; case 'a': break; }
❌ Compile error
duplicate case label

Fall-through

When a case matches, every statement from that case downwards runs until a break or the end of the switch. This is called fall-through. It is a common bug, but it also lets several cases share one action.

No breaks, so it falls through · ▶ Runs
int x = 1;
switch (x) {
    case 0: System.out.println("0");
    case 1: System.out.println("1");
    case 2: System.out.println("2"); break;
    case 3: System.out.println("3");
    default: System.out.println("default");
}
Output
1
2
Sharing one action on purpose · ▶ Runs
char grade = 'B';
switch (grade) {
    case 'A':
    case 'B':
    case 'C': System.out.println("Pass"); break;
    default: System.out.println("Try again");
}
Output
Pass
default can sit anywhere, even at the top. It still runs only when no case matches, and fall-through still applies from wherever it is.
Java 14 made arrow cases and switch expressions official. Arrows never fall through, several labels can share one arrow, and the whole switch can produce a value. Inside a block use yield to give the value.
Modern switch expression · ▶ Runs
String day = "SAT";
int hours = switch (day) {
    case "SAT", "SUN" -> 0;
    case "FRI" -> 6;
    default -> {
        int base = 8;
        yield base;
    }
};
System.out.println(hours);
Output
0
Java 21 added pattern matching for switch, which can test the type of an object and name it in one step.
Switch on the type · ▶ Runs
Object o = 42;
String text = switch (o) {
    case Integer i when i > 40 -> "a big integer " + i;
    case Integer i -> "an integer " + i;
    case String s -> "a string of length " + s.length();
    default -> "something else";
};
System.out.println(text);
Output
a big integer 42
Part 4

🔁while loop

Use while when you do not know in advance how many times the body will run, for example reading lines until a file ends.

Halving until we reach 1 · ▶ Runs
int n = 100, steps = 0;
while (n > 1) {
    n = n / 2;
    steps++;
}
System.out.println("steps = " + steps);
Output
steps = 6

The condition must be a boolean, and the same brace rules as if apply.

Unreachable code

The compiler refuses code that can never run. It works this out only from constant conditions.

The body can never run · ❌ Does not compile
while (false) {
    System.out.println("Hello");
}
❌ Compile error
unreachable statement
Nothing after an endless loop · ❌ Does not compile
while (true) {
    System.out.println("Hello");
}
System.out.println("Bye");
❌ Compile error
unreachable statement
A plain variable is not a constant · ▶ Runs
int a = 10, b = 20;
while (a > b) {                   // compiler does not evaluate a > b
    System.out.println("never");
}
System.out.println("Bye");
Output
Bye
If a and b were final, then a > b would become the constant false and the loop body would be an unreachable statement.
Part 5

🔂do while loop

A do while loop checks its condition at the end, so the body always runs at least once. A menu that shows itself before asking "again?" is the classic use.

Runs once even though the condition is false · ▶ Runs
int x = 10;
do {
    System.out.println("x = " + x);
    x++;
} while (x < 5);
Output
x = 10
  • The semicolon after while (...) is required.
  • Between do and while there must be exactly one statement or a block, and it must not be a lone declaration.
  • do; while (true); is legal: an empty statement repeated forever.
Unreachable after an endless do while · ❌ Does not compile
do {
    System.out.println("Hello");
} while (true);
System.out.println("Bye");
❌ Compile error
unreachable statement
Part 6

🔢for loop

The most used loop. Use it when you know how many times to repeat.

Java snippet
for (initialization ; condition ; update) {
    body
}

The order is: initialization once, then condition, body, update, condition, body, update, and so on until the condition is false.

All three parts are optional and independent

  • Initialization runs once. It may declare several variables of one type, or contain any statements separated by commas.
  • Condition must be boolean. If you leave it out, Java treats it as true.
  • Update can be any statements, not only i++.
Unusual but legal · ▶ Runs
int i = 0;
for (System.out.println("init"); i < 3; System.out.println("update")) {
    System.out.println("body " + i);
    i++;
}
Output
init
body 0
update
body 1
update
body 2
update
Two variables at once · ▶ Runs
for (int lo = 0, hi = 6; lo < hi; lo++, hi--) {
    System.out.println(lo + " " + hi);
}
Output
0 6
1 5
2 4
Two different types cannot be declared together · ❌ Does not compile
for (int i = 0, long j = 0; i < 3; i++) { }
❌ Compile error
<identifier> expected
for (;;) is an endless loop, the same as while (true).
Part 7

🍡for-each loop

Java 5 added the for-each loop, the easiest way to visit every element of an array or a collection.

Arrays and collections · ▶ Runs
int[] marks = {72, 88, 95};
for (int m : marks) System.out.print(m + " ");
System.out.println();
List<String> names = List.of("Asha", "Ravi", "Meera");
for (String n : names) System.out.print(n.charAt(0));
System.out.println();
int[][] grid = {{1, 2}, {3, 4, 5}};
for (int[] row : grid)
    for (int v : row) System.out.print(v);
Output
72 88 95 
ARM
12345

Limitations

  • It works only with arrays and objects that implement Iterable, such as every Collection.
  • It always goes forward through every element. No reverse order, no skipping, no index.
  • Assigning to the loop variable does not change the array, because the variable is a copy.
The loop variable is only a copy · ▶ Runs
int[] a = {1, 2, 3};
for (int v : a) v = v * 10;
System.out.println(Arrays.toString(a));
for (int i = 0; i < a.length; i++) a[i] = a[i] * 10;
System.out.println(Arrays.toString(a));
Output
[1, 2, 3]
[10, 20, 30]
Part 8

🛑break

break jumps out of the nearest switch or loop immediately. It is also allowed inside a labeled block. Anywhere else it does not compile.

Stop at the first multiple of 7 · ▶ Runs
for (int i = 1; i <= 20; i++) {
    if (i % 7 == 0) {
        System.out.println("found " + i);
        break;
    }
}
Output
found 7
break outside a loop or switch · ❌ Does not compile
int x = 10;
if (x == 10) break;
❌ Compile error
break outside switch or loop
Part 9

⏭️continue

continue skips the rest of the current pass and moves on to the next one. It is allowed only inside loops.

Print only odd numbers · ▶ Runs
for (int i = 0; i < 10; i++) {
    if (i % 2 == 0) continue;
    System.out.print(i + " ");
}
Output
1 3 5 7 9
continue inside a switch but not a loop · ❌ Does not compile
int x = 1;
switch (x) { case 1: continue; }
❌ Compile error
continue outside of loop
In a do while loop, continue jumps to the condition check at the bottom, not to the top of the body. Trace the next example by hand before you look at the output.
The famous do while with continue · ▶ Runs
int x = 0;
do {
    x++;
    System.out.print(x + " ");
    if (++x < 5) continue;
    x++;
    System.out.print(x + " ");
} while (++x < 10);
Output
1 4 6 8 10
Part 10

🏷️Labeled break and continue

In nested loops, a plain break or continue only affects the inner loop. Put a label on the outer loop to target it instead.

break with a label leaves both loops · ▶ Runs
outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == j) break outer;
        System.out.println(i + "..." + j);
    }
}
System.out.println("after the loops");
Output
after the loops
continue with a label moves the outer loop on · ▶ Runs
outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == j) continue outer;
        System.out.println(i + "..." + j);
    }
}
Output
1...0
2...0
2...1
Inside the inner loopPairs printed for i, j in 0 to 2
break1...0, 2...0, 2...1
break outernothing
continue0...1, 0...2, 1...0, 1...2, 2...0, 2...1
continue outer1...0, 2...0, 2...1
