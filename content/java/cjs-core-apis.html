Part 1

🧵Strings, the pool and equals

A String is an object holding a fixed sequence of characters. String literals are stored once in the String pool, so two variables with the same literal share one object. new String("java") always makes a separate object on the heap.

==

Compares references: are both variables pointing at the same object?

equals()

Compares the characters. Use it for every content check, such as comparing a page title with the expected text.

Strings are immutable. Methods such as concat, replace and toUpperCase return a new String and leave the original unchanged. To build text in a loop, use StringBuilder, which changes one buffer instead of creating a new String on every pass.

Joining Strings with += inside a loop, as the session's ReverseAString does, creates a new String every pass, so n characters cost about n²2 character copies. StringBuilder keeps it to about n.
Part 4

📏Arrays

An array holds a fixed number of values of one type in consecutive slots. new int[5] fills every slot with the default 0, and the size never changes afterwards. Reading animals[2] is one step, O(1), whatever the size.

Valid indexes run from 0 to length − 1. nums[5] on a 5 element array throws ArrayIndexOutOfBoundsException at run time. Note that length is a field for arrays and length() a method for Strings.
Part 5

🎁Wrapper classes

PrimitiveWrapperParse from text
intIntegerInteger.parseInt("59900")
doubleDoubleDouble.parseDouble("60000.05")
booleanBooleanBoolean.parseBoolean("false")
char, long, float, byte, shortCharacter, Long, Float, Byte, ShortLong.parseLong and so on

Collections hold objects only, so List<Integer> stores wrappers. Java converts automatically: autoboxing wraps an int into an Integer, unboxing unwraps it. Testers use the parse methods constantly, because everything read from a web page is text.

Integer objects from −128 to 127 are cached, so == works by luck for small values and fails at 128. Always compare wrappers with equals().

Part 7

🧯Exception handling

An exception is an object describing a problem that stops normal flow, such as dividing by zero. Without handling, the program ends and prints a stack trace (the session's ExceptionSession7). With try and catch it recovers and carries on.

BlockRule
tryHolds the risky lines. Must be followed by at least one catch or a finally
catchSeveral are allowed. List the specific type before the general one: catch (Exception) above catch (ArithmeticException) is a compilation error, since the second could never run
finallyAlways runs, with or without an exception, even after return. Use it to close drivers, files and connections
Part 8

🎯Checked and unchecked, throw and throws

Checked

Subclasses of Exception other than RuntimeException, such as IOException. The compiler forces you to catch them or declare them with throws.

Unchecked

RuntimeException and its children, such as NullPointerException and ArrayIndexOutOfBoundsException. They usually signal a bug, and the compiler does not force handling.

KeywordWhereMeaning
throwInside a method bodyRaises one exception object now: throw new InvalidAgeException("...")
throwsIn the method signatureWarns callers which checked exceptions may come out
The session's ExceptionSession6 catches an exception and throws new RuntimeException("Denominator is zero"). That wraps the problem in a clearer message, a pattern frameworks use to turn low level errors into readable test failures.
