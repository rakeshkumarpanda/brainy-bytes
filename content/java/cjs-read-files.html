Reading Test Data Files

Hard coding a username inside a test means editing code every time the data changes. The session's last module moves data into files under src/test/resources. This chapter reads each kind, text, properties, CSV, JSON and Excel, with the same file contents in Java, Python and JavaScript, and ends by feeding rows into one data driven test.

Part 1

🗄️Why test data lives in files

A data driven test keeps its inputs and expected results outside the code. Testers can add a row to a sheet without touching Java, the same test runs once per row, and secrets such as passwords stay out of the source.

FormatBest forJava reader
.txtLists, logs, simple linesFiles.readAllLines, BufferedReader
.propertiesConfiguration: URL, browser, timeoutjava.util.Properties
.csvRows of test data, easy to diff in Gitsplit(",", -1) or a CSV library
.jsonNested data, API payloads and responsesJackson, JsonPath
.xlsx / .xlsData that business users editApache POI, Fillo
The session builds every path from System.getProperty("user.dir"), the folder the program was started from, which is the project root in Maven and IntelliJ. Then "/src/test/resources/test.txt" works on every machine, unlike C:\Users\me\....

Locked user sees a warning

Files.readAllLines(path)

One call returns every line as a List<String>. Simple, but the whole file sits in memory.

BufferedReader.readLine()

Returns one line at a time and null at the end, so a 2 GB log never fills memory.

try (BufferedReader br = …) is try with resources: Java closes the file when the block ends, even if an exception is thrown. Python's with open(…) does the same.
Part 3

⚙️Properties files for configuration

src/test/resources/config.properties
# QA environment settings
url=https://qa.example.com
browser=chrome
username=qa_user
password=Secret@123
timeout=30
# a value with spaces and an escaped colon
welcome.text=Welcome back\: tester

Every value comes back as a String, so numbers need Integer.parseInt. Lines starting with # or ! are comments. Wrapping the file in one ConfigReader class means tests never repeat the path, and a value given on the command line with mvn test -Dbrowser=firefox can override the file.

user2,wrong,error

user4,Psw4,success
Java's split(",") drops trailing empty fields: "user5,Psw5,".split(",") has 2 parts, not 3. Pass a limit of −1, split(",", -1), to keep them. Values that contain commas inside quotes need a real CSV parser such as OpenCSV, or Python's csv module.

🧩JSON with Jackson and JsonPath

src/test/resources/test.json
{ "firstName": "John", "lastName": "Smith", "age": 25, "isAlive": true,
  "address": { "streetAddress": "21 2nd Street", "city": "New York", "state": "NY", "postalCode": "10021" },
  "phoneNumbers": [ { "type": "home",   "number": "212 555-1234" },
                    { "type": "office", "number": "646 555-4567" },
                    { "type": "mobile", "number": "123 456-7890" } ],
  "children": [], "spouse": null }

The session reads this file with JsonPath: JsonPath.parse(file).read("$.firstName"). $ is the root, .key goes into an object and [n] into an array. The code below uses Jackson, the library most Java projects already have: readTree turns the file into a tree of JsonNode objects.

JsonPathJacksonValue
$.firstNameroot.get("firstName").asText()John
$.address.cityroot.path("address").path("city").asText()New York
$.phoneNumbers[1].numberroot.at("/phoneNumbers/1/number")646 555-4567
$.phoneNumbers[*].typeloop over root.get("phoneNumbers")[home, office, mobile]
get("email") returns null for a missing key, so chaining .asText() after it throws a NullPointerException. path("email") returns a "missing node" whose text is empty, which is safer for deep chains.

The session uses Fillo, which lets you query a sheet like a database table: select username, password from sheet1 where status='Pass'. Fillo is built on Apache POI, the standard Java library for Office files. With POI you walk the structure yourself: Workbook → Sheet → Row → Cell.

WorkbookFactory.create opens both the older .xls format (POI's HSSF classes) and .xlsx (XSSF classes, which need the poi-ooxml dependency). The Java example reads the .xls copy of the sheet, the Python and JavaScript versions read the .xlsx copy, and the code is otherwise the same for both formats. DataFormatter returns every cell as the text Excel shows, so a number cell such as 1 does not come back as 1.0.
Part 7

🔁From rows to a data driven test

TestNG's @DataProvider returns Object[][]: one inner array per run, holding that run's arguments. Read any file into that shape and a single test method covers every row. The TestNG pages of this site show the real annotations, here the loop plays TestNG's part.

Keep an expected column next to the inputs, as login.csv does. A data row without its expected result can only tell you that the code ran, not that it did the right thing.
