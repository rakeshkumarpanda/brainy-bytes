java.lang: Object, String and Wrappers

Every Java program uses the java.lang package, whether it says so or not. Object is the parent of everything, String is the most used class on Earth, and wrappers let numbers behave like objects.

Part 1

🌳The Object class

java.lang.Object is the root of every class. If a class extends nothing, it extends Object directly. So every object you will ever create has Object's methods.

MethodWhat it does
String toString()a text form of the object
int hashCode()a number used by hash based collections
boolean equals(Object o)are two objects equal
Object clone()a copy of the object (protected)
Class getClass()the runtime class of the object (final)
void wait(), wait(long), wait(long, int)pause a thread until notified (final)
void notify(), notifyAll()wake waiting threads (final)
void finalize()old clean-up hook, deprecated since Java 9
The wait and notify methods live in Object, not in Thread, because a thread waits on any object's lock. That surprises almost everyone the first time.
Part 2

📝toString()

println(obj) calls obj.toString() for you. Object's version returns the class name, an @ and the hash code in hexadecimal, which is rarely what a human wants.

Java snippet
public String toString() {
    return getClass().getName() + "@" + Integer.toHexString(hashCode());
}
Default versus overridden · ▶ Runs
class Plain { }
class Student {
    String name; int roll;
    Student(String n, int r) { name = n; roll = r; }
    @Override public String toString() { return name + " (" + roll + ")"; }
}
class Main {
    public static void main(String[] args) {
        String p = new Plain().toString();
        System.out.println(p.substring(0, p.indexOf('@') + 1) + "…");
        System.out.println(new Student("Asha", 7));
    }
}
Output
Plain@…
Asha (7)

String, StringBuilder, every wrapper class and every collection already override toString(), which is why println(list) prints its elements.

Part 3

#️⃣hashCode()

Hash based collections such as HashMap and HashSet use the hash code to decide which bucket an object goes into, so they can find it again quickly. A good hash code spreads objects evenly.

  • The default hash code is chosen by the JVM and usually differs for every object.
  • Override it whenever you override equals, using the same fields.
  • Objects.hash(a, b, c) builds a decent hash code for you.
String has a content based hash code · ▶ Runs
System.out.println("Ab".hashCode());
System.out.println("BB".hashCode());
System.out.println(new String("Ab").hashCode() == "Ab".hashCode());
Output
2113
2112
true
hash("Ab") = 'A' × 31 + 'b' = 65 × 31 + 98 = 2113 hash("BB") = 'B' × 31 + 'B' = 66 × 31 + 66 = 2112
Strings like "Aa" and "BB" have the same hash code. Collisions are normal. That is why equals is still needed after the bucket is found.
Part 4

⚖️equals() and ==

Object's equals does the same as ==: it only checks whether both references point at the same object. Override it to compare contents.

Comparing students by roll number · ▶ Runs
import java.util.*;
class Student {
    String name; int roll;
    Student(String n, int r) { name = n; roll = r; }
    @Override public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Student s)) return false;
        return roll == s.roll && name.equals(s.name);
    }
    @Override public int hashCode() { return Objects.hash(name, roll); }
}
class Main {
    public static void main(String[] args) {
        Student a = new Student("Asha", 7), b = new Student("Asha", 7);
        System.out.println(a == b);
        System.out.println(a.equals(b));
        System.out.println(new HashSet<>(List.of(a, b)).size());
    }
}
Output
false
true
1
==equals()
an operator, works on primitives and referencesa method, works on objects only
for objects: same object or notfor objects: same contents, if the class overrides it
cannot be changedcan be overridden

The contract: if a.equals(b) is true, then a.hashCode() == b.hashCode() must be true. The reverse is not required. Break this rule and HashMap and HashSet misbehave.
String overrides equals, StringBuilder does not · ▶ Runs

System.out.println(s1.equals(s2));

Part 5

🐑clone(): shallow and deep copies

clone() makes a copy of an object. The class must implement the marker interface Cloneable, or Object's clone throws CloneNotSupportedException.

Shallow copy

The default. Fields are copied as they are, so referenced objects are shared by the original and the copy.

Deep copy

Referenced objects are copied too, so the copy is completely independent. You write this yourself.

Shallow copy shares the inner object · ▶ Runs
class Address { String city; Address(String c) { city = c; } }
class Person implements Cloneable {
    String name; Address addr;
    Person(String n, Address a) { name = n; addr = a; }
    @Override public Person clone() throws CloneNotSupportedException { return (Person) super.clone(); }
}
class Main {
    public static void main(String[] args) throws Exception {
        Person p1 = new Person("Ravi", new Address("Pune"));
        Person p2 = p1.clone();
        p2.addr.city = "Delhi";                   // changes the shared address
        System.out.println(p1.addr.city + " " + (p1 != p2) + " " + (p1.addr == p2.addr));
    }
}
Output
Delhi true true
Deep copy clones the inner object as well · ▶ Runs
class Address implements Cloneable {
    String city; Address(String c) { city = c; }
    @Override public Address clone() throws CloneNotSupportedException { return (Address) super.clone(); }
}
class Person implements Cloneable {
    String name; Address addr;
    Person(String n, Address a) { name = n; addr = a; }
    @Override public Person clone() throws CloneNotSupportedException {
        Person p = (Person) super.clone();
        p.addr = addr.clone();                    // copy the inner object too
        return p;
    }
}
class Main {
    public static void main(String[] args) throws Exception {
        Person p1 = new Person("Ravi", new Address("Pune"));
        Person p2 = p1.clone();
        p2.addr.city = "Delhi";
        System.out.println(p1.addr.city + " " + p2.addr.city);
    }
}
Output
Pune Delhi
Many teams avoid clone() and write a copy constructor instead: new Person(other). It is clearer and needs no marker interface.

Part 7

🧊String is immutable

Once a String object is created, its contents can never change. Every method that seems to change it actually returns a new String.

The original never changes · ▶ Runs
String s = new String("java");
s.concat(" rocks");                 // a new object is made, then forgotten
System.out.println(s);
s = s.concat(" rocks");             // keep the new object
System.out.println(s);
StringBuilder sb = new StringBuilder("java");
sb.append(" rocks");                // the same object changes
System.out.println(sb);
Output
java
java rocks
java rocks

Why immutable

  • Sharing is safe: many variables can point at one String in the pool, because nobody can change it.
  • Security: file names, URLs and passwords cannot be modified after checks pass.
  • Thread safety: immutable objects never need locks.
  • Hash caching: the hash code is computed once and reused, which makes Strings great HashMap keys.
Part 8

🏊The string constant pool

String literals are stored in a special area called the string constant pool (SCP). Before creating a literal, the JVM checks the pool. If an equal String is already there, it is reused.

String s = "java";

At most one object, in the pool. Reused if it already exists.

String s = new String("java");

Always a new object on the heap. The literal "java" also lives in the pool, so up to two objects.

Literals are shared, new is not · ▶ Runs
String a = "java";
String b = "java";
String c = new String("java");
System.out.println(a == b);
System.out.println(a == c);
System.out.println(a == c.intern());
Output
true
false
true

intern() returns the pool copy of a String, adding it to the pool if needed.

Constants are joined at compile time

When both parts of + are compile-time constants, the compiler joins them and the result is a pooled literal. With a plain variable involved, the join happens at run time and makes a new object.

Compile time versus run time joining · ▶ Runs
String s1 = "java rocks";
String s2 = "java" + " rocks";          // constant: joined by the compiler
String part = "java";
String s3 = part + " rocks";            // variable: joined at run time
final String fpart = "java";
String s4 = fpart + " rocks";           // final constant: compiler again
System.out.println((s1 == s2) + " " + (s1 == s3) + " " + (s1 == s4));
Output
true false true
How many objects does String s = new String("spring"); create, if the pool is empty? Two: one on the heap and one literal in the pool. Run it a second time and only one more appears, because the literal is reused.

Part 10

🧱StringBuffer

When the contents change often, String wastes objects. StringBuffer is a mutable sequence of characters: every change happens in the same object.

Capacity

A StringBuffer keeps spare room called capacity. new StringBuffer() starts with 16. When the text outgrows it, the new capacity follows this rule:

new capacity = (old capacity + 1) × 2
Watch the capacity grow · ▶ Runs
StringBuffer sb = new StringBuffer();
System.out.println(sb.capacity());
sb.append("abcdefghijklmnop");          // 16 characters, still fits
System.out.println(sb.capacity());
sb.append("q");                         // the 17th character
System.out.println(sb.capacity());
sb.append("r".repeat(18));              // now 35 characters
System.out.println(sb.capacity());
System.out.println(new StringBuffer("java").capacity());
Output
16
16
34
70
20
16 → (16 + 1) × 2 = 34 → (34 + 1) × 2 = 70 new StringBuffer("java") → 16 + "java".length() = 20

Important methods

Editing in place · ▶ Runs

sb.append(" Bytes").append(2026);
System.out.println(sb);
sb.insert(6, "!");
sb.delete(13, 17);                       // removes 2026 (start included, end excluded)
sb.deleteCharAt(6);
System.out.println(sb);

System.out.println(sb);

Every StringBuffer method is synchronized, so only one thread at a time can use the object. That is safe, but slow when there is only one thread anyway.

🎁Wrapper classes

Each primitive type has a wrapper class that holds the value as an object: Byte Short Integer Long Float Double Character Boolean. Collections and generics only store objects, so wrappers are everywhere.

The wrapper constructors such as new Integer(10) are deprecated for removal. Use Integer.valueOf(10) or simply autoboxing.

The Integer cache

Integer.valueOf keeps ready-made objects for values from −128 to 127 and hands out the same object each time. Outside that range it creates new objects.

Part 13

📦Autoboxing and unboxing

Since Java 5 the compiler converts between primitives and wrappers automatically.

Autoboxing

Integer i = 10;

becomes Integer i = Integer.valueOf(10);

Auto-unboxing

int x = i;

becomes int x = i.intValue();

Mixing freely · ▶ Runs
List<Integer> marks = new ArrayList<>();
marks.add(90);                      // boxing
marks.add(75);
int total = 0;
for (int m : marks) total += m;     // unboxing
Integer avg = total / marks.size(); // boxing again
System.out.println(total + " " + avg);
Output
165 82
Unboxing null crashes · 💥 Crashes at run time
Integer i = null;
int x = i;
💥 Runtime error
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "java.lang.Integer.intValue()" because "i" is null

Overloading with boxing

The compiler prefers, in this order: widening, then boxing, then var-args. It never widens and then boxes, but it can box and then widen.

Widening beats boxing · ▶ Runs
class Main {
    static void m(long x)    { System.out.println("widening"); }
    static void m(Integer x) { System.out.println("boxing"); }
    public static void main(String[] args) { m(10); }
}
Output
widening
Boxing then widening is allowed · ▶ Runs
class Main {
    static void m(Object o) { System.out.println("int → Integer → Object"); }
    public static void main(String[] args) { m(10); }
}

Part 14

🔏final versus immutable

These two ideas are often mixed up.

final

Applies to a variable. The reference cannot be pointed at another object.

immutable

Applies to an object. Its contents cannot change.

final does not freeze the object · ▶ Runs
final StringBuilder sb = new StringBuilder("final");
sb.append(" but changing");
System.out.println(sb);
Output
final but changing

Making your own immutable class

  1. Make the class final so no child can add mutable behaviour.
  2. Make every field private final.
  3. Offer no setters. A "change" method returns a new object instead.
  4. Copy mutable inputs in, and copy them out in getters.
An immutable Money class · ▶ Runs
final class Money {
    private final int rupees;
    Money(int rupees) { this.rupees = rupees; }
    Money plus(int more) { return new Money(rupees + more); }   // new object, old one untouched
    int rupees() { return rupees; }
}
class Main {
    public static void main(String[] args) {
        Money m1 = new Money(100);
        Money m2 = m1.plus(50);
        System.out.println(m1.rupees() + " " + m2.rupees());
    }
}
Output
100 150
