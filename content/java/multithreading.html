Part 1

🤹Multitasking

Multitasking means doing several tasks at the same time. It comes in two flavours.

Process based

Several independent programs run together: you type in an editor while music plays and a download runs. This is an operating system concern.

Thread based

Several independent parts of one program run together. Each part is a thread. This is what Java's multithreading gives you.

The goal of both is to make better use of the processor and to reduce response time. Typical uses: servers handling many users, games, animations, and keeping a screen responsive while work happens in the background.

Java made multithreading easy from day one by building it into the language: the Thread class, the Runnable interface and the synchronized keyword.
Part 2

🧵Defining a thread by extending Thread

Two threads, one program · ▶ Runs
class MyThread extends Thread {
    public void run() {                                      // the job of the child thread
        for (int i = 1; i <= 3; i++) System.out.println("child " + i);
    }
}
class Main {
    public static void main(String[] args) throws Exception {
        MyThread t = new MyThread();                         // instantiation
        t.start();                                           // a new thread begins
        for (int i = 1; i <= 3; i++) System.out.println("main " + i);
        t.join();
    }
}
One possible output (threads can take turns in a different order)
child 1
child 2
main 1
child 3
main 2
main 3

Which line prints first is decided by the thread scheduler, a part of the JVM and operating system. Its algorithm is not fixed, so the exact order can change from run to run.

start() versus run()

t.start() creates a new thread, which then calls run(). Calling t.run() directly is just a normal method call on the current thread, with no new thread at all.

run() stays on the main thread · ▶ Runs
class Main {
    public static void main(String[] args) throws Exception {
        Thread t = new Thread(() -> System.out.println("running on: " + Thread.currentThread().getName()));
        t.run();          // ordinary call
        t.start();        // new thread
        t.join();
    }
}
Output
running on: main
running on: Thread-0

start() does the hard work behind the scenes: it registers the thread with the scheduler, prepares its stack and then invokes run(). That is why it is called the heart of multithreading.

A thread can be started only once. Calling start() a second time throws IllegalThreadStateException.
Starting twice · 💥 Crashes at run time
Thread t = new Thread(() -> { });
t.start();
t.start();
💥 Runtime error
Exception in thread "main" java.lang.IllegalThreadStateException
  • If you do not override run(), the Thread class's empty run executes and nothing happens.
  • Overloading run(int) is allowed, but start() only ever calls the no-argument run().
  • Overriding start() in your class makes it an ordinary method: no new thread is created. Do not do it.
Part 3

🏃Defining a thread with Runnable

The second way: implement Runnable (a functional interface with one method, run()), and hand it to a Thread.

A Runnable job given to a Thread · ▶ Runs
class Countdown implements Runnable {
    public void run() {
        for (int i = 3; i >= 1; i--) System.out.println(Thread.currentThread().getName() + ": " + i);
    }
}
class Main {
    public static void main(String[] args) throws Exception {
        Thread t = new Thread(new Countdown(), "rocket");
        t.start();
        t.join();
        Thread lambda = new Thread(() -> System.out.println("lambda thread says hi"));
        lambda.start();
        lambda.join();
    }
}
Output
rocket: 3
rocket: 2
rocket: 1
lambda thread says hi
Prefer Runnable. A class that extends Thread can never extend anything else, while a Runnable class still can. It also separates the job from the worker that runs it.
Part 4

🏷️Names and priorities

Every thread has a name: one you give, or a default like Thread-0. The thread that runs main is called main.

Names · ▶ Runs
class Main {
    public static void main(String[] args) {
        System.out.println(Thread.currentThread().getName());
        Thread t = new Thread(() -> { });
        System.out.println(t.getName());
        Thread.currentThread().setName("boss");
        System.out.println(Thread.currentThread().getName());
    }
}
Output
main
Thread-0
boss

Priorities

Every thread has a priority from 1 (least) to 10 (most). Thread.MIN_PRIORITY is 1, NORM_PRIORITY is 5 and MAX_PRIORITY is 10. The main thread starts at 5, and a new thread inherits the priority of the thread that created it.

Inherited priority · ▶ Runs
class Main {
    public static void main(String[] args) {
        System.out.println(Thread.currentThread().getPriority());
        Thread.currentThread().setPriority(7);
        Thread t = new Thread(() -> { });
        System.out.println(t.getPriority());
    }
}
Output
5
7
Out of range · 💥 Crashes at run time
Thread.currentThread().setPriority(11);
💥 Runtime error
Exception in thread "main" java.lang.IllegalArgumentException
Priorities are only hints. Many operating systems ignore them, so never rely on priority for correctness.

Part 7

🔔Interrupting a thread

One thread can interrupt another that is sleeping or waiting by calling t.interrupt(). The sleeping thread wakes up with an InterruptedException. If the target is not sleeping yet, the request is remembered and fires the next time it sleeps or waits.

Wake a sleeping thread early · ▶ Runs
class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread sleeper = new Thread(() -> {
            try {
                System.out.println("going to sleep for 10 seconds");
                Thread.sleep(10_000);
                System.out.println("woke up normally");
            } catch (InterruptedException e) {
                System.out.println("someone woke me up early");
            }
        });
        sleeper.start();
        Thread.sleep(100);
        sleeper.interrupt();
        sleeper.join();
    }
}
Output
going to sleep for 10 seconds
someone woke me up early
Part 8

🔒Synchronization

When several threads change the same data at once, updates can be lost. This is a race condition. count++ looks like one step but is three: read, add, write.

A race: two threads, lost updates · ▶ Runs
class Main {
    static int count = 0;
    public static void main(String[] args) throws InterruptedException {
        Runnable job = () -> { for (int i = 0; i < 1_000_000; i++) count++; };
        Thread a = new Thread(job), b = new Thread(job);
        a.start(); b.start();
        a.join(); b.join();
        System.out.println("expected 2000000, got " + count);
    }
}
One possible output (threads can take turns in a different order)
expected 2000000, got 1560363

synchronized fixes it. Every object has one lock. A thread must get the lock before it enters a synchronized method or block on that object, so only one thread at a time can be inside.

Synchronized: always correct · ▶ Runs
class Counter {
    private int count = 0;
    synchronized void increment() { count++; }
    int get() { return count; }
}
class Main {
    public static void main(String[] args) throws InterruptedException {
        Counter c = new Counter();
        Runnable job = () -> { for (int i = 0; i < 1_000_000; i++) c.increment(); };
        Thread a = new Thread(job), b = new Thread(job);
        a.start(); b.start();
        a.join(); b.join();
        System.out.println("expected 2000000, got " + c.get());
    }
}
Output
expected 2000000, got 2000000

Rules worth knowing

  • synchronized applies to methods and blocks only, never to classes or variables.
  • While one thread is inside a synchronized method of an object, other threads may still run that object's non-synchronized methods.
  • Different objects have different locks, so two threads using two objects do not block each other.
  • A static synchronized method locks the class (its Class object), which is separate from every object lock.
  • A thread can hold several locks at once, from different objects.

Synchronized blocks

Locking a whole method is wasteful when only a few lines touch shared data. A block locks only what matters.

Java snippet
synchronized (this) { ... }          // the current object's lock
synchronized (someObject) { ... }    // that object's lock
synchronized (Main.class) { ... }    // the class level lock
Waiting for locks costs time. Keep synchronized regions small, or use ready-made thread safe tools such as AtomicInteger and ConcurrentHashMap.
Part 9

📨Inter-thread communication: wait and notify

Threads can signal each other. A thread calls wait() on an object to pause until another thread calls notify() or notifyAll() on the same object.

  • These methods belong to Object, not Thread, because threads wait on an object's lock.
  • They must be called inside a synchronized block or method on that object, otherwise IllegalMonitorStateException is thrown.
  • wait() releases the lock immediately. notify() releases it only when the notifying thread leaves the synchronized block.
  • notify() wakes one waiting thread (which one is not defined). notifyAll() wakes all of them.
Main waits for the child's answer · ▶ Runs
class Adder extends Thread {
    int total = 0;
    boolean done = false;
    public void run() {
        synchronized (this) {
            for (int i = 1; i <= 100; i++) total += i;
            done = true;
            System.out.println("child: giving notification");
            notify();
        }
    }
}
class Main {
    public static void main(String[] args) throws InterruptedException {
        Adder a = new Adder();
        a.start();
        synchronized (a) {
            while (!a.done) {                              // guard against missed or spurious wake-ups
                System.out.println("main: waiting");
                a.wait();
            }
            System.out.println("main: got " + a.total);
        }
    }
}
Output
main: waiting
child: giving notification
main: got 5050
wait outside synchronized · 💥 Crashes at run time
Object lock = new Object();
lock.wait();
💥 Runtime error
Exception in thread "main" java.lang.IllegalMonitorStateException: current thread is not owner

Part 10

💀Deadlock

A deadlock happens when two threads wait for each other forever. Thread 1 holds lock A and wants lock B. Thread 2 holds lock B and wants lock A. Neither can move.

Do not run: it hangs forever
Object a = new Object(), b = new Object();
Thread t1 = new Thread(() -> {
    synchronized (a) { pause(); synchronized (b) { System.out.println("t1 done"); } }
});
Thread t2 = new Thread(() -> {
    synchronized (b) { pause(); synchronized (a) { System.out.println("t2 done"); } }
});
t1.start(); t2.start();      // each grabs one lock, then waits for the other

Java has no automatic fix for deadlock. Prevention is up to you:

  • Always take locks in the same order everywhere (A then B, never B then A).
  • Hold locks for as short a time as possible.
  • Use tryLock with a timeout from java.util.concurrent.locks, so a thread can give up.
Same lock order, no deadlock · ▶ Runs
class Main {
    static final Object A = new Object(), B = new Object();
    static void work(String name) {
        synchronized (A) { synchronized (B) { System.out.println(name + " got both locks"); } }
    }
    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> work("t1")), t2 = new Thread(() -> work("t2"));
        t1.start(); t1.join();
        t2.start(); t2.join();
    }
}
Output
t1 got both locks
t2 got both locks
Starvation is the milder cousin of deadlock: a low priority thread waits a very long time, but it does eventually run. A deadlocked thread never does.
Part 11

👻Daemon threads

A daemon thread runs in the background to support other threads. The garbage collector is the famous example. When the last non-daemon thread ends, the JVM stops all daemon threads and exits.

  • Mark a thread with setDaemon(true) before starting it, otherwise IllegalThreadStateException.
  • A new thread inherits daemon status from its creator. The main thread is always non-daemon.
A daemon dies with main · ▶ Runs
class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread helper = new Thread(() -> {
            for (int i = 1; ; i++) {
                System.out.println("daemon heartbeat " + i);
                try { Thread.sleep(100); } catch (InterruptedException e) { }
            }
        });
        helper.setDaemon(true);
        helper.start();
        Thread.sleep(250);
        System.out.println("main ends, daemon goes too: " + helper.isDaemon());
    }
}
One possible output (threads can take turns in a different order)
daemon heartbeat 1
daemon heartbeat 2
daemon heartbeat 3
main ends, daemon goes too: true
Part 12

🆕Modern concurrency

Creating threads by hand is fine for learning. Real programs use the java.util.concurrent package.

A thread pool with Callable and Future · ▶ Runs
import java.util.*;
import java.util.concurrent.*;
class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(3);
        List<Future<Integer>> results = new ArrayList<>();
        for (int n : new int[]{10, 20, 30})
            results.add(pool.submit(() -> n * n));              // a Callable returns a value
        int sum = 0;
        for (Future<Integer> f : results) sum += f.get();      // get() waits for the answer
        pool.shutdown();
        System.out.println("sum of squares = " + sum);
    }
}
Output
sum of squares = 1400
AtomicInteger: lock free and correct · ▶ Runs
import java.util.concurrent.atomic.*;
class Main {
    public static void main(String[] args) throws InterruptedException {
        AtomicInteger count = new AtomicInteger();
        Runnable job = () -> { for (int i = 0; i < 1_000_000; i++) count.incrementAndGet(); };
        Thread a = new Thread(job), b = new Thread(job);
        a.start(); b.start(); a.join(); b.join();
        System.out.println(count.get());
    }
}
Output
2000000
Java 21 made virtual threads official. They are extremely light, so a program can run hundreds of thousands of them, which suits servers that spend most of their time waiting for networks and databases.
Ten thousand virtual threads · ▶ Runs
import java.util.concurrent.*;
import java.util.concurrent.atomic.*;
class Main {
    public static void main(String[] args) {
        AtomicInteger done = new AtomicInteger();
        try (ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 10_000; i++)
                ex.submit(() -> { Thread.sleep(10); return done.incrementAndGet(); });
        }                                                       // close() waits for all tasks
        System.out.println("finished tasks: " + done.get());
    }
}
Output
finished tasks: 10000
