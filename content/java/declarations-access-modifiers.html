Declarations and Access Modifiers

Modifiers are the small words in front of a class or member that decide who may see it, who may change it and how it behaves. Get them right and your code explains itself.

Part 1

📄Java source file structure

  • One source file can hold any number of classes.
  • At most one of them may be public, and the file must then be named after that class.
  • If no class is public, the file can have any name.
  • The compiler creates one .class file for every class, interface and enum in the file.
  • You can run any class that has a proper main.
Three classes, one file, three .class files · ▶ Runs
class A {
    public static void main(String[] args) { System.out.println("A's main"); }
}
class B {
    public static void main(String[] args) { System.out.println("B's main"); }
}
class C { }
Output
A's main
javac Test.java     → creates A.class, B.class and C.class
java A              → A's main
java B              → B's main
java C              → Error: Main method not found in class C
java D              → Error: Could not find or load main class D
Keep one class per file and name the file after it. It makes code much easier to find, and every team expects it.
Part 2

📥The import statement

Without an import you must write the full name of a class every time: java.util.ArrayList<String> list = new java.util.ArrayList<>();. An import lets you use the short name.

Explicit import

import java.util.ArrayList;

Names one class. Recommended, because a reader sees exactly where each class comes from.

Wildcard import

import java.util.*;

Brings every class of one package. Shorter, but can cause ambiguity.

Rules worth remembering

  1. java.lang and the current package are imported automatically. That is why String and System need no import.
  2. A wildcard does not reach into sub-packages. import java.util.*; does not import java.util.regex.Pattern.
  3. When two wildcards offer the same class name, using that name is an error. An explicit import wins over a wildcard.
  4. Imports exist only at compile time. They do not load anything or slow your program at run time. Java loads classes only when they are first used, which is called dynamic loading, unlike C's #include which copies headers in.
Date lives in two packages · ❌ Does not compile
import java.util.*;
import java.sql.*;
class Main {
    public static void main(String[] args) {
        Date d = new Date();
    }
}
❌ Compile error
reference to Date is ambiguous
both class java.sql.Date in java.sql and class java.util.Date in java.util match
An explicit import settles it · ▶ Runs
import java.util.*;
import java.sql.*;
import java.util.Date;
class Main {
    public static void main(String[] args) {
        Date d = new Date(0);
        System.out.println(d.getClass().getName());
    }
}
Output
java.util.Date
Wildcards skip sub-packages · ❌ Does not compile
import java.util.*;
class Main {
    public static void main(String[] args) {
        Pattern p = Pattern.compile("a+");
    }
}
❌ Compile error
cannot find symbol
symbol:   class Pattern
Part 3

⚡Static import

Java 5 added static import, which lets you use static members without writing the class name.

Math and System without their class names · ▶ Runs
import static java.lang.Math.*;
import static java.lang.System.out;
class Main {
    public static void main(String[] args) {
        out.println(sqrt(16) + " " + max(10, 20) + " " + PI);
    }
}
Output
4.0 20 3.141592653589793
  • Normal import: import pack.Class; or import pack.*;
  • Static import: import static pack.Class.member; or import static pack.Class.*;
When the same static name is available from several places, Java picks in this order: a member of the current class first, then an explicit static import, then a wildcard static import.
The current class wins · ▶ Runs
import static java.lang.Integer.MAX_VALUE;
class Main {
    static int MAX_VALUE = 999;
    public static void main(String[] args) {
        System.out.println(MAX_VALUE);
    }
}
Output
999
Two wildcards with the same name · ❌ Does not compile
import static java.lang.Integer.*;
import static java.lang.Byte.*;
class Main {
    public static void main(String[] args) {
        System.out.println(MAX_VALUE);
    }
}
❌ Compile error
reference to MAX_VALUE is ambiguous
both variable MAX_VALUE in Byte and variable MAX_VALUE in Integer match
Static imports save typing but can hide where a name comes from. Use them sparingly, for things like Math functions or test assertions.
Part 4

📦Packages

A package groups related classes and interfaces, the way folders group files. It solves name clashes, improves modularity and adds a layer of access control.

A class inside a package · ▶ Runs
package com.brainybytes.demo;
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello from " + Main.class.getName());
    }
}
Output
Hello from com.brainybytes.demo.Main
javac -d . Main.java                   → creates com/brainybytes/demo/Main.class
java com.brainybytes.demo.Main         → run it with its fully qualified name
  • Package names are lowercase reversed internet domains, such as com.icicibank.loans, so they never clash between companies.
  • -d tells the compiler where to put the package folders. . means the current folder.
  • A file may have at most one package statement, and it must be the very first statement (comments may come before it).
The order of a source file is fixed: at most one package, then any number of import lines, then the classes, interfaces and enums. An empty file is also a valid Java file.
Import before package · ❌ Does not compile
import java.util.*;
package demo;
class Main { }
❌ Compile error
class, interface, enum, or record expected
Part 5

🏛️Class level modifiers

A top level class may use only these modifiers: public, default (no word), final, abstract and strictfp. Inner classes may also be private, protected and static.

A top level class cannot be private · ❌ Does not compile
private class Main {
    public static void main(String[] args) { }
}
❌ Compile error
modifier private not allowed here
Class modifierMeaning
publicusable from any package
defaultusable only inside its own package (package-private)
finalnobody can extend it. String and every wrapper class are final
abstractnobody can create objects of it directly. It exists to be extended
strictfphistoric: forced strict IEEE floating point (see below)
A default class is invisible outside its package · ❌ Does not compile
// File: pack1/A.java
package pack1;
class A {
    public void m() { System.out.println("A.m"); }
}
// File: pack2/B.java
package pack2;
import pack1.A;
public class B {
    public static void main(String[] args) { new A().m(); }
}
❌ Compile error
A is not public in pack1; cannot be accessed from outside package
Make it public and it works · ▶ Runs
// File: pack1/A.java
package pack1;
public class A {
    public void m() { System.out.println("A.m from another package"); }
}
// File: pack2/B.java
package pack2;
import pack1.A;
public class B {
    public static void main(String[] args) { new A().m(); }
}
Output
A.m from another package
Part 6

🔒final

final class

Cannot be extended. Every method inside is effectively final too, but its variables need not be.

final method

Cannot be overridden by a child class.

final variable

Cannot be reassigned once it has a value. For a reference, the reference is fixed, but the object can still change.

Extending a final class · ❌ Does not compile
final class P { }
class C extends P {
    public static void main(String[] args) { }
}
❌ Compile error
cannot inherit from final P
Overriding a final method · ❌ Does not compile
class P {
    public final void marry() { System.out.println("arranged"); }
}
class C extends P {
    public void marry() { System.out.println("love"); }
}
❌ Compile error
marry() in C cannot override marry() in P
overridden method is final

final instance and static variables

JVM does not give final fields a default value. You must assign them yourself, exactly once, at one of these places:

final instance variablefinal static variable
at the declarationat the declaration
inside an instance block { }inside a static block static { }
inside every constructor
A final field nobody assigns · ❌ Does not compile
class Main {
    final int x;
    public static void main(String[] args) { }
}
❌ Compile error
variable x not initialized in the default constructor
Assigned in the constructor · ▶ Runs
class Main {
    final int x;
    Main() { x = 42; }
    public static void main(String[] args) {
        System.out.println(new Main().x);
    }
}
Output
42
A final reference, a changing object · ▶ Runs
final List<String> bag = new ArrayList<>();
bag.add("apple");          // fine: the object changes
bag.add("mango");
System.out.println(bag);
// bag = new ArrayList<>(); would not compile: the reference is fixed
Output
[apple, mango]
A final method parameter cannot be reassigned inside the method. Local variables that are final behave like constants once set.
Part 7

🧩abstract

An abstract method says what a child must do, without saying how. It has no body and ends with a semicolon. An abstract class is a class that may contain such methods and cannot be instantiated.

A partial plan, completed by children · ▶ Runs
abstract class Vehicle {
    abstract int wheels();                         // what, not how
    void describe() { System.out.println(getClass().getSimpleName() + " has " + wheels() + " wheels"); }
}
class Bus extends Vehicle { int wheels() { return 6; } }
class Auto extends Vehicle { int wheels() { return 3; } }
class Main {
    public static void main(String[] args) {
        new Bus().describe();
        new Auto().describe();
    }
}
Output
Bus has 6 wheels
Auto has 3 wheels

Rules

  1. A class with at least one abstract method must be declared abstract.
  2. An abstract class may have zero abstract methods. HttpServlet is a famous example, abstract only so nobody creates it directly.
  3. A child class must implement every abstract method, or be abstract itself.
  4. Abstract classes can still have constructors, fields and normal methods. The constructor runs when a child object is created.
Cannot create an abstract class · ❌ Does not compile
abstract class Shape { }
class Main {
    public static void main(String[] args) { Shape s = new Shape(); }
}
❌ Compile error
Shape is abstract; cannot be instantiated
Forgot to implement · ❌ Does not compile
abstract class Shape { abstract double area(); }
class Circle extends Shape { }
❌ Compile error
Circle is not abstract and does not override abstract method area() in Shape
abstract never talks about implementation, so it clashes with modifiers that do: final, static, private, synchronized, native and strictfp (in older Java). abstract final is the most common trap: one says "must be overridden", the other says "can never be overridden".
abstract and final together · ❌ Does not compile
abstract class Shape {
    abstract final void draw();
}
❌ Compile error
illegal combination of modifiers: abstract and final
Part 8

👀public, protected, default and private

These four control who can see a field, method or constructor. From most restricted to most open:

private < default < protected < public
Accessed fromprivatedefaultprotectedpublic
the same class✓✓✓✓
another class, same package✗✓✓✓
a child class, other package✗✗✓ (through the child reference only)✓
a non-child class, other package✗✗✗✓
The class itself must be visible first. A public method inside a default class is still unreachable from another package.

The protected twist

Outside the package, a child class can reach a protected member only through its own type (or its own children), never through a parent reference.

Through the child reference: allowed · ▶ Runs
// File: pack1/A.java
package pack1;
public class A {
    protected void m() { System.out.println("protected m"); }
}
// File: pack2/B.java
package pack2;
import pack1.A;
public class B extends A {
    public static void main(String[] args) {
        B b = new B();
        b.m();
    }
}
Output
protected m
Through a parent reference: refused · ❌ Does not compile
// File: pack1/A.java
package pack1;
public class A {
    protected void m() { System.out.println("protected m"); }
}
// File: pack2/B.java
package pack2;
import pack1.A;
public class B extends A {
    public static void main(String[] args) {
        A a = new A();
        a.m();
    }
}
❌ Compile error
m() has protected access in A
Common practice: fields private, the methods others need public, and protected only for hooks meant for subclasses.
Part 9

🧰static, native, synchronized, transient, volatile, strictfp

static

A static member belongs to the class, not to any object. It can be used through the class name without creating an object. Static code cannot touch instance members directly, because there may be no object at all.

Instance field from a static method · ❌ Does not compile
class Main {
    int x = 10;
    public static void main(String[] args) {
        System.out.println(x);
    }
}
❌ Compile error
non-static variable x cannot be referenced from a static context
Can I usefrom an instance methodfrom a static method
an instance memberyesno (needs an object)
a static memberyesyes

Static methods can be overloaded and are inherited, but they cannot be overridden. A child with the same static method hides the parent's version (covered in the OOP chapter).

native

A native method is written in another language such as C, and connected through the Java Native Interface. Its declaration ends with a semicolon, like public native int hashCode(); in Object.

synchronized

Only one thread at a time may run a synchronized method or block on the same object. It prevents data from getting mixed up, at the cost of waiting threads. See the Multithreading chapter.

transient

A transient field is skipped during serialization. Passwords are the usual example. See the Serialization chapter.

volatile

A volatile field is always read from and written to main memory, so every thread sees the latest value. It does not make compound actions like count++ safe.

strictfp

strictfp used to force strict IEEE floating point on every platform. Since Java 17 all floating point is strict anyway, so the keyword is obsolete and gives a warning.

ModifierClassMethodVariableBlock
staticinner only✓✓✓
native✗✓✗✗
synchronized✗✓✗✓
transient✗✗✓✗
volatile✗✗✓✗
strictfp✓✓✗✗
The only modifier allowed on a local variable is final. The only modifiers that work for constructors are the four access levels.
Part 10

🔌Interfaces

An interface is a contract: a list of services a class promises to provide. The person using it only needs the contract, not the implementation. JDBC is a classic example: Java defines interfaces like Connection, and each database vendor writes the classes.

One contract, two implementations · ▶ Runs
interface Payment {
    void pay(int amount);
}
class Upi implements Payment {
    public void pay(int amount) { System.out.println("UPI paid " + amount); }
}
class Card implements Payment {
    public void pay(int amount) { System.out.println("Card paid " + amount); }
}
class Main {
    public static void main(String[] args) {
        Payment[] options = { new Upi(), new Card() };
        for (Payment p : options) p.pay(250);
    }
}
Output
UPI paid 250
Card paid 250

Rules for interface members

  • Every method without a body is automatically public abstract.
  • Every variable is automatically public static final, so it must be initialized and can never change.
  • A class that implements an interface must make the methods public, or be abstract.
Implementing without public · ❌ Does not compile
interface Greeter { void greet(); }
class Main implements Greeter {
    void greet() { System.out.println("hi"); }
    public static void main(String[] args) { }
}
❌ Compile error
greet() in Main cannot implement greet() in Greeter
attempting to assign weaker access privileges; was public
Interface variables are constants · ❌ Does not compile
interface Limits { int MAX = 10; }
class Main implements Limits {
    public static void main(String[] args) { MAX = 20; }
}
❌ Compile error
cannot assign a value to static final variable MAX

extends and implements

  • A class extends one class only.
  • A class can implement any number of interfaces, and extend a class at the same time (extends comes first).
  • An interface can extend any number of interfaces, but never implements anything.
Java snippet
class Phone extends Device implements Camera, MusicPlayer { }
interface SmartTv extends Display, Speaker { }
Java 8 lets interfaces contain default methods (with a body that implementing classes inherit) and static methods. Java 9 added private methods to share code between defaults. Interfaces still cannot hold instance fields or constructors.
Default and static methods in an interface · ▶ Runs
interface Greeter {
    String name();
    default String greet() { return "Hello, " + name() + emoji(); }
    static Greeter of(String n) { return () -> n; }
    private String emoji() { return " 👋"; }
}
class Main {
    public static void main(String[] args) {
        System.out.println(Greeter.of("Asha").greet());
    }
}
Output
Hello, Asha 👋
Part 11

⚔️Naming conflicts in interfaces

Methods

If two interfaces declare the same method with the same signature and return type, one implementation in the class satisfies both. If they have the same signature but different return types, no class can implement both.

One method satisfies two interfaces · ▶ Runs
interface Left { void m(); }
interface Right { void m(); }
class Main implements Left, Right {
    public void m() { System.out.println("one m for both"); }
    public static void main(String[] args) { new Main().m(); }
}
Output
one m for both
Same name, different return types · ❌ Does not compile
interface Left { void m(); }
interface Right { int m(); }
class Main implements Left, Right {
    public void m() { }
    public static void main(String[] args) { }
}
❌ Compile error
Main is not abstract and does not override abstract method m() in Right

Variables

If two interfaces define a constant with the same name, using the plain name is ambiguous. Use the interface name to say which one you mean.

Ambiguous constant · ❌ Does not compile
interface Left { int x = 777; }
interface Right { int x = 888; }
class Main implements Left, Right {
    public static void main(String[] args) { System.out.println(x); }
}
❌ Compile error
reference to x is ambiguous
both variable x in Left and variable x in Right match
Qualify it · ▶ Runs
interface Left { int x = 777; }
interface Right { int x = 888; }
class Main implements Left, Right {
    public static void main(String[] args) { System.out.println(Left.x + " " + Right.x); }
}
Output
777 888
Part 12

🏷️Marker interfaces and adapter classes

Marker interfaces

A marker interface has no methods at all. Implementing it simply tags your class with an ability that the JVM or a library checks for.

  • Serializable: objects may be saved to a file or sent over a network.
  • Cloneable: Object.clone() may copy the object.
  • RandomAccess: the list supports fast access by index.
clone without Cloneable · 💥 Crashes at run time
class Sheep {
    public static void main(String[] args) throws Exception {
        Sheep dolly = new Sheep();
        Object copy = dolly.clone();
    }
}
💥 Runtime error
Exception in thread "main" java.lang.CloneNotSupportedException: Sheep
Add the marker and it works · ▶ Runs
class Sheep implements Cloneable {
    public static void main(String[] args) throws Exception {
        Sheep dolly = new Sheep();
        Object copy = dolly.clone();
        System.out.println(copy != dolly);
    }
}
Output
true

Adapter classes

An interface with many methods forces you to write all of them, even the ones you do not need. An adapter is an abstract class that implements the interface with empty bodies, so you override only what you care about. GenericServlet and the Swing WindowAdapter are well known adapters.

Override only what you need · ▶ Runs
interface Remote {
    void powerOn(); void powerOff(); void volumeUp(); void volumeDown(); void mute();
}
abstract class RemoteAdapter implements Remote {
    public void powerOn() { } public void powerOff() { } public void volumeUp() { }
    public void volumeDown() { } public void mute() { }
}
class KidsRemote extends RemoteAdapter {
    public void volumeUp() { System.out.println("LOUDER!"); }
}
class Main {
    public static void main(String[] args) { new KidsRemote().volumeUp(); }
}
Output
LOUDER!
With default methods, many adapters are no longer needed, because an interface can supply empty defaults itself. An interface with exactly one abstract method is a functional interface and can be written as a lambda.

"An abstract class cannot be instantiated, so why does it have a constructor?" Because creating a child object runs the parent constructor too, which initializes the fields the abstract class defines.
An abstract class constructor runs for the child · ▶ Runs
abstract class Person {
    String name;
    Person(String name) { this.name = name; System.out.println("Person constructor ran"); }
}
class Student extends Person {
    int roll;
    Student(String name, int roll) { super(name); this.roll = roll; }
}
class Main {
    public static void main(String[] args) {
        Student s = new Student("Kiran", 7);
        System.out.println(s.name + " " + s.roll);
    }
}
Output
Person constructor ran
Kiran 7
