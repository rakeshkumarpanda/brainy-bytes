Internationalization (I18N)

India writes 12,34,567.89, America writes 1,234,567.89 and Germany writes 1.234.567,89. Internationalization lets one program speak to all of them correctly, without rewriting a line of logic.

Part 1

🗺️What is I18N

Internationalization (shortened to I18N, because there are 18 letters between the I and the N) means designing a program so it can adapt to many countries: their number formats, currencies, dates and languages.

Localization (L10N) is the second step: actually supplying the formats and translations for one country.

Locale

Who is the user: a language plus a country.

NumberFormat

Numbers, currencies and percentages in that locale's style.

DateFormat and DateTimeFormatter

Dates and times in that locale's style.

ResourceBundle

Translated messages chosen by locale.

Part 2

📍Locale

A java.util.Locale object describes a language and, optionally, a country. It is final, Cloneable and Serializable.

Making and inspecting locales · ▶ Runs
Locale india = Locale.of("hi", "IN");           // Java 19 and later
Locale us = Locale.US;                           // ready-made constant
Locale de = Locale.GERMANY;
for (Locale l : new Locale[]{india, us, de})
    System.out.println(l + " → " + l.getDisplayLanguage(Locale.ENGLISH) + ", " + l.getDisplayCountry(Locale.ENGLISH));
System.out.println(india.getDisplayLanguage(india));
Output
hi_IN → Hindi, India
en_US → English, United States
de_DE → German, Germany
हिन्दी
The constructors new Locale("hi", "IN") are deprecated since Java 19. Use Locale.of(...), a constant such as Locale.UK, or Locale.forLanguageTag("hi-IN").
Locale.getDefault() returns the locale of the machine, and Locale.getAvailableLocales() lists every locale the JVM supports.
Part 3

💰NumberFormat

java.text.NumberFormat is abstract. Ask its factory methods for an object, then call format to turn a number into text, or parse to go the other way.

Factory methodFor
getInstance(locale) or getNumberInstance(locale)plain numbers
getCurrencyInstance(locale)money
getPercentInstance(locale)percentages
One number, four countries · ▶ Runs
double amount = 1234567.891;
Locale[] places = { Locale.of("en", "IN"), Locale.US, Locale.UK, Locale.GERMANY };
for (Locale l : places) {
    NumberFormat num = NumberFormat.getInstance(l);
    NumberFormat cur = NumberFormat.getCurrencyInstance(l);
    System.out.println(l + "\t" + num.format(amount) + "\t" + cur.format(amount));
}
Output
en_IN	1,234,567.891	₹1,234,567.89
en_US	1,234,567.891	$1,234,567.89
en_GB	1,234,567.891	£1,234,567.89
de_DE	1.234.567,891	1.234.567,89 €

Look closely at the Indian line: Java picks the rupee sign, but still groups by thousands (1,234,567). The classic java.text formatter supports only one grouping size, so it cannot write the lakh and crore style 12,34,567 on its own. Libraries such as ICU4J can, or you can write a tiny helper.

Lakh and crore grouping with a small helper · ▶ Runs
class Main {
    static String indian(long n) {
        String s = Long.toString(n);
        if (s.length() <= 3) return s;
        String last3 = s.substring(s.length() - 3), rest = s.substring(0, s.length() - 3);
        return rest.replaceAll("\\B(?=(\\d{2})+$)", ",") + "," + last3;   // commas every 2 digits, then the last 3
    }
    public static void main(String[] args) {
        for (long n : new long[]{999, 1234567, 123456789, 10000000})
            System.out.println(n + " → " + indian(n));
    }
}
Output
999 → 999
1234567 → 12,34,567
123456789 → 12,34,56,789
10000000 → 1,00,00,000
Percentages and parsing · ▶ Runs
NumberFormat pct = NumberFormat.getPercentInstance(Locale.US);
System.out.println(pct.format(0.875));
NumberFormat de = NumberFormat.getInstance(Locale.GERMANY);
Number n = de.parse("1.234,5");             // German style text back to a number
System.out.println(n.doubleValue() * 2);
Output
88%
2469.0
parse throws the checked ParseException when the text does not fit the format, so it must be handled or declared.

🔢Controlling digits

A NumberFormat can be told how many digits to show before and after the decimal point.

MethodEffect
setMaximumFractionDigits(n)round to at most n decimals
setMinimumFractionDigits(n)pad with zeros to at least n decimals
setMaximumIntegerDigits(n)keep only the last n digits before the point
setMinimumIntegerDigits(n)pad with zeros in front
Four settings, four results · ▶ Runs
NumberFormat a = NumberFormat.getInstance(Locale.US);
a.setMaximumFractionDigits(2);
System.out.println(a.format(123.4567));
NumberFormat b = NumberFormat.getInstance(Locale.US);
b.setMinimumFractionDigits(3);
System.out.println(b.format(123.4));
NumberFormat c = NumberFormat.getInstance(Locale.US);
c.setMaximumIntegerDigits(2);
System.out.println(c.format(1234.5));
NumberFormat d = NumberFormat.getInstance(Locale.US);
d.setMinimumIntegerDigits(5);
d.setGroupingUsed(false);
System.out.println(d.format(42));
Output
123.46
123.400
34.5
00042
NumberFormat rounds with HALF_EVEN (banker's rounding) by default. So with 0 decimals, 2.5 becomes 2 and 3.5 becomes 4.
Banker's rounding · ▶ Runs
NumberFormat f = NumberFormat.getInstance(Locale.US);
f.setMaximumFractionDigits(0);
System.out.println(f.format(2.5) + " " + f.format(3.5) + " " + f.format(2.51));
Output
2 4 3

📅DateFormat

java.text.DateFormat formats an old style java.util.Date. Pick a style and a locale.

StyleConstant value
DateFormat.FULL0
DateFormat.LONG1
DateFormat.MEDIUM2 (the default)
DateFormat.SHORT3
The same moment in four styles and three countries · ▶ Runs
TimeZone.setDefault(TimeZone.getTimeZone("UTC"));
Date d = new Date(1792368000000L);               // a fixed moment, so the output never changes
for (int style : new int[]{DateFormat.FULL, DateFormat.LONG, DateFormat.MEDIUM, DateFormat.SHORT})
    System.out.println(DateFormat.getDateInstance(style, Locale.US).format(d));
System.out.println(DateFormat.getDateInstance(DateFormat.LONG, Locale.UK).format(d));
System.out.println(DateFormat.getDateInstance(DateFormat.LONG, Locale.ITALY).format(d));
Output
Monday, October 19, 2026
October 19, 2026
Oct 19, 2026
10/19/26

DateFormat objects are not thread safe. Do not share one between threads, or switch to the modern java.time classes below, which are.
Part 6

⏰Modern dates with java.time

Java 8 introduced java.time. Its classes are immutable and thread safe, and DateTimeFormatter replaces DateFormat for new code.
Localised dates with java.time · ▶ Runs
import java.time.*;
import java.time.format.*;
import java.util.*;
class Main {
    public static void main(String[] args) {
        LocalDate diwali = LocalDate.of(2026, 11, 8);
        for (Locale l : new Locale[]{Locale.US, Locale.of("hi", "IN"), Locale.GERMANY, Locale.of("ar", "SA")}) {
            DateTimeFormatter f = DateTimeFormatter.ofLocalizedDate(FormatStyle.LONG).withLocale(l);
            System.out.println(l + "\t" + diwali.format(f));
        }
        System.out.println(diwali.getDayOfWeek() + ", " + diwali.plusDays(30));
    }
}
Output
en_US	November 8, 2026
hi_IN	8 नवंबर 2026
de_DE	8. November 2026
ar_SA	8 نوفمبر 2026
SUNDAY, 2026-12-08
Part 7

💬ResourceBundle: translated messages

Text shown to users should never be hard coded. Put each language's messages in its own resource bundle and let Java pick the right one for the locale. Bundles are usually .properties files, such as Messages_hi.properties. Here they are written as small classes so the example runs on its own.

Greeting in the user's language · ▶ Runs
// File: Messages.java
import java.util.*;
public class Messages extends ListResourceBundle {
    protected Object[][] getContents() { return new Object[][]{ {"hello", "Hello"}, {"bye", "Goodbye"} }; }
}
// File: Messages_hi.java
import java.util.*;
public class Messages_hi extends ListResourceBundle {
    protected Object[][] getContents() { return new Object[][]{ {"hello", "नमस्ते"} }; }
}
// File: Messages_de.java
import java.util.*;
public class Messages_de extends ListResourceBundle {
    protected Object[][] getContents() { return new Object[][]{ {"hello", "Hallo"}, {"bye", "Tschüss"} }; }
}
// File: Main.java
import java.util.*;
public class Main {
    public static void main(String[] args) {
        Locale.setDefault(Locale.ENGLISH);
        for (Locale l : new Locale[]{Locale.ENGLISH, Locale.of("hi"), Locale.GERMAN, Locale.FRENCH}) {
            ResourceBundle rb = ResourceBundle.getBundle("Messages", l);
            System.out.println(l + ": " + rb.getString("hello") + " / " + rb.getString("bye"));
        }
    }
}
Output
en: Hello / Goodbye
hi: नमस्ते / Goodbye
de: Hallo / Tschüss
fr: Hello / Goodbye

Hindi has no "bye" message, so Java falls back to the base bundle for it. French has no bundle at all, so it uses the base bundle completely.
