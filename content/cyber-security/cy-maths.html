Lesson 1 of 9

Bits, bytes, binary and hex

Every photo, password and message on a computer is stored as a long row of tiny switches that are either off or on. We write off as zero and on as one, and each switch is called a bit, short for binary digit. Eight bits make a byte, which can hold 256 different values, enough for one letter of the English alphabet. Security people read bytes all day long: in network packets, in malware files, in encryption keys. Writing eight zeros and ones for every byte is slow and easy to misread, so we use hexadecimal, base sixteen, where one byte is always exactly two symbols. When you see something like zero x C A, that is just the number 202 written in hex. In this lesson you will learn to switch between decimal, binary and hex by hand, so these strings never scare you again.

Source: RFC 4648 for Base64, RFC 3629 for UTF-8, and Katz and Lindell, Introduction to Modern Cryptography.

What it is
A bit is a single 0 or 1. A byte is 8 bits and holds a value from 0 to 255. Binary writes numbers in base 2, hexadecimal (hex) in base 16 with the digits 0 to 9 and A to F.
Why we need it
Keys, hashes, packets and files are all bytes. To read a hash, spot a malware signature or understand a key length, you must be at home with bits and hex.
How it works
Each binary place is worth double the one to its right: 1, 2, 4, 8, 16 and so on. To convert to binary, divide by 2 again and again and read the remainders from the bottom up. To convert binary to hex, cut the bits into groups of four, because 24 = 16.

Base64 and hex are encodings, not encryption. Anyone can decode them in one line. Attackers often hide data in Base64 hoping a human reviewer will not look closely.
Lesson 2 of 9

XOR: the most important operation in cryptography

If cryptography had a favourite operation, it would be XOR, which means exclusive or. It takes two bits and answers one simple question: are they different? If yes, the answer is one. If they are the same, the answer is zero. That sounds too simple to be useful, but XOR has a magic property: doing it twice with the same key brings back exactly what you started with. In 1917 an engineer at AT and T named Gilbert Vernam used this idea to encrypt teleprinter messages with a paper tape of random key. Later, Claude Shannon proved that if the key is truly random, as long as the message, and never used again, nobody can ever break it. That is the one time pad. Today XOR is inside AES, inside stream ciphers, inside hashes and inside checksums.
What it is
XOR (exclusive or, written ⊕ or ^) outputs 1 when its two input bits differ and 0 when they match. On bytes, it works on each of the 8 bit pairs separately.
Why we need it
XOR is fast, it undoes itself, and if one input is random the output is random too. This makes it the basic mixing step of almost every cipher.
How it works
To encrypt, XOR the message with a key: c = m ⊕ k. To decrypt, XOR again with the same key: c ⊕ k = m ⊕ k ⊕ k = m. The key bits decide which message bits get flipped.

XOR rulesExam favourite
a ⊕ 0 = a    a ⊕ a = 0    a ⊕ b = b ⊕ a    (a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)
Together these give (m ⊕ k) ⊕ k = m, so XOR with the same key decrypts.
XOR is addition without carry
a ⊕ b = (a + b) mod 2
For single bits. This is why XOR is "addition" in the field of two elements used inside AES.
Worked example: why reusing an XOR key is fatal
  1. Two messages m1 and m2 are encrypted with the same key k: c1 = m1 ⊕ k and c2 = m2 ⊕ k.
  2. An eavesdropper XORs the two ciphertexts: c1 ⊕ c2 = m1 ⊕ k ⊕ m2 ⊕ k.
  3. c1 ⊕ c2 = m1 ⊕ m2
  4. The key has vanished. The attacker now has the XOR of two real messages, and guessing a common word in one reveals the same spot in the other.
  5. This is why a one time pad key must be used only once. Soviet messages that reused pad pages were partly read by the US Venona project.
Lesson 3 of 9

Modular arithmetic: maths on a clock

You already know modular arithmetic, because you read clocks. If it is ten o’clock and you wait five hours, it is three o’clock, not fifteen o’clock. The numbers wrap around after twelve. Mathematicians write this as fifteen mod twelve equals three. The great German mathematician Carl Friedrich Gauss wrote the rules down in 1801, and almost two hundred years later these same rules became the base of RSA, Diffie Hellman and elliptic curve cryptography. The reason is beautiful. Some sums are easy one way on a clock, but very hard to undo, like mixing paint. Here we learn the basic rules. The Cryptography section builds the full number theory on top of them.
What it is
a mod n is the remainder when a is divided by n. Working "mod n" means every result wraps around into the range 0 to n − 1, like the hours on a clock.
Why we need it
Computers have fixed size numbers, so arithmetic wraps naturally. More importantly, public key cryptography is built on operations that are easy mod n but hard to reverse, such as powers mod n.
How it works
Add, subtract and multiply as normal, then take the remainder. You can take mod after every step and get the same final answer, which keeps the numbers small.

DefinitionExam favourite
a mod n = r, where a = q · n + r and 0 ≤ r < n
q is the whole number quotient, r the remainder.
RulesExam favourite
(a + b) mod n = ((a mod n) + (b mod n)) mod n
(a × b) mod n = ((a mod n) × (b mod n)) mod n
So big products never need to be computed in full.
Congruence
a ≡ b (mod n) means n divides a − b
17 ≡ 5 (mod 12), because 12 divides 12.
Caesar cipher
c = (m + k) mod 26    m = (c − k) mod 26
Letters A to Z as 0 to 25, shifted by the key k.
Worked example: a big power mod a small number, without big numbers
  1. Find 74 mod 10.
  2. 72 = 49, and 49 mod 10 = 9.
  3. 74 = (72)2, so take 92 = 81.
  4. 81 mod 10 = 1, so 74 mod 10 = 1
  5. Check: 74 = 2401, which ends in 1. Squaring and reducing at each step is the "square and multiply" method RSA uses on numbers with hundreds of digits.
Common mistake
In maths and Python, −3 mod 26 = 23. In C and Java, −3 % 26 gives −3. Many cipher bugs come from negative remainders.
Lesson 4 of 9

Counting keys and passwords: how big is big enough?

How long would it take to guess your password by trying every possibility? This question is called brute force, and the answer is just counting. If a lock has four dials with ten digits each, there are ten times ten times ten times ten, ten thousand combinations. A thief trying one per second needs under three hours. Every extra dial multiplies the work by ten. Computer keys work the same way, except that each extra bit doubles the work. Cryptographers today want at least 128 bits of security. Two to the power 128 is so large that if every computer on Earth tried keys for the age of the universe, they would still not finish. Counting tells us when a secret is long enough, and why short passwords fall in minutes.
What it is
The key space is the number of possible keys or passwords. With an alphabet of N symbols and length L, it is NL. Its size in bits is L × log2 N.
Why we need it
A cipher is only as strong as its key space allows. If the key space is small, an attacker simply tries every key. Counting tells us how long that takes.
How it works
Count the possibilities, divide by the attacker’s guessing speed. On average the right key is found halfway through, so the expected time is half the worst case.

Brute force time
worst = space / rate    average = space / (2 × rate)
Rate is guesses per second.
Doubling rule
2n+1 = 2 × 2n
One more bit doubles the work. Ten more bits multiply it by 1024.
Real world scenario: the 4 digit phone PIN

A phone PIN has 10,000 possibilities. A computer could try them all in a blink. Phones stay safe because of a different control: after a few wrong tries they make you wait, and some can wipe themselves. This limits the attacker to maybe a few guesses an hour. Security often combines a small key space with a rate limit. Without the rate limit, the PIN would be useless.

Common mistake
These counts assume random choices. Human passwords are not random: "Password@123" is in every attacker’s list. Real strength depends on how the password was chosen, not just its length.
Lesson 5 of 9

Probability traps: the birthday paradox and the base rate

Two puzzles from probability shape security more than almost any others. The first is the birthday paradox. In a class of only 23 students, there is a better than even chance that two share a birthday. It feels wrong because we compare ourselves with others, but the question is about any pair, and 23 students make 253 pairs. In cryptography, this means a hash with 128 bits of output can be broken for collisions with only about two to the power 64 tries, not two to the power 128. The second puzzle is the base rate fallacy. In 2000 the Swedish researcher Stefan Axelsson showed that an intrusion detector that is right 99 percent of the time can still raise mostly false alarms, simply because real attacks are so rare. Both puzzles are about thinking carefully before trusting your gut.
Birthday bound (exact)
P(repeat) = 1 − (N/N)((N−1)/N)...((N−k+1)/N)
k tries, N possible values.
Birthday bound (quick)Exam favourite
P(repeat) ≈ 1 − e−k2/(2N)    50% at k ≈ 1.1774 √N
For a b bit hash, N = 2b, so about 2b/2 tries find a collision.
Bayes ruleExam favourite
P(attack | alarm) = P(alarm | attack) P(attack)P(alarm)
P(alarm) = P(alarm | attack) P(attack) + P(alarm | normal) P(normal).

Worked example: an alarm from a 99% accurate detector
  1. Base rate: 1 attack per 1,000 events, P(attack) = 0.001. Detection rate 0.99, false alarm rate 0.01.
  2. P(alarm) = 0.99 × 0.001 + 0.01 × 0.999 = 0.00099 + 0.00999 = 0.01098.
  3. P(attack | alarm) = 0.00099 / 0.01098 ≈ 0.090
  4. Only about 9% of alarms are real attacks. Analysts would chase 10 false alarms for every real one.
  5. Cutting the false alarm rate to 0.001 gives 0.00099 / (0.00099 + 0.000999) ≈ 0.50. Reducing false alarms helped far more than raising detection could.
In the exam
When someone says a detector is "99% accurate", always ask: how rare is the thing it detects, and what is its false alarm rate? Without the base rate, accuracy means little.
Lesson 6 of 9

Entropy: measuring surprise and randomness

In 1948 Claude Shannon, working at Bell Labs, published a paper that started information theory. He asked how to measure information, and his answer was surprise. If I tell you the sun rose this morning, you learn almost nothing. If I tell you it snowed in Chennai, you learn a lot. Shannon turned this into a formula called entropy, measured in bits. For security, entropy answers two practical questions. How unpredictable is a password or a key? And does a file look random? Encrypted and compressed data look almost perfectly random, with close to eight bits of entropy per byte. Malware analysts use this to spot packed or encrypted parts of a suspicious program, and network defenders use it to spot data being smuggled out.
What it is
Shannon entropy is the average surprise of a symbol, in bits. If one symbol is certain, entropy is 0. If all N symbols are equally likely, entropy is the largest possible, log2 N.
Why we need it
It measures how hard a secret is to guess and whether data looks random. A key with low entropy can be guessed, however long it looks.
How it works
Count how often each symbol appears, turn the counts into probabilities p, and add up −p log2 p over every symbol.
Download this program (.py)Save it, open it in any editor and run it with python3 entropy.py.
Shannon entropyExam favourite
H = − Σ pi log2 pi
Sum over every symbol i with probability pi. Units: bits per symbol.
Maximum entropy
Hmax = log2 N
All N symbols equally likely. For bytes N = 256, so at most 8 bits per byte.
Entropy of a random secret
H = L × log2 N
L symbols chosen uniformly at random from N. A random 4 word passphrase from a 7,776 word list: 4 × 12.9 ≈ 51.7 bits.
Going deeper: Min entropy, the measure cryptographers really use

Shannon entropy is an average. An attacker cares about the most likely guess. Min entropy is H∞ = −log2(max pi). If a password scheme gives "123456" with probability 1/100, its min entropy is only log2 100 ≈ 6.6 bits, however many other passwords are possible. Random number generators for keys (NIST SP 800-90B) are assessed with min entropy for exactly this reason.

Lesson 7 of 9

Encoding, encryption and hashing compared

Three words are mixed up so often that they cause real security failures: encoding, encryption and hashing. All three turn data into something that looks different, so beginners treat them as the same thing. They are not. Encoding, like Base64 or hex, just changes the format so data travels safely, and anyone can reverse it. Encryption hides data with a key, and only someone with the key can reverse it. Hashing makes a fixed size fingerprint that cannot be reversed at all, and is used to check that data has not changed or to store passwords. Companies have leaked millions of passwords because a developer thought Base64 was encryption. After this lesson you will never make that mistake.

Bottom line: Encoding is for transport, encryption is for secrecy, hashing is for fingerprints. Never use encoding to protect anything.

Lesson 8 of 9

From beginner to expert

The maths in this chapter grows with you. At school you count combinations and convert numbers to binary. At college you use modular arithmetic, XOR and Bayes rule to reason about ciphers and detectors. At masters level you meet groups and fields, the algebra that makes AES and elliptic curves work, and you use probability bounds to prove that an attack needs a certain number of tries. At research level, security proofs measure an attacker’s advantage as a function of the number of queries, and these bounds decide exact key and block sizes in modern standards. Do not worry if the top levels feel far away. Each later chapter climbs one more step.
One idea, four depths

Computers store everything as 0s and 1s. Hex is a short way to write them. XOR flips bits where the key has a 1, and doing it twice undoes it. Longer passwords have many more possibilities.

Convert between bases, use mod n rules, compute key spaces as NL and bits as L log2 N, apply the birthday bound 2b/2 for collisions, and Bayes rule for alert accuracy.

The integers mod n form a ring, and mod a prime p they form a field where every non zero number has an inverse. XOR on bytes is addition in GF(28), the field inside AES. The birthday bound comes from 1 − e−k(k−1)/(2N), and min entropy measures guessing resistance.

Provable security bounds an adversary’s advantage, for example q2/2n for a block cipher modelled as a random permutation after q queries (the PRP to PRF switching lemma). Such birthday type bounds are why 64 bit block ciphers fell to the Sweet32 attack (2016) and why modes limit how much data one key may encrypt.

Beginner
Convert numbers to binary and hex, use XOR, and count possible passwords.
Intermediate
Do mod n arithmetic, compute bits of strength, apply the birthday bound and Bayes rule, and compute entropy.
Expert
Work in finite fields, use min entropy, and read birthday type advantage bounds in security proofs.
Lesson 9 of 9

Chapter summary

  1. A byte is 8 bits (0 to 255). Convert to binary by repeated division by 2, to hex by groups of 4 bits. One byte = 2 hex digits.
  2. Encoding (Base64, hex, UTF-8) is not encryption. Base64 makes 4 characters from every 3 bytes.
  3. XOR: 1 when bits differ. a ⊕ a = 0 and a ⊕ 0 = a, so (m ⊕ k) ⊕ k = m. Reusing an XOR key leaks m1 ⊕ m2.
  4. a mod n is the remainder. You may reduce mod n after every step. Caesar: c = (m + k) mod 26.
  5. Key space NL, strength L log2 N bits, average brute force time = space / (2 × rate). Each bit doubles the work.
  6. Birthday bound: about 2b/2 tries find a collision in a b bit hash. 23 people give a 50% chance of a shared birthday.
  7. Base rate: P(attack | alarm) = TP / (TP + FP). Rare attacks make most alarms false, so false alarm rate matters most.
  8. Entropy H = −Σ p log2 p. Random bytes are near 8 bits per byte, a sign of encryption or packing.
