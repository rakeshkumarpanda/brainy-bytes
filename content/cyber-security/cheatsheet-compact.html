Step 1Foundations · Start here

1.1What cybersecurity is: goals, threats and layers

  • Cybersecurity Protects systems and data from people who want to steal, change or stop them. People, process and technology together.
  • CIA triad Confidentiality (right people read), integrity (no unnoticed change), availability (works when needed). AAA: authentication, authorisation, accounting.
  • Words Asset, threat, vulnerability (weakness), exploit (method), risk = likelihood × impact, control, attack surface, zero day, CVE.
  • Defence in depth Independent layers: P(breach) = product of miss chances. Many tries: P(at least one) = 1 − (1 − p)n.
  • Principles Least privilege, fail safe defaults, complete mediation, economy of mechanism, open design (Kerckhoffs), separation of privilege, zero trust.
  • Money Expected loss = probability × cost. Gordon and Loeb: best spend under about 37% (1/e) of expected loss.
  • AAAAuthentication (who are you), Authorisation (what may you do), Accounting (what did you do)
  • Risk in one linerisk = likelihood × impact
  • Chance that an attack passes every layerP(breach) = m1 × m2 × ... × mk
  • Chance that at least one of many attempts succeedsP(at least one) = 1 − (1 − p)n
  • Expected lossexpected loss = probability × cost
  • Gordon and Loeb boundbest spend ≤ (1 / e) × expected loss ≈ 0.368 × expected loss
  • Exam Goals can pull against each other. Locking a file with a strong password raises confidentiality but can hurt availability if the password is lost. Good security balances all three for each asset.
  • Trap A vulnerability is the weakness, an exploit is the method that uses it, and a threat is who might use it. Students often swap these three in exams.
  • Exam The attacker needs to win once. The defender needs to win every time. Layers change this: now the attacker must win at every layer, every time.
  • Exam Open design is also called Kerckhoffs’s principle (1883): a cipher should stay safe even if the enemy knows everything about it except the key. Hiding the method is called security through obscurity, and it is not enough on its own.
  • Trap Exam details (number of questions, time, passing score, price) change every few years. Always check the official page of CompTIA, EC-Council, ISC2 or OffSec before you book. The revision chapter at the end of this subject lists them as checked when it was written.

1.2Risk in numbers: matrices, ALE, attack trees and continuity

  • Risk Risk = likelihood × impact. Inherent before controls, residual after. Appetite = what the business accepts.
  • Money SLE = AV × EF. ALE = SLE × ARO. Control value = ALEbefore − ALEafter − cost.
  • Responses and controls Avoid, reduce, transfer, accept. Categories: technical, managerial, operational, physical. Types: preventive, deterrent, detective, corrective, compensating, directive.
  • Threat models STRIDE: spoofing, tampering, repudiation, information disclosure, DoS, elevation of privilege. Attack trees: AND adds, OR takes the cheapest.
  • Uncertainty FAIR: risk = loss event frequency × loss magnitude. Monte Carlo gives the average and the 1 in 10 or 1 in 100 year loss.
  • Time RTO = time to restore, RPO = data you may lose. A = MTBF / (MTBF + MTTR). 99.9% = 8.76 h down per year.
  • Riskrisk = likelihood × impact
  • Single loss expectancySLE = AV × EF
  • Annualised loss expectancyALE = SLE × ARO
  • Value of a control (safeguard)value = ALEbefore − ALEafter − annual cost of the control
  • Attack tree with costsAND node: cost = sum of children    OR node: cost = smallest child
  • FAIR top levelrisk = loss event frequency × loss magnitude
  • Availability from MTBF and MTTRA = MTBF / (MTBF + MTTR)
  • Downtime alloweddowntime per year = (1 − A) × 525,600 minutes
  • Trap Matrix scores are labels, not real measurements. Do not add or average them across risks, and do not say a 12 is exactly twice a 6. Use them to sort and to start a conversation.
  • Exam ARO is a rate per year, not a probability. An event expected twice a year has ARO = 2. For rare events the ARO and the yearly probability are close, but they are not the same thing.
  • Exam One control can belong to a category and a type at once. A CCTV camera is a physical control that is both deterrent (people see it) and detective (it records).
  • Trap Accepting a risk is a real decision only when an owner with authority signs it, with a date to review. Ignoring a risk is not accepting it.
  • Exam RPO is about data loss and decides how often you back up. RTO is about downtime and decides how fast you restore. Exams love to swap them.

1.3The maths for security: bits, XOR, mod, counting, probability and entropy

  • Bits and hex Byte = 8 bits = 0 to 255 = 2 hex digits. n bits hold 2n values. Encoding (Base64, hex) is not encryption.
  • XOR 1 when bits differ. (m ⊕ k) ⊕ k = m. Same key twice leaks m1 ⊕ m2.
  • Mod a mod n = remainder. Reduce after every step. Caesar c = (m + k) mod 26.
  • Counting Key space NL, strength L log2 N bits. Each bit doubles brute force work.
  • Birthday and Bayes Collisions after about 2b/2 tries. P(attack | alarm) = TP / (TP + FP): rare attacks make most alarms false.
  • Entropy H = −Σ p log2 p. Max log2 N. Random or encrypted bytes are near 8 bits per byte.
  • Value of a binary numberbn−1·2n−1 + ... + b1·2 + b0
  • How many values n bits can hold2n values, from 0 to 2n − 1
  • XOR rulesa ⊕ 0 = a    a ⊕ a = 0    a ⊕ b = b ⊕ a    (a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)
  • Definitiona mod n = r, where a = q · n + r and 0 ≤ r < n
  • Rules(a + b) mod n = ((a mod n) + (b mod n)) mod n
    (a × b) mod n = ((a mod n) × (b mod n)) mod n
  • Key spaceNL
  • Bits of strengthbits = log2(NL) = L × log2 N
  • Birthday bound (quick)P(repeat) ≈ 1 − e−k2/(2N)    50% at k ≈ 1.1774 √N
  • Bayes ruleP(attack | alarm) = P(alarm | attack) P(attack)P(alarm)
  • Shannon entropyH = − Σ pi log2 pi
  • Trap Base64 and hex are encodings, not encryption. Anyone can decode them in one line. Attackers often hide data in Base64 hoping a human reviewer will not look closely.
  • Trap In maths and Python, −3 mod 26 = 23. In C and Java, −3 % 26 gives −3. Many cipher bugs come from negative remainders.
  • Trap These counts assume random choices. Human passwords are not random: "Password@123" is in every attacker’s list. Real strength depends on how the password was chosen, not just its length.
  • Exam When someone says a detector is "99% accurate", always ask: how rare is the thing it detects, and what is its false alarm rate? Without the base rate, accuracy means little.

Step 2Foundations · How computers and networks work

2.1Operating systems: users, permissions, processes and logs

  • Kernel Programs run in user mode (ring 3), the kernel in kernel mode (ring 0). System calls are the only door, so every request is checked.
  • Accounts Linux UID 0 = root. /etc/passwd lists accounts, /etc/shadow holds hashes. Windows SIDs, Administrator, SYSTEM. Use sudo or UAC.
  • Modes r = 4, w = 2, x = 1 for owner, group, other. 600, 644, 755, never 777. setuid 4000, setgid 2000, sticky 1000.
  • Rules First matching class decides (owner, else group, else other). Root skips r and w checks. new mode = default AND NOT umask.
  • Windows ACLs Order: explicit deny, explicit allow, inherited deny, inherited allow, else implicit deny.
  • Logs 4624 logon, 4625 failed, 4672 admin rights, 4688 new process, 4720 user created, 4740 lockout, 1102 log cleared.
  • One octal digitdigit = 4r + 2w + 1x
  • umasknew mode = default AND (NOT umask)
  • Trap Being in the docker group on Linux is close to being root, because a user who can start containers can mount the whole disk into one. Treat such groups like admin rights.
  • Exam Because only the first matching class counts, mode 604 lets "other" read a file but blocks its own group. Owner and group are not "at least other". This trips up many students.
  • Exam An explicit allow on a file beats an inherited deny from its parent folder, because explicit ACEs come first. "Deny always wins" is only true when the deny is at the same level or closer.
  • Exam Event 1102 (the security log was cleared) almost never happens in normal work. When it shows up, treat it as a sign that someone is hiding their tracks.

2.2Networks for security: layers, addresses, subnets, TCP and DNS

  • Layers TCP/IP: link (MAC), internet (IP), transport (ports, TCP/UDP), application. OSI has 7. Encapsulation adds a header per layer.
  • Addresses IPv4 32 bits, IPv6 128, MAC 48, port 16. Private 10/8, 172.16/12, 192.168/16. Loopback 127/8.
  • Subnets network = IP AND mask, broadcast = host bits all 1, hosts = 232−n − 2.
  • TCP and UDP SYN, SYN-ACK, ACK. ack = next expected byte. UDP has no handshake, so it is easy to spoof and amplify.
  • Ports 22 SSH, 23 Telnet, 25 SMTP, 53 DNS, 80 HTTP, 443 HTTPS, 445 SMB, 3389 RDP. 0 to 1023 well known.
  • Trusting helpers ARP, DNS and DHCP believe the first answer. Defend with dynamic ARP inspection, DNSSEC, DHCP snooping and TLS.
  • Hosts in a subnethosts = 232 − n − 2
  • Network and broadcastnetwork = IP AND mask    broadcast = network OR (NOT mask)
  • Acknowledgement numberack = seq of the received segment + its data length (+ 1 for a SYN or FIN)
  • Exam 172.32.0.1 is public, not private. The private block is 172.16.0.0/12, which ends at 172.31.255.255. This is a favourite trick question.
  • Exam Port ranges: 0 to 1023 well known (need admin rights to listen on Linux), 1024 to 49151 registered, 49152 to 65535 dynamic or private (used for the client side of connections).
  • Trap A checksum is not security. It detects random damage, but an attacker who changes a packet simply recomputes it. Protection against tampering needs a keyed MAC or a signature, which the Cryptography section teaches.
  • Exam 401 means "who are you? log in". 403 means "I know who you are, and you may not". Many apps mix them up, and testers check both.

2.3Python for security: bytes, hashes, logs, packets and safe code

  • Text and bytes str is text, bytes is 0 to 255. encode() and decode() with UTF-8 (1 to 4 bytes per character). Hex = 2 digits per byte.
  • Base64 L = 4 × ceil(n / 3), = padding. An encoding, not encryption. PowerShell -EncodedCommand is base64 of UTF-16 LE.
  • Hashes hashlib.sha256(data).hexdigest(), 64 hex digits. Chunks with update(). MD5 and SHA-1 broken. compare_digest for secrets.
  • Regex Raw strings, groups, (?P<name>...), (?:...)? optional. Test every line variant. Avoid (a+)+ (ReDoS).
  • struct "!" network byte order. B 1, H 2, I 4, Q 8 bytes. Checksums catch accidents only.
  • Safe code secrets not random. Path check with base + "/". subprocess with a list, no shell. No pickle, yaml.load or eval on untrusted data.
  • Hex lengthhex digits = 2 × bytes
  • Base64 lengthL = 4 × ceil(n / 3)
  • Expected bits that flipE = n × 1/2 = 256 × 1/2 = 128
  • ReDoS cost modelsteps ≈ 2n
  • Header sizesize = sum of field sizes
  • Internet checksumchecksum = NOT( sum of 16 bit words, carries folded back in )
  • Trap Base64 is an encoding, not encryption. Anyone can decode it. Seeing a password "protected" by base64 in a config file is a finding to report.
  • Exam Never compare a secret token or MAC with ==. Python stops comparing at the first different character, so the time taken leaks how many leading characters were right. An attacker can measure that and guess one character at a time.
  • Exam A checksum catches accidents, not attackers. Anyone who changes a packet can compute a new checksum. Protection against deliberate changes needs a MAC or a signature, covered in Cryptography.
  • Exam The check full.startswith(base) without the trailing slash is a classic bug: /srv/files2/secret starts with /srv/files. The program above shows it.
  • Trap A service bound to 127.0.0.1 can only be reached from the same computer. One bound to 0.0.0.0 can be reached from any network the computer is on. Many database leaks came from a single 0.0.0.0.

Step 1Cryptography · Classical and symmetric cryptography

1.1Classical ciphers: Caesar, substitution, Vigenère and the one time pad

  • Words Plaintext, ciphertext, key, key space, brute force. Kerckhoffs: only the key is secret.
  • Caesar C = (P + k) mod 26, P = (C − k) mod 26, A = 0. 26 keys. ROT13 is its own inverse.
  • Frequency analysis Substitution keeps letter counts. χ2 = Σ (O − E)2 / E. E 12.7%, T 9.1%, A 8.2%.
  • Vigenère Ci = (Pi + Ki mod m) mod 26. IC = Σ n(n − 1) / N(N − 1): English 0.066, random 0.038.
  • One time pad c = m ⊕ k, random key as long as the message, once. P(M | C) = P(M). |K| ≥ |M|. Reuse gives m1 ⊕ m2.
  • Unicity distance U ≈ H(K) / D, D ≈ 3.2 bits per letter. 26! ≈ 288.4, so about 28 letters.
  • EncryptC = (P + k) mod 26
  • DecryptP = (C − k) mod 26
  • Chi-squared scoreχ2 = Σi (Oi − Ei)2 / Ei
  • VigenèreCi = (Pi + Ki mod m) mod 26
  • Index of coincidenceIC = Σi ni(ni − 1) / ( N(N − 1) )
  • Perfect secrecy (Shannon)P(M = m | C = c) = P(M = m)
  • Shannon’s key size bound|K| ≥ |M|
  • Key entropyH(K) = log2 |K|
  • Unicity distanceU ≈ H(K) / D
  • Trap Never invent your own cipher for real use. History is full of "unbreakable" home made ciphers broken in days. Use public, studied algorithms such as AES, which this section covers next.
  • Exam Exam favourite: the number of Caesar keys is 26 if you count shift 0, and 25 useful ones. On average a brute force finds the key after trying about half of them.
  • Exam The program prints an average IC of about 0.063 at key length 6 and about 0.04 for the wrong lengths. Multiples of the real length, such as 12, would also score high, so pick the smallest length that scores high.

1.2Symmetric encryption: AES, GF(2⁸) and modes of operation

  • AES 128 bit block. Keys 128, 192, 256 bits with 10, 12, 14 rounds. SubBytes, ShiftRows, MixColumns, AddRoundKey. Last round no MixColumns.
  • GF(28) Add = XOR. xtime: shift left, XOR 0x11B on overflow. {57}+{83} = {d4}, {57}·{83} = {c1}. Inverse = a254.
  • Modes ECB leaks patterns. CBC: Ci = E(Pi ⊕ Ci−1), random IV. CTR: Pi ⊕ E(N ‖ i), unique nonce.
  • Padding PKCS 7: N bytes of value N, N = 16 − L mod 16, never 0. Padding oracles decrypt CBC.
  • AEAD AES-GCM or ChaCha20-Poly1305. 96 bit nonce, 16 byte tag. Never reuse a nonce. TLS 1.3 allows only AEAD.
  • Sizes Brute force 2n−1. Grover 2n/2. Block collisions after 2b/2 blocks (Sweet32 on 64 bit blocks).
  • Additiona + b = a ⊕ b
  • Multiply by 2 (xtime)xtime(a) = (a « 1) ⊕ (0x11B if bit 7 of a was 1)
  • MixColumns[b0, b1, b2, b3] = [[2,3,1,1],[1,2,3,1],[1,1,2,3],[3,1,1,2]] · [a0, a1, a2, a3]
  • Padding lengthN = 16 − (L mod 16)
  • Brute forceaverage tries = 2n / 2 = 2n−1
  • Grover’s quantum searchabout 2n/2 steps
  • Exam Shannon named the two goals in 1949: confusion hides how the key relates to the ciphertext, diffusion spreads each plaintext bit over the whole ciphertext. Every modern block cipher is built around them.
  • Trap The program is for learning only. Real code must use a tested library, because simple implementations leak the key through timing and cache use (table lookups take different times for different bytes). Modern CPUs offer AES instructions (AES-NI) that run in constant time.
  • Exam Order matters if you build it yourself: encrypt, then compute a MAC over the ciphertext (encrypt then MAC). MAC then encrypt led to the padding oracle attacks on TLS. Better still, use an AEAD from a library and do not build it yourself.

1.3Hash functions, MACs and password storage

  • Properties Preimage 2n, second preimage 2n, collision 2n/2. MD5 and SHA-1 broken for collisions.
  • Birthday P ≈ 1 − e−n2/2N. 50% at 1.18 √N. 23 people. SHA-256 = 128 bit collision security.
  • Merkle-Damgård Hi = f(Hi−1, Mi). Pad 0x80, zeros, 64 bit length. Length extension breaks H(key ‖ m). SHA-3 sponge is safe.
  • HMAC H((K0 ⊕ opad) ‖ H((K0 ⊕ ipad) ‖ m)), ipad 0x36, opad 0x5c, 64 byte block. compare_digest.
  • Passwords Salt per user, Argon2id (19 MiB, t = 2), scrypt N = 217, bcrypt 10+, PBKDF2 600,000. Never fast hashes.
  • Merkle trees Root commits to all items. Proof = log2 n sibling hashes. Git, Bitcoin, Certificate Transparency.
  • ExactP(collision) = 1 − ∏i=1n−1 (1 − i/N)
  • ApproximationP(collision) ≈ 1 − e−n2/2N ≈ n2/2N when small
  • ChainH0 = IV, Hi = f(Hi−1, Mi), hash = Ht
  • SHA-256 paddingm ‖ 1 ‖ 0k ‖ len64, with k the smallest number making the total a multiple of 512 bits
  • HMACHMAC(K, m) = H( (K0 ⊕ opad) ‖ H( (K0 ⊕ ipad) ‖ m ) )
  • Attack timetime = (number of candidates) / (guesses per second)
  • Effect of slownessguesses per second ÷ iterations
  • Proof sizehashes in a proof = log2 n
  • Exam Collision resistance is the first property to fall, because it only costs 2n/2. MD5 and SHA-1 lost collision resistance, but nobody has found a practical preimage attack on either. They are still banned for security use, because signatures need collision resistance.
  • Trap The program uses plain H(item) and H(left ‖ right) to stay short. Real systems add the 0x00 and 0x01 prefixes. Bitcoin’s simpler rule of copying the last hash when a level is odd allowed a real bug in 2012 (CVE-2012-2459), where two different transaction lists had the same root.

Step 2Cryptography · Public key cryptography and its maths

2.1Number theory for cryptography: modular arithmetic to primes

  • Modular a ≡ b (mod n) ⇔ n | a − b. Reduce after each step. Python % is 0 to n − 1.
  • Euclid gcd(a, b) = gcd(b, a mod b). Extended: s·a + t·b = gcd. Lamé: steps ≤ 5 × digits.
  • Inverse Exists ⇔ gcd(a, n) = 1. Extended Euclid or pow(a, −1, n). 17−1 mod 3120 = 2753.
  • Powers Square and multiply, about 2 log2 e. 65537 = 216 + 1 needs 17. Constant time against timing attacks.
  • Fermat and Euler ap−1 ≡ 1 (mod p). aφ(n) ≡ 1 (mod n). φ(pq) = (p − 1)(q − 1).
  • CRT and primes x = Σ aiMiyi mod M. π(x) ∼ x / ln x. Miller-Rabin ≤ 4−k. 561 is Carmichael.
  • Congruencea ≡ b (mod n) ⇔ n | (a − b)
  • Rules(a + b) mod n = ((a mod n) + (b mod n)) mod n, (a · b) mod n = ((a mod n)(b mod n)) mod n
  • Euclidgcd(a, b) = gcd(b, a mod b), gcd(a, 0) = a
  • Bézout’s identitys·a + t·b = gcd(a, b) for some whole numbers s, t
  • Inversea · a−1 ≡ 1 (mod n), exists ⇔ gcd(a, n) = 1
  • Costmultiplications ≤ 2 ⌊log2 e⌋
  • Fermatap−1 ≡ 1 (mod p)
  • Euler’s phiφ(pk) = pk − pk−1, φ(m n) = φ(m) φ(n) when gcd(m, n) = 1
  • Euler’s theoremaφ(n) ≡ 1 (mod n)
  • CRT solutionx = Σi ai Mi yi mod M, with Mi = M / mi and Mi yi ≡ 1 (mod mi)
  • Prime number theoremπ(x) ∼ x / ln x
  • Expected triesabout ln(x) / 2 odd candidates
  • Trial divisionabout √n divisions
  • Number field sieveLn[1/3, 1.923] = exp( 1.923 (ln n)1/3 (ln ln n)2/3 )
  • Exam Negative numbers trip up many programmers: in Python, −3 % 7 is 4, but in C, Java and JavaScript, −3 % 7 is −3. Crypto code written in those languages must add n back.
  • Exam Exam favourite: "Find d with 17d ≡ 1 (mod 3120)". Run the extended algorithm on 3120 and 17. The answer, 2753, comes from the textbook RSA example with p = 61 and q = 53.
  • Trap A naive implementation leaks the key: a 1 bit costs an extra multiplication, which shows up in timing and power traces. Libraries use constant time techniques such as the Montgomery ladder, which does the same work for every bit.
  • Trap The 2012 study "Ron was wrong, Whit is right" (Lenstra and others) and "Mining your Ps and Qs" (Heninger and others) found RSA keys that shared a prime with another key. A simple gcd of the two public moduli then factors both instantly.

2.2RSA: keys, proofs, signatures and attacks

  • Keys n = pq, φ = (p − 1)(q − 1), e = 65537 with gcd(e, φ) = 1, d = e−1 mod φ (or λ).
  • Use c = me mod n, m = cd mod n. Sign s = pad(H(M))d, verify se. 61, 53, 17, 2753: 65 to 2790.
  • Proof Fermat mod p and mod q, CRT joins. Works for every m, even gcd(m, n) ≠ 1.
  • CRT dp, dq, qinv, m = mq + q · (qinv(mp − mq) mod p). 4 times faster. Fault: gcd(s′e − m, n) = p.
  • Attacks Textbook: deterministic, malleable. Small e cube root, Håstad, shared prime gcd, Fermat for close p, q, Wiener for d < n1/4/3.
  • Padding and size OAEP to encrypt, PSS to sign. v1.5 encryption: Bleichenbacher, ROBOT. 2048 = 112 bits, 3072 = 128. Quantum: gone after 2035.
  • Key generationn = p q, φ(n) = (p − 1)(q − 1), gcd(e, φ(n)) = 1, d = e−1 mod φ(n)
  • Encryptionc = me mod n, with 0 ≤ m < n
  • Decryptionm = cd mod n
  • Correctness(me)d ≡ m (mod n) for every m from 0 to n − 1
  • Sign and verifys = H(M)d mod n, accept if se mod n = H(M)
  • CRT exponentsdp = d mod (p − 1), dq = d mod (q − 1), qinv = q−1 mod p
  • Garner’s recombinationmp = cdp mod p, mq = cdq mod q, h = qinv(mp − mq) mod p, m = mq + h q
  • Bellcore attackfaulty s′ with s′ ≡ s (mod p) but not mod q gives p = gcd(s′e − m, n)
  • Malleabilityc · te ≡ (m t)e (mod n)
  • Small e, short mif me < n then c = me exactly, so m = c1/e
  • Fermat factoringn = a2 − b2 = (a − b)(a + b), try a = ⌈√n⌉, ⌈√n⌉ + 1, ...
  • Why it works|e / n − k / d| < 1 / (2 d2) when d < n1/4 / 3
  • Recover p and qs = n − φ + 1, p, q = (s ± √(s2 − 4n)) / 2
  • OAEP message limitmax length = k − 2 h − 2 bytes
  • Cost of RSA operationsprivate key: about k3, public key with e = 65537: about k2
  • Exam Exam favourite: "Prove that RSA decryption is correct even when gcd(m, n) ≠ 1." Answers that only quote Euler’s theorem lose marks. Use Fermat modulo p and modulo q, then join with CRT as above.
  • Trap Sign then encrypt with the same RSA key pair is a classic mistake. Use separate key pairs for signing and for encryption, as the standards require.

2.3Diffie-Hellman, ElGamal and the discrete logarithm

  • Exchange A = ga, B = gb, K = Ba = Ab = gab. p = 23, g = 5, a = 6, b = 15: 8, 19, key 2.
  • Groups ord(g) | p − 1. Generator: g(p−1)/r ≠ 1 for each prime r | p − 1. Safe prime p = 2q + 1.
  • DLP attacks BSGS 2√n with √n memory, Pollard rho √n, Pohlig-Hellman uses small factors, NFS sub exponential mod p.
  • Validate and authenticate Check 1 < A < p − 1 and Aq = 1. Sign the handshake or compare fingerprints against MITM.
  • ElGamal (gk, m hk), m = c2/c1x. Randomized, multiplicatively homomorphic, never reuse k.
  • Forward secrecy Ephemeral DH, delete secrets, HKDF for keys. TLS 1.3 removed RSA key transport. Logjam: avoid 512 and shared 1024 bit groups.
  • Order of an elementord(g) = smallest k > 0 with gk ≡ 1 (mod p)
  • Lagrange’s theoremord(g) divides the group size, here p − 1
  • Public valuesA = ga mod p, B = gb mod p
  • Shared secretK = Ba = Ab = gab mod p
  • Generic lower bound (Shoup, 1997)any generic algorithm needs about √q group operations for a group of prime order q
  • Pohlig-Hellman costabout Σ ei(log n + √ri) operations
  • Public value check1 < A < p − 1 and Aq ≡ 1 (mod p)
  • ElGamal(c1, c2) = (gk, m hk), m = c2 (c1x)−1
  • Reused kc2 / m = hk, then m′ = c2′ / hk
  • HKDF (RFC 5869)PRK = HMAC(salt, IKM), OKM = T(1) ‖ T(2) ‖ ..., T(i) = HMAC(PRK, T(i−1) ‖ info ‖ i)
  • Exam Exam favourite: "Is g a generator modulo p?" Factor p − 1, then test g(p−1)/r for each prime factor r. Do not list all the powers.
  • Trap Logjam (2015): about 8 percent of the top million HTTPS sites still accepted 512 bit export Diffie-Hellman, and many servers shared the same few 1024 bit primes. Use groups of at least 2048 bits, such as the RFC 7919 ffdhe groups, or elliptic curves.

2.4Elliptic curve cryptography: ECDH, X25519, ECDSA and Ed25519

  • Curve y2 = x3 + ax + b mod p plus O, 4a3 + 27b2 ≠ 0. Hasse |#E − (p + 1)| ≤ 2√p.
  • Add λ = (y2 − y1)/(x2 − x1) or (3x2 + a)/2y. x3 = λ2 − x1 − x2, y3 = λ(x1 − x3) − y1.
  • ECDLP and ECDH Q = dG. Rho ≈ √n, 256 bit = 128 bit security. S = abG. X25519: ladder, clamping, RFC 7748.
  • ECDSA r = (kG)x, s = k−1(h + rd). Reused k: k = Δh/Δs, d = (sk − h)/r. RFC 6979.
  • Ed25519 Schnorr s = k + e d, k = H(prefix, m). 32 byte keys, 64 byte signatures. RFC 8032.
  • Attacks Invalid curve and small subgroup points, biased nonces, timing, MOV and anomalous curves, Dual EC DRBG, CurveBall.

1.1Machine learning for security

  • The ML loop Collect, label (or learn normal), features, train, validate on later data, deploy with a threshold, analyst feedback, watch drift, retrain. Denning 1987 anomaly model, Graham 2002 Bayes spam filter. Most work is data, labels and evaluation (Sommer and Paxson 2010).
  • Naive Bayes score = log(P(phish) / P(safe)) + Σ log(P(w | phish) / P(w | safe)). Laplace P(w | c) = (count + 1) / (Nc + |V|). P = 1 / (1 + e−score). Logs avoid underflow.
  • Logistic regression p = σ(w · x + b), log loss, gradient (p − y) xi. Features: length, dots, @ or hyphen, HTTPS, digits, entropy. Beware shortcut learning, test on newer data.
  • Anomalies z = (x − μ) / σ is fooled by outliers. Robust M = 0.6745 (x − median) / MAD, flag above 3.5. Isolation forest: s = 2−E[h]/c(n), near 1 anomaly, 0.5 average. Unusual is not proof of malicious.
  • Metrics Precision TP/(TP+FP), recall TP/(TP+FN), F1, FPR FP/(FP+TN). ROC AUC = chance an attack outranks a normal event. Base rate: precision = r TPR / (r TPR + (1 − r) FPR). KDD 99 flaws, use time splits.
  • Malware and drift Static (imports, entropy above about 7.2 suggests packing) and dynamic (sandbox API calls) features. Jaccard |A ∩ B| / |A ∪ B|. EMBER 2018. PSI = Σ (a − e) ln(a/e): below 0.1 stable, above 0.25 act. SHAP explains alerts.
  • Bayes rule for a class given the wordsP(phish | words) ∝ P(phish) × Π P(wi | phish)
  • Log odds scorescore = log(P(phish) / P(safe)) + Σ log(P(wi | phish) / P(wi | safe))
  • Laplace smoothingP(w | c) = (count(w, c) + 1) / (Nc + |V|)
  • Logistic regressionp = σ(z) = 1 / (1 + e−z), z = w · x + b
  • Log loss and its gradientL = −[y log p + (1 − y) log(1 − p)], ∂L/∂wi = (p − y) xi
  • z scorez = (x − μ) / σ
  • Modified (robust) z scoreM = 0.6745 (x − median) / MAD, flag when |M| > 3.5
  • Precision and recallprecision = TP / (TP + FP), recall = TP / (TP + FN)
  • F1 scoreF1 = 2 × precision × recall / (precision + recall)
  • False positive rateFPR = FP / (FP + TN)
  • Precision from the base rate (Bayes)precision = r · TPR / (r · TPR + (1 − r) · FPR)
  • Jaccard similarityJ(A, B) = |A ∩ B| / |A ∪ B|

  • Trap Shortcut learning is one of the most common failures of security ML. A model can score 99% on a test set drawn from the same old data and still fail on next month’s attacks. Always test on data collected after the training data.

2.1Federated learning in full

  • Idea and terms Send the model to the data. Rounds: select clients (fraction C), send wt, local training (E epochs, batch B, rate η), return weights, average. McMahan et al. 2016 and 2017, Gboard 2017, FeTS 71 sites (2022), Kairouz et al. 2021.
  • FedAvg maths F(w) = Σ (nk/n) Fk(w). wt+1 = Σ (nk/n) wkt+1. uk = E nk/B. FedSGD = gradient descent because Σ (nk/n)∇Fk = ∇F.
  • Communication Bytes per round 2mPb (100 clients, 1.4M float32 params: 1.12 GB). More local steps, fewer rounds (10 to 100 times). Top k, quantisation Δ = range/(2bits − 1), error feedback. Clients join when idle, charging, on Wi-Fi.
  • Non IID and drift Label, feature, quantity skew. Drift: average of local optima is not the global optimum (quadratic: w* = Σa c/Σa). FedProx + (μ/2)‖w − wt‖2. SCAFFOLD g − ck + c. Personalisation.
  • Types Cross device (millions, few per round, drop outs) and cross silo (few organisations, all rounds). Horizontal (same columns), vertical (same people: PSI, split model, encrypted errors, FATE), federated transfer learning.
  • Secure aggregation and layers Bonawitz 2017: yi = xi + Σj>i mij − Σj<i mji mod M, masks from DH, cancel in the sum, Shamir shares for drop outs, n(n − 1)/2 pairs. Layers: local data, SecAgg, DP-FedAvg, TEE, robust aggregation.

  • Data sent per roundbytes = 2 × m × P × b
  • Top k with positionsbytes ≈ k × (index bytes + value bytes)
  • Best global point for quadratic clientsw* = Σ pk ak ck / Σ pk ak
  • FedProx local objectivehk(w) = Fk(w) + (μ / 2) ‖w − wt‖2
  • Masked update of client iyi = xi + Σj > i mij − Σj < i mji (mod M)
  • The masks cancelΣi yi = Σi xi (mod M)
  • Number of pairwise maskspairs = n(n − 1) / 2
  • Expected participants after drop outsexpected = m × (1 − drop rate)
  • Trap A salted hash, as in the program, is only a sketch of matching customers. Customer IDs and phone numbers are easy to guess, so an attacker can hash every possible value. Real systems use a private set intersection protocol built on Diffie-Hellman style cryptography or oblivious transfer.

2.3Differential privacy

  • Why DP Anonymisation fails: Sweeney 1997 (ZIP, birth date, sex, 87%), AOL 2006, Netflix 2008. Reconstruction (Dinur and Nissim 2003, Census 2010 tests). DP: Dwork, McSherry, Nissim, Smith 2006, Gödel Prize 2017, US Census 2020.

  • Sensitivity and clipping Count 1, clipped mean (U − L)/n, clipped gradient C. Clipping bounds each person’s influence so finite noise can hide it.
  • DP in ML DP-SGD (Abadi 2016): per example gradients, clip to C, add N(0, σ2C2), sampling q = B/N, accountant gives (ε, δ). DP-FedAvg (2018) user level. Local DP (RAPPOR, Apple) versus central DP (Census). Adv ≤ eε − 1.

4.4API security: BOLA, rate limits, mass assignment and the OWASP API Top 10

  • APIs Web endpoints that apps call, usually JSON over HTTPS. Client side checks can be skipped. OWASP API Security Top 10 (2023): API1 BOLA to API10 unsafe consumption.
  • BOLA and BFLA Check object owner and caller role on every request. UUIDs are not access control. Return 404 for not yours. Two user tests. USPS 2018, Peloton 2021, Optus 2022.
  • Authentication Keys on servers only, scoped and rotated. Tokens short lived, verify signature, issuer, audience, expiry. Rate limit login and reset per account. Facebook 2018 token theft.
  • Rate limits Token bucket: allowed ≤ capacity + rate × T. 429 Too Many Requests (RFC 6585) with Retry-After. Per account, per key, per IP. Page, payload and GraphQL cost limits.
  • API3 properties Mass assignment: allow list of writable fields. Excessive data exposure: response schema. Rails 2012, Twitter 2022 (5.4 million).
  • Outbound and SSRF Webhooks fetch user URLs. Block private, loopback, link local (169.254.169.254, also 2852039166). Check resolved IPs, no blind redirects, IMDSv2. Capital One 2019 (about 106 million).
  • Operations Inventory from logs and OpenAPI, retire zombie and shadow APIs, fixed CORS origins, generic errors, alerts per token. T-Mobile 2023 (about 37 million). Test only what you own.
