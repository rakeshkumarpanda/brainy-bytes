Lesson 1 of 10

Why security people learn Python

Python was created by Guido van Rossum and first released in 1991. It was meant to be easy to read, and that is exactly why the security world adopted it. Security work is full of small, one off jobs: read a log, decode a strange string, check a thousand files, parse a packet. Writing those in C takes hours. In Python they take minutes. Over the years, many famous security tools were written in Python: Scapy for building and reading network packets, Volatility for studying memory dumps after an attack, sqlmap for testing databases, Impacket for Windows network protocols, and fail2ban, which blocks addresses that keep failing to log in. Defenders use Python to automate alerts and investigations, and researchers use it to analyse malware. You do not need to be a professional programmer. You need variables, loops, lists, dictionaries, functions, and the handful of security modules this chapter shows.

Source: Python 3.14 documentation for bytes, base64, hashlib, hmac, re, struct, secrets, subprocess and pickle, RFC 3629, RFC 4648, RFC 1071, RFC 1035 and FIPS 180-4.

What it is
Python for security means using a few standard modules to handle bytes, hashes, text patterns, binary formats, randomness and network sockets, and writing code that cannot be tricked by bad input.
Why we need it
Security jobs are full of repeated small tasks. A 15 line script that reads 10,000 log lines beats reading them by eye, and it does the same thing every time.
How it works
Learn the core language first. Then learn the security modules: bytes and base64, hashlib and hmac, re, struct, secrets, socket, and the safe ways to use subprocess and files.

Text and bytes: UTF-8, hex and base64

Inside a computer there are no letters, only numbers. A byte is eight bits, a number from 0 to 255. Long ago, the ASCII table from 1963 gave each English letter a number below 128: capital A is 65, small a is 97. That was fine for English but useless for Hindi, Chinese or Arabic. Unicode fixed that by giving every character in every language its own number, called a code point. Then in 1992, Ken Thompson and Rob Pike designed UTF-8, a clever way to store those code points as bytes: plain English letters still take one byte, exactly like ASCII, and other characters take two, three or four bytes. Today almost every web page uses UTF-8. Security people meet bytes everywhere: in network packets, in hashes, in keys, in malware. Two ways of writing bytes as text are everywhere. Hex writes each byte as two digits from 0 to f. Base64 packs every three bytes into four printable letters, so binary data can travel inside emails, web addresses and JSON. Attackers often hide commands in base64, so reading it quickly is a daily skill.
What it is
A Python str holds text (code points). A bytes object holds raw numbers from 0 to 255. encode() turns text into bytes and decode() turns bytes back into text. Hex and base64 are two ways to write bytes using only printable characters.
Why we need it
Hashes, keys, packets and files are bytes. If you mix up text and bytes you get wrong hashes, broken parsers and security checks that can be bypassed with strange characters.
How it works
UTF-8 uses 1 byte for code points below 128, 2 bytes up to 2,047, 3 bytes up to 65,535 and 4 bytes above that. Hex uses 2 digits per byte. Base64 cuts each group of 3 bytes (24 bits) into four 6 bit numbers and maps each to one of 64 letters, adding = padding at the end when needed.

Common mistake
Base64 is an encoding, not encryption. Anyone can decode it. Seeing a password "protected" by base64 in a config file is a finding to report.
Real world scenario: the base64 command in a phishing email

A help desk analyst opens a suspicious email attachment in a safe sandbox and finds a script that runs PowerShell with -EncodedCommand followed by a long base64 string. Instead of running it, the analyst decodes it with Python: base64.b64decode(s).decode("utf-16-le"), because PowerShell encodes commands as UTF-16 little endian. The decoded text shows a command that downloads a file from a strange address. The analyst blocks that address for the whole company in minutes. Knowing which encoding to try was the whole job.

Hashes in Python: hashlib and hmac

A hash function takes data of any size and returns a short fingerprint of fixed size. The same input always gives the same fingerprint, but you cannot run the function backwards to get the input, and it is practically impossible to find two inputs with the same fingerprint. Ron Rivest designed MD5 in 1991, and it was used everywhere until 2004, when Wang Xiaoyun and her team showed how to make two different files with the same MD5 hash. SHA-1 fell the same way in 2017, when Google and the CWI institute in Amsterdam published two different PDF files with the same SHA-1 hash. Today the standard choice is SHA-256, from the SHA-2 family that the NSA designed and NIST published in 2001. In daily security work you use hashes to check that downloads were not changed, to identify known malware by its fingerprint, and as one piece of how passwords are stored. The Cryptography section explains how SHA-256 works inside. Here you learn to use it correctly from Python.
What it is
hashlib computes hashes such as SHA-256. hmac adds a secret key to a hash, and hmac.compare_digest compares two secret values safely.
Why we need it
A hash proves data was not changed: if one bit changes, the hash changes completely. Malware databases, file integrity monitors and software downloads all rely on this.
How it works
Call hashlib.sha256(data).hexdigest() for small data. For big files, read pieces and call update() on each, or use hashlib.file_digest(f, "sha256") (Python 3.11 and newer). Compare secret values with hmac.compare_digest, which takes the same time whether the first byte or the last byte differs.

Expected bits that flipExam favourite
E = n × 1/2 = 256 × 1/2 = 128
Each output bit of a good hash flips with probability 1/2 when the input changes.
Spread
σ = √(n × p × (1 − p)) = √(256 × 1/4) = 8
So nearly every change flips between 104 and 152 bits (three spreads either side).
Finding a collision
about 2n/2 tries
The birthday bound. For SHA-256 that is 2128 tries, far beyond any computer. For MD5 better attacks need only seconds.

Regular expressions for logs

A regular expression is a small pattern language for finding text. The mathematician Stephen Kleene described regular languages in the 1950s, and Ken Thompson put them into the Unix tools ed and grep around 1973. The name grep even comes from the ed command g slash re slash p: globally search for a regular expression and print. Security teams live in logs, and logs are text, so regular expressions are one of the most used skills in security. A pattern such as Failed password for something from some address pulls out the user name and the address from thousands of lines in a second. The parts in round brackets are called groups and capture the pieces you want. But patterns can go wrong in two ways. They can miss lines you wanted, and an attacker who knows your pattern can write lines that slip past it. And some patterns are so slow on carefully made input that they freeze a server. That second problem is called ReDoS, and it took down Stack Overflow in 2016 and much of Cloudflare for about half an hour in 2019.
What it is
A regular expression describes a set of strings. re.search(pattern, text) finds the first match. Round brackets make groups that capture text, and (?P<name>...) gives a group a name.
Why we need it
Logs from servers, firewalls and apps are the main evidence of attacks. Patterns turn thousands of free text lines into counts and alerts.
How it works
Build the pattern from a real line, test it on lines that should match and lines that should not, then count matches per key in a dictionary.

Binary data with struct: headers and checksums

Network packets and many file formats are not text. They are fixed layouts of numbers: two bytes for this field, four bytes for that one. The struct module, part of Python since its early days, reads and writes such layouts. You describe the layout with a short format string, such as exclamation mark H H I, which means network byte order, then two 16 bit numbers, then one 32 bit number. Network byte order means big endian: the most significant byte comes first. Intel and AMD processors store numbers the other way round, little endian, which is why every network program has to convert. Tools like Scapy and Wireshark do this for every packet they show you. Writing a small parser yourself teaches you what those tools see. It also teaches you why parsers are a favourite target of attackers: a length field that says 60,000 when only 20 bytes arrived has caused countless security bugs in C programs. Python checks the bounds for you, which is one reason it is a safe choice for quick parsers.
What it is
struct.pack(format, values) turns numbers into bytes, and struct.unpack(format, data) turns bytes back into numbers. "!" means network byte order (big endian). B is 1 byte, H is 2 bytes, I is 4 bytes and Q is 8 bytes.
Why we need it
Every network protocol and many file formats are fixed layouts of numbers. To read a packet capture, check a header or study a malware file, you need to read bytes as numbers.
How it works
Write down the layout from the standard (for DNS that is RFC 1035: six 16 bit numbers), build the format string, unpack, and check each value. Check lengths before you trust them.

Header sizeExam favourite
size = sum of field sizes
"!HHHHHH" = 6 × 2 = 12 bytes. struct.calcsize gives it for you.
Internet checksumExam favourite

Adding the header with its checksum in place gives 0xFFFF, so the check function returns 0.
In the exam
A checksum catches accidents, not attackers. Anyone who changes a packet can compute a new checksum. Protection against deliberate changes needs a MAC or a signature, covered in Cryptography.

Writing safe Python: randomness, paths, commands and untrusted data

A security script that is itself insecure is worse than no script. Python makes some dangerous things very easy, so here are the habits that matter most. First, randomness. The random module uses an algorithm called the Mersenne Twister, from 1998. It is excellent for games and simulations, but after seeing 624 of its outputs anyone can predict every future value. That is why Python added the secrets module in version 3.6, through PEP 506, for passwords, tokens and keys. Second, file paths. If a user can type a file name such as dot dot slash dot dot slash etc slash passwd, a careless program may read a file far outside the folder it meant to use. This is called path traversal. Python’s own tarfile module had such a bug, CVE 2007 4559, that went unfixed for fifteen years, and researchers in 2022 estimated that hundreds of thousands of projects used tarfile unsafely. Third, commands. Building a shell command by joining strings lets a user add their own command. Fourth, never load pickle, unsafe YAML or eval on data from outside, because each one can run code.
What it is
Safe Python means using secrets for anything secret, checking that file paths stay inside the folder you expect, calling subprocess with a list and no shell, and never running pickle.load, yaml.load or eval on untrusted data.
Why we need it
Attackers do not attack your idea. They attack your input handling. These four mistakes cause a large share of real vulnerabilities in Python code.
How it works
For paths: join, normalise, then check the result still starts with the base folder plus a slash. For commands: pass a list such as ["ls", "-l", name] so the name is one argument. For data: use json or yaml.safe_load.

Sockets: checking your own services

A socket is the programming door to the network. The socket interface came from the University of California, Berkeley, in the early 1980s, in the BSD version of Unix, and almost every operating system still uses the same design. A program that wants to talk over TCP creates a socket, connects it to an address and a port, and then sends and receives bytes. If nothing is listening on that port, the other computer answers the connection with a reset and the connect fails. That simple fact is the basis of port scanning, which you met in the networks chapter. Defenders scan their own servers to find services that should not be running, such as an old database left open to the world. Attackers scan to find targets. The law is clear on this in most countries: scanning computers you do not own or do not have written permission to test can be a crime. So the program in this lesson only checks ports on your own computer, at address 127.0.0.1, which always means this machine.
What it is
A socket is an endpoint for sending and receiving data. connect_ex((host, port)) tries a TCP handshake and returns 0 when something is listening.
Why we need it
Knowing which ports are open on your own machines is basic hygiene. Every open port is a door that needs a reason to exist.
How it works
Create a socket, set a short timeout, call connect_ex, close it. A result of 0 means open. Anything else means closed or filtered.

Python compared with other security languages

Python is not the only language in security. System administrators on Linux reach for Bash, the shell, because it joins existing tools together in one line. Windows administrators use PowerShell, which Microsoft released in 2006, and which can reach almost every part of Windows. Sadly, attackers love PowerShell for the same reason, so defenders must know it well too. Go, from Google in 2009, has become popular for security tools that must be fast and easy to ship, because a Go program compiles into one file that runs without installing anything. C and Rust are used when you need full control of memory, for example in operating systems, exploits and very fast scanners. Rust adds memory safety, which removes the class of bugs behind most serious vulnerabilities in C. A good security person can read all of these and writes most daily scripts in Python.

Lesson 9 of 10

From beginner to expert

Python in security grows with you. A beginner writes ten line scripts that decode base64 and hash a file. A college student writes parsers for logs and packets, uses the secrets module, avoids shell injection, and automates checks with small tools. A masters student builds real tools: a packet sniffer with Scapy, a memory analysis plugin for Volatility, a detection pipeline that feeds a SIEM, or a fuzzer that throws strange inputs at a parser to find crashes. At the research level, Python drives serious program analysis. The angr framework from the University of California, Santa Barbara does symbolic execution of binaries, exploring every path through a program to find inputs that reach a bug. Google’s Atheris brings coverage guided fuzzing to Python code. And Python itself is studied as an attack surface: its package ecosystem, PyPI, is a constant target of supply chain attacks with fake and hijacked packages.
One idea, four depths

Python can turn text into bytes and back, make a fingerprint of a file, find words in a log and make strong random passwords. Base64 is not a secret code.

Use encode, decode, hex and base64 fluently, hash files in chunks, compare secrets with compare_digest, write and test regular expressions with named groups, parse headers with struct, use secrets for tokens, and call subprocess with a list.

Build tools: Scapy for packets, Volatility plugins for memory, log pipelines into a SIEM, fuzzers for parsers. Understand ReDoS and linear time regex engines, timing attacks on comparisons, pickle and YAML deserialisation risks, and software supply chain controls such as pinned hashes, signed packages and pip-audit.

Program analysis in Python: symbolic execution with angr, coverage guided fuzzing with Atheris and libFuzzer, taint analysis of Python web apps, and research on PyPI supply chain attacks (typosquatting, dependency confusion, malicious install scripts) and their detection with static and dynamic analysis.

Beginner
Turn text into bytes, decode base64, hash a file and make secure tokens.
Intermediate
Parse logs with regular expressions, read packet headers with struct, and avoid path traversal and command injection.
Expert
Build packet, memory and fuzzing tools, and analyse code and packages for supply chain risks.

Chapter summary

  1. A str holds text, bytes holds numbers 0 to 255. encode() and decode() convert, using UTF-8 (1 to 4 bytes per character).
  2. Hex uses 2 digits per byte. Base64 uses 4 characters per 3 bytes: L = 4 × ceil(n / 3). Base64 is an encoding, not encryption.
  3. hashlib.sha256(data).hexdigest() gives 64 hex digits. Hash big files in chunks with update(). MD5 and SHA-1 are broken.
  4. One input change flips about 128 of 256 bits (spread 8). Compare secrets with hmac.compare_digest, never with ==.
  5. Regular expressions with groups turn logs into counts. Test patterns on every line variant, use raw strings, and avoid nested repeats that cause ReDoS.
  6. struct reads binary layouts. "!" means network byte order. B = 1, H = 2, I = 4, Q = 8 bytes. A checksum catches accidents, not attackers.
  7. Use secrets for tokens, never random. Check paths stay inside the base folder plus a slash. Call subprocess with a list. Never unpickle untrusted data.
  8. Check ports only on your own machines. connect_ex returns 0 when a port is open.
