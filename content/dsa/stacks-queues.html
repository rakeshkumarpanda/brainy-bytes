Stacks and Queues

Two of the simplest structures in computing, and two of the most used. A stack hands back the newest item first, a queue hands back the oldest. This page builds both, then uses them to match brackets, evaluate expressions, run ring buffers, find next greater elements and power undo and redo.

Part 1

🥞The stack: last in, first out

A stack is a pile. You add to the top (push), look at the top (peek) and remove from the top (pop). The last item in is the first item out, which is called LIFO.

📞 The call stack

Every function call pushes a frame with its local variables. Returning pops it. Infinite recursion keeps pushing until the stack overflows.

⚠️ Underflow

Popping an empty stack is an error: an exception in Python and Java, undefined in JavaScript. Always check that it is not empty first.

In Java, avoid the old Stack class. It is synchronized and slower. ArrayDeque is the recommended stack and queue.
Part 2

🧷Matching brackets with a stack

Code editors, compilers and HTML checkers all need to know whether brackets are properly nested. A stack does it in one pass: push every opener, and when a closer arrives, the top of the stack must be its partner.

Three things can go wrong, and the code checks all three: a closer with an empty stack, a closer whose partner is not on top, and openers left on the stack at the end. Each character is pushed and popped at most once, so it is O(n).

Whenever the most recent unfinished thing must be finished first, think stack: brackets, nested tags, undo, function calls, backtracking.
Part 3

🧮Evaluating expressions

People write infix expressions like (3 + 4) * 2 − 5, with operators between the numbers and parentheses for order. Computers prefer postfix (also called reverse Polish notation), where each operator comes after its two operands: 3 4 + 2 * 5 −. Postfix needs no parentheses and no precedence rules.

Evaluating postfix

Read the tokens left to right. Push numbers. For an operator, pop the right operand, then the left one, compute, and push the result.

Turning infix into postfix

Edsger Dijkstra's shunting yard algorithm uses a stack of operators. Numbers go straight to the output. Before pushing an operator, pop every operator on the stack with greater or equal precedence. A ( waits on the stack until its ) arrives.

Pop order matters for − and /. The first pop gives the right operand. For 8 2 − you pop 2, then 8, and compute 8 − 2 = 6, not 2 − 8.
Part 4

🚶The queue: first in, first out

A queue is a line at a ticket counter. Items join at the back (enqueue) and leave from the front (dequeue). The first item in is the first item out: FIFO.

Removing the first element of a Python list (pop(0)) or a JavaScript array (shift()) moves every other element, which is O(n). Use collections.deque in Python, ArrayDeque in Java, and a head index or a ring buffer in JavaScript.

The circular buffer

A fixed size array can hold a queue with no shifting at all. Keep the index of the front (head) and the number of items (size). The back is at (head + size) mod capacity. When an index runs off the end of the array, the remainder wraps it back to 0.

tail = (head + size) mod capacity head = (head + 1) mod capacity
Keyboard input, audio streaming and network cards all use ring buffers: a fixed block of memory that is reused forever, with O(1) enqueue and dequeue.
Part 5

🎟️Deques and priority queues

↔️ Deque

A double ended queue allows push and pop at both ends in O(1). It can act as a stack, a queue, or both at once. Sliding window problems love it.

🏥 Priority queue

Items leave in order of priority, not arrival. An emergency room treats the most urgent patient first. It is built on a binary heap: insert and remove the smallest in O(log n).

A heap is a complete binary tree stored in an array: the children of index i sit at 2i + 1 and 2i + 2, and every parent is smaller than its children. The Trees topic explains it in detail.

Part 6

📈Monotonic stacks

A monotonic stack keeps its items in increasing or decreasing order. It answers "what is the next bigger (or smaller) item to my right?" for every position in a single pass.

For the next greater element, keep indexes of values still waiting for an answer. When a bigger value arrives, it is the answer for every smaller waiting value, so pop them and fill in their result. Then push the new index.

Each index is pushed once and popped at most once, so the nested loops still add up to O(n), not O(n²).

pushes + pops ≤ n + n = 2n
The same pattern solves "days until a warmer day", stock spans, the largest rectangle in a histogram and trapping rain water.
Part 7

↩️Undo, redo and other everyday uses

Undo and redo are two stacks. Every change pushes the old state onto the undo stack. Undo moves the current state to the redo stack and pops the previous one. A brand new change clears the redo stack, because the future it remembered no longer exists.
