Part 1

🛗Skip lists: express lanes over a linked list

Searching a sorted linked list means walking it one node at a time. A skip list adds lanes on top. Every key sits in the bottom lane, and a coin flip decides whether it also joins the lane above, then the next, and so on. A search starts in the top lane at the head, moves right while the next key is smaller, and drops down one lane when it would overshoot.

with a fair coin: about n ÷ 2k keys reach lane k, so there are about log2 n lanes
William Pugh described skip lists in 1990. Redis keeps its sorted sets in a skip list, because inserting and deleting only change a few links.
Part 2

🌸Bloom filters: maybe, or definitely not

A Bloom filter answers "have I seen this word?" with a row of bits and nothing else. Adding a word sets the bits at a few hash positions. Asking about a word checks those same positions. If any bit is 0, the word was definitely never added. If all of them are 1, the word is maybe present, because other words may have set those bits.

false positive chance ≈ ( 1 − e−kn ÷ m )k   for m bits, n words and k hashes
A plain Bloom filter cannot remove a word. Clearing its bits could also clear bits that another word needs, and then that word would be reported as absent.
Part 3

🧮Count-min sketch: counting in a small table

Counting every word in a huge stream needs one counter per distinct word. A count-min sketch uses a small table instead: a few rows of counters, each row with its own hash. Every word adds 1 to one counter in every row. To estimate a count, read the word's counter in each row and take the smallest.

WordTrue countEstimate
the44
cat22
owl12
fox00
Collisions only ever add to a counter, so the estimate is never smaller than the true count. More columns make collisions rarer, and more rows make it less likely that every row collides at once.
Part 4

🧱Sparse tables: range minimum in O(1)

A sparse table answers "what is the smallest value between l and r?" for a list that never changes. Row j stores the minimum of every block of 2j values, and each row is built from two halves in the row before. A query picks the biggest power of 2 that fits the range and looks at two blocks: one starting at l and one ending at r.

j = ⌊ log2( r − l + 1 ) ⌋    min = min( t[j][l], t[j][r − 2j + 1] )
The two blocks may overlap. That is fine for minimum, maximum and gcd, because counting a value twice does not change the answer. It does not work for sums.
Part 5

🧩Square root decomposition

Prefix sums answer a range sum in O(1) but need O(n) work after a change. Square root decomposition finds a middle ground. Cut the list into blocks of about √n cells and keep the total of every block. A query adds the loose cells at both ends and the whole blocks in between. An update changes one cell and one block total.

StructureRange sumChange one value
Prefix sumsO(1)O(n)
Square root blocksO(√n)O(1)
Segment tree or Fenwick treeO(log n)O(log n)
The same block idea answers harder questions too, such as "how many values below x in this range", by keeping each block sorted.
