Part 1

🪙The greedy choice, and when it fails

A greedy algorithm builds an answer one step at a time, and at every step takes whatever looks best right now. It never goes back to change an earlier choice. That makes greedy code short and fast. The hard part is knowing whether the best choice right now leads to the best answer overall.

A greedy algorithm is correct when the problem has the greedy choice property, so some best answer starts with the greedy choice, and optimal substructure, so the rest of a best answer is a best answer to what is left.
With coins 1, 5, 10 and 25, greedy is always right. With coins 1, 3 and 4, making 6 greedily gives 4 + 1 + 1, but 3 + 3 is better. When greedy fails, dynamic programming is usually the fix.
Part 2

📅Interval scheduling: finish first

You have a list of activities with start and end times and one room. What is the largest number that fit without overlapping? The winning rule is simple: sort by end time and keep every activity that starts after the last kept one ends. Try the other rules in the animation and watch them lose.

Why it works: take any best schedule. Swap its first activity for the one that finishes earliest. Nothing breaks, because the new one ends even sooner, and the count stays the same. Repeat for the rest.

🎒The fractional knapsack

A bag holds a limited weight, and each item has a value and a weight. If items can be split, like gold dust, the greedy rule is to sort by value per kilo and take the best first, splitting the last item if needed. If items must be taken whole, the same rule can fail badly.

Part 4

🌳Huffman codes

To store text in fewer bits, give common letters short codes and rare letters long ones. No code may be the start of another, so the text can be read back without gaps. Huffman's algorithm builds the best such code with a greedy rule: keep joining the two rarest trees until one tree is left. Left edges add a 0 and right edges add a 1.

For counts a 5, b 9, c 12, d 13, e 16 and f 45, Huffman needs 224 bits where fixed 3 bit codes need 300. The DEFLATE format inside ZIP, gzip and PNG files uses Huffman codes.
Part 5

✂️Greedy with a stack: remove k digits

Remove k digits from a number to make it as small as possible. The leftmost digits matter most, so walk from the left. Whenever the digit you just kept is bigger than the next one, removing it makes the number smaller. A stack keeps the digits chosen so far and makes popping easy.

If digits are still left to remove at the end, the kept digits rise from left to right, so drop them from the end. Then strip leading zeros, and return "0" if nothing is left.
Part 6

🔁Proving greedy right: the exchange argument

One server must run several jobs, one after another. Every job waits for all jobs before it. To make the total waiting as small as possible, run the shortest job first. The proof is an exchange argument: if a longer job runs right before a shorter one, swapping them lowers the total wait, so the best order has no such pair.

a before b adds a to the wait    b before a adds b    so put the smaller first
Dijkstra's shortest paths, Prim's and Kruskal's spanning trees and Huffman codes are all greedy algorithms with proofs like this one.
