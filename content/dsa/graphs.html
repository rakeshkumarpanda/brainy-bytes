Graphs

Graphs model anything made of things and links: roads, friendships, networks and plans. This page shows how to store a graph, explore it with breadth first and depth first search, put tasks in a valid order, find the cheapest routes with Dijkstra, connect everything with a minimum spanning tree, and treat grids as graphs.

Part 1

🕸️What a graph is

A graph is a set of vertices (also called nodes) joined by edges. Unlike a tree, a graph has no root and may contain loops, so you can walk in a circle and come back to where you started. Road maps, friendships, flight routes, web links and computer networks are all graphs.

↔️ Undirected or directed

A friendship goes both ways, so it is an undirected edge. "A follows B" goes one way, so it is a directed edge, drawn with an arrow.

⚖️ Weighted

An edge can carry a number such as a distance, a price or a travel time. Shortest path algorithms add these weights up.

Programs store a graph in one of two ways.

Part 2

🌊Breadth first search

Breadth first search (BFS) explores a graph in rings. It visits the start, then every vertex one edge away, then every vertex two edges away, and so on. A queue keeps the discovered vertices in order, and a seen mark stops any vertex from being added twice.

In a graph without weights, the first time BFS reaches a vertex is along a shortest path. Remember the parent of each vertex and you can walk the path back.

Every vertex enters the queue once and every edge is looked at once from each end, so BFS takes

O(V + E)
Part 3

🧗Depth first search

Depth first search (DFS) follows one path as far as it can go, then backs up to the last vertex with an unexplored neighbour and tries again. Recursion gives it a stack for free. Switch the animation above to DFS to compare the two orders.

Deep recursion can overflow the call stack on a graph with hundreds of thousands of vertices in a line. Python stops at about 1000 levels by default. For large inputs, write DFS with your own stack.
Part 4

👕Topological order

Some tasks must happen before others: socks before shoes, a course before the next course, a library before the program that uses it. Draw an arrow from each task to the task that depends on it, and you get a directed acyclic graph (DAG). A topological order lists every task so that all arrows point forwards.

Kahn's algorithm counts how many arrows point into each vertex (its in-degree). Every vertex with in-degree 0 is ready. Take a ready vertex, add it to the order, and remove its outgoing arrows, which may make new vertices ready.

If the order ends up shorter than the number of vertices, some vertices never became ready. That only happens when the graph has a cycle, so Kahn's algorithm is also a cycle detector.
Part 5

🗺️Dijkstra's shortest paths

When edges have weights, the path with the fewest edges is not always the cheapest. Dijkstra's algorithm grows a set of settled vertices whose shortest distance is final. Each round it settles the closest unsettled vertex, then tries to improve each neighbour through it. Trying to improve a neighbour is called relaxing an edge.

if dist[v] + w < dist[u] then dist[u] = dist[v] + w

With a binary heap as the priority queue, the running time is

O((V + E) log V)
Dijkstra needs weights that are zero or positive. A negative edge can make a settled distance wrong. For negative weights use Bellman-Ford, which relaxes every edge V − 1 times in O(V · E).
Part 6

🔌Minimum spanning trees and union find

A town wants to connect every house to the network with the least cable. A spanning tree connects all V vertices with exactly V − 1 edges and no cycle. The minimum spanning tree (MST) is the one with the smallest total weight.

Kruskal's algorithm sorts the edges from cheapest to most expensive and takes each one unless it would close a cycle. To check that quickly it uses union find: every vertex points towards a leader of its group, find follows the pointers to the leader, and union joins two groups by pointing one leader at the other.

StepCost
sort the edgesO(E log E)
find and union, with path compressionalmost O(1) each
totalO(E log E)
Union find also answers "are these two computers on the same network?" and "which edge closes a cycle?" without a full search.
Part 7

🏝️Grids are graphs too

Many puzzles hide a graph inside a grid. Every cell is a vertex, and it is joined to its four neighbours up, down, left and right. You never build an adjacency list. You compute the neighbours with small offsets and check that they stay inside the grid.

Scan every cell. When you find land that has not been seen, it starts a new island, and a BFS or DFS flood marks the whole island so it is never counted again. Each cell is handled a constant number of times, so the total is O(rows × cols).
