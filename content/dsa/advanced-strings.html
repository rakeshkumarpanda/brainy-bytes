Part 1

📦The Z algorithm

The Strings chapter matched one pattern with KMP. The Z algorithm does the same job with an idea that is easy to picture. For every position i, z[i] is how many letters starting at i match the start of the string. The trick is the Z box: the rightmost stretch already known to match the start. Inside it, a new position copies what it already knows from earlier, and only compares letters past the edge.

search: build pattern + $ + text, and report every i with z[i] = length of pattern
The right edge of the Z box only moves forward, so the total number of letter comparisons is at most about 2n. That makes the whole algorithm O(n).
Part 2

🪞Manacher: every palindrome in linear time

Growing a palindrome around every centre takes O(n²) in the worst case. Manacher's algorithm brings that down to O(n). First put a # between letters, so every palindrome has a single middle. Then remember the palindrome that reaches furthest to the right. A position inside it has a mirror on the other side of the centre, and the mirror already knows a radius to start from.

inside the furthest palindrome: p[i] starts at min( r − i, p[2c − i] ), then grows
The radius in the # string is exactly the length of the palindrome in the original word, which is why the # trick works so neatly.

🗂️Suffix arrays and the LCP array

A suffix array lists the start of every suffix of a string in sorted order. Sorting by doubling compares the first 1, 2, 4, 8 and more letters, reusing the ranks from the round before, so each round is one sort of pairs. The LCP array then stores how many letters each suffix shares with the one before it in sorted order.

QuestionAnswer from the arrays
Does a pattern appear?Binary search the sorted suffixes
Longest repeated substringThe biggest LCP value
Number of distinct substringsn(n + 1) ÷ 2 minus the sum of the LCP values
Kasai's method builds the LCP array in O(n) because the shared length drops by at most 1 when you move from one suffix to the next shorter one.
Part 4

🕸️Aho-Corasick: many patterns at once

To look for many words in one text, put all the words into one trie. Then add a fail link to every node: it points to the longest ending of that node's letters that is also somewhere in the trie. While reading the text, a missing branch sends you along the fail link instead of back to the start, so the text is read exactly once.

Fail links are built breadth first, so the link of every shorter node is ready before it is needed. A node also reports every word that ends at its fail link, which is how "she" also reports "he".
The original Unix fgrep tool was built on this algorithm, and virus scanners such as ClamAV use it to look for thousands of patterns in one pass.

🧮Rolling hashes and binary search

A rolling hash turns a window of letters into a number, and slides to the next window with one subtraction, one multiplication and one addition. With prefix hashes, the hash of any substring takes O(1). Two equal hashes mean the letters are probably equal, so a final letter check rules out a collision.

hash(s[i:j]) = h[j] − h[i] × basej − i   (mod a prime)
With a small modulus, as in the animation, collisions are common. Real code uses a large prime, or two different hashes at once, so that a collision is very unlikely.
