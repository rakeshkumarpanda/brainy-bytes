Linked Lists

A linked list is a chain of nodes joined by references. It gives up instant access by position, and in return inserting and deleting never move anything. This page builds lists by hand, rewires them, reverses and merges them, and shows the tortoise and hare trick that finds middles and loops.

Part 1

🔗Nodes holding hands

A linked list is a chain of nodes. Each node holds a value and a reference (a pointer) to the next node. The list itself only remembers the first node, called the head. The last node points at nothing: None in Python, null in JavaScript and Java.

📦 Array

One block of memory, boxes side by side. Box i is found by arithmetic, so reading by position is O(1). Inserting at the front shifts everything, O(n).

🔗 Linked list

Nodes can live anywhere in memory, joined only by references. Reaching node i means walking i steps, O(n). Inserting next to a node you already hold is O(1).

You can only enter a singly linked list through its head and only move forward. Lose the head and the whole list is gone.
Part 2

✂️Inserting and deleting by rewiring

Nothing ever moves in a linked list. Inserting or deleting only changes a few references, which is why these operations can be O(1) once you are standing at the right place.

OperationWhat changesCost
Insert at headnew.next = head, then head = newO(1)
Insert after a known nodenew.next = node.next, then node.next = newO(1)
Insert at tailwalk to the end first, or keep a tail referenceO(n), or O(1) with tail
Delete the node after prevprev.next = prev.next.nextO(1)
Delete by valuewalk to find the node before it, then unlinkO(n)
Order matters. When inserting after a node, set new.next first. If you set node.next = new first, the rest of the list is lost.

The dummy node trick

Deleting the head is usually a special case, because no node comes before it. Put a fake dummy (sentinel) node in front of the head. Now every real node has a node before it, the special case disappears, and the answer is dummy.next.

Part 3

↔️Doubly linked and circular lists

A doubly linked list gives every node two references: next and prev. It costs one more reference per node, and in return you can walk backwards and remove a node in O(1) when you hold that node, because it knows both of its neighbours.

↔️ Doubly linked

head and tail at both ends. Browser history, music playlists and text editors use it to move both ways.

🔄 Circular

The last node points back at the first instead of null. Round robin schedulers and turn based games loop through players this way.

Part 4

🔁Reversing a list in place

Reversing is the classic linked list exercise, and it trains the most important habit: save the next node before you change a reference.

  1. nxt = cur.next remembers the rest of the list.
  2. cur.next = prev turns one arrow around.
  3. prev = cur and cur = nxt step forward.

When cur falls off the end, prev is the old tail and the new head. Every node is visited once, so it is O(n) time and O(1) extra space.

The recursive version is shorter but uses one stack frame per node, so it needs O(n) space and can overflow the call stack on a list of a million nodes.
Part 5

🐢Fast and slow pointers

Send two pointers down the list at different speeds: the tortoise moves one node per step and the hare moves two. This one idea answers several questions in a single pass with O(1) extra space.

🎯 Middle node

When the hare reaches the end, the tortoise has gone half as far, so it stands in the middle.

🔄 Cycle detection

If the list loops, the hare enters the loop and eventually laps the tortoise. If it reaches null, there is no loop. This is Floyd's algorithm.

Why must they meet? Inside the loop the hare gains exactly one node on the tortoise every step, so the gap shrinks by one until it is zero. They meet within one lap of the loop.

gap after each step = gap − 1 so they meet in at most (loop length) steps
To find where the loop starts, put one pointer back at the head after they meet and move both one step at a time. They meet again exactly at the start of the loop.
Part 6

🤝Merging two sorted lists

Given two lists that are already sorted, build one sorted list by repeatedly taking the smaller front node. No new nodes are needed: we only rewire the existing ones. A dummy node again saves us from special cases at the start.

Each step moves one node into place, so merging lists of length n and m takes O(n + m) time and O(1) extra space. This is the heart of merge sort on linked lists, which sorts a list in O(n log n) without random access.

Part 7

⚖️Lists versus arrays in real code

On paper, linked lists win at inserting and deleting. In real programs, arrays often win anyway, because their boxes sit next to each other and the CPU cache loads many of them at once. Following references jumps around memory.

NeedBetter choiceWhy
Read item i oftenarrayO(1) access by index
Add or remove at both endsdeque or linked listO(1) at the front and the back
Remove items you already hold, very oftendoubly linked listO(1) unlink without searching
Iterate over everything fastarraycache friendly, no pointer chasing
Least recently used cachehash map + doubly linked listO(1) lookup and O(1) move to front
Your operating system keeps lists of free memory blocks and of waiting processes as linked lists, and the undo history in many editors is a doubly linked list of changes.
