Part 1

📅How JavaScript grows every year

Every June, Ecma publishes a new edition of the standard: ES2020, ES2021 and so on. A feature joins only after it reaches stage 4 at TC39, which needs two shipping browser engines and a full test suite. Engines often ship features months before the edition that lists them, so "can I use it" depends on your browsers and Node.js version, not the year on the label.

EditionHighlights you will meet in real code
ES2015 (ES6)let and const, arrow functions, classes, modules, promises, template literals, destructuring, Map and Set
ES2017async and await, Object.entries, padStart
ES2020?., ??, BigInt, Promise.allSettled, globalThis, dynamic import
ES2021||= &&= ??=, replaceAll, Promise.any, numeric separators, WeakRef
ES2022class fields and #private, top level await, .at(), Object.hasOwn, error cause
ES2023findLast, toSorted, toReversed, toSpliced, with
ES2024Object.groupBy, Map.groupBy, Promise.withResolvers, the v regex flag
ES2025iterator helpers, Set methods, RegExp.escape, Promise.try, import attributes, Float16Array
ES2026 (June 2026)Error.isError, Array.fromAsync, Uint8Array base64 and hex, Map and WeakMap getOrInsert (upsert), Iterator.concat, JSON.parse source text and JSON.rawJSON, Math.sumPrecise
Finished for ES2027using and await using with DisposableStack, Temporal, Atomics.pause, iterator chunks and windows, Iterator.zip, iterator includes and join

The "Finished for ES2027" row comes from TC39's list of finished proposals, checked in October 2026. Being finished means the design will not change, but a feature can still be missing from your Node.js or browser. The last part of this chapter shows how to check.

Check support on caniuse.com or MDN's compatibility tables, and set your TypeScript target and lint rules to match the oldest browser or Node.js you support.

❓ES2020 to ES2023: safer access and copies

🧪 QA essentialThese features appear in nearly every modern test file and page object.

Optional chaining and nullish coalescing removed most of the "cannot read properties of undefined" crashes from everyday code. The ES2023 change by copy methods return a new array and leave the original alone, which makes test data safe to reuse.

ES2020 and ES2021: ?., ??, BigInt and friends · ▶ Runs
const order = { id: 7, customer: { name: "Asha", address: null }, discount: 0 };

// Optional chaining: stop at null or undefined instead of throwing
console.log(order.customer?.address?.city);          // undefined, no crash
console.log(order.items?.[0], order.notify?.());     // works for indexes and calls too

// Nullish coalescing: a default only for null and undefined, not for 0 or ""
console.log(order.discount || 10, order.discount ?? 10);

// BigInt for whole numbers beyond 2^53
console.log(2 ** 53 + 1, 2n ** 53n + 1n);

// Logical assignment (ES2021)
const settings = { retries: 0, browser: null };
settings.retries ||= 3;        // 0 is falsy, so it becomes 3
settings.browser ??= "chromium";
console.log(settings);

console.log(1_000_000 + 0.000_5, "a-b-c".replaceAll("-", "/"));
console.log(typeof globalThis);

const runs = [{ id: 1, ok: true }, { id: 2, ok: false }, { id: 3, ok: true }, { id: 4, ok: false }];

console.log(runs.at(-1).id);                               // ES2022: count from the end

  try { JSON.parse("{bad"); }

console.log(byIdDesc.map(r => r.id), runs.map(r => r.id));

🧰ES2024 and ES2025: grouping, iterators, safer regexes

🧪 QA essentialgroupBy summarises test results in one line, and RegExp.escape makes text matching in tests safe.

Grouping a list, a promise you resolve from outside, lazy iterator helpers, real set operations and a safe way to put user text into a regular expression all arrived in the last two editions.

ES2024: groupBy, withResolvers, the v flag · ▶ Runs
const tests = [
  { name: "login", status: "passed", ms: 840 },
  { name: "search", status: "failed", ms: 120 },
  { name: "checkout", status: "failed", ms: 2310 },
  { name: "profile", status: "skipped", ms: 0 },
];

// Group a list into an object, or a Map, by any rule
const byStatus = Object.groupBy(tests, t => t.status);
console.log(Object.keys(byStatus), byStatus.failed.map(t => t.name));
const bySpeed = Map.groupBy(tests, t => (t.ms > 1000 ? "slow" : "fast"));
console.log(bySpeed.get("slow").map(t => t.name));

// A promise you can resolve from the outside
const { promise, resolve } = Promise.withResolvers();
setTimeout(() => resolve("done"), 10);
console.log(await promise);

// Well formed strings and the v flag for set operations in character classes
console.log("ok".isWellFormed(), "bad \uD800".isWellFormed());
console.log("Héllo Wörld".match(/[\p{L}--[a-z]]/gv));    // letters that are not plain a to z

Iterator helpers are lazy. Arrays do each step for every element before the next step starts. An iterator chain pulls one value at a time through all the steps, and stops the moment take has enough. That is why the example below can work on an endless list of test ids without running forever.

ES2025: iterator helpers, Set methods, RegExp.escape, Promise.try · ▶ Runs
// Iterator helpers: lazy map, filter, take on any iterator (chapter 8)
function* ids() { let n = 1; while (true) yield `TC-${n++}`; }
console.log(ids().filter(id => id.endsWith("7")).take(2).toArray());

// Set methods (chapter 8)
console.log([...new Set(["a", "b", "c"]).difference(new Set(["b"]))]);

// RegExp.escape: put user text into a pattern safely
const userText = "Price (incl. tax) $5.00?";
console.log(RegExp.escape(userText));
console.log(new RegExp(RegExp.escape(userText)).test(`Total: ${userText}`));

// Promise.try: run a function that may throw or return a promise, and always get a promise
const readConfig = () => { throw new Error("missing file"); };
await Promise.try(readConfig).catch(e => console.log("caught:", e.message));

// Duplicate named groups and inline modifiers in regular expressions
const date = /(?<y>\d{4})-(?<m>\d\d)|(?<m>\d\d)\/(?<y>\d{4})/;
console.log(date.exec("2026-10").groups.y, date.exec("10/2026").groups.y);
console.log(/^(?i:hello) World$/.test("HELLO World"), /^(?i:hello) World$/.test("hello WORLD"));

// Float16Array and Math.f16round for compact numbers (machine learning, graphics)
console.log(Math.f16round(1.337), new Float16Array([1.337])[0]);

🆕ES2026 and ES2027: using, Error.isError, upsert and more

🧪 QA essentialPlaywrightNode.jsusing makes sure browsers, servers and temp data are always cleaned up, even when a test fails.

The June 2026 edition, ES2026, is a collection of small tools that remove common helper functions from real projects:

  • Error.isError tells you whether a value is a real error, even one made in another frame or a vm context, where instanceof Error gives the wrong answer.
  • Array.fromAsync collects an async iterable, such as pages of API results, into one array.
  • Uint8Array base64 and hex methods replace the old btoa tricks and Buffer calls for tokens, file uploads and signatures.
  • Upsert: map.getOrInsert(key, value) and getOrInsertComputed(key, fn) read a key or add it in one step, the classic cache pattern.
  • Iterator.concat joins several iterables lazily, and JSON.parse source text access lets a reviver read the original text of a number, so long ids survive as BigInt.
  • Math.sumPrecise adds a list of numbers without the rounding drift of a loop. It is in the standard but not yet in Node.js 26, so it appears in the last part.

The headline feature for ES2027, already finished and already shipping in Node.js 24 and later, is explicit resource management. A variable declared with using is cleaned up automatically when its block ends, in reverse order, even when an error is thrown. It replaces long try and finally blocks around browsers, servers, files and connections.

ES2026 and using: Error.isError, fromAsync, base64, upsert and more · ▶ Runs
// Explicit resource management: "using" calls Symbol.dispose when the block ends,
// even if an error is thrown. Great for browsers, servers, temp files and DB connections.
function openBrowser(name) {
  console.log(`open ${name}`);
  return { name, [Symbol.dispose]() { console.log(`close ${name}`); } };
}
function runTest() {
  using browser = openBrowser("chromium");
  using other = openBrowser("firefox");
  console.log(`testing with ${browser.name} and ${other.name}`);
  throw new Error("assertion failed");
}
try { runTest(); } catch (e) { console.log("test failed:", e.message); }

// Async version: await using with Symbol.asyncDispose
async function startServer() {
  return { url: "http://localhost:4173", async [Symbol.asyncDispose]() { console.log("server stopped"); } };
}
{
  await using server = await startServer();
  console.log("server at", server.url);
}

// Error.isError works across frames and realms, unlike instanceof
console.log(Error.isError(new TypeError("x")), Error.isError({ message: "fake" }));

// Array.fromAsync collects an async iterable
async function* pages() { yield [1, 2]; yield [3]; }
console.log((await Array.fromAsync(pages())).flat());

// Base64 and hex built into Uint8Array
const bytes = new TextEncoder().encode("QA rocks");
console.log(bytes.toBase64(), bytes.toHex().slice(0, 8), new TextDecoder().decode(Uint8Array.fromBase64("UUEgcm9ja3M=")));

// Map.getOrInsertComputed, Iterator.concat
const cache = new Map();
console.log(cache.getOrInsertComputed("token", () => "t-123"), cache.size);
console.log(Iterator.concat([1, 2], new Set([3])).toArray());

// JSON.parse can read the original text of a number, so big ids survive
console.log(JSON.parse('{"orderId": 90071992547409931}', (k, v, ctx) => (k === "orderId" ? BigInt(ctx.source) : v)));

When the clean up steps are only known at run time, collect them in a DisposableStack. Each adopt or defer adds a step, and they all run in reverse order. If both the test and a clean up step fail, nothing is lost: the two errors are joined in a SuppressedError.

DisposableStack and SuppressedError for test set up · ▶ Runs
// DisposableStack: collect clean up steps as you go, run them all in reverse at the end
function setUpSuite() {
  using stack = new DisposableStack();
  const server = stack.adopt({ port: 4173 }, s => console.log("stop server on", s.port));
  stack.defer(() => console.log("delete temp folder"));
  const user = stack.adopt({ id: 42 }, u => console.log("delete test user", u.id));
  console.log("suite ready:", server.port, user.id);
  return stack.move();               // hand the clean up to the caller instead of running it now
}
const cleanup = setUpSuite();
console.log("tests run here");
cleanup.dispose();
console.log("disposed:", cleanup.disposed);

// Errors in clean up are not lost: they are wrapped in a SuppressedError
try {
  using a = { [Symbol.dispose]() { throw new Error("close failed"); } };
  throw new Error("test failed");
} catch (e) {
  console.log(e.name, "|", e.error.message, "| hid:", e.suppressed.message);
}
Output
suite ready: 4173 42
tests run here
delete test user 42
delete temp folder
stop server on 4173
disposed: true
SuppressedError | close failed | hid: test failed
These features ship in Node.js 24 and later and in current browsers, with TypeScript support for using. The page you are reading ran them on Node.js 26. If your users run older browsers, check support or use a transpiler.

🕰️Temporal: dates done right

🧪 QA essentialDate and time zone edge cases are a classic source of bugs and of wrong expected values in tests.

The old Date object mixes up time zones, months that start at 0 and objects that change in place. Temporal replaces it with clear types: PlainDate for a calendar date, PlainDateTime without a zone, ZonedDateTime with a zone, Instant for an exact moment and Duration for lengths of time. Every object is immutable.

Temporal: dates and times that behave · ▶ Runs
const { PlainDate, PlainDateTime, ZonedDateTime, Duration, Instant } = Temporal;

// Dates without times or time zones: perfect for test data such as birthdays and due dates
const due = PlainDate.from("2026-01-31");
console.log(due.add({ months: 1 }).toString());            // clamps to the end of February
console.log(due.dayOfWeek, due.daysInMonth, due.inLeapYear);

// Exact age check, for an "18 or older" rule
const birthday = PlainDate.from("2008-10-21");
const today = PlainDate.from("2026-10-20");
console.log("age:", birthday.until(today, { largestUnit: "years" }).years);

// Time zones done right: the same meeting in Kolkata and Berlin
const meeting = ZonedDateTime.from("2026-03-29T10:00[Asia/Kolkata]");
console.log(meeting.withTimeZone("Europe/Berlin").toString());

// Durations you can add, compare and round
const timeout = Duration.from({ minutes: 1, seconds: 30 });
console.log(timeout.total("milliseconds"), Duration.compare(timeout, { seconds: 60 }));

// Objects are immutable and comparisons are explicit
const a = PlainDateTime.from("2026-10-20T09:00");
console.log(PlainDateTime.compare(a, a.add({ minutes: 5 })), a.toString());
console.log(Instant.from("2026-10-20T09:00:00Z").epochMilliseconds);

Date bugs are some of the most common bugs testers find: month ends (31 January plus one month), leap years, daylight saving changes, and users in other time zones. Temporal makes the expected values in your tests easy to compute correctly.

🔭What comes next, and how to check before you use it

🧪 QA essentialTest code runs on CI images, old browsers and devices, so checking support prevents "works on my machine" failures.

A feature you read about may not exist where your code runs. Old phones, a company laptop with an old browser, or a CI image with an older Node.js all lag behind. Professionals do not guess from version numbers. They detect the feature at run time, or they let tools such as TypeScript's lib setting, ESLint and Babel check it at build time.

Which of the newest features this Node.js has · ▶ Runs
// Feature detection: ask the runtime instead of guessing from a version number
const checks = {
  "using (ES2027)": () => { new Function("{ using x = null; }")(); return true; },
  "Temporal (ES2027)": () => typeof Temporal === "object",
  "Error.isError (ES2026)": () => typeof Error.isError === "function",
  "Map getOrInsert (ES2026)": () => typeof Map.prototype.getOrInsert === "function",
  "Math.sumPrecise (ES2026)": () => typeof Math.sumPrecise === "function",
  "iterator chunks (ES2027)": () => typeof Iterator.prototype.chunks === "function",
  "Iterator.zip (ES2027)": () => typeof Iterator.zip === "function",
  "iterator join (ES2027)": () => typeof Iterator.prototype.join === "function",
};
for (const [name, check] of Object.entries(checks)) {
  let ok;
  try { ok = check(); } catch { ok = false; }
  console.log((ok ? "yes " : "not yet ") + name);
}
console.log("loop sum:", [0.1, 0.2, 0.3].reduce((a, b) => a + b, 0));

The "not yet" lines are features that TC39 has finished but V8 in Node.js 26 has not shipped. When they arrive, they will remove more small helpers from real projects: splitting test ids into batches for parallel workers, pairing names with timings in a report, and adding up money without floating point drift.

🎬Real world scenario: modernise safely

🧪 QA essential
The situationAn old test helper written in 2016 is hard to read. You want to rewrite it with modern features without changing what it returns.
Modernise an old helper and prove nothing changed · ▶ Runs
// Old style helper from a 2016 test suite
function oldSummary(results) {
  var copy = results.slice();
  copy.sort(function (a, b) { return b.ms - a.ms; });
  var groups = {};
  for (var i = 0; i < results.length; i++) {
    var s = results[i].status;
    if (!groups.hasOwnProperty(s)) groups[s] = [];
    groups[s].push(results[i].name);
  }
  var slowest = copy.length > 0 ? copy[0].name : "none";
  var owner = results.length && results[0].meta && results[0].meta.owner ? results[0].meta.owner : "unknown";
  return { failed: groups.failed || [], slowest: slowest, owner: owner };
}

// The same helper with modern features
const newSummary = results => ({
  failed: Object.groupBy(results, r => r.status).failed?.map(r => r.name) ?? [],
  slowest: results.toSorted((a, b) => b.ms - a.ms)[0]?.name ?? "none",
  owner: results[0]?.meta?.owner ?? "unknown",
});

const runs = [
  { name: "login", status: "passed", ms: 840, meta: { owner: "team-auth" } },
  { name: "checkout", status: "failed", ms: 2310 },
  { name: "search", status: "failed", ms: 120 },
];
for (const input of [runs, []]) {
  const before = oldSummary(input), after = newSummary(input);
  console.log(JSON.stringify(after), "| same as old:", JSON.stringify(before) === JSON.stringify(after));
}
Output
{"failed":["checkout","search"],"slowest":"checkout","owner":"team-auth"} | same as old: true
{"failed":[],"slowest":"none","owner":"unknown"} | same as old: true

The rewrite is a third of the size. Running both versions on the same inputs, including an empty list, and comparing the results is a simple form of characterisation testing: it proves the behaviour stayed the same before you delete the old code.
