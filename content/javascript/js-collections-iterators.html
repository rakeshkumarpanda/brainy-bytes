Part 1

🗺️Map

🧪 QA essential

A Map stores key and value pairs, like an object, with three differences that matter: keys can be any value (objects, numbers, functions), it remembers insertion order, and it has a size.

Map: a dictionary with any kind of key · ▶ Runs
const tokens = new Map();
tokens.set("admin", "tok-a1");
tokens.set("customer", "tok-c9");
console.log(tokens.get("admin"), tokens.has("guest"), tokens.size);

const visits = new Map();
const page = { url: "/cart" };          // an object as a key, which plain objects cannot do
visits.set(page, 3);
console.log(visits.get(page));

for (const [role, token] of tokens) console.log(role, "->", token);   // insertion order
console.log([...tokens.keys()], Object.fromEntries(tokens));

tokens.delete("customer");
console.log(tokens);
Output
tok-a1 false 2
3
admin -> tok-a1
customer -> tok-c9
[ 'admin', 'customer' ] { admin: 'tok-a1', customer: 'tok-c9' }
Map(1) { 'admin' => 'tok-a1' }
When a Map beats a plain object · ▶ Runs
const asObject = {};
asObject["1"] = "string key";
asObject[1] = "number key";               // object keys are always strings, so this overwrites
console.log(Object.keys(asObject).length);

const asMap = new Map([["1", "string key"], [1, "number key"]]);
console.log(asMap.size);

const counts = new Map();
for (const word of "to be or not to be".split(" ")) {
  counts.set(word, (counts.get(word) ?? 0) + 1);
}
console.log(counts);
console.log(counts.getOrInsert("maybe", 0), counts.size);   // ES2026: read or insert in one step
Output
1
2
Map(4) { 'to' => 2, 'be' => 2, 'or' => 1, 'not' => 1 }
0 5
Use a plain object for fixed shapes such as a user or a config. Use a Map for lookups that grow at run time: caches, counters, "element to data" tables. getOrInsert and getOrInsertComputed (ES2026) replace the "get, check, set" dance.
A Map is a clean way to cache one login token per role during a test run, so each role logs in once: tokens.getOrInsertComputed(role, () => login(role)) for a synchronous helper, or the get, check and set steps around an await.
Part 2

🧺Set and set operations

🧪 QA essentialPlaywrightCypressSelenium

A Set holds unique values. Adding a value twice keeps one copy. ES2025 added the operations from school maths, so comparing two lists no longer needs nested loops.

Set and the ES2025 set operations · ▶ Runs
const seen = new Set(["chromium", "firefox"]);
seen.add("webkit").add("chromium");      // duplicates are ignored
console.log(seen.size, seen.has("firefox"));

const expected = new Set(["Home", "Shop", "Deals", "Help", "Account"]);
const actual = new Set(["Home", "Shop", "Help", "Account", "Blog"]);

console.log("missing:", [...expected.difference(actual)]);      // ES2025 Set methods
console.log("extra:", [...actual.difference(expected)]);
console.log("both:", [...expected.intersection(actual)]);
console.log("all:", [...expected.union(actual)].length);
console.log("changed:", [...expected.symmetricDifference(actual)]);
console.log(new Set(["Home", "Shop"]).isSubsetOf(actual), expected.isDisjointFrom(new Set(["Login"])));
Output
3 true
missing: [ 'Deals' ]
extra: [ 'Blog' ]
both: [ 'Home', 'Shop', 'Help', 'Account' ]
all: 6
changed: [ 'Deals', 'Blog' ]
true true
MethodReturns
a.union(b)everything in either
a.intersection(b)only what is in both
a.difference(b)in a but not in b
a.symmetricDifference(b)in exactly one of them
a.isSubsetOf(b), isSupersetOf, isDisjointFromtrue or false
Checking a dropdown, a menu or a list of columns against the spec is a set comparison. Report expected.difference(actual) as missing and actual.difference(expected) as unexpected, and the failure message says exactly what is wrong.
Part 3

🪶WeakMap, WeakSet and WeakRef

Weak collections hold objects without keeping them alive. When nothing else uses the object, the garbage collector may remove it and its entry disappears. They cannot be listed or counted, because their contents can change at any moment.

WeakMap and WeakRef · ▶ Runs
const meta = new WeakMap();      // keys must be objects and do not keep them alive
function track(element) {
  meta.set(element, { clicks: (meta.get(element)?.clicks ?? 0) + 1 });
}
const button = { id: "buy" };
track(button); track(button);
console.log(meta.get(button));
console.log(meta.has({ id: "buy" }));   // a different object

const cache = new WeakRef({ big: "report data" });
console.log(cache.deref()?.big);        // may be undefined once memory is reclaimed
Output
{ clicks: 2 }
false
report data

Libraries use a WeakMap to attach extra data to DOM elements or objects they do not own without causing memory leaks. App code rarely needs WeakRef or FinalizationRegistry, and their timing must never be relied on.

Part 4

🔁Iterators and iterator helpers

An iterable is anything with a Symbol.iterator method: arrays, strings, Maps, Sets, NodeLists and arguments. That method returns an iterator, an object whose next() hands out { value, done } one at a time. for...of, spread and destructuring all use it.

The iteration protocol · ▶ Runs
const word = "QA";
const it = word[Symbol.iterator]();      // every iterable hands out an iterator
console.log(it.next(), it.next(), it.next());

// spread, for...of, destructuring and Array.from all use the same protocol
console.log([..."hey"], Array.from(new Set([3, 3, 4])));
const [first, ...rest] = new Map([["a", 1], ["b", 2]]);
console.log(first, rest);

const countdown = {
  from: 3,
  [Symbol.iterator]() {
    let n = this.from;
    return { next: () => (n > 0 ? { value: n--, done: false } : { value: undefined, done: true }) };
  },
};
console.log([...countdown]);
for (const n of countdown) console.log("T minus", n);
Output
{ value: 'Q', done: false } { value: 'A', done: false } { value: undefined, done: true }
[ 'h', 'e', 'y' ] [ 3, 4 ]
[ 'a', 1 ] [ [ 'b', 2 ] ]
[ 3, 2, 1 ]
T minus 3
T minus 2
T minus 1

Iterator helpers (ES2025)

Iterators now have map, filter, take, drop and friends. Unlike the array methods, they are lazy: no work happens until a value is asked for, so they work on huge or endless sequences.

Iterator helpers · ▶ Runs
// ES2025 iterator helpers: map, filter, take, drop, flatMap, reduce, some, every, find, toArray.
// They work lazily, one value at a time, on any iterator.
function* naturals() {
  let n = 1;
  while (true) yield n++;                 // an endless sequence is fine when consumed lazily
}

const firstEvenSquares = naturals()
  .map(n => n * n)
  .filter(n => n % 2 === 0)
  .take(4)
  .toArray();
console.log(firstEvenSquares);

const map = new Map([["a", 1], ["b", 2], ["c", 3]]);
console.log(map.values().filter(v => v > 1).toArray());
console.log(Iterator.from({ next: () => ({ value: 7, done: false }) }).take(3).toArray());
Output
[ 4, 16, 36, 64 ]
[ 2, 3 ]
[ 7, 7, 7 ]
Part 5

⏯️Generators and async generators

🧪 QA essentialJestPlaywrightAPI tests often have to walk paginated endpoints, and async generators make that a plain loop.

A generator function (function*) can pause at every yield and continue later from the same place. Calling it runs nothing. It returns an iterator, and each next() runs the body up to the next yield.

Generators pause and resume · ▶ Runs
function* idMaker(prefix) {
  let n = 1;
  while (true) {
    const reset = yield `${prefix}-${String(n).padStart(4, "0")}`;
    n = reset ? 1 : n + 1;
  }
}

const ids = idMaker("TC");
console.log(ids.next().value);
console.log(ids.next().value);
console.log(ids.next(true).value);      // a value passed to next() comes out of yield
console.log(ids.next().value);

function* steps() {
  console.log("  (running until the first yield)");
  yield "open";
  console.log("  (resumed)");
  yield "click";
  return "done";
}
const g = steps();
console.log("created, nothing ran yet");
console.log(g.next());
console.log(g.next());
console.log(g.next());
console.log(g.next());
Output
TC-0001
TC-0002
TC-0001
TC-0002
created, nothing ran yet
  (running until the first yield)
{ value: 'open', done: false }
  (resumed)
{ value: 'click', done: false }
{ value: 'done', done: true }
{ value: undefined, done: true }

Async generators and for await

An async function* can await between yields. Consumed with for await, it turns a paginated API into a simple loop, and it only fetches pages that are actually needed.

Async generators for paginated APIs · ▶ Runs
// A fake paginated API: 7 users, 3 per page
const ALL = ["asha", "ravi", "mei", "omar", "lena", "ken", "zoe"];
async function fetchPage(page) {
  await new Promise(r => setTimeout(r, 10));     // pretend network time
  const start = (page - 1) * 3;
  return { users: ALL.slice(start, start + 3), next: start + 3 < ALL.length ? page + 1 : null };
}

async function* allUsers() {
  let page = 1;
  while (page) {
    const body = await fetchPage(page);
    console.log(`  fetched page ${page}`);
    yield* body.users;                            // hand out each user of the page
    page = body.next;
  }
}

for await (const user of allUsers()) {
  console.log(user);
  if (user === "omar") break;                     // stop early: later pages are never fetched
}

console.log(await Array.fromAsync(allUsers()));
Output
  fetched page 1
asha
ravi
mei
  fetched page 2
omar
  fetched page 1
  fetched page 2
  fetched page 3
[
  'asha', 'ravi',
  'mei',  'omar',
  'lena', 'ken',
  'zoe'
]
Paginated endpoints are a classic API test target: page sizes, the last page, an empty page, a stable order across pages. An async generator gives you every item in one loop, and Array.fromAsync collects them for one big assertion.
Part 6

🔣Symbols

A symbol is a unique value used as a hidden key. Two symbols with the same description are still different, unless they come from the shared registry with Symbol.for. Symbol keys are skipped by Object.keys and JSON.stringify.

Symbols and well known symbols · ▶ Runs
const id = Symbol("id");
const user = { name: "Asha", [id]: 42 };
console.log(user[id], Object.keys(user), JSON.stringify(user));   // symbol keys are hidden from most tools
console.log(Symbol("x") === Symbol("x"), Symbol.for("x") === Symbol.for("x"));

const money = {
  amount: 2695,
  [Symbol.toPrimitive](hint) {
    return hint === "number" ? this.amount : `₹${this.amount.toLocaleString("en-IN")}`;
  },
};
console.log(`${money}`, +money, money * 2);
Output
42 [ 'name' ] {"name":"Asha"}
false true
₹2,695 2695 5390

Well known symbols let your objects plug into the language: Symbol.iterator makes them work with for...of, Symbol.toPrimitive controls how they turn into text and numbers, Symbol.asyncIterator works with for await, and Symbol.dispose works with using (chapter 16).

Part 7

🎬Real world scenario: compare a menu and walk every page

🧪 QA essential
The situationA release changed the site menu. You must report which items the spec asks for but the page lacks, which the page has that the spec does not mention, any duplicates, and whether the shared items keep their order. Then you must count every user across a paginated list.
Compare menus and walk every page · ▶ Runs
// Compare the menu a page shows with the menu the spec asks for, then read every page of the user list.
const specMenu = ["Home", "Shop", "Deals", "Help", "Account"];
const shownMenu = ["Home", "Shop", "Help", "Help", "Account", "Blog"];

const expected = new Set(specMenu);
const actual = new Set(shownMenu);
const report = {
  missing: [...expected.difference(actual)],
  unexpected: [...actual.difference(expected)],
  duplicated: shownMenu.filter((item, i) => shownMenu.indexOf(item) !== i),
  sameOrder: specMenu.filter(x => actual.has(x)).join() === [...actual].filter(x => expected.has(x)).join(),
};
console.log(report);

async function* pages(total, size) {
  for (let start = 0; start < total; start += size) {
    yield Array.from({ length: Math.min(size, total - start) }, (_, i) => `user${start + i + 1}`);
  }
}
let count = 0;
for await (const page of pages(23, 10)) {
  count += page.length;
  console.log(`page of ${page.length}, first ${page[0]}`);
}
console.log("total users:", count);
Output
{
  missing: [ 'Deals' ],
  unexpected: [ 'Blog' ],
  duplicated: [ 'Help' ],
  sameOrder: true
}
page of 10, first user1
page of 10, first user11
page of 3, first user21
total users: 23

Set operations produce the missing and unexpected lists in one line each, and duplicates are easy to spot once you compare each item's first position with its own. The async generator hides the paging, so the count is a plain loop.
