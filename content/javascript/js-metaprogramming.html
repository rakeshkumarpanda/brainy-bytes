Part 1

🧾Property descriptors, getters and setters

Every property has a descriptor with flags. writable allows changes, enumerable shows it in Object.keys, loops and JSON, and configurable allows deleting it or changing its flags. Accessor properties use get and set functions instead of a value.

Property descriptors, getters, setters and locking · ▶ Runs
"use strict";
const user = { name: "Asha" };
Object.defineProperty(user, "id", { value: 7, writable: false, enumerable: false, configurable: false });

console.log(Object.getOwnPropertyDescriptor(user, "name"));
console.log(Object.getOwnPropertyDescriptor(user, "id"));
console.log(Object.keys(user), JSON.stringify(user), user.id);      // not enumerable: hidden from keys and JSON
try { user.id = 8; } catch (e) { console.log(e.constructor.name, "on write") }
try { delete user.id; } catch (e) { console.log(e.constructor.name, "on delete") }

// Getters and setters: computed and validated properties
const cart = {
  items: [{ price: 40, qty: 2 }, { price: 250, qty: 1 }],
  get total() { return this.items.reduce((s, i) => s + i.price * i.qty, 0); },
  set coupon(code) {
    if (!/^[A-Z]+\d+$/.test(code)) throw new RangeError(`bad coupon ${code}`);
    this._coupon = code;
  },
};
console.log("total", cart.total);
cart.coupon = "SAVE10";
try { cart.coupon = "nope"; } catch (e) { console.log(e.message); }

// The three levels of locking
const levels = { preventExtensions: Object.preventExtensions, seal: Object.seal, freeze: Object.freeze };
for (const [name, lock] of Object.entries(levels)) {
  const o = lock({ a: 1 });
  const can = op => { try { op(o); return "yes"; } catch { return "no"; } };
  console.log(name.padEnd(17), "add:", can(o => (o.b = 2)), " change:", can(o => (o.a = 9)), " delete:", can(o => delete o.a));
}
Output
{ value: 'Asha', writable: true, enumerable: true, configurable: true }
{ value: 7, writable: false, enumerable: false, configurable: false }
[ 'name' ] {"name":"Asha"} 7
TypeError on write
TypeError on delete
total 330
bad coupon nope
preventExtensions add: no  change: yes  delete: yes
seal              add: no  change: yes  delete: no
freeze            add: no  change: no  delete: no
This is why a hidden property can be on an object you are testing but missing from JSON.stringify and toEqual comparisons. Use Object.getOwnPropertyDescriptors when an object behaves strangely.
Part 2

🔣Well known symbols

🧪 QA essentialHiding secrets from logs and reports is a must for test frameworks that log every object.

Built in operations look for special symbol keys on your objects. Symbol.toPrimitive controls conversion to numbers and strings, Symbol.hasInstance controls instanceof, Symbol.toStringTag the type label, and Symbol.iterator (chapter 8) makes an object loopable. Node.js adds util.inspect.custom for how an object is logged.

Well known symbols change built in behaviour · ▶ Runs
import util from "node:util";

class Money {
  constructor(amount, currency) { this.amount = amount; this.currency = currency; }
  // Decide what the object becomes in maths, in strings and by default
  [Symbol.toPrimitive](hint) { return hint === "number" ? this.amount : `${this.currency} ${this.amount.toFixed(2)}`; }
  get [Symbol.toStringTag]() { return "Money"; }
}
const price = new Money(49.5, "INR");
console.log(+price * 2, `${price}`, Object.prototype.toString.call(price));

// Control instanceof for duck typing
class Thenable { static [Symbol.hasInstance](x) { return typeof x?.then === "function"; } }
console.log(Promise.resolve() instanceof Thenable, {} instanceof Thenable);

// Hide secrets when objects are logged in Node.js
class Credentials {
  constructor(user, password) { this.user = user; this.password = password; }
  [util.inspect.custom]() { return `Credentials { user: '${this.user}', password: '***' }`; }
  toJSON() { return { user: this.user }; }
}
const login = new Credentials("asha", "s3cret");
console.log(login, JSON.stringify(login));
Output
99 INR 49.50 [object Money]
true false
Credentials { user: 'asha', password: '***' } {"user":"asha"}
Give credential and token objects a custom inspect and a toJSON that leave the secret out. Test reports, CI logs and screenshots of the console then never leak a password.
Part 3

🪞Proxy and Reflect

🧪 QA essentialPlaywrightSeleniumProxies power auto mocks and step logging, and let you add retries or reporting to every page object at once.

A Proxy sits in front of an object and can intercept almost anything done to it: reading, writing, deleting, in, listing keys, calling and new. Each handler function is a trap. Reflect has a method for every trap that does the normal behaviour, so a trap can add checks and then hand over.

Proxy and Reflect: intercept property access · ▶ Runs
// A Proxy wraps an object and intercepts operations through "traps"
const strictConfig = target => new Proxy(target, {
  get(obj, key, receiver) {
    if (typeof key === "string" && !(key in obj)) throw new ReferenceError(`unknown config key "${key}"`);
    return Reflect.get(obj, key, receiver);
  },
  set(obj, key, value) {
    if (key === "timeout" && !(Number.isInteger(value) && value > 0)) throw new TypeError("timeout must be a positive integer");
    return Reflect.set(obj, key, value);
  },
});

const config = strictConfig({ baseURL: "http://localhost:3000", timeout: 5000 });
console.log(config.timeout);
try { config.timout; } catch (e) { console.log(e.message); }              // typo caught at once
try { config.timeout = "5s"; } catch (e) { console.log(e.message); }

// Negative indexes for arrays
const last = arr => new Proxy(arr, { get: (a, k, r) => Reflect.get(a, typeof k === "string" && /^-\d+$/.test(k) ? a.length + Number(k) : k, r) });
console.log(last(["login", "search", "checkout"])[-1]);

// Count reads to find which settings are really used
const reads = new Map();
const watched = new Proxy({ a: 1, b: 2 }, { get(o, k) { reads.set(k, (reads.get(k) ?? 0) + 1); return o[k]; } });
watched.a; watched.a; watched.b;
console.log(Object.fromEntries(reads));
Output
5000
unknown config key "timout"
timeout must be a positive integer
checkout
{ a: 2, b: 1 }

The key idea is that the proxy and the target are two different objects. Code talks to the proxy, every operation is handed to a trap if there is one, and the trap decides whether to pass it on to the real object with Reflect.

Test frameworks use proxies for auto mocking, for fluent APIs and for wrapping page objects. Here a Proxy adds step logging and one retry on a known flaky error to every method, without touching the page class.

A Proxy that logs and retries page object steps · ▶ Runs
// Wrap every page object method: log the step and its time, and retry once on a known flaky error
function instrument(page, { log = console.log } = {}) {
  return new Proxy(page, {
    get(target, key, receiver) {
      const value = Reflect.get(target, key, receiver);
      if (typeof value !== "function") return value;
      return async (...args) => {
        const label = `${target.constructor.name}.${String(key)}(${args.map(a => JSON.stringify(a)).join(", ")})`;
        for (let attempt = 1; ; attempt++) {
          try {
            const result = await value.apply(receiver, args);
            log(`✔ ${label}${attempt > 1 ? ` after ${attempt} tries` : ""}`);
            return result;
          } catch (e) {
            if (attempt === 2 || !/detached|stale/i.test(e.message)) { log(`✖ ${label}: ${e.message}`); throw e; }
          }
        }
      };
    },
  });
}

class SearchPage {
  clicks = 0;
  async search(term) { if (++this.clicks === 1) throw new Error("element is detached from the DOM"); return `${term}: 3 results`; }
  async openResult(n) { if (n > 3) throw new Error(`result ${n} not found`); return `opened ${n}`; }
}
const page = instrument(new SearchPage());
console.log(await page.search("pen"));
await page.openResult(9).catch(() => {});
Output
✔ SearchPage.search("pen") after 2 tries
pen: 3 results
✖ SearchPage.openResult(9): result 9 not found
Proxies add a cost to every operation and can surprise people reading the code. Use them in tools and test frameworks, not in hot paths of application code.

🏷️Tagged template literals

🧪 QA essentialKnowing how query tags keep values apart from SQL text explains why injection tests pass or fail.

A tag is a function placed before a template literal. It receives the fixed text pieces and the values separately, so it can escape values, build safe queries or change the text. Libraries such as lit-html, styled-components and the gql tag for GraphQL are built on this.

Tagged templates: safe HTML and SQL · ▶ Runs
// A tag function receives the fixed strings and the values separately
function html(strings, ...values) {
  const escape = v => String(v).replace(/[&<>"']/g, c => ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" })[c]);
  return strings.reduce((out, s, i) => out + s + (i < values.length ? escape(values[i]) : ""), "");
}
const review = '<img src=x onerror="alert(1)">';
console.log(html`<p class="review">${review}</p>`);

// A SQL tag that never builds text from values, which prevents SQL injection
function sql(strings, ...values) {
  return { text: strings.reduce((q, s, i) => q + `$${i}` + s), values };
}
const email = "x' OR '1'='1";
console.log(sql`SELECT * FROM users WHERE email = ${email} AND active = ${true}`);

// String.raw keeps backslashes, handy for regexes and Windows paths
console.log(String.raw`C:\tests\new`, "|", `C:\tests\new`.length, String.raw`C:\tests\new`.length);

// A dedent tag for readable multi line test data
const dedent = (s, ...v) => String.raw(s, ...v).replace(/^\n/, "").replace(new RegExp(`^${String.raw(s, ...v).match(/^\n?( *)/)[1]}`, "gm"), "");
console.log(dedent`
    Feature: Login
      Scenario: wrong password
        Then I see "Try again"`);
Output
<p class="review">&lt;img src=x onerror=&quot;alert(1)&quot;&gt;</p>
{
  text: 'SELECT * FROM users WHERE email = $1 AND active = $2',
  values: [ "x' OR '1'='1", true ]
}

    Then I see "Try again"

🎀Decorators

A decorator is a function written as @name before a class, method, field or accessor. It receives the original and can replace or wrap it. Test frameworks use decorators for steps, retries, timeouts and dependency injection.

Decorators wrap methods and classes · Runs in chapter 25 with TypeScript
// Decorators are a TC39 proposal (listed at stage 2.7 in October 2026). TypeScript 5 and later supports them today (chapter 25),
// and Babel can compile them for JavaScript.
class CheckoutPage {
  @step("Pay with card")          // log the step in the report
  @retry(2)                       // retry the method on a flaky error
  async pay(card) { /* ... */ }
}

function step(title) {
  return function (method, context) {
    return async function (...args) {
      console.log(`step: ${title}`);
      return method.apply(this, args);
    };
  };
}

🎬Real world scenario: a fluent API client

🧪 QA essential
The situationThe API test suite calls dozens of endpoints. Writing a function for each one is slow, and URL strings built by hand are full of typos.
A dynamic API client with a Proxy · ▶ Runs
// A fluent API client built from a Proxy: api.users[7].orders.get() calls GET /users/7/orders
function client(baseURL, fetchFn) {
  const make = path => new Proxy(() => {}, {
    get(_, key) {
      if (["get", "post", "put", "delete"].includes(key))
        return (body) => fetchFn(key.toUpperCase(), `${baseURL}${path}`, body);
      return make(`${path}/${String(key)}`);
    },
  });
  return make("");
}

// A fake fetch so the example runs anywhere
const calls = [];
const fakeFetch = async (method, url, body) => { calls.push(`${method} ${url}${body ? " " + JSON.stringify(body) : ""}`); return { status: method === "POST" ? 201 : 200 }; };

const api = client("https://api.shop.test/v1", fakeFetch);
await api.users[7].orders.get();
await api.products.post({ name: "Pen", price: 40 });
await api.carts["c-19"].items.PEN.delete();
console.log(calls);
Output
[
  'GET https://api.shop.test/v1/users/7/orders',
  'POST https://api.shop.test/v1/products {"name":"Pen","price":40}',
  'DELETE https://api.shop.test/v1/carts/c-19/items/PEN'
]

Each property read adds a part to the path, and the verb at the end sends the request. The same trick is used by real clients for large APIs. Pair it with TypeScript types (chapter 24) so the editor suggests only valid paths.
