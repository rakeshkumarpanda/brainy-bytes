Part 2

🔒TypeScript 5.0: const type parameters

Before 5.0, a generic function that should keep exact strings needed callers to write as const. A const type parameter does it for every caller. 5.0 also introduced standard decorators, covered in the projects chapter.

const type parameters (5.0) · 🔷 tsc finds 1 error, then Node.js runs it
📄 src/main.ts
// TypeScript 5.0: a const type parameter infers literal types without "as const" at every call
function roles<const T extends readonly string[]>(list: T): T { return list; }
function rolesOld<T extends readonly string[]>(list: T): T { return list; }

const exact = roles(["admin", "qa", "viewer"]);     // readonly ["admin", "qa", "viewer"]
const loose = rolesOld(["admin", "qa", "viewer"]);  // string[]

type Role = (typeof exact)[number];                 // "admin" | "qa" | "viewer"
const me: Role = "qa";
console.log(exact, loose, me);

const typo: Role = "qaa";                           // caught, because the literals were kept

$ npx tsc
$ node src/main.ts
Terminal output

Part 3

🧹TypeScript 5.2 and 5.3: using and import attributes

🧪 QA essentialBrowsers, pages and connections that are always closed, even when an assertion fails, stop leaks that slow down whole test runs.

using is explicit resource management from a JavaScript proposal that TypeScript supports since 5.2 and Node.js runs natively. When the block ends, normally or by an error, the object's [Symbol.dispose]() runs. For test code that opens browsers, database connections or temp folders, this replaces fragile try and finally blocks.

using and await using: cleanup that cannot be forgotten (5.2) · 🔷 tsc passes, then Node.js runs it
📄 src/main.ts
// TypeScript 5.2 and Node.js: using calls [Symbol.dispose]() when the block ends, even after an error
function openDb(name: string) {
  console.log(`open ${name}`);
  return { name, query: (sql: string) => `${name}: ${sql}`, [Symbol.dispose]() { console.log(`close ${name}`); } };
}

async function startBrowser() {
  console.log("browser started");
  return { title: async () => "Shop", async [Symbol.asyncDispose]() { console.log("browser closed"); } };
}

function report() {
  using main = openDb("orders");
  using audit = openDb("audit");
  console.log(main.query("SELECT 1"));
  throw new Error("assertion failed");               // both connections still close, newest first
}

try { report(); } catch (e) { console.log("test failed:", (e as Error).message); }

{
  await using browser = await startBrowser();       // await using waits for an async cleanup
  console.log("title:", await browser.title());
}
console.log("done");

$ npx tsc && node src/main.ts
Terminal output

TypeScript 5.3 added import attributes. with { type: "json" } tells the runtime the file is JSON, which Node requires for JSON imports, and TypeScript infers the type of the data from the file.

Import attributes for JSON test data (5.3) · 🔷 tsc finds 1 error
📄 src/main.ts
// TypeScript 5.3: import attributes tell the runtime what kind of file it is loading
import users from "./users.json" with { type: "json" };

const admins = users.filter((u) => u.role === "admin");   // the JSON's shape is inferred
console.log(admins.map((u) => u.name));
console.log(users[0]?.email.toUpperCase());

console.log(users[0]?.phone);                             // no such field in the file

🎯TypeScript 5.4 and 5.5: smarter inference

🧪 QA essentialFiltering test data and writing locator or log patterns are daily work. These checks catch the mistakes early.

NoInfer<T> marks an argument that must match T but must not help decide what T is. Without it, a wrong default such as "safari" would simply widen T to include it. 5.4 also keeps narrowing inside callbacks created after the last change to a variable.

NoInfer and narrowing in closures (5.4) · 🔷 tsc finds 1 error, then Node.js runs it
📄 src/main.ts
// TypeScript 5.4: NoInfer<T> stops one argument from deciding what T is
function pickBrowser<T extends string>(supported: T[], fallback: NoInfer<T>): T {
  const wanted = process.env.BROWSER as T | undefined;
  return wanted && supported.includes(wanted) ? wanted : fallback;
}
console.log(pickBrowser(["chromium", "firefox", "webkit"], "chromium"));

// Narrowing now survives inside callbacks created after the last assignment
function label(id: string | number) {
  if (typeof id === "number") id = `#${id}`;
  return ["a", "b"].map((s) => `${s}-${id.toUpperCase()}`);   // id is known to be a string here
}
console.log(label(7));

pickBrowser(["chromium", "firefox"], "safari");     // without NoInfer, T would quietly widen to include "safari"

$ node src/main.ts

TypeScript 5.5 infers type predicates: rows.filter(r => r != null) finally gives an array without null. It also checks regular expression literals, so typos in patterns are found before a test runs.

Inferred type predicates (5.5) · 🔷 tsc passes, then Node.js runs it
📄 src/main.ts
// TypeScript 5.5: filter with a simple check now narrows the array type by itself
const rows = [{ id: 1, total: 450 }, null, { id: 2, total: 99 }, undefined];

const present = rows.filter((r) => r != null);      // { id: number; total: number }[]
console.log(present.map((r) => r.total));           // no "possibly null" error any more

// The inferred function is a real type predicate you can reuse
const isBig = (r: { total: number } | null) => r !== null && r.total > 100;
const isRow = (r: { id: number; total: number } | null | undefined) => r != null;
const checked = rows.filter(isRow);
console.log(checked.length, isBig(rows[0] ?? null));

Part 5

🚨TypeScript 5.6 to 5.9: fewer silent mistakes

5.6 reports conditions that can never be false, such as a function used without calling it. This is a classic bug in test helpers: if (isLoggedIn) is always true. 5.6 also typed the iterator helper methods such as filter, map and toArray on iterators.

Always truthy checks and iterator helpers (5.6) · 🔷 tsc finds 2 errors, then Node.js runs it
📄 src/main.ts
// TypeScript 5.6: conditions that are always true or always false are errors
function isLoggedIn(): boolean { return true; }

if (isLoggedIn()) console.log("called: fine");
if (isLoggedIn) console.log("forgot the ()");        // a function is always truthy

const role = "customer";
if (/admin/) console.log("forgot .test(role), so this always runs for " + role);   // a regex literal is always truthy

// TypeScript 5.6 also types the iterator helper methods that Node.js supports
const fast = [120, 455, 80, 999, 300].values().filter((ms) => ms < 400).map((ms) => `${ms} ms`).toArray();
console.log(fast);

src/main.ts(8,5): error TS2872: This kind of expression is always truthy.

5.7 reports variables that are never assigned anywhere, even when they are used inside a function, where older versions stayed quiet. 5.8 added erasableSyntaxOnly for running .ts files directly, and 5.9 added import defer, which loads a module but runs it only when first used.

Variables that are never initialised (5.7) · 🔷 tsc finds 1 error, then Node.js runs it
📄 src/main.ts
// TypeScript 5.7: a variable that is never assigned anywhere is now reported inside functions too
let total: number;
function report() { return total.toFixed(2); }       // before 5.7 this compiled, because it is inside a function

let baseURL: string;
function url(path: string) { return baseURL + path; }   // fine: baseURL is assigned below before use
baseURL = "http://localhost:3000";
console.log(url("/health"));

try { console.log(report()); } catch (e) { console.log("crashed:", (e as Error).message); }

Part 6

🌉TypeScript 6.0: the bridge release

🧪 QA essentialTemporal ends date bugs in test data, and RegExp.escape makes locators built from user text safe.

TypeScript 6.0 (March 2026) is the last version of the compiler written in JavaScript. It changes the defaults of a new project to strict: true, module: "esnext" and target: "es2025", and adds types for runtime features that Node.js and browsers already ship.

Map.getOrInsert, RegExp.escape and Temporal (6.0) · 🔷 tsc passes, then Node.js runs it
📄 src/main.ts
// TypeScript 6.0: types for ES2025 and newer runtime features that Node.js already has
const hits = new Map<string, number>();
for (const word of ["pass", "fail", "pass", "pass"]) {
  hits.set(word, hits.getOrInsert(word, 0) + 1);    // Map.getOrInsert (the "upsert" proposal)
}
console.log(hits);

const userInput = "price (in $)?";
const safe = new RegExp(RegExp.escape(userInput));  // escape text before putting it in a regex
console.log(safe.test("What is the price (in $)?"));

// The Temporal date and time API (esnext.temporal types)
const release = Temporal.PlainDate.from("2026-03-23");
const nextCheck = release.add({ months: 6 });
console.log(release.toString(), "->", nextCheck.toString(), release.until(nextCheck).total({ unit: "days" }), "days");

Terminal output

true

6.0 also deprecates options that TypeScript 7 removes: target: "es5", downlevelIteration, moduleResolution node10 and classic, the amd, umd and systemjs module formats, baseUrl, outFile, and the old module Foo {} namespace syntax. "ignoreDeprecations": "6.0" silences the warnings while a project migrates.

🚀TypeScript 7.0: the native compiler

TypeScript 7.0 is the compiler ported to Go. The language is the same, but builds are typically 8 to 12 times faster, and the VS Code code base went from 125.7 seconds to 10.6 seconds. Checking can run on several CPU cores.

TypeScript 7.0, the native compiler · 🧪 Tests run
📄 src/b.ts
import { a } from "./a.ts";
export const b: string = a;
Terminal

npx tsc -p . --target es5

New in 7.0Use
--checkers Nsplit type checking across N workers
--builders Nbuild N referenced projects at the same time
--singleThreadedturn parallelism off, for debugging or small CI machines
Tools that call the compiler from JavaScript, such as some lint rules and code generators, have no stable API in 7.0 yet. The @typescript/typescript6 package keeps the 6.0 compiler available as tsc6 until 7.1.
