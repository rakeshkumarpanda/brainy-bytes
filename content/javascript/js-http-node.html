Part 1

📨How HTTP works

🧪 QA essentialEvery API test checks a method, a status code, headers and a body.

Browsers, apps and test tools talk to servers with HTTP. The client sends a request: a method, a path, headers and sometimes a body. The server sends back a response: a status code, headers and usually a body. Both are plain text you can read.

What a request and a response really look like · ▶ Runs
import http from "node:http";
import net from "node:net";

// A tiny server, so we can see a real request and response
const server = http.createServer((req, res) => {
  const body = JSON.stringify({ id: 7, name: "Gel pen" });
  res.writeHead(201, { "Content-Type": "application/json", "Content-Length": body.length, "X-Request-Id": "abc-123" });
  res.end(body);
});
await new Promise(r => server.listen(0, "127.0.0.1", r));
const { port } = server.address();

// Send a request by hand over a raw socket and print the exact text that comes back
const socket = net.connect(port, "127.0.0.1");
socket.write(
  "POST /api/products HTTP/1.1\r\n" +
  `Host: 127.0.0.1:${port}\r\n` +
  "Content-Type: application/json\r\n" +
  "Content-Length: 18\r\n" +
  "Connection: close\r\n\r\n" +
  '{"name":"Gel pen"}'
);
let text = "";
for await (const chunk of socket) text += chunk;
console.log(text.replaceAll("\r\n", "\n"));
server.close();

📡fetch and URLs

🧪 QA essentialPlaywrightJestCypressAPI tests send requests and read responses with fetch or a wrapper around it, such as Playwright request or Cypress cy.request.

fetch(url, options) sends a request and returns a promise for the response. It is built into browsers and Node.js. Read the body once with res.json(), res.text() or res.blob().

fetch: GET, POST and errors · ▶ Runs
import http from "node:http";

// A small fake API to talk to
const products = [{ id: 1, name: "Gel pen", price: 20 }];
const server = http.createServer(async (req, res) => {
  const send = (status, body) => {
    res.writeHead(status, { "Content-Type": "application/json" });
    res.end(JSON.stringify(body));
  };
  if (req.method === "GET" && req.url === "/api/products") return send(200, products);
  if (req.method === "POST" && req.url === "/api/products") {
    let raw = "";
    for await (const chunk of req) raw += chunk;
    const item = { id: products.length + 1, ...JSON.parse(raw) };
    products.push(item);
    return send(201, item);
  }
  send(404, { error: "Not found" });
});
await new Promise(r => server.listen(0, r));
const base = `http://localhost:${server.address().port}`;

// GET and read JSON
const res = await fetch(`${base}/api/products`);
console.log(res.status, res.ok, res.headers.get("content-type"));
console.log(await res.json());

// POST with a JSON body
const created = await fetch(`${base}/api/products`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ name: "Coffee mug", price: 199 }),
});
console.log(created.status, await created.json());

// fetch does NOT reject on 404 or 500. Only network failures reject.
const missing = await fetch(`${base}/api/nothing`);
console.log(missing.status, missing.ok, await missing.json());

server.close();

// Only a missing response rejects, for example when nothing listens on the port
const gone = http.createServer();
await new Promise(r => gone.listen(0, r));
const deadUrl = `http://localhost:${gone.address().port}/`;
await new Promise(r => gone.close(r));
try {
  await fetch(deadUrl);
} catch (e) {
  console.log("rejected:", e.name, e.message, e.cause?.code);
}
Output
200 true application/json
[ { id: 1, name: 'Gel pen', price: 20 } ]
201 { id: 2, name: 'Coffee mug', price: 199 }
404 false { error: 'Not found' }
rejected: TypeError fetch failed ECONNREFUSED
fetch only rejects when there is no response at all: a refused connection, a DNS error or an abort. A 404 or 500 still fulfils, so always check res.ok or res.status.

🔑Authentication: 401 against 403

🧪 QA essentialAuthorisation bugs are among the most serious and the easiest to test at the API level.

Most APIs need you to prove who you are. A common pattern: log in once, receive a token, then send it on every request in the Authorization: Bearer ... header. Browsers usually keep the session in a cookie instead.

Logging in and sending a Bearer token · ▶ Runs
import http from "node:http";

const USERS = { "asha@shop.example": { password: "s3cret", role: "customer" }, "admin@shop.example": { password: "adm1n", role: "admin" } };
const tokens = new Map();

const server = http.createServer(async (req, res) => {
  const send = (status, body) => { res.writeHead(status, { "Content-Type": "application/json" }); res.end(JSON.stringify(body)); };
  if (req.url === "/login" && req.method === "POST") {
    let raw = ""; for await (const c of req) raw += c;
    const { email, password } = JSON.parse(raw);
    if (USERS[email]?.password !== password) return send(401, { error: "Invalid credentials" });
    const token = "tok_" + tokens.size;
    tokens.set(token, { email, role: USERS[email].role });
    return send(200, { token });
  }
  const user = tokens.get(req.headers.authorization?.replace(/^Bearer /, ""));
  if (!user) return send(401, { error: "Log in first" });                 // who are you?
  if (req.url === "/admin/reports" && user.role !== "admin") return send(403, { error: "Admins only" });  // not allowed
  send(200, { ok: true, user: user.email });
});
await new Promise(r => server.listen(0, r));
const base = `http://localhost:${server.address().port}`;

async function login(email, password) {
  const res = await fetch(`${base}/login`, { method: "POST", body: JSON.stringify({ email, password }) });
  return (await res.json()).token;
}
const get = (path, token) => fetch(base + path, { headers: token ? { Authorization: `Bearer ${token}` } : {} }).then(r => r.status);

const customer = await login("asha@shop.example", "s3cret");
const admin = await login("admin@shop.example", "adm1n");
console.log("wrong password:", await fetch(`${base}/login`, { method: "POST", body: '{"email":"asha@shop.example","password":"x"}' }).then(r => r.status));
console.log("no token:      ", await get("/orders"));
console.log("customer:      ", await get("/orders", customer), await get("/admin/reports", customer));
console.log("admin:         ", await get("/orders", admin), await get("/admin/reports", admin));
server.close();
Output
wrong password: 401
no token:       401
customer:       200 403
admin:          200 200
401 UnauthorizedThe server does not know who you are: no token, a wrong one or an expired one. Log in again.
403 ForbiddenThe server knows exactly who you are, and you are not allowed to do this. Logging in again will not help.
Every protected endpoint deserves at least four tests: no token (401), a broken or expired token (401), a valid token without permission (403) and a valid token with permission (2xx). Checking that a customer cannot read another customer's order by changing an id is one of the most valuable security tests you can write.

🖥️Writing a server with Express

🧪 QA essentialsupertestAPI test suites start a server like this one, and chapter 20 tests this exact app with supertest.

On the server side, Node.js answers requests. Express is the most used library for it: you declare routes (a method plus a path) and a handler that receives the request and builds the response. Middleware runs before the routes, for example to parse JSON or check a token.

A REST API with Express · ▶ Runs
import express from "express";

const app = express();
app.use(express.json());                         // parse JSON bodies

const db = new Map([[1, { id: 1, name: "Gel pen", price: 20 }]]);
let nextId = 2;

app.get("/api/products", (req, res) => {
  const max = Number(req.query.maxPrice ?? Infinity);
  res.json([...db.values()].filter(p => p.price <= max));
});
app.get("/api/products/:id", (req, res) => {
  const p = db.get(Number(req.params.id));
  p ? res.json(p) : res.status(404).json({ error: "Product not found" });
});
app.post("/api/products", (req, res) => {
  const { name, price } = req.body ?? {};
  if (!name || !(price > 0)) return res.status(400).json({ error: "name and a positive price are required" });
  const p = { id: nextId++, name, price };
  db.set(p.id, p);
  res.status(201).location(`/api/products/${p.id}`).json(p);
});
app.delete("/api/products/:id", (req, res) => {
  db.delete(Number(req.params.id)) ? res.status(204).end() : res.status(404).json({ error: "Product not found" });
});

const server = app.listen(0);
await new Promise(r => server.once("listening", r));
const base = `http://localhost:${server.address().port}/api/products`;
const call = async (method, path = "", body) => {
  const res = await fetch(base + path, { method, headers: { "Content-Type": "application/json" }, body: body && JSON.stringify(body) });
  const text = await res.text();
  console.log(method.padEnd(6), ("/api/products" + path).padEnd(28), res.status, text);
};

await call("GET");
await call("POST", "", { name: "Coffee mug", price: 199 });
await call("POST", "", { name: "Free thing", price: 0 });
await call("GET", "?maxPrice=100");
await call("GET", "/2");
await call("DELETE", "/2");
await call("GET", "/2");
server.close();
Output
GET    /api/products                200 [{"id":1,"name":"Gel pen","price":20}]
POST   /api/products                201 {"id":2,"name":"Coffee mug","price":199}
POST   /api/products                400 {"error":"name and a positive price are required"}
GET    /api/products?maxPrice=100   200 [{"id":1,"name":"Gel pen","price":20}]
GET    /api/products/2              200 {"id":2,"name":"Coffee mug","price":199}
DELETE /api/products/2              204 
GET    /api/products/2              404 {"error":"Product not found"}
Return the right status code and a helpful error body. Clients and tests rely on 201 with a Location header for created items, 204 with no body for deletes, 400 for bad input and 404 for missing items.
Knowing how routes and status codes are written makes API bugs easier to explain: "POST with price 0 returns 400, as it should, but PUT with price 0 returns 200 and saves it" points straight at the missing check.

🧰Node.js core modules

🧪 QA essentialData driven tests read CSV and JSON files, and custom reports are written with fs and path.

Node.js comes with modules for files, paths, processes and more. Test suites use them to read test data, write reports and run other tools.

Files, folders and paths in Node.js · ▶ Runs
import { readFile, writeFile, mkdir, readdir } from "node:fs/promises";
import path from "node:path";
import os from "node:os";

// Test data in a CSV file
await writeFile("users.csv", "email,role,active\nasha@shop.example,admin,true\nravi@shop.example,customer,false\n");

const [header, ...lines] = (await readFile("users.csv", "utf8")).trim().split("\n");
const keys = header.split(",");
const users = lines.map(l => Object.fromEntries(l.split(",").map((v, i) => [keys[i], v])));
console.log(users);

// Write a JSON report into a folder, creating it if needed
const outDir = path.join("reports", "2026-10-20");
await mkdir(outDir, { recursive: true });
const file = path.join(outDir, "summary.json");
await writeFile(file, JSON.stringify({ total: users.length, active: users.filter(u => u.active === "true").length }, null, 2));
console.log(file, "->", await readFile(file, "utf8"));
console.log(await readdir("reports", { recursive: true }));

console.log(path.extname(file), path.basename(file, ".json"), typeof os.cpus().length);
console.log(process.argv.length >= 2, process.platform.length > 0);

🎬Real world scenario: a mock API for UI tests

🧪 QA essentialPlaywrightCypress
The situationThe real backend is shared, slow and its data changes all the time, so UI tests fail for reasons that have nothing to do with the UI. You need an API that each test can reset, fill with data, slow down and make fail on purpose.
A controllable mock API for UI tests · ▶ Runs
import express from "express";

// A mock API that UI tests can start in a second, with data each test controls
export function createMockApi() {
  const app = express();
  app.use(express.json());
  let state = { products: [], failNext: null, delayMs: 0 };

  app.use(async (req, res, next) => {                       // slow network, on demand
    if (state.delayMs) await new Promise(r => setTimeout(r, state.delayMs));
    next();
  });
  app.post("/__test/reset", (req, res) => { state = { products: [], failNext: null, delayMs: 0, ...req.body }; res.sendStatus(204); });
  app.post("/__test/fail-next", (req, res) => { state.failNext = req.body.status; res.sendStatus(204); });
  app.get("/health", (req, res) => res.json({ status: "up" }));
  app.get("/api/products", (req, res) => {
    if (state.failNext) { const s = state.failNext; state.failNext = null; return res.status(s).json({ error: "Injected failure" }); }
    res.json(state.products);
  });
  return app;
}

const server = createMockApi().listen(0);
await new Promise(r => server.once("listening", r));
const base = `http://localhost:${server.address().port}`;
const post = (p, body) => fetch(base + p, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(body) });
const show = async label => { const r = await fetch(`${base}/api/products`); console.log(label.padEnd(24), r.status, await r.text()); };

console.log("health:", await (await fetch(`${base}/health`)).json());
await show("empty catalogue:");
await post("/__test/reset", { products: [{ id: 1, name: "Gel pen" }] });
await show("one product:");
await post("/__test/fail-next", { status: 503 });
await show("server error injected:");
await show("next call recovers:");

await post("/__test/reset", { delayMs: 300 });
const t = performance.now();
await show("slow network:");
console.log("took about", Math.round((performance.now() - t) / 100) * 100, "ms");
server.close();
Output
health: { status: 'up' }
empty catalogue:         200 []
one product:             200 [{"id":1,"name":"Gel pen"}]
server error injected:   503 {"error":"Injected failure"}
next call recovers:      200 [{"id":1,"name":"Gel pen"}]
slow network:            200 []
took about 300 ms

The /__test routes exist only in the mock. A test resets the state, sets up exactly the products it needs and can inject a 503 to check that the page shows a friendly error and a retry button. A delay shows whether loading spinners appear.

Playwright can do the same without a server by intercepting requests with page.route(), and Cypress with cy.intercept(). A mock server is still useful when mobile apps or several services need the same fake.
