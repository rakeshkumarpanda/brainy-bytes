Load the data and look before you touch it

Source: McKinney, Python for Data Analysis chapters 6 to 8 and 10, the pandas 3.0 user guide, the scikit-learn 1.8 imputation guide, Little and Rubin, Statistical Analysis with Missing Data chapter 1, and Tukey, Exploratory Data Analysis.

What it is
Data cleaning means finding and fixing the problems in raw data: missing values, repeated rows, wrong types, messy text, impossible numbers and outliers. It starts with inspecting the data: its size, column types, missing counts and unusual values.
Why we need it
A model learns whatever the data says, including its mistakes. "Garbage in, garbage out" is the first rule of machine learning. In real projects, cleaning and preparing data often takes more time than training the model.
How it works
Load the file with pandas, then ask a fixed list of questions: how many rows and columns (shape), what type each column has (dtypes), how many values are missing (isna().sum()), are there repeated rows (duplicated()), and what values does each text column hold (unique()). Write down every problem before fixing anything.

Lesson 2 of 11

Missing values: drop or fill

What it is
A missing value is a hole in the table, shown by pandas as NaN (or None, or NaT for dates). You can drop rows or columns with holes, or impute (fill) them with a sensible value such as the mean, the median or the most common value.
Why we need it
Most scikit-learn models refuse to train on NaN. Dropping is simple but throws away good information in the other columns: in the program below, dropping keeps only 3 of 6 rows. Filling keeps every row.
How it works
For numbers use the median (safe with outliers) or the mean. For categories use the mode. Add a 0 or 1 column that says "this value was missing", because missingness itself can carry information. Compute the fill value on the training rows only, then use that same value for the test rows.

Common mistake
Fitting the imputer on the whole dataset before splitting lets test rows influence the fill value. That is data leakage (Foundations 1.2). Put the imputer inside a Pipeline so it is fitted on the training part only.

Fix types, text, dates and duplicates

What it is
Raw columns often have the wrong type (numbers stored as text), messy text (extra spaces, mixed case, different names for the same thing), dates stored as plain strings, and duplicate rows.
Why we need it
A model sees "Delhi", " delhi" and "DELHI" as three different cities, and a price stored as text cannot be averaged at all. Duplicate rows count some examples twice and can leak the same row into both the training and the test set.
How it works
Use the .str methods to strip spaces and fix case, replace to merge synonyms ("Bombay" into "mumbai"), pd.to_numeric and pd.to_datetime with errors="coerce" to turn bad values into NaN instead of crashing, and drop_duplicates to remove repeated rows.

Lesson 4 of 11

Outliers: find them, then decide

What it is
An outlier is a value far away from the rest. The IQR rule flags values below Q1 − 1.5 IQR or above Q3 + 1.5 IQR, where the IQR is the width of the middle half of the data. The z score rule flags values more than 3 standard deviations from the mean.
Why we need it
Outliers can be mistakes (a 2,000 m2 flat) that pull a linear model badly off course, or real rare events (fraud, a machine about to fail) that are exactly what you want to find. Either way you must know they are there.
How it works
Compute the quartiles, the IQR and the fences, and list the values outside them. Then look at each one. Fix or remove clear mistakes. For real but extreme values, keep them, clip them to the fences (winsorising), use a log transform, or use a robust model such as a tree.
Download this program (.py)Save it, open it in any editor and run it with python3 find_outliers.py.
In the exam
The z score rule missed the 150 in the program: z = 2.97, just under 3. The outlier itself raised the mean and the standard deviation, which hid it. This is called masking. The IQR rule uses quartiles, which one extreme value cannot move, so it is more robust.
IQR fencesExam favourite
low = Q1 − 1.5 × IQR, high = Q3 + 1.5 × IQR, IQR = Q3 − Q1
Tukey’s box plot rule. Use 3 instead of 1.5 for far outliers.
z scoreExam favourite
z = (x − mean) / std
Flag |z| > 3. Easily fooled by the outliers themselves.
Robust z score
z = 0.6745 (x − median) / MAD
MAD is the median of |x − median|. Flag |z| > 3.5.

Combine and reshape tables

What it is
Data often lives in several tables. merge joins two tables on a shared key, like SQL JOIN. melt turns wide tables (one column per subject) into long tables (one row per student and subject), and pivot turns them back.
Why we need it
A model needs one row per example with all its features. Customer details and their orders are in different tables, so you join them. Many plotting and grouping tools want long data, while models want wide data, so you reshape.
How it works
Pick the key column and the join type. An inner join keeps only keys found in both tables. A left join keeps every row of the left table and fills NaN where the right table has no match. After a merge, always check the row count, because a key that repeats multiplies rows.

Lesson 7 of 11

A cleaning function you can trust

What it is
Put all the cleaning steps into one function that takes raw data and returns clean data, and finish it with checks (assert statements) that fail loudly if something is still wrong.
Why we need it
New data arrives every week. If the cleaning lives in scattered notebook cells, someone will forget a step and the model will quietly get worse. A function gives the same result every time, and checks catch new kinds of mess the moment they appear.
How it works
Write the steps in a fixed order: drop duplicates, fix text, fix types, mark impossible values as missing, fill holes, set final types. Then assert the rules your data must follow: ids are unique, nothing is missing, values sit in sensible ranges.
Download this program (.py)Save it, open it in any editor and run it with python3 clean_function.py.
The cleaning checklist
  1. Inspect: shape, dtypes, isna().sum(), duplicated().sum(), unique values of text columns, describe().
  2. Remove exact duplicates, then fix text (strip, case, synonyms).
  3. Convert types with errors="coerce" and count the new NaN values.
  4. Mark impossible values (negative ages, 2,000 m2 flats) as NaN.
  5. Fill or drop the holes, with fill values learned from training data only.
  6. Validate with asserts, then save the clean data and the code that made it.

The maths, all in one place

Quantile position (pandas linear method)Exam favourite
position = (n − 1) × q, then interpolate between the two nearest sorted values
Q1 is q = 0.25, the median q = 0.5, Q3 q = 0.75.
IQR fencesExam favourite
Q1 − 1.5 IQR and Q3 + 1.5 IQR
Values outside are outliers.
Mean after mean fillingExam favourite
mean stays the same, variance shrinks by the factor (nknown − 1)/(n − 1) or so
Every filled value sits exactly at the mean, adding no spread.
z score
z = (x − x̄) / s
Distance from the mean in standard deviations.
Worked example: quartiles and fences by hand
  1. Sorted values: 32, 35, 36, 38, 40, 41, 43, 45, 47, 150 (n = 10).
  2. Q1 position = 9 × 0.25 = 2.25, so Q1 = 36 + 0.25 × (38 − 36) = 36.5.
  3. Q3 position = 9 × 0.75 = 6.75, so Q3 = 43 + 0.75 × (45 − 43) = 44.5.
  4. IQR = 8, fences = 36.5 − 12 = 24.5 and 44.5 + 12 = 56.5
  5. Only 150 is above 56.5, so it is the only outlier. This matches the program.
Going deeper: Why single imputation makes models too confident

Filling a hole with one value treats a guess as if it were measured, so the variance of the column and the standard errors of anything estimated from it come out too small. Multiple imputation (Rubin, 1987) fills each hole several times with random draws from a model, analyses each completed dataset, and combines the results so the uncertainty of the guesses is included. scikit-learn’s IterativeImputer with sample_posterior=True can produce such draws.

From beginner to expert

One idea, four depths

Real data has holes, repeats, typing mistakes and strange values. Look at the data first, then fix each problem, and check the result.

Inspect with shape, dtypes, isna and duplicated. Drop or fill missing values with mean, median or mode plus a missing flag, fix text and types with .str, to_numeric and to_datetime, find outliers with the IQR rule, and join tables with merge.

Know MCAR, MAR and MNAR, use KNN or iterative imputers and models that accept NaN, avoid leakage by fitting imputers inside a Pipeline, use robust outlier rules, and write a validated cleaning function.

Use multiple imputation for honest uncertainty, model the missingness mechanism, build data contracts and schema checks (for example with pandera or Great Expectations) into production pipelines, and monitor data quality over time (MLOps 1.3).

Beginner
Load a CSV, find missing values and duplicates, and fill holes with the median.
Intermediate
Clean text, types and dates, flag outliers with the IQR rule, and merge tables safely.
Expert
Pick an imputation method from the missingness mechanism and turn cleaning into a tested, validated pipeline.

Chapter summary

  1. Inspect first: shape, dtypes, isna().sum(), duplicated().sum(), unique values, describe().
  2. Missing values: drop, or fill with median (numbers) or mode (categories), and add a missing flag. Learn fill values on training data only.
  3. MCAR is pure chance, MAR depends on other columns, MNAR depends on the missing value itself.
  4. Fix text with .str.strip() and .str.lower(), merge synonyms with replace, convert with to_numeric and to_datetime (errors="coerce").
  5. Outliers: the IQR rule (Q1 − 1.5 IQR, Q3 + 1.5 IQR) is robust. z scores can be masked. Decide: fix, remove, clip, or keep.
  6. merge joins tables (inner, left, right, outer). Check row counts after every merge. melt and pivot reshape.
  7. KNN and iterative imputers use the other columns and usually beat a single fill value.
  8. Wrap cleaning in a function and finish with assert checks.
