Lesson 1 of 10

Why tables break, and learning a value function

Source: Sutton and Barto (2018) sections 9.1 to 9.4 and example 9.1.

What it is
Value function approximation replaces the table with a function v̂(s, w) that has far fewer weights than there are states. Learning means adjusting w so that v̂ matches the true values on the states the agent visits. Changing one weight changes the values of many states at once, which is called generalisation.
Why we need it
Backgammon has about 1020 states, Go about 10170, and a robot with continuous sensors has infinitely many. No table can hold them, and most states are never seen twice. A function that generalises lets experience in one state improve the estimate in similar states.
How it works
Pick features and a model, then use stochastic gradient descent on the squared error. Gradient Monte Carlo moves w towards the return Gt. Semi gradient TD(0) moves it towards r + γv̂(s′, w) and treats that target as a fixed number when taking the gradient, which is why it is only a semi gradient.

In the exam
With 10 groups of 100 states, 10 weights stand in for 1000 values. After 2000 episodes gradient Monte Carlo reaches a root mean squared error of 0.058, close to the best any staircase can do. Semi gradient TD reaches 0.11 because its target leans on the next group’s weight, which is itself only an average. Its steps near the two ends stay closer to 0.
Prediction objectiveExam favourite
VE(w) = Σs μ(s) [vπ(s) − v̂(s, w)]2
μ(s) is the share of time spent in s.
Gradient Monte CarloExam favourite
w ← w + α[Gt − v̂(St, w)] ∇v̂(St, w)
Unbiased target, converges to a local minimum of VE.
Semi gradient TD(0)Exam favourite
w ← w + α[R + γv̂(S′, w) − v̂(S, w)] ∇v̂(S, w)
The target also depends on w, but we ignore that in the gradient.

Linear features and tile coding

Source: Sutton and Barto (2018) sections 9.4, 9.5, 10.1 and example 10.1, and Albus, A new approach to manipulator control: the CMAC (1975).

What it is
A linear approximator computes v̂(s, w) = w · x(s), a weighted sum of features. Its gradient is simply the feature vector x(s). Tile coding covers the state space with several grids (tilings), each shifted a little. A state switches on one tile in each grid, and its value is the sum of those tiles’ weights.
Why we need it
Linear methods are fast, easy to analyse and, with on policy data, semi gradient TD is guaranteed to converge for them. Tile coding gives local generalisation: nearby states share most of their tiles, distant states share none. The shifts give fine resolution from coarse grids.
How it works
Scale each state variable, find the active tile in every tiling, and keep one weight per tile and action. Q(s, a) is the sum of the active weights. With n tilings use a step size of about α = 0.1/n to 0.5/n, so one update moves the value by about αn of the error.

By episodes 51 to 60 it needs about 149 steps on average. It has learned to rock back and forth to build up speed.

Lesson 3 of 10

Deep Q networks: replay memory and a target network

Source: Mnih and colleagues, Playing Atari with Deep Reinforcement Learning (2013) and Human-level control through deep reinforcement learning (Nature 2015).

What it is
A deep Q network (DQN) is Q learning with a neural network Q(s, a, θ) that outputs one value per action. Two ideas make it stable. Experience replay stores transitions in a large memory and trains on random minibatches. A target network is a frozen copy θ− of the weights, used only to compute targets and refreshed every C steps.
Why we need it
Naive Q learning with a network tends to oscillate or diverge. Consecutive steps are strongly correlated, which breaks the assumption behind stochastic gradient descent, and every update also moves the target it is chasing. Replay breaks the correlation and reuses each transition many times. The target network holds the target still for a while.
How it works
Act ε greedily and push (s, a, r, s′, done) into the memory. Each training step, sample a minibatch, compute y = r + γ maxa′ Q(s′, a′, θ−) (just r if done), and take a gradient step on (y − Q(s, a, θ))2, usually with the Huber loss. Copy θ into θ− every C steps.
Download this program (.py)Save it, open it in any editor and run it with python3 dqn_cartpole.py.
In the exam
This DQN is written in plain NumPy: 4 inputs, 32 hidden units and 2 outputs, Adam, a memory of 10,000 and a target copy every 100 steps. It balances the pole for about 11 to 23 steps on average in the first 75 episodes, then 58.6, 131.1 and 171.4 in later blocks of 25 episodes. Ten greedy test runs last 134 to 147 steps out of 200. Deep RL is sensitive to settings and seeds, so real work compares several seeds.
Real world scenario: The Atari result

The 2015 Nature DQN learned 49 Atari 2600 games from raw pixels and the score alone, with the same network and settings for every game. The input was the last 4 frames, shrunk to 84 by 84 grey pixels. It used a replay memory of 1,000,000 transitions, minibatches of 32, a target update every 10,000 steps, γ = 0.99, ε falling from 1 to 0.1 over the first million frames, and rewards clipped to −1, 0 or +1. It reached more than 75% of a professional human tester’s score on 29 of the 49 games.

DQN lossExam favourite
L(θ) = E(s, a, r, s′) ~ D[(r + γ maxa′ Q(s′, a′, θ−) − Q(s, a, θ))2]
D is the replay memory, θ− the target weights.
Huber loss
Lδ(e) = e2/2 if |e| ≤ 1, else |e| − 1/2
Same as clipping the error to [−1, 1] in the gradient.

Double DQN, dueling networks, prioritised replay and Rainbow

Source: van Hasselt, Guez and Silver (AAAI 2016), Wang and colleagues (ICML 2016), Schaul and colleagues (ICLR 2016), and Hessel and colleagues, Rainbow (AAAI 2018).

What it is
Many improvements followed DQN. Double DQN chooses the next action with the online network and evaluates it with the target network. A dueling network splits the output into a state value V(s) and advantages A(s, a). Prioritised replay samples surprising transitions, those with a large TD error, more often. Rainbow combines six such ideas.
Why we need it
DQN overestimates values because of the maximisation bias from chapter 2.3, and Double DQN fixes that at no extra cost. Dueling helps when many actions have similar values, because V is learned from every update. Prioritised replay spends updates where there is most to learn. Together they made learning on Atari much faster and stronger.
How it works
Double DQN: y = r + γQ(s′, argmaxa Q(s′, a, θ), θ−). Dueling: Q = V + A − mean of A. Prioritised replay: sample transition i with chance piα / Σ pkα with pi = |δi| + small constant, and correct the bias with importance weights (N P(i))−β.

Lesson 5 of 10

The deadly triad: when approximation diverges

Source: Baird, Residual algorithms (ICML 1995), Tsitsiklis and Van Roy (1997), Sutton and Barto (2018) sections 11.2 and 11.3, and Sutton and colleagues, Fast gradient descent methods for TD learning with linear function approximation (ICML 2009).

What it is
The deadly triad is the combination of function approximation, bootstrapping and off policy training. Any two of them are safe. All three together can make the weights grow without limit, even on a tiny problem whose true values are all 0.
Why we need it
DQN has all three: a network, a TD target and a replay memory of old, off policy data. Knowing the triad explains why target networks, replay and careful step sizes matter, and why research on stable off policy methods is still active.
How it works
Baird’s counterexample has 7 states, 8 weights and zero rewards. Semi gradient off policy TD makes the weights explode. Fixes: drop one leg of the triad (use Monte Carlo targets, on policy data or a table), slow the target down (target networks), or use true gradient methods such as gradient TD (GTD2, TDC) or emphatic TD.

In the exam
With linear features the size of the weight vector grows from 10.34 to 452.23 in 1000 steps, although every true value is 0. With a table (one value per state) and the same off policy data, it slowly shrinks, from 2.65 to 2.61. The problem is not off policy data alone, but all three parts of the triad together.
Importance ratioExam favourite
ρ = π(a|s) / b(a|s)
Reweights off policy samples. In Baird’s example ρ = 7 for solid and 0 for dashed.
Linear TD fixed point
wTD = A−1b, A = E[xt(xt − γxt+1)T], b = E[Rt+1xt]
Stable when A is positive definite, which holds on policy.
TD error bound
VE(wTD) ≤ VE(best w) / (1 − γ)

Worked example: one semi gradient TD update with linear features
  1. Features x(s) = [1, 2], x(s′) = [1, 1], weights w = [0.5, 1.0], reward 1, γ = 0.9, α = 0.1.
  2. v̂(s) = 0.5 + 2.0 = 2.5,   v̂(s′) = 0.5 + 1.0 = 1.5
  3. δ = 1 + 0.9 × 1.5 − 2.5 = −0.15
  4. w += 0.1 × (−0.15) × [1, 2] = [−0.015, −0.03]
  5. New weights [0.485, 0.97]. Both weights moved, so the values of every state that uses these features changed too. That is generalisation, and it is also why updates can interfere with each other.
Going deeper: Why semi gradient, and what a true gradient would need

The squared TD error (R + γv̂(S′, w) − v̂(S, w))2 depends on w through both terms. Semi gradient methods differentiate only the second term. They are faster and usually learn better, but they are not gradient descent on any objective, which is why they can diverge off policy. Differentiating both terms gives the residual gradient algorithm of Baird (1995), which is stable but slow and, with random transitions, converges to the wrong values unless two independent next states are sampled. Gradient TD methods such as GTD2 and TDC instead minimise the projected Bellman error with a second set of weights, and they converge off policy with linear features at the cost of extra parameters and a second step size.

Chapter summary

  1. Large or continuous state spaces need function approximation: v̂(s, w) with far fewer weights than states, which generalises to unseen states.
  2. Gradient Monte Carlo targets the return. Semi gradient TD targets r + γv̂(s′, w) and ignores the target’s dependence on w.
  3. Linear features such as tile coding are fast and stable on policy. Mountain car is solved with 1944 weights.
  4. DQN uses a neural network, experience replay and a target network. It learned 49 Atari games from pixels.
  5. Double DQN, dueling, prioritised replay, multi step returns, distributional RL and noisy nets combine into Rainbow.
  6. The deadly triad of approximation, bootstrapping and off policy data can diverge, as Baird’s counterexample shows.
