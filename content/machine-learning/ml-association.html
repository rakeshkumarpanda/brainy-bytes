Lesson 1 of 9

Items that go together: support, confidence and lift

Source: Agrawal, Imielinski and Swami (SIGMOD 1993), Brin, Motwani, Ullman and Tsur (SIGMOD 1997), and Tan, Steinbach and Kumar, Introduction to Data Mining chapter 5.

What it is
Association rule mining finds rules of the form "if a basket has A, it often also has B" in lists of transactions. Three numbers judge a rule: support (how often A and B appear together), confidence (how often B appears when A does) and lift (confidence compared with how common B is anyway).
Why we need it
Shops use rules for shelf layout, bundles and "frequently bought together" offers. The same idea finds symptoms that occur together, web pages visited in the same session, and features of software that are used together. It needs no labels.
How it works
Count baskets. support(A ⇒ B) = count(A and B) / n, confidence = support(A and B) / support(A), lift = confidence / support(B). Keep rules with enough support to matter, enough confidence to act on, and lift clearly above 1.

supp(A ⇒ B) = P(A ∩ B)
Share of baskets with both.
ConfidenceExam favourite
conf(A ⇒ B) = P(B | A) = supp(A ∩ B) / supp(A)
Not symmetric.
LiftExam favourite
lift = conf(A ⇒ B) / supp(B) = P(A ∩ B) / (P(A) P(B))
Symmetric. 1 means independent.

Apriori: finding frequent itemsets fast

Source: Agrawal and Srikant, Fast Algorithms for Mining Association Rules (VLDB 1994).

What it is
Rules come from frequent itemsets: sets of items that appear in at least a minimum share of baskets. Apriori finds them level by level. Its key fact, the Apriori property, is that every subset of a frequent itemset is also frequent, so a set with any infrequent subset can be skipped without counting.
Why we need it
With d items there are 2d − 1 possible itemsets, far too many to count for a shop with 10,000 products. The Apriori property cuts the search down to the few sets that could still be frequent.
How it works
Count single items and keep the frequent ones. Join frequent sets of size k into candidates of size k + 1, drop any candidate with an infrequent size k subset, count the rest, and repeat until no candidates remain. Then split each frequent itemset into rules and keep those with high confidence.

With a minimum of 3 baskets, 5 of the 6 items are frequent (biscuits is in only 2). The 5 frequent items give 10 candidate pairs, and 4 pairs survive. Lesson 3 of 9

From itemsets to a table of rules

What it is
Each frequent itemset can be split into a left side and a right side to make rules. Each rule then gets its support, confidence and lift, plus leverage (supp(A ∩ B) − supp(A) supp(B)) and conviction ((1 − supp(B)) / (1 − confidence)). Sorting the table by lift shows the strongest links.
Why we need it
A real shop produces thousands of rules, most of them obvious, rare or caused by chance. Filtering by support, confidence and lift, and reading the top of the table with domain knowledge, turns that into a few useful actions.
How it works
Put the transactions in a one hot table (one column per item), compute supports with column means, then confidence and lift for each candidate rule. In Python the mlxtend package offers apriori, fpgrowth and association_rules, but the core is just this counting, which runs here with pandas alone.

In the exam
The three habits built into the simulation come out on top: bread with butter (lift 1.97), tea with biscuits (1.82) and coffee with sugar (1.79). Each pair appears in both directions with the same lift but different confidence, because lift is symmetric and confidence is not. 38 of the 44 rules with support of at least 5% have lift below 1, so support alone is a poor filter.

FP-Growth, big data and pitfalls

Source: Han, Pei and Yin, Mining Frequent Patterns without Candidate Generation (SIGMOD 2000), and Leskovec, Rajaraman and Ullman, Mining of Massive Datasets chapter 6.

What it is
FP-Growth compresses all baskets into a prefix tree (the FP-tree) where shared beginnings of baskets share a path, then mines frequent itemsets from the tree without generating candidates. On very large data, algorithms such as PCY and SON count pairs with hashing or in parallel chunks.
Why we need it
Apriori scans the data once per level and can generate huge numbers of candidates when the minimum support is low. FP-Growth usually needs only two scans and is much faster on dense data. Knowing the costs helps choose settings that finish.
How it works
Start with a minimum support that keeps the result small, raise it if mining is slow, and use FP-Growth for large or dense data. Be careful with rules that only reflect popular items, rules found by testing thousands of pairs (some will look strong by chance), and correlation that is not causation.
How an FP-tree is built
  1. Scan once and count every item. Drop the infrequent items.
  2. Sort the items in each basket by overall frequency, most frequent first.
  3. Insert each sorted basket into a tree from the root, sharing nodes with earlier baskets that start the same way and adding 1 to each count.
  4. Link all nodes of the same item with a list, so each item’s paths can be found quickly.
  5. For each item, collect the paths that end in it (its conditional pattern base) and mine them recursively.
Remember
A rule found in the data is a pattern, not a cause. "Diapers and beer" type stories need a test, such as an experiment with shelf placement, before acting on them.

The maths, all in one place

SupportExam favourite
supp(X) = |{{t : X ⊆ t}}| / n
Share of transactions t containing itemset X.
ConfidenceExam favourite
conf(A ⇒ B) = supp(A ∪ B) / supp(A)
A ∪ B here means both itemsets in the basket.
LiftExam favourite
lift(A ⇒ B) = supp(A ∪ B) / (supp(A) supp(B))
1 = independent.
Leverage
supp(A ∪ B) − supp(A) supp(B)
0 = independent.
Conviction
(1 − supp(B)) / (1 − conf(A ⇒ B))
Infinite for a rule that is never wrong.
Apriori propertyExam favourite
X ⊆ Y ⇒ supp(X) ≥ supp(Y)
Support never rises when a set grows.
Worked example: one rule, every measure
  1. 1,000 baskets. Bread in 200, butter in 300, both in 120.
  2. Support = 120 / 1,000 = 0.12. Confidence(bread ⇒ butter) = 120 / 200 = 0.6.
  3. Lift = 0.6 / 0.3 = 2: butter is twice as likely in a bread basket.
  4. Leverage = 0.12 − 0.2 × 0.3 = 0.06
  5. Conviction = (1 − 0.3) / (1 − 0.6) = 0.7 / 0.4 = 1.75.
Going deeper: Why rule counts explode, and how many rules an itemset gives

d items give 2d − 1 non empty itemsets and 3d − 2d+1 + 1 possible rules, because each item can be on the left, on the right or absent, minus the cases with an empty side. One frequent itemset of size k gives 2k − 2 rules. Confidence has a useful partial monotonicity: for a fixed itemset, moving items from the left side to the right side can only lower confidence, so rule generation can prune too. Lift is symmetric and does not have that property. When thousands of rules are tested, some will show high lift by chance, so serious analyses use significance tests or hold out data, as in any multiple testing problem.

Chapter summary

  1. Rules "if A then B" are judged by support P(A ∩ B), confidence P(B | A) and lift P(A ∩ B) / P(A)P(B).
  2. High confidence can mislead when B is common anyway. Lift below 1 means the items avoid each other.
  3. Apriori property: subsets of frequent sets are frequent, so candidates with an infrequent subset are skipped.
  4. Apriori goes level by level. FP-Growth compresses baskets into a prefix tree and avoids candidate generation.
  5. Leverage and conviction add views of the same link. Sort rules by lift, filter by support, and read them with domain knowledge.
  6. Mined rules are correlations found among many tests. Check them before acting.
