Lesson 1 of 9

Learning from rewards: the agent and its environment

Source: Sutton and Barto, Reinforcement Learning: An Introduction (2nd edition, 2018) chapters 1 and 3, and Silver, UCL Course on RL lecture 1.

What it is
Reinforcement learning (RL) is learning what to do by trial and error. An agent acts in an environment. At each time step it observes a state, chooses an action, and receives a reward (a number) and the next state. Its rule for choosing actions is its policy. The goal is a policy that collects as much reward as possible over time.
Why we need it
Many problems have no labelled right answer for each step, only a score that comes later: winning a game, keeping a robot upright, cutting the energy a data centre uses. RL learns from that score alone. It beat world champions at Go (AlphaGo, 2016), learned Atari games from pixels (DQN, 2015), and is used to fine tune large language models from human preferences.
How it works
Write the problem as states, actions and rewards. Let the agent act, record what happens, and change the policy so that actions which led to more total reward become more likely. The rest of this section shows how: bandits, Markov decision processes, dynamic programming, Q learning and deep RL.

Lesson 2 of 9

The return and the discount factor

Source: Sutton and Barto (2018) section 3.3, Returns and Episodes.

What it is
The agent does not maximise the next reward but the return Gt: the sum of all rewards from step t on. A discount factor γ between 0 and 1 multiplies a reward k steps ahead by γk, so Gt = rt+1 + γ rt+2 + γ2 rt+3 + ...
Why we need it
Some good actions pay off only much later, and some quick wins lead to disaster. Adding up future rewards captures that. Discounting keeps the sum finite in tasks that never end, and expresses that sooner rewards are surer and worth more.
How it works
Compute returns backwards from the end of an episode with Gt = rt+1 + γ Gt+1. Pick γ for the task: 0.9 to 0.999 is common. Small γ makes a short sighted agent, and γ = 1 is safe only when every episode ends.

Lesson 3 of 9

Policies, value and the explore or exploit choice

Source: Sutton and Barto (2018) sections 1.3 and 3.5.

What it is
A policy π(a | s) gives the chance of each action in each state. It can be deterministic (always right) or stochastic (right 80% of the time). The value of a policy is the return it earns on average. RL compares policies by value and searches for the best one, the optimal policy π*.
Why we need it
The agent must try actions to learn what they do (exploration) but also use what it already knows to earn reward (exploitation). Too much of either wastes reward. This trade off is the core difficulty of RL and has no counterpart in supervised learning.
How it works
Estimate the value of a policy by running many episodes and averaging the totals, as below. Later chapters estimate value much more cleverly, state by state, and improve the policy step by step.

Lesson 4 of 9

Environments in code: the Gymnasium interface

Source: Gymnasium documentation (Farama Foundation), Env.reset and Env.step, and Towers and colleagues, Gymnasium: A Standard Interface for Reinforcement Learning Environments (2024).

What it is
Gymnasium, the maintained successor of OpenAI Gym, is the standard Python interface for RL environments. reset(seed) starts an episode and returns the first observation and an info dictionary. step(action) returns five values: observation, reward, terminated, truncated and info.
Why we need it
With one interface, the same agent code can learn CartPole, Atari games or a robot simulator, and libraries such as Stable Baselines3 plug straight in. Knowing the difference between terminated and truncated avoids a classic bug in value estimates.
How it works
Loop: reset, then step until terminated or truncated. Terminated means the task really ended (goal or failure), so no future reward follows. Truncated means a time limit cut it short, so the state still has future value, and a learning update must not treat it as an end. Install with pip install gymnasium, then gymnasium.make("CartPole-v1").

Going deeper: Where RL is used, and where it struggles

Successes: games (Atari, Go, StarCraft II, Dota 2), robot control in simulation, chip floor planning, data centre cooling, recommendation with long term goals, and reinforcement learning from human feedback (RLHF) for language models. Struggles: it can need millions of trials, rewards are easy to specify wrongly (the agent finds loopholes, called reward hacking), results vary a lot between random seeds, and trial and error is unsafe on real machines and people. Many real systems therefore learn in simulation or from logged data first. The last chapter of this section returns to these issues.

Worked example: return of the best corridor path
  1. Start in cell 2 and always go right: rewards −1, −1, +10.
  2. Plain sum: −1 − 1 + 10 = 8.
  3. With γ = 0.9: −1 + 0.9 × (−1) + 0.81 × 10 = −1 − 0.9 + 8.1 = 6.2
  4. Backwards: G3 = 10, G2 = −1 + 0.9 × 10 = 8, G1 = −1 + 0.9 × 8 = 6.2.
Going deeper: Why discounting is more than a trick

For continuing tasks the plain sum of rewards can be infinite, so policies cannot be compared. Discounting with γ < 1 bounds the return by rmax / (1 − γ). It can also be read as a chance 1 − γ that the world ends at every step, or as interest rates in economics. An alternative for continuing tasks is the average reward per step, which Sutton and Barto treat in chapter 10. In practice γ is also a tuning knob: a smaller γ makes value estimates lower in variance but more short sighted.

Chapter summary

  1. An agent observes a state, takes an action, and receives a reward and the next state from the environment.
  2. A policy π(a | s) chooses actions. The goal is the policy with the largest expected return.
  3. The return Gt = rt+1 + γ Gt+1 adds discounted future rewards. Small γ is short sighted.
  4. The agent must balance exploration (learning) and exploitation (earning).
  5. Gymnasium’s step returns observation, reward, terminated, truncated and info. Truncated is not a real end.
  6. RL fits problems where actions shape future data and feedback is a delayed score.
