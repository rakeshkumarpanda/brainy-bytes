Lesson 1 of 12

Encoding categories as numbers

Source: Zheng and Casari, Feature Engineering for Machine Learning, Kuhn and Johnson, Feature Engineering and Selection chapters 5, 6 and 10 to 12, the scikit-learn 1.8 user guide sections 6.1 to 6.3 and 1.13, and Guyon and Elisseeff, JMLR 2003.

What it is
A feature is one input column the model learns from. Encoding turns text categories (city, colour, plan) into numbers. One hot encoding makes one 0 or 1 column per category. Ordinal encoding gives each category one number.
Why we need it
Models do maths, and maths needs numbers. But the way you turn text into numbers matters: if Delhi = 0, Mumbai = 1 and Pune = 2, a linear model thinks Pune is "twice Mumbai", which is nonsense. One hot avoids any fake order.
How it works
Use one hot for categories with no order and only a few values. Use ordinal, with the order given by you, for categories with a real order (small, medium, large). In scikit-learn set handle_unknown="ignore" so a city never seen in training becomes all zeros instead of crashing.
Download this program (.py)Save it, open it in any editor and run it with python3 encode_categories.py.
Remember
pd.get_dummies is handy for a quick look, but use OneHotEncoder in real projects. It remembers the categories it saw during training, so the test data always gets exactly the same columns in the same order.
Lesson 2 of 12

Scaling numbers

What it is
Feature scaling changes the range of numeric features so they are comparable. Standardisation gives mean 0 and standard deviation 1, min max scaling squeezes values into 0 to 1, robust scaling uses the median and IQR, and a log transform pulls in long right tails.
Why we need it
Models that use distances (KNN, k means, SVM) or gradient descent (linear and logistic regression, neural networks) treat a feature measured in thousands as far more important than one measured in units. In the program below, scaling raises KNN accuracy on the wine data from 0.691 to 0.949.
How it works
Fit the scaler on the training data (it learns the mean and std, or the min and max), then use the same numbers to transform the test data. Put it in a Pipeline so cross validation does this correctly.

Lesson 3 of 12

Creating new features

What it is
Feature engineering means building new columns from the ones you have: parts of a date, ratios, groups (bins), log values, and combinations of features.
Why we need it
A model only sees the columns you give it. "Price per square metre" or "is it a weekend" may be what really drives the target, but a simple model cannot invent it. Good features often help more than a fancier model.
How it works
Use domain knowledge. Split dates into month, weekday and weekend flags. Divide related numbers (price by size). Group ages into bins with pd.cut. Take logs of skewed amounts. Then check whether each new feature improves the cross validated score.

Only build features from information you would have at prediction time. "Number of support calls in the month after cancelling" predicts cancelling perfectly, and is useless (and leaky) for a real prediction.

Polynomial and interaction features

What it is
Polynomial features add powers of a feature (x2, x3). Interaction features multiply two features (a × b). PolynomialFeatures in scikit-learn makes all of them for you.
Why we need it
A linear model can only draw straight lines. If the target follows a curve, a straight line fits badly. Adding x2 lets the same simple linear model fit a curve, while it stays easy to train and explain.
How it works
Create the new columns, then fit an ordinary linear model on them. The model is still linear in its weights, which is why the usual training works, but it is curved in the original x.
Download this program (.py)Save it, open it in any editor and run it with python3 polynomial_features.py.
Common mistake
The number of columns grows fast. With d features and degree p there are C(d + p, p) − 1 columns: 10 features at degree 3 gives 285 columns. Use regularisation (Supervised 1.2) to stop the extra columns from overfitting.
Lesson 5 of 12

Features from text

What it is
Bag of words turns each text into counts of the words it contains. TF-IDF (term frequency times inverse document frequency) gives a higher weight to words that are common in this text but rare in the others.
Why we need it
Reviews, emails and tickets are text, and a model needs numbers. Bag of words with a linear model is still a strong, fast baseline for spam filtering and sentiment.
How it works
Build a vocabulary of all words, then make one column per word. CountVectorizer stores counts. TfidfVectorizer multiplies each count by log(N / df), where df is how many texts contain the word, so words found everywhere (like "the") count for less.

Lesson 6 of 12

Feature selection: keep what helps

What it is
Feature selection keeps the most useful features and drops the rest. There are three families: filter methods score each feature on its own, wrapper methods try subsets with a model (RFE), and embedded methods select while training (L1 regularisation, tree importance).
Why we need it
Fewer features mean faster training, simpler explanations, less overfitting when data is small, and fewer columns to collect and clean in production. Useless or noisy features can hurt distance based models a lot.
How it works
Filter: compute a score such as the F test or mutual information and keep the top k. Wrapper: RFE trains a model, removes the weakest feature, and repeats. Embedded: an L1 penalty pushes the weights of weak features to exactly 0. Always choose k with cross validation, inside a Pipeline.
Download this program (.py)Save it, open it in any editor and run it with python3 select_features.py.
Remember
In this program the full 30 features give the best accuracy (0.981). Selection does not always raise the score. Here its value is a much simpler model: 5 features keep 0.949. Different methods also choose different features when features are correlated, as the radius, perimeter and area columns are.
Common mistake
Selecting features on the whole dataset and then cross validating is leakage: the test folds helped choose the features, so the score is too optimistic. Put the selector inside the Pipeline, as the k loop in the program does.
Lesson 7 of 12

One pipeline for every column

What it is
A ColumnTransformer applies different preparation to different columns (fill and scale the numbers, one hot encode the categories) and joins the results. Put it in a Pipeline with the model.
Why we need it
Real tables mix numbers and text. Preparing them by hand in separate steps is easy to get wrong and easy to leak. One pipeline object does every step in the right order, fits only on training folds during cross validation, and can be saved and used in production as one piece.
How it works
List the numeric columns and the categorical columns. Give each list its own small pipeline. Pass the ColumnTransformer and the model to Pipeline. Then call fit, predict and cross_val_score on the raw DataFrame.
Download this program (.py)Save it, open it in any editor and run it with python3 column_transformer.py.
The standard tabular pipeline
  1. Numbers: SimpleImputer(strategy="median") then StandardScaler().
  2. Categories: SimpleImputer(strategy="most_frequent") if needed, then OneHotEncoder(handle_unknown="ignore").
  3. Join them with ColumnTransformer and add the model at the end of a Pipeline.
  4. Evaluate with cross_val_score on the raw data. No step ever sees a test fold while fitting.
  5. Save the fitted pipeline with joblib and load it in the serving code (the MLOps subject shows how).

Bottom line: one hot for few categories, target encoding for many.

In the exam
Target encoding replaces a category by the average target for that category. Using a row’s own target to encode it leaks the answer. scikit-learn’s TargetEncoder avoids this with cross fitting: each row is encoded with means from the other folds, and rare categories are pulled towards the overall mean. That is why its numbers in the program differ a little from the plain shop means.

The maths, all in one place

StandardisationExam favourite
z = (x − μ) / σ
Mean 0, standard deviation 1.
Min maxExam favourite
x′ = (x − min) / (max − min)
Range 0 to 1.
RobustExam favourite
x′ = (x − median) / IQR
Ignores outliers when choosing the scale.
Number of polynomial columnsExam favourite
C(d + p, p) − 1
d features, degree p, without the constant column.
Mutual information
I(X, Y) = Σ p(x, y) log(p(x, y) / (p(x) p(y)))
0 when X and Y are independent. Catches non linear links.
Smoothed target encoding
enc(c) = (nc × meanc + m × meanall) / (nc + m)
Rare categories move towards the overall mean.
Worked example: scaling one value three ways
  1. Values 30, 35, 40, 45, 50, 400. Scale the value 40.
  2. Standard: mean = 600 / 6 = 100, population std = √(108,250 / 6) = 134.3. (40 − 100) / 134.3 = −0.45.
  3. Min max: (40 − 30) / (400 − 30) = 10 / 370 = 0.03.
  4. Robust: median 42.5, IQR 48.75 − 36.25 = 12.5, so (40 − 42.5) / 12.5 = −0.2
  5. Only robust scaling keeps 40 at a sensible distance from its neighbours.
Going deeper: The curse of dimensionality

As the number of features d grows, the volume of the space grows like (side length)d, so a fixed amount of data covers it ever more thinly. In high dimensions the distance to the nearest neighbour and to the farthest point become almost equal, which hurts KNN and clustering. The amount of data needed to keep the same density grows exponentially with d. Feature selection, dimensionality reduction (Unsupervised 2.1) and regularisation are the main defences.

From beginner to expert

One idea, four depths

Models need numbers on similar scales. Turn categories into 0 or 1 columns, scale numbers, and add helpful new columns like "price per square metre".

Use OneHotEncoder and OrdinalEncoder correctly, choose between standard, min max and robust scaling, build date, ratio, bin and log features, add polynomial terms, and use CountVectorizer and TF-IDF for text.

Select features with filter, wrapper and embedded methods inside a Pipeline, use target encoding with cross fitting for high cardinality, build a ColumnTransformer for mixed data, and avoid leaky features.

Learn representations instead of hand crafting them (embeddings, autoencoders), use feature stores for consistent training and serving features, and study stability of selection under correlated features (stability selection, Meinshausen and Bühlmann, 2010).

Beginner
One hot encode a category and standardise a number column.
Intermediate
Engineer date, ratio and text features and select the best ones with cross validation.
Expert
Design a leak free ColumnTransformer pipeline and pick encodings for high cardinality data.

Chapter summary

  1. One hot for unordered categories (handle_unknown="ignore"), ordinal only for a real order, target encoding with cross fitting for many categories.
  2. Scale for distance and gradient based models: standard (default), min max (0 to 1), robust (outliers), log (skewed). Trees do not need it.
  3. Fit every scaler and encoder on training data only, inside a Pipeline.
  4. Engineer features: date parts, ratios, bins, logs, aggregates, cyclical sin and cos. Only use what is known at prediction time.
  5. Polynomial and interaction features let linear models fit curves. Columns grow as C(d + p, p) − 1.
  6. Text: bag of words counts, TF-IDF down weights common words.
  7. Selection: filter (scores), wrapper (RFE), embedded (L1, trees). Choose k by cross validation.
  8. ColumnTransformer prepares numbers and categories differently in one pipeline.
