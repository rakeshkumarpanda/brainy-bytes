Lesson 1 of 12

The confusion matrix

Source: Fawcett, An Introduction to ROC Analysis (2006), Davis and Goadrich (2006), Saito and Rehmsmeier (2015), Hand (2009), Google’s Machine Learning Crash Course classification module, and the scikit-learn 1.8 user guide section 3.4.

What it is
A confusion matrix counts the four possible outcomes of a yes or no prediction: true positives (TP), false positives (FP, false alarms), false negatives (FN, misses) and true negatives (TN). Every classification metric is built from these four numbers.
Why we need it
A single accuracy number hides which mistakes the model makes, and the two kinds of mistake rarely cost the same. Missing a cancer (FN) is far worse than an extra test (FP). Flagging an honest customer as fraud (FP) loses business. The confusion matrix shows both.
How it works
Count them by comparing the true labels with the predictions, or call sklearn.metrics.confusion_matrix(y_true, y_pred). In scikit-learn the rows are the true classes and the columns the predicted classes, sorted by label.
Download this program (.py)Save it, open it in any editor and run it with python3 confusion_by_hand.py.
PrecisionExam favourite
precision = TP / (TP + FP)
Of the predicted positives, the share that are real.
Recall (sensitivity, TPR)Exam favourite
recall = TP / (TP + FN)
Of the real positives, the share we found.
F1 scoreExam favourite
F1 = 2PR / (P + R)
Harmonic mean, low if either is low.
Real world scenario: a smoke alarm

A smoke alarm that goes off at every slice of toast has perfect recall and terrible precision: it never misses a fire but most alarms are false. An alarm that only sounds when the room is full of smoke has great precision but poor recall. Where you set the sensitivity depends on what a missed fire costs compared with a false alarm.

Why accuracy can lie

What it is
Accuracy is the share of correct predictions. On imbalanced data, where one class is rare, a model that always predicts the common class gets a high accuracy and is useless.
Why we need it
Fraud, disease, defects and clicks are all rare events. A fraud model with 99% accuracy may catch no fraud at all. You need metrics that look at the rare class directly.
How it works
Report recall and precision for the rare class, the balanced accuracy (the mean of the recall of each class), or the F1 score. Compare every model with a dummy baseline such as DummyClassifier(strategy="most_frequent").
Download this program (.py)Save it, open it in any editor and run it with python3 accuracy_trap.py.
In the exam
Predicting "never fraud" scores 99.1% accuracy and catches none of the 89 frauds: recall 0 and balanced accuracy 0.5, the same as guessing. Always look at the class you care about.

Remember
classification_report gives precision, recall and F1 for every class. The macro average treats each class equally, the weighted average weights by the number of examples (support). For a rare class, the macro average shows problems that the weighted average hides.

Thresholds and the precision recall trade off

What it is
Most classifiers output a score or probability. The threshold turns it into a yes or no. Lowering the threshold catches more positives (higher recall) but adds false alarms (lower precision). Raising it does the opposite.
Why we need it
The default threshold of 0.5 is rarely the right one. In medicine you lower it so no cancer is missed, in spam filtering you raise it so no real email is lost. Choosing the threshold is a business decision, made after training.
How it works
Get probabilities with predict_proba, then compare them with your own threshold. precision_recall_curve gives precision and recall at every threshold, and TunedThresholdClassifierCV (scikit-learn 1.5 and later) picks one by cross validation.
Download this program (.py)Save it, open it in any editor and run it with python3 thresholds.py.
Remember
At the default 0.5 the model misses 4 of 64 cancers. At 0.1 it misses none, at the cost of precision falling from 0.984 to 0.653, so about one in three alarms is a healthy patient sent for more tests. Here that trade is usually worth it.
F beta scoreExam favourite
Fβ = (1 + β2) PR / (β2P + R)
β > 1 weights recall more, β < 1 weights precision more.
Lesson 4 of 12

ROC curves and AUC

What it is
The ROC curve plots the true positive rate (recall) against the false positive rate FP / (FP + TN) for every threshold. The AUC (area under it) sums up the whole curve in one number between 0 and 1.
Why we need it
AUC measures how well the model ranks positives above negatives, independent of any threshold. It lets you compare models before you choose a threshold. 0.5 means random ranking and 1.0 means perfect ranking.
How it works
roc_curve(y, scores) gives the points and roc_auc_score(y, scores) the area. Pass scores or probabilities, never the 0 or 1 predictions, or the curve collapses to a single point.
Download this program (.py)Save it, open it in any editor and run it with python3 roc_auc.py.
In the exam
AUC equals the share of (positive, negative) pairs where the positive gets the higher score. Here 12 of 16 pairs are ordered correctly, so AUC = 0.75, exactly what scikit-learn reports. This ranking view is the Mann and Whitney U statistic.
False positive rateExam favourite
FPR = FP / (FP + TN) = 1 − specificity
Share of negatives wrongly flagged.
Lesson 5 of 12

Precision recall curves for rare positives

What it is
The precision recall (PR) curve plots precision against recall for every threshold. Its area, the average precision, focuses on how well the model finds the rare positives.
Why we need it
ROC AUC uses the false positive rate, whose denominator is the huge number of negatives, so many false alarms barely move it. On very imbalanced data ROC AUC can look good while precision is poor. The PR curve shows the problem.
How it works
Use average_precision_score(y, scores). The baseline for a random model is the share of positives, not 0.5.
Download this program (.py)Save it, open it in any editor and run it with python3 pr_vs_roc.py.
Remember
As positives become rare (50%, 5%, 1%), ROC AUC stays between 0.69 and 0.79, while average precision collapses from 0.82 to 0.12. With 1% positives a random model would have average precision 0.01, so 0.12 is better than random but means most alarms are false. Saito and Rehmsmeier (2015) recommend PR curves for such data.
Lesson 6 of 12

Metrics for regression

What it is
Regression metrics measure the size of the errors y − ŷ. MAE averages their absolute values, MSE averages their squares, RMSE is the square root of MSE in the original units, MAPE averages percentage errors, and R² compares the model with always predicting the mean.
Why we need it
Each answers a different question. MAE is easy to explain and robust to outliers. RMSE punishes big errors much more. R² is unit free. MAPE is intuitive for business but breaks near zero targets.
How it works
Use the metric that matches the cost of errors. If one big miss is much worse than several small ones, use RMSE. Report the metric on held out data, next to a baseline such as DummyRegressor.
Download this program (.py)Save it, open it in any editor and run it with python3 regression_metrics.py.
In the exam
Four predictions are off by 10 and one by 100. MAE is 28, but RMSE is 45.6, pulled up by the single big miss because it is squared. If that miss matters, RMSE tells you. If it is a rare outlier you can live with, MAE is fairer.
MAEExam favourite
MAE = (1/n) Σ|yi − ŷi|
Average absolute error.
RMSEExam favourite
RMSE = √((1/n) Σ(yi − ŷi)2)
Big errors count more.
R²Exam favourite
R² = 1 − SSE / SST
Share of variance explained. Can be negative.
Lesson 7 of 12

Metrics for probabilities

What it is
When the probabilities themselves matter, use log loss (cross entropy) or the Brier score (mean squared error of the probabilities). Both punish confident wrong answers.
Why we need it
Two models with the same accuracy can give very different probabilities. A risk score, a price or a medical decision depends on the probability being right, not just on which side of 0.5 it falls.
How it works
log_loss(y, p) and brier_score_loss(y, p) in scikit-learn. Lower is better for both. Calibration (Supervised 4.3) improves them without changing the ranking.
Download this program (.py)Save it, open it in any editor and run it with python3 prob_metrics.py.
Remember
The careful model is right every time with modest confidence. The bold model says 99% for everything and is wrong once: its log loss is almost three times worse (1.159 against 0.434), because that one confident mistake costs −ln(0.01) = 4.6 on its own.
Log lossExam favourite
L = −(1/n) Σ[y ln p + (1 − y) ln(1 − p)]
Confident mistakes cost a lot.

Worked example: the confusion matrix by hand
  1. Ten examples: 4 real positives, 6 real negatives.
  2. The model predicts 4 positives: 3 are real (TP = 3), 1 is not (FP = 1). It misses one positive (FN = 1), and TN = 5.
  3. Precision = 3 / (3 + 1) = 0.75. Recall = 3 / (3 + 1) = 0.75.
  4. F1 = 2 × 0.75 × 0.75 / (0.75 + 0.75) = 0.75
  5. Accuracy = (3 + 5) / 10 = 0.8, as the program prints.
Going deeper: Why F1 is a harmonic mean, and the limits of AUC

The harmonic mean 2PR/(P + R) is dominated by the smaller value: precision 1.0 with recall 0.01 gives F1 = 0.02, while the ordinary mean would say 0.5. That stops a model from looking good by maximising only one of the two. F1 ignores true negatives entirely, so it suits problems where negatives are plentiful and uninteresting. ROC AUC has its own limits: it averages over all thresholds, including ones you would never use, and Hand (2009) showed it implicitly uses different misclassification cost ratios for different classifiers, which can make comparisons incoherent. Partial AUC over a useful range of FPR, or expected cost at your real cost ratio, are more honest when costs are known.

Chapter summary

  1. The confusion matrix counts TP, FP, FN and TN. Every classification metric comes from it.
  2. Precision TP/(TP + FP) asks how many alarms are real. Recall TP/(TP + FN) asks how many positives were found. F1 combines them.
  3. Accuracy misleads on imbalanced data. Compare with a dummy baseline and use balanced accuracy or per class metrics.
  4. The threshold trades precision against recall. Choose it from the costs, not by default 0.5.
  5. ROC AUC measures ranking. For rare positives prefer the PR curve and average precision.
  6. Regression: MAE (robust), RMSE (punishes big errors), R² (versus the mean).
  7. Probabilities: log loss and Brier punish confident mistakes.
