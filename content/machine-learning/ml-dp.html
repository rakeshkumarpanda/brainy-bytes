Lesson 1 of 9

Dynamic programming and policy evaluation

Source: Sutton and Barto (2018) sections 4.1 and 4.2, example 4.1.

What it is
Dynamic programming (DP) solves an MDP when the full model p(s′, r | s, a) is known. Its first tool is iterative policy evaluation: start with any values and repeatedly replace every v(s) with the right side of the Bellman expectation equation for the policy, until the values stop changing.
Why we need it
Solving the linear system directly costs about n3 operations for n states. Sweeps cost about n2 each (much less when each state has few successors), and the values converge geometrically. DP is also the foundation for every other RL method, which can be seen as DP with samples instead of a model.
How it works
Loop over states, compute the expected one step reward plus discounted value of the next state under π, and stop when the largest change in a sweep is below a small threshold θ. Updating in place (using new values as soon as they exist) usually converges faster than keeping two arrays.

Lesson 2 of 9

Policy improvement and policy iteration

Source: Howard, Dynamic Programming and Markov Processes (1960), and Sutton and Barto (2018) sections 4.2 and 4.3.

What it is
The policy improvement theorem says that acting greedily with respect to qπ gives a policy at least as good as π in every state. Policy iteration alternates two steps: evaluate the current policy, then make it greedy with respect to its own values. It stops when the greedy policy no longer changes, and that policy is optimal.
Why we need it
There are only finitely many deterministic policies and each step is a strict improvement until the end, so policy iteration must finish, usually in very few iterations, often fewer than 10 even for large problems.
How it works
Start with any policy. Evaluate it fully. For every state pick argmaxa q(s, a) using one step lookahead with the model. If nothing changed, stop. Break ties in a fixed way, or the loop can flip between equally good policies forever.

In the exam
Starting from "always go left", the value of the start rises from 0 to 0.121, 0.52, 0.532 and finally 0.542 after 7 iterations, when the policy stops changing. The optimal first move at the start is left, into the wall. On ice where you slide sideways two times in three, pushing against the wall means you can only slide down or stay put, never into danger. Good policies on slippery ice look odd but are safe.
Policy iteration
  1. Initialise π arbitrarily, for example always left.
  2. Policy evaluation: compute vπ (sweeps or a linear solve).
  3. Policy improvement: π′(s) = argmaxa Σ p(s′, r | s, a)[r + γ vπ(s′)] for every s.
  4. If π′ = π, stop: π is optimal and vπ = v*.
  5. Otherwise set π = π′ and go back to step 2.
Lesson 3 of 9

Value iteration

Source: Bellman (1957), and Sutton and Barto (2018) section 4.4.

What it is
Value iteration skips the full evaluation. Each sweep applies the Bellman optimality equation as an update: v(s) ← maxa Σ p(s′, r | s, a)[r + γ v(s′)]. When the values stop changing, the greedy policy for them is optimal.
Why we need it
It is policy iteration with evaluation cut to a single sweep, which is often cheaper overall. It is also the direct ancestor of Q learning, which applies the same max backup using samples instead of the model.
How it works
Initialise v = 0, sweep with the max backup until the largest change is below θ, then extract the policy with one step lookahead. The values spread backwards from the rewards, about one step per sweep, so the number of sweeps grows with the distance to reward and with 1 / (1 − γ).

Remember
Sutton and Barto’s gambler with a 0.4 coin: the best play is bold. With 50 you stake everything (win chance 0.4). With 25 you stake 25 to reach 50, so the win chance is 0.4 × 0.4 = 0.16. With 75 you stake 25 to reach 100 or fall back to 50, giving 0.4 + 0.6 × 0.4 = 0.64. When the odds are against you, fewer bets mean less time for the house edge to work.
Lesson 4 of 9

Generalised policy iteration and the limits of DP

Source: Sutton and Barto (2018) sections 4.5 to 4.8.

What it is
Generalised policy iteration (GPI) is the idea behind almost every RL method: keep a value estimate and a policy, and let them improve each other. Evaluation makes the values match the policy, improvement makes the policy greedy for the values. How much of each step you do is a choice. Asynchronous DP updates states in any order, for example only those the agent visits.
Why we need it
DP needs the full model and touches every state, so it breaks down when the model is unknown or the state space is huge. Bellman called this the curse of dimensionality: the number of states grows exponentially with the number of state variables. Seeing every later method as GPI with approximations makes them easy to place.
How it works
Use DP when the model is known and the states fit in memory: inventory control, small games, robot planning on grids, and checking other algorithms. For unknown models, learn from samples (Monte Carlo and TD, next chapter). For huge spaces, approximate values with functions such as neural networks (deep RL).

Going deeper: Linear programming and the cost of solving MDPs exactly

An MDP can also be solved as a linear program: minimise Σs v(s) subject to v(s) ≥ Σ p(s′, r | s, a)[r + γv(s′)] for every state and action. The smallest v that satisfies all the constraints is v*, which proves that MDPs can be solved in polynomial time. Policy iteration needs at most a number of iterations that is polynomial in the number of states and actions for a fixed γ (Ye, 2011), and in practice far fewer. Value iteration needs about log(1/ε) / (1 − γ) sweeps for accuracy ε, so γ close to 1 makes it slow. Prioritised sweeping, which updates the states whose values would change most first, speeds DP up a lot on large sparse problems.

Policy iteration and value iteration compared

Two ways to solve a known MDP
Policy iterationValue iteration
Each iterationFull evaluation, then greedy improvementOne sweep of max backups
Iterations to finishFew (often under 10)Many (hundreds when γ is near 1)
Cost per iterationHigh (a full evaluation)Low (one sweep)
Stops whenThe policy does not changeValues change less than θ
GivesExact optimal policyNear optimal values, then the greedy policy
Leads on toActor critic methodsQ learning

Bottom line: use policy iteration when evaluation is cheap or the number of policies is small, value iteration when sweeps are cheap. Both give the same optimal policy.

Worked example: one value iteration backup
  1. γ = 0.9. Action a: with chance 0.5 reward 1 and the episode ends, with chance 0.5 reward 0 and a state worth 10.
  2. Action b: reward 0 for sure and a state worth 6.
  3. Q(a) = 0.5 × (1 + 0) + 0.5 × (0 + 0.9 × 10) = 0.5 + 4.5 = 5
  4. Q(b) = 0 + 0.9 × 6 = 5.4
  5. The backup sets v(s) = max(5, 5.4) = 5.4, and the greedy action is b.
Going deeper: Proof sketch of the policy improvement theorem

Suppose qπ(s, π′(s)) ≥ vπ(s) everywhere. Start from vπ(s) ≤ qπ(s, π′(s)) = E[Rt+1 + γ vπ(St+1) | At = π′(s)]. Apply the same inequality to vπ(St+1) inside the expectation, then to vπ(St+2), and so on. After unrolling, the right side becomes the expected discounted return of following π′ forever, which is vπ′(s). If the greedy step changes nothing, then vπ satisfies the Bellman optimality equation, so it equals v* and π is optimal.

Chapter summary

  1. Dynamic programming solves MDPs with a known model by repeated Bellman backups over all states.
  2. Policy evaluation sweeps v(s) ← Σ π Σ p (r + γv) until the largest change is below θ.
  3. Policy improvement: being greedy on qπ is never worse. Policy iteration alternates both and stops in few iterations.
  4. Value iteration sweeps v(s) ← maxa Σ p (r + γv), then extracts the greedy policy.
  5. On slippery FrozenLake both reach start value 0.542, and the best first move points into a wall for safety.
  6. GPI: values and policies improve each other. DP needs a model and suffers the curse of dimensionality.
