Lesson 1 of 12

What machine learning is

Source: Tom Mitchell, Machine Learning (1997) chapter 1, Arthur Samuel (1959), the scikit-learn 1.8 user guide and the Google Machine Learning Crash Course.

What it is
Machine learning (ML) is a way to make a computer good at a task by showing it examples, instead of writing every rule by hand. The computer finds the pattern in the examples and uses it on new cases.
Why we need it
Many tasks have rules that are too many, too fuzzy or too fast changing for a person to write down: spotting a face, reading handwriting, catching spam, guessing tomorrow’s sales. People can do these tasks but cannot explain the exact rules. ML lets the data teach the rules.
How it works
We collect examples, pick a model (a rule with adjustable numbers called parameters), and let a learning method change those numbers until the model’s answers match the examples well. Then we use the trained model on new data.

Tom Mitchell gave the definition most courses use: a program learns from experience E for a task T, measured by P, if its performance on T, measured by P, gets better with experience E. For a spam filter, T is "sort emails", E is "emails people already marked", and P is "the share of emails sorted correctly". If P goes up as E grows, the program is learning.

Real world scenario: your email spam folder

Nobody at your email company wrote a rule for every spam message in the world. Spammers change their words every day. Instead, every time someone clicks "Report spam", that email becomes a new example. The filter keeps learning which words, links and senders show up in spam, so it catches new tricks without a programmer writing new rules.

Lesson 2 of 12

The learning loop: guess, check, adjust, repeat

Almost every ML method, from a straight line to a huge chatbot, learns with the same four step loop. Press Step to watch it find the rule between study hours and marks. Change the data or the learning rate and play it again.

What it is
The learning loop is the repeated cycle of making a prediction, measuring how wrong it is with a loss (an error score), and changing the parameters a little to make the loss smaller.
Why we need it
We almost never know the best parameters in advance. Trying every possible value would take forever. The loop lets the model walk towards good values one small step at a time.
How it works
The slope of the loss tells which direction makes the loss smaller. We move the parameter a small amount, called the learning rate, in that direction. This method is called gradient descent and you will meet it in almost every chapter.
Download this program (.py)Save it, open it in any editor and run it with python3 learning_loop.py.
Worked example: one round of the loop by hand
  1. Data: hours 1 and 2, marks 10 and 20. First guess w = 5. Learning rate 0.1.
  2. Predictions: 5 × 1 = 5 and 5 × 2 = 10. Errors: 5 − 10 = −5 and 10 − 20 = −10.
  3. Loss (mean squared error) = ((−5)2 + (−10)2) / 2 = (25 + 100) / 2 = 62.5.
  4. Slope of the loss = (2 × (−5) × 1 + 2 × (−10) × 2) / 2 = (−10 − 40) / 2 = −25.
  5. new w = 5 − 0.1 × (−25) = 7.5
  6. With w = 7.5 the predictions are 7.5 and 15, much closer to 10 and 20. The true best value is w = 10.
Common mistake
A learning rate that is too big makes the guess jump past the best value and the loss can grow. One that is too small makes learning very slow. Choosing it well is part of the job.

Lesson 5 of 12

Learning, not memorising: generalisation

What it is
Generalisation means doing well on new data the model has never seen, not only on the examples it trained on.
Why we need it
A model that only remembers its training examples is useless in real life, because real inputs are always new. A face unlock that works only on the exact photos you gave it would fail the moment you change your hair.
How it works
We keep some data hidden from the model (a test set) and measure the model on it. A model that does great on training data but badly on test data has overfitted: it learned the noise and the details, not the pattern.
Download this program (.py)Save it, open it in any editor and run it with python3 memorise_or_learn.py.
Real world scenario: learning for an exam

Two students prepare for a maths exam. The first memorises the answers to last year’s paper. The second learns how to solve each type of question. On last year’s paper both score 100. On the new paper the first student is lost, while the second does well. The first student overfitted. ML models face exactly this risk, which is why we always test them on unseen data.

Common mistake
Never measure a model only on its training data. The score will look great and mean nothing. Always keep a separate test set, and look at it only at the end.

The maths of learning

You do not need hard maths to start, but these four lines appear in every chapter. Read them slowly. They are the whole idea of supervised learning written as formulas.

A modelExam favourite
ŷ = f(x, θ)
x is the input, θ (theta) are the parameters, ŷ (y hat) is the prediction.
Mean squared error (loss for numbers)Exam favourite
MSE = (1/n) Σ (yi − ŷi)2
Average of the squared gaps between true answers y and predictions ŷ over n examples.
Accuracy (score for categories)
accuracy = correct predictions / all predictions
Between 0 and 1. Higher is better.
One gradient descent stepExam favourite
θnew = θ − η × (slope of the loss at θ)
η (eta) is the learning rate. Move against the slope, because the slope points uphill.
Learning as a search
θ* = the θ that makes the average loss on the training data smallest
Training is finding θ*. Generalisation asks if θ* also works on new data.
Download this program (.py)Save it, open it in any editor and run it with python3 measure_a_model.py.
Worked example: score a tiny model
  1. True prices 30, 50, 80. Predicted prices 35, 45, 80.
  2. Gaps: 30 − 35 = −5, 50 − 45 = 5, 80 − 80 = 0.
  3. Squares: 25, 25, 0. Sum = 50.
  4. MSE = 50 / 3 ≈ 16.67
  5. The root of the MSE, about 4.08, is in the same unit as the price. So the model is off by about 4 lakh on a typical house.
Going deeper: Why squared errors?

Squaring makes every gap positive, so errors above and below do not cancel. It punishes big mistakes much more than small ones (a gap of 10 counts 100 times a gap of 1). It also gives a smooth curve with a single lowest point for a straight line model, which makes gradient descent easy. If the noise in the data follows a bell curve (normal distribution), minimising squared error is the same as choosing the most likely parameters (maximum likelihood). You will prove this in Foundations 2.3.

Lesson 10 of 12

From beginner to expert

One idea, four depths

Machine learning means teaching a computer with examples instead of rules. It looks at many examples, finds the pattern, and uses it to answer new questions.

A model has parameters. Training changes the parameters to make a loss small on training data, usually with gradient descent. We judge a model on separate test data, because the real goal is to generalise.

Supervised learning is empirical risk minimisation: pick θ to minimise the average loss over n samples drawn from an unknown distribution. The gap between training loss and true loss depends on how flexible the model family is (its capacity) and on n. Regularisation and validation control that gap.

Learning theory bounds the gap. In the PAC framework (Valiant, 1984) a finite hypothesis class H needs about (1/ε)(ln|H| + ln(1/δ)) samples to be probably (1 − δ) approximately (ε) correct, and VC dimension extends this to infinite classes. The no free lunch theorem (Wolpert, 1996) says no learner is best on every possible problem: every method relies on an inductive bias that matches some worlds and not others.

Beginner
Explain ML in your own words, name the three kinds of learning and spot features and labels in a table.
Intermediate
Run the learning loop by hand, use fit and predict in scikit-learn, and explain overfitting with a test set.
Expert
Write supervised learning as risk minimisation, explain inductive bias and no free lunch, and reason about sample size with PAC bounds.
Going deeper: Inductive bias and no free lunch

From a finite set of examples, infinitely many rules fit the data perfectly. A learner must prefer some rules over others, for example "simple lines first" or "nearby points share labels". This preference is its inductive bias. The no free lunch theorem shows that, averaged over every possible problem, all learners do equally well. ML works in practice because real problems are not random: nearby inputs usually have similar outputs, and simple explanations usually beat complicated ones.

Lesson 12 of 12

Chapter summary

  1. Machine learning makes a computer good at a task by learning from examples instead of hand written rules.
  2. Mitchell’s definition: performance P on task T improves with experience E.
  3. Every model learns with the same loop: guess, measure the loss, adjust the parameters, repeat. Gradient descent moves each parameter against the slope of the loss, by the learning rate.
  4. Supervised learning uses labelled examples (regression for numbers, classification for categories). Unsupervised learning finds structure without labels. Reinforcement learning learns from rewards.
  5. Features are the inputs, the label is the answer, parameters are learned, hyperparameters are chosen by you.
  6. The goal is generalisation: do well on new data. Always test on data the model never saw.
  7. scikit-learn models all use the same steps: create, fit(X, y), predict(X_new), score.
