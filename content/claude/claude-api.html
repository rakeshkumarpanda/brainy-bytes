Part 1

🔑Get a key and install the SDK

🧒 Beginner friendly

The Claude API lets your own program talk to Claude. You pay per token used, separate from a Claude.ai subscription.

  1. Sign in at platform.claude.com and add billing.
  2. Create an API key.
  3. Store it in the ANTHROPIC_API_KEY environment variable.
  4. Install the official SDK.
Get a key and install the SDK · ⌨️ Type this in your terminal
# 1. Create a key at platform.claude.com (Settings, then API keys)
# 2. Keep it in an environment variable, never in code
export ANTHROPIC_API_KEY="sk-ant-..."        # macOS / Linux
setx ANTHROPIC_API_KEY "sk-ant-..."          # Windows (open a new terminal after)

# 3. Install the SDK for your language
pip install anthropic                        # Python
npm install @anthropic-ai/sdk                # JavaScript / TypeScript
Never put the key in code, in a Git repository or in a web page. Anyone with the key can spend your money. Keep it in an environment variable or a secrets manager.
Part 2

👋Your first call, line by line

🧒 Beginner friendly
Your first API call · ▶ Real SDK code, run against a local stand-in API with scripted replies
📄 app.py
import anthropic

client = anthropic.Anthropic()   # reads ANTHROPIC_API_KEY from the environment

response = client.messages.create(
    model="claude-haiku-5-5",
    max_tokens=1000,
    messages=[
        {"role": "user", "content": "What is the capital of India? One sentence."}
    ],
)

for block in response.content:
    if block.type == "text":
        print(block.text)

print("stop_reason:", response.stop_reason)
print("tokens in:", response.usage.input_tokens, "| tokens out:", response.usage.output_tokens)

Part 3

🧑‍🏫System prompts and conversations

🧒 Beginner friendly

The system prompt sets the role and rules for the whole chat. The API does not remember anything between calls, so your code keeps the history and sends it every time.

A tutor with a system prompt and memory of the chat · ▶ Real SDK code, run against a local stand-in API with scripted replies
📄 app.py
import anthropic

client = anthropic.Anthropic()

SYSTEM = """You are Pinky, a friendly maths tutor for a 9 year old.
Use short sentences and Indian examples like rupees and cricket.
Never give the final answer straight away. Give one hint at a time."""

history = []

def ask(text):
    history.append({"role": "user", "content": text})
    reply = client.messages.create(
        model="claude-sonnet-5-5",
        max_tokens=500,
        system=SYSTEM,
        messages=history,          # the API remembers nothing, so send the whole chat each time
    )
    answer = reply.content[0].text
    history.append({"role": "assistant", "content": answer})
    print("Child:", text)
    print("Pinky:", answer, "\n")

ask("What is 3 times 4?")
ask("Is it 7?")
ask("Oh! Then it is 12?")
print("messages sent in the last request:", len(history) - 1)

What goes in a system prompt: who Claude is in this app, who the user is, the tone, the rules it must always follow, and the format of answers. The same advice as chapter 2 applies: be clear, give reasons, use examples and XML tags.

⚖️Choose a model and know the cost

🧒 Beginner friendly
ModelId$ per million in / outGood for
Fable 5.1claude-fable-5-110 / 50the hardest, longest tasks
Opus 5.5claude-opus-5-54 / 20complex agents, coding, deep analysis
Sonnet 5.5claude-sonnet-5-52 / 10most apps: strong and quick
Haiku 5.5claude-haiku-5-50.10 / 0.50sorting, extracting, high volume

All four have a 1 million token context window and up to 128K output tokens. Haiku 5.5 costs $0.50 / $2.50 for prompts over 100K tokens.

cost = (input tokens × input price + output tokens × output price) ÷ 1,000,000

The same job priced on four models · ▶ Runs
// What a job costs on each model. Prices are dollars per million tokens (input / output).
const PRICES = {
  "claude-fable-5-1":  [10, 50],
  "claude-opus-5-5":   [4, 20],
  "claude-sonnet-5-5": [2, 10],
  "claude-haiku-5-5":  [0.10, 0.50],   // for prompts of 100K tokens or fewer
};

// A support team summarises 2,000 tickets a day: about 1,500 tokens in and 200 out each.
const tickets = 2000, inTok = 1500, outTok = 200;

for (const [model, [pin, pout]] of Object.entries(PRICES)) {
  const perDay = tickets * (inTok * pin + outTok * pout) / 1e6;
  console.log(model.padEnd(18), "$" + perDay.toFixed(2).padStart(7), "a day  $" + (perDay * 30).toFixed(0).padStart(5), "a month");
}
Output
claude-fable-5-1   $  50.00 a day  $ 1500 a month
claude-opus-5-5    $  20.00 a day  $  600 a month
claude-sonnet-5-5  $  10.00 a day  $  300 a month
claude-haiku-5-5   $   0.50 a day  $   15 a month

Start with Sonnet. Move simple, high volume steps to Haiku, and hard steps to Opus. Test with your own examples before you switch.

Part 5

🌊Streaming: show words as they arrive

Long answers take time. Streaming sends the text piece by piece, so your app can show it at once. Use it for anything long, because it also avoids request timeouts.

Stream the answer as it is written · ▶ Real SDK code, run against a local stand-in API with scripted replies
📄 app.py
import anthropic

client = anthropic.Anthropic()

with client.messages.stream(
    model="claude-sonnet-5-5",
    max_tokens=2000,
    messages=[{"role": "user", "content": "Write a two line poem about monsoon rain."}],
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)    # words appear as they are written
    final = stream.get_final_message()

print("\n\nstop_reason:", final.stop_reason, "| tokens out:", final.usage.output_tokens)

Part 6

🧾Get JSON your code can trust

With output_config.format and a JSON schema, the reply is valid JSON in exactly that shape. No more "please answer only in JSON" and hoping.

Get JSON in a fixed shape · ▶ Real SDK code, run against a local stand-in API with scripted replies
📄 app.py
import json
import anthropic

client = anthropic.Anthropic()

review = "Delivery was 2 days late but the mixer grinder works great. Box was damaged."

response = client.messages.create(
    model="claude-haiku-5-5",
    max_tokens=1000,
    messages=[{"role": "user", "content": f"Read this product review and fill in the fields.\n\n<review>{review}</review>"}],
    output_config={
        "format": {
            "type": "json_schema",
            "schema": {
                "type": "object",
                "properties": {
                    "sentiment": {"type": "string", "enum": ["positive", "mixed", "negative"]},
                    "issues": {"type": "array", "items": {"type": "string"}},
                    "stars": {"type": "integer"},
                },
                "required": ["sentiment", "issues", "stars"],
                "additionalProperties": False,
            },
        }
    },
)

data = json.loads(response.content[0].text)   # valid JSON in the exact shape asked for
print(data)
print("needs follow-up:", data["sentiment"] != "positive" and len(data["issues"]) > 0)
Terminal
$ python app.py
Terminal output
{'sentiment': 'mixed', 'issues': ['late delivery', 'damaged box'], 'stars': 3}

Part 7

💾Effort and prompt caching

  • Effort (output_config.effort) sets how hard Claude thinks: low, medium, high, xhigh or max. Low is faster and cheaper, high is better for hard problems.
  • Prompt caching stores the start of a prompt you send again and again, such as a long policy. Later calls read it from the cache at a fraction of the price: $0.20 per million instead of $4 on Opus 5.5.
Effort and prompt caching · ▶ Real SDK code, run against a local stand-in API with scripted replies
📄 app.py
import anthropic

client = anthropic.Anthropic()
POLICY = open("leave-policy.md").read()   # a long document you send with every question

response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1000,
    output_config={"effort": "low"},       # low | medium | high | xhigh | max
    system=[
        {"type": "text", "text": "Answer HR questions using only the policy below."},
        {"type": "text", "text": POLICY, "cache_control": {"type": "ephemeral"}},   # cache everything up to here
    ],
    messages=[{"role": "user", "content": "How many casual leaves do I get?"}],
)
print(response.content[0].text)
print("written to cache:", response.usage.cache_creation_input_tokens,
      "| read from cache:", response.usage.cache_read_input_tokens)
📄 leave-policy.md
# Leave policy

Casual leave: 12 days a year.
Sick leave: 10 days a year.
Terminal
$ python app.py
Terminal output

The stand-in API does not cache, so it reports 0 for both. Against the real API the first call writes the policy to the cache and calls in the next 5 minutes read it.

🧯When things go wrong

errors.py: handle what can go wrong · 📄 Ready to copy
import anthropic

client = anthropic.Anthropic(max_retries=4)   # 429, 5xx and connection errors are retried for you (default 2)

try:
    response = client.messages.create(
        model="claude-sonnet-5-5",
        max_tokens=300,
        messages=[{"role": "user", "content": "Summarise our refund policy"}],
    )
except anthropic.AuthenticationError:
    print("401: the API key is missing or wrong")
except anthropic.RateLimitError:
    print("429: too many requests, slow down and try later")
except anthropic.APIStatusError as e:
    print("API error", e.status_code, e.message)
else:
    if response.stop_reason == "max_tokens":
        print("The answer was cut off. Raise max_tokens.")
    elif response.stop_reason == "refusal":
        print("Claude declined this request.")
    else:
        print(response.content[0].text)
