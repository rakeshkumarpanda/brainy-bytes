Part 1

📘What CLAUDE.md is for

🧒 Beginner friendly📄 CLAUDE.md

CLAUDE.md is a plain Markdown file of instructions Claude Code reads at the start of every session. Write down what you would otherwise explain again and again: how to run the project, the house rules, the traps.

Anthropic's guidance on when to add a line:

  • Claude made the same mistake a second time.
  • A review caught something Claude should have known.
  • You typed the same correction you typed last session.
  • A new teammate would need the same context.
Claude treats CLAUDE.md as guidance, not enforcement. It usually follows it, but it can slip. For "must never happen" rules, use a hook (chapter 8).

Claude Code loads these from the folder you start in and every folder above it, joined from the top down. A CLAUDE.md inside a subfolder loads later, when Claude reads or edits a file in that subfolder.

Which files load, and in what order · ▶ Runs
// Claude Code loads CLAUDE.md and CLAUDE.local.md from the folder you start in
// and every folder above it. They are joined from the top folder down,
// so the instructions closest to you are read last.
const files = {
  "/home/asha/CLAUDE.md": "(not loaded: only ~/.claude/CLAUDE.md is your user file)",
  "/home/asha/.claude/CLAUDE.md": "user: short answers",
  "/home/asha/work/CLAUDE.md": "work: company rules",
  "/home/asha/work/shop/CLAUDE.md": "shop: npm ci, vitest",
  "/home/asha/work/shop/CLAUDE.local.md": "local: my port is 4100",
  "/home/asha/work/shop/api/CLAUDE.md": "api: loads later, when Claude touches a file in api/",
};

function loadOrder(cwd) {
  const order = ["/home/asha/.claude/CLAUDE.md"];
  const parts = cwd.split("/").filter(Boolean);
  for (let i = 1; i <= parts.length; i++) {
    const dir = "/" + parts.slice(0, i).join("/");
    for (const name of ["CLAUDE.md", "CLAUDE.local.md"]) {
      const f = dir + "/" + name;
      if (f in files && f !== "/home/asha/CLAUDE.md") order.push(f);
    }
  }
  return order;
}

loadOrder("/home/asha/work/shop").forEach((f, i) => console.log(i + 1, f.padEnd(40), files[f]));

📥What to put in, and what to leave out

🧒 Beginner friendly📄 CLAUDE.md

This table comes from Anthropic's best practices guide. For every line, ask: would removing this cause Claude to make mistakes? If not, cut it.

✅ Include❌ Leave out
commands Claude cannot guessanything Claude can work out by reading the code
style rules that differ from the usualstandard conventions Claude already knows
how to run tests, which runner you preferlong API documentation (link to it instead)
branch names and pull request habitsinformation that changes every week
architecture decisions specific to yoututorials and long explanations
environment quirks, required variablesa description of every file
gotchas that are not obvious"write clean code" and other things that go without saying
  • Concrete and checkable lines: "Run npm test before committing", not "test your changes".
  • Headings and bullets, not long paragraphs.
  • Under 200 lines. Longer files cost context on every request and are followed less well.
  • One line with IMPORTANT when Claude keeps skipping it. If everything is important, nothing stands out.

🧾Three real CLAUDE.md files

🧒 Beginner friendly📄 CLAUDE.md

Each file is short, specific and written for its own audience. Copy the one closest to your work and change the details.

CLAUDE.md for a web shop · 📄 Ready to copy
# GreenLeaf shop website

Online plant shop. Next.js front end, Node API, PostgreSQL.

## Commands
- Install: `npm ci`
- Run locally: `npm run dev` (http://localhost:3000)
- Test one file: `npx vitest run path/to/file.test.ts`
- Before every commit: `npm run lint && npm run typecheck`

## Code style
- TypeScript strict mode. No `any`.
- Prices are stored in paise as integers. Format only in the UI with `formatINR()`.
- API handlers live in `src/api/handlers/`, one file per route.

## Workflow
- Branch names: `feat/short-name` or `fix/short-name`.
- Write or update a test for every bug fix.
- IMPORTANT: never edit files in `src/generated/`. Run `npm run codegen` instead.

## Gotchas
- The payment sandbox needs `RAZORPAY_KEY_ID` in `.env.local`. Ask the user if it is missing.
- Images must go through `next/image`, the CDN rejects raw `<img>` tags.
CLAUDE.md for a data team · 📄 Ready to copy
# Sales analytics notebooks

Python 3.12 with pandas. Data comes from the `sales` schema in BigQuery.

## Commands
- Set up: `uv sync`
- Run a report: `uv run python reports/monthly.py --month 2026-09`

## Rules for numbers
- Revenue is always net of returns and GST. Use `clean.net_revenue()`.
- Months follow the financial year starting 1 April.
- Round money to 2 decimals only when printing, never in calculations.

## Output
- Charts go in `out/charts/` as PNG, 1200x700.
- Every report starts with a 3 line summary a manager can read on a phone.
CLAUDE.md for someone who does not code · 📄 Ready to copy
# My blog: "Weekend Treks Near Pune"

This folder holds my blog posts as Markdown files in `posts/`.

## Voice
- Friendly, first person, short paragraphs. Readers are beginners.
- Distances in km, heights in metres, times as "about 2 hours".

## Every new post
1. Start from `templates/post.md`.
2. File name: `posts/YYYY-MM-DD-trek-name.md`.
3. Include a "What to carry" list and a "Getting there" section.
4. Check facts against my notes in `notes/` and ask me if something is missing.
Notice what is missing: no explanation of how Next.js or pandas work, no list of every file. Claude already knows those or can look.

- My machine is Windows 11 with PowerShell. Give PowerShell commands, not bash.

Add CLAUDE.local.md to .gitignore so it is never committed. Within each folder it is read after CLAUDE.md, so your notes come last at that level.

🔗Split a long file with @ imports

📄 CLAUDE.md

Write @path/to/file anywhere in a CLAUDE.md to pull another file in. Paths are relative to the file that contains the import. Imported files may import others, up to four hops deep. A path inside backticks is not imported. Block HTML comments are removed before Claude sees the file, so you can leave notes for humans.

@ imports, expanded the way Claude Code loads them · ▶ Runs a small model of the loader
📄 CLAUDE.md
<!-- Maintainers: keep this file under 200 lines. Claude never sees this comment. -->
# GreenLeaf

See @README.md for what the project does.

## Git workflow
- @docs/git.md

## Note
Mention a file without loading it by using backticks: `@docs/old-notes.md`
📄 docs/git.md
- Branches: feat/name or fix/name
- Squash merge pull requests. See @../RELEASE.md for releases.
📄 expand.mjs
// A small model of how Claude Code reads a CLAUDE.md: block HTML comments are
// removed, and every @path import (relative to the importing file, at most four
// hops deep) is loaded too. Paths inside backticks are left alone.
import { readFileSync, existsSync } from "node:fs";
import { dirname, join } from "node:path";

const loaded = [];
function load(file, from, depth) {
  const text = readFileSync(file, "utf8").replace(/^<!--[\s\S]*?-->\n?/gm, "").trim();
  loaded.push({ file, from, text });
  for (const line of text.split("\n")) {
    if (line.includes("`")) continue;                         // `@path` in backticks is not an import
    for (const m of line.matchAll(/(^|\s)@([\w./~-]+)/g)) {
      const target = join(dirname(file), m[2]);
      if (depth < 4 && existsSync(target)) load(target, file, depth + 1);
    }
  }
}

load("CLAUDE.md", null, 0);
for (const f of loaded) {
  console.log(`=== ${f.file}` + (f.from ? `  (imported by ${f.from})` : ""));
  console.log(f.text + "\n");
}
const lines = loaded.reduce((n, f) => n + f.text.split("\n").length, 0);
console.log(`files loaded: ${loaded.length}, lines Claude sees: ${lines}`);

Imports help you organise, but they do not save context: imported files load at launch too. To load something only for certain files, use a path rule (chapter 6). To load it only for a task, use a skill (chapter 7).

The first time a project imports a file from outside the project folder, Claude Code asks you to approve it.

🤝AGENTS.md and other tools

📄 AGENTS.md📄 CLAUDE.md

Some teams already have an AGENTS.md file for other coding tools. Claude Code reads it as project instructions only when there is no CLAUDE.md, .claude/CLAUDE.md or CLAUDE.local.md in your folder or above it. If you have both, only the CLAUDE.md files load.

To use both, import one from the other:

CLAUDE.md that reuses an existing AGENTS.md · 📄 Ready to copy
@AGENTS.md

## Claude Code only
- Use plan mode before changing anything in `src/billing/`.
If someone tells you to write an "agents.md" to create Claude Code helpers, that is a different thing. Subagents live in .claude/agents/<name>.md (chapter 9). AGENTS.md at the project root is only shared project instructions.

You can change this with the Project instructions setting: read both files, only CLAUDE.md, or only your organisation's managed file.

Part 8

🧠Auto memory: notes Claude writes for itself

🧒 Beginner friendly📄 ~/.claude/projects/<project>/memory/MEMORY.md

Besides your CLAUDE.md, Claude Code keeps its own notes per project. When you correct it ("use PowerShell, not bash"), it may save that so you do not have to repeat it next week.

📘 CLAUDE.mdWritten by you. Instructions and rules. Shared with the team if committed.
🧠 Auto memoryWritten by Claude. Your preferences, corrections, project facts it cannot read from code. Stays on your machine.
What auto memory looks like on disk · 📂 Written by Claude, yours to edit
~/.claude/projects/<project>/memory/
├── MEMORY.md            # index, one line per memory, first 200 lines or 25KB load every session
├── user_role.md         # type: user       "Asha is a QA engineer, prefers PowerShell"
├── feedback_testing.md  # type: feedback   "Run only the changed test file, not the whole suite"
└── project_launch.md    # type: project    "Diwali sale launch freeze from 15 Oct 2026"
  • Memories have four types: user, feedback, project and reference.
  • Only the first 200 lines or 25KB of MEMORY.md load each session. Topic files are read when needed.
  • Turn it off with the toggle in /memory, with "autoMemoryEnabled": false in settings, or with CLAUDE_CODE_DISABLE_AUTO_MEMORY=1.
Part 9

🔁Create, check and improve it

🧒 Beginner friendly📄 CLAUDE.md
Create and check a CLAUDE.md · ⌨️ Type this in your terminal
cd ~/projects/greenleaf
claude
/init            # Claude studies the project and writes a starter CLAUDE.md
/memory          # open CLAUDE.md files and the auto memory folder to edit them
/context         # check that the file loaded, under "Memory files"
What happens

/init writes build commands, test instructions and conventions it finds. If a CLAUDE.md exists, it suggests improvements instead of overwriting it.

  1. Run /init for a first draft.
  2. Delete lines Claude could work out by itself.
  3. Add the commands, rules and gotchas only your team knows.
  4. Run /context to confirm it loaded.
  5. When Claude gets something wrong twice, add one line. When a line stops mattering, remove it.
Audit your instruction files · ⌨️ Type this in your terminal
/doctor prompt-audit                    # check every instruction file for conflicts and stale lines
/doctor prompt-audit .claude/rules      # or just one folder
What happens

Claude reports outdated or conflicting instructions with proposed edits. Nothing changes until you ask it to apply them.

🏢 Real scenario: a growing fileA team's CLAUDE.md grew to 600 lines and Claude started ignoring rules. They kept the 120 lines everyone needs, moved database rules to .claude/rules/database.md with a path filter, and turned the release checklist into a skill. Claude followed the rules again.
