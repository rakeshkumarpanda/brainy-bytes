📦Plugins: share your whole setup in one folder

🧒 Beginner friendly📄 .claude-plugin/plugin.json📄 skills/📄 agents/📄 hooks/hooks.json📄 .mcp.json

By now you have skills, agents, hooks and MCP servers. A plugin puts them in one folder so a whole team can install them with one command. Use plain .claude/ files for one project, and a plugin when several projects or people need the same setup.

A complete plugin · 📂 Folder layout
team-toolkit/
├── .claude-plugin/
│   └── plugin.json          the manifest: name, description, version, author
├── skills/
│   └── release-notes/
│       └── SKILL.md         becomes /team-toolkit:release-notes
├── agents/
│   └── reviewer.md          a subagent
├── hooks/
│   └── hooks.json           { "hooks": { ... } } same shape as in settings.json
└── .mcp.json                MCP servers the plugin brings
team-toolkit/.claude-plugin/plugin.json · 📄 Ready to copy
{
  "name": "team-toolkit",
  "description": "Our review agent, release notes skill, format hook and docs MCP server",
  "version": "1.0.0",
  "author": { "name": "Platform team" }
}
What goes where: only plugin.json goes inside .claude-plugin/. Skills, agents, hooks/hooks.json and .mcp.json sit next to that folder at the plugin root. Plugin skills are called with the plugin name in front, such as /team-toolkit:release-notes.
Check two plugin folders · ▶ Runs a check of the plugin layout rules
📄 check-plugin.mjs
// check-plugin.mjs: checks a plugin folder against the layout rules in the plugin docs.
import { existsSync, readdirSync, readFileSync, statSync } from "node:fs";
import { join } from "node:path";

for (const dir of process.argv.slice(2)) {
  const problems = [];
  const manifestPath = join(dir, ".claude-plugin", "plugin.json");
  let name = dir;
  if (existsSync(manifestPath)) {
    const m = JSON.parse(readFileSync(manifestPath, "utf8"));
    name = m.name;
    if (!m.name) problems.push("plugin.json has no name");
    else if (/\s/.test(m.name)) problems.push("name may not contain spaces");
  }
  for (const f of readdirSync(join(dir, ".claude-plugin"))) {
    if (f !== "plugin.json") problems.push(`.claude-plugin/${f} will not load: only plugin.json goes there`);
  }
  const found = [];
  if (existsSync(join(dir, "skills"))) for (const s of readdirSync(join(dir, "skills"))) {
    if (existsSync(join(dir, "skills", s, "SKILL.md"))) found.push(`skill  /${name}:${s}`);
    else problems.push(`skills/${s} has no SKILL.md`);
  }
  if (existsSync(join(dir, "agents"))) for (const a of readdirSync(join(dir, "agents"))) found.push(`agent  ${name}:${a.replace(/\.md$/, "")}`);
  if (existsSync(join(dir, "hooks", "hooks.json"))) {
    const h = JSON.parse(readFileSync(join(dir, "hooks", "hooks.json"), "utf8"));
    if (!h.hooks) problems.push('hooks/hooks.json needs a top level "hooks" key');
    else found.push("hooks  " + Object.keys(h.hooks).join(", "));
  }
  if (existsSync(join(dir, ".mcp.json"))) found.push("mcp    " + Object.keys(JSON.parse(readFileSync(join(dir, ".mcp.json"), "utf8")).mcpServers).join(", "));
  console.log(`== ${dir}`);
  for (const f of found) console.log("   " + f);
  console.log(problems.length ? problems.map(p => "   ✘ " + p).join("\n") : "   ✔ layout looks right");
}

Terminal output

   skill  /team-toolkit:release-notes
   agent  team-toolkit:reviewer
   hooks  PostToolUse

== broken-kit

Part 2

🧾claude -p: use Claude in scripts

🧒 Beginner friendly

The -p flag runs Claude Code once, prints the answer and exits. That makes it a normal command you can put in shell scripts, npm scripts and scheduled jobs.

claude -p: Claude Code inside any script · ⌨️ Type this in your terminal
# Ask once and print the answer
claude -p "What does the auth module do?"

# Pipe data in, write the answer out
cat build-error.txt | claude -p "explain the root cause in 3 lines" > why.txt

# Let it use only some tools, without prompts
claude -p "Run the tests and fix failures" --allowedTools "Bash,Read,Edit"

# Same result on every machine: skip local CLAUDE.md, hooks, plugins and MCP
claude --bare -p "Summarize README.md" --allowedTools "Read"

# Carry on the same conversation
claude -p "Review this codebase for performance issues"
claude -p "Now focus on the database queries" --continue
What happens

Exit code 0 means success, so scripts can check it. --bare needs ANTHROPIC_API_KEY because it skips your login.

FlagWhat it does
--allowedToolstools it may use without asking, in permission rule syntax
--permission-modea baseline such as acceptEdits or dontAsk
--output-formattext, json or stream-json
--json-schemathe exact shape of data you want back
--append-system-promptextra instructions on top of the default
--bareskip local hooks, skills, plugins, MCP and CLAUDE.md for repeatable runs
Part 3

🧮Get data back, not just text

Ask for JSON in a fixed shape with --json-schema. The data arrives in the structured_output field, ready for the next step of your script.

Ask for data in a fixed shape · ⌨️ Type this in your terminal
claude -p "Read invoices/*.pdf and list each customer, amount and days late" \
  --allowedTools "Read" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"invoices":{"type":"array","items":{"type":"object","properties":{"customer":{"type":"string"},"amount":{"type":"number"},"days_late":{"type":"integer"}},"required":["customer","amount","days_late"]}}},"required":["invoices"]}' \
  > result.json

📄 read-result.mjs
// read-result.mjs: a script reading the JSON that claude -p --output-format json prints.
// result.json below is a hand written example of that shape, so the script can run here without a login.
import { readFileSync } from "node:fs";

const r = JSON.parse(readFileSync("result.json", "utf8"));
if (r.is_error || !r.structured_output) {
  console.error("Claude did not return the data:", r.result);
  process.exit(1);
}
const { invoices } = r.structured_output;
const overdue = invoices.filter(i => i.days_late > 30);
console.log(`${invoices.length} invoices, ${overdue.length} more than 30 days late:`);
for (const i of overdue) console.log(` - ${i.customer}: ₹${i.amount.toLocaleString("en-IN")} (${i.days_late} days)`);
console.log("cost of this run: $" + r.total_cost_usd.toFixed(4));

$ node read-result.mjs
Terminal output

Always check that structured_output is there before you use it. If Claude could not do the task, the field is missing.

Part 4

🐙Claude in GitHub Actions

🧒 Beginner friendly📄 .github/workflows/claude.yml
  1. Run /install-github-app in Claude Code inside your repository.
  2. It installs the Claude GitHub App and saves a secret named ANTHROPIC_API_KEY (or CLAUDE_CODE_OAUTH_TOKEN for a subscription).
  3. Merge the pull request it opens with the workflow file.
  4. Write @claude in an issue or pull request comment.
Set up GitHub Actions the quick way · ⌨️ Type this in your terminal
gh auth login            # once, so Claude Code can talk to GitHub
claude
/install-github-app      # installs the app, saves the secret, opens a pull request with the workflow
.github/workflows/claude.yml: answer @claude in issues and pull requests · 📄 Ready to copy
name: Claude Code
on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
      actions: read
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
Never paste a key into a workflow file. Always use ${{ secrets.ANTHROPIC_API_KEY }}. Put your review standards in CLAUDE.md, because the action reads it too.
Part 5

⏰Run it on a schedule

📄 .github/workflows/daily-report.yml

With a prompt input, the action runs on any event, including a timer. GitHub schedules use cron lines in UTC.

.github/workflows/daily-report.yml: a weekday morning report · 📄 Ready to copy
name: Daily Report
on:
  schedule:
    - cron: "30 3 * * 1-5"      # 09:00 in India on weekdays
jobs:
  report:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      issues: read
      id-token: write
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: "Summarize yesterday's commits and open issues for the stand-up"
          claude_args: |
            --model claude-sonnet-5-5
            --max-turns 10
            --allowedTools "mcp__github__list_commits,mcp__github__list_issues"
Read a cron line in plain words · ▶ Runs
// cron.mjs: explains a five part cron line, the format GitHub Actions schedules use (always in UTC).
const DAYS = ["Sunday", "Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday"];

function explain(line) {
  const [min, hour, dom, mon, dow] = line.trim().split(/\s+/);
  const time = `${hour.padStart(2, "0")}:${min.padStart(2, "0")} UTC`;
  let when = "every day";
  if (dow === "1-5") when = "every weekday";
  else if (dow !== "*") when = "every " + dow.split(",").map(d => DAYS[+d]).join(" and ");
  if (dom !== "*") when = `on day ${dom} of every month`;
  return `${line.padEnd(14)} -> ${when} at ${time}`;
}

for (const line of ["0 9 * * *", "30 3 * * 1-5", "0 17 * * 5", "0 6 1 * *"]) console.log(explain(line));

// India is UTC + 5:30, so 03:30 UTC is 09:00 in India.
const ist = (h, m) => { const t = h * 60 + m + 330; return `${String(Math.floor(t / 60) % 24).padStart(2, "0")}:${String(t % 60).padStart(2, "0")} IST`; };
console.log("\n03:30 UTC is", ist(3, 30));
Output
0 9 * * *      -> every day at 09:00 UTC
30 3 * * 1-5   -> every weekday at 03:30 UTC
0 17 * * 5     -> every Friday at 17:00 UTC
0 6 1 * *      -> on day 1 of every month at 06:00 UTC

03:30 UTC is 09:00 IST

A plain prompt gets no shell or GitHub tools until you allow them in claude_args. GitHub runs schedules only from the default branch.

Repeat something during a session · 💬 Prompt to try
/loop 10m check whether the staging deploy finished and tell me when it does
/loop 1h /release-notes
What happens

/loop runs a prompt or a slash command again on an interval while the session is open. Leave out the interval and Claude picks the pace.

Part 6

🍳Daily automation recipes

🧒 Beginner friendly
Five daily recipes · ⌨️ Type this in your terminal
# 1. Commit message from staged changes
claude -p "Write a commit message for my staged changes and commit" \
  --allowedTools "Bash(git diff *),Bash(git status *),Bash(git commit *)"

# 2. Typo check on a pull request diff (in package.json scripts)
git diff main | claude -p "list each typo as file:line then the fix. nothing else."

# 3. Meeting notes to action items
claude -p "Turn notes/standup.md into a table of owner, task and due date" > actions.md

# 4. Clean a messy spreadsheet export
claude -p "Read sales.csv, fix the date formats to YYYY-MM-DD, remove duplicate rows, save clean.csv" \
  --allowedTools "Read,Write"

# 5. Explain a failing build in CI
npm test 2>&1 | tail -80 | claude -p "explain why this failed and the smallest fix"
🏢 Real scenario: an accounts teamEvery Monday a scheduled job runs the invoice script from this chapter. It reads the PDFs, returns JSON, and the script posts the list of invoices more than 30 days late to the team channel. Nobody opens a spreadsheet.
A safe recipe has four parts: a clear prompt, the smallest --allowedTools list, an output you can check (a file, JSON or an exit code), and --max-turns so it cannot run for ever.
