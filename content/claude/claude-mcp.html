Part 1

🔌What MCP is

🧒 Beginner friendly

MCP (Model Context Protocol) is an open standard that lets Claude use tools and data from other programs: your issue tracker, a database, a calendar, or a script you wrote yourself. One program, the MCP server, offers the tools. Claude Code, Claude Desktop and claude.ai are MCP clients that connect to it.

A server can offerWhat it isHow you use it
Toolsactions Claude can run, like "add expense"Claude calls them when they fit your request
Resourcesread only data, like a file or a recordtype @server:uri in your prompt
Promptsready made prompt templatestype /mcp__server__prompt
Part 2

🧷Connect a server, step by step

🧒 Beginner friendly
  1. Find a server: the Anthropic Directory, or the vendor's own docs.
  2. Run claude mcp add in your terminal, outside a session.
  3. Check it with claude mcp list, or /mcp inside a session.
  4. If it needs a login, open /mcp and pick it to sign in.
  5. Ask for something the server can do.
Your first MCP server in three steps · ⌨️ Type this in your terminal
# 1. Add the free Claude Code docs server (no login needed)
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp

# 2. Check it connected
claude mcp list

# 3. Use it
claude
> Use the claude-code-docs server to find how hooks block a command
What happens

claude mcp list shows the server with a connected tick. In the session Claude calls the server's search tool and answers from the official pages.

Adding and managing servers · ⌨️ Type this in your terminal
# A hosted (remote) server: use http
claude mcp add --transport http notion https://mcp.notion.com/mcp

# A remote server that needs a key in a header
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer your-token"

# A local program (stdio). Everything after -- is the command that starts it
claude mcp add --transport stdio --env AIRTABLE_API_KEY=YOUR_KEY airtable \
  -- npx -y airtable-mcp-server

# Manage
claude mcp list            # all servers
claude mcp get notion      # one server
claude mcp remove notion   # remove it
/mcp                       # inside a session: status, sign in, tools
What happens

http is for hosted services and is the recommended remote transport. stdio starts a program on your computer. SSE still works but is deprecated.

For a local server, the -- matters. Everything after it is the command that starts the server, so flags like --port go to the server and not to Claude.

📍Scopes and the .mcp.json file

📄 .mcp.json📄 ~/.claude.json
ScopeLoads inShared with teamStored in
local (default)this project onlyno~/.claude.json, under this project
projectthis project onlyyes, through git.mcp.json at the project root
userall your projectsno~/.claude.json
Choosing a scope · ⌨️ Type this in your terminal
claude mcp add --transport http stripe https://mcp.stripe.com                    # local (default)
claude mcp add --transport http shared --scope project https://example.com/mcp  # writes .mcp.json
claude mcp add --transport http hubspot --scope user https://mcp.hubspot.com/anthropic
claude mcp reset-project-choices   # forget your approvals of .mcp.json servers
.mcp.json (at the project root, committed for the team) · 📄 Ready to copy
{
  "mcpServers": {
    "claude-code-docs": {
      "type": "http",
      "url": "https://code.claude.com/docs/mcp"
    },
    "expenses": {
      "type": "stdio",
      "command": "node",
      "args": ["${CLAUDE_PROJECT_DIR:-.}/mcp/server.mjs"]
    },
    "company-api": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}
What goes in .mcp.json: one entry per server under mcpServers. Each has a type (http or stdio), then url and headers for http, or command, args and env for stdio. Never write a real key here. Use ${API_KEY} so each person's key comes from their own environment, and ${VAR:-default} for a fallback.
The file is .mcp.json at the project root. Claude Code does not read ~/.claude/mcp.json or .claude/.mcp.json. An http entry without "type" is an error, because an entry with no type is read as stdio.

When the same name is in several scopes, local wins, then project, then user. Claude Code asks once before it uses servers from a project's .mcp.json.

Part 4

🟩Build your own server in Node.js

🧒 Beginner friendly📄 server.mjs📄 package.json

Here is a server that saves expenses. Claude will be able to say "Saved team lunch for ₹850" because it called your code.

  1. Make a folder and install the SDK and zod.
  2. Write server.mjs: create an McpServer, register each tool with a name, a description and an input schema, then connect over stdio.
  3. Test it with a small client before you add it to Claude.
  4. Add it with claude mcp add and ask Claude to use it.
Set up a Node.js server project · ⌨️ Type this in your terminal
mkdir expenses-mcp && cd expenses-mcp
npm init -y
npm pkg set type=module
npm install @modelcontextprotocol/sdk zod
# write server.mjs (below), then test it (below), then:
claude mcp add --transport stdio expenses -- node "$PWD/server.mjs"
server.mjs · 📄 Ready to copy
// server.mjs: a small MCP server that saves expenses to a file.
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";
import { readFileSync, writeFileSync, existsSync } from "node:fs";

const FILE = "expenses.json";
const load = () => (existsSync(FILE) ? JSON.parse(readFileSync(FILE, "utf8")) : []);

const server = new McpServer({ name: "expenses", version: "1.0.0" });

// Tool 1: save one expense. The description tells Claude when to use it.
server.registerTool("add_expense", {
  title: "Add an expense",
  description: "Save one expense with what it was for and the amount in rupees.",
  inputSchema: {
    item: z.string().describe("What the money was spent on"),
    amount: z.number().positive().describe("Amount in rupees"),
  },
}, async ({ item, amount }) => {
  const list = load();
  list.push({ item, amount });
  writeFileSync(FILE, JSON.stringify(list, null, 2));
  return { content: [{ type: "text", text: `Saved ${item} for ₹${amount}. Expenses saved: ${list.length}.` }] };
});

// Tool 2: add everything up.
server.registerTool("total_spent", {
  title: "Total spent",
  description: "Add up every saved expense and say the total in rupees.",
  inputSchema: {},
}, async () => {
  const total = load().reduce((sum, e) => sum + e.amount, 0);
  return { content: [{ type: "text", text: `Total spent: ₹${total}` }] };
});

// stdio servers talk on stdin and stdout, so log to stderr only.
await server.connect(new StdioServerTransport());
console.error("expenses MCP server is running");
Start the server and call its tools · ▶ A real MCP client talks to the real server
📄 try-it.mjs
// try-it.mjs: plays the part of Claude Code. It starts the server, lists its tools and calls them.
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";

const client = new Client({ name: "try-it", version: "1.0.0" });
await client.connect(new StdioClientTransport({ command: "node", args: ["server.mjs"], stderr: "ignore" }));

const { tools } = await client.listTools();
console.log("Tools the server offers:");
for (const t of tools) console.log(" -", t.name + ":", t.description);

const call = async (name, args = {}) => {
  const r = await client.callTool({ name, arguments: args });
  console.log(`${name}(${JSON.stringify(args)}) ->`, r.isError ? "ERROR " : "", r.content[0].text.split("\n")[0]);
};
await call("add_expense", { item: "auto rickshaw", amount: 120 });
await call("add_expense", { item: "team lunch", amount: 850 });
await call("total_spent");
await call("add_expense", { item: "refund", amount: -50 });   // the schema says positive, so this is refused

await client.close();
Terminal
$ node try-it.mjs
Terminal output

 - total_spent: Add up every saved expense and say the total in rupees.
add_expense({"item":"auto rickshaw","amount":120}) ->  Saved auto rickshaw for ₹120. Expenses saved: 1.

What makes a good tool: a short verb name like add_expense, a description that says when to use it, an input schema with a description on every field, and a reply that tells Claude what happened. Never console.log in a stdio server, because stdout carries the messages. Use console.error.

🐍Build your own server in Python

🧒 Beginner friendly📄 timetable.py

The same idea in Python: a school timetable that a child could ask about. The function's type hints become the input schema and the docstring becomes the description.

Set up a Python server project · ⌨️ Type this in your terminal
mkdir timetable-mcp && cd timetable-mcp
python3 -m venv .venv && source .venv/bin/activate
pip install "mcp>=2"
# write timetable.py (below), then:
claude mcp add --transport stdio timetable -- "$PWD/.venv/bin/python" "$PWD/timetable.py"
timetable.py · 📄 Ready to copy
# timetable.py: a small MCP server in Python with one tool and one resource.
from mcp.server import MCPServer

mcp = MCPServer("timetable")

TIMETABLE = {
    "monday": ["Maths", "English", "Science", "Art"],
    "tuesday": ["Hindi", "Maths", "Games", "Computers"],
}


@mcp.tool()
def classes_on(day: str) -> str:
    """List the classes for one school day, for example monday."""
    lessons = TIMETABLE.get(day.lower())
    if not lessons:
        return f"No timetable saved for {day}."
    return f"{day.title()}: " + ", ".join(lessons)


@mcp.resource("timetable://week")
def whole_week() -> str:
    """The whole week's timetable."""
    return "\n".join(f"{d}: {', '.join(l)}" for d, l in TIMETABLE.items())


if __name__ == "__main__":
    mcp.run()   # stdio by default
Start the Python server and use it · ▶ The Python server answers a real MCP client
📄 try-python.mjs
// try-python.mjs: starts the Python server the same way Claude Code would and uses it.
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";

const client = new Client({ name: "try-python", version: "1.0.0" });
await client.connect(new StdioClientTransport({ command: process.env.PY, args: ["timetable.py"], stderr: "ignore" }));

const { tools } = await client.listTools();
for (const t of tools) console.log("tool:", t.name, "| input:", JSON.stringify(t.inputSchema.properties));

for (const day of ["Monday", "sunday"]) {
  const r = await client.callTool({ name: "classes_on", arguments: { day } });
  console.log(`classes_on(${day}) ->`, r.content[0].text);
}

const { resources } = await client.listResources();
console.log("resources:", resources.map(r => r.uri).join(", "));
const week = await client.readResource({ uri: "timetable://week" });
console.log(week.contents[0].text);
await client.close();

Part 6

📨What travels between Claude and a server

Under the hood, MCP is a conversation of small JSON messages (JSON-RPC). For a stdio server they go one per line on stdin and stdout. First a handshake, then Claude asks for the tool list, then it calls a tool.

The JSON messages on the wire · ▶ Every line below was really sent and received
📄 wire.mjs
// wire.mjs: shows the exact JSON messages that travel between Claude Code and an MCP server.
import { spawn } from "node:child_process";
import { createInterface } from "node:readline";

const server = spawn("node", ["server.mjs"], { stdio: ["pipe", "pipe", "ignore"] });
const replies = createInterface({ input: server.stdout });
const waiting = new Map();
replies.on("line", line => { const m = JSON.parse(line); waiting.get(m.id)?.(m); });

let id = 0;
const send = (method, params) => new Promise(resolve => {
  const msg = { jsonrpc: "2.0", id: ++id, method, params };
  console.log("CLAUDE CODE ->", JSON.stringify(msg));
  waiting.set(id, m => { console.log("SERVER      <-", JSON.stringify(m.result).slice(0, 150) + "\n"); resolve(m); });
  server.stdin.write(JSON.stringify(msg) + "\n");
});

await send("initialize", { protocolVersion: "2025-11-25", capabilities: {}, clientInfo: { name: "demo", version: "1" } });
server.stdin.write(JSON.stringify({ jsonrpc: "2.0", method: "notifications/initialized" }) + "\n");
await send("tools/list", {});
await send("tools/call", { name: "add_expense", arguments: { item: "chai", amount: 20 } });
server.kill();

Terminal output

Each tool's name, description and schema are what Claude reads to decide when to call it. That is why clear descriptions matter so much.

🎛️Using MCP inside Claude Code

🧒 Beginner friendly📄 .claude/settings.json
Using tools, resources and prompts · 💬 Prompt to try
Add a ₹450 expense for printer ink, then tell me the total
Compare @github:issue://123 with @docs:file://api/authentication
/mcp__github__pr_review 456
What happens

Claude calls mcp__expenses__add_expense and mcp__expenses__total_spent. The @ mentions pull in two resources. The slash command runs a prompt the github server offers.

Every MCP tool gets a full name mcp__<server>__<tool>. Use that name in permission rules, in a skill's allowed-tools, in an agent's tools and in hook matchers.

.claude/settings.json: rules for MCP tools · 📄 Ready to copy
{
  "permissions": {
    "allow": ["mcp__expenses__*", "mcp__claude-code-docs__*"],
    "ask":   ["mcp__github__create_pull_request"],
    "deny":  ["mcp__company-api__delete_customer"]
  }
}
  • Claude warns when one tool result is over 10,000 tokens. The default limit is 25,000, set by MAX_MCP_OUTPUT_TOKENS.
  • Tool search loads only tool names at start and fetches full definitions when needed, so many servers cost little context.
  • Only add servers you trust. A server can read what you send it and its replies go into Claude's context.

🖥️The same servers in Claude Desktop

📄 claude_desktop_config.json

The Claude Desktop chat app reads its own file, claude_desktop_config.json. Open it from Settings, then Developer, then Edit Config. On macOS it is in ~/Library/Application Support/Claude/ and on Windows in %APPDATA%\Claude\. Use full paths, then restart the app.

claude_desktop_config.json (Claude Desktop app) · 📄 Ready to copy
{
  "mcpServers": {
    "expenses": {
      "command": "node",
      "args": ["/Users/asha/expenses-mcp/server.mjs"]
    },
    "timetable": {
      "command": "/Users/asha/timetable-mcp/.venv/bin/python",
      "args": ["/Users/asha/timetable-mcp/timetable.py"]
    }
  }
}
Moving between Claude Desktop and Claude Code · ⌨️ Type this in your terminal
claude mcp add-from-claude-desktop   # copy Desktop servers into Claude Code (macOS, WSL)
claude mcp serve                     # run Claude Code itself as an MCP server for other apps
