Part 1

🧠Context engineering in one sentence

🧒 Beginner friendly

Prompt engineering is about how you ask. Context engineering is about everything Claude can see when it answers: instructions, files, tools, past messages and notes. Anthropic describes it as finding the smallest set of high value tokens that gives the result you want.

✍️ Prompt engineeringWriting one good request.
🧠 Context engineeringDeciding what goes into the window, when it is loaded, and what is left out, across many turns.
A student with a huge pile of photocopies does worse in an open book exam than one with five well chosen pages. Claude is the same.
Part 2

🫧Why more is not always better

🧒 Beginner friendly

Claude's attention is a limited budget. Every extra token takes a little of it. As the window fills, the model gets slightly worse at recalling any one fact. Anthropic calls this context rot. So even with a one million token window, a focused context gives better answers than a stuffed one.

In Claude Code, run /context to see the real numbers for your session. The biggest item is usually files read and old conversation, not your instructions.
Part 3

🎚️Write instructions at the right altitude

📄 CLAUDE.md📄 SKILL.md📄 system prompt

A system prompt, CLAUDE.md or SKILL.md can be too low (a long list of brittle if this then that rules) or too high (vague advice that assumes Claude knows your business). The right altitude gives a clear goal, the principles to decide with, and only the few hard rules that matter.

Three system prompts at different altitudes · 📄 Ready to copy
<!-- Too low: brittle if-else rules -->
If the customer says "refund" reply with template R1.
If the customer says "return" reply with template R2.
If the customer says "money back" reply with template R1.

<!-- Too high: vague, assumes shared context -->
Be helpful to customers.

<!-- Right altitude: clear goal, principles and the few rules that matter -->
## Goal
Resolve the customer's issue in one reply when possible.

## How to decide
- Money back requests of any wording follow the refund policy in policies/refunds.md.
- If the order is older than 30 days, explain the policy kindly and offer store credit.
- If you are not sure which policy applies, ask one clarifying question.

Organise long instructions into sections with headings or tags, such as background, steps, tools and output format. Start small, test, and add a line only when Claude gets something wrong.

Part 4

🔧Tools and examples are context too

Every tool Claude has comes with a name and description that sit in the context. Good tool sets are small, do not overlap and have clear names. If a human could not say which of two tools fits a job, Claude cannot either.

Examples work the same way. A few varied, typical examples teach more than a long list of every edge case.

  • One tool per clear job: search_orders, refund_order, not three tools that all "get order data".
  • Tools that return short, useful results, not a whole database table.
Part 5

🎯Just in time retrieval

🧒 Beginner friendly

Do not paste everything up front. Give Claude light pointers such as file paths, a list of document titles or a search tool, and let it load details only when a question needs them. Claude Code works this way: it keeps file paths and uses search and read tools instead of reading your whole project at the start.

A mix often works best: load a little up front (like CLAUDE.md) and fetch the rest on demand (files, skills, MCP tools).

Part 6

⏳Long tasks: compaction, notes and subagents

Some jobs run for hours and outgrow any window. Three techniques keep them on track.

1. Compaction. Summarise the old conversation and continue with the summary plus the latest turns. Claude Code does this automatically near the limit.

2. Structured notes. Claude writes progress to a file such as progress.json, a to do list or NOTES.md. A fresh session reads it and carries on.

A progress file Claude keeps and a fresh session reads first · 📄 Ready to copy
# NOTES.md: invoice clean-up, started 2026-10-19

## Done
- Fixed date formats in invoices 001 to 140
- Removed 12 duplicate rows (list in duplicates.csv)

## Next
- Invoices 141 to 300
- Check the 3 invoices with a missing GST number (ids in todo.csv)

## Decisions
- Amounts stay in paise as whole numbers. Format only in the final report.

3. Subagents. A helper explores in its own clean window and returns only a short summary. Chapter 9 builds them.

Send a big investigation to a subagent · 💬 Prompt to try
Use a subagent to read every file in src/payments/ and find where refunds are calculated.
Report back only: the file names, the function names, and one line on what each does.
What happens

The subagent reads dozens of files in its own context. Your main conversation receives a short list, not thousands of lines of code.

Part 7

💻Context tools in Claude Code

🧒 Beginner friendly📄 CLAUDE.md📄 SKILL.md📄 .mcp.json

Claude Code gives you direct control over the window.

Context commands in Claude Code · ⌨️ Type this in your terminal
/context                        # see what is using the window right now
/clear                          # start fresh when you switch to unrelated work
/compact keep the API changes and the failing test names
/btw what was the port number again?     # quick side question, not saved to history
What happens

/context prints a breakdown by category, including which CLAUDE.md and memory files loaded. /compact replaces the history with a summary that keeps what you asked for.

FeatureWhen it loadsContext cost
CLAUDE.mdsession startevery request, full text
Skillsdescription at start, body when usedlow until used
MCP serverstool names at start, full details on demandlow until a tool is used
Subagentswhen startedseparate window, only the summary comes back
Hookson events, run outside Claudezero unless the hook returns text

After compaction, the project root CLAUDE.md, rules without paths, and auto memory are loaded again from disk. Rules with paths and nested CLAUDE.md files come back only when Claude touches a matching file again. Skill bodies come back capped at 5,000 tokens each, keeping the start, so put the key steps at the top of a SKILL.md.

Part 8

✅A context checklist for any task

🧒 Beginner friendly📄 CLAUDE.md📄 .claude/rules/📄 SKILL.md📄 .claude/agents/
  1. Always needed? Put it in CLAUDE.md or project instructions. Keep it short.
  2. Needed for one kind of task? Put it in a skill.
  3. Needed only for some files? Put it in a path rule in .claude/rules/.
  4. Big and only sometimes needed? Leave it in files and let Claude search.
  5. Noisy investigation? Send it to a subagent.
  6. Long job? Keep a progress file and use /compact with a focus.
  7. New topic? /clear or a new chat.
