Part 1

🧰What a skill is

🧒 Beginner friendly📄 SKILL.md

A skill is a folder with a file called SKILL.md. The top of the file has a short description of when to use it. The rest has the steps. Claude Code, claude.ai and the API all use this format.

Skills use progressive disclosure, which means Claude reads them in layers and only as far as it needs:

LevelWhen it loadsSize
1. name and descriptionalways, at startabout 100 tokens per skill
2. the body of SKILL.mdwhen the skill is usedkeep it under 5,000 tokens
3. other files and scriptsonly if the steps point to themscripts run, only their output is read
Use a skill when you notice you are pasting the same instructions for the third time.
Part 2

🚀Build your first skill in three steps

🧒 Beginner friendly📄 ~/.claude/skills/<name>/SKILL.md
  1. Make a folder named after the skill in ~/.claude/skills/ (just for you) or .claude/skills/ (for the team).
  2. Create SKILL.md inside it with a description at the top and the steps below.
  3. Start Claude Code and either ask naturally or type / and the folder name.
~/.claude/skills/summarize-changes/SKILL.md · 📄 Ready to copy
---
description: Summarizes uncommitted changes and flags anything risky. Use when the user asks what changed, wants a commit message, or asks to review their diff.
---

## Current changes

!`git diff HEAD`

## Instructions

Summarize the changes above in two or three bullet points, then list any risks
you notice such as missing error handling, hardcoded values, or tests that need
updating. If the diff is empty, say there are no uncommitted changes.
Create and try it · ⌨️ Type this in your terminal
mkdir -p ~/.claude/skills/summarize-changes
# save the file above as ~/.claude/skills/summarize-changes/SKILL.md
claude
> what did I change?              # Claude picks the skill because the description matches
> /summarize-changes              # or run it yourself by name
What happens

Claude answers with two or three bullets about your real diff and a list of risks. The git diff was pasted into the skill before Claude read it.

The line !`git diff HEAD` is dynamic context: Claude Code runs the command first and pastes the output into the skill, so Claude reads your real changes.

🏷️The front matter: what goes at the top

📄 SKILL.md

Every field is optional, but description matters most: Claude reads it to decide when to use the skill. Put the main use first and include the words people actually type.

Part 5

🔣Arguments and live data

📄 SKILL.md

Text typed after the skill name becomes its arguments. Use $ARGUMENTS for all of it, $0, $1 for each word (counting from zero), or names listed in arguments. Lines with !`command` are replaced by the command's output before Claude sees the skill.

.claude/skills/standup/SKILL.md · 📄 Ready to copy
---
name: standup
description: Writes my daily stand-up update from yesterday's git commits. Use when I ask for a standup, daily update or what I did yesterday.
argument-hint: "[name] [date]"
arguments: [person, day]
---

Write a stand-up update for $person for $day.

## Commits since yesterday
!`git log --since=yesterday --pretty=format:"- %s"`

## Open tasks
!`cat TODO.md`

## Format
Three headings: Done, Doing, Blocked. At most 3 bullets each. Plain English, no commit hashes.

Here is a small program that does the same steps on a real git repository, so you can see exactly what Claude would receive.

What Claude receives after /standup Asha 2026-10-19 · ▶ Runs a model of skill rendering with a real git repository
📄 render.mjs
// A model of what Claude Code does when a skill is invoked: drop the front matter,
// put the arguments in place of $ARGUMENTS, $0, $1 and named arguments, then run each
// !`command` line and paste its output in, so Claude receives real data.
import { readFileSync } from "node:fs";
import { execSync } from "node:child_process";

function render(path, args) {
  const text = readFileSync(path, "utf8");
  const [, front, body] = text.match(/^---\n([\s\S]*?)\n---\n([\s\S]*)$/);
  const names = (front.match(/^arguments:\s*\[(.*)\]/m)?.[1] ?? "").split(",").map(s => s.trim()).filter(Boolean);
  let out = body.replace(/\$ARGUMENTS\[(\d+)\]|\$(\d+)|\$ARGUMENTS/g, (all, a, b) =>
    a ?? b ? (args[Number(a ?? b)] ?? all) : args.join(" "));
  names.forEach((n, i) => { out = out.replaceAll("$" + n, args[i] ?? ""); });
  return out.replace(/(^|\s)!`([^`]+)`/g, (all, pre, cmd) => pre + execSync(cmd, { encoding: "utf8" }).trim());
}

console.log(render(".claude/skills/standup/SKILL.md", ["Asha", "2026-10-19"]).trim());

📎Supporting files and scripts

📄 SKILL.md📄 checklist.md📄 scripts/totals.py

Keep SKILL.md short (under 500 lines) and put detail in other files in the same folder. Link to them from SKILL.md so Claude knows when to open them. Scripts are run, not read, so a long script costs almost nothing in context.

.claude/skills/invoice-checker/SKILL.md · 📄 Ready to copy
---
name: invoice-checker
description: Checks supplier invoices for arithmetic errors and missing details. Use when the user shares an invoice CSV or PDF, or asks to verify, audit or check an invoice.
allowed-tools: Bash(python ${CLAUDE_SKILL_DIR}/scripts/totals.py *)
---

# Invoice checker

1. If the invoice is a CSV, run:
   `python ${CLAUDE_SKILL_DIR}/scripts/totals.py <file>`
   Trust the script's arithmetic. Do not redo the sums yourself.
2. Check the invoice against [checklist.md](checklist.md).
3. Reply with:
   - RESULT line from the script
   - each problem as one bullet with the line item and the amount
   - a two sentence email to the supplier if anything is wrong
.claude/skills/invoice-checker/checklist.md · 📄 Ready to copy
# Invoice checklist
- Supplier GSTIN present and 15 characters long
- Invoice number and date present
- Our PO number quoted (format PO-2026-xxxx)
- Payment terms are 30 days or more
The skill's script, run on a real invoice · 🐍 Python script run for real
📄 .claude/skills/invoice-checker/scripts/totals.py
"""Add up an invoice CSV and check it against the total line. Prints a short report."""
import csv
import sys

rows = list(csv.DictReader(open(sys.argv[1], encoding="utf-8")))
items = [r for r in rows if r["item"] != "TOTAL"]
stated = next(float(r["amount"]) for r in rows if r["item"] == "TOTAL")
computed = round(sum(float(r["qty"]) * float(r["rate"]) for r in items), 2)

for r in items:
    line = round(float(r["qty"]) * float(r["rate"]), 2)
    flag = "" if abs(line - float(r["amount"])) < 0.01 else "   <-- line amount does not match qty x rate"
    print(f'{r["item"]:<18} {r["qty"]:>3} x {float(r["rate"]):>8.2f} = {float(r["amount"]):>9.2f}{flag}')
print(f"{'stated total':<34} {stated:>9.2f}")
print(f"{'computed total':<34} {computed:>9.2f}")
print("RESULT:", "OK" if abs(stated - computed) < 0.01 else f"MISMATCH of {round(stated - computed, 2)}")

The best first skills are jobs you already do every week. Here are two more to copy.

Daily work: meeting notes to actions · 📄 Ready to copy
---
name: meeting-actions
description: Turns raw meeting notes or a transcript into a clean action list with owners and dates. Use when the user pastes meeting notes, a transcript or asks for action items.
---

From the notes the user gave:

1. List decisions made, one line each.
2. List action items as a table: Owner, Task, Due date.
   If no owner is named, write "Owner needed". If no date, write "No date".
3. List open questions.
4. Write a 3 line summary email the organiser can send.

Use the names exactly as written in the notes.
Daily work: commit messages · 📄 Ready to copy
---
name: commit
description: Stage and commit the current changes with a clear message
disable-model-invocation: true
allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *) Bash(git diff *)
---

1. Run `git status` and `git diff` to see what changed.
2. Write a commit message: a summary line under 60 characters in the imperative

☁️Skills in claude.ai and the API

📄 SKILL.md📄 skill.zip

The same folder can be uploaded to claude.ai as a ZIP, or sent through the Skills API. Uploads follow the open Agent Skills format, which is stricter than Claude Code:

  • Only six front matter fields: name, description, license, compatibility, metadata, allowed-tools.
  • name: up to 64 characters, lowercase letters, numbers and hyphens, and it may not contain "anthropic" or "claude".
  • description: not empty, up to 1,024 characters, no XML tags.
  • Claude Code only features such as !`command` do not work in claude.ai or the API.

📄 validate.mjs
// Checks the front matter rules that claude.ai uploads and the Skills API enforce.
// Claude Code accepts more fields, but an upload with any other key is rejected.
import { readFileSync } from "node:fs";

const ALLOWED = ["name", "description", "license", "compatibility", "metadata", "allowed-tools"];

function check(path) {
  const front = readFileSync(path, "utf8").match(/^---\n([\s\S]*?)\n---/)[1];
  const keys = [...front.matchAll(/^([\w-]+):/gm)].map(m => m[1]);
  const get = k => (front.match(new RegExp("^" + k + ":\\s*(.*)$", "m")) || [])[1] || "";
  const name = get("name"), desc = get("description");
  const errors = [];
  const extra = keys.filter(k => !ALLOWED.includes(k));
  if (extra.length) errors.push("unexpected key(s): " + extra.join(", "));
  if (!/^[a-z0-9-]{1,64}$/.test(name)) errors.push("name must be 1-64 lowercase letters, numbers or hyphens");
  if (/anthropic|claude/i.test(name)) errors.push('name may not contain "anthropic" or "claude"');
  if (!desc || desc.length > 1024) errors.push("description must be 1-1024 characters");
  if (/<[^>]+>/.test(name + desc)) errors.push("no XML tags in name or description");
  console.log(path.padEnd(28), errors.length ? "FAIL\n  - " + errors.join("\n  - ") : "OK");
}

check("invoice-checker/SKILL.md");
check("claude-helper/SKILL.md");

Part 10

💡Make skills that work every time

🧒 Beginner friendly📄 SKILL.md
  • Description first. If a skill does not trigger, add the words people really use to its description.
  • Key steps at the top. After compaction a skill keeps only its first 5,000 tokens.
  • Say what to do, not long reasons. The body stays in context once loaded, so every line has a cost.
  • Scripts for exact work like sums, dates and file conversions.
  • Test it with three real requests, then fix the description or steps. The skill-creator plugin can run tests on a skill for you.
  • /skills lists every skill, and you can sort by token cost to find heavy ones.
