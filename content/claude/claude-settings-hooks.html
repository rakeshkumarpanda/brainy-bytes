Part 1

⚙️The settings files and which one wins

🧒 Beginner friendly📄 ~/.claude/settings.json📄 .claude/settings.json📄 .claude/settings.local.json

Settings are plain JSON files. Each one has a different reach. When two files set the same key, the higher one in this list wins. Lists such as permission rules are combined from all files.

PriorityFileReaches
1 (highest)managed settings from your organisationeveryone on managed machines, cannot be overridden
2--settings on the command linethis one session
3.claude/settings.local.jsonyou, in this project (not committed)
4.claude/settings.jsonthe whole team, through git
5~/.claude/settings.jsonyou, in every project
Settings files are strict JSON. A comment or a trailing comma breaks the file. Add the $schema line to get autocomplete and checks in your editor, and run /status to confirm what loaded.
Part 2

🚦Permission rules: allow, ask and deny

🧒 Beginner friendly📄 .claude/settings.json

A rule names a tool, and optionally what it may touch: Bash(npm run test *), Read(./.env), Edit(src/**), WebFetch(domain:example.com). A * matches anything.

  • allow: run without asking.
  • ask: always ask, even in a relaxed mode.
  • deny: never run.

Rules are checked deny first, then ask, then allow. An allow rule can never make an exception to a deny rule.

deny, then ask, then allow · ▶ Runs
// A model of how Claude Code checks permission rules for a Bash command:
// deny first, then ask, then allow. The first list with a match decides.
const rules = {
  deny:  ["Bash(rm *)", "Bash(curl *)"],
  ask:   ["Bash(git push *)"],
  allow: ["Bash(npm run *)", "Bash(git *)"],
};

function matches(rule, cmd) {
  const pattern = rule.slice(5, -1);                       // text inside Bash(...)
  const re = new RegExp("^" + pattern.split("*").map(s => s.replace(/[.+?^${}()|[\]\\]/g, "\\$&")).join(".*") + "$");
  return re.test(cmd);
}

function decide(cmd) {
  for (const list of ["deny", "ask", "allow"]) {
    if (rules[list].some(r => matches(r, cmd))) return list;
  }
  return "ask (no rule, so the mode decides)";
}

for (const cmd of ["npm run test", "git status", "git push origin main", "rm -rf build", "/bin/rm -rf build", "python manage.py migrate"]) {
  console.log(cmd.padEnd(26), "->", decide(cmd));
}
Output
npm run test               -> allow
git status                 -> allow
git push origin main       -> ask
rm -rf build               -> deny
/bin/rm -rf build          -> ask (no rule, so the mode decides)
python manage.py migrate   -> ask (no rule, so the mode decides)
Look at the /bin/rm line. Pattern rules match the command as written, so Bash(rm *) does not catch /bin/rm or bash -c 'rm ...'. Use deny rules for clear cases and a hook for anything that truly must be stopped.

  • .claude/settings.json: safe commands to allow, risky ones to ask about, secrets to deny, team hooks.
  • ~/.claude/settings.json: your model, your default mode, your personal hooks such as notifications.
  • .claude/settings.local.json: your local URLs and extra allows. "Yes, and don't ask again" writes here.

A safety detail: defaultMode values auto and bypassPermissions are ignored in project files, so a repository cannot switch your safety checks off. Allow rules in a project file apply only after you trust the folder. Deny and ask rules apply straight away.

Part 4

🪝Hooks: code that runs on events

🧒 Beginner friendly📄 settings.json📄 .claude/hooks/

A hook is a command Claude Code runs at a fixed moment, such as just before a tool runs or when Claude is waiting for you. Unlike CLAUDE.md, a hook always runs. It is your tool for rules that must never be broken and for automation that must happen every time.

EventFiresTypical use
SessionStarta session begins or resumesload fresh facts
UserPromptSubmityou send a promptadd context, block secrets in prompts
PreToolUsebefore a tool runs, can block itstop dangerous commands, protect files
PostToolUseafter a tool succeedsformat, lint, log
NotificationClaude needs your attentiondesktop alert
StopClaude finishes its answerrun checks before it stops
PreCompact, SessionEndbefore compaction, at the endsave notes, clean up

Each hook gets a JSON description of the event on stdin. It replies with an exit code: 0 means no objection, 2 means block, and the text on stderr is sent to Claude as the reason. For finer control it can print JSON instead.

⛔Hook 1: block dangerous commands

🧒 Beginner friendly📄 .claude/hooks/block-dangerous.mjs📄 .claude/settings.json
  1. Save the script in .claude/hooks/.
  2. Register it under PreToolUse with the matcher Bash in .claude/settings.json.
  3. Use "$CLAUDE_PROJECT_DIR" in the command so it works from any folder.
  4. Test it by piping a sample event into it, exactly as below.
Block dangerous commands · 🪝 Hook run for real with the JSON Claude Code sends
📄 .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block-dangerous.mjs"
          }
        ]
      }
    ]
  }
}
📄 .claude/hooks/block-dangerous.mjs
// PreToolUse hook for Bash: block a few commands that should never run.
// Claude Code sends the tool call as JSON on stdin.
let raw = "";
for await (const chunk of process.stdin) raw += chunk;
const { tool_input } = JSON.parse(raw);
const cmd = tool_input.command ?? "";

const banned = [
  [/\brm\s+-rf\s+(\/|~|\*)/, "deleting whole folders is not allowed"],
  [/git\s+push\b.*--force/, "force pushing is not allowed, open a pull request instead"],
  [/drop\s+table/i, "dropping tables is not allowed"],
];

for (const [pattern, reason] of banned) {
  if (pattern.test(cmd)) {
    console.error(`Blocked: ${reason}. Command was: ${cmd}`);   // stderr goes back to Claude
    process.exit(2);                                              // exit 2 = block this tool call
  }
}
process.exit(0);                                                  // exit 0 = no objection

🔒Hook 2: protect secret files, with a JSON answer

📄 .claude/hooks/protect-files.mjs

Instead of an exit code, a PreToolUse hook can print JSON with permissionDecision set to deny, ask or allow, plus a reason Claude will read.

Protect secret and generated files · 🪝 Hook run for real with the JSON Claude Code sends
📄 .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.mjs"
          }
        ]
      }
    ]
  }
}
📄 .claude/hooks/protect-files.mjs
// PreToolUse hook for Edit and Write: refuse to touch secret or generated files.
// It answers with JSON instead of an exit code, so it can give a clear reason.
let raw = "";
for await (const chunk of process.stdin) raw += chunk;
const file = (JSON.parse(raw).tool_input.file_path ?? "").replaceAll("\\", "/");

const protectedParts = [".env", "package-lock.json", ".git/", "src/generated/"];
const hit = protectedParts.find(p => file.includes(p));

if (hit) {
  console.log(JSON.stringify({
    hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: `${file} is protected (${hit}). Ask the user to change it by hand.`,
    },
  }));
}
Terminal
$ echo '{"session_id": "abc123", "cwd": "/home/asha/shop", "hook_event_name": "PreToolUse", "tool_name": "Edit", "tool_input": {"file_path": "/home/asha/shop/src/cart.ts"}}' | node .claude/hooks/protect-files.mjs
$ echo '{"session_id": "abc123", "cwd": "/home/asha/shop", "hook_event_name": "PreToolUse", "tool_name": "Write", "tool_input": {"file_path": "/home/asha/shop/.env"}}' | node .claude/hooks/protect-files.mjs

📣Hook 3: add live facts to prompts

📄 .claude/hooks/release-status.mjs

A UserPromptSubmit hook can add text to Claude's context with additionalContext, nested inside hookSpecificOutput. Here it tells Claude about a release freeze, but only when the prompt is about deploying.

Add live facts to every prompt · 🪝 Hook run for real with the JSON Claude Code sends
📄 .claude/settings.json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "node \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/release-status.mjs"
          }
        ]
      }
    ]
  }
}
📄 .claude/hooks/release-status.mjs
// UserPromptSubmit hook: add today's release status to every prompt.
import { readFileSync, existsSync } from "node:fs";

let raw = "";
for await (const chunk of process.stdin) raw += chunk;
const { prompt } = JSON.parse(raw);

const freeze = existsSync("release-freeze.txt") ? readFileSync("release-freeze.txt", "utf8").trim() : "";
if (freeze && /deploy|release|merge/i.test(prompt)) {
  console.log(JSON.stringify({
    hookSpecificOutput: { hookEventName: "UserPromptSubmit", additionalContext: "Release status: " + freeze },
  }));
}

// PostToolUse hook for Edit and Write: keep a simple audit log of every file Claude changed.
import { appendFileSync, readFileSync } from "node:fs";

let raw = "";
for await (const chunk of process.stdin) raw += chunk;
const { tool_name, tool_input, session_id } = JSON.parse(raw);

appendFileSync(".claude/edits.log", `${session_id} ${tool_name} ${tool_input.file_path}\n`);
console.error("log now has", readFileSync(".claude/edits.log", "utf8").trim().split("\n").length, "line(s)");

🩺Check and debug

📄 settings.json
Check your settings and hooks · ⌨️ Type this in your terminal
/hooks              # browse every hook that is configured, by event
/permissions        # view and edit allow, ask and deny rules by scope
/status             # check which settings files loaded
chmod +x .claude/hooks/*.sh      # shell script hooks must be executable on macOS and Linux
claude --debug      # see full hook output and errors
What happens

/hooks lists each hook under its event. If a hook does not fire, check the event name, the matcher and that the script runs on its own.

  • Hook not firing? Event names are case sensitive (PreToolUse, not preToolUse). The matcher must match the tool name.
  • Hook seems ignored? Test the script on its own by piping JSON into it, as on this page.
  • JSON has no effect? Make sure nothing else is printed before it, and that fields like additionalContext sit inside hookSpecificOutput.
Hooks run with your user's permissions. Read every hook in a repository you clone before you trust the folder.
