Part 1

💻What Claude Code is

🧒 Beginner friendly

Claude Code is Claude working as an agent inside a folder on your computer. It can read your files, search them, edit them, run commands such as tests, and use git. You describe the goal in plain words. It works out the steps and asks before doing anything risky.

It runs in the terminal, in VS Code and JetBrains, in the Claude desktop app and on the web at claude.ai/code. All of them read the same files you will learn about: CLAUDE.md, .claude/ and .mcp.json.

It is not only for programmers. People use it to tidy folders of documents, turn CSV files into reports, rename hundreds of photos and write scripts they could not write themselves.
Part 2

📥Install and start, step by step

🧒 Beginner friendly
  1. Open a terminal. On Windows use PowerShell.
  2. Run the install command for your system.
  3. Close and reopen the terminal, then check with claude --version.
  4. Go to a project folder with cd and type claude.
  5. Log in when asked. A Claude Pro, Max, Team or Enterprise plan works, or a Claude Console account.
Install Claude Code · ⌨️ Type this in your terminal
# macOS, Linux or WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# or with a package manager
brew install --cask claude-code          # macOS
winget install Anthropic.ClaudeCode      # Windows

# check it worked
claude --version
What happens

The installer puts the claude command on your PATH. claude --version prints the installed version number.

Start your first session · ⌨️ Type this in your terminal
cd ~/projects/my-shop        # go to your project folder
claude                       # start a session here. The first time, it asks you to log in.
What happens

Claude Code opens in the terminal, shows the folder it is working in, and waits for your request. It asks before editing files or running commands.

First requests to try, one at a time · 💬 Prompt to try
what does this project do? give me a 5 line summary
where is the code that calculates the delivery charge?
add a free delivery rule for orders above Rs 499, then run the tests
what files have I changed?
commit my changes with a descriptive message
What happens

Claude reads files to answer the first two, edits the delivery code for the third and runs the tests, then uses git for the last two.

Part 3

🔄How it works: the agent loop

🧒 Beginner friendly

For each request, Claude repeats a simple loop: gather context (search and read), take action (edit, run a command), check the result, then decide the next step. It stops when the task is done or it needs you.

The single most useful habit: give Claude a way to check its work, such as tests, a sample input with the expected output, or a screenshot to compare. With a check, Claude can fix its own mistakes before you see them.

Give Claude a way to check its own work · 🧪 Tests run
📄 shop/delivery.py
def delivery_charge(order_total):
    if order_total >= 499:      # free delivery rule
        return 0
    return 40
📄 tests/test_delivery.py
import unittest
from shop.delivery import delivery_charge


class DeliveryTest(unittest.TestCase):
    def test_small_orders_pay_40(self):
        self.assertEqual(delivery_charge(200), 40)

    def test_499_and_above_ship_free(self):
        self.assertEqual(delivery_charge(499), 0)
        self.assertEqual(delivery_charge(1200), 0)
Terminal
$ python -m unittest -v
Terminal output

🚦Permission modes: how much Claude may do alone

🧒 Beginner friendly📄 .claude/settings.json📄 .claude/settings.local.json

The permission mode decides which actions Claude can take without asking. Press Shift+Tab to switch during a session, or set defaultMode in settings.json (chapter 8). In recent versions, new terminal and VS Code sessions start in auto mode, where a separate safety check reviews actions and blocks only what looks risky.

ModeWhat it meansGood for
default (shown as Manual)asks the first time each tool is usedlearning, unfamiliar projects
acceptEditsedits files and runs simple file commands without askingtrusted work where you review the diff later
planreads and explores only, no edits to your sourcethinking a change through first
autono routine prompts, a safety check reviews risky actionslong tasks you supervise loosely
dontAskrefuses anything that would need a promptlocked down scripts
bypassPermissionsskips promptsonly inside a throwaway container
When Claude asks, read the command. "Yes, and don't ask again" saves a rule to .claude/settings.local.json, so think before choosing it for commands like git push.
Part 5

🗺️Explore, plan, code, commit

Anthropic's recommended workflow for anything bigger than a one line fix has four steps. The first two happen in plan mode, so nothing changes until you agree.

Plan mode · ⌨️ Type this in your terminal
claude --permission-mode plan        # start a session in plan mode
# or press Shift+Tab inside a session until the status bar shows "plan mode on"
What happens

Claude reads files and runs read only commands, then writes a plan. It does not edit your source files until you approve. Ctrl+G opens the plan in your editor.

Explore, plan, code, commit · 💬 Prompt to try
1. (plan mode) read src/checkout and explain how coupons are applied today
2. (plan mode) I want coupons to expire. What files change? Write a plan.
3. (normal mode) implement the plan. Add tests for an expired coupon and run them.
4. commit with a message that explains why, and open a pull request
What happens

Each step builds on the last. Mistakes are caught in the plan, where they are cheap to fix, instead of in the code.

🏫 Real scenario: a school websiteA volunteer wants a "notice board" page. In plan mode Claude finds that pages are built from Markdown files and proposes three changes. The volunteer edits the plan to drop a database they do not need, then approves. The result is smaller and fits the site.
Part 6

⏪Stop, undo and come back later

🧒 Beginner friendly
  • Esc stops Claude mid action. Your conversation stays, so you can redirect it.
  • Esc Esc or /rewind opens the rewind menu. Claude snapshots files before each change, so you can restore the code, the conversation, or both.
  • /clear starts fresh in the same window.
Come back to earlier work · ⌨️ Type this in your terminal
claude --continue        # carry on with the most recent conversation in this folder
claude --resume          # pick an older conversation from a list (or /resume inside a session)
claude -p "summarise the last 5 commits"     # one question, print the answer, exit
What happens

--continue reopens the latest session, --resume shows a picker. -p runs once without the interactive screen, which is how scripts use Claude Code (chapter 11).

Checkpoints cover edits Claude made with its file tools. They do not undo things outside your folder, such as a database change or a message sent by a command. Use git as well.

Part 8

📁The .claude folder: where everything lives

🧒 Beginner friendly📄 CLAUDE.md📄 CLAUDE.local.md📄 .mcp.json📄 .claude/📄 ~/.claude/📄 ~/.claude.json

Claude Code reads settings and instructions from two places: your project (shared with your team through git) and your home folder (just for you, in every project). The rest of this module fills in each file.

my-shop/                        your project
├── CLAUDE.md                   project instructions, loaded every session (ch 5)
├── CLAUDE.local.md             your private notes for this project, add to .gitignore
├── .mcp.json                   MCP servers the team shares (ch 10)
└── .claude/
    ├── settings.json           permissions, hooks, env for the team (ch 8)
    ├── settings.local.json     your personal overrides, not committed
    ├── rules/                  topic rules, some only for certain paths (ch 6)
    ├── skills/<name>/SKILL.md   repeatable tasks (ch 7)
    ├── agents/<name>.md        subagents (ch 9)
    ├── output-styles/          custom response styles (ch 9)
    └── hooks/                  scripts your hooks run (ch 8)

~/.claude/                       your home folder, applies to every project
├── CLAUDE.md                   your personal preferences
├── settings.json               your personal settings
├── rules/  skills/  agents/  output-styles/
└── projects/<project>/memory/MEMORY.md   auto memory Claude writes

~/.claude.json                   app state and your personal MCP servers
You may hear about files like "rules.md", "agents.md" or "skills.md". Claude Code has no single file with those names. The real places are the folders .claude/rules/, .claude/agents/ and .claude/skills/<name>/SKILL.md. One exception: Claude Code can read an AGENTS.md file, used by other coding tools, when the folder has no CLAUDE.md. Chapter 5 covers it.
