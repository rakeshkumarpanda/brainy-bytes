Choosing columns and doing sums

SELECT does more than copy columns. Every item in the SELECT list is an expression: a column, a fixed value, or a little calculation worked out once for every row. A shopkeeper checking "how much stock money sits on each shelf" multiplies price by stock for each product. SQL does it in one line.

OperatorMeaningExampleResult
+ - * /add, subtract, multiply, divideprice * 2double the price
%remainder after divisionstock % 1040 gives 0, 25 gives 5
||join two pieces of textname || ' (' || category || ')'Notebook (Stationery)
/ on whole numbersinteger division drops the fraction7 / 23, but 7 / 2.0 gives 3.5
Common mistake
In SQLite and PostgreSQL, dividing two whole numbers gives a whole number. 7 / 2 is 3. Write 7 / 2.0 or CAST(7 AS REAL) / 2 when you want 3.5. MySQL is different: its / always gives a decimal.

Aliases, text and quoting

An alias gives a column or a table a nickname with AS. It makes results readable, and later it saves typing when many tables meet in one query.

Use single quotes for text. MySQL also accepts double quotes for text, but in standard SQL, SQLite and PostgreSQL double quotes mean a name. Single quotes work everywhere.
Lesson 3 of 4

DISTINCT, LIMIT and OFFSET

Ask "which cities do our customers live in" and you do not want Pune printed twice. DISTINCT removes repeated rows from the result. LIMIT keeps only the first few rows, and OFFSET skips some rows first, which is how page 2 of search results works.

Remove repeatsExam favourite
SELECT DISTINCT col, col FROM t;
Repeats are judged on the whole row of chosen columns, not on the first column alone.
Page of resultsExam favourite
... ORDER BY col LIMIT n OFFSET k;
Skip k rows, then return n. Page p of size n uses OFFSET (p − 1) × n.
Standard spelling
OFFSET k ROWS FETCH FIRST n ROWS ONLY
The SQL standard form, used by PostgreSQL, Oracle 12c and later, and SQL Server (with ORDER BY). SQL Server also has SELECT TOP n.
Real world scenario: page 2 of a shopping site

You search "school bag" and see 20 results. You click page 2. The site runs the same query with ORDER BY on relevance, LIMIT 20 OFFSET 20. If the query had no ORDER BY, the database could return rows in any order, and the same bag might appear on both pages while another never shows up.

Common mistake
LIMIT without ORDER BY gives "some" rows, not "the first" rows. Always sort before you limit.
Lesson 4 of 4

From intuition to research

One idea, four depths

SELECT is like telling a photocopier which columns of a page to copy, with a little calculator for each line.

The SELECT list is evaluated per row after FROM and WHERE. DISTINCT then removes duplicate result rows, ORDER BY sorts, and LIMIT and OFFSET cut the sorted list.

In relational algebra the SELECT list is projection (π). Pure projection removes duplicates, but SQL keeps them unless you write DISTINCT, because SQL works on multisets. DISTINCT costs a sort or a hash table over the result.

Large OFFSET values are slow because the engine still produces and throws away the skipped rows. Production systems use keyset pagination instead: remember the last key seen and ask for WHERE id > last_id ORDER BY id LIMIT 20, which an index answers directly.

Going deeper: Why SELECT * is risky in real programs

If someone adds a column to the table later, SELECT * suddenly returns more data, which can break code that reads columns by position and sends more data over the network. Naming columns keeps the result stable and lets the engine use a covering index.
