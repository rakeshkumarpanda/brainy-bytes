Set operations: UNION, INTERSECT and EXCEPT

Lesson 1 of 4

UNION and UNION ALL: stacking results

Joins put tables side by side. Set operations stack results on top of each other. "Every city where we have a customer or a warehouse" is the customer cities stacked on the warehouse cities.

RuleWhy
Both queries must return the same number of columnsrows are stacked column by column
Matching columns should hold the same kind of dataa name on top of a price makes no sense, and strict engines refuse it
Column names come from the first queryso put aliases there
ORDER BY and LIMIT go once, at the very endthey apply to the whole combined result
Remember
UNION has to find and remove duplicates, which costs a sort or hash. When you know there are no duplicates, or you want them, use UNION ALL.
Lesson 2 of 4

INTERSECT and EXCEPT

INTERSECT keeps rows that appear in both results. EXCEPT keeps rows of the first result that do not appear in the second. Oracle calls EXCEPT MINUS.

OperatorVenn diagram ideaDuplicatesAlso written
UNIONeverything in A or Bremoved
UNION ALLeverything, counted twice if in bothkept
INTERSECTthe overlap of A and BremovedINTERSECT ALL in PostgreSQL
EXCEPTA without BremovedMINUS in Oracle, EXCEPT ALL in PostgreSQL
Order matters for EXCEPT
  1. A EXCEPT B keeps what is in A and missing from B.
  2. B EXCEPT A keeps what is in B and missing from A.
  3. Warehouse cities EXCEPT customer cities gives Mumbai and Kolkata: warehouses with no local customers.
  4. UNION and INTERSECT give the same rows either way round, EXCEPT does not
Lesson 3 of 4

Set operations versus joins and NULLs

Set operations compare whole rows, and here NULLs count as equal, unlike in a WHERE test. That makes INTERSECT and EXCEPT a neat, NULL safe way to compare two tables row by row, for example to check that a copy of a table matches the original.

QuestionSet operationJoin or subquery form
In A or BA UNION BFULL OUTER JOIN (with COALESCE)
In bothA INTERSECT BJOIN, or WHERE EXISTS
In A, not in BA EXCEPT BLEFT JOIN ... WHERE b.key IS NULL, or NOT EXISTS
Real world scenario: checking a data migration

A company copies its customers table from an old system to a new one. To prove nothing was lost or changed, an engineer runs SELECT * FROM old_customers EXCEPT SELECT * FROM new_customers and then the same the other way round. Two empty results mean the tables hold exactly the same rows, including rows with NULLs.

Lesson 4 of 4

From intuition to research

One idea, four depths

UNION pours two lists together, INTERSECT keeps what both share, EXCEPT takes one list away from the other.

Set operations need union compatible inputs: the same number of columns with compatible types. Duplicates are removed unless you write ALL.

In relational algebra these are union (∪), intersection (∩) and difference (−). SQL’s bag versions with ALL follow multiset rules: UNION ALL adds counts, INTERSECT ALL takes the smaller count, EXCEPT ALL subtracts counts.

Engines implement duplicate removing set operations with sorting or hashing, much like GROUP BY. In SQLite, EXPLAIN QUERY PLAN shows a line such as COMPOUND QUERY with a temporary B-tree for UNION.

Going deeper: UNION ALL as a view over partitions

Before native partitioning existed, people split a big table by year into sales_2024, sales_2025 and so on, then made one view: SELECT * FROM sales_2024 UNION ALL SELECT * FROM sales_2025. Queries on the view read every part, and some engines can skip parts whose CHECK rules exclude the requested dates.
