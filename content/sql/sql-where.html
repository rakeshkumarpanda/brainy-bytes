WHERE keeps only the rows you want

A library has thousands of books, but you only want the ones about cricket. WHERE is the librarian's filter. It tests every row with a condition, keeps the rows where the condition is true, and throws the rest away.

Remember
Text comparisons are exact in SQLite with = : 'pune' is not equal to 'Pune'. Dates stored as text in the ISO form YYYY-MM-DD sort and compare correctly as text.
Lesson 2 of 5

AND, OR, NOT and brackets

Real questions have more than one condition. "Sports items under Rs 500" needs both tests to be true, so it uses AND. "Kitchen or Sports items" needs either one, so it uses OR. NOT flips true and false.

ABA AND BA OR BNOT A
truetruetruetruefalse
truefalsefalsetruefalse
falsetruefalsetruetrue
falsefalsefalsefalsetrue

AND is done before OR, just as multiplication is done before addition in maths. Forgetting this is one of the most common SQL bugs.

Read the first query the way SQLite does
  1. AND binds tighter than OR, so the condition is Sports OR (Kitchen AND price < 300).
  2. Every Sports product passes, whatever its price: Cricket ball and Football.
  3. Kitchen products pass only under 300: Water bottle at 250 passes, Lunch box at 399 fails.
  4. With brackets the price rule covers both, so only Cricket ball and Water bottle remain
Common mistake
When AND and OR appear together, add brackets even if you know the rule. The next reader may not.
Lesson 3 of 5

LIKE, GLOB and IS NULL

Sometimes you know only part of a value, like "a product with box in its name". LIKE matches patterns. A % stands for any run of characters, even none. An _ stands for exactly one character.

PatternMatchesDoes not match
'P%'Pencil box, Phone chargerNotebook
'%box'Pencil box, Lunch boxBoxing gloves (box is not at the end)
'_o%'Notebook, Football (o is the second letter)Pencil box
'%a_e%'Water bottle (a, any letter, e)Cricket ball
In the exam
In SQLite, LIKE ignores the difference between capital and small letters for plain English letters. GLOB is the case sensitive cousin and uses * and ? instead of % and _. PostgreSQL LIKE is case sensitive, and it has ILIKE for case insensitive matching.

Missing values need special care. email = NULL never finds anything, because comparing with an unknown value gives unknown, not true. Use IS NULL and IS NOT NULL. The next step of this subject has a whole chapter on NULL.

Lesson 4 of 5

ORDER BY: sorting the result

A cricket scoreboard lists batters by runs, highest first. ORDER BY sorts the result. ASC (the default) puts small values first, DESC puts big values first. You can sort by several columns: the second one only breaks ties in the first.

RuleIn SQLite
Where do NULLs go in ASC orderFirst, because SQLite treats NULL as smaller than every other value
Choose yourselfORDER BY city NULLS LAST (supported since SQLite 3.30.0, also in PostgreSQL and Oracle)
Sort by an aliasSELECT price * stock AS v ... ORDER BY v DESC works
Sort by positionORDER BY 2 means the 2nd column of the SELECT list, allowed but hard to read
Text orderBy character codes (BINARY collation): capital letters come before small ones. COLLATE NOCASE ignores case for English letters
Real world scenario: the cricket points table

A league table sorts teams by points, highest first. Two teams on equal points are split by net run rate. In SQL that is ORDER BY points DESC, net_run_rate DESC. The second column only matters when the first one ties.

Lesson 5 of 5

From intuition to research

One idea, four depths

WHERE is a sieve that keeps the rows you want, and ORDER BY lines them up neatly.

WHERE runs before SELECT and ORDER BY runs after it. That is why WHERE cannot use a column alias from the SELECT list but ORDER BY can.

A WHERE condition is selection (σ) in relational algebra. The planner can use an index when a condition compares a column directly with a value, such as price < 300. Wrapping the column in a function, such as lower(name) = ..., usually stops a plain index from being used.

Optimizers estimate how many rows each condition keeps (its selectivity) from statistics such as histograms, then order the work so the most selective, cheapest tests run first. Bad estimates are a top cause of slow queries in real systems.

Going deeper: LIKE and indexes

A pattern that starts with a fixed prefix, such as 'Pen%', can use an index in many engines, because the matching values sit together in sorted order. A pattern that starts with %, such as '%box', must check every row. Full text search features exist for searching words inside long text.
