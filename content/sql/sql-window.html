OVER: an answer for every row

GROUP BY folds many rows into one. Sometimes you want a group answer next to each row: each employee with their department’s average, or each order with a running total. A window function does that. The word OVER turns an ordinary function into a window function.

Window functionExam favourite
function(...) OVER (PARTITION BY a ORDER BY b)
PARTITION BY makes groups, ORDER BY sorts inside each group. Both are optional.
Whole table
AVG(salary) OVER ()
Empty brackets: the window is every row of the result.
GROUP BYWindow function
Rows in the resultone per groupone per input row

Ranking: ROW_NUMBER, RANK and DENSE_RANK

Add ORDER BY inside OVER and the function can number or rank rows. The three ranking functions differ only in how they treat ties.

FunctionSalaries 140, 70, 70, 60Use it for
ROW_NUMBER()1, 2, 3, 4picking exactly one row per group, paging
RANK()1, 2, 2, 4sports style positions
DENSE_RANK()1, 2, 2, 3the second highest distinct value

Common mistake
ROW_NUMBER breaks ties in no guaranteed order. Add a tie breaker such as id to the ORDER BY when the result must be the same every time.
Lesson 3 of 5

Running totals, LAG and LEAD

With ORDER BY, an aggregate such as SUM becomes a running aggregate: it adds rows from the start of the partition up to the current row. LAG and LEAD reach back or forward to a neighbouring row.

FunctionReturns
LAG(x) and LAG(x, n, default)x from the row n places before, default when there is none
LEAD(x)x from the next row
FIRST_VALUE(x), LAST_VALUE(x)x from the first or last row of the frame
NTH_VALUE(x, n)x from row n of the frame
Lesson 4 of 5

Frames, named windows and the WHERE trap

The frame is the exact set of rows an aggregate sees for the current row. You can set it yourself.

FrameMeaning
no ORDER BYthe whole partition
ORDER BY only (default)RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW: start to here, tied rows included
ROWS BETWEEN 2 PRECEDING AND CURRENT ROWthis row and the 2 before it: a 3 row moving window
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWINGthe whole partition, needed for LAST_VALUE to mean the true last row
GROUPS BETWEEN 1 PRECEDING AND CURRENT ROWthis group of tied rows and the group before (SQLite, PostgreSQL)
Remember
In the logical order of a query, window functions run after WHERE, GROUP BY and HAVING, and before ORDER BY and LIMIT. That is why they can use aggregates but cannot be filtered by WHERE in the same SELECT.
Lesson 5 of 5

From intuition to research

One idea, four depths

A window function writes a group answer, such as a rank or an average, next to every row without hiding any rows.

OVER (PARTITION BY ... ORDER BY ... frame) defines the window. Ranking, offset and aggregate functions all work over it. They run after GROUP BY and HAVING.

Frames come in ROWS, RANGE and GROUPS units with EXCLUDE options. Engines sort once per distinct window and sweep the rows, keeping running state, so a running SUM costs about one pass after sorting.

Efficient evaluation of arbitrary frames uses segment trees and similar structures (Leis et al., VLDB 2015, "Efficient Processing of Window Functions in Analytical SQL Queries"). Some engines add QUALIFY, a WHERE for window results, found in Snowflake, BigQuery, Teradata and DuckDB.

Going deeper: Where window functions came from

They entered the SQL standard in SQL:2003 (first as OLAP functions in an amendment to SQL:1999). PostgreSQL added them in 8.4 (2009), SQL Server in 2005 with fuller frame support in 2012, MySQL in 8.0 (2018), and SQLite in 3.25.0 (2018).
