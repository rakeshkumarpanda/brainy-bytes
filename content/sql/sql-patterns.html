Top N per group

"The two most expensive products in each category", "each customer’s latest order". LIMIT works on the whole result, not per group. The standard pattern ranks inside each group with a window function, then filters outside.

WantUse
exactly N rows per groupROW_NUMBER() ... WHERE rn <= N
N, plus anyone tied with the NthRANK() ... WHERE rnk <= N
the top N distinct valuesDENSE_RANK() ... WHERE dr <= N
one row per group, PostgreSQL onlySELECT DISTINCT ON (group) ... ORDER BY group, value DESC
Lesson 2 of 6

Gaps and islands: finding streaks

Streaks of consecutive days, runs of the same status, ranges of free seats: these are islands, and the holes between them are gaps. The neat trick: subtract a row number from the value. Within a streak the difference stays constant.

The row number trick with dates
  1. Convert each date to a day number with julianday(d).
  2. Subtract ROW_NUMBER() OVER (ORDER BY d).
  3. GROUP BY the difference. Each group is one unbroken run of dates.
  4. day − row number is constant inside an island
Lesson 3 of 6

Pivoting rows into columns

A pivot turns values in rows into columns: one row per customer with a column per status, or one row per student with a column per subject. Standard SQL does it with conditional aggregation.

EnginePivot syntax
Every engineconditional aggregation with CASE, as above
SQL Server, OraclePIVOT ( aggregate FOR column IN (values) )
PostgreSQLFILTER, or crosstab() from the tablefunc extension
DuckDB, SnowflakePIVOT and UNPIVOT statements
Remember
The columns of a pivot must be known when you write the query. A pivot with columns decided by the data needs dynamic SQL built by a program.
Lesson 4 of 6

Duplicates and percent of total

Real data arrives with duplicates: the same customer typed twice, a form submitted two times. First find them, then keep one copy of each.

Remember
rowid is SQLite’s hidden row number. PostgreSQL has ctid, and elsewhere you use the primary key. The pattern is the same: number the copies, delete all but number 1.
Lesson 5 of 6

JSON inside a database

Many apps store flexible data as JSON text in a column: settings, tags, event details. Modern engines can read inside it with SQL. SQLite’s JSON functions are built in (since 3.38 by default).

EngineRead a fieldNotes
SQLitedata ->> '$.user'JSON stored as text, functions json_extract, json_each
PostgreSQLdata ->> 'user'jsonb type is binary and can be indexed with GIN
MySQLdata ->> '$.user'JSON type, generated columns for indexing
SQL ServerJSON_VALUE(data, '$.user')OPENJSON turns arrays into rows
Remember
JSON is handy for data whose shape varies. Fields you filter or join on every day usually deserve real columns, which get types, constraints and simple indexes.
Lesson 6 of 6

From intuition to research

One idea, four depths

Many hard looking questions are known patterns: rank and filter for top N, row number tricks for streaks, CASE inside SUM for pivots.

Learn to recognise the pattern behind a question. Window functions, CTEs and conditional aggregation solve most reporting tasks in a single statement.

Each pattern has trade offs: correlated subqueries versus window functions, JSON versus columns, deleting duplicates versus preventing them with constraints. Read the query plan (chapter 7.2) to choose.

Semi structured data in relational engines is an active field: binary JSON formats, JSON path standards (SQL:2016 added SQL/JSON), and automatic shredding of JSON into hidden columns for speed in systems such as Snowflake and SingleStore.

Going deeper: Unpivot

The reverse of a pivot turns columns back into rows. Portable SQL uses UNION ALL: SELECT name, 'algebra' AS subject, algebra AS score FROM report UNION ALL SELECT name, 'physics', physics FROM report. SQL Server, Oracle and DuckDB also have an UNPIVOT keyword.
