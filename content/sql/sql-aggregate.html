Squeezing many rows into one answer

"How many orders did we get?" "What is our average price?" These questions take many rows and squeeze them into one number. The functions that do it are called aggregate functions.

FunctionGivesNULLs
COUNT(*)number of rowscounted
COUNT(col)number of values that are not NULLskipped
COUNT(DISTINCT col)number of different valuesskipped
SUM(col)totalskipped, and SUM of no values is NULL
AVG(col)average (mean)skipped
MIN(col), MAX(col)smallest, biggestskipped
group_concat(col, sep)all values joined into one textskipped (string_agg in PostgreSQL and SQLite 3.44+)
In the exam
An aggregate query with no GROUP BY always returns exactly one row, even when the table is empty. COUNT then gives 0 and SUM gives NULL.
Lesson 2 of 5

GROUP BY: one answer per group

A shop owner wants "how many products in each category", not one number for the whole shop. GROUP BY splits the rows into groups that share a value, then runs the aggregate once per group. One group becomes one result row.

The golden rule of GROUP BY
  1. After grouping, each result row stands for a whole group of rows.
  2. A column in the SELECT list must be either in GROUP BY or inside an aggregate.
  3. Otherwise the engine does not know which row’s value to show. PostgreSQL, SQL Server and MySQL (by default) refuse such a query.
  4. SQLite allows these bare columns and takes the value from some row of the group. Avoid relying on it
Lesson 3 of 5

HAVING filters groups, WHERE filters rows

"Categories with at least 3 products" is a test on a group, not on a single row. WHERE cannot do it, because WHERE runs before the groups exist. HAVING runs after grouping, so it can use aggregates.

WHEREHAVING
Filterssingle rowswhole groups
Runsbefore GROUP BYafter GROUP BY
Can use aggregatesnoyes
ExampleWHERE stock > 0HAVING SUM(stock) > 100
Grouped queryExam favourite
SELECT g, agg(x) FROM t WHERE row_test GROUP BY g HAVING group_test ORDER BY ...;
Clauses must be written in this order.
Conditional count
COUNT(*) FILTER (WHERE cond) or SUM(CASE WHEN cond THEN 1 ELSE 0 END)
Counts only some rows of each group. FILTER works in PostgreSQL and SQLite 3.30+.

The order SQL really runs in

You write a query starting with SELECT, but the engine logically starts with FROM. Knowing the real order explains most beginner errors.

StepClauseWhat it doesSo you can
1FROM (and JOIN)picks and combines tablesrefer to their columns
2WHEREkeeps rowsnot use aggregates or SELECT aliases yet
3GROUP BYmakes groupsonly group columns survive as plain values
4HAVINGkeeps groupsuse aggregates
5SELECTworks out the result columns and aliasesname things with AS
6DISTINCTremoves duplicate rows
7ORDER BYsortsuse aliases from SELECT
8LIMIT / OFFSETcuts the list
Remember
This is the logical order, which defines what a query means. The engine may physically do things in another order, for example use an index to avoid sorting, as long as the answer is the same.
Real world scenario: the monthly sales report

A manager asks for "the top 3 cities by revenue last month, only cities with more than 10 orders". Read it in the logical order: FROM orders joined to customers, WHERE the date is in last month, GROUP BY city, HAVING COUNT(*) > 10, SELECT city and SUM of the amounts as revenue, ORDER BY revenue DESC, LIMIT 3. Each phrase of the request lands in exactly one clause.

Lesson 5 of 5

From intuition to research

One idea, four depths

GROUP BY sorts things into piles, the aggregate counts or adds each pile, and HAVING throws away piles you do not want.

Grouping is done with a sort or a hash table. Engines also support ROLLUP, CUBE and GROUPING SETS (PostgreSQL, SQL Server, Oracle, MySQL has WITH ROLLUP) to get subtotals and a grand total in one query.

Aggregates can be split for parallel work: SUM and COUNT combine easily, AVG is computed as SUM and COUNT combined at the end. MEDIAN cannot be combined so simply, which is why exact medians on huge data are expensive.

Analytics engines use approximate aggregates such as HyperLogLog for COUNT DISTINCT on billions of rows, trading a small, known error for huge speed. Column stores keep each column separately, so SUM(price) reads only the price column.

Going deeper: ROLLUP in action

In PostgreSQL, SELECT category, status, SUM(qty) FROM sales GROUP BY ROLLUP (category, status) returns one row per category and status, one subtotal row per category (status shown as NULL) and one grand total row. SQLite has no ROLLUP, but a UNION ALL of three grouped queries gives the same result.
