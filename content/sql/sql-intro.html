Lesson 1 of 5

Data is everywhere, and it needs a home

Every time you order food on an app, top up a phone, or get your marks on a school portal, a computer somewhere writes down a few small facts. Who ordered. What they ordered. When. How much it cost. Those small facts are called data.

A notebook works for ten facts. A spreadsheet works for a few thousand. But a train booking site has millions of seats, thousands of people booking at the same second, and no room for mistakes such as selling one seat twice. For that we need a database: an organised store of data, looked after by a program called a database management system (DBMS).

Remember
A database is not one file or one table. It is the whole collection of tables plus the rules that tie them together, kept by a DBMS.

Tables, rows, columns and keys

In 1970 Edgar F. Codd, a researcher at IBM, published a paper called A Relational Model of Data for Large Shared Data Banks. His idea was simple and powerful: keep all data in tables, and let people ask questions about what they want, without caring how the computer stores it on disk. Almost every business database today follows his idea.

Read the table like a database does
  1. The table has a name, customers. Names let SQL find it.
  2. There are 5 columns: id, name, city, email and joined.
  3. Each row is one customer. Row order has no meaning in the relational model, so SQL never promises an order unless you ask for one.
  4. id is the primary key. It is unique and never empty, so it picks out exactly one row.
  5. Kabir has no email. The cell holds NULL, which means unknown or missing
Common mistake
A primary key must be unique and must never be missing. Names are bad keys because two customers can both be called Asha.
Lesson 3 of 5

What SQL is and your first query

SQL stands for Structured Query Language. People say it as the letters S Q L or as the word "sequel". It began at IBM in 1974, when Donald Chamberlin and Raymond Boyce described a language called SEQUEL for asking questions of Codd style tables. The name was later shortened to SQL. It became an ANSI standard in 1986 and an ISO standard in 1987, and the standard is still updated: the current edition is SQL:2023 (ISO/IEC 9075).

SQL is declarative. You describe the answer you want, and the database works out the steps. Compare asking a waiter for "one masala dosa" with walking into the kitchen and giving the cook a recipe.

The smallest queryExam favourite
SELECT column, column FROM table;
SELECT says which columns, FROM says which table. Keywords are not case sensitive, so select works too, but capitals make queries easier to read.
Every column
SELECT * FROM table;
The star means all columns. Handy for a quick look, but real programs should name the columns they need.

Database engines and the journey of a query

SQL is the language. A database engine is the program that understands it. Each engine follows the SQL standard closely but adds its own extras, called a dialect.

EngineKindWhere you meet it
SQLiteEmbedded, a library inside the app, no serverEvery Android and iPhone, browsers, and this page

MySQL and MariaDBClient and server, open sourceMany websites and online shops

The SQL on these pages runs on SQLite, compiled to WebAssembly so it works inside your browser (the sql.js project). It is the real SQLite, so every answer you see is the true answer, not a guess. The SQLite team describes it as the most widely deployed database engine in the world.

What happens after you press Run
  1. The parser checks the grammar and that every table and column exists. A spelling mistake stops here with a syntax error.
  2. The planner, also called the optimizer, chooses a plan: read the whole table, or jump in using an index.
  3. The executor follows the plan and reads the rows.
  4. The result goes back to you as a new table, even if it has one row or none
Real world scenario: two people book the last seat

Two friends in different cities press Book on the last train seat at the same moment. A client and server engine such as PostgreSQL receives both requests. It lets the first booking finish, then the second one sees the seat is gone and gets a friendly "sold out". Without the database keeping order, both might get a ticket for one seat.

Lesson 5 of 5

From intuition to research

One idea, four depths

A database is a big, careful cupboard of tables. SQL is the polite way to ask the cupboard keeper for exactly what you need.

A DBMS gives you a data model (tables), a language (SQL), integrity rules (keys and constraints), safe sharing (transactions) and fast access (indexes). The relational model treats a table as a set of rows, which is why row order is not part of the data.

Codd’s model rests on relational algebra: selection (WHERE), projection (the SELECT list), join, union, difference and rename. SQL is close to it but not identical. SQL tables can hold duplicate rows (a multiset or bag) and use NULL with three valued logic, two points Codd himself debated.

Research engines explore learned query optimizers, column stores for analytics, and distributed SQL that keeps one logical database across many machines. The core idea of saying what you want and letting the system choose how is still the centre of all of them.

Going deeper: Why SQL is called declarative

In a language such as Python you write a loop: open the file, read each line, check the city, keep matching lines. In SQL you write one sentence, and the planner may pick a different method each day as the data grows, for example an index instead of a full scan, without you changing the query.
