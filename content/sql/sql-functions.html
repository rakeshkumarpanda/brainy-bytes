Text functions

A function takes values in and gives one value back, like a juicer: fruit in, juice out. SQL has dozens of them. Text functions clean and reshape words, which matters because real data is messy: extra spaces, mixed capitals, codes hidden inside longer strings.

Remember
Function names differ between engines. SQLite and PostgreSQL use substr and length. SQL Server uses SUBSTRING and LEN. MySQL has both SUBSTR and SUBSTRING. The idea is the same everywhere.

CASE is how SQL says "if this, then that, otherwise something else". It checks each WHEN from top to bottom and returns the THEN of the first true one. If none is true it returns the ELSE value, or NULL when there is no ELSE.

Searched CASEExam favourite
CASE WHEN cond THEN a WHEN cond2 THEN b ELSE c END
The first true WHEN wins. A NULL test counts as not true.
Simple CASE
CASE status WHEN 'pending' THEN 1 WHEN 'shipped' THEN 2 ELSE 3 END
Compares one value with each WHEN using =.
IIF
iif(cond, a, b)
A short CASE with one test. In SQLite since 3.32.0 and in SQL Server.

COALESCE, NULLIF, CAST and typeof

Missing values are common. COALESCE returns the first argument that is not NULL, which is perfect for a fallback: "show the email, or if there is none, show the word unknown". NULLIF(a, b) does the opposite job: it returns NULL when a equals b, which is a classic trick to avoid dividing by zero.

SQLite is flexible about types: a column declared INTEGER can still hold text unless the table is STRICT. PostgreSQL, MySQL and SQL Server are strict and will reject or convert the value. Chapter 4.1 covers this in depth.

Dates and times

SQLite has no special date type. It stores dates as TEXT in the ISO 8601 form YYYY-MM-DD HH:MM:SS, as a REAL Julian day number, or as an INTEGER count of seconds since 1970 (Unix time). Its date functions understand all three. Text in ISO form has a big bonus: sorting the text sorts the dates correctly.

Real world scenario: the delivery promise

An app promises delivery within 5 days. Each night a report runs WHERE status <> 'delivered' AND date(order_date, '+5 days') < date('now') to list late orders, so the support team can call those customers before they complain.

From intuition to research

One idea, four depths

Functions are little machines: put a value in, get a changed value out. CASE is a decision box.

Scalar functions work on one row at a time and return one value. Aggregate functions such as COUNT and SUM, in the next chapters, work on many rows and return one value.

Functions on a column inside WHERE can stop an index from being used. Many engines let you index an expression, for example CREATE INDEX ON customers(lower(email)), so the same expression in WHERE can use it.

Time zones and calendars are hard: daylight saving changes, leap seconds and historical calendar reforms. Systems store times in UTC and convert only for display. PostgreSQL offers timestamp with time zone, which stores an absolute instant and shows it in the session time zone.

Going deeper: Deterministic functions

A function is deterministic when the same input always gives the same output, such as upper(). random() and date('now') are not. Engines only allow deterministic functions in places such as expression indexes and generated columns, because the stored value must stay correct.
