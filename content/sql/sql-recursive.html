Lesson 1 of 5

A query that calls itself

Some questions have no fixed number of steps: "everyone who reports to Priya, directly or through others", "every date in June". A recursive CTE answers them by running a query again and again on its own latest results until nothing new appears.

Recursive CTEExam favourite
WITH RECURSIVE name(cols) AS ( anchor UNION ALL recursive_part ) SELECT ... FROM name;
The anchor runs once. The recursive part reads name, but only sees the rows from the round before.
How the engine runs it
  1. Run the anchor and put its rows in the result and in a queue.
  2. Take rows from the queue and run the recursive part on them.
  3. Add any new rows to the result and to the queue.
  4. Stop when the queue is empty. No stop rule means it never empties.
Common mistake
Always write a stop rule, such as WHERE x < 10, a depth limit, or a LIMIT on the outer query. SQL Server stops after 100 rounds by default (MAXRECURSION), SQLite has no such limit.

Generating series and calendars

SQLite has no built in series generator in this build, so a recursive CTE is the usual way to make a run of numbers or dates. A calendar of days is handy for reports that must show days with zero sales too.

Walking hierarchies

A table that points at itself, like employees.manager_id, stores a tree. A recursive CTE walks the tree one level per round, and can carry the depth and the path along.

Lesson 4 of 5

Graphs, cycles and UNION

A tree has one parent per node. A graph can have many links and even loops, such as train routes. A naive recursive walk around a loop never ends, so you must stop it.

Way to stop a cycleHow
Path checkkeep the path as text or JSON and skip nodes already in it
UNION instead of UNION ALLdrops rows that are exact repeats, which ends simple loops where the whole row repeats
Depth limitcarry a level column and add WHERE level < 10
LIMITa LIMIT on the outer query stops the recursion early in SQLite
CYCLE clausePostgreSQL 14+: CYCLE id SET is_cycle USING path
Real world scenario: friend suggestions

A social app suggests "people you may know": friends of your friends who are not already your friends. That is a two step walk on the friendship graph. Graph databases such as Neo4j are built for long walks, but for a few hops a recursive CTE with a depth limit works in any SQL engine.

Lesson 5 of 5

From intuition to research

One idea, four depths

A recursive query starts with some rows and keeps finding more rows from the ones it just found, until no new ones appear.

Anchor UNION ALL recursive part, with a stop rule. Use it for series, hierarchies and graph walks. Guard against cycles with a path, UNION or a depth limit.

Semantically it computes a least fixed point. Engines run it as semi naive evaluation: each round joins only the new rows (the delta) from the previous round, which is why the recursive part sees only last round’s rows. Linear recursion, where the CTE appears once, is what the SQL standard allows.

Recursive SQL comes from Datalog research on deductive databases. Modern work studies graph query languages, including the ISO GQL standard (2024) and SQL/PGQ (SQL:2023 part 16), which adds property graph queries to SQL itself.

Going deeper: Other ways to store trees

Besides parent pointers (the adjacency list used here) there are nested sets (left and right numbers per node), materialized paths (a column such as /1/2/4/), and closure tables (one row per ancestor and descendant pair). They make some reads faster and writes slower. PostgreSQL’s ltree extension stores materialized paths.
