CREATE TABLE: drawing the empty form

Until now every table already existed. Now you build your own. CREATE TABLE describes an empty table: its name, its columns, the kind of data each column holds, and the rules every row must follow. Think of printing a blank admission form before any student fills it in.

Create a tableExam favourite
CREATE TABLE name (column type constraints, ...);
One line per column. Constraints can follow each column, or come at the end for rules that cover several columns.
Only if missing
CREATE TABLE IF NOT EXISTS name (...);
Does nothing, without an error, when the table is already there. Handy in setup scripts that run more than once.

Common mistake
Never store money in a floating point column. 0.1 + 0.2 is not exactly 0.3 in binary. Use a DECIMAL type, or store whole paise or cents as an integer, as our products table does with prices in rupees.

Constraints: rules every row must obey

A constraint is a rule stored with the table. The database checks it on every INSERT and UPDATE, from every app, so bad data cannot sneak in through a program that forgot to check.

ConstraintRuleExample
NOT NULLthe column must have a valuename TEXT NOT NULL
UNIQUEno two rows share this value (NULLs are allowed, and do not clash)email TEXT UNIQUE
PRIMARY KEYunique and identifies the rowid INTEGER PRIMARY KEY
CHECK (test)the test must not be falseCHECK (price > 0)
DEFAULT valueused when the INSERT leaves the column outstatus TEXT DEFAULT 'new'
REFERENCES t(c)the value must exist in another tablecustomer_id INTEGER REFERENCES customers(id)
A CHECK rule and NULL
  1. CHECK refuses a row only when its test is false.
  2. With age NULL, age >= 18 is unknown, not false.
  3. So the row is accepted. Add NOT NULL as well if the age must be known.
  4. CHECK passes on TRUE and on UNKNOWN, it fails only on FALSE

How SQLite treats types, and STRICT tables

Most engines refuse text in an integer column. SQLite is more relaxed: a column’s type gives it an affinity, a preference, and SQLite converts values to that preference when it can. When it cannot, it stores the value as it is.

Declared type containsAffinityExample
INTINTEGERINT, INTEGER, BIGINT
CHAR, CLOB or TEXTTEXTVARCHAR(20), TEXT
BLOB, or no type at allBLOBBLOB
REAL, FLOA or DOUBREALREAL, DOUBLE, FLOAT
anything elseNUMERICDECIMAL(10,2), BOOLEAN, DATE

Since version 3.37 (2021) SQLite also offers STRICT tables. A STRICT table allows only the types INT, INTEGER, REAL, TEXT, BLOB and ANY, and refuses a value that cannot be converted losslessly, the way other engines do.

Remember
When you move a design from SQLite to PostgreSQL or MySQL, a STRICT table behaves much closer to what you will meet there.
Lesson 4 of 5

ALTER TABLE and DROP TABLE

Designs change. ALTER TABLE changes a table that already holds data, and DROP TABLE removes a table and every row in it.

Add a columnExam favourite
ALTER TABLE t ADD COLUMN c type DEFAULT v;
Existing rows get the default, or NULL when there is none.
Rename
ALTER TABLE t RENAME TO t2; and ALTER TABLE t RENAME COLUMN a TO b;
Names change, data stays.
Drop a column
ALTER TABLE t DROP COLUMN c;
SQLite 3.35 and later. It refuses a column used by an index, a key or a CHECK.
Remove a table
DROP TABLE IF EXISTS t;
Gone with all its rows. There is no undo outside a transaction.
EngineWhere to see the tables
SQLiteSELECT name FROM sqlite_schema WHERE type = 'table'
PostgreSQL, MySQL, SQL ServerSELECT table_name FROM information_schema.tables
OracleSELECT table_name FROM user_tables
Real world scenario: a migration on a live app

A food delivery app wants to show a rating for each restaurant. The team writes a migration: a small script with ALTER TABLE restaurants ADD COLUMN rating REAL. Tools such as Flyway, Liquibase, Alembic or Rails migrations number these scripts and record which ones ran, so every copy of the database, on every laptop and server, ends up with the same shape.

Lesson 5 of 5

From intuition to research

One idea, four depths

CREATE TABLE draws a blank form with labelled boxes, and constraints are the rules printed on the form, such as "this box must not be empty".

A schema is the set of table definitions. Types and constraints together keep the data valid. DDL (data definition language) is the part of SQL that creates and changes structure: CREATE, ALTER, DROP.

Constraints are declarative integrity rules: domain constraints (types, CHECK), entity integrity (primary keys) and referential integrity (foreign keys). The engine enforces them, which is stronger than checking in every application.

Schema change on huge live tables is a research and engineering topic of its own. Some ALTERs rewrite every row. Tools such as gh-ost and pt-online-schema-change for MySQL copy the table in the background and swap it in, and PostgreSQL can add a column with a constant default without rewriting the table (since version 11).

Going deeper: Why SQLite chose flexible typing

SQLite’s author describes flexible typing as a feature: a value has a type, and a column only prefers one. This matches scripting languages and lets old files keep working. STRICT tables were added later for people who want rigid columns. Both are documented on sqlite.org under datatype3 and stricttables.
