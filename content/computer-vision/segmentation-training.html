Lesson 1 of 5

Masks, logits and the pixel loss

The lecturer split machine learning design into three parts: data (what goes in and what comes out), the model (the last two chapters), and training and evaluation (this one). The slide adds: good segmentation is not only architecture, it is also data, loss, metric and understanding failures.

Ignore labels

Every image needs a mask of the same size. Some pixels cannot be labelled reliably: outside the annotated area, unclear boundaries, ambiguous regions. They get a reserved ID such as 255 and are skipped in the loss. In PyTorch this is nn.CrossEntropyLoss(ignore_index=255), with logits of shape B × C × H × W and targets B × H × W.

Logits

The lecturer: the value before the activation function is the logit, also called the score. Strictly, a logit is the log-odds ln(p ÷ (1 − p)) of logistic regression. Deep learning stretched the word to mean any raw score before SoftMax or sigmoid. Logits can be any real number. Loss functions take logits and apply SoftMax inside, which is numerically safer.

Pixel-wise cross-entropyExam favourite
L = −1|Ω| Σi ∈ Ω ln pi, yi
Ω is the set of valid pixels and pi, yi the probability given to the true class at pixel i. The one hot target picks out that one probability.
Prediction for a car pixelP(car)Loss −ln P
Good0.900.105
Uncertain0.500.693
Bad0.052.996
Average only the valid pixels
  1. A 5 × 5 loss map adds to 7.5, so the plain mean is 7.5 ÷ 25 = 0.30.
  2. Now five pixels with loss 0.5 carry the ignore label. The valid 20 pixels add to 7.5 − 2.5 = 5.0.
  3. Correct loss: 5.0 ÷ 20 = 0.25. Dividing by all 25 gives 0.20, silently biased.

Binary or categorical? A student answered correctly: binary cross-entropy for two classes with one sigmoid, categorical for many exclusive classes with SoftMax. For independent per class masks, use a sigmoid and binary CE on each channel.

Class imbalance: weighted CE, focal and Dice

ClassPixelsShare

The lecturer: every pixel counts equally, so the model gets very good at road and very bad at pedestrians, which is why people still ask whether self driving cars are safe for pedestrians. High pixel accuracy can hide poor performance on rare but important classes.

Weighted cross-entropyExam favourite
L = Σi wyi (−ln pi, yi)Σi wyi
Rare or important classes get larger weights.
Inverse frequency weight
wc = NC · nc
N pixels, C classes, nc pixels of class c. Every class then contributes N ÷ C weighted pixels.
Weights for the street image
  1. N = 100,000 and C = 5. Road: 100,000 ÷ (5 × 50,000) = 0.4. Sky 0.8, building 1.0, car 5.0, pedestrian 20.0.
  2. Each class now contributes 20,000 weighted pixels, for example 1,000 × 20 for pedestrians. Perfectly balanced.
  3. The slide's hand picked weights: road 0.5, sky 0.7, car 2.0, pedestrian 5.0. Three pixels with CE 0.1 (road), 0.7 (car) and 2.3 (pedestrian) give 0.05 + 1.4 + 11.5 = 12.95 over a total weight of 7.5, a mean of 1.727 against the plain 1.033.
Common mistake
Very large weights can make training unstable or raise false positives. Weights can follow importance, not only frequency.

Focal loss

Focal loss
FL = −(1 − pt)γ ln pt
The same function as in detection (chapter 5.2). It scales by difficulty rather than by class.
An easy and a hard pixel, γ = 2
  1. Easy road pixel, P = 0.99: CE = 0.01005, focal = 0.0001 × 0.01005 ≈ 1.0 × 10−6.
  2. Hard car pixel on the road boundary, P = 0.45: CE = 0.7985, focal = 0.55² × 0.7985 = 0.2415.
  3. The hard pixel weighs 79 times the easy one under CE, and about 240,000 times under focal loss. Not every pixel should teach equally.

Dice loss

Soft Dice lossExam favourite
LDice = 1 − 2 Σ pi gi + εΣ pi + Σ gi + ε
Uses probabilities, not 0 or 1, so it is differentiable. ε avoids 0 ÷ 0 when the class is absent.
Soft Dice on four pixels
  1. p = [0.9, 0.8, 0.2, 0.1], g = [1, 1, 0, 0].
  2. Σpg = 1.7, Σp = 2.0, Σg = 2.
  3. Dice = 3.4 ÷ 4 = 0.85, so the loss is 0.15.

A student asked why not train only on Dice, since it measures overlap directly. The lecturer: you can, if you design the loss for it. Such losses exist (V-Net, 2016). In practice Dice is usually combined with CE, because CE gives a steady gradient at every pixel while Dice is one global ratio whose gradients get noisy when the object is tiny or absent. A common recipe is L = CE + λ Dice. The lecturer's general form: α A + β B + γ C, with the weights chosen by what matters for your problem.

Lesson 3 of 5

Metrics: accuracy, Dice, IoU and mIoU

Accuracy 90%, tumour found: none
  1. A 10,000 pixel scan with 9,000 background and 1,000 tumour pixels. The model says background everywhere.
  2. Pixel accuracy = 9,000 ÷ 10,000 = 90%.
  3. Tumour: TP = 0, so IoU = 0 and Dice = 0.
  4. Background IoU = 0.9, so the two class mIoU = (0.9 + 0) ÷ 2 = 0.45. The metric that forces every class to count exposes the failure.
DiceExam favourite
Dice = 2|P ∩ G||P| + |G| = 2TP2TP + FP + FN
P prediction, G ground truth. The F1 score of the pixels.
IoU (Jaccard)Exam favourite
IoU = |P ∩ G||P ∪ G| = TPTP + FP + FN
The same IoU as for boxes, applied to pixel sets.
Relation
Dice = 2 · IoU1 + IoU,   IoU = Dice2 − Dice
Dice ≥ IoU always, equal only at 0 and 1.
The tumour example from the slides
  1. |G| = 100, |P| = 120, overlap 80. So TP = 80, FP = 40, FN = 20.
  2. Dice = 160 ÷ 220 = 0.727, about 72.7% overlap quality.
  3. Union = 100 + 120 − 80 = 140, so IoU = 80 ÷ 140 = 0.571.
  4. Check: 0.727 ÷ (2 − 0.727) = 0.571. Same prediction, two numbers. Never compare them as if they were one metric.

The lecturer's rule of thumb: Dice is preferred in medical work and IoU in road scenes and benchmarks such as PASCAL VOC and Cityscapes. Both measure overlap.

mean IoU

Compute IoU for each class, then average. The slide: road 0.91, sky 0.88, building 0.75, car 0.62, person 0.40 gives 3.56 ÷ 5 = 0.712. The person class drags it down, exactly the information pixel accuracy hides.

A confusion matrix by hand
  1. Rows are truth, columns are prediction. Road row 900, 20, 5. Car row 30, 140, 10. Person row 15, 5, 30. Total 1,155.
  2. For each class TP is the diagonal, FN the rest of its row, FP the rest of its column.
  3. Road: TP 900, FN 25, FP 45, IoU 0.928. Car: TP 140, FN 40, FP 25, IoU 0.683. Person: TP 30, FN 20, FP 15, IoU 0.462.
  4. mIoU = 0.691. Pixel accuracy = 1,070 ÷ 1,155 = 0.926, much higher. Frequency weighted IoU (about 0.87) also follows the big classes.
Common mistake
Benchmarks add one confusion matrix over the whole dataset, then compute IoU per class. Averaging per image IoUs is different and noisier, since an image without a class gives 0 ÷ 0. Say which one you report.

Boundaries

Two masks can have the same IoU while one has blurry edges and the other has sharp edges and a small area error. For surgical planning, lanes and thin structures, edges matter. Boundary F-score and Boundary IoU compare only pixels near the true contour. Hausdorff distance is the worst gap between the two outlines, and HD95 uses the 95th percentile to ignore stray outliers.

ApplicationPreferWhy
Small brain tumourDice or IoU, plus recallTiny foreground, a miss is costly
Road and sidewalk edgesBoundary metric plus IoUEdges matter
Balanced many class benchmarkmIoUEvery class counts
Surgical planning, lane markingsBoundary F-score, HD95A few pixels of edge error matter
Lesson 4 of 5

The training pipeline and data leakage

Augmentation

Medical datasets are small, so augmentation shows the model more variety. Spatial transforms (flip, rotate, crop, scale) must hit the image and the mask identically. The lecturer: if I flip the image I flip the mask, so X and Y stay matched. Colour changes, noise and brightness go to the image only, since class IDs are not colours. Libraries such as albumentations take aug(image=img, mask=mask) and handle this.

Resizing masks

A strip of road (1) next to a car (3), resized with bilinear interpolation, gets the values 1.5 and 2.5. Rounded, they become 2, a sidewalk that is not there. Images may use bilinear or area resizing. Masks must use nearest neighbour. Predicted logits are continuous, so they may be resized bilinearly before argmax.

The loop

  1. Load an image and its mask.
  2. Apply the same spatial augmentation to both.
  3. Forward pass to B × C × H × W logits.
  4. Loss over valid pixels, skipping the ignore label.
  5. Back-propagate and update the weights.
  6. After each epoch, run the validation set, argmax, add up a confusion matrix and report mIoU or Dice.

Validation without self deception

SplitRole
TrainUpdates the weights
ValidationTunes settings and selects models
TestUsed once for the final report

A student asked what avoiding self deception means. The lecturer: if you apply min-max normalisation using Xmin and Xmax of all the data, the model learns the test distribution through the scaling. It looks good on the test set but is not. That is data leakage.

The leak in numbers
  1. Training values 10, 20, 30 and one test value 100, a genuinely different case.
  2. Right: fit on training only, min 10, max 30. The test value maps to (100 − 10) ÷ 20 = 4.5, outside 0 to 1, so the shift is visible.
  3. Wrong: fit on all, min 10, max 100. Training becomes 0, 0.111, 0.222 and the test point 1.0. The shift is hidden and the validation score is flattered.
In the exam
Leakage in segmentation also comes from slices of one patient or frames of one video landing in both train and test. Split by patient, scene or video, never by random image. A model with high training IoU and low validation IoU is probably overfitting.

Case questions from the slides

  1. Small brain tumour, a miss is serious. The class answered Dice. Measure Dice or IoU and recall on the tumour class. Train with CE plus Dice, or weighted CE or focal loss.
  2. Road scene where the road and sidewalk boundary matters. Boundary problem. Inspect boundary F-score or Boundary IoU, and fix with skips, a high resolution decoder or a boundary loss.
  3. Crop and weed look alike under new lighting. Both domain shift and class confusion. Use colour and lighting augmentation, more diverse data and domain adaptation.

The last question in class: segmentation understands the scene, but how does that become the right action for a car? The recording ends before the answer. A driving system is a pipeline: perception (segmentation, detection, depth, tracking), prediction of where others will move, planning of a safe path, and control of steering and brakes. Segmentation supplies the map of drivable space. It does not decide.

One idea, four depths

To train a pixel labeller you need a mask for every image, a score that punishes wrong pixels, and fair ways to measure success. Counting correct pixels can fool you when one class is tiny, so we measure overlap for each class instead.

Pixel CE averages −ln p over valid pixels, skipping the ignore label. Imbalance is handled with class weights N ÷ (C nc), focal loss or Dice. Report per class IoU and mIoU, or Dice, never accuracy alone. Dice = 2·IoU ÷ (1 + IoU). Resize masks with nearest neighbour and fit statistics on the training split only.

Benchmarks pool one confusion matrix over the dataset. Boundary metrics and HD95 capture edge quality that region overlap misses. Lovász-softmax optimises IoU directly. Split by patient or scene to avoid leakage, and diagnose failures by type before changing the architecture.

Calibration of pixel probabilities, uncertainty maps and conformal prediction for masks matter in medicine and driving. Domain generalisation and test time adaptation target the shift problem. Topology aware losses (for vessels and roads) preserve connectivity that IoU ignores.
