Datasets and the long tail

To score a detector you first need labelled images, then a metric that copes with boxes, duplicates and misses. This chapter builds both. The lecture started with the four datasets almost every paper uses.

DatasetClassesImages (slide)Notes
PASCAL VOC20about 5KThe classic small benchmark. The 2007 train and validation split has 5,011 images.

The lecturer asked what happens to accuracy if the dataset shrinks. Expect a learning curve: mAP falls as data shrinks, and it falls fastest for rare classes. Starting from a pre-trained backbone, covered at the end of this chapter, softens the fall.

The long tail

Plot the number of boxes per class with classes sorted by frequency and you get a few classes with huge counts and many with very few. A student called it class imbalance. The lecturer gave the more exact name: a long tailed dataset, where the imbalance is across semantic categories.

ImbalanceWhereTypical cure
Foreground against backgroundInside every image, most anchors see backgroundFocal loss, hard example mining (chapter 5.2)

Repeat factor sampling (LVIS)Exam favourite
r(c) = max(1, √t ÷ f(c)),   r(image) = max over its classes r(c)
f(c) is the fraction of training images that contain class c and t is a threshold, 0.001 in the LVIS paper. Images with rare classes are shown r times per epoch.
A rare class
  1. t = 0.001 and the class appears in f = 0.0001 of the images.
  2. t ÷ f = 10, and the square root is about 3.16.
  3. Images that contain this class are repeated about 3 times per epoch. A class in 5% of images gives √0.02 < 1, so the max keeps it at 1.
Remember
Always look at the class histogram of a dataset before comparing mAP numbers. A model can look good on average while failing every rare class.
Lesson 2 of 6

Matching detections: TP, FP and FN

The lecturer showed why classification is easy to score: four images, three correct labels, accuracy 75%. Detection has two extra problems.

  1. Location errors. The predicted dog box is near the true box but not on it. How close is close enough?
  2. Over and under prediction. Three boxes on one dog and none on a second dog. One accuracy number cannot capture too many and too few.

Close enough means IoU above α

A detection counts as correct when its IoU with a true box exceeds a threshold α that we choose, exactly as we choose a probability threshold in classification. The lecturer showed overlaps of 0.5, 0.7 and 0.95 and asked which to accept. Her answer: it depends on you.

ThresholdMeaningSuits
α = 0.5Roughly the right place. The PASCAL VOC rule.Counting people in a crowd
α = 0.75A tight boxA robot grasping an object, measuring size
0.5 to 0.95 averagedRewards tight boxes at every level. The COCO rule.Comparing detectors fairly

For two equal squares shifted sideways by a fraction s of their width, IoU = (1 − s) ÷ (1 + s): 0.818 at 10%, 0.667 at 20%, 0.538 at 30% and 0.333 at 50%. A shift of a third of the width already fails at α = 0.5.

The matching rules

OutcomeRule
True positive (TP)Right class, IoU above α with a true box that has not been matched yet
False positive (FP)IoU below α (poor box), lies on background, or a duplicate of an object already matched
False negative (FN)A true object that no detection matched. Also called a miss.
True negativeNot used. The number of empty windows is effectively infinite.
Three dogs, four detections, α = 0.5
  1. Sort by score: d1 0.95, d2 0.90, d3 0.85, d4 0.60.
  2. d1 overlaps GT1 with IoU 0.80 and GT1 is free, so TP. GT1 is now matched.
  3. d2 best overlaps GT2, but IoU 0.30 is below 0.5, so FP. GT2 stays free.
  4. d3 overlaps GT3 with IoU 0.75, so TP.
  5. d4 overlaps GT1 with IoU 0.60, but GT1 is taken, so FP (a duplicate).
  6. GT2 was never matched, so FN = 1. Totals: TP 2, FP 2, FN 1.
In the exam
Remember the names this way. The first word says whether the model was right, the second says what it predicted. A false positive is a box the model drew that was wrong. The lecturer added that books draw the confusion matrix in different layouts, so learn the idea and not one picture.
Lesson 3 of 6

Precision, recall and the score threshold

PrecisionExam favourite
P = TPTP + FP
Of the boxes the model drew, how many were right. False alarms lower it.
RecallExam favourite
R = TPTP + FN
Of the real objects, how many were found. Misses lower it.
F1 score
F1 = 2PRP + R
The harmonic mean. It is low if either one is low.

For the three dogs: P = 2 ÷ 4 = 0.50, R = 2 ÷ 3 = 0.667 and F1 = 2(0.5)(0.667) ÷ 1.167 = 0.571.

Which one matters more

Students said medical cases need precision and fraud detection needs recall. The lecturer agreed for fraud: calling an honest case suspicious is acceptable, missing a fraud is not. The medical case needs care. In screening, such as finding a tumour on a scan, a miss is the worst error, so recall comes first and a second test clears the false alarms. Precision comes first when the next action is costly or cannot be undone, such as surgery or blocking an account. Ask which mistake costs more.

The score threshold

The last step of a detector keeps only boxes whose score is at least a threshold. The lecturer: move it one way and precision falls while recall rises, move it the other way and the reverse happens.

Precision is not perfectly monotonic: 0.75 at 0.2, then 0.67 at 0.4. That zig-zag is the reason the next lesson smooths the curve. Instead of arguing about one threshold, look at all of them at once.

Lesson 4 of 6

The PR curve and average precision

Sweep the score threshold, record (recall, precision) at each step and plot recall across and precision up. That is the precision recall curve. An ideal detector hugs the top right corner. Average precision (AP) is the area under the curve: a single number between 0 and 1, always stated for an IoU threshold, such as AP@0.5.

Interpolated precisionExam favourite
pinterp(r) = maxr′ ≥ r p(r′)
The best precision at this recall or any higher recall. It turns the zig-zag into a staircase that only goes down.
AP, all pointsExam favourite
AP = Σk (rk − rk−1) · pinterp(rk)
Add a rectangle each time recall increases.
AP, 11 points
AP11 = 111 Σr ∈ {0, 0.1, …, 1} pinterp(r)
PASCAL VOC 2007. COCO uses 101 points, 0 to 1 in steps of 0.01.
AP for one class, 6 true objects, 10 detections
  1. Rank by score and mark TP or FP: T T F T F T F T F F. Five of the six objects are found, so recall stops at 5 ÷ 6 = 0.833.
  2. Running precision and recall: 1.000 and 0.167, 1.000 and 0.333, 0.667 and 0.333, 0.750 and 0.500, 0.600 and 0.500, 0.667 and 0.667, 0.571 and 0.667, 0.625 and 0.833, 0.556 and 0.833, 0.500 and 0.833.
  3. Envelope: 1.000 up to recall 0.333, 0.750 up to 0.5, 0.667 up to 0.667, 0.625 up to 0.833, then 0.
  4. Area: 0.333 × 1.000 + 0.167 × 0.750 + 0.167 × 0.667 + 0.167 × 0.625 = 0.3333 + 0.1250 + 0.1111 + 0.1042 = 0.674.
  5. 11 points: (4 × 1.0 + 2 × 0.75 + 0.667 + 2 × 0.625 + 0 + 0) ÷ 11 = 0.674 as well.
Going deeper: Why use the envelope

A false positive at rank 3 lowers precision for a moment. A user who wants more recall would pick whichever threshold gives the best precision at that recall or higher, so the dip is never a real operating point. Taking the envelope removes the dip and makes AP less sensitive to the exact order of detections with nearly equal scores.

Lesson 5 of 6

mAP and the COCO protocol

AP is for one class. The headline number averages it.

  1. Compute AP separately for every class: airplane, apple, backpack, banana and so on.
  2. mAP is the mean of those APs at one IoU threshold, for example mAP@0.5 or mAP@0.75.
  3. COCO also averages over ten IoU thresholds, 0.50, 0.55 up to 0.95. That is the number papers call AP or mAP@[0.5:0.95]. It rewards accurate boxes, not just finding the object.
mAPExam favourite
mAP = 1C Σc APc
The mean over the C classes.
COCO APExam favourite
APCOCO = 110 Σt ∈ {0.50, 0.55, …, 0.95} mAPt
Mean over classes and over IoU thresholds.
mAP by hand
  1. Class APs at IoU 0.5: dog 0.72, cat 0.65, car 0.80.
  2. mAP@0.5 = (0.72 + 0.65 + 0.80) ÷ 3 = 2.17 ÷ 3 = 0.723.
  3. One class across the ten thresholds: 0.80, 0.78, 0.75, 0.71, 0.66, 0.60, 0.52, 0.42, 0.27, 0.08 (illustrative values).
  4. Their mean is 5.59 ÷ 10 = 0.559, well below the 0.80 at IoU 0.5, because tight boxes are demanded.

COCO also reports APS, APM and APL for small objects (area below 32² pixels), medium ones and large ones (above 96² pixels), and average recall. APS is almost always the lowest, which is why feature pyramids matter.

Check which metric a paper reports. COCO AP numbers of 30 to 50 look small next to PASCAL VOC AP@0.5 numbers of 70 to 90, but they measure a much stricter thing.
Lesson 6 of 6

Choosing, speeding up and training a detector

How to pick a model

Three choices: the meta-architecture (SSD, Faster R-CNN, R-FCN and others), the feature extractor (VGG, ResNet, Inception, MobileNet) and the image size (300 × 300 up to 800 × 1296). Then the deployment limits: the sensor, the device (laptop, data centre, phone, Raspberry Pi, TPU), the latency and the memory. The lecturer was firm that no model is guaranteed best for a domain. Try several architectures and several resolutions, measure, and choose.

The Pareto frontier

Slides from Huang and colleagues (CVPR 2017) plot mAP against GPU time for many detectors. Past a certain accuracy each extra point costs much more time. The best detectors lie on the Pareto optimal curve. A student offered the Pareto principle, the 80/20 rule. Same Vilfredo Pareto, different idea. A model is Pareto optimal when no other model is at least as good on both accuracy and speed and strictly better on one.

Seven detectors (mAP, latency in ms)
  1. A (21, 30), B (24, 45), C (30, 90), D (32, 80), E (34, 150), F (37, 200), G (28, 120).
  2. C: D is more accurate and faster, so C is dominated. G: D beats it too.
  3. A, B, D, E and F: none is beaten on both counts, so they form the frontier.
  4. Choose along it by budget: A or B for real time on a phone, F for offline accuracy.

Simple speed levers

  • Lower resolution, for example 300 instead of 600: much faster, but small objects shrink and are missed.
  • Fewer proposals in a two stage detector, for example 100 instead of 300: much faster with a small loss of recall. Big backbones gain more from many proposals than small ones.

Bigger images need more memory each, so the batch shrinks, from 32 to 2 for example. Batch normalisation estimates a mean and variance from the batch, and the standard error of a batch mean grows like 1 ÷ √N. Going from 32 to 2 images makes the estimate √16 = 4 times noisier. The cures: freeze batch norm and reuse the pre-trained statistics, use GroupNorm which normalises within each image, or use synchronised batch norm across many GPUs.

Transfer learning

Start from a network pre-trained to classify a larger dataset, then fine tune it for detection. The slide (Sun and colleagues, 2017): COCO AP rises from 34.3 with ImageNet pre-training to 36.7 with JFT-300M, a set of 300 million images, and to 37.4 with both. Larger pre-training data helps, and it also softens the small data drop from the first lesson.

One idea, four depths

To check a detector we count how many of its boxes were right and how many real objects it found. One number, average precision, sums up both. Picking a detector means balancing how accurate it is against how fast it runs.

A detection is a TP when its IoU with an unmatched true box is above α. Precision is TP ÷ (TP + FP), recall is TP ÷ (TP + FN). Sweeping the score threshold gives the PR curve, AP is its area, and mAP averages AP over classes. Models on the Pareto frontier are the only sensible choices.

AP uses the interpolated envelope, all points or 11 or 101 sampled recalls. COCO averages over IoU 0.50 to 0.95 and reports AP by object size. Long tailed data needs repeat factor sampling r = max(1, √(t ÷ f)). Small batches make batch norm noisy as 1 ÷ √N, so detectors freeze BN or use GroupNorm or Sync-BN.

LVIS introduced federated annotation and rare, common and frequent splits. Newer metrics address AP blind spots, for example LRP error and the boundary aware measures for masks. Speed comparisons are only fair on the same hardware, batch size and precision, and many papers now report latency with export to TensorRT or similar runtimes.
