Lesson 1 of 6

FCN: turning a classifier into a segmenter

A classifier ends with global pooling or a fully connected layer and one label. A fully convolutional network (FCN, Long and colleagues, 2015) keeps a spatial grid to the end, so it outputs class scores at every location. The lecturer's caution: the first dense map is coarse. A 256 × 256 image gives only a small score map, which must then be upsampled to 256 × 256.

Going deeper: A fully connected layer is a convolution

A fully connected layer on a 7 × 7 × 512 map flattens it to 25,088 numbers and multiplies by a 25,088 × 4,096 matrix. A 7 × 7 convolution with 512 input channels and 4,096 filters, applied at the one place where it fits, computes the same sums with the same weights: 7 · 7 · 512 · 4,096 = 102,760,448 of them.

The difference shows on a larger input. On a 14 × 14 × 512 map the convolution slides and gives (14 − 7) + 1 = 8, an 8 × 8 grid of scores, while the fully connected layer only accepts 7 × 7. So any classifier can be converted into a dense predictor.

VariantUsesMap for 256 × 256Final upsamplingResult
FCN-32sonly the 1/32 map8 × 8×32strong meaning, coarse boundaries
FCN-16sadds the 1/16 map16 × 16×16better spatial detail
FCN-8sadds the 1/8 map32 × 32×8even better boundaries

The lecturer: deeper layers give meaning, early layers give refined location, and we need to combine them. FCN-16s and FCN-8s add earlier score maps to the upsampled deep one. That is the start of the skip connection idea.

Remember
A smaller final jump means less blur. For a 512 × 512 image FCN-8s predicts on a 64 × 64 grid, four times finer in each direction than the 16 × 16 grid of FCN-32s.

Three ways to make a map bigger

The literature went from nearest neighbour to bilinear interpolation to learned upsampling.

MethodHowGoodLimit
Nearest neighbourCopy each value into an F × F blockSimple, fast, keeps the original valuesBlocky boundaries, learns nothing
BilinearWeighted average of the 4 nearest inputsSmoothOnly blends, does not know where a boundary lies
Transposed convolutionLearned kernel spread over the outputLearns shapes, such as a road edge against a person edgeCan still fail if the encoder lost the information
Bilinear 2 × 2 → 4 × 4 with values 0, 100, 100, 200
  1. Half pixel centres: output pixel i sits at input coordinate (i + 0.5) ÷ 2 − 0.5, so −0.25, 0.25, 0.75, 1.25, clamped to 0, 0.25, 0.75, 1.
  2. The map is f = 100x + 100y, which is linear, so bilinear reproduces it exactly.
  3. Rows: 0, 25, 75, 100 | 25, 50, 100, 125 | 75, 100, 150, 175 | 100, 125, 175, 200.
  4. With align corners the first row would be 0, 33, 67, 100. Frameworks differ, so check the setting.

Transposed convolution

Output sizeExam favourite
Hout = (Hin − 1) · s − 2p + k + pout
s stride, p padding, k kernel, pout extra output padding. With Hin = 16, k = 4, s = 2, p = 1 the size doubles to 32.
2 × 2 input, 3 × 3 kernel, stride 2
  1. Input [[1, 2], [3, 4]], kernel [[1, 0, 1], [0, 1, 0], [1, 0, 1]]. Output size (2 − 1) × 2 + 3 = 5.
  2. Each input value scales the whole kernel and is added at (i · 2, j · 2).
  3. Placements overlap in row and column 2. The centre gets 1 + 2 + 3 + 4 = 10, because all four corner weights land there.
  4. Output rows: [1, 0, 3, 0, 2], [0, 1, 0, 2, 0], [4, 0, 10, 0, 6], [0, 3, 0, 4, 0], [3, 0, 7, 0, 4].
Going deeper: Why it is called transposed

An ordinary convolution is a linear map y = Cx, where each row of the matrix C holds the kernel at one output place. Back-propagation sends gradients back with Cᵀ. Using Cᵀ in the forward direction, y = Cᵀx, maps the small size back to the large one with the same connection pattern. It is not an inverse: it restores the size, not the values.

Common mistake
When the kernel size is not divisible by the stride, some output cells receive more overlapping contributions than others, which prints a checkerboard pattern into the mask. Fixes: kernel = 2 × stride (k = 4, s = 2), or resize with nearest or bilinear and then apply a normal convolution, or use sub-pixel convolution (PixelShuffle).

A student asked whether transposed convolution causes overfitting. The lecturer: overfitting is a different matter. It happens when the data is limited and the model is big, in any architecture. Detect it by comparing training and validation scores.

Encoder, decoder and skip connections

EncoderDecoder
Resolutionreducesrestores
Receptive fieldgrows
Produceshigh level meaningdense class scores
AnswersWhat is present?Where exactly?

The slide: compress the scene into meaning, then expand meaning back into a pixel map. The output is not a photo. It is a class map.

Track the tensor shape
  1. Input 256 × 256 × 3, encoder feature 64 × 64 × 128, bottleneck 16 × 16 × 512.
  2. A 1 × 1 classifier on the bottleneck gives 16 × 16 × C. With C = 7 that is 16 × 16 × 7.
  3. The decoder upsamples ×16 to 256 × 256, then argmax gives the mask.
  4. The 1 × 1 head alone has 512 × 7 + 7 = 3,591 parameters.

The bottleneck

Low resolution, many channels, a large receptive field. It recognises what is present and uses context to resolve ambiguity, but its spatial detail is coarse. How far to shrink, 32 × 32, 16 × 16 or 8 × 8, is a hyperparameter the lecturer said you find by experiment.

Going deeper: Side topic: autoencoders and VAEs

An autoencoder maps x to a code z and back to x̂, trained on the reconstruction error. A variational autoencoder outputs a mean μ and variance σ² for each latent feature, and samples from that distribution, which lets it generate varied new images. Its training adds a KL term that keeps each distribution close to N(0, 1):

KL = ½ (μ² + σ² − 1 − ln σ²). For μ = 0.5 and σ = 0.8 this is ½(0.25 + 0.64 − 1 − ln 0.64) ≈ 0.168. It is 0 exactly when μ = 0 and σ = 1.

Sampling is made differentiable with z = μ + σ ε, where ε is drawn from N(0, 1). An autoencoder's target is its own input. A segmentation network's target is a mask. The shape is shared, the purpose is not.

Why plain encoder-decoders fail, and the fix

The lecturer: if something is missing in the encoder, the decoder cannot reconstruct it. So build a bridge from each high resolution encoder level to the decoder level of the same size. These are skip connections, and they carry WHERE information: edges, local texture, exact position and small structures lost after pooling.

FusionHowCost (128 × 128 map, 64 + 64 channels, 3 × 3 conv to 64)
Concatenate (U-Net)Stack both feature sets, the next conv learns how to mix them3 · 3 · 128 · 64 + 64 = 73,792
Add (FCN, FPN, ResNet)Shapes must match, both go into one shared space3 · 3 · 64 · 64 + 64 = 36,928

The lecturer's view: fusion is also driven by science, so test which one your domain needs. An executive student asked for a framework that pinpoints what to change. Her answer: watch where the model fails and design for it. Neural architecture search automates part of this, but its search space still encodes human expertise.

Lesson 4 of 6

U-Net

U-Net (Ronneberger and colleagues, 2015) was built for cell images in microscopy, where boundaries must be precise and labelled data is scarce. It is a symmetric encoder-decoder that copies high resolution encoder maps into the decoder at every level. The lecturer stressed that a large share of medical papers build on it. Its descendants include U-Net++, Attention U-Net, 3D U-Net and nnU-Net, which configures a U-Net for a new dataset automatically. U-Net also sits inside diffusion image generators as the denoiser.

PartWhat happens
Contracting pathTwo 3 × 3 convs, then 2 × 2 max pool. Resolution halves, channels double, features become more semantic.
BottleneckThe most compressed map: strongest context, coarsest detail.
Expanding path2 × 2 up-convolution, concatenate the skip, two 3 × 3 convs. A final 1 × 1 conv gives class scores.
SkipsU-Net does not wait until the end to recover detail. It injects detail at every decoder stage.
Why the original output is smaller than its input
  1. The 2015 paper used unpadded 3 × 3 convs, each removing 2 pixels. Start with a 572 × 572 tile.
  2. Encoder: 572 → 568 (skip) → 284 → 280 (skip) → 140 → 136 (skip) → 68 → 64 (skip) → 32.
  3. Bottleneck: 32 → 28. Up to 56, crop the 64 skip to 56, convs to 52.
  4. Up to 104 (crop 136), convs to 100. Up to 200 (crop 280), convs to 196. Up to 392 (crop 568), convs to 388.
  5. Large images are processed as overlapping tiles. Modern code pads, so sizes go exactly 256, 128, 64, 32, 16 and back.
Where the 31 million parameters sit
  1. A 3 × 3 conv from Cin to Cout has 9 Cin Cout + Cout parameters. The first block (1 → 64 → 64) has 640 + 36,928 = 37,568.
  2. The deepest block (512 → 1024 → 1024) has 4,719,616 + 9,438,208 = 14,157,824, almost half the network.
  3. Decoder convs take twice the channels because of concatenation. The level 4 decoder conv takes 1,024 in and gives 512: 9 · 1,024 · 512 + 512 = 4,719,104.
  4. All convs, up-convs and the final 1 × 1 (1 input channel, 2 classes) add to 31,030,658, about 31.0 M.

Lesson 5 of 6

Dilated convolution, ASPP and DeepLab

Even with skips, U-Net struggles when objects appear at very different scales. Good segmentation balances two problems.

Boundary problemContext problem
Edges may be thin or irregularA grey patch could be road, wall or roof
Nearby classes may look alikeWide scene context resolves it
The mask can leak outside the objectDeep features and large receptive fields help
High resolution features helpBut enlarging the receptive field has a cost

Ways to see more context: bigger kernels (parameters grow with k²), more layers, more downsampling (loses resolution, the very problem), or dilation, which is free in parameters and keeps resolution.

Dilated 3 × 3 kernelExam favourite
keff = k + (k − 1)(r − 1) = 2r + 1
r = 1, 2, 4, 6, 12, 18 cover 3, 5, 9, 13, 25 and 37 cells. Always 9 weights. Padding r keeps the map size.
Stacking dilations 1, 2, 4, 8
  1. Each layer adds 2r to the receptive field.
  2. r = 1 + 2(1 + 2 + 4 + 8) = 31, against 9 for four plain layers.
  3. A 256 → 256 channel layer has 589,824 weights for any rate, and the same number of multiply adds.

A student asked whether the dots in the dilated picture are pixels. Yes: the taps read ordinary neighbouring pixels r apart, and the pixels in the gaps are simply not used. Another asked whether the network could choose its own dilation. The lecturer said it is a hyperparameter in classic models. Deformable convolution (Dai and colleagues, 2017) does learn per pixel sampling offsets, which is close to that idea.

ASPP and DeepLab

Atrous spatial pyramid pooling runs several dilated branches in parallel on the same map: a 1 × 1 conv, three 3 × 3 convs with rates 6, 12 and 18, and an image level pooling branch. Their outputs are concatenated and mixed by a 1 × 1 conv. At output stride 16 the three dilated branches see about 13 × 16 = 208, 25 × 16 = 400 and 37 × 16 = 592 input pixels across. The slide's picture: several observers with different zoom levels describing the same map.

DeepLabv3+ adds a light decoder: the ASPP output (stride 16) is upsampled ×4, concatenated with a reduced low level map at stride 4, refined and upsampled ×4 again. Context for WHAT, decoder detail for WHERE.

Choosing an architecture from its failures

The slide: architecture design is not arbitrary, it is driven by segmentation failures. Ask four questions. Do we need small object accuracy? Do boundaries matter? Do we need global context? What are the latency and memory limits?

ApplicationSensible startWhy
Medical tumour boundaryU-Net or encoder-decoderBoundary accuracy with little data
Street scenesDeepLab style or a transformerMany scales and much context
Drone or phoneLightweight encoder-decoderLatency and memory
Satellite land coverMulti-scale context modelLarge regions and very small structures
FailureArchitectural fix
Blurry object boundariesSkip connections, a high resolution decoder
Small object missedHigh resolution features, multi-scale design
Road confused with sidewalkBroader context, DeepLab style modules
Thin structure disappearsLess aggressive downsampling, more skips
Object scale varies a lotASPP, feature pyramids

Three scenarios from the slides

  1. 95% pixel accuracy, but pedestrians and cyclists are missed. Not a good model. Road, sky and buildings dominate the pixels. Check per class IoU, mIoU, pedestrian recall, the confusion matrix and failures at night, under occlusion and at distance.
  2. FCN-32s finds the person but misses arms and legs. The 8 × 8 map knows person but not the outline, and one ×32 jump makes a blob. Fuse earlier features: FCN-16s or 8s, or U-Net skips.
  3. A tumour covers 2% of pixels, and predicting all background scores 98%. Tumour recall and Dice are 0. Measure Dice or IoU on the tumour, and weight the loss: wc = N ÷ (C · nc) gives background 100 ÷ (2 × 98) = 0.510 and tumour 100 ÷ (2 × 2) = 25, so both classes now carry half the loss.
In the exam
The class answered context for road against sidewalk confusion, and both slide decks agree. The recording has the lecturer saying boundary, which is most likely a transcription slip. In exams: road and sidewalk confusion is a context problem.
One idea, four depths

To label every pixel, a network first shrinks the image to understand what is in it, then grows it back to full size. Shortcuts carry fine detail from the early layers to the late ones so edges stay sharp.

FCN replaces the classifier head with convolutions. Upsampling uses nearest, bilinear or learned transposed convolution. U-Net copies each encoder level into the decoder. DeepLab uses dilated convolutions, keff = 2r + 1, and ASPP to see many scales without losing resolution.

Transposed convolution is the adjoint Cᵀ of a convolution, with Hout = (Hin − 1)s − 2p + k + pout. U-Net parameters concentrate at the bottleneck. Concatenation costs twice the input channels of addition. Dilation stacks risk gridding, which mixed or parallel rates avoid.

HRNet keeps a high resolution branch all the way through. Attention U-Net gates the skips, and nnU-Net automates configuration and is a strong medical baseline. Transformer encoders such as SegFormer and Swin, and mask classification heads (Mask2Former), now lead most benchmarks, covered in the vision and language step.
