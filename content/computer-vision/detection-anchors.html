Lesson 1 of 5

What a detector predicts

Classification says what is in the picture. Object detection says what is there and where, for every object, however many there are. The lecture calls it a multi-task problem: identify each object and locate it.

TaskAnswersOutput
ClassificationWhat is in the image?One class label
LocalisationWhat and where, one objectOne label and one box
DetectionWhat and where, many objectsA list of (class, box, score) of any length
SegmentationWhere, pixel by pixelA class for every pixel

For each object a detector returns three things: a class label (person, car, dog, with background as an extra class), a bounding box of four numbers, and a confidence score such as 0.94.

Two box formatsExam favourite
(x1, y1, x2, y2)   ⟷   (xc, yc, w, h)
xc = (x1 + x2) ÷ 2, w = x2 − x1, and the same for y. Image y grows downwards.
Detection output
{{ class, box, confidence }} × N objects
N is not known in advance. It can be 0 or 50.

Why detection is harder than ImageNet classification

  • The number of outputs varies from image to image.
  • Objects can be tiny, with far fewer pixels than an ImageNet photo, so the model must use context: a kite is in the sky, a surfer is on the sea.
  • Images must be larger, often 600 × 1000 or more, so small objects keep enough pixels.
ApplicationWhich mistake hurts more
Self driving and driver assistanceA missed pedestrian (false negative), so favour recall
SurveillanceA missed threat, but too many false alarms cause alarm fatigue
Crop disease spottingMissed disease loses the crop, false alarms waste spray
Medical screeningA missed lesion, so favour recall and let a doctor confirm
Lesson 2 of 5

Sliding windows and their four problems

The simplest detector: take a window, place it in a corner, crop the patch, run a classifier that answers background or which class, then slide the window one step and repeat over the whole image. The lecturer compared it to working out a product by repeated addition, 2 + 2 + 2 + …, instead of multiplying. It always works, but the cost is huge.

Number of window positionsExam favourite
N = (⌊W − ws⌋ + 1) × (⌊H − hs⌋ + 1)
Image W × H, window w × h, stride s. For every window shape and scale.
ProblemWhat goes wrong
LocationA small step is accurate but slow. A large step is fast but can cut an object in half and miss it.
ScaleObjects can be tiny or huge. A small window loses context, a fixed window cannot fit both a far person and a near bus.
ShapePeople are tall, cars are wide. One square window fits neither.
ComputationThousands of windows, each a full classifier pass, recomputing almost the same pixels as its neighbours.
The lecture count for a 640 × 480 image
  1. Window 64 × 128 (a person shape), stride 8.
  2. Across: ⌊(640 − 64) ÷ 8⌋ + 1 = 72 + 1 = 73. Down: ⌊(480 − 128) ÷ 8⌋ + 1 = 44 + 1 = 45.
  3. Total: 73 × 45 = 3,285 windows for this one shape. Stride 4 gives 12,905 and stride 1 gives 203,681.
  4. At about 4 GFLOPs per ResNet-50 pass, 3,285 windows need about 13 TFLOPs, over a second on a fast GPU. Add 9 shapes and it reaches about 94 TFLOPs, around 9 seconds. Real time needs about 30 milliseconds.
In the exam
Overlap between windows is a consequence, not a separate problem. A fine stride makes neighbouring windows overlap heavily, and that is why the same pixels are processed again and again.
Lesson 3 of 5

Anchor boxes and box regression

The fix is to test far fewer rough boxes and learn how to adjust them. An anchor is a predefined rough box at a fixed place. The lecturer put it simply: do not try to be perfect, just put one box. The network then predicts four corrections that move and resize the anchor onto the object.

Choosing a class is classification, a choice from a finite list. The corrections are regression, because a box can take infinitely many positions and sizes, so they are real numbers. Detection uses both.

The simple version from the lecture

Anchor centre (100, 150), size 40 × 80, corrections Δx = +5, Δy = −10, Δw = +8, Δh = +4
  1. New centre x = 100 + 5 = 105, new centre y = 150 − 10 = 140.
  2. New width = 40 + 8 = 48, new height = 80 + 4 = 84.
  3. Final box: centre (105, 140), size 48 × 84. No exhaustive search was needed.

The version real detectors use

Real detectors predict corrections relative to the anchor size, and use logarithms for the sizes.

Encode (make the training target)Exam favourite
tx = x − xawa,   ty = y − yaha,   tw = ln wwa,   th = ln hha
Anchor (xa, ya, wa, ha), true box (x, y, w, h), all in centre size form.
Decode (turn a prediction into a box)Exam favourite
x = xa + txwa,   y = ya + tyha,   w = waetw,   h = haeth
The exact reverse of encoding.

Why divide by the anchor size, and why logarithms

  • Same meaning at every scale. A 10 pixel error is half of a 20 pixel object but only 2% of a 500 pixel one. Dividing by the anchor size makes the targets comparable.
  • Positive sizes for free. w = waetw is positive for any tw, so the network can output any number.
  • Symmetry. Doubling is ln 2 = +0.693 and halving is ln ½ = −0.693, equal effort in opposite directions.
  • Scale invariance. A 75 pixel box on a 60 pixel anchor and a 750 pixel box on a 600 pixel anchor both give ln 1.25 = 0.223.
Lesson 4 of 5

Anchor grids, shapes and convolutional heads

Where do the anchors come from? Run the backbone CNN once over the whole image. Each position of its feature map sees a patch of the image through its receptive field and is treated as one sliding window anchor. The same small classifier and box regressor are applied at every position, and applying the same weights everywhere is exactly what a convolution does. One forward pass therefore scores every anchor at once. This answers the hint on the sliding window slide: fast, and not so inaccurate after all.

Heads as convolutions
class scores = SoftMax(Conv(V, Wcls)),   offsets = Conv(V, Wloc)
V is the feature map. Two heads, one backbone.
Head sizesExam favourite
class channels = k(C + 1),   box channels = 4k
k anchors per position, C classes plus background.

Several shapes and sizes

With one anchor shape the network cannot cope with fine and coarse objects in the same picture. So each position gets several anchors, typically 3 scales × 3 aspect ratios = 9: tall ones for pedestrians, wide ones for cars and buses, small and large for far and near objects. Each anchor type has its own classifier and regressor.

SSD (2016) also predicts from several layers: fine 38 × 38 maps for small objects and coarse 3 × 3 and 1 × 1 maps for large ones. With 4 or 6 anchors per cell it scores 38² × 4 + 19² × 6 + 10² × 6 + 5² × 6 + 3² × 4 + 1² × 4 = 8,732 boxes per class.

How close must the anchors be?

Anchor stride rule
s ≤ 0.367 w
Worst case: the object sits midway between four grid points. Requiring IoU ≥ 0.5 there gives (w − s/2)² ≥ ⅔ w², which simplifies to this.
Remember
This is why anchor sizes grow with the stride of each feature level. RetinaNet uses anchors of 32 on its stride 8 level: 8 ÷ 32 = 0.25, safely under 0.367.
Lesson 5 of 5

How far can we trust the score?

The lecturer stressed that every model is uncertain, and that a field, uncertainty quantification, studies how much to trust predictions. The class listed where this matters: finance, cyclone forecasts, traffic, tumour diagnosis, drug discovery, fraud and surveillance. In each, a wrong answer has a cost.

In detection, uncertainty applies to three things: the class, the box position, and whether the object exists at all.

KindSourceDoes more data help?
AleatoricNoise in the data itself: blur, occlusion, a tiny objectNo
EpistemicThe model does not know: too little or unrepresentative data, wrong assumptionsYes

SoftMax scores are guaranteed to lie between 0 and 1 and to add up to 1. That is a mathematical fact, but it does not make them correct probabilities. Modern networks are often overconfident.

Expected calibration error, worked
  1. 100 predictions. 60 have average confidence 0.90 but only 70% are right. 40 have confidence 0.60 and 60% are right.
  2. First group: gap |0.70 − 0.90| = 0.20, weight 60 ÷ 100 = 0.6, contribution 0.12.
  3. Second group: gap |0.60 − 0.60| = 0, contribution 0.
  4. ECE = 0.12. The model is overconfident by 12 percentage points on average.
Going deeper: a real guarantee: conformal prediction

Split conformal prediction turns any classifier into one that outputs a set of classes containing the truth with probability at least 1 − α, assuming only that calibration and test images are exchangeable. Hold out n calibration images and score each by s = 1 − p̂(true class). Let q̂ be the k-th smallest score with k = ⌈(n + 1)(1 − α)⌉. For a new image, output every class with 1 − p̂(class) ≤ q̂. The rank of the new score among all n + 1 scores is uniform, so the chance that it is at most k is k ÷ (n + 1) ≥ 1 − α. With n = 9 and α = 0.2, k = ⌈10 × 0.8⌉ = 8.

One idea, four depths

A detector draws boxes around things and names them. Checking every possible box would take far too long, so it starts from a set of ready made boxes on a grid and learns to nudge each one into place.

Sliding windows cost (⌊(W − w) ÷ s⌋ + 1)(⌊(H − h) ÷ s⌋ + 1) classifier passes per shape. Anchors plus regression of t = ((x − xa) ÷ wa, (y − ya) ÷ ha, ln(w ÷ wa), ln(h ÷ ha)) replace the search, and convolutional heads score all anchors in one pass.

Anchor design is a coverage problem: the grid stride must satisfy s ≤ 0.367w for worst case IoU 0.5, so multi-scale feature maps carry anchors proportional to their stride. Calibration (ECE, temperature scaling) and the split between aleatoric and epistemic uncertainty decide whether scores can drive decisions.

Anchor free detectors (FCOS, CenterNet) predict boxes directly from points, and DETR treats detection as set prediction with a transformer and Hungarian matching, removing hand designed anchors and duplicate removal. Conformal methods are being extended to give coverage guarantees for boxes, not only classes.
