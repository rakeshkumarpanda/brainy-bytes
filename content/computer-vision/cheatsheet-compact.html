Step 1Seeing like a machine

1.1What computer vision is and why it is hard

  • The definition Computer vision computes properties of the physical world from images and video. Its three jobs are measurement, perception and search.
  • The task family Classification, detection (what and where), categorisation, instance recognition, scene, attribute, activity and relationship recognition, and segmentation.
  • Why it is hard Illumination, viewpoint, scale, occlusion, clutter, intra class variation, inter class similarity, field of view, weather and messy environments.
  • Robustness and generalisation Robustness handles expected variation. Generalisation handles new or shifted data. Imbalance hides poor performance on rare cases.
  • Size and cost N = H × W × C, bytes = N × b ÷ 8, levels = 2 to the power b, raw video rate = frame bytes × fps. Systems trade accuracy against time, memory and energy.
  • Classical and learned features Classical features are designed by hand and are cheap and interpretable. Deep networks learn features in a hierarchy from edges to objects.
  • Numbers in an imageN = H × W × C
  • Raw video data raterate = H × W × C × b8 × fps
  • Exam Examiners like the pair detection versus recognition. Detection finds and localises objects. Recognition decides what they are and what they mean. Categorisation gives a class, instance recognition names one particular object.
  • Trap A high score on the test set does not prove the model will work after deployment. If the deployment conditions are missing from the data, the test set cannot measure them.
  • Trap Do not say that classical features such as HOG are needed "because CNNs overfit". The notes correct this. Overfitting depends on data size, model size, regularisation and augmentation. Classical features are useful because they are efficient, simple and easy to interpret.
  • Trap OpenCV loads colour images in BGR order, not RGB. Most other libraries (Matplotlib, PIL, PyTorch models) expect RGB. Forgetting to convert is one of the most common bugs in vision code.

1.2Marr's theory, edges and hand made features

  • Marr's four stages Input image, primal sketch (edges, blobs), 2½-D sketch (depth and orientation of visible surfaces), 3D model (full shape). 2½-D because it depends on the viewpoint.
  • Good features Distinctive, stable (repeatable) and invariant. Corners beat edges, edges beat flat regions. Detection finds points, description turns them into vectors.
  • Gradients Gx and Gy by differences or Sobel. Magnitude √(Gx² + Gy²), direction atan2(Gy, Gx), pointing across the edge from dark to bright.
  • SIFT DoG scale space for scale, dominant orientation for rotation, 4 × 4 × 8 = 128 descriptor, ratio test d1 ÷ d2 < 0.8 for matching.
  • HOG Cells of 8 × 8, 9 unsigned bins, votes weighted by magnitude, 2 × 2 block normalisation, 3,780 numbers for 64 × 128. Good for upright people, weak on pose changes and occlusion.
  • Why classical features matter Efficiency, interpretability, domain knowledge and support for deep pipelines, not because CNNs overfit.
  • Gradient magnitude|∇I| = √Gx² + Gy²
  • Gradient directionθ = atan2(Gy, Gx)
  • Descriptor length4 × 4 cells × 8 bins = 128
  • Descriptor length(nx − 1)(ny − 1) × 4 × B
  • Exam Depth is not volume. A depth map gives the distance to each visible surface. A 3D model describes the whole object, including the hidden back. The exam asks this as "why is it called 2½-D".
  • Exam Feature detection finds where the interesting points are. Feature description turns the neighbourhood of each point into a vector of numbers so points can be compared. SIFT does both. HOG is mainly a descriptor.
  • Trap With image coordinates the y axis points down. An angle of 90° therefore means "brightness increases downwards". Many textbooks draw y upwards, so check which convention a question uses.

Step 2Images as numbers

2.1Pixels, colour models and compression

  • Image as numbers H × W × C values from 0 to 255. Check channel order, range, type, normalisation and layout before a model sees an image.
  • Colour models RGB adds light, CMYK adds ink, HSL separates hue from lightness, YCbCr separates brightness from colour. OpenCV uses BGR. Grey = 0.299R + 0.587G + 0.114B.
  • Lossy and lossless PNG keeps every pixel, JPEG throws away detail the eye misses. Use lossless for text, medical and legal images.
  • JPEG in five steps YCbCr, chroma downsampling, 8 × 8 DCT, quantisation (the lossy step), zig zag plus Huffman coding. DC = 8 × mean.
  • I, P and B frames I stands alone, P predicts from the past, B from past and future. B is smallest but adds delay, so live systems avoid it.
  • Compression and evidence Edge processing and content aware compression save bandwidth, but heavy compression can erase important detail.
  • Stored valuesH × W × C
  • Grey from RGB (BT.601)Y = 0.299 R + 0.587 G + 0.114 B
  • Compression ratioratio = original sizecompressed size
  • 2D DCT of an 8 × 8 blockF(u, v) = ¼ C(u) C(v) Σx=07 Σy=07 f(x, y) cos (2x + 1)uπ16 cos (2y + 1)vπ16
  • QuantisationFq(u, v) = round(F(u, v)Q(u, v))
  • Trap Compression and normalisation are different things. Compression makes files smaller for storage and transfer. Normalisation changes the scale of numbers so a model can learn. The notes list this as a common confusion.
  • Trap For medical, legal and industrial images, use lossless or very light compression. The fine edges that JPEG throws away can be the tumour boundary, the digit on a number plate or the crack in a weld.

2.2Histograms, brightness and contrast

  • Histogram h(i) counts pixels with value i, p(i) = h(i) ÷ N, CDF is the running total. It tells how many, never where.
  • Brightness, contrast, dynamic range Brightness = mean (where the histogram sits), contrast = spread such as σ or Michelson, dynamic range = number of levels used.
  • Point operations Negative 255 − f, linear αf + β with clipping, log c·log(1 + r) to compress highlights, gamma 255(r ÷ 255)^γ, slicing for one band.
  • Equalisation s = round[(CDF − CDFmin) ÷ (1 − CDFmin) × 255]. Lecture example 80, 100, 120, 140 gives 0, 85, 170, 255. Not perfectly flat for discrete images.
  • Why it matters Dark, low contrast inputs weaken edges and bias models toward dominant regions. Use the same preprocessing in training and deployment.
  • Cumulative distributionCDF(r) = Σi ≤ r p(i)
  • BrightnessB(I) = 1wh Σv=1h Σu=1w I(u, v)
  • Negativeg(x, y) = L − f(x, y)
  • Log transforms = c · log(1 + |r|)
  • Equalisation mappings = round[ CDF(r) − CDFmin1 − CDFmin × 255 ]
  • Trap These methods change the input distribution. Apply exactly the same preprocessing at training time and at deployment, or the model sees two different worlds.

2.3Noise, convolution and filtering

  • Noise models Additive g = f + n (Gaussian, salt and pepper), multiplicative g = f(1 + n) (speckle). Gaussian → averaging or Gaussian filter, impulse → median, speckle → adaptive or median type, shot → denoising.
  • Convolution Slide a kernel, multiply and add. Output size ⌊(W − k + 2P) ÷ S⌋ + 1. True convolution flips the kernel, correlation does not.
  • Smoothing Mean (1/9)·ones, Gaussian with σ (OpenCV σ = 1.7 for 9 × 9), median for outliers. Lecture patch: mean 23.33, median 10.
  • Sharpening Lecture high pass (1/9)[[−1, −1, −1], [−1, 8, −1], [−1, −1, −1]] sums to 0. Notebook kernel [[0, −1, 0], [−1, 5, −1], [0, −1, 0]] sums to 1 and equals identity minus Laplacian.
  • Frequency view g = h ∗ f ⟺ G = H · F. Low pass blurs, high pass keeps edges. Noise is added on purpose for robustness tests and is the core of denoising autoencoders and diffusion models.
  • Additive noiseg(x, y) = f(x, y) + n(x, y)
  • Multiplicative (speckle) noiseg(x, y) = f(x, y) · (1 + n(x, y))
  • Filtering (correlation)g(x, y) = Σi=−aa Σj=−bb h(i, j) · f(x + i, y + j)
  • Output sizeO = ⌊W − k + 2PS⌋ + 1
  • Mean (box) filterh = 19111111111
  • Gaussian kernelG(x, y) = 12πσ² exp(−x² + y²2σ²)
  • Lecture high pass kernelh = 19-1-1-1-18-1-1-1-1
  • Notebook sharpening kernelh = 0-10-15-10-10
  • Convolution theoremg = h ∗ f   ⟺   G(ω1, ω2) = H(ω1, ω2) F(ω1, ω2)
  • Exam Salt and pepper pushes a few pixels straight to an extreme by a sudden jump. Speckle changes values gradually by multiplying them. The mechanisms differ, which is why they need different filters.
  • Trap Sharpening cannot bring back detail that blur destroyed. It boosts whatever high frequencies are left, and that includes noise. In the project, sharpening the blurred COCO128 images raised mAP50 from 0.6176 to 0.6277 but it stayed below the original 0.6706. You will meet those numbers again in the project lab.

Step 3Motion and video

3.1Optical flow, HOF, MBH and video tasks

  • Optical flow Flow (u, v) per pixel between frames T and T + 1. Magnitude √(u² + v²), direction atan2(v, u), speed = magnitude × fps. Lecture: (3, 4) gives 5 px per frame, 150 px per second at 30 fps.
  • Sparse and dense Sparse tracks a few corners and is cheap. Dense gives every pixel a vector and suits crowded scenes but costs much more.
  • Brightness constancy Ixu + Iyv + It = 0: one equation, two unknowns, so the aperture problem. Lucas and Kanade (window, least squares, corners) and Horn and Schunck (global smoothness).
  • HOF and MBH HOF bins flow directions (how things move). MBH bins gradients of the flow (where motion differs) and ignores uniform camera motion. HOG is appearance.
  • Action pipeline Interest points → patches → HOG, HOF, MBH → k-means visual words → histogram → SVM. Replaced by 3D CNNs, two stream networks and video transformers.
  • Video tasks Interpolation predicts a missing middle frame. Also stabilisation, denoising, re-identification, propagation over time, context graphs and video RAG.
  • Flow magnitude|(u, v)| = √u² + v²
  • Speedspeed = magnitude × fps
  • Optical flow constraintIx u + Iy v + It = 0
  • HOF bin weightH[b] = Σpixels with direction in bin b √u² + v²
  • MBH input∇u = (∂u/∂x, ∂u/∂y),   ∇v = (∂v/∂x, ∂v/∂y)
  • k-means objectiveJ = Σi ‖xi − μc(i)‖²
  • Exam In flow pictures, colour shows direction and the strength of the colour shows speed. Learn to read the colour wheel, because exam figures often use it.
  • Exam The rule from the lecture: whenever camera motion is present and could contaminate HOF, prefer MBH. When nothing competes with the motion you care about, HOF alone is sufficient.
  • Trap Interpolation was defined in class only after several attempts. It is not generating new images and not editing pixels. It is predicting the missing frame between two frames.

Step 4Recognising what is in an image

4.1Image classification and convolutional networks

  • Classification One label for the whole image, from a probability per class. ImageNet challenge: 1,000 classes, about 1.28 million training images. Hard because of inter-class similarity and intra-class variation.
  • CNN layer y = ReLU(W ∗ x + b), params k × k × Cin × Cout + Cout, output ⌊(W − k + 2P) ÷ S⌋ + 1. Pooling shrinks maps. Features go from edges to parts to objects.
  • SoftMax and loss pi = ezi ÷ Σ ezj, loss −ln ptrue, gradient p − y. [2, 1, 0.1] gives [0.659, 0.242, 0.099]. Sigmoids for multi-label.
  • Confidence Confidence is usually the SoftMax output. Inductive bias (2, 4, 6) shapes it. A calibrated model is right c of the time when it says c.
  • Architectures AlexNet (GPU, ReLU, augmentation), VGG (stacked 3 × 3), Inception (several sizes, 1 × 1), ResNet H(x) = F(x) + x, ViT (patches as tokens).
  • Design axes Architecture, loss, optimisation. 1 × 1 conv on 80 × 80 × 128 with 256 filters gives 80 × 80 × 256 and 33,024 parameters.
  • One convolution layery = ReLU(W ∗ x + b),   ReLU(t) = max(0, t)
  • Parameters of a layerparams = k × k × Cin × Cout + Cout
  • SoftMaxpi = eziΣj ezj
  • Sigmoidσ(z) = 11 + e−z
  • Cross entropy lossL = −Σj yj ln pj = −ln ptrue
  • CalibrationAmong all predictions made with confidence c, the fraction that is correct should be about c
  • Residual learningH(x) = F(x) + x
  • Gradient descentw ← w − η ∂L∂w
  • Exam Classification gives one label for the whole image. Detection adds a box for each of a variable number of objects. Segmentation labels every pixel. Know all three outputs.
  • Trap Some models now report lower error than the estimated human error on ImageNet. That does not mean human level vision. Models still fail under unusual conditions, distribution shift, adversarial changes, occlusion, new categories and ambiguous scenes. Benchmark wins are specific to the benchmark.

Step 5Finding objects

5.1From sliding windows to anchor boxes

  • Detector output For each object: class, box, confidence. Corners (x1, y1, x2, y2) or centre size (xc, yc, w, h). The number of objects varies.
  • Sliding windows (⌊(W − w) ÷ s⌋ + 1)(⌊(H − h) ÷ s⌋ + 1) windows per shape: 3,285 for 64 × 128 at stride 8 in 640 × 480. Four problems: location, scale, shape, computation.
  • Anchors and regression Rough box plus four learned corrections. t = ((x − xa) ÷ wa, (y − ya) ÷ ha, ln(w ÷ wa), ln(h ÷ ha)), decode with x = xa + tx wa and w = wa e^tw.
  • Heads and anchor design One backbone pass, conv heads score all anchors. k(C + 1) class and 4k box channels. 9 anchors = 3 scales × 3 ratios. SSD 8,732 boxes. Stride s ≤ 0.367w.
  • Trusting scores Aleatoric (data noise) versus epistemic (model ignorance). SoftMax is valid but often overconfident. ECE measures it. Conformal prediction gives a coverage guarantee.
  • Two box formats(x1, y1, x2, y2)   ⟷   (xc, yc, w, h)
  • Number of window positionsN = (⌊W − ws⌋ + 1) × (⌊H − hs⌋ + 1)
  • Encode (make the training target)tx = x − xawa,   ty = y − yaha,   tw = ln wwa,   th = ln hha
  • Decode (turn a prediction into a box)x = xa + txwa,   y = ya + tyha,   w = waetw,   h = haeth
  • Head sizesclass channels = k(C + 1),   box channels = 4k
  • Exam Overlap between windows is a consequence, not a separate problem. A fine stride makes neighbouring windows overlap heavily, and that is why the same pixels are processed again and again.

5.2Training a detector: targets and losses

  • Target assignment Match anchors to true boxes by IoU. RetinaNet: ≥ 0.5 positive, < 0.4 background, between ignored. RPN: 0.7 and 0.3. Background gets only a class loss.
  • Box loss MSE squares errors (outliers dominate), MAE is robust but kinked, Huber = ½e² for |e| ≤ 1 else |e| − ½, gradient clip(e, −1, 1). Bad box example: 345× under e², 1.1× in gradient with Huber.
  • Imbalance Easy background swamps the loss: 97.8% in the worked example. Remedies: subsample, down-weight, hard example mining, focal loss.
  • Cross entropy and focal loss BCE = −ln pt. FL = −α(1 − pt)γ ln pt, γ = 2, α = 0.25. Background share falls to 0.54%. Bias b = ln(π ÷ (1 − π)) = −4.595 for π = 0.01.
  • Design axes Architecture, loss, optimisation. GAN → DCGAN (architecture) → WGAN (loss, earth mover distance).
  • Per-anchor lossL = 1N Σanchors [ α Lcls + β δ(positive) Lloc ]
  • Huber (Smooth L1)Huber(e) = ½e² if |e| ≤ 1,   |e| − ½ otherwise
  • Binary cross entropyBCE = −[ y ln p + (1 − y) ln(1 − p) ]
  • Focal lossFL(pt) = −αt (1 − pt)γ ln pt
  • Prior biasσ(b) = π   ⟹   b = ln π1 − π

5.3IoU, NMS and detector architectures

  • IoU |A ∩ B| ÷ (|A| + |B| − |A ∩ B|). Lecture: 0.389 (miss) and 0.747 (hit) at 0.5. Equal squares shifted by s: (1 − s) ÷ (1 + s).
  • NMS Sort by score, keep the best, remove same class boxes with IoU above the threshold, repeat. Slide example gives {A, D}. Crowds and fixed thresholds are weak spots. Soft-NMS decays by e−IoU² ÷ σ.
  • One and two stage One stage: SSD, YOLO, RetinaNet. Two stage: Faster R-CNN with a class agnostic RPN. The speed and accuracy divide is fuzzy today. Stage wise, joint and hybrid training.
  • RetinaNet and FPN ResNet + FPN + focal loss + prior bias. Early layers: high resolution, low meaning. FPN: 1 × 1 lateral + ×2 upsample + add, shared heads. 76,725 anchors at 640 × 640.
  • RoIAlign Bilinear f = Σ weights × corners, weights are opposite areas and add to 1. (2.3, 4.6) gives 26.8. RoIAlign samples bins without rounding, so the detector trains end to end.
  • IoUIoU(A, B) = |A ∩ B||A ∪ B| = |A ∩ B||A| + |B| − |A ∩ B|
  • One FPN mergePl = Conv1×1(Cl) + Upsample×2(Pl+1)
  • Bilinear interpolationf(x, y) = (1 − u)(1 − v) f00 + u(1 − v) f10 + (1 − u)v f01 + uv f11
  • Trap The lecturer mentioned comparing with the ground truth. At test time there is no ground truth, so NMS uses only scores and box to box IoU. Ground truth is used in training (target assignment) and in evaluation.

5.4Evaluating and choosing detectors

  • Matching Sort by score. TP if IoU above α with an unmatched true box, otherwise FP (poor box, background or duplicate). Unmatched true boxes are FN. No true negatives. Three dogs example: TP 2, FP 2, FN 1.
  • Precision and recall P = TP ÷ (TP + FP), R = TP ÷ (TP + FN), F1 = 2PR ÷ (P + R). Example 0.5, 0.667, 0.571. A higher score threshold usually raises P and lowers R.
  • AP Envelope pinterp(r) = max precision at recall ≥ r. All point AP adds rectangles where recall grows. Lecture list gives 0.674, and the 11 point version also 0.674. COCO uses 101 points.
  • mAP and COCO mAP = mean AP over classes. COCO AP also averages IoU 0.50 to 0.95, so 0.80 at IoU 0.5 became 0.559. APS below 32², APL above 96².
  • Practice Dominated models are never the right pick. Lower resolution and fewer proposals speed things up. Batch 32 to 2 makes BN 4 times noisier, so use frozen BN, GroupNorm or Sync-BN. Pre-training helps: 34.3 to 36.7 to 37.4. Long tail: r = max(1, √(t ÷ f)).
  • Repeat factor sampling (LVIS)r(c) = max(1, √t ÷ f(c)),   r(image) = max over its classes r(c)
  • PrecisionP = TPTP + FP
  • RecallR = TPTP + FN
  • Interpolated precisionpinterp(r) = maxr′ ≥ r p(r′)
  • AP, all pointsAP = Σk (rk − rk−1) · pinterp(rk)
  • mAPmAP = 1C Σc APc
  • COCO APAPCOCO = 110 Σt ∈ {0.50, 0.55, …, 0.95} mAPt
  • Exam Remember the names this way. The first word says whether the model was right, the second says what it predicted. A false positive is a box the model drew that was wrong. The lecturer added that books draw the confusion matrix in different layouts, so learn the idea and not one picture.
  • Trap Check which metric a paper reports. COCO AP numbers of 30 to 50 look small next to PASCAL VOC AP@0.5 numbers of 70 to 90, but they measure a much stricter thing.

Step 6Understanding every pixel

6.1What segmentation predicts

  • The task I ∈ ℝH×W×3 → Y ∈ {1..C}H×W. Before argmax H × W × C, after argmax H × W. 512 × 512 needs 262,144 predictions. Use the cheapest task that answers the question.
  • Semantic, instance, panoptic Semantic: class per pixel, cannot count touching objects. Instance: object identity. Panoptic: both, scored by PQ = SQ × RQ.
  • SoftMax per pixel pc = ezc ÷ Σ ezk. argmax of SoftMax = argmax of logits. SoftMax for one label per pixel, sigmoids for multi-label. Ignore label 255 gets no loss.
  • Why classifiers fail Convolution is equivariant, global pooling is invariant. Downsampling grows the receptive field (r += (k − 1)dj) but erases thin and small structures. What the encoder drops, the decoder cannot recover.
  • WHAT and WHERE Early layers: high resolution, WHERE. Deep layers: semantics, WHAT. Every architecture in the next chapter combines the two. Same body, different head for depth, flow and keypoints.
  • Semantic segmentationI ∈ ℝH × W × 3 → Y ∈ {1, …, C}H × W
  • SoftMax at each pixelP(c | x, y) = ezc(x, y)Σk ezk(x, y)
  • Receptive field recurrencerl = rl−1 + (k − 1) · dl · jl−1,   jl = jl−1 · sl
  • Exam The slide warned: do not memorise architecture names. FCN, U-Net, DeepLab and transformers are different answers to one question: how do we combine WHAT is present with exactly WHERE it is?

6.2Segmentation architectures

  • FCN An FC layer equals a conv with the map size as kernel, so classifiers become dense predictors. FCN-32s, 16s and 8s predict at 1/32, 1/16 and 1/8 and fuse earlier maps.
  • Upsampling Nearest copies, bilinear blends (0, 25, 75, 100 for the lecture map), transposed conv learns. Hout = (Hin − 1)s − 2p + k. Use k = 2s to avoid checkerboards. Masks: nearest only.
  • Encoder-decoder and skips Encoder: what. Decoder: where. Bottleneck: strongest context, coarsest detail. Skips carry WHERE. Concat costs about twice addition (73,792 against 36,928).
  • U-Net Contracting path, bottleneck, expanding path, skip at every level. Original 572 → 388 with valid convs, 31.0 M parameters, about half in the bottleneck.
  • DeepLab Dilated 3 × 3: keff = 2r + 1, 9 weights, padding r. Rates 1, 2, 4, 8 give a field of 31. ASPP: rates 6, 12, 18 + 1 × 1 + pooling. v3+ adds a decoder at stride 4.
  • Output sizeHout = (Hin − 1) · s − 2p + k + pout
  • Dilated 3 × 3 kernelkeff = k + (k − 1)(r − 1) = 2r + 1
  • Trap When the kernel size is not divisible by the stride, some output cells receive more overlapping contributions than others, which prints a checkerboard pattern into the mask. Fixes: kernel = 2 × stride (k = 4, s = 2), or resize with nearest or bilinear and then apply a normal convolution, or use sub-pixel convolution (PixelShuffle).
  • Exam Teaching sentence from the slide: deep features say this region is probably a car, skip features decide the car boundary is exactly here.
  • Exam The class answered context for road against sidewalk confusion, and both slide decks agree. The recording has the lecturer saying boundary, which is most likely a transcription slip. In exams: road and sidewalk confusion is a context problem.

6.3Training and evaluating segmentation

  • Pixel loss L = −(1 ÷ |Ω|) Σ ln p over valid pixels. Ignore label 255 leaves both the sum and the count. P(car) 0.9, 0.5, 0.05 gives 0.105, 0.693, 2.996.
  • Imbalance Weights wc = N ÷ (C nc): pedestrian 20 in the street image. Focal (1 − pt)γ scales by difficulty. Soft Dice 1 − 2Σpg ÷ (Σp + Σg), usually with CE.
  • Metrics Accuracy hides rare classes (90% with tumour IoU 0). Dice = 2TP ÷ (2TP + FP + FN), IoU = TP ÷ (TP + FP + FN), Dice = 2IoU ÷ (1 + IoU). mIoU from a dataset confusion matrix.
  • Pipeline Same spatial transform for image and mask, colour only for the image. Masks resize with nearest neighbour. Fit statistics on the training split. Split by patient, scene or video.
  • Debugging Six failures: boundary, small or thin, class confusion, domain shift, occlusion, over-smoothing. Check alignment, IDs, ignore handling, imbalance and per class IoU before blaming the architecture.
  • Pixel-wise cross-entropyL = −1|Ω| Σi ∈ Ω ln pi, yi
  • Weighted cross-entropyL = Σi wyi (−ln pi, yi)Σi wyi
  • Soft Dice lossLDice = 1 − 2 Σ pi gi + εΣ pi + Σ gi + ε
  • DiceDice = 2|P ∩ G||P| + |G| = 2TP2TP + FP + FN
  • IoU (Jaccard)IoU = |P ∩ G||P ∪ G| = TPTP + FP + FN
  • Trap Very large weights can make training unstable or raise false positives. Weights can follow importance, not only frequency.
  • Trap Benchmarks add one confusion matrix over the whole dataset, then compute IoU per class. Averaging per image IoUs is different and noisier, since an image without a class gives 0 ÷ 0. Say which one you report.
  • Exam Leakage in segmentation also comes from slices of one patient or frames of one video landing in both train and test. Split by patient, scene or video, never by random image. A model with high training IoU and low validation IoU is probably overfitting.

Step 7Vision meets language and 3D

7.1Connecting vision and language

  • CLIP Image and text encoders into one space. Cosine similarity. Symmetric contrastive loss over an N × N matrix with temperature τ. 400 million pairs, batch 32,768.
  • Zero-shot One prompt per class, pick the highest similarity, SoftMax of 100 × cosine for probabilities. Prompt wording matters and ensembling helps. CLIP gives scores, SAM gives masks.
  • Transformers Patch = token, (n ÷ p)² tokens, N² attention pairs: 196 → 38,416, 1,024 → 1,048,576. Windows cut the cost (64× in the Swin example). SegFormer, Mask2Former queries with Hungarian matching.
  • SAM and language SAM: ViT encoder, prompt encoder, light decoder, SA-1B (11 M images, 1.1 B masks), class agnostic. Language-guided segmentation returns a mask for a phrase. Referring segmentation answers with a mask, VQA with text.
  • Generation, restoration, 3D DALL-E makes images from text, CLIP matches them. Restoration and super-resolution infer plausible detail, so validate clinically. Stereo Z = fB ÷ d, error ≈ Z² Δd ÷ (fB).
  • The processing ladderpixels → edges and textures → shapes → objects → scenes and activities
  • Cosine similaritycos(x, y) = x · y‖x‖ ‖y‖
  • Symmetric contrastive lossL = ½ [ CErows(S ÷ τ) + CEcolumns(S ÷ τ) ]
  • TokensN = (n ÷ p)²
  • Stereo depthZ = f Bd
  • Trap Some models now beat the estimated human error on the ImageNet benchmark. The lecturer's caution: that is task specific. The same models can still fail under unusual conditions, distribution shift, adversarial changes, occlusion and new categories. Benchmark superiority is not general intelligence.
  • Exam CLIP and SAM both take prompts but answer different questions. CLIP says what an image corresponds to and outputs scores. SAM says which pixels belong to the object and outputs masks.
  • Trap SAM is class agnostic. It tells you where an object is, not what it is. Pair it with a detector or CLIP when you need names.
  • Trap A visually attractive restored image can still contain wrong information. In medicine, legal evidence and inspection, invented detail is dangerous, so validate restoration on the task it serves, not on how it looks.

Step 8Project lab

8.1Project lab: blur, sharpening and detection
