Q1, Q6 and Q8: peak, kernels and memory

Q1. 80 SMs, 64 cores each, 1.5 GHz, and "every cycle each SM achieves the peak of 4 FMA operations per cycle". Peak of one SM?

Q1
  1. Read the SM statement: one SM does 4 FMA per cycle.
  2. Each FMA = 2 FLOPs, so 8 FLOPs per cycle.
  3. 8 × 1.5 × 10⁹ = 12 × 10⁹.
  4. 12 GFLOPS, inside 10.5 to 12.5: answer 2
In the exam
The other reading, 4 FMA per core, gives 64 × 4 × 2 × 1.5 = 768 GFLOPS per SM, which matches no option. When a question gives two numbers for the same thing, use the one that describes exactly what is asked (here the SM) and check the options.

Q6. A kernel is marked __global__ and must return void: the CPU launches it and continues at once, so there is nobody waiting to receive a value. Results go back through memory. Answer 5.

QualifierRuns onCalled from

__shared__not a function: a variable in shared memory

Q8. Global memory is reachable by every SM and keeps its contents until freed or the program ends. Shared memory belongs to one block, and L1 and L2 are caches, not places you allocate. Answer 1.

Q2 to Q4: loads and races in matrix multiply

q2_naive.cu
__global__ void matMulNaive(const float *A, const float *B, float *C, int N) {    int row = blockIdx.y * blockDim.y + threadIdx.y;    int col = blockIdx.x * blockDim.x + threadIdx.x;    if (row < N && col < N) {        float sum = 0.0f;        for (int k = 0; k < N; k++) {            sum += A[row * N + k] * B[k * N + col];        }        C[row * N + col] = sum;    }}
What each marked line does and why
  1. Line 7sum += A[row * N + k] * B[k * N + col];Each pass of the loop loads one A and one B value from global memory.
  2. Line 9C[row * N + col] = sum;One store per thread.
Q2: N = 1024, blocks of 16 × 16
  1. Each thread runs the loop N = 1024 times.
  2. Each pass loads 2 values: 2048 loads per thread.
  3. 256 threads per block.
  4. 256 × 2048 = 524,288 loads per block
Q3: tiled with 16 × 16 tiles
  1. The k loop runs N ÷ 16 = 64 phases.
  2. In each phase every thread loads 1 value of A and 1 of B into shared memory.
  3. 64 × 256 × 2.
  4. 32,768 loads per block, 16 times fewer

Q4. The quiz kernel loads tiles and computes, with no barrier at all.

q4_fixed.cu
__global__ void matMul(const float *A, const float *B, float *C, int N) {    __shared__ float tileA[16][16];    __shared__ float tileB[16][16];    int row = blockIdx.y * blockDim.y + threadIdx.y;    int col = blockIdx.x * blockDim.x + threadIdx.x;    float sum = 0.0f;    for (int k = 0; k < N / 16; k++) {        tileA[threadIdx.y][threadIdx.x] = A[row * N + (k * 16 + threadIdx.x)];        tileB[threadIdx.y][threadIdx.x] = B[(k * 16 + threadIdx.y) * N + col];        __syncthreads();                  // missing in the quiz: statement a becomes false        for (int t = 0; t < 16; t++) {            sum += tileA[threadIdx.y][t] * tileB[t][threadIdx.x];        }        __syncthreads();                  // missing in the quiz: statement b becomes false    }    C[row * N + col] = sum;}
What each marked line does and why
  1. Line 8tileA[threadIdx.y][threadIdx.x] = A[row * N + (k * 16 + threadIdx.x)];Each thread writes one element of each tile.
  2. Line 10__syncthreads(); // missing in the quiz: statement a becomes falseWithout this barrier a thread can start reading tileA[5][3] before thread (5, 3) wrote it. Statement a is true in the quiz.
  3. Line 14__syncthreads(); // missing in the quiz: statement b becomes falseWithout this barrier a fast thread starts the next phase and overwrites tileB while slower threads still read it. Statement b is true.
In the exam
Answer 3: both statements are true for the quiz code, because it has no __syncthreads. The fixed version above needs one barrier after loading and one after computing.
Lesson 4 of 6

Q5: segments for a transposed store

q5.cu
__global__ void ValUpdate(float *A, float *B, int width, int height) {    int x = blockIdx.x * blockDim.x + threadIdx.x;    int y = blockIdx.y * blockDim.y + threadIdx.y;    if (x < width && y < height) {        float val = A[y * width + x];     // a warp reads 32 neighbours: 1 segment        B[x * height + y] = val;          // a warp writes 2048 floats apart: 32 segments    }}
What each marked line does and why
  1. Line 5float val = A[y * width + x]; // a warp reads 32 neighbours: 1 segmentThreads of one warp have x = 0 to 31 and the same y: 32 consecutive floats = 128 bytes = 1 segment.
  2. Line 6B[x * height + y] = val; // a warp writes 2048 floats apart: 32 segmentsThe same threads write B[x × 2048 + y]: neighbours are 2048 floats = 8192 bytes apart, so each one needs its own segment.
Q5
  1. A warp is 32 threads with consecutive x and one y.
  2. Store address for thread x: (x × 2048 + y) × 4 bytes.
  3. Neighbouring threads are 8192 bytes apart, far more than 128.
  4. 32 segments for one warp store

The fix is the transpose trick of chapter 3.2: read a tile into shared memory, then write it out row by row, so both the read and the write are coalesced.

Q7, Q9 and Q10: tracing, divergence and warps

Q7. One thread per row of y = A x. Thread 2 owns row 2.

Q9. With if (tid % 4 == 1), branch A is taken by tids 1, 5, 9, …, 29.

Q9
  1. The tids form 1 + 4k for k = 0 to 7: 8 terms.
  2. Sum of an arithmetic series = terms × (first + last) ÷ 2.
  3. 8 × (1 + 29) ÷ 2.
  4. 120

Q10. N = 2²⁰ threads in blocks of 256.

Q10
  1. Blocks = (2²⁰ + 255) ÷ 256 = 4096.
  2. Warps per block = 256 ÷ 32 = 8.
  3. 4096 × 8.
  4. 32,768 warps (the latencies in the question are not needed)
Lesson 6 of 6

From intuition to research

One idea, four depths

Read each question twice, then draw one warp or one thread. Most quiz questions are about counting the right thing.

Peak = units × 2 × clock. Naive matmul loads 2N per thread, tiled 2N ÷ T. Segments: look at neighbouring threads. Kernels return void. Warps = blocks × ⌈threads ÷ 32⌉.

Check each answer two ways: by formula and by a tiny Python loop, as in the code above.

The same counting is how researchers model kernels before writing them: count loads, bytes and FLOPs, then place the kernel on the roofline.
