from numba import cudaimport numpy as np @cuda.jitdef add(a, b, c):    i = cuda.grid(1)    if i < c.size:        c[i] = a[i] + b[i] n = 1_000_000a = np.arange(n, dtype=np.float32)b = 2 * ad_a, d_b = cuda.to_device(a), cuda.to_device(b)d_c = cuda.device_array_like(a)threads = 256blocks = (n + threads - 1) // threadsadd[blocks, threads](d_a, d_b, d_c)c = d_c.copy_to_host()print(c[:4])
What each marked line does and why
  1. Line 4@cuda.jitCompile this function for the GPU the first time it is called.
  2. Line 6i = cuda.grid(1)The global index, the same as blockIdx.x × blockDim.x + threadIdx.x.
  3. Line 7if i < c.size:The same guard as in CUDA C, because the last block may stick out.
  4. Line 13d_a, d_b = cuda.to_device(a), cuda.to_device(b)Copy to the GPU: cudaMalloc plus cudaMemcpy.
  5. Line 14d_c = cuda.device_array_like(a)Allocate on the GPU only, no copy.
  6. Line 16blocks = (n + threads - 1) // threadsCeiling division gives enough blocks.
  7. Line 17add[blocks, threads](d_a, d_b, d_c)The launch: square brackets play the role of the triple angle brackets.
  8. Line 18c = d_c.copy_to_host()Copy back. This waits for the kernel to finish.

[0. 3. 6. 9.]

Shared memory, barriers and atomics work the same way. This block sum is the reduction of chapter 5.1 in Python.

numba_sum.py
from numba import cuda, float32import numpy as np TPB = 256 @cuda.jitdef block_sum(x, out):    s = cuda.shared.array(TPB, dtype=float32)    t = cuda.threadIdx.x    i = cuda.grid(1)    s[t] = x[i] if i < x.size else 0.0    cuda.syncthreads()    stride = TPB // 2    while stride > 0:        if t < stride:            s[t] += s[t + stride]        cuda.syncthreads()        stride //= 2    if t == 0:        cuda.atomic.add(out, 0, s[0]) n = 1000d_x = cuda.to_device(np.ones(n, dtype=np.float32))d_out = cuda.to_device(np.zeros(1, dtype=np.float32))block_sum[(n + TPB - 1) // TPB, TPB](d_x, d_out)print(d_out.copy_to_host()[0])
What each marked line does and why
  1. Line 8s = cuda.shared.array(TPB, dtype=float32)A shared array, one per block, sized at compile time.
  2. Line 11s[t] = x[i] if i < x.size else 0.0Threads past the end load 0, the identity for addition.
  3. Line 12cuda.syncthreads()Everyone must finish loading before anyone reads a neighbour.
  4. Line 14while stride > 0:The tree: halve the stride each round.
  5. Line 17cuda.syncthreads()The barrier is outside the if, so every thread reaches it.
  6. Line 20cuda.atomic.add(out, 0, s[0])One atomic per block adds the block total to the result.
What it prints
1000.0

CuPy: NumPy on the GPU

CuPy arrays live in GPU memory and support most of NumPy. Each operation launches a ready made kernel. When you need something special, write it as an element wise expression or as raw CUDA C.

cupy_demo.py
import cupy as cp x = cp.arange(1_000_000, dtype=cp.float32)y = 2 * x + 1total = float(y.sum()) saxpy = cp.ElementwiseKernel(    'float32 a, float32 x, float32 y', 'float32 z',    'z = a * x + y', 'saxpy')z = saxpy(cp.float32(2.0), x, y) square = cp.RawKernel(r"""extern "C" __global__ void square(const float *x, float *y, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) y[i] = x[i] * x[i];}""", 'square')out = cp.empty_like(x)square(((x.size + 255) // 256,), (256,), (x, out, cp.int32(x.size)))host = cp.asnumpy(out)
What each marked line does and why
  1. Line 3x = cp.arange(1_000_000, dtype=cp.float32)Created directly in GPU memory.
  2. Line 4y = 2 * x + 1Each operator launches an element wise kernel (two here: multiply, then add).
  3. Line 5total = float(y.sum())The sum runs on the GPU. float() copies the single number back to the CPU.
  4. Line 7saxpy = cp.ElementwiseKernel(An element wise kernel from a one line C expression: inputs, output, body, name.
  5. Line 12square = cp.RawKernel(r"""Raw CUDA C, compiled at run time. The same kernel you would write in a .cu file.
  6. Line 18square(((x.size + 255) // 256,), (256,), (x, out, cp.int32(x.size)))Launch with a grid tuple, a block tuple and the arguments.
  7. Line 19host = cp.asnumpy(out)Copy the result back as a NumPy array.
Remember
Every separate operation reads and writes the whole array. 2 * x + 1 is two passes over memory. cp.fuse or an ElementwiseKernel does it in one pass, which matters because element wise work is memory bound.

Triton: think in blocks

In CUDA you write what one thread does. In Triton you write what one program does to a whole block of elements. The compiler maps the block to threads, vector loads and shared memory. PyTorch uses Triton to generate many of its fused kernels.

triton_add.py
import torchimport tritonimport triton.language as tl @triton.jitdef add_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr):    pid = tl.program_id(axis=0)    offs = pid * BLOCK + tl.arange(0, BLOCK)    mask = offs < n    x = tl.load(x_ptr + offs, mask=mask)    y = tl.load(y_ptr + offs, mask=mask)    tl.store(out_ptr + offs, x + y, mask=mask) x = torch.rand(98432, device='cuda')y = torch.rand(98432, device='cuda')out = torch.empty_like(x)grid = (triton.cdiv(x.numel(), 1024),)add_kernel[grid](x, y, out, x.numel(), BLOCK=1024)
What each marked line does and why
  1. Line 5@triton.jitCompile this as a Triton kernel. BLOCK is fixed at compile time.
  2. Line 7pid = tl.program_id(axis=0)Which program this is, like blockIdx.x.
  3. Line 8offs = pid * BLOCK + tl.arange(0, BLOCK)BLOCK indices at once, as a vector.
  4. Line 9mask = offs < nThe guard, for the whole block in one line.
  5. Line 10x = tl.load(x_ptr + offs, mask=mask)A masked load: lanes past the end are not read.
  6. Line 12tl.store(out_ptr + offs, x + y, mask=mask)A masked store.
  7. Line 17grid = (triton.cdiv(x.numel(), 1024),)Number of programs: the ceiling of n ÷ 1024.

PyTorch: streams, pinned memory and tensor cores

The ideas of chapter 6.2 and 8.1 appear in PyTorch with friendlier names.

torch_overlap.py
import torch x = torch.randn(4096, 4096).pin_memory()s = torch.cuda.Stream()with torch.cuda.stream(s):    d = x.to('cuda', non_blocking=True)    y = (d.half() @ d.half()).float()torch.cuda.synchronize()print(y.shape, y.dtype)
What each marked line does and why
  1. Line 3x = torch.randn(4096, 4096).pin_memory()pin_memory puts the tensor in page locked host memory so the copy can run asynchronously.
  2. Line 4s = torch.cuda.Stream()A CUDA stream: an in order queue on the GPU.
  3. Line 5with torch.cuda.stream(s):Work inside this block goes into stream s.
  4. Line 6d = x.to('cuda', non_blocking=True)non_blocking=True returns at once, like cudaMemcpyAsync.
  5. Line 7y = (d.half() @ d.half()).float()An FP16 matmul runs on tensor cores, with FP32 accumulation inside.
  6. Line 8torch.cuda.synchronize()Wait for the GPU before using the result on the CPU.

Lesson 6 of 6

From intuition to research

One idea, four depths

CuPy is like swapping a hand saw for a power saw with the same handle: NumPy code, GPU speed. Numba lets you build your own tool. Triton gives you a workshop that sets up the tools for you.

Numba: @cuda.jit, cuda.grid(1), to_device, add[blocks, threads], copy_to_host, shared.array, syncthreads, atomic.add. Triton: program_id, arange, mask, load, store.

Profile Python GPU code with nsys and ncu like any program. Watch for hidden copies between host and device, and for many tiny kernels: fuse them.

torch.compile turns Python models into fused Triton kernels. JAX and XLA do the same from traced programs. Mojo and CUDA Python bring lower level control into Python syntax.
