Lesson 1 of 5

Sign, exponent and mantissa

A float is stored like scientific notation in base 2: a sign, a power of two, and the digits after the point. The leading 1 is not stored, which buys one extra bit for free.

IEEE-754 valueExam favourite
value = (−1)S × 1.f × 2E − bias
bias = 127 for float (8 exponent bits), 1023 for double (11 bits).
Binary fraction
0.b₁b₂b₃… = b₁ × ½ + b₂ × ¼ + b₃ × ⅛ + …
1.00101₂ = 1 + ⅛ + 1/32 = 1.15625.
Exact or not
a decimal fraction is exact in binary only if its denominator is a power of 2
0.625 = 5/8 is exact. 0.6 = 3/5 repeats for ever.

Common mistake
The lecture 5 notes give 1.00101₂ = 1.5625. Adding the bits gives 1 + 0.125 + 0.03125 = 1.15625 = 37/32, which is the value the workbook uses.
Lesson 2 of 5

Encoding by hand

Lecture 5 example: 34.625 as a float
  1. Integer part: 34 = 100010₂ (32 + 2).
  2. Fraction by doubling: 0.625 → 1.25 (1), 0.25 → 0.5 (0), 0.5 → 1.0 (1), so .101.
  3. 34.625 = 100010.101₂ = 1.00010101 × 2⁵.
  4. Exponent field 5 + 127 = 132 = 10000100₂. Mantissa 00010101 followed by zeros.
  5. 0 10000100 00010101000000000000000 = 0x420A8000
Why 5.6 is not exact
  1. 0.6 by doubling: 1.2 (1), 0.4 (0), 0.8 (0), 1.6 (1), then 0.6 again, so 0.1001 1001 1001…
  2. 5.6 = 1.011001100110… × 2², exponent field 129.
  3. Round to 23 bits: word 0x40B33333.
  4. The float holds 5.599999904632568
Machine epsilon
ε = 2−mantissa bits
FP32: 2⁻²³ ≈ 1.19 × 10⁻⁷. The gap between 1 and the next float. Relative rounding error is at most ε ÷ 2.
Lesson 3 of 5

Adding floats, and why order matters

To add two floats the hardware lines up the exponents, adds the mantissas, normalises and rounds. Lining up shifts the smaller number right, and bits that fall off the end are lost.

Homework: 5.75 + 0.375
  1. 5.75 = 101.11₂ = 1.0111 × 2². 0.375 = 0.011₂ = 1.1 × 2⁻².
  2. Align: shift 1.1 right by 2 − (−2) = 4 places, 0.00011 × 2².
  3. Add: 1.01110 + 0.00011 = 1.10001 × 2².
  4. 110.001₂ = 6.125
Homework: 6.5 − 4.25
  1. 6.5 = 1.101 × 2², 4.25 = 1.0001 × 2², already aligned.
  2. 1.1010 − 1.0001 = 0.1001 × 2².
  3. Normalise: 1.001 × 2¹ = 10.01₂ = 2.25
In the exam
A GPU reduction adds numbers in a different order from a CPU loop, so float sums can differ in the last digits. That is expected. Compare float results with a tolerance, never with ==.
fma.cu
#include <cstdio>#include <cmath> __global__ void fmaDemo(float *out, float a, float b, float c) {    out[0] = __fmul_rn(a, b) + c;      // multiply, round, then add and round again    out[1] = fmaf(a, b, c);            // fused: a * b + c with a single rounding} int main() {    float *d, h[2];    cudaMalloc(&d, 2 * sizeof(float));    float a = 1.0f + 1.0f / 4096, c = -(1.0f + 1.0f / 2048);    fmaDemo<<<1, 1>>>(d, a, a, c);    cudaMemcpy(h, d, sizeof(h), cudaMemcpyDeviceToHost);    printf("separate: %.10g\nfused:    %.10g\n", h[0], h[1]);    cudaFree(d);    return 0;}
What each marked line does and why
  1. Line 5out[0] = __fmul_rn(a, b) + c; // multiply, round, then add and round again__fmul_rn forces a separate multiply that is rounded before the add.
  2. Line 6out[1] = fmaf(a, b, c); // fused: a * b + c with a single roundingfmaf computes a × b + c exactly and rounds once. GPUs do this in one instruction, counted as 2 FLOPs.
  3. Line 12float a = 1.0f + 1.0f / 4096, c = -(1.0f + 1.0f / 2048);With a = 1 + 2⁻¹², a² = 1 + 2⁻¹¹ + 2⁻²⁴. The 2⁻²⁴ term is lost by the separate multiply but kept by the FMA.
What it prints
separate: 0
fused:    5.960464478e-08

Special values and precision on GPUs

Exponent fieldMantissaMeaning
00±0

255not 0NaN (0 ÷ 0, √−1)

Double precision costs more on most GPUs. Fermi did 1 TFLOP/s single and 0.5 TFLOP/s double. Gaming GPUs run FP64 at 1/32 or 1/64 of FP32. Use double where accuracy needs it, for example long sums in scientific codes.

Going deeper: Kahan summation

Keep a small correction c of the bits lost at each step: y = x − c, t = s + y, c = (t − s) − y, s = t. The error stops growing with the number of terms. It costs 4 operations per element instead of 1.

Lesson 5 of 5

From intuition to research

One idea, four depths

A float is a number in scientific notation with a fixed number of digits. Some numbers, like 0.1, cannot be written exactly, so tiny errors appear.

value = (−1)^S × 1.f × 2^(E − bias). Float 1/8/23, bias 127. Align, add, normalise, round. Order changes sums.

Mixed precision: store in FP16 or BF16, multiply on tensor cores, accumulate in FP32 (chapter 8.1). Watch overflow in FP16 (largest 65,504) and use loss scaling in training.

FP8 (E4M3 and E5M2) on Hopper and FP4 on Blackwell use per block scale factors to keep the range. Deterministic reductions fix the summation order so results repeat bit for bit.
