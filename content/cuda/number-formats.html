Lesson 1 of 5

Why use fewer bits?

A neural network is a chain of layers. Lecture 9 splits them into two families.

FamilyExamplesTime goes intoTensor cores help?
Math limitedconvolution, fully connected, recurrentcalculatinga lot
Memory limitedbias add, normalisation, ReLU, dropoutmoving numbersnot at all

Fewer bits per number help both. The memory limited layers move half the bytes in FP16 and a quarter in INT8. The math limited layers get faster hardware: a tensor core does many more 16 bit multiplies than 32 bit ones in the same time.

It works because networks forgive small errors. In class the example was accuracy falling from 92 to 91 percent, which is fine, against 92 to 82 percent, which is not. Scientific codes, such as nuclear or biological simulations, cannot accept that and stay in FP64.

Fewer bytes, higher intensityExam favourite
AI = FLOPs ÷ bytes
Halve the bytes and the arithmetic intensity doubles. Batch 1 FC layer: AI ≈ 1 in FP16, ≈ 2 with INT8 weights.

How a float is stored, and the formats side by side

Every floating point number has a sign bit, E exponent bits and M mantissa bits.

Value of a normal numberExam favourite
x = (−1)s × 1.m1m2…mM (binary) × 2e − bias
The leading 1 is not stored, so M bits give M + 1 bits of precision.
BiasExam favourite
bias = 2E − 1 − 1
5 bits: 15. 8 bits: 127. 11 bits: 1023.

Exponent bits give range: each extra bit doubles how many powers of two are available. Mantissa bits give detail: they split each interval such as [1, 2) into 2M equal steps. Type any number below and see what each format keeps.

Which format when, and why the sum stays wide

FormatUsed forWatch out for
FP32master weights in training, science, anything delicateslow on tensor cores
TF32FP32 code on Ampere and later, about 8 times faster on an A100not a storage format: memory still holds FP32
FP16inference, training with loss scalingtiny range: gradients underflow, 70,000 overflows
BF16the default for training large modelsonly about 2 to 3 digits
FP8, FP4Hopper and Blackwell training and inferenceneeds a scale factor per tensor or per block
INT8, INT4inference after quantisationneeds a scale factor, accuracy must be checked

TF32 keeps FP32 in memory. The tensor core rounds the inputs to 10 mantissa bits inside, multiplies, and adds the results in FP32. The professor joked that it should have been called TF19, since it uses 1 + 8 + 10 bits.

Mixed precision. A and B are stored in a narrow format, but the running sum is kept in FP32. Why it matters: add 1 to an FP16 sum again and again. Once the sum reaches 2048, the gap between FP16 numbers is 2, so 2048 + 1 rounds back to 2048 and the sum stops growing.

FP16 versus FP32 accumulator (dot product of 4096 FP16 numbers, from the notes)
  1. True answer −18.16.
  2. FP16 accumulator: −18.36, error 0.20.
  3. FP32 accumulator: error 0.000026.
  4. About 7600 times smaller error with the wide accumulator
Remember
Loss scaling for FP16 training: multiply the loss by a large number such as 1024 before back propagation so that small gradients do not round to 0, then divide the gradients by the same number. BF16 has the range of FP32 and does not need it.
In the exam
Slide 11's bars (TF32, FP16 and BF16 at 4 times, FP8 at 8, FP4 at 16) are labelled illustrative. On an A100, TF32 is 8 times and FP16 16 times the FP32 CUDA core rate. Always use the data sheet of the GPU in front of you.

Quantisation step by step

In class the idea was "treat everything from 0.9 to 1.7 as 1". Real quantisation is a straight line map from real numbers to small integers.

QuantiseExam favourite
q = clip(round(x ÷ s) + z, qmin, qmax)
s is the scale, z the zero point.
Bring backExam favourite
x̂ = s × (q − z)
The rounding error is at most s ÷ 2 unless the value was clipped.
Symmetric INT8
s = R ÷ 127, z = 0
For values between −R and R.
Asymmetric (UINT8)
s = (max − min) ÷ 255, z = round(−min ÷ s)
For values that are not centred on 0, such as ReLU outputs.
Workbook 9.3: store 0.3 with R = 1
  1. s = 1 ÷ 127 = 0.007874.
  2. 0.3 ÷ 0.007874 = 38.1, round to 38.
  3. Back: 38 × 0.007874 = 0.2992.
  4. Error 0.0008, storage 1 byte instead of 4
quantise.cu
#include <cuda_fp16.h>#include <cuda_bf16.h>#include <cstdint> __global__ void quantise(const float *w, int8_t *q, int n, float s) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) {        float r = rintf(w[i] / s);                 // round to the nearest integer        r = fminf(fmaxf(r, -127.0f), 127.0f);      // clip to the INT8 range        q[i] = (int8_t)r;    }} __global__ void dequantise(const int8_t *q, float *w, int n, float s) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) w[i] = s * q[i];} __global__ void to_16bit(const float *x, __half *h, __nv_bfloat16 *b, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) {        h[i] = __float2half(x[i]);                 // FP16: 5 exponent bits, 10 mantissa bits        b[i] = __float2bfloat16(x[i]);             // BF16: 8 exponent bits, 7 mantissa bits    }}
What each marked line does and why
  1. Line 5__global__ void quantise(const float *w, int8_t *q, int n, float s) {One thread per weight. s is computed once on the host.
  2. Line 8float r = rintf(w[i] / s); // round to the nearest integerrintf rounds to the nearest integer, with ties to even.
  3. Line 9r = fminf(fmaxf(r, -127.0f), 127.0f); // clip to the INT8 rangeClip so that a weight outside the range does not wrap around.
  4. Line 10q[i] = (int8_t)r;The integer is stored in a single byte.
  5. Line 16if (i < n) w[i] = s * q[i];Dequantise: multiply back by the scale.
  6. Line 22h[i] = __float2half(x[i]); // FP16: 5 exponent bits, 10 mantissa bitsConversions to the two 16 bit formats are built in.
Going deeper: Per channel scales and FP8 scaling

One scale for a whole tensor is set by its largest value, so small channels get coarse steps. Real systems keep one scale per output channel or per block of 32 to 128 values. FP8 training on Hopper keeps a scale factor per tensor that is updated from the largest values seen recently, so numbers stay inside the 448 limit of E4M3.

Lesson 5 of 5

From intuition to research

One idea, four depths

A format is a ruler. The exponent decides how long it is, the mantissa how fine the marks are. FP16 is short with fine marks, BF16 is very long with coarse marks.

x = (−1)s × 1.m × 2e − bias. FP16 fails on size, BF16 on detail. Accumulate in FP32. INT8: s = R ÷ 127, q = round(x ÷ s).

Pick the format per tensor: weights INT8 or FP8, activations BF16, sums FP32. Check overflow and underflow with real data. Batch 1 inference gains roughly in proportion to the bytes saved.

Research uses 4 bit weights (GPTQ, AWQ), block scaled FP4 on Blackwell, stochastic rounding for training, and outlier handling such as SmoothQuant.
