1.1

Why GPUs: latency, throughput and power

Open chapter

CPU against GPU design, latency and throughput, FPS and batch time, clock and power, peak FLOPs, and the hardware spectrum.

Key ideas

  • Two designs CPU: big control and caches, few strong ALUs, low latency. GPU: thousands of small ALUs, small control, high throughput.
  • Latency and throughput Latency = time for one job. Throughput = jobs ÷ time. FPS = 1000 ÷ ms per frame. Batch time = ⌈N ÷ C⌉ × time per round.
  • Power P ∝ α C V² f. Higher clock needs higher voltage, so power explodes. GPUs use many cores at a moderate clock.
  • Peak Peak = FLOPs per tick per core × clock × cores. FMA = 2 FLOPs. T4 ≈ 8.1, A100 FP32 ≈ 19.5 TFLOP/s.
  • Hardware spectrum CPU → GPU → FPGA → ASIC: less flexible, more efficient. TPU and NPU are ASIC style AI accelerators. The CPU is always the host.

Speedup, the PCIe trip and Amdahl's law

Open chapter

Speedup with copies counted, Amdahl's law and its ceiling, working backwards, Gustafson's law, and break even sizes.

Key ideas

  • Speedup S = old ÷ new. Count copy in + kernel + copy out. Copy time = bytes ÷ bandwidth (PCIe about 12 to 16 GB/s).
  • Amdahl S(N) = 1 ÷ ((1 − P) + P/N). Ceiling 1 ÷ (1 − P). Efficiency S ÷ N. Back: P = (1 − 1/S) ÷ (1 − 1/N).
  • Part speedup Speeding a part p by s gives 1 ÷ ((1 − p) + p/s). Speed up the biggest part first.
  • Gustafson Scaled speedup N − (1 − P)(N − 1) when the problem grows with N (weak scaling).
  • Keep data on the GPU Copy once, run many kernels, copy back once. Small jobs have a break even size below which the CPU wins.

First GPU workloads: heat simulation and convolution

Open chapter

The heat simulation update rule and its stability, why it suits a GPU, and normal against depthwise separable convolution cost.

Key ideas

  • Heat rule T_new = T + α(up + down + left + right − 4T) + βQ. 1-D uses −2T. Updates = cells × steps.
  • Why parallel Each cell needs only old neighbour values, so one thread per cell. Keep two buffers (old and new).
  • Stability Explicit scheme: α ≤ 1/2 in 1-D, 1/4 in 2-D, 1/6 in 3-D, or values blow up.
  • Convolution cost Normal H W Cin Cout K². Separable H W Cin K² + H W Cin Cout. Ratio (K² + Cout) ÷ (K² Cout) → 1/K².
  • Same pattern Heat updates and convolutions are stencils: each output reads a small neighbourhood. Tiling with halos speeds them up later.

Formulas

The heat equation
∂T/∂t = α (∂²T/∂x² + ∂²T/∂y²) + Q
T is temperature, α the thermal diffusivity (how fast heat spreads), Q the heat the battery makes itself.
Lesson: Workload 1: a battery heat simulation
2-D update rule (5 points)Exam favourite
Tnew = T + α (up + down + left + right − 4T) + βQ
New temperature = old temperature + heat from the four neighbours + heat made inside.
Lesson: Workload 1: a battery heat simulation
1-D version
Tnew = T + α (left + right − 2T) + βQ
The same idea along a rod.
Lesson: Workload 1: a battery heat simulation
How much work
cells = height × width
updates = cells × time steps
A 1024 × 1024 grid has 1,048,576 cells per step.
Lesson: Workload 1: a battery heat simulation
Normal convolutionExam favourite
mults = H × W × Cin × Cout × K × K
Every output pixel of every output channel looks at a K × K patch of every input channel.
Lesson: Workload 2: image recognition and convolution cost
Depthwise separable
depthwise = H W Cin K²
pointwise = H W Cin Cout
First one K × K filter per input channel, then a 1 × 1 convolution that mixes channels. MobileNet uses this.
Lesson: Workload 2: image recognition and convolution cost
Saving ratioExam favourite
separable ÷ normal = (K² + Cout) ÷ (K² × Cout)
For many output channels this tends to 1 ÷ K², so at most 9 times fewer for 3 × 3 filters.
Lesson: Workload 2: image recognition and convolution cost

Tips and traps

  • Common mistake
    A GPU heat code must keep two buffers. If threads wrote into the same grid they read from, some would read a neighbour's new value and some its old value, and the answer would depend on timing.Lesson: Workload 1: a battery heat simulation
  • Remember
    Fewer multiplications does not always mean proportionally faster on a GPU. Depthwise layers do little work per byte loaded, so they are often limited by memory, not maths (chapter 4.2).Lesson: Workload 2: image recognition and convolution cost

Threads, blocks and grids: indexing in 1-D, 2-D and 3-D

Open chapter

The global index, blocks and idle threads, dim3 and 2-D image indexing, going backwards, grid stride loops and matrix vector per row.

Key ideas

  • Global index i = blockIdx.x × blockDim.x + threadIdx.x. Blocks = (N + B − 1)/B. Guard i < N. Idle = blocks × B − N.
  • 2-D col = bx·Bx + tx, row = by·By + ty, index = row × width + col. Grid = (⌈W/Bx⌉, ⌈H/By⌉), guard both.
  • Linear order thread = tx + ty·Bx + tz·Bx·By (x fastest). Warps are cut from this order.
  • Backwards block = ⌊g ÷ per block⌋, leftover = g mod per block, x = leftover mod Bx, y = ⌊leftover ÷ Bx⌋.
  • Grid stride Start at i = idx, keep going while i < n, and add blockDim.x × gridDim.x each time. A fixed grid then covers any N.

SMs, warps and hiding latency

Open chapter

SM anatomy, warps and lanes, wasted lanes, Little's law and latency hiding, and registers per thread.

Key ideas

  • Mapping Thread → core lane, warp → scheduler, block → one SM for life, grid → whole GPU.
  • Warps warps = ⌈B/32⌉, warp = ⌊t/32⌋, lane = t mod 32, t = x + y·Bx. Efficiency B ÷ (32 × warps).
  • Little's law In flight = latency × throughput. Warps = that ÷ 32. Bytes in flight = bandwidth × latency.
  • Latency hiding Zero cost warp switching because registers stay on chip. Need many warps or independent instructions.
  • Registers Registers per thread = file ÷ threads. 65,536 on modern SMs. Too many spill to slow local memory.
