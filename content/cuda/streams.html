Lesson 1 of 4

Who waits for whom

A kernel launch only puts work in a queue and returns at once. The CPU can do other things while the GPU runs. Some calls make the CPU wait.

CallBlocks the CPU?Notes
kernel<<>>()noqueued in the default stream
cudaMemcpyyesstarts after earlier work in the stream, returns when the copy is done
cudaMemcpyAsyncnoneeds pinned host memory to really overlap
cudaStreamSynchronize(s)yesuntil stream s is empty
cudaDeviceSynchronize()yesuntil all GPU work is done

Work inside one stream runs in order. Work in different streams may run at the same time, on different engines: the copy engines move data over PCIe while the SMs run kernels.

Common mistake
In class it was said that asynchrony is dangerous because a second kernel could overwrite the first. Work in one stream always runs in order. The real danger is the CPU reading or reusing a host buffer before the GPU has finished with it. Synchronise before reading results.
Lesson 2 of 4

Overlapping copies and compute

Split the data into chunks and give each chunk its own stream. While one chunk computes, the next can be copied in and the previous copied out.

SerialExam favourite
t = N × (tin + tkernel + tout)
One stream, nothing overlaps.
Overlapped, equal stages tExam favourite
t = (N + 2) × t, speedup 3N ÷ (N + 2)
N = 4: 2 times. N = 16: 2.67. Never more than 3 (the number of stages).
Unequal stages
t ≈ fill + N × slowest stage
The slowest stage sets the pace. 2, 5, 2 ms with 10 chunks: 2 + 50 + 2 = 54 ms.
streams.cu
#include <cstdio>#define NS 4 __global__ void scale(float *d, int n, float a) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) d[i] *= a;} int main() {    const int N = 1 << 22, chunk = N / NS;    const size_t cbytes = chunk * sizeof(float);    float *h, *d;    cudaMallocHost(&h, N * sizeof(float));          // pinned: needed for async copies    cudaMalloc(&d, N * sizeof(float));    for (int i = 0; i < N; ++i) h[i] = 1.0f;     cudaStream_t s[NS];    for (int k = 0; k < NS; ++k) cudaStreamCreate(&s[k]);     for (int k = 0; k < NS; ++k) {        int off = k * chunk;        cudaMemcpyAsync(d + off, h + off, cbytes, cudaMemcpyHostToDevice, s[k]);        scale<<<(chunk + 255) / 256, 256, 0, s[k]>>>(d + off, chunk, 2.0f);        cudaMemcpyAsync(h + off, d + off, cbytes, cudaMemcpyDeviceToHost, s[k]);    }    cudaDeviceSynchronize();                          // wait for all streams before reading h    printf("h[0] = %.1f, h[N-1] = %.1f\n", h[0], h[N - 1]);     for (int k = 0; k < NS; ++k) cudaStreamDestroy(s[k]);    cudaFreeHost(h); cudaFree(d);    return 0;}
What each marked line does and why
  1. Line 13cudaMallocHost(&h, N * sizeof(float)); // pinned: needed for async copiesPinned memory: cudaMemcpyAsync from pageable memory would not overlap.
  2. Line 18for (int k = 0; k < NS; ++k) cudaStreamCreate(&s[k]);Four independent queues.
  3. Line 22cudaMemcpyAsync(d + off, h + off, cbytes, cudaMemcpyHostToDevice, s[k]);Each chunk is copied in, scaled and copied out in its own stream, so chunks can overlap.
  4. Line 23scale<<<(chunk + 255) / 256, 256, 0, s[k]>>>(d + off, chunk, 2.0f);The fourth launch value names the stream.
  5. Line 26cudaDeviceSynchronize(); // wait for all streams before reading hWait for every stream before the CPU reads h.
What it prints
h[0] = 2.0, h[N-1] = 2.0

Events: timing and dependencies

An event is a marker placed in a stream. It records when the GPU reached that point. Two events give an elapsed time. Another stream can wait for an event without stopping the CPU.

events.cu
// Make stream b wait for work in stream a, without blocking the CPUvoid dependent(cudaStream_t a, cudaStream_t b, float *x, float *y, int n) {    cudaEvent_t done;    cudaEventCreateWithFlags(&done, cudaEventDisableTiming);    cudaMemcpyAsync(y, x, n * sizeof(float), cudaMemcpyDeviceToDevice, a);    cudaEventRecord(done, a);              // marks the point in stream a    cudaStreamWaitEvent(b, done, 0);       // later work in b starts only after that point    cudaEventDestroy(done);}
What each marked line does and why
  1. Line 4cudaEventCreateWithFlags(&done, cudaEventDisableTiming);DisableTiming makes a lighter event when it is only used for ordering.
  2. Line 6cudaEventRecord(done, a); // marks the point in stream acudaEventRecord places the marker after the copy in stream a.
  3. Line 7cudaStreamWaitEvent(b, done, 0); // later work in b starts only after that pointWork queued in b after this call waits for the marker. The CPU continues straight away.
Going deeper: CUDA graphs

Each launch costs a few microseconds of CPU time. For many small kernels, capture the sequence once into a CUDA graph and replay it with one call. The driver then knows all dependencies in advance.

Workbook 6.3: 2²⁰ floats over 4 streams at 12 GB/s
  1. Chunk = 2²⁰ ÷ 4 = 262,144 floats = 1 MiB.
  2. Blocks of 256: 262,144 ÷ 256 = 1024.
  3. Copy time 1,048,576 bytes ÷ 12 × 10⁹ B/s.
  4. ≈ 87 µs per chunk copy

From intuition to research

One idea, four depths

A laundry with a washer, a dryer and a folding table. While load 2 washes, load 1 dries. Three machines working at once finish many loads almost 3 times faster.

Streams are in order queues. Overlap needs pinned memory and separate streams. Equal stages: (N + 2)t, speedup ≤ 3. Synchronise before reading results.

Check overlap in Nsight Systems: copies and kernels should appear on separate rows at the same time. Watch for implicit syncs from cudaMalloc, cudaFree or the legacy default stream.

Large training jobs overlap gradient all reduce (NCCL) with the backward pass using streams. Programmatic dependent launch on Hopper starts the next kernel before the previous one fully ends.
