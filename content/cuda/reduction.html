Lesson 1 of 5

From a serial loop to a tree

Adding n numbers with one adder takes n − 1 steps, one after another. With many threads we can add pairs at the same time: n/2 sums, then n/4, and so on, until one value is left. That needs only log₂ n levels.

LevelsExam favourite
levels = ⌈log₂ n⌉
1024 numbers need 10 levels instead of 1023 serial additions.
AdditionsExam favourite
total additions = n − 1
The tree does the same work, it only runs it in parallel.
Barriers
barriers = 1 (after loading) + levels
A 1024 thread tree uses 11 __syncthreads().
Real world scenario: a knockout tournament

64 teams play a knockout. In round one 32 matches happen at the same time, then 16, 8, 4, 2 and 1. Six rounds find the winner, even though 63 matches are played in total. A tree reduction is a knockout where each match adds two numbers.

Lesson 2 of 5

Which threads work: divergence and the barrier bug

The pairing decides how many warps split. With interleaved pairing (thread t works if t mod 2s = 0) the working threads are spread out, so every warp keeps some idle lanes. With sequential pairing (thread t works if t < s) the working threads sit together, so whole warps finish and only the last 5 levels (s = 16 to 1) split a warp.

Workbook 12.1 worked example: 1024 threads, first stride 512, barrier inside the if
  1. At stride 512 threads 0 to 511 work: warps 0 to 15 fully busy, warps 16 to 31 fully idle. No warp splits at this level.
  2. But the __syncthreads() is inside if (t < stride), so threads 512 to 1023 never reach it.
  3. The CUDA rules say every thread of the block must reach the same barrier, otherwise the behaviour is undefined.
  4. Move the barrier out of the if
bad_sum.cu
// WRONG: the barrier sits inside the if, so threads with t >= stride never reach it__global__ void badSum(float *s) {    int t = threadIdx.x;    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1) {        if (t < stride) {            s[t] += s[t + stride];            __syncthreads();      // undefined behaviour: not all threads of the block arrive        }    }}
What each marked line does and why
  1. Line 5if (t < stride) {Only threads with t below stride enter this block.
  2. Line 7__syncthreads(); // undefined behaviour: not all threads of the block arriveA barrier that some threads skip can hang the block or let threads race ahead.
Lesson 3 of 5

Beyond one block: launches and atomics

A block can only sum its own values. For a big array each block writes one partial sum. Then either a second launch adds the partial sums, or each block adds its result to the total with one atomicAdd.

Launches without atomics
repeat: n ← ⌈n ÷ B⌉ until n = 1
1,000,000 numbers with B = 256: 3907, then 16, then 1, so 3 launches.
Atomics neededExam favourite
one per block = ⌈n ÷ B⌉
2²⁰ numbers with B = 1024: 1024 atomics instead of 1,048,576.
block_sum.cu
#include <cstdio> // Sum of n floats. Each block reduces 2 x blockDim values, then one atomicAdd per block.__global__ void blockSum(const float *in, float *total, int n) {    extern __shared__ float s[];    int t = threadIdx.x;    int i = blockIdx.x * blockDim.x * 2 + t;    float v = 0.0f;    if (i < n) v += in[i];    if (i + blockDim.x < n) v += in[i + blockDim.x];   // each thread adds two values first    s[t] = v;    __syncthreads();    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1) {        if (t < stride) s[t] += s[t + stride];          // sequential addressing: no bank conflicts        __syncthreads();                                // outside the if: every thread reaches it    }    if (t == 0) atomicAdd(total, s[0]);                 // one atomic per block} int main() {    const int n = 1 << 20, B = 256;    float *d, *dt, h = 0.0f;    cudaMalloc(&d, n * sizeof(float));    cudaMalloc(&dt, sizeof(float));    float *ones = new float[n];    for (int k = 0; k < n; ++k) ones[k] = 1.0f;    cudaMemcpy(d, ones, n * sizeof(float), cudaMemcpyHostToDevice);    cudaMemset(dt, 0, sizeof(float));    int blocks = (n + 2 * B - 1) / (2 * B);    blockSum<<<blocks, B, B * sizeof(float)>>>(d, dt, n);    cudaMemcpy(&h, dt, sizeof(float), cudaMemcpyDeviceToHost);    printf("sum = %.0f using %d blocks\n", h, blocks);    delete[] ones; cudaFree(d); cudaFree(dt);    return 0;}
What each marked line does and why
  1. Line 5extern __shared__ float s[];Dynamic shared memory, one float per thread, size given by the third launch value.
  2. Line 10if (i + blockDim.x < n) v += in[i + blockDim.x]; // each thread adds two values firstThread coarsening: each thread adds two inputs before the tree, so half as many blocks are needed.
  3. Line 14if (t < stride) s[t] += s[t + stride]; // sequential addressing: no bank conflictsSequential addressing: the active threads stay packed at the front.
  4. Line 15__syncthreads(); // outside the if: every thread reaches itThe barrier is outside the if, so every thread reaches it every level.
  5. Line 17if (t == 0) atomicAdd(total, s[0]); // one atomic per blockOne atomicAdd per block makes the final total without a second launch.
  6. Line 30blockSum<<<blocks, B, B * sizeof(float)>>>(d, dt, n);Each block covers 2 × 256 = 512 values.
What it prints
sum = 1048576 using 2048 blocks
Lesson 4 of 5

Warp shuffles: the modern way

Inside one warp, threads can read each other's registers directly with __shfl_down_sync. No shared memory and no barrier are needed, because the 32 lanes of a warp step together when the mask names them all.

warp_sum.cu
// Warp level sum with shuffles: no shared memory, no __syncthreads inside a warp__inline__ __device__ float warpSum(float v) {    for (int off = 16; off > 0; off >>= 1)        v += __shfl_down_sync(0xffffffff, v, off);   // read v from lane + off    return v;                                        // lane 0 holds the warp total} __global__ void sumShfl(const float *in, float *total, int n) {    __shared__ float warpTotals[32];    int i = blockIdx.x * blockDim.x + threadIdx.x;    float v = (i < n) ? in[i] : 0.0f;    v = warpSum(v);    int lane = threadIdx.x % 32, w = threadIdx.x / 32;    if (lane == 0) warpTotals[w] = v;    __syncthreads();    if (w == 0) {        v = (lane < blockDim.x / 32) ? warpTotals[lane] : 0.0f;        v = warpSum(v);        if (lane == 0) atomicAdd(total, v);    }}
What each marked line does and why
  1. Line 3for (int off = 16; off > 0; off >>= 1)Offsets 16, 8, 4, 2, 1: five steps for 32 lanes.
  2. Line 4v += __shfl_down_sync(0xffffffff, v, off); // read v from lane + offLane i adds the value held by lane i + off. The mask 0xffffffff says all 32 lanes take part.
  3. Line 14if (lane == 0) warpTotals[w] = v;After warpSum, lane 0 of each warp holds that warp's total.
  4. Line 17v = (lane < blockDim.x / 32) ? warpTotals[lane] : 0.0f;Warp 0 then reduces the (at most 32) warp totals the same way.
Remember
Floating point addition is not associative (chapter 4.1), so the tree order gives a slightly different float sum from a CPU loop. Compare with a tolerance.
Going deeper: CUB and Thrust

For production code, cub::DeviceReduce::Sum and thrust::reduce choose the block size, coarsening and shuffles for you and are tuned for each GPU. Writing your own is how you learn what they do.

Lesson 5 of 5

From intuition to research

One idea, four depths

Adding numbers in pairs, then pairs of sums, finishes in a few rounds, like a knockout tournament.

log₂ n levels, n − 1 additions, barriers outside ifs, sequential addressing, one atomic per block, shuffles inside warps.

The classic NVIDIA reduction sequence: interleaved, sequential addressing, first add during load, unroll the last warp, complete unrolling, many elements per thread. Each step removes a bottleneck and the last versions reach close to full memory bandwidth.

A reduction reads every byte once with AI near 0.25, so it is memory bound. The target is the bandwidth roof. Decoupled look back (Merrill and Garland) does single pass scans and reductions across the whole grid.
