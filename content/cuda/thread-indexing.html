Lesson 1 of 5

The global index in one dimension

Every thread runs the same kernel code. The only thing that differs is its position, given by four built in variables. Each thread uses them to pick its own piece of data.

VariableMeaningRange
threadIdx.x/y/zmy position inside my block0 to blockDim − 1
blockIdx.x/y/zmy block's position inside the grid0 to gridDim − 1
blockDim.x/y/zsize of every blockset by the launch, at most 1024 threads in total
gridDim.x/y/znumber of blocksx up to 2³¹ − 1, y and z up to 65,535
Global indexExam favourite
i = blockIdx.x × blockDim.x + threadIdx.x
Skip all the full blocks before mine, then step to my seat in my block.
Blocks neededExam favourite
blocks = ⌈N ÷ B⌉ = (N + B − 1) ÷ B
Whole number division drops the remainder, so adding B − 1 first rounds up.
Going backwards
block = ⌊i ÷ B⌋, thread = i − block × B
Which thread handles element i.
Idle threads
idle = blocks × B − N
They fail the guard and do nothing.
Real world scenario: cinema seats

A cinema has rows of 20 seats. Your ticket says row 3, seat 7. Your seat number counting from the very first seat is 3 × 20 + 7 = 67. Rows are blocks, seats are threads, and 20 is blockDim.

Workbook worked example: 10,000 numbers, blocks of 256
  1. Blocks = (10,000 + 255) ÷ 256 = 10,255 ÷ 256 = 40 (whole number division).
  2. Threads launched = 40 × 256 = 10,240, so 240 are idle.
  3. Thread 10 of block 3 handles i = 3 × 256 + 10 = 778
Lesson 2 of 5

dim3, images and two dimensional grids

Blocks and grids can be 1-D, 2-D or 3-D. The shape is only a way of numbering. It makes images (2-D) and volumes (3-D) easy to map. A missing dimension counts as 1, so dim3 threads(256) means 256 × 1 × 1.

Pixels in an imageExam favourite
col = blockIdx.x × blockDim.x + threadIdx.x
row = blockIdx.y × blockDim.y + threadIdx.y
memory position = row × width + col
Images are stored row by row (row major). x is the column, y is the row.
Grid for a W × H image
grid = (⌈W ÷ Bx⌉, ⌈H ÷ By⌉)
Idle threads = all threads − W × H.
Position to one number (x fastest)Exam favourite
thread = tx + tyBx + tzBxBy
block = bx + byGx + bzGxGy
global = block × (threads per block) + thread
This is how the hardware lines threads up before cutting them into warps.
invert.cu
__global__ void invert(unsigned char* img, int width, int height) {    int col = blockIdx.x * blockDim.x + threadIdx.x;    int row = blockIdx.y * blockDim.y + threadIdx.y;    if (col < width && row < height) {        int idx = row * width + col;        img[idx] = 255 - img[idx];    }} void launchInvert(unsigned char* d_img, int width, int height) {    dim3 block(16, 16);    dim3 grid((width + block.x - 1) / block.x, (height + block.y - 1) / block.y);    invert<<<grid, block>>>(d_img, width, height);}
What each marked line does and why
  1. Line 2int col = blockIdx.x * blockDim.x + threadIdx.x;x picks the column. Neighbouring threads in a warp have neighbouring x, so they touch neighbouring bytes in memory (good for speed, chapter 3.2).
  2. Line 3int row = blockIdx.y * blockDim.y + threadIdx.y;y picks the row.
  3. Line 4if (col < width && row < height) {Two guards, one per dimension. The right and bottom edge blocks can hang over the image.
  4. Line 5int idx = row * width + col;Row major: skip row full rows, then step col places.
  5. Line 11dim3 block(16, 16);16 × 16 = 256 threads per block, 8 warps.
  6. Line 12dim3 grid((width + block.x - 1) / block.x, (height + block.y - 1) / block.y);Round up in each dimension separately.
Workbook worked example: a 1920 × 1080 picture with 16 × 16 blocks
  1. Across: ⌈1920 ÷ 16⌉ = 120 exactly.
  2. Down: ⌈1080 ÷ 16⌉ = 67.5, rounded up to 68.
  3. Blocks = 120 × 68 = 8160. Threads = 8160 × 256 = 2,088,960.
  4. Idle = 2,088,960 − 2,073,600 = 15,360 (the half block row at the bottom)
Remember
Using 32 × 8 blocks for 1920 × 1080 wastes nothing (1080 ÷ 8 = 135) and each warp covers one full 32 pixel row. Picking a block shape that divides the image is free speed.
Lesson 3 of 5

Three dimensions, going backwards, and the slide correction

Lecture 3 slides 15 to 16: grid 5 × 4 blocks, each block 5 × 5 threads. Where is global thread 343?
  1. Threads per block = 25. Block number = ⌊343 ÷ 25⌋ = 13, leftover 343 − 325 = 18.
  2. Block 13 in a grid 5 wide: x = 13 mod 5 = 3, y = ⌊13 ÷ 5⌋ = 2. So blockIdx = (3, 2, 0).
  3. Thread 18 in a block 5 wide: x = 18 mod 5 = 3, y = ⌊18 ÷ 5⌋ = 3. So threadIdx = (3, 3, 0).
  4. The slide showed threadIdx (2, 3, 0), which is actually thread 342
One number to position
block = ⌊g ÷ threads per block⌋, leftover = g − block × threads per block
x = leftover mod Bx, y = ⌊leftover ÷ Bx⌋
The same mod and divide works for the block inside the grid.
In the exam
Exams love going backwards. Always divide by the number of threads per block first, then split the leftover with mod and divide, x first.
Going deeper: why the x dimension is special

Warps are cut from the linear thread number t = x + y Bx + z BxBy. So a warp holds 32 consecutive x values (or several short rows if Bx < 32). Make x the dimension that walks along contiguous memory, and keep Bx a multiple of 32 when you can.

Grid stride loops and one thread per row

Two more patterns finish the picture. A grid stride loop lets a fixed size grid cover any N: each thread handles i, then i plus the total number of threads, and so on. It also reuses each thread's set up work and lets you launch just enough blocks to fill the GPU.

saxpy_stride.cu
__global__ void saxpy(int n, float a, const float* x, float* y) {    for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n;         i += blockDim.x * gridDim.x) {        y[i] = a * x[i] + y[i];    }}
What each marked line does and why
  1. Line 2for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n;Start at my global index.
  2. Line 3i += blockDim.x * gridDim.x) {Jump by the total number of threads in the grid. With 2 blocks of 8, thread 3 handles 3, 19, 35 and so on.
  3. Line 4y[i] = a * x[i] + y[i];SAXPY: y = a x + y, a classic BLAS routine.

One thread per output row. Quiz 1 question 7 launches one thread per row of a matrix vector product: thread i computes the dot product of row i of A with x.

matvec.cu
__global__ void matVecMul(const float* A, const float* x, float* y, int N) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < N) {        float sum = 0.0f;        for (int j = 0; j < N; j++) {            sum += A[i * N + j] * x[j];        }        y[i] = sum;    }}
What each marked line does and why
  1. Line 2int i = blockIdx.x * blockDim.x + threadIdx.x;With one block of 4 threads, thread 2 has i = 0 × 4 + 2 = 2.
  2. Line 6sum += A[i * N + j] * x[j];Row i starts at i × N in the flat row major array.
  3. Line 8y[i] = sum;One store per thread.
Common mistake
In matVecMul neighbouring threads read A[i × N + j] for the same j, which are N floats apart. That is a strided, uncoalesced read (chapter 3.2). A transposed layout or one warp per row is faster for large N.

Lesson 5 of 5

From intuition to research

One idea, four depths

Every worker gets a badge with a team number and a seat number. From these two numbers each worker knows which piece of the job is theirs.

i = blockIdx.x × blockDim.x + threadIdx.x, blocks = (N + B − 1) / B, guard i < N. In 2-D, col from x, row from y, index row × width + col.

The thread to data mapping decides memory efficiency: let threadIdx.x walk contiguous addresses. Grid stride loops decouple the grid from N and are the default style in libraries.

Persistent kernels launch exactly one wave of blocks that pull work from a queue. Hopper adds thread block clusters, a level between block and grid whose blocks can share memory. Index arithmetic in 64 bits matters once tensors exceed 2³¹ elements.
