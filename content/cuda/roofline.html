Counting the work: FLOPs

A FLOP is one floating point operation: an add, a multiply, or half of an FMA. FLOP/s (or FLOPS) is a rate. The lecture warned that slides mix the two, so always check the unit.

Matrix multiply n × nExam favourite
FLOPs = 2n³
Each of n² outputs needs n multiplies and n adds.
Filter k × k
FLOPs = 2k² × outputs
A 5 × 5 filter on 1020 × 1020 outputs: 52,020,000.
Peak of a GPUExam favourite
peak = SMs × cores per SM × 2 (FMA) × clock
A100: 108 × 64 × 2 × 1.41 GHz ≈ 19.5 TFLOP/s.
Efficiency
achieved ÷ peak
A simple kernel at 3171 GFLOP/s on an H100 with about 51,000 is about 6.2 percent.
Lecture 5: mul_add loop
  1. x = a × x + b runs 50 times.
  2. Each iteration is 2 FLOPs.
  3. 100 FLOPs per call. In 1 second that is 100 FLOP/s
Lesson 2 of 5

Bandwidth and arithmetic intensity

Every kernel both computes and moves data. If data cannot arrive fast enough, the cores sit idle however fast they are. The lecture's latency numbers for a CPU make the point: register 1 cycle, L1 4, L2 14, L3 75, DRAM 200.

BandwidthExam favourite
GB/s = (bytes read + bytes written) ÷ 10⁹ ÷ seconds
Count both directions.
Arithmetic intensityExam favourite
AI = FLOPs ÷ bytes moved to or from DRAM
Unit FLOP per byte.
SAXPY
AI = 2 ÷ 12 ≈ 0.167
Read x, read y, write y (3 × 4 bytes) for one multiply and one add. DAXPY is half that.
Matrix multiply
no reuse: 2 FLOPs per 2 loads → 0.25 (float), perfect reuse: AI = n ÷ 8 (float) or n ÷ 16 (double)
Reuse is what raises AI.
saxpy_bw.cu

Lesson 3 of 5

The roofline model

Attainable speedExam favourite
attainable = min(peak FLOP/s, AI × bandwidth)
The lower roof wins.
Ridge pointExam favourite
AIridge = peak ÷ bandwidth
Left of it a kernel is memory bound, right of it compute bound.
Time
t ≥ max(FLOPs ÷ peak, bytes ÷ bandwidth)
The shortest possible time is set by the slower of the two.
Workbook 4.4: 10⁹ FLOPs and 2 × 10⁸ bytes on a 10 TFLOP/s, 500 GB/s GPU
  1. Maths time 10⁹ ÷ 10¹³ = 0.1 ms.
  2. Memory time 2 × 10⁸ ÷ 5 × 10¹¹ = 0.4 ms.
  3. The memory time is longer, so the kernel takes at least 0.4 ms.
  4. Speed 10⁹ ÷ 0.4 ms = 2.5 TFLOP/s, memory bound (AI 5 is below the ridge 20)
In the exam
For a memory bound kernel, doubling the maths units changes nothing. Only more bandwidth or more reuse helps. Doubling Fermi's cores gives plain matrix multiply no gain.

8K frame (7680 × 4320, 1 byte per pixel): where does the time go?
  1. Frame in and out: 2 × 33.2 MB = 66.4 MB. At 13 to 16 GB/s that takes about 4.1 to 5.1 ms.
  2. The kernel itself is 1.65 ms of the 8.66 ms total, about 19 percent.
  3. The kernel moves 66.4 MB in 1.65 ms = 40.2 GB/s, only 15.7 percent of the GPU's 256 GB/s.
  4. Keep frames on the GPU: about 606 FPS, 5.25 times faster
Going deeper: hierarchical roofline

Nsight Compute draws one roof per memory level: L1, L2 and DRAM. A kernel can be far below the DRAM roof but at the L2 roof, which tells you that improving cache reuse, not DRAM traffic, is the next step.

From intuition to research

One idea, four depths

A kitchen with very fast cooks but a slow delivery van serves meals at the speed of the van. Only recipes that use each delivered ingredient many times keep the cooks busy.

AI = FLOPs ÷ bytes. Ridge = peak ÷ bandwidth. Attainable = min(peak, AI × B). Below the ridge only bandwidth or reuse helps.

Tiling raises AI by T (chapter 5.2). Fusing kernels removes the bytes of intermediate results. Lower precision halves bytes and raises tensor core peaks, which moves both roofs.

Williams, Waterman and Patterson introduced the roofline in 2009. LLM decoding at batch 1 is deeply memory bound (AI near 1), which is why KV cache compression and speculative decoding matter.
