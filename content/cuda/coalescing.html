Lesson 1 of 5

Memory hands out 32 byte boxes

DRAM does not deliver single floats. It delivers sectors of 32 bytes (8 floats). When the 32 threads of a warp issue a load, the hardware collects all their addresses and fetches the smallest set of sectors that covers them. This is called coalescing.

Bytes the warp wantsExam favourite
useful = 32 × element size
Floats: 128 bytes. Doubles: 256 bytes.
EfficiencyExam favourite
efficiency = useful bytes ÷ (sectors × 32)
Stride 1 floats: 128 ÷ (4 × 32) = 100 percent.
Sectors for stride s (floats, aligned)
sectors = min(32, 4 × s)
Each thread lands in its own sector once s ≥ 8.
Real world scenario: buying sweets

Buying one sweet from each of 32 different shops costs 32 trips. Buying 32 sweets from one shop costs one trip. Neighbouring threads should read neighbouring addresses so the warp visits as few shops as possible.

Rows, columns and Quiz 1 question 5

In C, a 2-D array is stored row by row (row major). Element [y][x] sits at position y × width + x. Consecutive threads should vary x, the fast moving index.

Thread t readsNeighbouring lanes areSectors per warp read (floats)
A[row][t] (along a row)4 bytes apart4 (100 percent)
A[t][col] (down a column of width 1024)4096 bytes apart32 (12.5 percent)
Quiz 1 question 5: the store B[x × height + y]
  1. blockDim.x = 32, so a warp holds 32 consecutive x values and one y.
  2. Lane x writes B[x × 2048 + y]. Neighbouring lanes are 2048 floats = 8192 bytes apart.
  3. Every lane falls in a different 128 byte segment.
  4. 32 segments for the store (the load from A uses only 1)
transpose.cu
#define TILE 32 // Naive: reads are coalesced, writes jump by n floats (like Quiz 1 question 5)__global__ void transposeNaive(float *out, const float *in, int n) {    int x = blockIdx.x * TILE + threadIdx.x;    int y = blockIdx.y * TILE + threadIdx.y;    if (x < n && y < n) out[x * n + y] = in[y * n + x];} // Through shared memory: both the read and the write walk along rows__global__ void transposeShared(float *out, const float *in, int n) {    __shared__ float tile[TILE][TILE + 1];          // +1 avoids bank conflicts (chapter 3.3)    int x = blockIdx.x * TILE + threadIdx.x;    int y = blockIdx.y * TILE + threadIdx.y;    if (x < n && y < n) tile[threadIdx.y][threadIdx.x] = in[y * n + x];    __syncthreads();    x = blockIdx.y * TILE + threadIdx.x;            // swap the block coordinates    y = blockIdx.x * TILE + threadIdx.y;    if (x < n && y < n) out[y * n + x] = tile[threadIdx.x][threadIdx.y];}

The stride benchmark (lecture 11)

The lecture measured a copy kernel on a T4 while making threads read further and further apart. At stride 1 it reached 206 GB/s, about 64 percent of the T4's 320 GB/s data sheet value.

Sector modelExam favourite
useful bandwidth ≈ (stride 1 bandwidth) ÷ min(s, 8)
Once threads are 8 floats apart each lane needs its own sector, and the model stops falling. Real GPUs fall further at big strides because of DRAM page and TLB effects.

#include <cstdio> __global__ void copyStride(float *out, const float *in, int n, int s) {    int i = (blockIdx.x * blockDim.x + threadIdx.x) * s;   // thread t touches element t * s    if (i < n) out[i] = in[i];} int main() {    const int n = 1 << 24;    float *in, *out;    cudaMalloc(&in, n * sizeof(float));    cudaMalloc(&out, n * sizeof(float));    cudaEvent_t a, b;    cudaEventCreate(&a); cudaEventCreate(&b);    for (int s = 1; s <= 32; s *= 2) {        int threads = n / s;        cudaEventRecord(a);        copyStride<<<(threads + 255) / 256, 256>>>(out, in, n, s);        cudaEventRecord(b); cudaEventSynchronize(b);        float ms; cudaEventElapsedTime(&ms, a, b);        double useful = 2.0 * threads * sizeof(float);       // one read and one write per thread        printf("stride %2d: %7.1f GB/s useful\n", s, useful / ms / 1e6);    }    cudaFree(in); cudaFree(out);    return 0;}

Data layout: AoS against SoA, and wider loads

particles.cu
struct ParticleAoS { float x, y, z, mass; };        // array of structures: 16 bytes per particle struct ParticlesSoA { float *x, *y, *z, *mass; };   // structure of arrays: one array per field __global__ void moveAoS(ParticleAoS *p, float dx, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) p[i].x += dx;                        // lanes read floats 16 bytes apart: stride 4} __global__ void moveSoA(ParticlesSoA p, float dx, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) p.x[i] += dx;                        // lanes read neighbouring floats: stride 1}
What each marked line does and why
  1. Line 1struct ParticleAoS { float x, y, z, mass; }; // array of structures: 16 bytes per particleArray of structures: x, y, z and mass of one particle sit together, 16 bytes per particle.
  2. Line 3struct ParticlesSoA { float *x, *y, *z, *mass; }; // structure of arrays: one array per fieldStructure of arrays: all x values together, then all y values and so on.
  3. Line 7if (i < n) p[i].x += dx; // lanes read floats 16 bytes apart: stride 4Reading only p[i].x makes lanes 16 bytes apart, so 3 of every 4 bytes fetched are wasted.
  4. Line 12if (i < n) p.x[i] += dx; // lanes read neighbouring floats: stride 1Now lane i reads x[i]: a perfect stride 1 read.
Vector loads
float4: 32 lanes × 16 bytes = 512 bytes = 16 sectors, 100 percent
One instruction moves four floats per thread, so fewer instructions for the same bytes. The address must be 16 byte aligned.
Remember
AoS is natural for the CPU and often slow on the GPU. When kernels touch only some fields, store each field in its own array.
Going deeper: L1 caching and 128 byte lines

L1 and L2 track data in 128 byte lines made of four 32 byte sectors. Older GPUs (Fermi, Kepler) moved whole 128 byte lines on an L1 miss, so a scattered warp could move 32 × 128 = 4096 bytes. Modern GPUs fetch only the sectors that are needed, which is why the course counts sectors.

Lesson 5 of 5

From intuition to research

One idea, four depths

Neighbouring threads should read neighbouring addresses. Then one delivery covers the whole warp.

Sectors are 32 bytes. Efficiency = 32 × element size ÷ (sectors × 32). Stride s floats needs min(32, 4s) sectors. Row major: let threadIdx.x move along the row.

Misaligned starts cost one extra sector. AoS to SoA turns stride 4 into stride 1. Transposes and column walks are fixed by staging a tile in shared memory. Nsight Compute reports "sectors per request" to check this.

Hopper's TMA loads whole multi dimensional tiles with a single descriptor and handles strides and edges in hardware, which is how FlashAttention 3 keeps memory busy.
