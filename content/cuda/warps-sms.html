Streaming multiprocessors: what really runs your threads

A GPU is a set of identical streaming multiprocessors (SMs). Each SM has its own cores, registers, schedulers and on chip memory. A kernel's blocks are handed out to SMs, and an SM may hold several blocks at once.

Software (what you write)Hardware (what runs it)Rule
ThreadA CUDA core (one lane)Has its own registers and program counter
Warp of 32 threadsA warp schedulerIssues one instruction for all 32 lanes
Block (up to 1024 threads)One SMStays on that SM until it finishes, shares its shared memory
Grid (all blocks of a launch)The whole GPUBlocks spread over all SMs in any order
Common mistake
In class it was said that grids sit inside cores. It is the other way round: a thread runs on a core, a block on one SM, and a grid across all SMs.

Fermi had 16 SMs × 32 cores = 512 cores. An A100 has 108 SMs with 64 FP32 cores each, an H100 has 132.

Lesson 2 of 5

Warps, lanes and SIMT

The SM does not schedule single threads. It schedules warps: 32 threads with consecutive linear thread numbers. All lanes of a warp execute the same instruction at the same time on their own data. NVIDIA calls this SIMT, single instruction, multiple threads.

Warps per blockExam favourite
warps = ⌈B ÷ 32⌉
A part full warp still takes 32 lanes.
Warp and lane of thread tExam favourite
warp = ⌊t ÷ 32⌋, lane = t − 32 × warp
For 2-D blocks first compute t = x + y × Bx.
Wasted lanes
wasted = 32 × warps − B
efficiency = B ÷ (32 × warps)
Use block sizes that are multiples of 32.
Real world scenario: a school trip in 32 seat buses

The school hires buses with exactly 32 seats. 100 children need 4 buses, and the last bus leaves with only 4 children and 28 empty seats. The fuel cost is the same for a full bus. Choosing 96 or 128 children per trip wastes nothing.

who_am_i.cu

What each marked line does and why
  1. Line 4int t = threadIdx.x + threadIdx.y * blockDim.x;Linear thread number inside the block, x fastest. This is the order the hardware uses to cut warps.
  2. Line 5int warp = t / warpSize;warpSize is a built in constant, 32 on every NVIDIA GPU so far.
  3. Line 7if (lane == 0)Only lane 0 of each warp prints, so we see one line per warp.
  4. Line 13dim3 block(16, 16);A 16 × 16 block has 256 threads, so 8 warps of two rows each.
What it prints
block 0: warp 0 starts at thread (0, 0)
block 0: warp 1 starts at thread (0, 2)
... (8 lines, warp w starts at row 2w)
Going deeper: independent thread scheduling (Volta and later)

Since Volta each thread has its own program counter, so threads of a diverged warp can interleave and even wait for each other. The warp still issues one instruction at a time for its active lanes, so divergence still costs time (chapter 6.1), and code that relies on all 32 lanes being in step must say so with __syncwarp().

Lesson 3 of 5

Hiding latency: Little's law

A GPU core waits about 20 ticks for an arithmetic result and several hundred ticks for global memory. It does not stall. Each tick the warp scheduler picks another warp that is ready and issues its instruction. The cost of switching is zero, because every warp keeps its registers on the SM all the time.

Little's lawExam favourite
jobs in flight = latency (ticks) × throughput (jobs per tick)
To keep a pipe full you need as many jobs inside it as its length times its width.
In warps
warps in flight = (latency × operations per tick) ÷ 32
One warp instruction is 32 operations.
Memory version
bytes in flight = bandwidth × latency
To use all the bandwidth, this many bytes must be on the way at every moment.
Workbook worked example: Fermi against Kepler
  1. Fermi: latency 20 ticks, 32 operations per tick. In flight 20 × 32 = 640 operations = 20 warps.
  2. Kepler: latency 20 ticks, 192 operations per tick. In flight 20 × 192 = 3840 operations = 120 warps.
  3. Kepler needs 6 times more parallel work to stay busy
Real world scenario: a pizza oven

A pizza bakes for 8 minutes and the chef can slide in one pizza per minute. To keep the oven always working, there must be 8 pizzas inside at any moment. With only 4 orders the chef stands idle half the time. Warps are the pizzas.

Remember
Latency hiding needs either many warps (thread level parallelism) or several independent instructions inside each warp (instruction level parallelism). Two independent loads per warp halve the warps needed.
Lesson 4 of 5

Registers: the hidden limit

Registers per thread
registers per thread = registers on the SM ÷ threads on the SM
Lecture example: 32K registers for 1024 threads gives 32 each.
Binary K
32K = 32 × 1024 = 32,768
64K = 65,536
For registers K means 1024.
Bits to name a register
smallest b with 2b ≥ number of registers
An instruction names its operands, so 32 registers need 5 bits, 255 need 8.

Every resident thread keeps all its variables in the SM's register file, which is fixed when the chip is made (65,536 on recent GPUs). A kernel that needs more registers per thread leaves room for fewer threads, so there are fewer warps to hide latency. If a kernel needs more registers than allowed, the compiler spills them to local memory, which lives in slow DRAM.

How many threads fit by registers? (workbook P2.5.4)
  1. The kernel needs 40 registers per thread and the SM has 65,536.
  2. 65,536 ÷ 40 = 1638.4 threads.
  3. Threads come in whole warps: 1638 ÷ 32 = 51.2, so 51 warps.
  4. 51 warps = 1632 threads (the exact allocation rules are in chapter 2.4)
Lesson 5 of 5

From intuition to research

One idea, four depths

The GPU moves threads around in groups of 32, like buses. While one bus waits at a red light, the driver of another bus goes. With enough buses the road is always busy.

warps = ⌈B/32⌉, warp = ⌊t/32⌋, lane = t mod 32. Little: in flight = latency × throughput, divide by 32 for warps. Registers per thread = register file ÷ threads.

Each SM has 4 sub partitions on recent GPUs, each with its own scheduler issuing one warp instruction per tick. Occupancy (chapter 2.4) measures how many warps are resident, and the profiler's "stall reasons" say why ready warps are missing.

Volkov showed that high ILP can beat high occupancy: fewer warps with more independent work per thread reach peak bandwidth. Modern GEMM kernels run at low occupancy with large register tiles and asynchronous copies.
