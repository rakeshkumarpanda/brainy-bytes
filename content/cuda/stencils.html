What a stencil is

A stencil updates every point from a fixed pattern of neighbours. Blurs, edge filters, heat and wave simulations, and the Game of Life are all stencils. Every output can be computed at the same time, so one thread per output works well.

StencilPointsExample
1-D radius R2R + 1moving sum, R = 3 gives 7
2-D plus (radius 1)5heat in a plate
2-D box radius r(2r + 1)²blur, r = 2 gives 25
3-D plus (radius 1)7heat in a block
3-D box radius 127smoothing a volume
Neighbours in 2-DExam favourite
N = i − W, S = i + W, W = i − 1, E = i + 1
Row major with width W. Pixel (row 10, col 20) of a 640 wide image is 6420.
Neighbours in 3-DExam favourite
± 1, ± N, ± N²
Index i = (z × N + y) × N + x.
Real world scenario: passing a rumour

Each pupil in a classroom grid listens to the four pupils next to them and repeats an average of what they heard. After a few rounds the news has spread. Every pupil can listen at the same moment, which is why a GPU suits it.

Lesson 2 of 5

Halos in shared memory

Neighbouring outputs share most of their inputs. A block loads its B inputs into shared memory once, plus R extra values on each side called the halo, then every thread reads its 2R + 1 inputs from the fast tile.

Tile sizeExam favourite
B + 2R values
R = 3, B = 256: 262.
Global reads per outputExam favourite
(B + 2R) ÷ B with the tile, 2R + 1 without
R = 3, B = 256: 1.023 against 7, about 6.8 times fewer.
stencil1d.cu
#define R 3#define B 256 // out[i] = sum of in[i - R] .. in[i + R]. The input is padded with R values on each side.__global__ void stencil1d(const int *in, int *out) {    __shared__ int tile[B + 2 * R];    int g = blockIdx.x * B + threadIdx.x + R;   // position in the padded input    int s = threadIdx.x + R;                    // position in the tile    tile[s] = in[g];    if (threadIdx.x < R) {        tile[s - R] = in[g - R];                // left halo        tile[s + B] = in[g + B];                // right halo    }    __syncthreads();    int sum = 0;    for (int k = -R; k <= R; ++k)        sum += tile[s + k];    out[g - R] = sum;}
What each marked line does and why
  1. Line 7int g = blockIdx.x * B + threadIdx.x + R; // position in the padded inputg skips the R padding values at the start of the input.
  2. Line 9tile[s] = in[g];Every thread loads its own centre value.
  3. Line 10if (threadIdx.x < R) {The first R threads also load the halos, R on the left and R on the right.
  4. Line 14__syncthreads();Wait until the whole tile, halos included, is in shared memory.
  5. Line 17sum += tile[s + k];All 2R + 1 reads come from shared memory.
Lesson 3 of 5

3-D tiles: why big tiles still stay memory bound

Without tiling
AI = 13 ÷ 28 ≈ 0.46
7 multiplies and 6 adds, 7 floats loaded.
With T × T × T tilesExam favourite
AI(T) = 13 × (T − 2)³ ÷ (4T³)
Only the inner (T − 2)³ points make outputs.
Halo shareExam favourite
(T³ − (T − 2)³) ÷ T³
T = 8: 57.8 percent of loaded points are border.

AI can never pass 13 ÷ 4 = 3.25, and T = 8 already uses 512 threads. With one thread per point, a 3-D stencil stays memory bound on every modern GPU. Real codes use 2-D tiles that march through z, keeping three planes in registers.

Lesson 4 of 5

The heat equation and stability

3-D explicit heat stepExam favourite
Tnew = (1 − 6λ) T + λ × (sum of 6 neighbours)
λ = α Δt ÷ h². Weights add to 1, so a constant field stays constant.
StabilityExam favourite
λ ≤ 1/6 in 3-D, 1/4 in 2-D, 1/2 in 1-D
Above it the centre weight is negative and values oscillate and grow.
Largest time step
Δt ≤ h² ÷ (6α)
α = 0.0001, h = 0.01 gives Δt ≤ 0.167 s.
Common mistake
Lecture 6 slide 14 uses 0.25 for the centre and 0.1 for each of the 6 neighbours. They add to 0.85, so a field of 100 drops to 85 every step. With neighbour weight 0.1 the centre must be 1 − 6 × 0.1 = 0.4.
heat3d.cu
// One explicit step of 3-D heat: Tnew = (1 - 6L) T + L (sum of 6 neighbours)__global__ void heat3d(const float *T, float *Tn, int N, float L) {    int x = blockIdx.x * blockDim.x + threadIdx.x;    int y = blockIdx.y * blockDim.y + threadIdx.y;    int z = blockIdx.z * blockDim.z + threadIdx.z;    if (x < 1 || y < 1 || z < 1 || x >= N - 1 || y >= N - 1 || z >= N - 1) return;    int i = (z * N + y) * N + x;                 // x fastest, then y, then z    float nb = T[i - 1] + T[i + 1] + T[i - N] + T[i + N] + T[i - N * N] + T[i + N * N];    Tn[i] = (1.0f - 6.0f * L) * T[i] + L * nb;   // stable only when L <= 1/6} void run(float *dA, float *dB, int N, float L, int steps) {    dim3 blk(8, 8, 8), grd((N + 7) / 8, (N + 7) / 8, (N + 7) / 8);    for (int s = 0; s < steps; ++s) {        heat3d<<<grd, blk>>>(dA, dB, N, L);        float *t = dA; dA = dB; dB = t;         // ping-pong: new becomes old    }}
What each marked line does and why
  1. Line 7int i = (z * N + y) * N + x; // x fastest, then y, then zx is the fastest index, so a warp reads neighbouring x values: coalesced.
  2. Line 8float nb = T[i - 1] + T[i + 1] + T[i - N] + T[i + N] + T[i - N * N] + T[i + N * N];The six neighbours: x ± 1, y ± 1 (± N) and z ± 1 (± N²).
  3. Line 9Tn[i] = (1.0f - 6.0f * L) * T[i] + L * nb; // stable only when L <= 1/6Weights 1 − 6L and L add to 1.
  4. Line 16float *t = dA; dA = dB; dB = t; // ping-pong: new becomes oldPing-pong: swap the pointers so the new grid becomes the old one. No copy is needed.

Lesson 5 of 5

From intuition to research

One idea, four depths

Each point looks at its neighbours and updates. Load a patch once with a border around it, and let everyone read the patch.

Tile B + 2R, reads (B + 2R)/B against 2R + 1. 3-D AI = 13(T − 2)³/(4T³) ≤ 3.25. Heat stable for λ ≤ 1/6 in 3-D.

2.5-D blocking keeps three z planes in registers and marches up the grid. Temporal blocking does several time steps per load, trading extra halo for less traffic.

Weather, seismic and CFD codes are mostly stencils. Implicit schemes avoid the stability limit by solving a linear system each step, which brings in sparse solvers and multigrid.
