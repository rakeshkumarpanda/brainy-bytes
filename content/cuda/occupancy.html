Lesson 1 of 5

What occupancy means

Chapter 2.3 showed that an SM hides waiting by switching between warps. Occupancy says how many warps an SM really holds compared with the most it could hold.

OccupancyExam favourite
occupancy = active warps per SM ÷ maximum warps per SM
A100: maximum 64 warps (2048 threads). 48 active warps is 75 percent.
Blocks that fitExam favourite
blocks = min(warp limit, block limit, register limit, shared memory limit)
Every resource must fit at the same time, so the tightest one decides.

Real world scenario: a cinema with four rules

A cinema lets in a group only if there are enough seats, the group count is under the limit, the snack counter has enough cups and the car park has space. The hall may have empty seats but still turn groups away because the car park is full. The SM works the same way.

Lesson 2 of 5

Limit 1 and 2: threads and blocks

An SM holds at most a fixed number of warps and a fixed number of blocks. Small blocks run into the block limit long before the warps are used up.

Workbook worked example: 1024 threads, 32 warps, 8 blocks per SM, 16 × 16 blocks
  1. A block has 256 threads = 8 warps.
  2. Warp limit: 32 ÷ 8 = 4 blocks. Block limit: 8 blocks.
  3. The smaller is 4 blocks, so 4 × 8 = 32 warps.
  4. occupancy = 32 ÷ 32 = 100 percent
Small blocks on the same SM (P2.3.3)
  1. A 64 thread block is 2 warps.
  2. Warp limit 32 ÷ 2 = 16 blocks, block limit 8.
  3. 8 blocks × 2 warps = 16 warps.
  4. 16 ÷ 32 = 50 percent: the block limit bites
Smallest block for full occupancy
Bmin = max threads per SM ÷ max blocks per SM
A100: 2048 ÷ 32 = 64 threads. Anything smaller cannot reach 100 percent.
Lesson 3 of 5

Limit 3: registers, with rounding

Registers are not handed out one by one. On recent GPUs each warp receives registers in chunks of 256, so the per warp count is rounded up.

Registers per warpExam favourite
per warp = ⌈(r × 32) ÷ 256⌉ × 256
r = registers per thread. 37 registers give 1184, rounded up to 1280, the same as 40.
Register limit in blocksExam favourite
blocks = ⌊⌊65,536 ÷ per warp⌋ ÷ warps per block⌋
First whole warps, then whole blocks.
Workbook worked example 7.5: A100, 256 threads, 40 registers
  1. 40 × 32 = 1280 registers per warp (already a multiple of 256).
  2. 65,536 ÷ 1280 = 51.2, so 51 warps.
  3. 51 ÷ 8 warps per block = 6.4, so 6 blocks = 48 warps.
  4. 48 ÷ 64 = 75 percent
bounds.cu
// Ask the compiler to keep registers low enough for 4 blocks of 256 threads per SM__global__ void __launch_bounds__(256, 4)heavy(float *out, const float *in, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i >= n) return;    float a = in[i], s = 0.0f;    for (int k = 1; k <= 8; ++k) s += a / k;    out[i] = s;}
What each marked line does and why
  1. Line 2__global__ void __launch_bounds__(256, 4)__launch_bounds__(max threads per block, min blocks per SM) tells the compiler how you will launch the kernel.
  2. Line 3heavy(float *out, const float *in, int n) {With 256 threads and 4 blocks the SM needs 1024 threads, so the compiler caps each thread at 65,536 ÷ 1024 = 64 registers.
  3. Line 7for (int k = 1; k <= 8; ++k) s += a / k;A small loop. If a kernel needed more registers than the cap, the compiler would spill to local memory.
Remember
The flag -maxrregcount=N caps registers for every kernel in a file. __launch_bounds__ is better because it is per kernel and says why.
Lesson 4 of 5

Limit 4: shared memory

Each block that uses shared memory takes its bytes from the SM's pool. On compute capability 8.x the system also reserves 1 KB per block.

Shared memory limitExam favourite
blocks = ⌊shared memory per SM ÷ (bytes per block + reserved)⌋
CC 8.6: 102,400 bytes per SM, 1024 reserved per block.
Workbook 9.7: CC 8.6, 256 threads, 32 registers, 32 KB of shared memory
  1. Warp limit 48 ÷ 8 = 6. Block limit 16. Registers 32 × 32 = 1024 per warp, 64 warps, 8 blocks.
  2. Shared memory: 102,400 ÷ (32,768 + 1024) = 3.03, so 3 blocks.
  3. The smallest limit is 3 blocks = 24 warps.
  4. 24 ÷ 48 = 50 percent

Lesson 5 of 5

Is higher occupancy always faster?

One idea, four depths

The SM is a hall with limited seats, groups, cups and parking. Occupancy is the share of seats in use. More people waiting means less idle time, up to a point.

Blocks = min of four limits. Registers round up to 256 per warp. Shared memory adds 1 KB reserved per block on 8.x. Occupancy = blocks × warps per block ÷ max warps.

Once enough warps hide the latency (Little's law), more occupancy gives nothing. A kernel at 50 percent with 4 independent loads per thread can beat one at 100 percent with 1. Measure with Nsight Compute "achieved occupancy", which can be lower than the theory because of tail effects and uneven blocks.

High performance GEMM and attention kernels deliberately run at 12 to 25 percent occupancy: each thread holds a large tile of results in registers, and asynchronous copies (cp.async, TMA) keep memory busy. Occupancy is a means, not the goal.
