Lesson 1 of 4

Host, device and the recipe every program follows

A CUDA program is an ordinary C++ program that runs on the CPU (the host) and now and then hands a function, called a kernel, to the GPU (the device). Host and device have separate memories, so data must be copied across.

  1. Allocate on hostmalloc or new
  2. Allocate on devicecudaMalloc
  3. Copy incudaMemcpy host to device
  4. Launchkernel<<<blocks, threads>>>
  5. Copy outcudaMemcpy device to host
  6. FreecudaFree and free
QualifierRuns onCalled fromNotes
__global__devicehost (and device with dynamic parallelism)A kernel. Must return void. Launched with <<< >>>
__device__devicedeviceA helper function used inside kernels. May return any type

In the exam
Quiz 1 question 6: the correct kernel signature is __global__ void. A kernel cannot return a value, because thousands of threads run it and the launch returns to the host at once without waiting. Results go back through memory. __shared__ is a memory space, not a function qualifier.
Real world scenario: posting parcels to a factory

You (the host) pack raw material into boxes, ship them to a factory (cudaMemcpy), send a work order (the launch), and wait for the finished goods to be shipped back. The factory has thousands of workers, but nothing happens until the material arrives, and you cannot use the goods until they come back.

The complete vector addition program

vector_add.cu
#include <cstdio>#include <cstdlib>#include <cuda_runtime.h> #define CHECK(call) do { cudaError_t e = (call); if (e != cudaSuccess) { \    printf("CUDA error %s at line %d\n", cudaGetErrorString(e), __LINE__); exit(1); } } while (0) __global__ void add(const float* a, const float* b, float* c, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) c[i] = a[i] + b[i];} int main() {    int n = 1000000;    size_t bytes = n * sizeof(float);    float *a = (float*)malloc(bytes), *b = (float*)malloc(bytes), *c = (float*)malloc(bytes);    for (int i = 0; i < n; i++) { a[i] = i; b[i] = 2.0f * i; }     float *d_a, *d_b, *d_c;    CHECK(cudaMalloc(&d_a, bytes));    CHECK(cudaMalloc(&d_b, bytes));    CHECK(cudaMalloc(&d_c, bytes));    CHECK(cudaMemcpy(d_a, a, bytes, cudaMemcpyHostToDevice));    CHECK(cudaMemcpy(d_b, b, bytes, cudaMemcpyHostToDevice));     int threads = 256;    int blocks = (n + threads - 1) / threads;    add<<<blocks, threads>>>(d_a, d_b, d_c, n);    CHECK(cudaGetLastError());    CHECK(cudaMemcpy(c, d_c, bytes, cudaMemcpyDeviceToHost));     printf("c[10] = %.1f, c[%d] = %.1f\n", c[10], n - 1, c[n - 1]);    CHECK(cudaFree(d_a)); CHECK(cudaFree(d_b)); CHECK(cudaFree(d_c));    free(a); free(b); free(c);    return 0;}
What each marked line does and why
  1. Line 3#include <cuda_runtime.h>The CUDA runtime header: cudaMalloc, cudaMemcpy, cudaFree and the error types. nvcc includes it automatically, but writing it makes the file clearer.
  2. Line 5#define CHECK(call) do { cudaError_t e = (call); if (e != cudaSuccess) { \A small macro that checks every CUDA call. Almost every CUDA function returns a cudaError_t. Without checks a failed call goes unnoticed and later results are silently wrong.
  3. Line 8__global__ void add(const float* a, const float* b, float* c, int n) {__global__ marks a kernel: it runs on the GPU, is launched from the host, and must return void. const and pointers to device memory are normal C++.
  4. Line 9int i = blockIdx.x * blockDim.x + threadIdx.x;The global thread index. Each thread computes a different i, so each handles a different element.
  5. Line 10if (i < n) c[i] = a[i] + b[i];The guard. We launch a whole number of blocks, so some threads may have i ≥ n. They must do nothing, or they write past the end of the array.
  6. Line 15size_t bytes = n * sizeof(float);size_t for byte counts, because large arrays overflow a 32 bit int.
  7. Line 16float *a = (float*)malloc(bytes), *b = (float*)malloc(bytes), *c = (float*)malloc(bytes);Host memory, allocated with ordinary malloc.
  8. Line 20CHECK(cudaMalloc(&d_a, bytes));cudaMalloc reserves memory in the GPU's global memory and writes the device address into d_a. The host must never dereference d_a.
  9. Line 23CHECK(cudaMemcpy(d_a, a, bytes, cudaMemcpyHostToDevice));Copy the input from host to device over PCIe. The last argument names the direction.
  10. Line 26int threads = 256;Threads per block: a multiple of 32 (a warp). 128 to 512 is a good default.
  11. Line 27int blocks = (n + threads - 1) / threads;Blocks needed = ⌈n ÷ threads⌉ using whole number arithmetic. For a million elements that is 3907 blocks.
  12. Line 28add<<<blocks, threads>>>(d_a, d_b, d_c, n);The launch. <<<blocks, threads>>> is the execution configuration. It returns to the host immediately, the GPU runs in the background.
  13. Line 29CHECK(cudaGetLastError());A launch returns no error code, so ask for it. This catches a bad configuration such as 2000 threads per block.
  14. Line 30CHECK(cudaMemcpy(c, d_c, bytes, cudaMemcpyDeviceToHost));Copy the result back. This cudaMemcpy waits until the kernel has finished, so it also synchronises.
  15. Line 33CHECK(cudaFree(d_a)); CHECK(cudaFree(d_b)); CHECK(cudaFree(d_c));Give the device memory back. Leaking it in a loop eventually makes cudaMalloc fail.
What it prints
c[10] = 30.0, c[999999] = 2999997.0

nvcc -O3 -arch=sm_75 vector_add.cu -o vector_add./vector_add# on Google Colab, put %%writefile vector_add.cu at the top of a cell, then run !nvcc ... in the next cell
What you will see

-arch=sm_75 compiles for compute capability 7.5 (a T4). Use sm_80 for an A100, sm_86 for an RTX 30 card, sm_89 for an RTX 40 card. nvcc splits the file: host code goes to the normal C++ compiler, device code becomes PTX (a virtual assembly) and then SASS (the real machine code of that GPU).

Hello world, asynchronous launches and unified memory

hello.cu
#include <cstdio> __global__ void hello() {    printf("Hello from block %d, thread %d\n", blockIdx.x, threadIdx.x);} int main() {    hello<<<2, 3>>>();    cudaDeviceSynchronize();    return 0;}
What each marked line does and why
  1. Line 4printf("Hello from block %d, thread %d\n", blockIdx.x, threadIdx.x);printf works inside a kernel. Output is buffered on the GPU and printed when the host synchronises.
  2. Line 8hello<<<2, 3>>>();Two blocks of three threads: six lines of output.
  3. Line 9cudaDeviceSynchronize();Kernel launches are asynchronous. Without this wait, main could return and the program end before the GPU prints anything.
What it prints
Hello from block 0, thread 0
Hello from block 0, thread 1
Hello from block 0, thread 2
Hello from block 1, thread 0
Hello from block 1, thread 1
Hello from block 1, thread 2
Common mistake
The order of the six lines is not guaranteed. Blocks may run in any order, so block 1 can print first. Never write code that depends on the order blocks run in.
managed.cubeyond the lecture: unified memory
#include <cstdio> __global__ void scale(float* x, float s, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) x[i] *= s;} int main() {    int n = 1 << 20;    float* x;    cudaMallocManaged(&x, n * sizeof(float));    for (int i = 0; i < n; i++) x[i] = 1.0f;    scale<<<(n + 255) / 256, 256>>>(x, 3.0f, n);    cudaDeviceSynchronize();    printf("x[0] = %.1f\n", x[0]);    cudaFree(x);    return 0;}
What each marked line does and why
  1. Line 11cudaMallocManaged(&x, n * sizeof(float));cudaMallocManaged gives one pointer that works on both host and device. The driver moves pages to whichever side touches them (unified memory).
  2. Line 12for (int i = 0; i < n; i++) x[i] = 1.0f;The host fills the array directly, no cudaMemcpy.
  3. Line 14cudaDeviceSynchronize();Now the wait is essential: the host may not read x until the kernel has finished.
What it prints
x[0] = 3.0

Unified memory makes the first program shorter, but the copies still happen behind the scenes as page migrations. For speed, explicit copies or cudaMemPrefetchAsync are often better, because you control when the data moves.

Going deeper: what the launch really does

The host puts a launch command into a queue (a stream) and returns. The GPU front end takes blocks from the grid and hands each block to an SM that has room. A block stays on its SM until all its threads finish, and the SM runs its threads warp by warp. Blocks are never guaranteed to run in a fixed order or at the same time, which is why blocks may not wait for each other inside a kernel.

Lesson 4 of 4

From intuition to research

One idea, four depths

The CPU is the boss and the GPU is a big team in another building. The boss sends materials, gives the order, waits, and collects the result.

Six steps: cudaMalloc, cudaMemcpy H2D, launch <<<⌈n/B⌉, B>>>, guard if (i < n), cudaMemcpy D2H, cudaFree. Kernels are __global__ void. Check every call.

Launches are asynchronous and ordered within a stream. cudaMemcpy on the default stream synchronises. Errors in a kernel appear at the next synchronising call, so debug builds call cudaDeviceSynchronize after each launch. nvcc compiles device code to PTX and SASS for the -arch you name.

CUDA Graphs record a whole sequence of launches and copies once and replay it with one call, cutting launch overhead. Dynamic parallelism lets kernels launch kernels. Libraries such as cuBLAS, cuDNN and Thrust, and Python front ends like Numba, CuPy and Triton, generate the same kernels for you.

Work it out: how many threads start? (lecture 3 slide 4)
  1. Kernel1<<<100, 256>>>: 100 × 256 = 25,600 threads.
  2. Kernel2<<<50, 1024>>>: 50 × 1024 = 51,200 threads (the slide is right, 5120 said in class was a slip).
  3. Total threads = blocks × threads per block
