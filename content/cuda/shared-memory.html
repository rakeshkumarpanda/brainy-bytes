Shared memory: a cache you control

Each SM has a small, very fast memory that the threads of a block share. You declare it with __shared__, fill it from global memory, call __syncthreads() so everyone sees the full tile, and then read it many times. Unlike a normal cache, nothing is loaded or kept unless you write the code for it.

reverse.cu
#include <cstdio> // Reverse each block of 256 elements using a shared memory buffer__global__ void reverseBlock(int *d, int n) {    __shared__ int s[256];                   // one copy per block, on the SM    int t = threadIdx.x;    int i = blockIdx.x * blockDim.x + t;    if (i < n) s[t] = d[i];                  // every thread loads one element    __syncthreads();                         // wait until the whole tile is loaded    int src = blockDim.x - 1 - t;    if (i < n) d[i] = s[src];                // read an element another thread loaded} int main() {    const int n = 1024;    int h[n], *d;    for (int k = 0; k < n; ++k) h[k] = k;    cudaMalloc(&d, n * sizeof(int));    cudaMemcpy(d, h, n * sizeof(int), cudaMemcpyHostToDevice);    reverseBlock<<<n / 256, 256>>>(d, n);    cudaMemcpy(h, d, n * sizeof(int), cudaMemcpyDeviceToHost);    printf("%d %d %d\n", h[0], h[255], h[256]);    cudaFree(d);    return 0;}
What each marked line does and why
  1. Line 5__shared__ int s[256]; // one copy per block, on the SM256 ints = 1 KB of shared memory per block.
  2. Line 8if (i < n) s[t] = d[i]; // every thread loads one elementEach thread copies one element from slow global memory into the tile.
  3. Line 9__syncthreads(); // wait until the whole tile is loadedThe barrier: no thread continues until every thread of the block has reached this line.
  4. Line 10int src = blockDim.x - 1 - t;Thread t reads the element thread 255 − t wrote. Without the barrier it could read a value not loaded yet.
What it prints
255 0 511
dynamic_shared.cu
// Dynamic shared memory: the size is chosen at launch time__global__ void scaleTile(float *d, float a) {    extern __shared__ float buf[];           // size comes from the third launch parameter    int t = threadIdx.x, i = blockIdx.x * blockDim.x + t;    buf[t] = d[i];    __syncthreads();    d[i] = a * buf[t];} void launch(float *d, int n, int threads) {    size_t bytes = threads * sizeof(float);    scaleTile<<<n / threads, threads, bytes>>>(d, 2.0f);}
What each marked line does and why
  1. Line 3extern __shared__ float buf[]; // size comes from the third launch parameterextern __shared__ with empty brackets means the size is decided at launch.
  2. Line 12scaleTile<<<n / threads, threads, bytes>>>(d, 2.0f);The third value inside <<< >>> is the number of dynamic shared memory bytes per block.
Common mistake
__syncthreads() must be reached by every thread of the block. Putting it inside an if that only some threads enter can hang the block or give wrong results.
Lesson 2 of 4

Banks and conflicts

Shared memory is split into 32 banks, each 4 bytes wide. Each bank can serve one 4 byte word per tick. If the 32 lanes of a warp hit 32 different banks, the access takes one pass. If several lanes need different words in the same bank, they take turns.

Bank of an addressExam favourite
bank = ⌊byte address ÷ 4⌋ mod 32
Word w lives in bank w mod 32. Byte 260 is word 65, bank 1.
Conflict for stride sExam favourite
ways = gcd(s, 32)
Odd strides are always conflict free.
Broadcast
same word for many lanes → no conflict
One read is sent to every lane that asked for it.
Real world scenario: 32 ticket windows

A station has 32 ticket windows. If 32 travellers each go to a different window, everyone is served at once. If 8 travellers queue at window 0 for different tickets, the last one waits 8 turns. If 8 travellers all want the same newspaper, the clerk holds it up once and everyone reads it.

Lesson 3 of 4

Padding and layout fixes

Workbook 11.2 worked example: thread t reads tile[t][0] of a 32 × 32 float tile
  1. Element [t][0] is word 32t, so bank (32t) mod 32 = 0 for every lane.
  2. 32 different words in bank 0: 32 passes.
  3. Declare the tile as [32][33]: element [t][0] is word 33t, bank t mod 32.
  4. 32 different banks, 1 pass. The cost is 32 × 33 × 4 − 32 × 32 × 4 = 128 bytes
Workbook 11.3: 32 threads each store 32 powers
  1. Layout A writes A[32i + p]: at each p the lanes are 32 words apart, a 32-way conflict.
  2. 32 steps × 32 passes = 1024 passes.
  3. Layout B writes B[32p + i]: lanes 1 word apart, 1 pass per step.
  4. 32 passes, 32 times faster
powers.cu
// 32 threads, each computes 32 powers of its own number into shared memory__global__ void powers(float *out, const float *x) {    __shared__ float A[32 * 32];    __shared__ float B[32 * 32];    int i = threadIdx.x;    float v = 1.0f;    for (int p = 0; p < 32; ++p) {        v *= x[i];        A[32 * i + p] = v;      // layout A: lanes 32 words apart, every lane in bank 0        B[32 * p + i] = v;      // layout B: lanes 1 word apart, one lane per bank    }    __syncthreads();    for (int k = i; k < 32 * 32; k += 32) out[k] = A[k] + B[k];}
What each marked line does and why
  1. Line 9A[32 * i + p] = v; // layout A: lanes 32 words apart, every lane in bank 0Layout A: thread i owns a row of 32 values, so at one moment all lanes write column p: same bank.
  2. Line 10B[32 * p + i] = v; // layout B: lanes 1 word apart, one lane per bankLayout B: the 32 lanes write one row together: 32 different banks.
  3. Line 12__syncthreads();Both tiles must be complete before they are copied out.
  4. Line 13for (int k = i; k < 32 * 32; k += 32) out[k] = A[k] + B[k];Copy out with consecutive lanes on consecutive words, which is also coalesced in global memory.
Going deeper: 8 byte values

A double covers two banks. Under the plain 32-bit model, lane t reading double t touches words 2t and 2t + 1, so 16 lanes fill the 32 banks and the warp needs 2 passes. Recent GPUs serve 64-bit accesses in two half warp phases, which gives the same 2 passes without any extra waiting.

Lesson 4 of 4

From intuition to research

One idea, four depths

Shared memory is a fast shelf for a team. It has 32 doors. Spread the team over the doors, or let everyone read the same thing.

bank = word mod 32, conflict = gcd(stride, 32). Pad 2-D tiles to an odd width. __syncthreads() between writing and reading a tile.

Shared memory and L1 share one SRAM per SM. You can ask for a bigger shared carve out with cudaFuncSetAttribute and cudaFuncAttributePreferredSharedMemoryCarveout. More shared memory per block lowers occupancy (chapter 2.4).

Swizzled layouts (XOR of row and column bits) avoid conflicts without wasting padding. CUTLASS and the Hopper TMA use them for matrix tiles.
