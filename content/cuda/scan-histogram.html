Prefix sums: inclusive and exclusive

A scan (prefix sum) turns a list into running totals. It looks serial, because each total needs the one before it, but it can be done in log₂ n parallel steps.

Inclusive scanExam favourite
yi = x0 + x1 + … + xi
[3, 1, 7, 0] → [3, 4, 11, 11].
Exclusive scanExam favourite
yi = x0 + … + xi−1, y0 = 0
[3, 1, 7, 0] → [0, 3, 4, 11]. The inclusive scan shifted right by one.
AlgorithmStepsAdditionsNote

Hillis and Steelelog₂ nn log₂ n − (n − 1)simple, extra work

Lesson 2 of 5

A block scan in CUDA

scan_block.cu
// Inclusive Hillis and Steele scan of one block (n = blockDim.x <= 1024), double buffered__global__ void scanBlock(const int *in, int *out, int n) {    extern __shared__ int buf[];               // 2 * n ints: two halves we swap between    int t = threadIdx.x, src = 0, dst = n;    buf[t] = (t < n) ? in[t] : 0;    __syncthreads();    for (int off = 1; off < n; off <<= 1) {        int v = buf[src + t];        if (t >= off) v += buf[src + t - off];  // add the value off places to the left        buf[dst + t] = v;        __syncthreads();        int tmp = src; src = dst; dst = tmp;    // swap halves, never read and write one array    }    if (t < n) out[t] = buf[src + t];}
What each marked line does and why
  1. Line 3extern __shared__ int buf[]; // 2 * n ints: two halves we swap betweenTwo halves of shared memory. A step reads one half and writes the other.
  2. Line 7for (int off = 1; off < n; off <<= 1) {off = 1, 2, 4, …: log₂ n steps.
  3. Line 9if (t >= off) v += buf[src + t - off]; // add the value off places to the leftThreads with t < off have nothing to the left at this distance and keep their value.
  4. Line 11__syncthreads();Every thread must write before anyone reads the next step.
  5. Line 12int tmp = src; src = dst; dst = tmp; // swap halves, never read and write one arraySwapping halves avoids the race where a thread reads a value its neighbour already overwrote in this step.
Common mistake
Updating one array in place with buf[t] += buf[t − off] is a race: thread t may read buf[t − off] after thread t − off has already added to it. Double buffering or a barrier between the read and the write fixes it.
Going deeper: scans larger than one block

Scan each block, write each block's total to an array, scan that array, then add each block's scanned total to all its elements. CUB's DeviceScan does it in a single pass with decoupled look back.

Lesson 3 of 5

What scans are for: compaction

Filtering a list on the GPU is hard because each thread does not know where to write its kept value. An exclusive scan of 0/1 flags gives every kept value its output position, so all threads can write at the same time without clashing.

UseHow the scan helps
Stream compactionpositions of kept items
Radix sortpositions of keys with bit 0 and bit 1
Sparse matrices (CSR)row start offsets from row lengths
Allocating variable outputeach thread's write offset

Histograms and atomic contention

A histogram counts how many values fall in each bin. Many threads may hit the same bin at once, so the increment must be an atomic operation. When many threads hit one address, the atomics are done one after another (contention).

Global atomics without privatisation
one atomic per element
n = 10⁶ bytes → 10⁶ global atomics, all on 256 addresses.
Privatised (shared memory) histogramExam favourite
global atomics = blocks × bins at most
Each block counts in fast shared memory, then merges once.
histogram.cu
#define BINS 256 // Histogram of bytes: private copy per block in shared memory, then merge__global__ void histogram(const unsigned char *data, int n, unsigned int *hist) {    __shared__ unsigned int local[BINS];    for (int b = threadIdx.x; b < BINS; b += blockDim.x) local[b] = 0;    __syncthreads();    for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += blockDim.x * gridDim.x)        atomicAdd(&local[data[i]], 1u);         // fast shared memory atomic    __syncthreads();    for (int b = threadIdx.x; b < BINS; b += blockDim.x)        if (local[b]) atomicAdd(&hist[b], local[b]);   // one global atomic per bin per block}
What each marked line does and why
  1. Line 5__shared__ unsigned int local[BINS];A private histogram for this block in shared memory.
  2. Line 6for (int b = threadIdx.x; b < BINS; b += blockDim.x) local[b] = 0;Clear it with a block stride loop: 256 bins and any number of threads.
  3. Line 8for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += blockDim.x * gridDim.x)Grid stride loop over the data (chapter 2.2).
  4. Line 9atomicAdd(&local[data[i]], 1u); // fast shared memory atomicShared memory atomics are much cheaper than global ones, and only threads of this block compete.
  5. Line 12if (local[b]) atomicAdd(&hist[b], local[b]); // one global atomic per bin per blockMerge: at most 256 global atomics per block instead of one per element.
Real world scenario: a class vote

Asking 1000 pupils to walk to one ballot box makes a long queue. Letting each class count its own votes, then sending one sheet per class to the head teacher, removes the queue.

Lesson 5 of 5

From intuition to research

One idea, four depths

Running totals and tallies. With many helpers the totals can be built in a few rounds, and each class can count its own votes first.

Inclusive and exclusive scan, Hillis and Steele (log n steps, n log n work), Blelloch (2 log n steps, 2n work). Histogram: private shared memory copy, then one global atomic per bin per block.

Bank conflicts in Blelloch are removed with padding. Warp scans use __shfl_up_sync. Histograms with very skewed data (one hot bin) suffer most contention, aggregating in registers first helps.

Single pass scans with decoupled look back (Merrill and Garland 2016) run at memory bandwidth. Onesweep radix sort builds on them and is used in CUB.
