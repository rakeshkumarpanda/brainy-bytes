Five places a value can live

A GPU has several memories because no memory can be big, fast and visible to everyone all at once. Fast memory sits on the chip and is small. Big memory is far away and slow. CUDA gives you a menu and lets you choose.

MemoryWho sees itLives forSpeedHow you get it
Registersone threadthe threadabout 1 tickany normal local variable
Localone threadthe threadDRAM speed (cached)big private arrays, spilled registers
Sharedall threads of one blockthe blockabout 20 to 30 ticks__shared__
Globalall threads, all kernels, the hostuntil cudaFreeabout 400 to 800 tickscudaMalloc
Constantall threads, read onlythe applicationfast when the warp reads one address__constant__ and cudaMemcpyToSymbol
Common mistake
Local memory is not near the thread. "Local" means private. It lives in device DRAM and is only cached on chip.
Real world scenario: a kitchen

The chopping board in front of a cook is a register: tiny, private, instant. The shared counter of one cooking team is shared memory. The big store room everyone walks to is global memory. The recipe card pinned on the wall that nobody may change is constant memory.

Lesson 2 of 5

Quiz 1 question 8: visible to all SMs, for the whole application

The question asks which memory every SM can reach directly and which lasts for the whole program. Test each option for both properties.

Rakesh's worked solution
  1. Shared memory belongs to one block on one SM, so it fails the "all SMs" test.
  2. L1 cache is private to each SM, so it fails too.
  3. L2 cache is shared by all SMs, but it is a cache, not a memory space. You cannot allocate in it and the hardware evicts what it likes.
  4. Global memory is addressed by every thread on every SM, and an allocation lives until cudaFree or program exit.
  5. Answer: option 1, global memory
In the exam
A memory space is something you name and address. A cache is a hardware copy of global data that fills and empties by itself. This difference decides questions like Q8.
Lesson 3 of 5

Constant memory and caches

Constant memory holds small read only values such as filter weights. The host writes it before the launch. When all 32 threads of a warp read the same address, one fetch is broadcast to the whole warp. If they read different addresses, the reads are done one after another.

blur_constant.cu
#include <cstdio> __constant__ float c_weights[9];          // 36 bytes in constant memory, read only for kernels __global__ void blur3x3(const float *in, float *out, int w, int h) {    int x = blockIdx.x * blockDim.x + threadIdx.x;    int y = blockIdx.y * blockDim.y + threadIdx.y;    if (x < 1 || y < 1 || x >= w - 1 || y >= h - 1) return;    float s = 0.0f;    for (int dy = -1; dy <= 1; ++dy)        for (int dx = -1; dx <= 1; ++dx)            s += c_weights[(dy + 1) * 3 + (dx + 1)] * in[(y + dy) * w + (x + dx)];    out[y * w + x] = s;} int main() {    float h_w[9];    for (int k = 0; k < 9; ++k) h_w[k] = 1.0f / 9.0f;    cudaMemcpyToSymbol(c_weights, h_w, sizeof(h_w));    printf("weights copied to constant memory\n");    return 0;}
What each marked line does and why
  1. Line 3__constant__ float c_weights[9]; // 36 bytes in constant memory, read only for kernels__constant__ puts the array in the 64 KB constant bank. Kernels may read it but never write it.
  2. Line 12s += c_weights[(dy + 1) * 3 + (dx + 1)] * in[(y + dy) * w + (x + dx)];Every thread of the warp reads the same weight at the same loop step, so the broadcast works perfectly.
  3. Line 18for (int k = 0; k < 9; ++k) h_w[k] = 1.0f / 9.0f;The weights are made on the CPU first.
  4. Line 19cudaMemcpyToSymbol(c_weights, h_w, sizeof(h_w));cudaMemcpyToSymbol copies host data into a __constant__ variable by its name.
What it prints

Going deeper: read only loads and __restrict__

Marking pointers const float *__restrict__ in tells the compiler that no other pointer writes the same data, so it may use the read only data path. The function __ldg(&in[i]) asks for it directly.

Host memory: pageable, pinned and unified

Data starts in the CPU's RAM. Normal malloc memory is pageable: the operating system may move it. The GPU's copy engine cannot read such memory directly, so the driver first copies it into a hidden locked buffer. Pinned (page locked) memory from cudaMallocHost skips that extra copy and is required for copies that overlap with kernels (chapter 6.2).

Copy timeExam favourite
t = bytes ÷ bandwidth
The PCIe link is far slower than the GPU's own DRAM, so copy once and reuse.
Worth sending to the GPU
tcopy in + tkernel + tcopy out < tCPU
From chapter 1.2: count the copies too.
pinned_vs_pageable.cu
#include <cstdio>#include <cstdlib> int main() {    const size_t bytes = 256u << 20;               // 256 MB    float *pageable = (float *)malloc(bytes);    float *pinned = nullptr;    cudaMallocHost(&pinned, bytes);                // page locked host memory    float *d = nullptr;    cudaMalloc(&d, bytes);     cudaEvent_t t0, t1;    cudaEventCreate(&t0); cudaEventCreate(&t1);    float ms = 0.0f;     cudaEventRecord(t0);    cudaMemcpy(d, pageable, bytes, cudaMemcpyHostToDevice);    cudaEventRecord(t1); cudaEventSynchronize(t1);    cudaEventElapsedTime(&ms, t0, t1);    printf("pageable: %.2f GB/s\n", bytes / ms / 1e6);     cudaEventRecord(t0);    cudaMemcpy(d, pinned, bytes, cudaMemcpyHostToDevice);    cudaEventRecord(t1); cudaEventSynchronize(t1);    cudaEventElapsedTime(&ms, t0, t1);    printf("pinned:   %.2f GB/s\n", bytes / ms / 1e6);     cudaFree(d); cudaFreeHost(pinned); free(pageable);    return 0;}
What each marked line does and why
  1. Line 8cudaMallocHost(&pinned, bytes); // page locked host memorycudaMallocHost returns page locked memory. Use it for buffers you copy often, and do not lock too much of the RAM.
  2. Line 12cudaEvent_t t0, t1;CUDA events time work on the GPU timeline. Elapsed time comes back in milliseconds.
  3. Line 20printf("pageable: %.2f GB/s\n", bytes / ms / 1e6);bytes ÷ ms ÷ 10⁶ gives GB/s.
  4. Line 28cudaFree(d); cudaFreeHost(pinned); free(pageable);Every cudaMallocHost needs a cudaFreeHost.
What it prints
(typical result: pinned is faster than pageable, how much depends on the machine)
unified.cu
#include <cstdio> __global__ void addOne(float *a, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) a[i] += 1.0f;} int main() {    int n = 1 << 20, dev = 0;    float *a = nullptr;    cudaMallocManaged(&a, n * sizeof(float));      // one pointer for CPU and GPU    for (int i = 0; i < n; ++i) a[i] = i;           // pages start on the CPU    cudaMemPrefetchAsync(a, n * sizeof(float), dev); // move them before the kernel needs them    addOne<<<(n + 255) / 256, 256>>>(a, n);    cudaDeviceSynchronize();                        // wait before the CPU reads    printf("a[10] = %.1f\n", a[10]);    cudaFree(a);    return 0;}
What each marked line does and why
  1. Line 11cudaMallocManaged(&a, n * sizeof(float)); // one pointer for CPU and GPUcudaMallocManaged gives one pointer that works on both CPU and GPU. Pages move on demand.
  2. Line 13cudaMemPrefetchAsync(a, n * sizeof(float), dev); // move them before the kernel needs themPrefetching moves the pages before the kernel starts, so the kernel does not stop on page faults.
  3. Line 15cudaDeviceSynchronize(); // wait before the CPU readsThe CPU must wait before reading results, otherwise it reads old values.
What it prints
a[10] = 11.0
Lesson 5 of 5

From intuition to research

One idea, four depths

Close memory is small and fast, far memory is big and slow. Keep the things you use again and again close by.

Registers (thread), shared (block), global (all, host too), constant (all, read only, broadcast), local (private, but in DRAM). Copy time = bytes ÷ bandwidth. Pinned memory is needed for async copies.

A good kernel loads each byte from DRAM once and reuses it many times from registers and shared memory. That is the idea of tiling (chapters 5.2 to 5.4). The roofline (chapter 4.2) turns this into numbers.

Hopper adds distributed shared memory between the blocks of a cluster and the Tensor Memory Accelerator, which copies whole tiles from global to shared memory without using threads.
