Lesson 1 of 5

The plain kernel and its traffic

One thread computes one element of C = A × B. It walks along a row of A and down a column of B, so it loads 2N values from global memory to do N multiply-adds. Every value of A is loaded N times in total, once by each thread in its row of C.

matmul_naive.cu
__global__ void matMulNaive(const float *A, const float *B, float *C, int N) {    int row = blockIdx.y * blockDim.y + threadIdx.y;    int col = blockIdx.x * blockDim.x + threadIdx.x;    if (row < N && col < N) {        float sum = 0.0f;        for (int k = 0; k < N; k++)            sum += A[row * N + k] * B[k * N + col];   // 2 global loads per multiply-add        C[row * N + col] = sum;    }}
What each marked line does and why
  1. Line 2int row = blockIdx.y * blockDim.y + threadIdx.y;y picks the row of C, x picks the column, as in chapter 2.2.
  2. Line 7sum += A[row * N + k] * B[k * N + col]; // 2 global loads per multiply-addA[row × N + k] walks along a row. B[k × N + col] walks down a column, but neighbouring threads have neighbouring col, so that read is coalesced across the warp.
  3. Line 8C[row * N + col] = sum;One store per thread.

Lesson 2 of 5

Tiles in shared memory

A block of T × T threads computes a T × T tile of C. In each phase it loads one T × T tile of A and one of B into shared memory, each thread loading one value of each. Then every thread does T multiply-adds from shared memory. Each loaded value is used T times.

PhasesExam favourite
phases = ⌈N ÷ T⌉
N = 1024, T = 16: 64 phases.
Loads per thread (tiled)Exam favourite
2 × ⌈N ÷ T⌉
One A value and one B value per phase.
Total loads (tiled)Exam favourite
2N²⌈N ÷ T⌉ = 2N³ ÷ T when T divides N
Global traffic drops by a factor of T.
Arithmetic intensity
AI ≈ T ÷ 4 (float)
Plain matmul has 0.25. T = 16 gives 4.
Quiz 1 Q3: N = 1024, 16 × 16 tiles, loads per block
  1. 256 threads per block, 64 phases.
  2. Each thread loads 1 value of A and 1 of B per phase: 2 × 64 = 128.
  3. 256 × 128.
  4. 32,768 loads per block, 16 times fewer than 524,288

Two barriers per phase: Quiz 1 question 4

The tiled loop needs two __syncthreads() per phase. The first makes sure the whole tile is in shared memory before anyone reads it. The second makes sure everyone has finished reading before the next phase overwrites it.

quiz1_q4.cu
// Quiz 1 question 4: the tiled kernel WITHOUT barriers (wrong on purpose)__global__ void matMul(const float *A, const float *B, float *C, int N) {    __shared__ float tileA[16][16];    __shared__ float tileB[16][16];    int row = blockIdx.y * blockDim.y + threadIdx.y;    int col = blockIdx.x * blockDim.x + threadIdx.x;    float sum = 0.0f;    for (int k = 0; k < N / 16; k++) {        tileA[threadIdx.y][threadIdx.x] = A[row * N + (k * 16 + threadIdx.x)];        tileB[threadIdx.y][threadIdx.x] = B[(k * 16 + threadIdx.y) * N + col];        for (int t = 0; t < 16; t++)            sum += tileA[threadIdx.y][t] * tileB[t][threadIdx.x];    }    C[row * N + col] = sum;}
What each marked line does and why
  1. Line 9tileA[threadIdx.y][threadIdx.x] = A[row * N + (k * 16 + threadIdx.x)];Each thread writes one element of each tile.
  2. Line 12sum += tileA[threadIdx.y][t] * tileB[t][threadIdx.x];Thread (5, 10) reads tileA[10][t] for t = 0 to 15, including tileA[10][3], which thread (3, 10) writes. Without a barrier it may read before that write.
  3. Line 13}No barrier here either, so a fast thread can start the next phase and overwrite tileB while slower threads still read it.
Rakesh's worked solution
  1. Statement a: thread (5, 10) can start the inner loop before thread (5, 3) has written its value. With no barrier nothing stops it, so a can happen: true.
  2. Statement b: thread (3, 12) can overwrite tileB[3][12] for the next k while another thread is still reading it. Also possible: true.
  3. Both true: answer 3. The fix is the two barriers in matmul_tiled.cu
matmul_tiled.cu
#define T 16 // Works for any N: tiles that hang over the edge are padded with zeros__global__ void matMulTiled(const float *A, const float *B, float *C, int N) {    __shared__ float As[T][T];    __shared__ float Bs[T][T];    int tx = threadIdx.x, ty = threadIdx.y;    int row = blockIdx.y * T + ty;    int col = blockIdx.x * T + tx;    float sum = 0.0f;    for (int p = 0; p < (N + T - 1) / T; ++p) {        int ka = p * T + tx, kb = p * T + ty;        As[ty][tx] = (row < N && ka < N) ? A[row * N + ka] : 0.0f;        Bs[ty][tx] = (kb < N && col < N) ? B[kb * N + col] : 0.0f;        __syncthreads();                    // tile fully loaded before anyone reads it        for (int k = 0; k < T; ++k)            sum += As[ty][k] * Bs[k][tx];        __syncthreads();                    // everyone done before the next phase overwrites it    }    if (row < N && col < N) C[row * N + col] = sum;}
What each marked line does and why
  1. Line 4__global__ void matMulTiled(const float *A, const float *B, float *C, int N) {This version also handles N that is not a multiple of T.
  2. Line 11for (int p = 0; p < (N + T - 1) / T; ++p) {⌈N ÷ T⌉ phases.
  3. Line 13As[ty][tx] = (row < N && ka < N) ? A[row * N + ka] : 0.0f;Out of range elements are loaded as 0, so they add nothing to the sum.
  4. Line 15__syncthreads(); // tile fully loaded before anyone reads itBarrier 1: the tile must be complete before it is read (statement a).
  5. Line 18__syncthreads(); // everyone done before the next phase overwrites itBarrier 2: nobody may overwrite the tile while others still read it (statement b).
  6. Line 20if (row < N && col < N) C[row * N + col] = sum;Only threads inside C write their result.
Lesson 4 of 5

Ragged edges and tile size limits

Workbook 7.1: n = 5 with 4 × 4 tiles
  1. Phases and blocks per side: ⌈5 ÷ 4⌉ = 2, so 2 × 2 = 4 blocks.
  2. Threads 4 × 16 = 64, of which 64 − 25 = 39 do no output.
  3. Reads tiled 2 × 25 × 2 = 100, plain 2 × 125 = 250.
  4. 2.5 times fewer reads
Shared memory for two tiles
bytes = 2 × T² × 4
T = 32: 8 KB. 48 KB allows T up to 78.
Thread limit
T² ≤ 1024
So T ≤ 32 when each thread computes one output.

With T = 32 on an A100 (19.5 TFLOP/s, 1555 GB/s) a 4096 matrix still needs about 11 ms for memory and 7 ms for maths: memory bound. Faster kernels give each thread several outputs (chapter 8.3).

Lesson 5 of 5

From intuition to research

One idea, four depths

Instead of every student walking to the library for every book, a group borrows a shelf of books once, and everyone in the group reads them at the table.

Plain: 2N per thread, 2N³ total. Tiled: 2⌈N/T⌉ per thread, 2N³/T total. Two __syncthreads per phase. T ≤ 32 for one output per thread.

Register tiling: each thread computes a 4 × 4 or 8 × 8 block of C, which raises AI far beyond T/4. Double buffering loads the next tile while computing the current one.

CUTLASS splits the work in a hierarchy: thread block tiles, warp tiles, and tensor core fragments, with cp.async or TMA pipelines. cuBLAS reaches 80 to 90 percent of peak this way.
