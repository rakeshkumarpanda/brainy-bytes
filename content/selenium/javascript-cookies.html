Run JavaScript in the page

Sometimes a test needs something that no WebDriver command offers: read a value from the page state, scroll a box by a few pixels, or check how many items a list has without finding them all. executeScript sends a piece of JavaScript to the browser and returns the result to your code.

The browser runs your text as the body of a function. That is why every script that gives back a value starts with return, and why 1 + 1 on its own gives back nothing. The values you pass after the script arrive as arguments[0], arguments[1] and so on. A WebElement you pass in becomes the real DOM node inside the script.

Run JavaScript, pass an element in, and see what type comes back
RunScript.java
import java.util.List;import org.openqa.selenium.By;import org.openqa.selenium.JavascriptExecutor;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.chrome.ChromeDriver; public class RunScript {    static String type(Object o) { return o == null ? "null" : o.getClass().getSimpleName(); }     public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        JavascriptExecutor js = (JavascriptExecutor) driver;        driver.get("https://www.selenium.dev/selenium/web/javascriptPage.html");        for (String script : List.of("return 42", "return 4.5", "return 'hi'", "return [1, 'a']", "return {a: 1}", "return undefined", "return document.getElementById('dynamo')", "1 + 1")) {            System.out.println(script + " -> " + type(js.executeScript(script)));        }        WebElement dinner = driver.findElement(By.id("dynamo"));        System.out.println("arguments: " + js.executeScript("return arguments[0].innerText + ' / ' + arguments[1]", dinner, 7));        js.executeScript("arguments[0].click();", driver.findElement(By.id("updatediv")));        System.out.println("after js click: " + dinner.getText());        driver.quit();    }}
  1. The Java class of whatever came back.
  2. Every driver class implements JavascriptExecutor, so this cast is safe.
  3. Run the script as the body of a function and convert the result.
  4. Extra arguments arrive in the script as arguments[0], arguments[1] and so on.
  5. A click done by JavaScript. It skips the checks a real click makes.

The same JavaScript value lands as a different type in each language. Look at the three outputs side by side: a whole number is a Long in Java, an int in Python and a number in JavaScript. A DOM node comes back as a WebElement you can click. undefined and a missing return both become null or None.

Common mistake
A click done with JavaScript always works, even on a covered or disabled element, because it skips every check a user faces. A test that passes with a JavaScript click may be hiding a real bug. Use it only when you know why the real click cannot work.
Real world scenario: reading the cart total

A shop keeps the cart in a JavaScript object called window.cart. The test adds three items through the user interface, then reads return window.cart.items.length and return window.cart.total with one script each, and compares them with what the page shows. If the numbers match the state but not the screen, the bug is in the rendering.

Asynchronous scripts and the script timeout

Some answers only exist later: a timer, a network call, an animation that ends. executeAsyncScript adds a callback function as the last argument of your script. The command waits until your script calls it, and returns the value you pass to it. A script that returns a promise through plain executeScript is also waited for, because the W3C spec awaits a returned promise.

Asynchronous scripts, promises, the script timeout and a JavaScript error
AsyncScript.java
import java.time.Duration;import org.openqa.selenium.JavascriptException;import org.openqa.selenium.JavascriptExecutor;import org.openqa.selenium.ScriptTimeoutException;import org.openqa.selenium.WebDriver;import org.openqa.selenium.chrome.ChromeDriver; public class AsyncScript {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        JavascriptExecutor js = (JavascriptExecutor) driver;        driver.get("https://www.selenium.dev/selenium/web/blank.html");        Object waited = js.executeAsyncScript("const done = arguments[arguments.length - 1]; setTimeout(() => done('waited'), 300);");        System.out.println("async: " + waited);        System.out.println("promise: " + js.executeScript("return new Promise(r => setTimeout(() => r('from promise'), 200));"));        driver.manage().timeouts().scriptTimeout(Duration.ofMillis(200));        try {            js.executeAsyncScript("const done = arguments[arguments.length - 1]; setTimeout(() => done('late'), 500);");        } catch (ScriptTimeoutException e) {            System.out.println("too slow: " + e.getMessage().split("\n")[0]);        }        try {            js.executeScript("return nosuch.thing;");        } catch (JavascriptException e) {            System.out.println("broken script: " + e.getMessage().split("\n")[0]);        }        driver.quit();    }}
  1. Selenium adds a callback as the last argument. The command returns when the script calls it.
  2. A returned promise is awaited by the browser before it answers.
  3. How long a script may run. The default is 30 seconds.
  4. The callback came after 500 ms, the limit was 200 ms.
  5. A JavaScript error in the page becomes javascript error.

Cookies

A cookie is a small named value that a site stores in the browser and gets back with every request. Logins, language choices, consent banners and shopping carts usually live in cookies. Selenium can add, read and delete them, which lets a test skip a slow login screen or start with the banner already accepted.

Add, read, protect and delete cookies
Cookies.java
import org.openqa.selenium.Cookie;import org.openqa.selenium.InvalidCookieDomainException;import org.openqa.selenium.JavascriptExecutor;import org.openqa.selenium.WebDriver;import org.openqa.selenium.chrome.ChromeDriver; public class Cookies {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        try {            driver.manage().addCookie(new Cookie("key", "value"));        } catch (InvalidCookieDomainException e) {            System.out.println("before visiting: " + e.getMessage().split("\n")[0]);        }        driver.get("https://www.selenium.dev/selenium/web/blank.html");        driver.manage().addCookie(new Cookie("key", "value"));        Cookie c = driver.manage().getCookieNamed("key");        System.out.println("key: " + c.getValue() + ", domain " + c.getDomain() + ", sameSite " + c.getSameSite() + ", secure " + c.isSecure() + ", httpOnly " + c.isHttpOnly());        driver.manage().addCookie(new Cookie.Builder("foo", "bar").sameSite("Strict").build());        driver.manage().addCookie(new Cookie.Builder("secret", "s").isHttpOnly(true).build());        System.out.println("cookies: " + driver.manage().getCookies().size());        System.out.println("page script sees: " + ((JavascriptExecutor) driver).executeScript("return document.cookie"));        driver.manage().deleteCookieNamed("foo");        System.out.println("missing cookie: " + driver.manage().getCookieNamed("foo"));        driver.manage().deleteAllCookies();        System.out.println("after delete all: " + driver.manage().getCookies().size());        driver.quit();    }}
  1. The browser is still on an empty start page with no domain.
  2. Visit the domain first. A small page is enough.
  3. Read one cookie by name.
  4. The builder sets the other fields.
  5. httpOnly hides the cookie from page JavaScript.
  6. Asking for a cookie that is not there gives null, not an error.
  7. A clean start, for example before logging in as another user.

Four things in this run are worth remembering. A cookie can only be added for the domain the browser is on, so the first call failed with invalid cookie domain on the empty start page. A new cookie on this https page came back with secure true and sameSite Lax, which Chrome chose because the test did not say. The httpOnly cookie secret was stored but not shown to document.cookie. And a missing cookie is not an error in Java and Python, which return null and None, while JavaScript raises NoSuchCookieError.

FieldMeaning

domain, pathWhere the cookie is sent. They must match the current page.

httpOnlyHidden from page JavaScript.
sameSiteStrict, Lax or None. Whether the cookie goes with requests started by other sites.
expirySeconds since 1970. With no expiry the cookie lasts for the session.
Real world scenario: skip the login screen

Every test in a suite of 300 needs a logged in user. Logging in through the form takes 4 seconds. The suite logs in once through the API, gets the session cookie, and each test opens a small page on the domain, adds that cookie and goes straight to the page it tests. The form login is still tested once, in its own test.

One idea, four depths

Selenium can run JavaScript in the page and give you the answer, and it can read and set the cookies a site stores.

executeScript runs your text as a function body, passes arguments in and converts the return value. executeAsyncScript waits for a callback. Cookies need the browser to be on their domain first.

Execute Script and Execute Async Script are W3C commands that serialise arguments and results as JSON, with element references for DOM nodes. A returned promise is awaited. Cookie commands work on the cookies of the current browsing context domain.

BiDi adds script.evaluate and script.callFunction with realms and preload scripts, and storage.getCookies and storage.setCookie with partitions, which can set cookies without visiting the site first.
