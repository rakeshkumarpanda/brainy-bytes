Lesson 1 of 3

Windows and tabs

WebDriver does not tell windows and tabs apart. Each one has a window handle, a unique id that stays the same for the whole session. Commands always go to one window, the current one. When a link opens a new window, the browser shows it on screen, but the documentation points out that WebDriver does not follow. You must switch.

Follow a link into a new window, come back, open a new tab
Windows.java
import java.time.Duration;import org.openqa.selenium.By;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WindowType;import org.openqa.selenium.chrome.ChromeDriver;import org.openqa.selenium.support.ui.ExpectedConditions;import org.openqa.selenium.support.ui.WebDriverWait; public class Windows {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/xhtmlTest.html");        String original = driver.getWindowHandle();        System.out.println("windows at start: " + driver.getWindowHandles().size());        driver.findElement(By.name("windowTwo")).click();        new WebDriverWait(driver, Duration.ofSeconds(2)).until(ExpectedConditions.numberOfWindowsToBe(2));        for (String handle : driver.getWindowHandles()) {            if (!handle.equals(original)) driver.switchTo().window(handle);        }        System.out.println("new window: " + driver.getTitle());        driver.close();        driver.switchTo().window(original);        System.out.println("back to: " + driver.getTitle());        driver.switchTo().newWindow(WindowType.TAB);        driver.get("https://www.selenium.dev/selenium/web/resultPage.html");        System.out.println("new tab: " + driver.getTitle() + ", windows: " + driver.getWindowHandles().size());        driver.quit();    }}
  1. The id of the current window. It stays the same for the whole session.
  2. This link has target="_blank", so it opens a new window.
  3. Wait until the second window exists.
  4. Every open window, in the order they were opened.
  5. Switch to the one that is not the original.
  6. Close only this window.
  7. Switch back, or the next command fails with no such window.
  8. Selenium 4: open a new tab and switch to it in one step.
  9. Closes every window and tab at once.

Common mistake
After close() you are still pointing at the closed window. The documentation warns that the next command raises no such window. Always switch back to a handle you saved before.
Real world scenario: the payment pop up

A shop opens the card payment page of its bank in a new window. The test saves the shop window handle, clicks Pay, waits for two windows, switches to the bank window, fills in the test card and confirms. The bank window closes itself, so the test switches back to the saved shop handle and checks the order confirmation.

Lesson 2 of 3

Frames and iframes

An iframe puts a whole second document inside a page, often from another site: a payment form, a video player, a chat box or an editor. Selenium only sees the elements of the document it is pointing at, so the documentation explains that an element inside an iframe gives no such element until you switch into the frame.

Switch into an iframe three ways and back out
Frames.java
import org.openqa.selenium.By;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.chrome.ChromeDriver; public class Frames {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/iframes.html");        System.out.println("email boxes seen from the top: " + driver.findElements(By.id("email")).size());        WebElement frame = driver.findElement(By.id("iframe1"));        driver.switchTo().frame(frame);        System.out.println("by element: " + driver.findElement(By.id("email")).getAttribute("type"));        driver.switchTo().defaultContent();        driver.switchTo().frame("iframe1-name");        System.out.println("by name: " + driver.findElements(By.id("email")).size() + " email box");        driver.switchTo().defaultContent();        driver.switchTo().frame(0);        System.out.println("title inside the frame: " + driver.getTitle());        driver.switchTo().defaultContent();        System.out.println("heading: " + driver.findElement(By.id("iframe_page_heading")).getText());        driver.quit();    }}
  1. The form lives inside the iframe, so the top document sees none.
  2. 1. Switch with a WebElement: the most flexible way.
  3. Leave the frame: back to the top document.
  4. 2. Switch with the frame name or id.
  5. 3. Switch with an index: the first frame of the page.
  6. Get Title always reports the top level page, even from inside a frame.
  7. Outside elements are reachable again.

One detail in the output surprises people: inside the frame, Get Title still returned the title of the top page. Title belongs to the top level browsing context. Element commands, on the other hand, go to the frame you switched to.

Lesson 3 of 3

Alerts, confirms and prompts

JavaScript has three native pop ups, drawn by the browser and not by the page, so they cannot be found with locators. WebDriver has its own commands for them.

Pop upButtonsWhat you can do
alertOKRead the text, accept
confirmOK and CancelRead the text, accept or dismiss
promptOK and Cancel, plus a text boxRead the text, send keys, accept or dismiss. Sending keys replaces the placeholder text
Alert, confirm, prompt, a slow alert and one left open
Alerts.java
import java.time.Duration;import org.openqa.selenium.Alert;import org.openqa.selenium.By;import org.openqa.selenium.UnhandledAlertException;import org.openqa.selenium.WebDriver;import org.openqa.selenium.chrome.ChromeDriver;import org.openqa.selenium.support.ui.ExpectedConditions;import org.openqa.selenium.support.ui.WebDriverWait; public class Alerts {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(2));        driver.get("https://www.selenium.dev/selenium/web/alerts.html");        driver.findElement(By.id("alert")).click();        Alert alert = wait.until(ExpectedConditions.alertIsPresent());        System.out.println("alert: " + alert.getText());        alert.accept();        driver.findElement(By.id("confirm")).click();        Alert confirm = driver.switchTo().alert();        System.out.println("confirm: " + confirm.getText());        confirm.dismiss();        driver.findElement(By.id("prompt")).click();        Alert prompt = wait.until(ExpectedConditions.alertIsPresent());        prompt.sendKeys("Selenium");        prompt.accept();        System.out.println("page shows: " + driver.findElement(By.id("text")).getText());        driver.findElement(By.id("slow-alert")).click();        System.out.println("slow: " + wait.until(ExpectedConditions.alertIsPresent()).getText());        driver.switchTo().alert().accept();        driver.findElement(By.id("alert")).click();        try {            driver.getTitle();        } catch (UnhandledAlertException e) {            System.out.println("left open: " + e.getMessage().split("\n")[0]);        }        driver.quit();    }}

  2. Wait for the alert, then get a handle on it.
  3. Press OK.
  4. A confirm box: OK or Cancel.
  5. Switch to it without waiting, because it opens at once.
  6. Press Cancel.
  7. A prompt asks for text.
  8. Type the answer into the prompt.
  9. The page wrote our answer into a paragraph.
  10. This one opens 200 ms later.
  11. switchTo().alert() now would fail, so wait.
  12. Open one more alert and forget about it.
  13. Any command while an alert is open.
  14. The default behaviour dismisses it and reports an error.

Two lessons come out of this run. A slow alert needs a wait, exactly like a slow element: alertIsPresent in Java, alert_is_present in Python, until.alertIsPresent in JavaScript. And an alert you forget breaks the next command. The unhandledPromptBehavior capability decides what happens. Its default, dismiss and notify, closes the pop up and raises unexpected alert open, so the test fails at the line after the real cause.

unhandledPromptBehaviorWhat happens to a forgotten pop up
dismiss and notify (default)Dismissed, and the command raises unexpected alert open
accept and notifyAccepted, and the command raises unexpected alert open
dismissDismissed silently
acceptAccepted silently
ignoreLeft open, and the command raises unexpected alert open
Remember
Recent drivers dismiss beforeunload prompts, the "Leave site?" box, by default. Chapter 2.1 showed where unhandledPromptBehavior is set.
One idea, four depths

Selenium works in one window and one document at a time. To use a new tab, a frame or a pop up, you tell it to switch there first.

Windows have handles, frames are switched into by element, name or index, and alerts have their own accept, dismiss, text and send keys commands. Save the original handle and always switch back.

The W3C spec keeps a current top level browsing context and a current browsing context. Window commands change the first, frame commands the second. Title and window rect read the top level context, element commands use the current one.

BiDi models every window, tab and frame as a browsingContext with events for creation, navigation and user prompts. A test can then react to a pop up or a new tab the moment it opens, instead of polling for it.
