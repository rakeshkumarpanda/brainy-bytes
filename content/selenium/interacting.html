Click, type and clear

The documentation says there are only five basic commands for an element: click, send keys, clear, submit and select. Almost every form you will ever test needs nothing more.

CommandWorks onWatch out for
clickAny elementIt clicks the centre of the element. If something else is on top there, you get element click intercepted.
send keysText fields and other keyboard interactable elementsIt adds to the existing text. Clear first if you want to replace it.
clearEditable, resettable elements: text inputs and content editableReadonly and disabled inputs give invalid element state.
submitForm elementsIn Selenium 4 it runs a script, so the documentation recommends clicking the submit button instead.
selectselect and option elementsUse the Select class, covered below.
Fill in a form: clear, type, tick and click
FillForm.java
import java.time.Duration;import org.openqa.selenium.By;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.chrome.ChromeDriver; public class FillForm {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(2));        driver.get("https://www.selenium.dev/selenium/web/web-form.html");        WebElement text = driver.findElement(By.name("my-text"));        text.sendKeys("first try");        text.clear();        text.sendKeys("Selenium");        WebElement check2 = driver.findElement(By.id("my-check-2"));        System.out.println("check 2 before: " + check2.isSelected());        check2.click();        System.out.println("check 2 after: " + check2.isSelected());        driver.findElement(By.id("my-radio-2")).click();        System.out.println("radio 1 now: " + driver.findElement(By.id("my-radio-1")).isSelected());        driver.findElement(By.cssSelector("button")).click();        System.out.println(driver.findElement(By.id("message")).getText());        driver.quit();    }}
  1. As in chapter 1.3: let finds retry for up to 2 seconds, so the page after Submit has time to load.
  2. Element Send Keys: types into the box, adding to what is already there.
  3. Element Clear: empties the box.
  4. Type the real value.
  5. isSelected reads whether a checkbox is ticked.
  6. Element Click: ticks it, as a mouse click would.
  7. Clicking the second radio button unselects the first one.
  8. Click Submit. The documentation prefers this to the submit() method.

Two checks before every action

These commands copy what a user can do, so the driver does two things first. It scrolls the element into view if it is outside the viewport, lining up its bottom with the bottom of the viewport. Then it checks that the element is interactable: displayed, with a size, and able to receive the pointer or the keyboard. If not, you get element not interactable.

The three errors interactions give, made on purpose
InteractErrors.java
import org.openqa.selenium.By;import org.openqa.selenium.JavascriptExecutor;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebDriverException;import org.openqa.selenium.chrome.ChromeDriver; public class InteractErrors {    static void attempt(String what, Runnable step) {        try {            step.run();            System.out.println(what + ": ok");        } catch (WebDriverException e) {            System.out.println(what + ": " + e.getClass().getSimpleName() + ", " + e.getMessage().split("[:\n]")[0]);        }    }     public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/web-form.html");        attempt("type into disabled", () -> driver.findElement(By.name("my-disabled")).sendKeys("x"));        attempt("clear readonly", () -> driver.findElement(By.name("my-readonly")).clear());        ((JavascriptExecutor) driver).executeScript(            "const b = document.createElement('div'); b.textContent = 'We use cookies';"            + "b.style.cssText = 'position:fixed;left:0;right:0;bottom:0;height:400px;background:orange';"            + "document.body.appendChild(b);");        attempt("click under banner", () -> driver.findElement(By.cssSelector("button")).click());        driver.quit();    }}
  1. Run one step and report the error it raises, if any.
  2. A disabled input cannot take keyboard input.
  3. A readonly input cannot be reset.
  4. Add a cookie banner that covers the bottom of the page, as many real sites do.
  5. The banner sits over the centre of the button.

Each error tells you something different. element not interactable: the element cannot take this action at all, here because it is disabled. invalid element state: the element exists and is visible, but its state forbids the action, here readonly. element click intercepted: the element is fine, but something else lies on top of it.

Real world scenario: the cookie banner that broke every test

A shop adds a cookie consent banner on Monday. On Tuesday half the checkout tests fail with element click intercepted. Nothing was wrong with the checkout: the banner covered the bottom of every page. The fix was one step at the start of each test that clicks Accept on the banner, or sets the consent cookie before the first page loads. Reading the "Other element would receive the click" part of the message points straight at the cause.

Attribute or property

The three value lines show the difference that confuses many testers. An attribute is what the HTML says. A property is the live JavaScript value of the element right now. The text box has no value attribute in its HTML, so the DOM attribute is empty, but after typing, the value property is hello.

MethodReadsUse it for
get DOM attributeOnly the attribute in the HTMLChecking what the server sent, such as a data-test value
get DOM propertyOnly the live JavaScript propertyWhat is in a field now, whether a box is checked now
get attribute (classic)The property if there is one, otherwise the attribute. Selenium does this with a JavaScript atomOld code. Prefer the two precise methods.
In the exam
isDisplayed is not defined by the W3C spec, because deciding what a person can see covers too many cases. The documentation explains that Selenium runs a large JavaScript function that makes approximations. Treat it as a good guide, not a perfect one.

A <select> drop down needs a helper: the Select class in the support package. Wrap the element, then choose options by visible text, by value or by index.

Work with single and multiple select lists
Selects.java
import org.openqa.selenium.By;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.chrome.ChromeDriver;import org.openqa.selenium.support.ui.Select; public class Selects {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/formPage.html");        Select single = new Select(driver.findElement(By.name("selectomatic")));        System.out.println("options: " + single.getOptions().size());        single.selectByVisibleText("Four");        System.out.println("now: " + single.getFirstSelectedOption().getText());        single.selectByValue("two");        System.out.println("now: " + single.getFirstSelectedOption().getText());        single.selectByIndex(0);        System.out.println("now: " + single.getFirstSelectedOption().getText());        Select multi = new Select(driver.findElement(By.id("multi")));        System.out.println("multi starts with: " + multi.getAllSelectedOptions().size() + " selected");        multi.deselectByValue("eggs");        multi.selectByVisibleText("Ham");        for (WebElement o : multi.getAllSelectedOptions()) System.out.println("  selected: " + o.getText());        driver.quit();    }}
  1. Select lives in the support package.
  2. Wrap a select element in a Select object.
  3. getOptions lists every option element.
  4. Pick by the text the user sees.
  5. Pick by the value attribute.
  6. Pick by position, counting from 0.
  7. A select with the multiple attribute.
  8. Eggs and Sausages are selected in the HTML.
  9. Only multiple lists can deselect.

File upload

Selenium cannot touch the operating system file dialog. The documentation gives the way round it: send the full path of the file to the input type="file" element with send keys. No dialog appears, and the browser attaches the file as if the user had picked it.

Upload a file without the file dialog
Upload.java
import java.nio.file.Files;import java.nio.file.Path;import org.openqa.selenium.By;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.chrome.ChromeDriver; public class Upload {    public static void main(String[] args) throws Exception {        Path file = Files.writeString(Path.of("report.txt"), "quarterly numbers");        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/web-form.html");        WebElement input = driver.findElement(By.name("my-file"));        input.sendKeys(file.toAbsolutePath().toString());        System.out.println("browser shows: " + input.getDomProperty("value"));        driver.quit();    }}
  1. Make a small file to upload.
  2. The input with type="file".
  3. Send the full path. No dialog opens, the file is simply attached.
  4. Browsers hide the real folder and show a made up folder called fakepath.

The value the page sees starts with C:\fakepath\ on every operating system. Browsers hide the real folder from web pages for privacy, so this is expected, not a bug.

Remember
When the test runs on a Grid, the file must reach the remote machine. The Java, Python and JavaScript bindings handle this with a file detector that uploads the file to the node first. Chapter 6.1 shows it.
One idea, four depths

Click, type, clear and pick from a list. Then ask the element whether it is shown, enabled, ticked and what it says.

Before acting, the driver scrolls the element into view and checks it can be used. Errors say what was wrong: not interactable, invalid state or click intercepted. Attributes are the HTML, properties are the live value.

Element Click aims at the in view centre point and checks the topmost element there. Element Send Keys focuses the element and dispatches key events, so page JavaScript sees real typing. File inputs are a special case where send keys sets the file list.

Because Element Click needs the centre to be unobscured, sticky headers, overlays and animations cause most click failures. When you truly need pointer moves at exact offsets, the Actions API in chapter 4.3 skips these user like checks.
