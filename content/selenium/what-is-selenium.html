Lesson 1 of 4

What Selenium is

Think about the last time you bought a train ticket online. You opened a website, typed two station names, picked a date, clicked Search, chose a seat and paid. Every one of those steps is something a person does with a browser. Selenium is a set of free, open source tools that lets a program do the same steps in a real browser, as fast and as often as you like.

The official documentation puts it this way: Selenium is an umbrella project for a range of tools and libraries that enable and support the automation of web browsers. At its core it is a browser user agent library: a library your code calls to control a browser the way a user would. It can type into fields, choose from drop downs, tick boxes, click links, move the mouse and run JavaScript.

What people use Selenium forAn everyday example
Testing web applicationsBefore a bank releases a new version of its login page, a test opens the page in Chrome, Firefox and Edge, logs in with a test account and checks the balance appears.
Repetitive tasksA script logs into a supplier portal every morning at 6 and downloads the order report for the day.
Collecting data from pagesA researcher reads prices from a site that has no API. The docs ask you to check the terms of service of the site first, because some sites forbid it and some block Selenium.

Most people use it for the first one: automated testing. That is why most of this subject is about testing, but every command you learn works for any browser job.

Real world scenario: a shopping site on sale day

A shop changes its checkout page on Friday. On Saturday thousands of people buy during a sale. If the Pay button stopped working in Firefox, the shop loses money every minute. A Selenium test that runs on every change opens the checkout in each browser, fills the form and presses Pay, so the broken button is caught on Friday afternoon instead of by customers on Saturday.

One interface for every browser

Chrome, Firefox, Edge and Safari are built very differently inside, even when the pages look the same. A guiding principle of the project is one common interface for all major browsers. Selenium hides the differences, so the same few lines of your code run on each browser. You learn the commands once.

Common mistake
Selenium only controls the browser. It does not decide whether a test passed, it does not write reports and it does not give you Given, When, Then syntax. Those come from a test framework such as JUnit, pytest or Mocha. Chapter 5.1 joins the two.
Lesson 2 of 4

WebDriver, IDE and Grid

Selenium is not one tool. The documentation names three parts, and each one answers a different need.

PartWhat it isUse it when
WebDriverA library for your programming language plus a driver for each browser. Your code sends commands, the driver makes the browser carry them out.You write automated tests or scripts in Java, Python, JavaScript, C# or Ruby. This is what most of this subject teaches.
IDEA Chrome and Firefox extension that records what you do in the browser and plays it back as Selenium commands.You want a quick recording, or you are learning which command matches which action.
GridA server that spreads WebDriver sessions over many machines, browsers and operating systems.One machine is too slow, or you must test on browser and operating system pairs you do not have.

Four words you will hear every day

WordMeaning in the Selenium documentation
APIThe set of commands you use to control WebDriver, such as get, findElement and click.
LibraryThe code module that holds those commands for one language: a .jar file for Java, a pip package for Python, an npm package for JavaScript.
DriverThe program that controls one browser, such as chromedriver for Chrome and geckodriver for Firefox. Browser vendors write most of them. It usually runs on the same machine as the browser.
FrameworkAn extra library that supports a test suite: test runners such as JUnit, pytest or Mocha, or tools such as Cucumber.
  1. Your codeCalls the WebDriver API in your language.
  2. Language bindingThe Selenium library turns each call into a command.
  3. Driverchromedriver receives the command.
  4. BrowserChrome does the work and the answer travels back.

Chapter 1.2 opens up that chain and shows the real messages that travel along it.

One idea, four depths

Selenium is a remote control for a web browser. Your program presses the buttons, the browser does what a person would do.

WebDriver is a library plus a browser specific driver. The library sends commands, the driver executes them in the browser, and results come back. IDE records and replays, and Grid runs many sessions on many machines.

WebDriver is a client and server design: the language binding is the local end and the driver is the remote end of the W3C WebDriver protocol. Because the browser is driven through vendor automation APIs and not through code compiled into the app, the build you test is the build you ship.

The W3C protocol separates intent from mechanism. Ongoing work in WebDriver BiDi adds a two way event channel over WebSocket, so a client can listen to console logs, network traffic and DOM changes as they happen, which the request and response design of classic WebDriver cannot do.

Lesson 3 of 4

How Selenium grew

Selenium is more than twenty years old, and its history explains its design. The early versions ran JavaScript inside the page. That broke on many browser rules, so the project moved to driving the browser from outside, and in the end the browser makers agreed on a standard.

VersionReleasedWhat changed
Selenium 2.08 July 2011The WebDriver APIs became the heart of Selenium. Selenium 1 code still ran.
Selenium 3.013 October 2016The original Selenium Core implementation was removed. Every major browser vendor now ships its own driver.
W3C WebDriver5 June 2018WebDriver became a W3C Recommendation, a standard every browser can implement the same way.
Selenium 4.013 October 2021Support for the old JSON Wire Protocol was removed. Only the W3C protocol is used. Relative locators and a rebuilt Grid arrived.
In the exam
Interviewers like to ask what changed in Selenium 4. The short answer: W3C protocol only, so capabilities must follow the W3C names (browserVersion, platformName) or carry a vendor prefix such as goog:chromeOptions. Options classes replaced DesiredCapabilities, Java lost the findElementById style helpers, and relative locators and Grid 4 arrived. Selenium Manager came later, in 4.6.
Going deeper: Why driving from outside the page matters

A script running inside the page follows the same rules as the page. The browser same origin policy stops a page from one site touching another, so Selenium Core needed a proxy server to pretend every page came from the same place. Events made by JavaScript are also not the same as real ones: the Selenium 2 release notes describe how native events, sent at the operating system level, avoid browser quirks of JavaScript made events. WebDriver lets the browser vendor build the automation into the browser itself, which is why the vendors write the drivers today.

A first look at real code

Here is the smallest useful Selenium program, written three times. Pick your language with the buttons, then press Explain line by line to read what each line does. The output under the code is real: this page was built by running each program in Chrome.

A first look: open a page, read its title, close the browser
FirstLook.java
import org.openqa.selenium.WebDriver;import org.openqa.selenium.chrome.ChromeDriver; public class FirstLook {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/web-form.html");        System.out.println("Title: " + driver.getTitle());        System.out.println("URL: " + driver.getCurrentUrl());        driver.quit();    }}
  1. Bring in the WebDriver interface. Every browser driver in Java speaks through it.
  2. ChromeDriver is the class that starts and talks to Chrome.
  3. A plain Java class. Java runs the main method below.
  4. Start Chrome. Selenium Manager finds a matching chromedriver for you, then a new browser session begins.
  5. Ask the browser to open the page and wait until it has loaded.
  6. Ask the browser for the page title and print it.
  7. Ask which address the browser is showing now.
  8. End the session. This closes every window and stops the driver process.

main.js
const { Builder, Browser } = require('selenium-webdriver'); (async function firstLook() {  const driver = await new Builder().forBrowser(Browser.CHROME).build();  await driver.get('https://www.selenium.dev/selenium/web/web-form.html');  console.log('Title: ' + await driver.getTitle());  console.log('URL: ' + await driver.getCurrentUrl());  await driver.quit();})();
  1. Load the two pieces we need from the selenium-webdriver package.
  2. Every Selenium call in JavaScript returns a promise, so we work inside an async function.
  3. Build a driver for Chrome. Selenium Manager finds chromedriver and a session starts.
  4. Open the page and wait for it to load.
  5. Ask for the title. await waits for the browser to answer.
  6. Ask which address the browser shows.
  7. End the session and close the browser.

All three programs do the same four things: start a session, send the browser somewhere, ask it a question, and end the session. Every Selenium program you will ever write follows that shape. Chapter 1.3 grows it into the eight standard steps.

Remember
Always end with quit. If a program stops without it, the driver process and the browser keep running in the background and hold memory and ports. On a busy test machine those leftovers pile up quickly.
What happened when the Python version ran
  1. webdriver.Chrome() asked Selenium Manager for a chromedriver that matches the installed Chrome, started it, and sent it a New Session request.
  2. chromedriver launched Chrome with a fresh, empty profile and replied with a session id.
  3. get sent the address. The driver waited until the page reported it had finished loading, then answered.
  4. title and current_url were two more small questions, each with an answer.
  5. quit sent Delete Session. Chrome and chromedriver both closed.
