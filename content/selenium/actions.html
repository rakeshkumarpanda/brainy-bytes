Lesson 1 of 3

How actions work, and the mouse

Most tests only need click() and sendKeys() on an element. Some things a real user does cannot be said with those: a double click, a right click, hovering to open a menu, dragging a card to another column, holding Shift while typing, or turning the mouse wheel. The Actions API is the low level way to describe exactly what the input devices do.

You build a chain of steps and then call perform(). Only then is a request sent. The binding turns the chain into one POST /session/{id}/actions request. This is the body Python really sent for drag_and_drop in the run below, with the element ids shortened:

POST /session/{id}/actions
{"actions": [
  {"type": "pointer", "id": "mouse", "parameters": {"pointerType": "mouse"},
   "actions": [
     {"type": "pointerMove", "duration": 250, "x": 0, "y": 0, "origin": {"element-6066-...": "...e.3"}},
     {"type": "pointerDown", "duration": 0, "button": 0},
     {"type": "pointerMove", "duration": 250, "x": 0, "y": 0, "origin": {"element-6066-...": "...e.4"}},
     {"type": "pointerUp", "duration": 0, "button": 0}]},
  {"type": "key", "id": "key",
   "actions": [
     {"type": "pause", "duration": 0}, {"type": "pause", "duration": 0},
     {"type": "pause", "duration": 0}, {"type": "pause", "duration": 0}]}
]}

There is one list per input source: a pointer (mouse, pen or touch), a key source and a wheel. The W3C spec runs the lists together, one column at a time. Each column is called a tick. A tick lasts as long as the slowest action in it. Python filled the key list with pauses so that both lists have four ticks.

Double click, right click, hover, drag and drop, and move to a point
Mouse.java
import org.openqa.selenium.By;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.chrome.ChromeDriver;import org.openqa.selenium.interactions.Actions; public class Mouse {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/mouse_interaction.html");        WebElement box = driver.findElement(By.id("clickable"));        new Actions(driver).doubleClick(box).perform();        System.out.println("double: " + driver.findElement(By.id("click-status")).getText());        new Actions(driver).contextClick(box).perform();        System.out.println("right: " + driver.findElement(By.id("click-status")).getText());        new Actions(driver).moveToElement(driver.findElement(By.id("hover"))).perform();        System.out.println("hover: " + driver.findElement(By.id("move-status")).getText());        WebElement from = driver.findElement(By.id("draggable"));        WebElement to = driver.findElement(By.id("droppable"));        new Actions(driver).dragAndDrop(from, to).perform();        System.out.println("drag: " + driver.findElement(By.id("drop-status")).getText());        new Actions(driver).moveToLocation(8, 12).perform();        System.out.println("at: " + driver.findElement(By.id("absolute-location")).getText());        new Actions(driver).moveByOffset(13, 15).perform();        System.out.println("moved by: " + driver.findElement(By.id("absolute-location")).getText());        driver.quit();    }}
  1. Build a chain, then perform() sends it to the browser in one request.
  2. A right click.
  3. Move to the centre of the element. Nothing is clicked.
  4. Move to from, press, move to to, release.
  5. A point measured from the top left of the viewport.
  6. From wherever the pointer is now. The driver remembered it between chains.

Remember
A pointer move has a duration. In the bindings used here, Python uses 250 ms by default and JavaScript 100 ms. Some drag libraries ignore a move that takes 0 ms, so if a drag does nothing, try a chain with a longer move.
Real world scenario: a Kanban board

A task board lets a user drag a card from To do to Done. element.click() cannot express that. The test finds the card and the Done column, calls drag and drop, then checks that the card is now inside the Done column. When the board is built with a library that needs several mouse moves, the test builds the chain by hand: click and hold the card, move by an offset, move to the column, release.

Lesson 2 of 3

Keyboard actions

A key source sends keyDown and keyUp. sendKeys("abc") inside a chain becomes a key down and key up for every character. Special keys such as Shift, Control, Enter and Backspace are characters from a private Unicode range. Shift is U+E008, Control is U+E009 and Enter is U+E007, which you can see in the payload of the Shift plan in the animation above.

Hold Shift, select all with the right modifier, and type into an element
KeyboardActions.java
import org.openqa.selenium.By;import org.openqa.selenium.Keys;import org.openqa.selenium.Platform;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.chrome.ChromeDriver;import org.openqa.selenium.interactions.Actions; public class KeyboardActions {    public static void main(String[] args) {        WebDriver driver = new ChromeDriver();        driver.get("https://www.selenium.dev/selenium/web/single_text_input.html");        WebElement input = driver.findElement(By.id("textInput"));        new Actions(driver)            .keyDown(Keys.SHIFT)            .sendKeys("abc")            .keyUp(Keys.SHIFT)            .sendKeys("def")            .perform();        System.out.println("typed: " + input.getAttribute("value"));        Keys cmdCtrl = Platform.getCurrent().is(Platform.MAC) ? Keys.COMMAND : Keys.CONTROL;        new Actions(driver).keyDown(cmdCtrl).sendKeys("a").keyUp(cmdCtrl).sendKeys(Keys.BACK_SPACE).perform();        System.out.println("after select all and delete: '" + input.getAttribute("value") + "'");        new Actions(driver).sendKeys(input, "Selenium!").perform();        System.out.println("typed into element: " + input.getAttribute("value"));        driver.quit();    }}
  1. Press Shift and keep holding it.
  2. Goes to the element that has focus. The page focuses this box on load.
  3. Let go of Shift.
  4. Select all is Command A on a Mac and Control A elsewhere.
  5. Clicks the element first, then types.

Key methodWhat it does
keyDown(key)Press a key and keep it down. Meant for modifier keys.
keyUp(key)Release it. Forget this and the key stays down for the next chain.
sendKeys(text)Type into whatever has focus, one key down and key up per character.
sendKeys(element, text)Click the element first, then type. Java and Python only.
Common mistake
Actions type into the focused element. If nothing has focus, the keys go to the page body and the test seems to type into nothing. Element sendKeys focuses the element itself, which is why it is the better choice for plain typing.

Scroll wheel actions

The wheel source turns the mouse wheel. The documentation offers three cases: scroll an element into view, scroll by an amount, and scroll by an amount starting from a point or an element. The last one matters when only part of the page scrolls, such as a frame or a list with its own scroll bar.

Scroll to an element, by an amount, and inside a frame

Real world scenario: an endless product feed

A shop loads 20 more products each time the user reaches the bottom of the list. The test counts the products, scrolls the last one into view with the wheel, waits until the count grows, and repeats until it finds the product it needs. Scrolling with JavaScript would move the page without firing the wheel events some feeds listen for, so the wheel action is closer to a real user.

One idea, four depths

Actions let a test do what a person does with a mouse and keyboard: double click, right click, hover, drag, hold Shift and scroll.

Build a chain, then call perform(). Each device is an input source. The browser runs the steps tick by tick, and waits for the slowest step in each tick.

Perform Actions takes a list of input sources, each with a list of actions. Pointer moves have durations and origins: the viewport, the current pointer or an element centre. The driver keeps the input state between calls until Release Actions resets it.

Because a whole chain is one request, timing inside it is exact and does not suffer from network delay between steps. Moves with a duration are broken into several pointer events, which is what some drag and drop and drawing libraries need.
