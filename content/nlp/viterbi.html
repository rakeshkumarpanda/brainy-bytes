Lesson 1 of 4

Why brute force fails

Decoding means finding the tag sequence with the highest score. With q tags and T words, every position can take any tag, so there are qT sequences. For two words and two tags that is 4, fine by hand. For a 25 word newspaper sentence with the 45 Penn Treebank tags it is about 2 × 10⁴¹. A computer scoring a billion sequences a second would need far longer than the age of the universe.

The decoding objectiveExam favourite
T̂ = argmaxt₁ … tn ∏i P(wi | ti) · P(ti | ti−1)
The first factor is the emission, the second the transition. P(t₁ | t₀) means the start probability π(t₁).

Lesson 2 of 4

The Viterbi algorithm

The professor's summary: "If you have reached here, there is a best path until here. When you go further, use that best path. Do not start from scratch again." A road trip works the same way. To find the fastest route from Delhi to Chennai through Nagpur, you only need the fastest route to Nagpur. Any slower way of reaching Nagpur can be thrown away, since the rest of the trip does not care how you got there.

Viterbi recursionExam favourite
v1(j) = πj bj(w₁)     vt(j) = maxi vt−1(i) · aij · bj(wt)
vt(j) is the probability of the best tag path that ends in tag j after reading t words. Store the winning i as a back pointer.
Cost
O(T · q²) time,   O(T · q) memory
For each of T positions and q tags, compare q predecessors.

The model has three tags, N (noun), M (modal) and V (verb), and "they can fish" has two readings: they are able to fish (N M V) and they put fish in cans (N V N).

Going deeper: Proof that keeping one path per cell is safe

Take a best complete path whose tag at time t is j. Its score splits into [score of its first t steps] × [score of the rest]. Under the Markov assumption the rest depends on the past only through j.

Suppose its first t steps were not the best path into j. Swap them for the best one. The rest factor is unchanged and the first factor grows, so the total grows. That contradicts the path being best. So the best overall path always runs through the best partial path into each of its cells, and storing one number and one back pointer per cell loses nothing. This is Bellman's principle of optimality.

In the exam
Exam recipe. 1: write π, A and B as tables and check the rows. 2: if T ≤ 3 and q ≤ 2, enumerating all paths is fine, show every product. 3: otherwise fill a q × T table column by column, writing the winning predecessor in each cell. 4: back trace from the best last cell. 5: state the tag sequence and its probability. Strike out zero emissions first.

The forward algorithm and confidence

Replace max with a sum and the same table answers a different question: how likely is the sentence itself, adding up every way the tags could have produced it? This turns the HMM into a language model.

Forward recursionExam favourite
α1(j) = πj bj(w₁)     αt(j) = Σi αt−1(i) · aij · bj(wt)
αt(j) is the total probability of the first t words with tag j at position t.
Sentence probability and posterior
P(W) = Σj αT(j)     P(T | W) = P(W, T)P(W)
The posterior says how sure the model is of one tagging.
Problem G9: P(they can fish)
  1. α₁: N 0.21, M 0, V 0, as in Viterbi.
  2. α₂: only N is alive at t = 1, so sums equal maxima here. N 0.0084, M 0.084, V 0.0252.
  3. α₃(N) = (0.0084 × 0.2 + 0.084 × 0.1 + 0.0252 × 0.6) × 0.5 = (0.00168 + 0.0084 + 0.01512) × 0.5 = 0.0126.
  4. α₃(V) = (0.0084 × 0.4 + 0.084 × 0.9 + 0.0252 × 0.3) × 0.7 = (0.00336 + 0.0756 + 0.00756) × 0.7 = 0.060564. α₃(M) = 0.
  5. P(W) = 0.0126 + 0.060564 = 0.073164
  6. P(N M V | W) = 0.05292 ÷ 0.073164 = 0.7233

The posteriors add up to 1, and the order is the same in both columns, since every row was divided by the same P(W). Counting multiplications: brute force uses 27 × 5 = 135, Viterbi uses 3 + 18 + 18 = 39. The gap grows exponentially with length.

Going deeper: Posterior decoding and forward backward

A backward pass βt(i) = Σj aij bj(wt+1) βt+1(j) gives the probability of the rest of the sentence. Then P(ti = j | W) = αi(j) βi(j) ÷ P(W) for every word separately. Picking the best tag per word maximises the expected number of correct tags, while Viterbi maximises the chance that the whole sequence is right. The two can disagree. The same α and β give the soft counts used by Baum-Welch.

Lesson 4 of 4

Ties, trigrams and real taggers

What if two paths tie?

A student asked what happens if two sequences both score 0.45. The professor: "Very nice question. Then you need a tie breaking rule. The tagger may return either one. If you really want, you can write code that emits both." In practice exact ties are rare, since scores are products of many estimated numbers. Python's max keeps the first maximum it meets, so the order of the tag list decides. Principled options are the k best list (k best Viterbi) or per word posteriors from forward backward.

Going to a trigram HMM

Second order HMM
P(ti | ti−2, ti−1)     cost O(T · q³)
Viterbi now runs over pairs of tags. There are q³ transition parameters instead of q², so sparsity grows and interpolation is needed, exactly as for trigram language models.

The TnT tagger (Brants 2000) is a trigram HMM with interpolated smoothing and a suffix model for unknown words. It reaches about 96.7% on the Penn Treebank. The professor's warning when students asked for a trigram: "You can take it further, but you have to make sure the probabilities still sum to one."

Real world scenario: voice assistant transcripts

A speech recogniser hears "I scream" or "ice cream". Underneath, it runs the same Viterbi search over a much larger hidden state graph: sounds as hidden states, audio frames as observations. Without dynamic programming, real time speech recognition would be impossible. The posterior from the forward pass also tells the assistant when it is unsure and should ask again.

One idea, four depths

Fill a table one word at a time. In each box keep only the best way to get there and an arrow back. At the end, follow the arrows.

vt(j) = maxi vt−1(i) aij bj(wt). Replace max with sum for the forward algorithm and P(W). Cost T q² instead of qT.

Viterbi is max product dynamic programming on a chain. Its correctness is the principle of optimality under the Markov assumption. In log space it is a shortest path problem. Forward backward computes marginals, k best Viterbi gives ranked lists, and beam search prunes the trellis for large q.

The same semiring view (max product, sum product) covers CKY parsing, CRF inference and belief propagation on trees. Modern neural taggers still use Viterbi in their CRF output layer, and constrained decoding of language models reuses the same trellis ideas.
