Lesson 1 of 4

Information is surprise

In 1943 Alan Turing visited Bell Labs in New York, where Claude Shannon worked. They could not discuss their secret war work, but both were asking the same question: how can information and computation be described with mathematics? Turing had broken Enigma messages by tracking how each new clue changed the probability of a guess. Shannon turned the same idea into a theory of communication, published in 1948.

The professor's example: "Keep the flower on the table" tells you little that is new. "Keep the flower on the laptop" is surprising, so it tells you more. Information and surprise are the same quantity.

Surprisal of one outcomeExam favourite
I(x) = −log₂ p(x) = log₂ 1p(x)
Measured in bits. A certain event (p = 1) gives 0 bits. Every halving of the probability adds exactly 1 bit.
Units
log₂ → bits,   ln → nats,   log₁₀ → hartleys
1 nat = 1.4427 bits and 1 hartley = 3.3219 bits. Changing the base only rescales.
Why a logarithm? The proof
  1. We want a measure I(p) of the information in an outcome of probability p.
  2. Rule 1: a certain event tells us nothing, so I(1) = 0.
  3. Rule 2: rarer is more informative, so I falls as p rises.
  4. Rule 3: for independent events information adds, so I(p · q) = I(p) + I(q).
  5. The only continuous functions with f(pq) = f(p) + f(q) are f(p) = c log p. Rule 2 makes c negative.
  6. So I(p) = −log p, up to the choice of base.

Turing's weight of evidence

How a clue changes a probability
  1. Hypothesis: the U-boat is in square A. Before any clue, 100 squares are equally likely, so P = 0.01 and the uncertainty is log₂ 100 = 6.64 bits.
  2. A radio intercept is 20 times more likely if the boat is in A. Turing measured this as 10 log₁₀ 20 = 13.0 decibans.
  3. Bayes in odds form: posterior odds = prior odds × 20 = (0.01 ÷ 0.99) × 20 = 0.202.
  4. P(A | clue) = 0.202 ÷ 1.202 = 0.168
  5. If later clues narrow it to 5 equal squares, uncertainty falls to log₂ 5 = 2.32 bits. The clues gave 6.64 − 2.32 = 4.32 bits of information.
Remember
Because these measures are logarithms, independent pieces of evidence simply add. That is the reason Turing, Hartley and Shannon all used logs.
Lesson 2 of 4

Entropy: average surprise

Surprisal measures one outcome. Entropy measures a whole random variable: it is the surprisal you expect on average. A student in class spotted the link: it has the shape of an expected value, E[X] = Σ x p(x), with x replaced by log 1/p(x).

Shannon's entropyExam favourite
H(X) = −∑x p(x) log₂ p(x) = E[ −log₂ p(X) ]
The average uncertainty, the expected surprise, and the fewest bits per outcome any code can use on average. 0 log 0 is taken as 0.
BoundsExam favourite
0 ≤ H(X) ≤ log₂ n
H = 0 only when one outcome is certain. H = log₂ n only when all n outcomes are equally likely.

Class activity: entropy of a fair 8 sided die
  1. X is the face shown, with p(i) = 1/8 for i = 1 to 8.
  2. H(X) = −Σ (1/8) log₂(1/8). All eight terms are equal.
  3. So H = −8 × (1/8) × log₂(1/8) = −log₂(1/8).
  4. log₂(1/8) = −3, so H = 3 bits
  5. Meaning: each roll can be sent with a 3 digit binary code, 001, 010, … and 000 for 8.
Going deeper: Proofs of the bounds

Lower bound: each p is between 0 and 1, so log p ≤ 0 and every term −p log p ≥ 0. A sum of non negative terms is non negative. Upper bound: log is concave, so Jensen's inequality gives E[log Z] ≤ log E[Z]. Take Z = 1/p(X). Then H = E[log 1/p(X)] ≤ log E[1/p(X)] = log Σ p(x)/p(x) = log n, with equality only when every p(x) = 1/n.

Hartley (1928) had already measured a message of n symbols from an alphabet of s as n log s, assuming all symbols equally likely. Shannon's formula gives exactly log s per symbol in that case and less when the symbols are unequal.

What entropy does not measure

ABABABAB and AABBBABA both contain half A and half B, so their single symbol entropy is 1 bit each. Yet the first is perfectly predictable. Entropy looks only at how often each symbol occurs, not at their order. Language depends on history, so we also need entropy given the context, which is the next lesson and chapter 3.3.

Lesson 3 of 4

Entropy as the shortest code

How many bits are needed to send the numbers 1 to 8? A student said 0 to 7 needs 3 bits but 8 needs 4. What matters is the number of different values, not their labels: 8 values need 3 bits, with 8 written as 000. In general a fixed length code for n values needs ⌈log₂ n⌉ bits. For 26 letters that is 5, since 2⁴ = 16 is too few and 2⁵ = 32 is enough.

Fixed length code
bits = ⌈log₂ n⌉
20 amino acids need 5 bits, 100 words need 7, 50,000 words need 16.
Source coding theoremExam favourite
H(X) ≤ L̄ < H(X) + 1
No lossless code can average fewer than H bits per symbol. The best symbol by symbol code, Huffman, is within 1 bit.

When the probabilities are unequal, we do better than a fixed length code by giving frequent symbols short codes and rare symbols long ones, as Morse code does with E and T. Huffman's algorithm builds the best such code.

Huffman for a 0.4, b 0.3, c 0.2, d 0.1
  1. Entropy: H = 0.529 + 0.521 + 0.464 + 0.332 = 1.846 bits.
  2. Merge the two smallest, c and d, into a node of 0.3.
  3. Now a 0.4, b 0.3, cd 0.3. Merge b and cd into 0.6.
  4. Merge a and the 0.6 node into the root, 1.0.
  5. Read the codes: a = 0, b = 10, c = 110, d = 111. No code starts another, so decoding is never ambiguous.
  6. L̄ = 0.4 × 1 + 0.3 × 2 + 0.2 × 3 + 0.1 × 3 = 1.9 bits ≥ H = 1.846
Real world scenario: why a ZIP file is small

ZIP uses DEFLATE, which first replaces repeated strings with pointers back to an earlier copy (LZ77) and then gives frequent symbols short Huffman codes. Ordinary English text compresses to about 2 to 3 bits per character from the 8 bits of ASCII. Shannon's theorem says no lossless method can beat the true entropy of the source.

Lesson 4 of 4

Context and redundancy

Wherever q appears in English, the u after it is almost certain. The u carries almost no new information, so it is redundant. Shannon asked how much of English is like this.

How redundant is the u after q? (Brown)
  1. Without context, u is 2.24% of all characters, so seeing a u carries −log₂ 0.0224 = 5.48 bits.
  2. After q, Brown has 4,936 u out of 5,006 q, so P(u | q) = 0.986.
  3. Surprisal of u after q = −log₂ 0.986 = 0.020 bits
  4. The context q removed about 5.46 bits. The few exceptions are names such as Iraq and abbreviations such as Q.

Shannon's approximations to English

Without a computer, Shannon generated text from a book. For a second order letter sample he opened a random page, found the current letter and wrote down the letter that followed it. Each order uses one more letter of context.

One idea, four depths

A surprising word carries more information than an expected one. Entropy is the average surprise. Because English is full of patterns, about half of every message could be guessed.

Surprisal is −log₂ p and entropy H = −Σ p log₂ p lies between 0 and log₂ n. Huffman codes come within one bit of H. Shannon's n-th order approximations and the 50% redundancy estimate show how context lowers uncertainty.

For sequences the right quantity is the entropy rate lim H(Xn | X1 … Xn−1). Shannon's 1951 guessing experiments bounded English at roughly 0.6 to 1.3 bits per character with long context. Plug in estimates on finite corpora are biased low at high orders because contexts are seen once.

Modern language models are compressors: their cross entropy in bits per character is an upper bound on the entropy rate of text, and large models reach under 1 bit per character on English. Arithmetic coding with a neural model turns that prediction directly into compression, which is why prediction and compression are studied as one problem.
