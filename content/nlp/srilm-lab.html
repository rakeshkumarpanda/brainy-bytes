Lesson 1 of 3

SRILM in three commands

SRILM, the SRI Language Modeling toolkit, is a set of C++ libraries and command line programs for building and applying statistical language models. It has been used for speech recognition, tagging, segmentation and machine translation. The lecture used it to check every hand calculation of the activity.

StepCommandWhat it does
1. Countngram-count -text train.txt -order 2 -write train.countWrites every n-gram with its count
2. Estimatengram-count -text train.txt -order 2 -lm train.lm -addsmooth 0Turns counts into probabilities and backoff weights, saved as an ARPA file
3. Testngram -lm train.lm -ppl test.txt -debug 2Prints each word's probability, then logprob, ppl and ppl1

The training file has one sentence per line and no tags. The toolkit adds <s> and </s> to every line itself. Add -unk to both commands to keep an <unk> token and map unknown test words to it.

The count file and the ARPA file

The count file lists one n-gram per line with its count: <s> 5, <s> Sam 3, I 5, I am 2, the same numbers as chapter 4.1. The ARPA file, a format named after DARPA, starts with a header such as "ngram 1=8, ngram 2=14": 8 unigram entries including <s> and <unk>, and 14 different bigrams. Then each line holds a log₁₀ probability, the n-gram, and for lower orders a log₁₀ backoff weight.

Reading the test output

For every token SRILM prints p( word | context ) = [2gram] probability [ log10 ]. "[2gram]" means the bigram was found. "[1gram]" would mean it backed off to the unigram. Each sentence ends with two lines: the number of words and OOVs, then zeroprobs, logprob, ppl and ppl1. The last two lines do the same for the whole file.

Flags for smoothing
-addsmooth k,   -cdiscount d,   -wbdiscount,   -kndiscount,   -interpolate
Add-k, absolute discounting, Witten-Bell, Kneser-Ney, and making a method interpolated instead of backoff.

no flag = Good-Turing discounting with Katz backoff

Lesson 2 of 3

From the toy corpus to the Brown corpus

In-class activity 2 repeated the toy exercise on a real corpus. The Brown corpus has about one million words of American English published in 1961, spread over 15 genres: news, religion, lore, fiction, romance and others. The professor put it as "one class of text is fiction, another is fact". It is also tagged with parts of speech, which step 5 uses.

The data came split three ways: brown-train, brown-dev and brown-test. The task was to build unigram and bigram models with the commands from the tutorial, test on dev and test, report logprob, ppl, ppl1 and OOVs, then try smoothing. Asked whether Python was needed, the professor said no: the tutorial commands were enough and it was "hardly half an hour of work".

A sensible order of work
  1. Count and estimate on brown-train only. Never let dev or test text into the counts.
  2. Run an unsmoothed bigram on dev and read the OOV and zeroprob counts. They will be large.
  3. Add -unk so unknown words are scored, and a smoothing flag so unseen bigrams get probability.
  4. Compare methods and settings on dev. Pick the best.
  5. Run the chosen model once on test and report that number.
Remember
The professor asked students to do the coding activities with their own hands and not with a chatbot: "knowing is one thing, doing it with your hand is a different experience". The widgets in this chapter show the results so you can check yours, not replace them.

Assignment 2, question by question

This lesson rebuilds the submitted answers of assignment 2 as interactive charts. The numbers are the ones SRILM printed on the Brown data.

Question 1: why the unknown word breaks the model

<unk> never appears in the training data. With -addsmooth 0 nothing is smoothed, so P(<unk>) = 0 and its log is −∞, and bigrams that need it back off to zero as well. -addsmooth 0 means a δ of 0, and -unk keeps an <unk> word in the model and maps OOV test words to it. The fix used was -addsmooth 1 -unk: then log₁₀ P(<unk>) = −5.428, with 0 OOVs and 0 zeroprobs.

Every discounting method beats add-one, and Kneser-Ney is best. A large part of the gap comes from how much probability each method keeps for <unk>: add-one and Good-Turing give it about 10−5.4, Kneser-Ney about 10−0.9. Moving from bigram to trigram lowers perplexity for the four discounting methods and raises it for add-one.

Perplexity rises after each removal. Since the vocabulary and token count change, this is a trend and not a strict comparison. Punctuation and stop words are frequent and easy to predict, so they pull the average down. Without them only the harder content words remain, words that were never neighbours become adjacent, and the bigram context weakens.

Real world scenario: choosing a model for a support chatbot

A team must pick a language model to rank reply suggestions. They follow the assignment's recipe: train on old tickets, tune on last month's tickets, test once on this week's. They also keep the tokenisation fixed across all candidates, because the stop word experiment showed how much perplexity moves when the vocabulary changes.

One idea, four depths

A toolkit does the counting and the arithmetic, and you check that its numbers match what you can do by hand on a small example.

ngram-count builds counts and an ARPA model, ngram -ppl scores text. Read OOVs and zeroprobs before trusting a ppl. On Brown, Kneser-Ney beats Witten-Bell, absolute discounting, Good-Turing and add-one.

ARPA stores log₁₀ probabilities and backoff weights so that any n-gram probability is a short look up. The best method depends on how it shares mass with unseen events, which is visible in log P(<unk>). Grid search over k and λ is model selection on held out data.

Modern toolkits such as KenLM build modified Kneser-Ney models over billions of words with quantised tries. n-gram models are still used as fast first pass scorers, for data filtering, and as baselines when measuring how much a neural model really gains.
