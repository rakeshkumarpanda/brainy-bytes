Lesson 1 of 10

Programs that choose

Source: Python 3.14 tutorial sections 4.1 and 4.7, Language Reference 8.1 and 8.6, PCEP-30-02 section 2.1.

What it is
A conditional statement runs a block of code only when a condition is True. The condition is any expression, and Python asks "is it truthy?".
Why we need it
Real decisions depend on data: pass or fail, discount or no discount, access allowed or denied. Without conditions a program does the same thing every time.
How it works
Python works out the condition. If it is truthy, the indented block under it runs. If not, the block is skipped and Python moves to the next elif, the else, or the code after the statement.
Real world scenario: a traffic signal

A driver checks the signal: if it is red, stop. Otherwise if it is yellow, slow down. Otherwise (green), go. The driver checks in that order and does exactly one thing. That is an if, elif, else chain. Checking "green" first and then also checking "red" separately would be dangerous, and in code it gives the wrong answer too.

Rules for a chain
  1. A chain starts with one if, may have any number of elif, and may end with one else.
  2. Python checks the conditions from the top. The first truthy one wins and only its block runs.
  3. After a block runs, every remaining elif and else of the chain is skipped without being checked.
  4. Put the strictest condition first, for example score >= 90 before score >= 75

Bottom line: an elif chain is the usual choice. Use separate ifs for independent checks and keep nesting to two levels.

Lesson 6 of 10

match and case: pattern matching

What it is
match compares a value (the subject) with a list of patterns. The first pattern that fits runs its block. Patterns can check the shape of the data and pull values out of it at the same time.
Why we need it
Long elif chains that look inside lists, tuples and dicts are hard to read. match describes the shape you expect directly, like a picture of the data.
How it works
Python tries each case from the top. A literal must be equal, a name captures the value, [a, b] needs a sequence of length 2, *rest collects the remaining items, {"key": v} looks inside a dict, | means or, if adds a guard, and _ matches anything.

Common mistake
A plain name in a case is a capture, not a comparison. case RED: catches everything and binds it to RED. To compare with a constant, use a dotted name such as case Color.RED:.

The maths: boolean algebra

De Morgan lawsExam favourite
not (a and b) == (not a) or (not b), not (a or b) == (not a) and (not b)
Use them to simplify or flip a condition.
Number of pathsExam favourite
k independent if statements give up to 2k combinations
An elif chain with k conditions and an else has exactly k + 1 paths.
Distributive law
a and (b or c) == (a and b) or (a and c)
Like a × (b + c) = ab + ac in school algebra.
Worked example: flip "is a teenager"
  1. Teenager: 13 <= age and age <= 19.
  2. Not a teenager: not (13 <= age and age <= 19).
  3. De Morgan: not (13 <= age) or not (age <= 19).
  4. age < 13 or age > 19

Lesson 8 of 10

From beginner to expert

One idea, four depths

if is a fork in the road. Python checks a question and takes one path. elif adds more questions, else is the path when every answer was no.

Conditions use truthiness. A chain runs exactly one block. Combine with and, or, not, chained comparisons and in. Use the conditional expression for simple one line choices and match for data shaped choices.

match compiles to a sequence of type checks, length checks and lookups. Sequence patterns do not match str, bytes or bytearray, so case [a, b]: never fits "ab". Class patterns use __match_args__ for positional parts.

Branches cost time on real chips when they are hard to predict (branch misprediction), which is why sorted data can make an if inside a loop faster in compiled languages. In testing, branch coverage (every if both ways) and MC/DC coverage (each condition shown to matter, required for avionics software) measure how well conditions are tested.

Beginner
Write if, elif, else chains in the right order and test every branch.
Intermediate
Use truthiness, De Morgan, conditional expressions and match with captures and guards.
Expert
Explain how match is compiled, why sequence patterns skip strings, and design tests for branch and MC/DC coverage.
Real world scenario: an online shop checkout

At checkout, the shop decides delivery: if the order is above 499 rupees, delivery is free. Otherwise, if the customer is a member, it is 20 rupees. Otherwise it is 40. A coupon code is then matched: "WELCOME10", "FESTIVE", or anything else is "invalid code". The first part is an elif chain, the second is a natural match statement.

Chapter summary

  1. if runs its block only when the condition is truthy. else runs when it is not. elif adds more checks in between.
  2. In a chain Python checks from the top, runs the first truthy branch only, and skips the rest. Put the strictest test first.
  3. Falsy values: False, None, 0, 0.0, "", and empty collections. Everything else is truthy, even "0" and [0].
  4. Combine with and, or, not, 13 <= age <= 19 and day in ("Sat", "Sun"). day == "Sat" or "Sun" is always True.
  5. One line choices: x if cond else y. The walrus (n := len(data)) assigns inside a condition.
  6. match tries patterns from the top: literals, captures, _, |, [a, *rest], {"k": v}, Class(...), and guards with if.
  7. De Morgan: not (a and b) == not a or not b. k independent ifs give up to 2k paths to test.
