Data formats: saving and sharing data

Source: Python 3.14 documentation of csv, json, xml.etree.ElementTree, configparser, tomllib and pickle.

What it is
A data format is an agreed way to write data as text or bytes, so that another program (or the same one tomorrow) can read it back. Python's standard library reads and writes the common ones: CSV for tables, JSON for nested data, XML for documents with tags, INI and TOML for settings, and pickle for Python objects.
Why we need it
Objects live only while the program runs. To save them, send them over the network or share them with a spreadsheet, a web browser or a program in another language, they must become text or bytes in a format the other side understands.
How it works
Each module turns Python objects into text (writing, also called serializing or dumping) and text back into objects (reading, parsing or loading). The conversion is not always perfect, as the animation shows: types can change on the way.

Common mistake
Never parse XML from strangers with the standard library alone: specially made files can use huge amounts of memory (the "billion laughs" attack). Use the defusedxml package for untrusted XML.

pickle: Python objects as bytes

Download this program (.py)Save it, open it in any editor and run it with python3 pickle_data.py.
Common mistake
pickle can save almost any Python object, but pickle.loads can run any code the creator of the data chose, as the Evil class shows with a harmless print. Never unpickle data from the internet, uploads or anyone you do not fully trust. Use JSON for data you exchange.
Going deeper: Other binary formats

For big tables, columnar formats such as Parquet (with pandas or pyarrow) are much smaller and faster than CSV. For messages between services, Protocol Buffers or MessagePack are compact and typed. The struct module packs numbers into exact byte layouts for files and network protocols.

The maths: sizes and overheads

CSV file sizeExam favourite
bytes ≈ rows × (sum of value lengths + separators + 2 for \r\n)
1000 rows of 3 values of 6 characters: 1000 × (18 + 2 + 2) = 22,000 bytes.
JSON overhead for a list of dicts
every row repeats every key with quotes, a colon and a comma
Keys "name", "city", "age" add about 25 bytes to each row, often more than the data itself.
Base64 for binary data in JSON or XMLExam favourite
size out = 4 × ⌈n / 3⌉
A 300 KB image becomes 400 KB of text.
Unicode escapes
ensure_ascii=True writes a non ASCII letter as 6 characters
"Zürich" grows from 7 bytes (UTF-8) to 11 characters with \u00fc.
Sniffing a separator
pick the character that appears the same number of times on every line
"id;price" and "1;2,50": the ; appears once on each line, the comma does not.
Worked example: CSV or JSON for 10,000 orders with id, city and total?
  1. A CSV row like "1042,Paris,29.90\r\n" is 16 characters plus 2 line ending bytes, so 18 bytes: 10,000 rows is about 180 KB.
  2. A JSON row like {"id": 1042, "city": "Paris", "total": 29.9}, is about 46 bytes: about 460 KB.
  3. The keys repeat in every JSON row, so JSON is about 2.7 times bigger here.
  4. CSV ≈ 170 KB, JSON ≈ 460 KB, but JSON keeps types and nesting

From beginner to expert

One idea, four depths

Read and write CSV with DictReader and DictWriter (newline=""), and JSON with dump, load, dumps and loads.

Handle quoting and separators, write default= and object_hook for dates and sets, read XML with find, findall and iter, and settings with configparser and tomllib.

Choose a format by shape, types, size and safety, avoid pickle and raw XML with untrusted data, and validate JSON with a schema (jsonschema, pydantic).

Stream huge files (csv row by row, ET.iterparse, ijson), use columnar and binary formats (Parquet, Arrow, Protocol Buffers), and design versioned formats that stay readable for years.

Chapter summary

  1. CSV: csv.DictReader and DictWriter, open with newline="", values come back as strings, commas inside values get quotes.
  2. JSON: dumps and loads (strings), dump and load (files). Tuples become lists, keys become strings. default= and object_hook for other types.
  3. XML: ET.fromstring or parse, find, findall, iter and simple XPath. defusedxml for untrusted files.
  4. Settings: configparser for INI (getint, getboolean, fallback), tomllib to read TOML. Secrets in environment variables.
  5. pickle saves any object but loading can run code: only for trusted data.
