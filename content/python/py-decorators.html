Lesson 1 of 12

Decorators: add behaviour without changing the code

Source: Python 3.14 reference section 8.7 (function definitions), PEP 318, PEP 570, PEP 3102, the functools documentation and PCPP-32-101 block 1.

What it is
A decorator is a function that takes a function (or a class) and returns a replacement for it, usually a wrapper that does something extra before or after calling the original. Writing @decorator above a def applies it.
Why we need it
Many functions need the same extra jobs: logging, timing, checking arguments, retrying, caching, checking a login. Copying that code into every function is repetitive and easy to get wrong. A decorator writes the job once and adds it to any function with one line.
How it works
Functions are objects, so they can be passed to other functions and returned from them. @shout above def add runs add = shout(add) right after the def. shout returns a wrapper, a closure that remembers the original function and calls it inside.
Real world scenario: gift wrapping

A gift wrapped in paper is still the same gift, but now it comes with a ribbon and a card. Anyone who receives it opens the paper first, then reaches the gift. A decorator wraps a function the same way: callers reach the wrapper first, and the wrapper hands them on to the original.

A closure is a function that remembers the variables of the function it was made in, even after that function has returned. greet remembers greeting. That memory, stored in __closure__, is what lets a wrapper keep hold of the original function.

Common mistake
Without @wraps every decorated function is called "wrapper" and loses its docstring, which breaks help(), debuggers, logging and frameworks that look up functions by name (Flask uses the name for its routes). Always put @wraps(func) on the wrapper.

Decorators with arguments

Download this program (.py)Save it, open it in any editor and run it with python3 factory.py.
Reading @repeat(3)
  1. repeat(3) runs first and returns decorate, which remembers times = 3.
  2. decorate(wave) runs and returns wrapper, which remembers times and func.
  3. The name wave now points to wrapper.
  4. Every call wave(...) runs wrapper(...), which calls the original three times.
Common mistake
A decorator with arguments has three nested functions: the factory (settings), the decorator (the function) and the wrapper (the call). Forgetting the brackets, @retry instead of @retry(3), passes the function as attempts and fails in a confusing way.

Decorators are applied from the bottom up (nearest the def first) and run from the top down at call time. @a then @b above def f means f = a(b(f)).

The maths: memoisation and backoff

Calls of plain recursive FibonacciExam favourite
C(n) = 1 + C(n − 1) + C(n − 2), C(0) = C(1) = 1, so C(n) = 2F(n + 1) − 1
fib(25): 2 × 121,393 − 1 = 242,785 calls, as the program counted.
Calls with @cacheExam favourite
each n from 0 to N is computed once: N + 1 misses
fib(25): 26 misses and 23 hits.
Growth
F(n) ≈ φn / √5, φ = (1 + √5) / 2 ≈ 1.618
Plain recursion is exponential, O(φn). The cached version is linear, O(n).
Exponential backoff
wait before retry k = base × 2k, total for n retries = base(2n − 1)
base 1 s, 4 retries: 1 + 2 + 4 + 8 = 15 s.
LRU hit rate
hit rate = hits / (hits + misses)
square with maxsize 2 on 1, 2, 1, 3, 2: 1 hit, 4 misses, 20 %.
Worked example: why fib(25) with @cache has 23 hits
  1. fib(25) misses and calls fib(24), which misses and calls fib(23), and so on down to fib(1): 25 misses on the way down.
  2. Back in fib(2), the second call fib(0) has never been seen: one more miss, 26 in total.
  3. Back in fib(3) up to fib(25), each second call fib(n − 2) finds its answer already cached: 23 hits.
  4. cache_info() reports hits=23, misses=26

From beginner to expert

One idea, four depths

Know that @decorator above a def means f = decorator(f), and use built in decorators such as @cache.

Write decorators with *args and **kwargs and @wraps, decorators that keep state, decorators with arguments, and know the order of stacked decorators.

Write class decorators and classes used as decorators, decorate methods safely, combine positional only and keyword only parameters, and use caching with a clear idea of when results may go stale.

Decorators are just expressions evaluated at definition time (any expression since PEP 614). To decorate methods with a class based decorator, implement the descriptor protocol (__get__) so it binds self. Type checkers keep the signature of a wrapper with ParamSpec and Concatenate (PEP 612).

Beginner
Use @decorators and write a simple wrapper with @wraps.
Intermediate
Write decorators with arguments, with state, and stack them correctly.
Expert
Write class decorators, descriptor aware decorators and typed decorators with ParamSpec.

Lesson 12 of 12

Chapter summary

  1. Parameters: positional only before /, keyword only after * or *args, *args is a tuple, **kwargs is a dict. At a call, * and ** unpack.
  2. Functions are objects: name them, store them, pass them, return them. A closure remembers the variables of the function that made it.
  3. @d above def f means f = d(f). A decorator usually returns a wrapper(*args, **kwargs) that calls the original.
  4. Always use @functools.wraps(func) on the wrapper to keep the name, docstring and __wrapped__.
  5. Decorators with arguments have three levels: factory(settings), decorator(func), wrapper(*args).
  6. Stacked decorators are applied bottom up and run top down: @a @b def f is a(b(f)).
  7. Decorators can keep state, take classes, or be classes with __call__. @cache and @lru_cache memoise pure functions.
