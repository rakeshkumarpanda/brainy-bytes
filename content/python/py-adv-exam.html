Find the bug

Download this program (.py)Save it, open it in any editor and run it with python3 bug_hunt.py.
Seven bugs examiners and reviewers love
  1. Bug 1. The wrapper calls fn but never returns its result, so every decorated function returns None. Write return fn(*args, **kwargs) (1.2).
  2. Bug 2. A generator can be used only once. The second sum sees nothing. Use a list, or make a new generator (2.1).
  3. Bug 3. Defining __eq__ removes __hash__. Add __hash__ based on the same fields, or use @dataclass(frozen=True) (1.1).
  4. Bug 4. items = [] in the class body is ONE list shared by every Basket. Make it in __init__ with self.items = [] (1.3).
  5. Bug 5. except Exception: pass hides the error, and the caller gets None without knowing why. Catch the exact error and log it or raise your own (1.4, 3.3).
  6. Bug 6. __exit__ returning True swallows every exception, so the program goes on with total missing. Return True only for the errors you really handle (2.3).
  7. Bug 7. In a normal string \b is the backspace character, so the pattern never matches. Always write patterns as raw strings r"..." (6.1).

Chapter summary

  1. PCPP1 (PCPP-32-101) as listed by training providers: 45 questions, 65 minutes, 70 %. Check the official page before you book.
  2. Objects: __eq__ needs a matching __hash__, return NotImplemented for unknown types, super() follows the MRO, wraps keeps the name.
  3. Iteration: generators run only on next, can be used once, send resumes a yield, yield from passes values and the return value.
  4. Context and errors: __exit__ returning True swallows the error, raise from sets __cause__, except* splits exception groups.
  5. Library: raw strings for regex, json changes tuples and keys, csv gives strings, deque maxlen drops from the other end, sqlite3 needs commit.
  6. Technique: about 87 seconds per question, trace on paper, aim for 85 % in practice.
