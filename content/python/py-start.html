Lesson 1 of 11

What a program is

Source: Python 3.14 tutorial, chapters 1 to 3, and the PCEP-30-02 syllabus, section 1.1.

A computer is very fast but it has no common sense. It does exactly what it is told, one small step at a time. A program is a list of those steps, written down so that the computer can follow them.

Real world scenario: a recipe in the kitchen

A recipe says: boil water, add rice, wait 15 minutes, switch off the stove. A cook follows the steps in order. If a step is missing ("add rice" is not written), the rice never goes in. If a step is wrong ("wait 150 minutes"), the cook still follows it and the rice burns. A computer is a cook who follows every line exactly, even a silly one.

What it is
A program is a set of instructions written in a programming language. Python is one such language. Its instructions look close to plain English, for example print("Hello").
Why we need it
The chip inside a computer only understands machine code: long rows of 0s and 1s. People cannot write large programs in 0s and 1s without mistakes, so we write in a language people can read, and let a tool translate it.
How it works
You write the steps in a text file that ends in .py. A program called the Python interpreter reads the file, checks it, translates it, and runs it line by line from the top.

Three words every programmer uses

WordMeaningIn everyday language
LexisThe words and symbols a language allows (print, if, +, "text")The vocabulary of English
SyntaxThe grammar rules: how words may be put together"I rice eat" breaks English grammar
SemanticsWhat a correct sentence means"The stone ate the rice" has good grammar but makes no sense

Python is popular because its lexis is small, its syntax is clean, and the same code runs on Windows, macOS, Linux, phones and even inside a web browser. It is used for websites (Instagram is built on Django), data science, artificial intelligence, test automation and small scripts that save people hours of boring work.

Compiler, interpreter and how Python runs your file

Code written by people must be translated into something the machine can run. There are two classic ways to translate.

Two ways to translate a program
CompilerInterpreter
How it worksTranslates the whole program first into a separate machine code file, then you run that fileReads the program and runs it straight away, statement by statement
LikeTranslating a full book into Hindi, printing it, then reading itA live interpreter at a meeting who translates each sentence as it is spoken
When errors showMost mistakes are found before anything runsA mistake is found when Python reaches that line (except grammar mistakes, see below)
SpeedUsually faster to runUsually slower, but you see results at once
ExamplesC, C++, Go, RustPython, JavaScript in old browsers, shell scripts

Bottom line: CPython, the standard Python, does a bit of both. It first compiles your file into bytecode (simple instructions for a virtual machine), then its interpreter loop runs that bytecode. Because the compile step comes first, a grammar mistake anywhere in the file stops the program before line 1 runs.

What happens when you type python3 hello.py
  1. Python opens hello.py and reads the text.
  2. It splits the text into tokens (words, numbers, symbols) and checks the grammar. A grammar mistake here gives a SyntaxError and nothing runs.
  3. It compiles the grammar tree into bytecode, small instructions such as LOAD_CONST and CALL.
  4. The Python virtual machine runs the bytecode from top to bottom. print() sends text to the screen.
  5. source code (.py) → tokens → syntax tree → bytecode → run → output
Remember
Python is often called an interpreted language, but CPython does compile your code to bytecode first. Both words are partly true. The Advanced Python step 7 chapter "How Python runs" opens every one of these stages with an animation.

Install Python and run your first program

You can try every example on this page with the Run button, which runs real Python in your browser. To work on your own computer, install Python once.

Install Python
  1. Go to python.org/downloads and download the newest Python 3 for your system (Windows, macOS or Linux). On Linux it is often already installed.
  2. On Windows, tick "Add python.exe to PATH" in the installer. This lets you type python in any terminal.
  3. Open a terminal (Command Prompt, PowerShell or Terminal) and type python3 --version (on Windows: python --version or py --version).
  4. If you see a version such as Python 3.14.0, Python is ready

print(): showing results on the screen

What it is
print() is a built in function. A function is a named action. You give it values inside the round brackets (called arguments) and it writes them on the screen.
Why we need it
A program that shows nothing is useless to a person. print() is how a program talks back: results, messages, and while learning, what is happening inside.
How it works
print() turns each argument into text with str(), joins the texts with sep (a space unless you say otherwise), adds end (a new line unless you say otherwise), and writes the result.
The full form of print()Exam favourite
print(*values, sep=" ", end="\n", file=sys.stdout, flush=False)
values: any number of values. sep: text between them. end: text after the last one. file: where to write. flush: write at once.
Characters written by one print()Exam favourite
N = ∑ len(str(vi)) + (n − 1) · len(sep) + len(end)
n values v1 to vn. There are n − 1 gaps between n values.

Keywords, statements, comments and indentation

A Python program is made of statements, normally one per line. Some words have a fixed meaning in the language. They are called keywords and you cannot use them as names for your own things.

Common mistake
Python uses indentation where many languages use curly brackets. Mixing tabs and spaces, or using 3 spaces on one line and 4 on the next, gives IndentationError. PEP 8 says: always 4 spaces.
Going deeper: why indentation instead of brackets

Guido van Rossum took the idea from the ABC language. People already indent code to read it, so making the indentation itself the rule removes a whole class of bugs where the brackets say one thing and the indentation says another. The tokenizer turns a deeper indent into an INDENT token and a shallower one into DEDENT tokens, so the parser sees blocks just as clearly as with brackets.

Three kinds of errors

Everyone makes mistakes in code, even experts, every day. What matters is knowing which kind of mistake you made, because each kind is found in a different way.

KindWhen Python finds itExampleWhat you see

How to read a traceback
  1. Read the last line first. It names the error and gives a short reason, for example ZeroDivisionError: division by zero.
  2. Look at the line just above it. It shows the file name, the line number and the code that failed.
  3. Go to that line in your editor and ask: which value was not what I expected?
  4. last line = what went wrong, line number = where

The maths: counting what print() writes

Being exact about small things is the habit that makes a good programmer. Here we count exactly how many characters a print() writes.

Characters from one print()Exam favourite
N = L + (n − 1) · s + e
L = total length of all values as text, n = number of values, s = len(sep), e = len(end).
Bytes in a plain English text file
bytes = characters
Each English letter, digit, space and new line is 1 byte in UTF-8. Letters from other scripts can take 2 to 4 bytes (Core 3.1).
Worked example: print("Total", 3, "apples")
  1. The values as text are "Total" (5), "3" (1) and "apples" (6). L = 5 + 1 + 6 = 12.
  2. There are n = 3 values, so n − 1 = 2 gaps. sep is one space, s = 1, so the gaps add 2.
  3. end is one new line, e = 1.
  4. N = 12 + 2 × 1 + 1 = 15 characters

Worked example: print("2026", "11", "07", sep="-", end="")
  1. L = 4 + 2 + 2 = 8.
  2. Two gaps of one dash: 2.
  3. end is empty: 0.
  4. N = 8 + 2 + 0 = 10, the text 2026-11-07
Lesson 9 of 11

From beginner to expert

One idea, four depths

A program is a recipe for the computer. Python reads your recipe from top to bottom and does each step. print() is how it shows you the result.

CPython compiles a .py file to bytecode and runs it on a stack based virtual machine. Grammar is checked for the whole file first (SyntaxError), while exceptions happen only when a line runs. print() calls str() on each argument and writes sep.join(texts) + end to sys.stdout.

sys.stdout is a buffered text stream. When it is a terminal it is line buffered, so print("x", end="") may not appear until a new line is written or flush=True is passed. When output goes to a file or a pipe it is block buffered, which is why progress messages sometimes appear late in logs.

The grammar of Python is a PEG grammar (PEP 617, since 3.9), and the tokenizer produces INDENT and DEDENT tokens from leading white space. Error messages improved a lot in 3.10 to 3.14 ("Did you mean: price?"), based on research on helping novices read errors.

Beginner
Write and run a .py file, use print() with sep and end, and read the last line of a traceback.
Intermediate
Know the difference between compile time and run time, follow PEP 8 names, and use the REPL to test small ideas.
Expert
Explain bytecode, output buffering and flush, and why a SyntaxError on line 50 stops line 1 from running.
Real world scenario: a shop bill printed at the counter

The billing machine at a shop runs a small program. It prints the shop name, then each item and price with a fixed gap (that is sep), then a line of dashes and the total (each print ends with a new line, that is end). If the programmer types + instead of * for quantity times price, the machine prints a wrong bill with no error. That is a logic error, and it is why shops test the machine with a known bill before using it.

Chapter summary

  1. A program is a list of exact instructions. Python is a programming language with a small, readable vocabulary (lexis) and clear grammar (syntax).
  2. A compiler translates the whole program first. An interpreter runs it statement by statement. CPython compiles to bytecode, then interprets the bytecode.
  3. Run Python in the REPL (>>>) for quick tests, or save a .py file and run python3 file.py.
  4. print() calls str() on each value, puts sep (a space) between them and end (a new line) after them. N = L + (n − 1)s + e characters.
  5. Python 3.14 has 35 keywords and 4 soft keywords. Comments start with #. Blocks are shown by indentation of 4 spaces.
  6. Syntax errors stop the program before it starts. Runtime errors stop it at the bad line. Logic errors give wrong answers silently.
  7. PEP 8 is the style guide (snake_case, 4 spaces, 79 characters). PEP 20 is the Zen of Python (import this).
