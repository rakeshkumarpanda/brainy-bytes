Lesson 1 of 10

The right container for the job

Source: Python 3.14 documentation of collections, heapq and bisect.

What it is
The collections module adds containers that do one job better than a plain list or dict: Counter for counting, deque for queues, namedtuple for small records, OrderedDict and ChainMap for special dicts, and defaultdict for missing keys. heapq turns a list into a priority queue and bisect searches and inserts in a sorted list.
Why we need it
Chapter 4.1 showed that the wrong container makes code slow: list.pop(0) is O(n), finding the smallest of a changing list again and again is O(n) each time, and searching a sorted list item by item wastes its order. These tools make those jobs O(1) or O(log n), and the code shorter and clearer too.
How it works
Each one is written in C and tested by millions of programs. You import it and use it like a normal list or dict: deque has append and pop at both ends, Counter is a dict of counts, heapq is a set of functions that keep any list in heap order, and bisect uses binary search.

Remember
Counter is a dict subclass, so everything a dict can do works too. Unlike a dict, a missing key gives 0 instead of KeyError. most_common(k) returns the k most common items with their counts, and items with the same count keep the order in which they were first seen.

deque: a fast queue with two ends

Download this program (.py)Save it, open it in any editor and run it with python3 queues.py.
In the exam
A deque (say "deck") is a double ended queue. Adding and removing at either end is O(1). A list does the same at the end, but list.insert(0, x) and list.pop(0) must shift every other item, which is O(n).
Remember
Breadth first search (BFS) always takes the oldest path from the front of the queue and adds new paths at the back. That is why it finds the path with the fewest steps first, and why it needs a deque, not a list.

In the exam
Since Python 3.7 every dict keeps insertion order. OrderedDict still has extras: move_to_end(key), popitem(last=False) for the oldest item, and == compares order too. That makes it the classic tool for an LRU cache.
Remember
ChainMap does not copy anything. It searches the dicts one after another, so a change to user is seen at once. Writes go to the first dict only. It is how Python looks up names: locals, then globals, then builtins.

heapq: a priority queue in a list

Download this program (.py)Save it, open it in any editor and run it with python3 heaps.py.
In the exam
A heap is a list where every item is smaller than or equal to its two children: heap[i] ≤ heap[2i + 1] and heap[i] ≤ heap[2i + 2]. So heap[0] is always the smallest. The rest is NOT sorted. heappush and heappop are O(log n), heapify is O(n), and looking at heap[0] is O(1).
Remember
Put tuples like (priority, count, task) in a heap. Tuples compare item by item, so the priority decides first. The count (from itertools.count()) breaks ties, so two tasks with the same priority never have to be compared, which would fail for objects that cannot be compared.

Bottom line: a heap is the best all round choice when items keep arriving and you keep taking the most urgent one.

FunctionReturns
bisect_left(a, x)The first index where x could go: before any equal items
bisect_right(a, x) (also bisect)The index after the last item equal to x
insort(a, x)Puts x into a, keeping it sorted (search O(log n), insert O(n))
key=func (3.10+)Compare func(item) instead of the item, without building a new list
Remember
bisect_right(a, x) − bisect_left(a, x) is how many times x appears. Counting values in a range or looking up which band a number falls into (grades, tax brackets, prices) are classic uses.
Going deeper: Sorted containers for big data

insort is O(n) because a list must shift items. For millions of inserts the third party package sortedcontainers (SortedList) keeps O(log n) inserts. In the standard library, a heap is the tool when you only ever need the smallest item.

The maths: heap indexes, heights and costs

Heap indexesExam favourite
parent(i) = (i − 1) // 2, children 2i + 1 and 2i + 2
Index 4 has parent 1 and children 9 and 10.
Height of a heapExam favourite
h = ⌊log2 n⌋
1,000,000 items: 19 levels below the top, so a push makes at most 19 swaps.
heapify is O(n)
work ≤ ∑ (n / 2h+1) · h < n
Most items are near the bottom and move only a little, so the total is less than n swaps.
Top k with a heapExam favourite
O(n log k) instead of O(n log n) for a full sort
k = 10 of n = 106: about 3.3 × 106 steps against 2 × 107.
Binary search
comparisons ≤ ⌈log2(n + 1)⌉
1000 sorted items: at most 10 comparisons.
Front removals from a list
shifts = (n − 1) + (n − 2) + ... + 1 = n(n − 1) / 2
Emptying 10,000 items with pop(0): about 5 × 107 shifts. With deque.popleft: 0.
Worked example: the top 3 of 1,000,000 scores
  1. Sorting: n log2 n ≈ 106 × 20 = 2 × 107 comparisons.
  2. heapq.nlargest(3, scores) keeps a heap of only 3 items while it reads all the scores.
  3. Each score costs at most log2 3 ≈ 1.6 steps: about 1.6 × 106 in total.
  4. Over 10 times less work, and only 3 items in memory

Chapter summary

  1. Counter counts in one line, gives 0 for missing keys, and supports most_common, total and + - & |.
  2. deque adds and removes at both ends in O(1). Use it for queues, BFS and (with maxlen) the last n items.
  3. namedtuple gives read only records with names. OrderedDict has move_to_end and popitem(last=False) for LRU caches. ChainMap layers dicts.
  4. heapq keeps a list in heap order: heap[0] is the smallest, push and pop are O(log n), heapify is O(n). Tuples set priorities.
  5. bisect finds positions in a sorted list in O(log n): bisect_left, bisect_right, insort and key=.
