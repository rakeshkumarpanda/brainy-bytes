Lesson 1 of 11

What Flask is

Source: Flask 3.1 documentation (quickstart, API, testing, deploying), Jinja 3.1 template designer documentation and PEP 3333 (WSGI).

What it is
Flask is a small web framework for Python. You write normal functions and tell Flask which URL each one answers with @app.route. Flask gives every function the request (the URL, the form, the JSON, the cookies) and turns what it returns into an HTTP response. It comes with Jinja templates for HTML pages and a test client.
Why we need it
With only http.server you would parse paths, read bodies, set headers, escape HTML and keep sessions yourself, for every page. That is slow to write and easy to get wrong, for example by letting users inject scripts.
How it works
Flask does the repeated work and stays small: routing, request and response objects, templates with automatic escaping, signed session cookies and error handlers. Everything else (database, login, forms) you add with plain Python or extensions, only when you need it. That is why it is called a microframework.

Remember
Build links with url_for("hello", name="Bob") and never by hand. If you rename a URL later, every link still works, and url_for escapes special characters for you. Extra arguments become the query string, as with page=3 above.
In the exam
A route answers only GET (and HEAD, OPTIONS) unless you pass methods=. A wrong method gives 405 Method Not Allowed, a URL that matches no rule gives 404 Not Found.

Common mistake
Jinja escapes every value by default in .html templates, so a name such as <script> is shown as text and never runs. This stops cross site scripting (XSS). Only mark text as safe with |safe when you made it yourself.
Real world scenario: a shop with 40 pages

All 40 pages of a shop share the same header, menu and footer. With template inheritance there is one base.html with a block for the content, and each page only fills that block. Changing the menu means editing one file, not 40.

Forms, sessions and flash messages

Download this program (.py)Save it, open it in any editor and run it with python3 forms_session.py.
How the login works
  1. GET /login shows the form. The browser sends it back as POST /login with the fields in the body.
  2. The view reads request.form, checks the password and stores the user name in session.
  3. Flask puts the session into a cookie, signed with app.secret_key. The user can read it but cannot change it, because the signature would not match.
  4. The view answers with a redirect (Post, Redirect, Get), so pressing refresh does not send the form again.
  5. flash() stores a short message that the next page shows once.
Common mistake
The session cookie is signed, NOT encrypted: the example decodes it and reads the user name. Never put secrets in it, keep secret_key secret and long, and read it from an environment variable.
In the exam
Real forms also need protection against cross site request forgery (CSRF), so another website cannot post forms as your user. The extension Flask-WTF adds a hidden token to every form and checks it.

Running a Flask app for real

Run this one on your own computer. It starts a real web server on your computer and calls it with requests. Install both with pip install flask requests. The output above comes from a real run with CPython when this page was built.
Download this program (.py)Run it with python3 real_server.py.
From one file to a running site
  1. Make a virtual environment and install Flask: python3 -m venv .venv, activate it, then pip install flask.
  2. Save the app as app.py and start the development server with flask --app app run --debug. Open http://127.0.0.1:5000 in a browser.
  3. --debug reloads the code when you save a file and shows an interactive error page. Never use it on a public server: the error page can run Python code.
  4. In production run the app with a real WSGI server such as gunicorn -w 4 "app:app", behind a web server such as nginx that handles HTTPS.
  5. Keep settings such as SECRET_KEY and the database address in environment variables, not in the code.

The maths: workers, time and limits

Requests in progress (Little's law)Exam favourite
L = λ × W
120 requests/s, 0.2 s each: 24 requests at the same moment, so at least 24 workers or threads.
Gunicorn starting point
workers = 2 × CPU cores + 1
4 cores: 9 worker processes.
Throughput of sync workersExam favourite
requests/s ≤ workers / time per request
9 workers, 50 ms each: 9 / 0.05 = 180 requests/s.
Python time limit with threads (GIL)
requests/s ≤ 1 / CPU time per request, per process
10 ms of Python per request: at most 100 requests/s for one process, however many threads.
Cookie size
base64 makes data 4 / 3 as big
A 4,096 byte cookie holds about 3,072 bytes of session data.
Error rate
rate = errors / requests × 100 %
30 errors out of 600 requests: 5 %.
Worked example: how many workers?
  1. A page needs 10 ms of Python and 40 ms of waiting for the database: 50 ms in total.
  2. You expect 300 requests per second at the busiest time.
  3. Little's law: 300 × 0.05 = 15 requests are in progress at once, so you need at least 15 workers or threads.
  4. CPU limit: each request needs 10 ms of Python, so one process can do at most 100 per second. You need at least 3 processes, for example 4 workers with 4 threads each.
  5. workers × threads ≥ λ × W, and processes ≥ λ × CPU time

Going deeper: What WSGI is

WSGI (PEP 3333) is the agreement between Python web servers and frameworks. The server calls app(environ, start_response): environ is a dict with the request, and start_response receives the status and headers. A Flask app is such a callable. That is why the same Flask app runs on Werkzeug, Gunicorn, uWSGI or Waitress without changes. ASGI is the async version that FastAPI and Django channels use.

Chapter summary

  1. Flask maps URLs to view functions with @app.route. Converters such as <int:id> check and convert parts of the path. url_for builds links.
  2. request gives args, form, get_json(), files, headers and cookies. A view returns a str, a dict or list (JSON), a (body, status) pair, redirect() or abort().
  3. Jinja templates print values with escaping, loop, test conditions, and share a base page with extends and block.
  4. session is a signed cookie: readable, not changeable. Use Post, Redirect, Get after forms and flash() for one time messages.
  5. Test with app.test_client(). Develop with flask run --debug, deploy with Gunicorn and keep secrets in environment variables.
