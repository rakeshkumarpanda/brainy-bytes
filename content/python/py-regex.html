Regular expressions: patterns for text

Source: Python 3.14 documentation of the re module and the Regular Expression HOWTO.

What it is
A regular expression (regex) is a small pattern that describes text, such as "three digits, a dash, four digits". Python's re module uses patterns to find, check, split and replace text.
Why we need it
Finding a phone number, checking an email address, pulling the date out of a log line or cleaning extra spaces would take many lines of loops and if statements. A pattern does it in one line, and the same pattern works in Python, JavaScript, SQL databases, editors and command line tools.
How it works
Write the pattern as a raw string, r"...", so backslashes reach re unchanged. Special characters stand for groups of characters (\d is any digit) or for repetition ({3} means exactly three times). The engine tries the pattern at each place in the text, from left to right, and returns a match object with the text and its position.

Groups: pulling parts out

SyntaxMeaning
(...)Capture this part as group 1, 2, ...
(?P<name>...)A named group, read with m["name"] or m.group("name")
(?:...)Group without capturing, for | or repeats
\1, (?P=name)The same text that group 1 or name matched
m.groups(), m.groupdict()All groups as a tuple, named groups as a dict
Common mistake
findall changes what it returns when the pattern has groups: with one group it returns that group's text, with several it returns tuples. Use (?:...) for groups you only need for | or repeats.

Greedy, lazy, anchors and lookarounds

Download this program (.py)Save it, open it in any editor and run it with python3 greedy.py.
SyntaxMeaning
.*, .+Greedy: take as much as possible, then back off
.*?, .+?Lazy: take as little as possible, then take more
(?=...), (?!...)Lookahead: what follows must (not) match. Uses up no characters
(?<=...), (?<!...)Lookbehind: what comes before must (not) match
*+, ++, (?>...)Possessive and atomic (3.11+): never give characters back
Common mistake
Some patterns make the engine try a huge number of ways before failing, for example (a+)+$ on "aaaaaaaaaaaaaaaaaaaaaaaaaaaa!". This is catastrophic backtracking, and attackers use it to freeze servers (ReDoS). Avoid nested repeats of the same thing, or use possessive quantifiers.

Remember
A named, verbose pattern reads like documentation. fullmatch makes sure the line has exactly the expected shape, and broken lines are skipped instead of giving wrong data.
Going deeper: How the engine works

Python's re is a backtracking engine: it tries one way, and when it gets stuck, goes back to the last choice and tries another. That makes features like backreferences possible, but can be slow on bad patterns. Engines such as RE2 (Google) turn the pattern into an automaton that never backtracks and always runs in time proportional to the text, but they cannot support backreferences.

The maths: languages and automata

Choices for a character classExam favourite
patterns of length n over a class of size k match kn strings
\d{4} matches 104 = 10,000 strings, 0000 to 9999.
A range of repeats
[ab]{1,3} matches 2 + 4 + 8 = 14 strings
∑ ki for i from min to max.
Positions tried by search
up to n + 1 starting places
Text of length 17: starts 0 to 17.
A regular languageExam favourite
built from single characters with union (|), concatenation and star (*)
Every such pattern can be matched by a finite automaton with no memory.
Catastrophic backtrackingExam favourite
ways to split n letters among nested repeats grows like 2n
(a+)+$ on 30 a's followed by "!": about 230 ≈ 109 tries.
Linear time engines
time = O(m × n) for pattern size m and text size n
RE2 and Rust's regex guarantee this, Python's re does not.
Worked example: how many PIN codes does r"\d{4}" accept, and how many have no repeated digit?
  1. Each of the 4 places can be any of 10 digits: 104 = 10,000 codes.
  2. No repeated digit: 10 choices, then 9, then 8, then 7.
  3. 10 × 9 × 8 × 7 = 5040.
  4. 10,000 codes, of which 5040 have four different digits

From beginner to expert

One idea, four depths

Use \d, \w, \s, ., [ ], *, + and ? with re.search, findall and sub, always in raw strings.

Use groups and named groups, fullmatch for validation, split, flags, re.VERBOSE and re.compile, and lazy quantifiers.

Use lookarounds and backreferences, understand backtracking, avoid catastrophic patterns, and know when a parser is the right tool.

Know regular languages, NFAs and DFAs, Thompson's construction, why backreferences make matching NP-hard, and linear time engines such as RE2.

Chapter summary

  1. Write patterns as raw strings. \d \w \s . [ ] are characters, * + ? {m,n} are repeats, ^ $ \b are positions.
  2. search finds the first match, match only at the start, fullmatch the whole string. findall gives strings, finditer match objects.
  3. Groups ( ) and named groups (?P<name>...) pull out parts. (?:...) groups without capturing.
  4. sub replaces (with \1 or a function), split cuts. Flags: IGNORECASE, MULTILINE, DOTALL, VERBOSE.
  5. Repeats are greedy unless you add ?. Lookarounds check without using characters. Avoid nested repeats (ReDoS).
  6. Regex is for patterns, not nested formats: use a parser for HTML, JSON and XML.
