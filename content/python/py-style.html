Lesson 1 of 9

Clean code: style, docstrings and type hints

Source: PEP 8, PEP 257, PEP 20, PEP 484, PEP 544, PEP 589, PEP 604, PEP 695, the typing and doctest documentation, and PCPP-32-101 block 2. Tool outputs are real runs of ruff 0.17.4, black 26.10.1 and mypy 2.4.1.

What it is
Clean code is code that other people (and you, in six months) can read quickly and change safely. Python has written rules for it: PEP 8 for layout and names, PEP 257 for docstrings, PEP 20 (the Zen of Python) for the spirit, and type hints (PEP 484) that say what kind of value each name holds.
Why we need it
Code is read far more often than it is written. When every file looks different, readers waste time on layout instead of logic, and small mistakes hide in the mess. Some style rules also prevent real bugs: is None cannot be fooled, a None default avoids a shared list, and a type checker finds a wrong argument before any user does.
How it works
You follow the rules by habit and let tools check them: a formatter (black or ruff format) fixes layout automatically, a linter (ruff or flake8) reports problems like unused imports and bad names, and a type checker (mypy or pyright) reads the hints and reports type mistakes without running the code.

Bottom line: use is None for missing values and plain truthiness (if items:) for empty containers. They mean different things: 0 and [] are falsy but not None.

Remember
PEP 8 also says: use isinstance instead of comparing types, use startswith and endswith instead of slicing, do not compare booleans to True with ==, and keep try blocks small so you only catch the error you expect.

Always triple double quotes"""Return the mean."""
First line: a short summary that ends with a full stop, written as a command"""Return the mean of a list.""", not """Returns the mean"""
Longer docstring: summary, blank line, then detailsArguments, return value, errors raised, examples

A class docstring says what the class is, __init__ says how to make oneSee Wallet above
Remember
doctest finds >>> lines in docstrings, runs them and compares the output with the next line. TestResults(failed=0, attempted=2) means both examples still work. It keeps documentation honest. Real test suites come in 3.2.

The maths: complexity, paths and line budgets

Cyclomatic complexity (McCabe)Exam favourite
M = E − N + 2 (edges and nodes of the control flow graph) = decision points + 1
circle_area has one if, so M = 1 + 1 = 2. ruff rule C901 warns when M is above a limit, often 10.
Paths through k independent if statementsExam favourite
paths = 2k
4 separate ifs give 16 paths. Smaller functions keep this testable.
Minimum tests to cover every independent path
tests ≥ M
A function with M = 6 needs at least 6 tests for basis path coverage.
Characters left on a line
room = 79 − indent
Code nested 2 levels deep (8 spaces) has 71 characters left.
Spaces of indentation
spaces = 4 × depth
3 levels deep: 12 spaces. Deep nesting eats the line budget, a hint to split the function.
Worked example: the complexity of a grading function
  1. It has if, elif, elif and else: 3 decisions (else adds none).
  2. It also has a for loop: 1 more decision.
  3. Decisions = 3 + 1 = 4.
  4. M = 4 + 1 = 5, so at least 5 tests to cover its paths
Lesson 7 of 9

From beginner to expert

One idea, four depths

Follow the PEP 8 basics: 4 space indents, snake_case names, spaces around operators, one statement per line.

Write PEP 257 docstrings with doctest examples, use is None and truthiness correctly, and run a formatter and a linter.

Add type hints with generics, unions, Callable, Protocol and TypedDict, and run mypy in strict mode.

Configure ruff, black and mypy in pyproject.toml and run them in pre commit hooks and CI. Know the limits: gradual typing, Any, variance of generics (list is invariant, Sequence is covariant), and PEP 649 lazy annotations read through annotationlib.

Beginner
Write PEP 8 style code.
Intermediate
Document and lint it.
Expert
Type it fully and automate every check.

Lesson 9 of 9

Chapter summary

  1. PEP 8: 4 spaces, lines up to 79 characters, 2 blank lines around top level definitions, sorted imports one per line.
  2. Names: snake_case for functions and variables, CapWords for classes, UPPER_CASE for constants.
  3. Use is None, truthiness for empty containers, isinstance, and None instead of a mutable default.
  4. PEP 257: triple double quoted docstrings with a one line summary. doctest runs the examples in them.
  5. Type hints document types and let mypy find mistakes before running. Python itself ignores them.
  6. A formatter fixes layout, a linter finds problems, a type checker finds type mistakes: use all three.
