Lesson 1 of 10

Classes are objects too

Source: Python 3.14 data model chapter 3.3.3 (customizing class creation), the documentation of type, getattr, setattr, vars, dir and inspect, PEP 3115, PEP 3129, PEP 487, and PCPP-32-101 block 1.

What it is
Metaprogramming means writing code that makes or changes other code, mostly classes, while the program runs. In Python a class is an ordinary object. You can store it in a variable, pass it to a function, make one with type(), look inside it, and run your own code at the moment it is created. A metaclass is the class of a class: the thing that builds class objects.
Why we need it
Some rules apply to many classes at once: "every plugin must register itself", "every model needs a table name", "every command must have a run method". Writing that rule by hand in each class repeats code and is easy to forget. Metaprogramming puts the rule in one place and applies it to every class automatically.
How it works
When Python runs a class statement it collects the class body into a dict and then calls the metaclass (normally type) with the name, the base classes and that dict. Hooks let you join in: __init_subclass__ on a parent class, a class decorator after the class is built, or a custom metaclass that controls the whole process.

In the exam
type has two jobs. With one argument, type(x) tells you the class of x. With three arguments, type(name, bases, namespace) builds a new class. And type(type) is type: type is its own class, which is where the chain ends.

Remember
A class statement and a type() call give exactly the same kind of class. Python itself turns every class statement into a call like type("Cat", (object,), namespace). You only need type() directly when the name or the fields are known only while the program runs, for example from a config file.

Common mistake
The class body runs once, at the moment Python reaches the class statement, not each time you make an object. Names it creates (tax, price, total) end up in the namespace dict, which becomes the class __dict__. That is why a class body can hold any normal code, even print.

__init_subclass__ and class decorators

Download this program (.py)Save it, open it in any editor and run it with python3 initsub.py.
In the exam
__init_subclass__ (PEP 487, Python 3.6) runs on the PARENT every time a child class is created. It is a class method automatically. Keyword arguments in the class line, like name="csv", are passed to it. Always call super().__init_subclass__(**kwargs) so other parents in a multiple inheritance chain get their turn.

Remember
A class decorator is a function that takes a finished class and returns a class, usually the same one after changing it. @dataclass, @functools.total_ordering and @enum.unique are class decorators from the standard library. Stacked decorators run from the bottom up, so auto_repr ran before route.

Metaclasses

Download this program (.py)Save it, open it in any editor and run it with python3 metaclass.py.
In the exam
A metaclass is a subclass of type. Its __new__(mcs, name, bases, namespace) gets everything the class statement collected and must return the new class, normally from super().__new__. Children of Job use CheckMeta too, because Python uses the metaclass of the base class when none is given. The check fires when the class is DEFINED, long before anyone uses it.
Download this program (.py)Save it, open it in any editor and run it with python3 singleton.py.
Common mistake
Calling a class, Config(...), really calls type(Config).__call__. The normal type.__call__ runs __new__ and then __init__. Overriding __call__ in a metaclass changes what calling the class does: here it returns the saved object. Notice that the second call did not even run __init__, so mode stayed "prod".
Download this program (.py)Save it, open it in any editor and run it with python3 stdmeta.py.
Remember
You already use metaclasses: ABC is built by ABCMeta (that is how abstract methods block objects) and every Enum by EnumType (that is why len(Colour) and for c in Colour work on the class itself). A class whose bases have two unrelated metaclasses cannot be made, because Python cannot pick one metaclass that is a child of both.

Going deeper: Tim Peters on metaclasses

"Metaclasses are deeper magic than 99% of users should ever worry about. If you wonder whether you need them, you don't." Most frameworks that once needed a metaclass (Django models, SQLAlchemy declarative classes) can now be written with __init_subclass__ and __set_name__.

Lesson 6 of 10

The full order of class creation

Download this program (.py)Save it, open it in any editor and run it with python3 order.py.
What Python does for a class statement, in order
  1. Pick the metaclass: the one given with metaclass=, otherwise the metaclass of the bases (the most derived one), otherwise type.
  2. Call Meta.__prepare__(name, bases) to get the namespace. type gives a plain dict.
  3. Run the class body inside that namespace. It stores __module__, __qualname__ and every name the body defines.
  4. Call Meta(name, bases, namespace). That runs Meta.__new__, which calls type.__new__ to build the class object.
  5. Inside type.__new__: call __set_name__ on every attribute that has it, then __init_subclass__ on the parent.
  6. Run Meta.__init__ on the new class.
  7. Apply class decorators from the bottom up.
  8. Store the result under the class name. Later, calling the class runs Meta.__call__, which runs __new__ and __init__.
Going deeper: Going further: __prepare__, __mro_entries__ and types.new_class

__prepare__ may return any mapping, for example one that refuses duplicate names or records the order of definitions. __mro_entries__ lets an object that is not a class appear in a base list (typing.Generic uses it). types.new_class(name, bases, kwds, exec_body) is the safe way to build a class with a metaclass and keywords from code, because it follows every step above exactly like a class statement.

The maths: counting classes, lookups and steps

Classes made by a factory
classes = n1 × n2 × ... × nk
make_record for 3 colours and 4 sizes builds 3 × 4 = 12 classes.
Classes in a full hierarchy below one baseExam favourite
b + b2 + ... + bd = b(bd − 1) / (b − 1)
With b = 3 children each and d = 2 levels: 3 + 9 = 12 subclasses, each one seen by __init_subclass__.
Average checks in an if and elif chainExam favourite
average = (n + 1) / 2 for n equally likely names
A chain of 9 actions needs 5 checks on average. A dict or getattr needs about 1 lookup.
Worst case attribute lookup
dicts checked ≤ 1 + len(C.__mro__)
The instance dict, then each class in the MRO. For Kitten, Cat, object: at most 1 + 3 = 4.
Objects made by a singleton
objects = 1 for any n ≥ 1 calls, against n for a normal class
50 calls of Config() make 1 object.
Steps from an object up to type
type(rex) = Dog, type(Dog) = Meta, type(Meta) = type, type(type) = type
Three steps reach type, and then the chain repeats itself.
Worked example: how many registry entries does Plugin collect?
  1. Plugin has 3 direct children: b = 3.
  2. Each child has 3 children of its own: d = 2 levels.
  3. Level 1 gives 3 classes and level 2 gives 3 × 3 = 9.
  4. 3 + 9 = 3(32 − 1) / (3 − 1) = 12 entries

From beginner to expert

One idea, four depths

Know that classes are objects: type(x), isinstance, store and pass classes, and read __name__, __bases__ and __dict__.

Build classes with type(name, bases, dict), use getattr, setattr, hasattr and vars to work with names in strings, and write class decorators and __init_subclass__ registries.

Write metaclasses with __new__ and __call__, explain inherited metaclasses and metaclass conflicts, and recognise ABCMeta and EnumType in the standard library.

Explain the whole class creation protocol: metaclass selection, __prepare__, the body, __new__, __set_name__, __init_subclass__, __init__, decorators. object is an instance of type and type is a subclass of object, a loop CPython sets up by hand at start up. Know when __mro_entries__ and types.new_class are the right tools, and why most designs should not need a metaclass at all.

Beginner
Treat classes as objects and look inside them.
Intermediate
Make classes from data and react when classes are created.
Expert
Control class creation completely, and choose the lightest tool.

Chapter summary

  1. Classes are objects. type(x) gives the class of x, and the class of a class is its metaclass, normally type.
  2. type(name, bases, namespace) builds a class without a class statement. Use it, or make_dataclass, when the class shape comes from data.
  3. A class body runs once and fills a namespace dict that becomes the class __dict__.
  4. getattr, setattr, hasattr, vars, dir and inspect let code look at and change objects by name while it runs.
  5. __init_subclass__ runs on the parent for every new child (great for registries). A class decorator gets the finished class.
  6. A metaclass is a subclass of type. __new__ controls building the class, __call__ controls making objects. Children inherit the metaclass.
  7. Order: pick metaclass, __prepare__, body, Meta.__new__, __set_name__, __init_subclass__, Meta.__init__, decorators, bind the name.
