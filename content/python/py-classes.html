Lesson 1 of 15

Classes and objects

Source: Python 3.14 tutorial chapter 9 "Classes", the data model reference section 3.3, and PCAP-31-03 section 3.

What it is
A class is a blueprint that describes a kind of thing: what data it holds (its attributes) and what it can do (its methods). An object (also called an instance) is one real thing made from that blueprint.
Why we need it
Programs model the real world: students, bank accounts, shapes, orders. Keeping each thing as loose variables and separate functions gets messy fast. A class keeps the data and the code that works on it together in one place, so each object looks after itself.
How it works
class Dog: makes a class object. Calling Dog("Rex", 3) makes a new empty object and runs __init__ on it to fill in its attributes. Every object has its own attributes but shares the methods of its class. When you write rex.bark(), Python finds bark on the class and passes rex in as self.
Real world scenario: a cake recipe and the cakes

A recipe says a cake has a flavour and a size and can be cut into slices. The recipe itself is not a cake. Each cake you bake from it is a separate cake with its own flavour and size. Cutting one cake does not change the others. The recipe is the class and each cake is an object.

Methods, self and __init__

Download this program (.py)Save it, open it in any editor and run it with python3 self.py.
In the exam
self is not a keyword. It is only the name every Python programmer uses for the first parameter of a method. Python fills it in for you: rex.bark() becomes Dog.bark(rex). Forget self in the def line and the call fails with "takes 0 positional arguments but 1 was given".
You writePython does
rex = Dog("Rex")Makes an empty object, then calls Dog.__init__(that object, "Rex"), then names it rex
rex.bark()Finds bark on the class and calls Dog.bark(rex)
Dog.barkA plain function
rex.barkA bound method: the function plus the object, ready to call
Going deeper: Where does the new object come from

Making an object has two steps. First the special method __new__ creates the empty object. Then __init__ fills it in. __init__ only sets things up and must return None. Returning anything else raises TypeError. You almost never write __new__ yourself (Advanced 1.4 shows when you do).

Bottom line: put data that changes from object to object on the instance, and shared constants on the class.

How Python reads obj.attr
  1. Look in obj.__dict__, the attributes of the object itself.
  2. If it is not there, look in the class of the object (and later in its parent classes, see 6.2).
  3. If it is still not found, raise AttributeError.
In the exam
Writing obj.attr = value never goes to the class. It always creates or changes the attribute on that one object. That is why a.species = "wolf" left b.species and Dog.species alone.

The shared list trap

Download this program (.py)Save it, open it in any editor and run it with python3 shared.py.
Common mistake
A class attribute that holds a list, dict or set is ONE object for all instances. Changing it with append or update through any object changes it for every object. Create such data in __init__ with self.items = [] instead. This is the same trap as a mutable default argument (4.1).

In the exam
Encapsulation means an object guards its own data and offers methods to work with it, so outside code cannot put it into a bad state (like a negative balance). Python trusts programmers: it has no real private keyword like Java. Use one underscore for internal things, and properties (Advanced 1.3) when you need checks on reading or writing.

Identity and equality of objects

Download this program (.py)Save it, open it in any editor and run it with python3 identity.py.
In the exam
a is b asks "are these the same object". a == b asks "are these equal". For your own classes == means the same as is until you write __eq__. Writing __eq__ sets __hash__ to None, so the objects can no longer be set items or dict keys unless you also write __hash__ (Advanced 1.1).

From beginner to expert

One idea, four depths

A class is a blueprint and objects are things made from it. Write __init__ to set attributes with self, and call methods with dot notation.

Tell instance attributes from class attributes, avoid the shared list trap, write __str__ and __repr__, use isinstance, hasattr and getattr, and protect data with methods and the underscore convention.

Know how attribute lookup works (instance dict, then class), what a bound method is, what name mangling does and why it exists, and how __eq__ and __hash__ go together. Choose between a dict, a class and a dataclass for a design.

Classes are objects too: their type is type, the class body runs once and fills a namespace that type() turns into a class. Attribute access goes through object.__getattribute__, which checks data descriptors on the class, then the instance __dict__, then other class attributes. Methods are functions that are descriptors: their __get__ makes the bound method. __slots__ replaces the per object dict with fixed slots to save memory (Advanced 1.3 and 1.4).

Beginner
Write a class with __init__, attributes and methods, and make objects from it.
Intermediate
Use class attributes correctly, write __str__ and __repr__, use introspection and encapsulation.
Expert
Explain attribute lookup, bound methods, name mangling and the __eq__ and __hash__ contract.

Chapter summary

  1. A class is a blueprint, an object (instance) is one thing made from it. Calling the class makes an object.
  2. __init__(self, ...) sets up a new object. self is the object a method works on: obj.m() means Class.m(obj).
  3. Instance attributes (self.x) belong to one object. Class attributes (in the class body) are shared by all objects.
  4. Reading obj.x looks in the object first, then the class. Writing obj.x = v always writes to the object.
  5. A list or dict as a class attribute is shared by every object. Create it in __init__ instead.
  6. __str__ is for print, __repr__ is for developers. Write __repr__ at least.
  7. type, isinstance, hasattr, getattr, setattr, vars and __name__, __module__, __bases__ let code look inside objects.
  8. _x means internal by convention. __x is name mangled to _Class__x. is checks identity, == checks equality (identity until you write __eq__).
