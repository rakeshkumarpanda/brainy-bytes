Lesson 1 of 10

Exceptions, copies and saved objects

Source: Python 3.14 tutorial chapter 8, PEP 3134, PEP 654, PEP 678, and the traceback, warnings, copy, pickle and shelve documentation, plus PCPP-32-101 block 1.

What it is
This chapter goes deeper into three things every real program needs: exceptions that carry their full story (their own types, causes, notes and groups), copies of objects that do or do not share their insides, and serialisation, turning objects into bytes so they can be saved and loaded later with pickle and shelve.
Why we need it
In a big program a bare "ValueError" says little. You need to know what went wrong, where, and what caused it. Copying is a classic source of bugs: changing a "copy" that secretly shares data with the original. And objects vanish when the program ends unless you save them.
How it works
Custom exception classes form a family you can catch at any level. raise ... from ... links a new error to its cause. add_note and ExceptionGroup add context and report many errors at once. copy.copy and copy.deepcopy decide how deep a copy goes. pickle.dumps turns almost any object into bytes and pickle.loads rebuilds it.

Common mistake
Never unpickle data from a source you do not trust. pickle.loads can run any code the data asks for, so a crafted file can take over your computer. For data from users or the internet use JSON.

Bottom line: use JSON to talk to the world, pickle for trusted Python to Python data, and shelve when you want a dict that survives restarts.

In the exam

The maths: retries, copies and sizes

Chance that k independent attempts all failExam favourite
P(all fail) = pk, P(success) = 1 − pk
A call fails 20 % of the time. With 3 attempts: 1 − 0.23 = 99.2 % success.
Objects created by copies of an n by m nested listExam favourite
shallow: 1 list. deep: 1 + n lists
For [[1, 2], [3, 4]]: shallow makes 1 new list, deep makes 3. The ints are immutable and shared either way.
Attempts needed for a target
k ≥ log(1 − target) / log(p)
p = 0.2, target 99.99 %: k ≥ log(0.0001) / log(0.2) ≈ 5.7, so 6 attempts.
Expected attempts until success
E = 1 / (1 − p)
p = 0.2: 1.25 attempts on average.
Worked example: success chance with 3 attempts at p = 0.2
  1. All three fail: 0.2 × 0.2 × 0.2 = 0.008.
  2. So at least one succeeds with 1 − 0.008.
  3. 0.992, which is 99.2 %
Lesson 8 of 10

From beginner to expert

One idea, four depths

Write your own exception class, and know that b = a does not copy while a.copy() and copy.deepcopy(a) do.

Build an exception hierarchy, chain with raise from, read tracebacks, choose shallow or deep copies, and save objects with pickle and shelve.

Use add_note, ExceptionGroup and except*, warnings filters, __copy__ and __deepcopy__, and know the pickle security risk and when JSON is the right tool.

pickle stores a program for a small stack machine: classes are saved by import path and rebuilt with __reduce__, __getstate__ and __setstate__, which is both why pickle can rebuild almost anything and why loading it can run arbitrary code. Protocol 5 (PEP 574) adds out of band buffers for large data.

Beginner
Raise and catch your own exceptions, copy lists safely.
Intermediate
Chain exceptions, choose the right copy, pickle and shelve objects.
Expert
Use exception groups and notes, customise copying and pickling, explain the pickle VM.

Chapter summary

  1. Make one base exception per package and a child per problem. Pass a clear message to super().__init__ and store useful fields.
  2. raise New() from err sets __cause__. Raising inside except sets __context__. from None hides the original.
  3. err.__traceback__ and the traceback module show where an error happened. add_note adds context. ExceptionGroup with except* reports many errors.
  4. Warnings flag old or risky use without stopping. assert checks your own logic and disappears with python -O.
  5. b = a shares everything, a shallow copy shares the inner objects, copy.deepcopy shares nothing and handles loops with a memo.
  6. pickle.dumps and loads turn objects into bytes and back. Never unpickle untrusted data. shelve is a dict on disk that returns copies.
