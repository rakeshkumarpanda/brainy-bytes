Six bugs examiners and interviewers love
  1. Bug 1. Removing items from a list while a for loop walks it skips the item after each removal, so 4 survives. Build a new list instead (3.2).
  2. Bug 2. Strings never change. upper() returns a new string, which was thrown away. Assign the result (3.1).
  3. Bug 3. The function computes w * h but never returns it, so the caller gets None (4.1).
  4. Bug 4. except Exception catches ValueError first, so the narrow handler can never run. Put specific handlers before general ones (5.1).
  5. Bug 5. input() returns text, and "7" * 2 is "77". Convert with int() first (1.4).
  6. Bug 6. list = [...] hides the built in list, so list("abc") calls a list object and fails. Never use built in names as variables (4.2).

Exam technique and a study plan

Time per questionExam favourite
minutes × 60 / questions
PCEP: 40 × 60 / 30 = 80 seconds. PCAP: 65 × 60 / 40 = 97.5 seconds.
Questions to pass (if every item counts the same)Exam favourite
correct needed = ceil(pass mark × questions)
PCEP: 0.7 × 30 = 21. PCAP: 0.7 × 40 = 28.
Points by block
block share of the exam = block weight
Object oriented programming is 34 % of PCAP, more than any other block, so it deserves the most practice.
A four week plan
  1. Week 1: chapters 1.1 to 2.2. Do paper A without looking, then reread the chapter behind every wrong answer.
  2. Week 2: chapters 3.1 to 3.4 and paper B. Practise slicing and dict methods until you can predict them instantly.
  3. Week 3: chapters 4.1 to 5.3 and paper C. Write small programs for args, scope, closures and exceptions.
  4. Week 4: chapters 6.1 and 6.2 and paper D, then the mock quiz in the Quiz tab with a timer. Aim for 85 % to leave a safety margin.
In the exam
In the exam: read the whole snippet before the options, trace it line by line on scratch paper, watch for indentation and for a missing comma or bracket that turns the answer into "the code raises an error". Mark hard questions and come back, every question is worth the same.
One idea, four depths

PCEP level: predict the output of short programs with operators, loops, lists, dicts, strings, functions and simple try and except.

PCAP level: add modules and packages, the exception tree, string methods, classes, inheritance, comprehensions, lambdas, closures and files.

PCPP level (Advanced part): decorators, the data model, generators, testing, concurrency, design patterns and the standard library in depth.

Expert: explain why each trap happens from the language reference (evaluation order, the data model, the C3 MRO, name binding rules) and spot them in code review before they reach production.

Chapter summary

  1. PCEP-30-02: 30 questions, 40 minutes, 70 %. PCAP-31-03: 40 questions, 65 minutes, 70 %. Newer versions started on 31 October 2026.
  2. Operators: ** before unary minus and right to left, // rounds down, % takes the sign of the divisor, round goes to even on ties.
  3. Loops: else runs only without break. Never change a list while looping over it.
  4. Collections: assignment makes aliases, [[0] * 3] * 3 shares one row, (1,) is a tuple, sort returns None, True and 1 are the same dict key.
  5. Functions: mutable defaults are shared, assigning a name makes it local, lambdas in loops bind late, nonlocal changes an enclosing name.
  6. Exceptions: first matching except wins, specific before general, else when no error, finally always.
  7. Objects: instance assignment never changes the class, __x is mangled, call super().__init__().
  8. Technique: about 80 to 98 seconds per question, trace on paper, aim for 85 % in practice.
