Lesson 1 of 10

What a web API is, and why requests

Source: The requests 2.34 documentation (quickstart and advanced usage), RFC 9110 (HTTP semantics) and the Python 3.14 documentation of json and urllib.request.

What it is
A web API is a website made for programs instead of people. You send an HTTP request to a URL and get data back, usually as JSON. Weather services, payment companies, GitHub and maps all offer one. requests is the most used Python library for calling them.
Why we need it
Python can already call APIs with urllib.request, but you must encode query strings, write JSON bodies and headers, and catch errors by hand. That is a lot of code for something every program does.
How it works
requests does those jobs in one call: requests.get(url, params=..., timeout=...) builds the URL, sends the request, reuses connections and returns a Response object with status_code, headers, text and json(). You only write what is special about your call.

Common mistake
Always pass timeout=. requests has no timeout by default, so a server that never answers keeps your program waiting for ever. A number such as timeout=5 is used for connecting and again for each wait while reading.

Remember
For a big download use requests.get(url, stream=True, timeout=10) and write for chunk in r.iter_content(64_000) into a file opened with "wb". Then the whole file never has to fit in memory.
Real world scenario: a shop sends an order to a delivery company

When a customer pays, the shop server calls the delivery company API with requests.post(url, json=order, headers=..., timeout=10). The delivery API answers 201 with a tracking number, which the shop stores. If the answer is 422, the address is wrong and the shop asks the customer. If it is 503, the shop tries again a little later.

A safe way to call an API
  1. Pass a timeout to every call.
  2. Call r.raise_for_status() right away, or check r.status_code yourself when some errors are normal (a 404 can mean "no such user").
  3. Catch the exact exceptions first and RequestException last, because except blocks are checked from top to bottom.
  4. Log the URL, the status and the error message from the body, so you can find the problem later.
  5. Retry only errors that may go away (timeouts, 429, 502, 503, 504), and only for requests that are safe to repeat.

In the exam
A Session keeps cookies and default headers, and it reuses the TCP (and TLS) connection for every request to the same host. The example shows 3 requests over 1 connection. That saves one or two round trips each time, so use a Session whenever you make more than a couple of calls.
Common mistake
Never put a real token or password in code that you share or commit to git. Read it with os.environ["API_TOKEN"] and keep it in a .env file that git ignores.

The maths: round trips, timeouts and limits

Pages to fetchExam favourite
pages = ⌈items / page size⌉
95 items, 20 per page: ⌈4.75⌉ = 5 requests.
Time without a Session
n × (handshake RTTs + 1) × RTT
10 calls, 2 handshake RTTs, RTT 50 ms: 10 × 3 × 50 = 1,500 ms.
Time with a SessionExam favourite
(handshake RTTs + n) × RTT
(2 + 10) × 50 = 600 ms, so 900 ms saved.
Longest wait with timeout=(c, r)
up to c + r for each silent stretch
timeout=(3, 2): up to 3 s to connect, then 2 s with no data before ReadTimeout.
Rate limit
minimum time = requests / allowed rate
300 calls at 60 per minute: 5 minutes.
Chance one of k tries worksExam favourite
P = 1 − (1 − p)k
p = 0.9, k = 3: 1 − 0.001 = 0.999.
Worked example: download 2,000 records
  1. The API gives 100 records per page, so ⌈2000 / 100⌉ = 20 requests.
  2. RTT is 60 ms and the server needs 40 ms per page. With a Session each request costs about 100 ms.
  3. One after another that is 20 × 100 = 2,000 ms, plus 120 ms for the first handshake.
  4. Without a Session each call adds 2 handshake round trips: 20 × (100 + 120) = 4,400 ms.
  5. Session: about 2.1 s, no Session: about 4.4 s

Going deeper: What requests is made of

requests sits on top of urllib3, which keeps a pool of open connections for each host and does the TLS work with Python's ssl module. Certificates are checked against the certifi bundle by default. That is why verify=False is dangerous: it turns off the check that you really talk to the right server.

Lesson 10 of 10

Chapter summary

  1. A web API is HTTP for programs. requests.get, post, put, patch and delete call it and return a Response.
  2. params= goes into the URL, json= sends a JSON body, data= a form, files= uploads. Always pass timeout=.
  3. A 4xx or 5xx is not an exception until raise_for_status(). Catch HTTPError, Timeout and ConnectionError, and RequestException last.
  4. A Session keeps cookies and headers and reuses connections. Send tokens in the Authorization header and keep them out of code.
  5. r.json() gives dicts and lists. Use [] for required keys and .get() for optional ones, and parse dates with datetime.
