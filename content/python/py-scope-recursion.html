Lesson 1 of 15

Where names live, and functions that call themselves

Source: Python 3.14 tutorial section 9.2, language reference section 4.2, PCEP-30-02 sections 4.1 and 4.2.

What it is
The scope of a name is the part of the program where you can use it. A name made inside a function is local to that function. A name made at the top of a file is global. Recursion is when a function calls itself to solve a smaller copy of the same problem.
Why we need it
Scopes keep functions independent: a helper can use the name i or total without breaking the same name somewhere else. Recursion makes problems that are made of smaller copies of themselves (folders inside folders, family trees, maths like n!) short and clear.
How it works
Each call gets a fresh set of local names (a frame). Python looks names up in the order Local, Enclosing, Global, Built-in. A recursive function has a base case that answers directly and a recursive case that calls itself on a smaller input, so it always reaches the base case.
Real world scenario: Russian nesting dolls

To count the dolls in a matryoshka set, open the outer doll. If it is empty, the answer is 1 (the base case). Otherwise the answer is 1 plus the number of dolls inside, and you count those the same way (the recursive case). Each opened doll waits on the table until the inner count comes back. Those waiting dolls are the call stack.

In the exam
Assigning to a name inside a function makes a new local name, even if a global with the same name exists. This is called shadowing. Changing an object (items.append) is different from rebinding a name (items = [...]): the first is seen by the caller, the second is not.

nonlocal and closures

Download this program (.py)Save it, open it in any editor and run it with python3 closure.py.
What it is
A closure is an inner function that remembers names from the function around it, even after that outer function has finished.
Why we need it
It lets you make functions with their own private memory: counters, multipliers, settings, without a global variable or a class.
How it works
Python stores each remembered name in a cell attached to the inner function (func.__closure__). Reading an enclosing name needs nothing special. Assigning to it needs nonlocal, or Python would make a new local name.
In the exam
global reaches the module scope. nonlocal reaches the nearest enclosing function scope and is a SyntaxError at the top level. Decorators (Advanced 1.2) are built from closures.

The recursion limit

Download this program (.py)Save it, open it in any editor and run it with python3 limit.py.
Common mistake
Each call uses a frame on the call stack. To protect the program, CPython stops at about 1,000 frames deep with RecursionError. sys.setrecursionlimit can raise the limit, but a recursion that deep is usually better written as a loop.

Memoisation: remember answers

Download this program (.py)Save it, open it in any editor and run it with python3 memo.py.
What it is
Memoisation means storing the answer of each call so the same call never has to be worked out twice.
Why we need it
Naive fib(n) calls fib(n − 2) twice, fib(n − 3) three times, and so on: the number of calls grows like 1.6n. fib(25) needs 242,785 calls.
How it works
functools.lru_cache keeps a dict from arguments to results. With it each fib(k) is computed once, so fib(n) takes n + 1 calls. A plain loop with two names does the same in O(n) time and O(1) memory.

Recursion or a loop

Recursion compared with iteration
RecursionLoop
Fits bestNested data: trees, folders, JSON, divide and conquerWalking a list, counting, simple repeats
MemoryOne frame per pending call: O(depth)Usually O(1)
Depth limit in PythonAbout 1,000None
Speed in CPythonSlower (each call has a cost)Faster
ReadabilityVery clear when the problem is recursiveVery clear when it is a sequence

Bottom line: use recursion when the data or the problem is naturally nested, and a loop for everything else. Python does not remove tail calls, so a deep "tail recursive" function still hits the limit.

The maths of recursion

Recurrence for a simple recursionExam favourite
T(n) = T(n − 1) + c gives T(n) = O(n)
factorial and countdown do constant work and then one smaller call.
Calls made by naive fib(n)Exam favourite
C(n) = C(n − 1) + C(n − 2) + 1 = 2F(n + 1) − 1
fib(5) makes 2 × 8 − 1 = 15 calls, as the animation counts.
Golden ratio growth
F(n) ≈ φn / √5, φ = (1 + √5)/2 ≈ 1.618
So naive fib is exponential: about 1.6n calls.
Tower of Hanoi movesExam favourite
M(n) = 2M(n − 1) + 1 = 2n − 1
3 discs need 7 moves, 64 discs need about 1.8 × 1019.
Fast power
T(n) = T(n/2) + c gives T(n) = O(log n)
power(2, 1000) needs only about 10 levels of calls.
Master theorem (divide and conquer)
T(n) = a·T(n/b) + O(nd)
If d > logb a: O(nd). If equal: O(nd log n). If less: O(nlogb a). Merge sort: a = 2, b = 2, d = 1 gives O(n log n).
Worked example: prove factorial is correct by induction
  1. Claim: factorial(n) returns n! for every n ≥ 0.
  2. Base: for n = 0 and n = 1 it returns 1, which is 0! and 1!.
  3. Step: assume factorial(n − 1) returns (n − 1)!. Then factorial(n) returns n × (n − 1)! = n!.
  4. By induction the claim holds for every n ≥ 0
  5. This is why a correct base case and a smaller recursive call are all you need.

From beginner to expert

One idea, four depths

Names made in a function are local and vanish after the call. A function can call itself if it has a base case.

Python finds names with LEGB. global and nonlocal let a function assign to an outer name. Assigning anywhere makes a name local. Recursion needs a base case and a smaller step, and stops near 1,000 frames.

Closures keep enclosing names alive in cells. Memoise repeated calls with lru_cache. Write recurrences to find the cost of a recursive function, and prove it correct with induction.

The compiler classifies every name as local, cell, free or global and emits different bytecodes (LOAD_FAST, LOAD_DEREF, LOAD_GLOBAL). Since Python 3.11 pure Python calls do not use the C stack, but the recursion limit still guards against runaway recursion. Recursion with memoisation is top down dynamic programming, the loop version is bottom up.

Beginner
Tell local from global names and write a factorial with a base case.
Intermediate
Use LEGB, global and nonlocal correctly, trace the call stack, and avoid UnboundLocalError.
Expert
Write closures, memoise with lru_cache, analyse recursion with recurrences and prove it correct by induction.

Chapter summary

  1. Names assigned in a function are local. Names at the top of a file are global. A local name hides a global one with the same name.
  2. Python looks names up in the order Local, Enclosing, Global, Built-in.
  3. If a name is assigned anywhere in a function, it is local in the whole function. Reading it first gives UnboundLocalError.
  4. global name lets a function assign to a module name. nonlocal name does the same for an enclosing function.
  5. A closure is an inner function that remembers enclosing names after the outer function returns.
  6. Recursion needs a base case and a recursive case that gets smaller. Each pending call is a frame on the call stack.
  7. CPython stops at about 1,000 frames with RecursionError. Memoise repeated calls with lru_cache, or use a loop.
  8. Naive fib makes 2F(n + 1) − 1 calls. Hanoi needs 2n − 1 moves. Fast power needs O(log n) calls.
