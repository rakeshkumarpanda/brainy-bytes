Lesson 1 of 9

asyncio: many waits in one thread

Source: Python 3.14 documentation of asyncio, PEP 492 (async and await), PEP 525 (async generators) and httpx. The httpx run is real, against a local server that answers after 0.2 s.

What it is
asyncio runs many tasks in one thread. A function written with async def is a coroutine: it can pause at every await while it waits for something, and an event loop runs another coroutine in the meantime.
Why we need it
A web server or a crawler may have thousands of network connections open, each waiting most of the time. One thread per connection costs memory and needs locks. asyncio handles them all in one thread, and because a task can only be paused at an await, shared data cannot change in the middle of a line.
How it works
You write normal looking code with await in front of anything that waits: await asyncio.sleep(1), await client.get(url). The event loop keeps a queue of tasks that are ready to run, and a list of tasks that wait for a time or for network data. asyncio.run(main()) starts the loop. asyncio.gather and TaskGroup run coroutines at the same time.

Common mistake
Calling make_tea(...) only creates a coroutine object, it runs nothing. The code runs when it is awaited, or when it is wrapped in a task (gather, create_task, TaskGroup). Forgetting await is the most common asyncio bug: Python warns "coroutine ... was never awaited".

Event loopThe scheduler: runs ready tasks one at a time and wakes waiting ones

Common mistake
Keep a reference to every task you create with create_task (in a list or a set), or use a TaskGroup. The loop holds tasks only weakly, so a task nobody refers to can disappear before it finishes.

In the exam
Cancelling a task raises CancelledError inside it at its current await. Clean up in finally blocks, and do not swallow CancelledError without raising it again, or the task cannot be stopped.
Remember
A Semaphore limits how many tasks do something at once. Without it, gathering 10,000 downloads opens 10,000 connections at the same moment, which servers often punish by refusing or blocking you.

Remember
asyncio.Queue is like queue.Queue, but put and get are awaited. With maxsize=2 the producer waits when two items are waiting. This back pressure stops a fast producer from filling memory while a slow consumer catches up.
Going deeper: Async generators and async for

An async def with yield is an async generator: async for x in agen() awaits each value, and [x async for x in agen()] is an async comprehension. async with calls the awaitable methods __aenter__ and __aexit__, which is how httpx.AsyncClient and database connections clean up.

Common mistake
A normal blocking call (time.sleep, requests.get, a slow calculation) inside a coroutine freezes the whole loop. Use the async version (asyncio.sleep, httpx.AsyncClient, aiofiles), or push the blocking call to a thread with asyncio.to_thread, or to a process pool with loop.run_in_executor.

Bottom line: asyncio for many network connections with async libraries, threads to speed up existing blocking code, processes for CPU work.

The maths: waits that overlap

Time one by oneExam favourite
T = n × t
20 requests of 0.2 s: 4 s.
Time with all at onceExam favourite
T ≈ max(ti) + overhead
20 requests of 0.2 s: about 0.2 s (measured 0.26 s).
With a limit of k at onceExam favourite
T ≈ ⌈n / k⌉ × t
20 requests, at most 5 at once, 0.2 s each: 4 rounds, 0.8 s.
Throughput
requests per second = k / t
5 at once, 0.2 s each: 25 requests per second.
Little's law for open connections
L = λ × W
1000 requests per second with 0.5 s waits: 500 tasks waiting at any moment.
Memory for many waiters
memory ≈ n × size of one waiter
10,000 tasks of about 2 KB is about 20 MB. 10,000 threads reserve about 80 GB of address space for stacks.
Worked example: how long do 1000 API calls take?
  1. Each call waits 0.5 s for the server. One by one: 1000 × 0.5 = 500 s.
  2. The API allows at most 50 calls at a time, so use asyncio.Semaphore(50).
  3. ⌈1000 / 50⌉ = 20 rounds of 0.5 s.
  4. 20 × 0.5 = 10 s, fifty times faster, in one thread

Lesson 9 of 9

Chapter summary

  1. async def makes a coroutine. It runs only when awaited or wrapped in a task. await pauses it and lets the loop run others.
  2. asyncio.run(main()) once at the top. gather or TaskGroup to run coroutines at the same time. create_task for background work.
  3. Waits overlap: n waits of t seconds take about t, not n × t. A Semaphore limits how many run at once.
  4. asyncio.timeout and wait_for stop slow work. task.cancel() raises CancelledError at the current await.
  5. asyncio.Queue builds pipelines with back pressure. Async generators and async with exist too.
  6. Never block the loop: use async libraries such as httpx, or asyncio.to_thread for blocking calls.
