Lesson 1 of 14

What a string is

Source: Python 3.14 library reference, Text Sequence Type str. PCEP-30-02 section 3.4 and PCAP-31-03 section 2.

What it is
A string (type str) is a piece of text: a sequence of characters such as letters, digits, spaces and symbols. You write it between quotes: single, double, or three of either for many lines.
Why we need it
Almost every program works with text: names, messages, file contents, web pages, passwords. Numbers alone cannot hold "Hello, Asha". The str type stores any text in any language and gives you more than 40 ready made tools (methods) to work with it.
How it works
Python keeps the characters in order, so each one has a position number (an index) starting at 0. You can read one character, cut out a part (a slice), join strings and search inside them. A string never changes after it is made. Every change builds a new string.
Real world scenario: a name on a train ticket

A train ticket prints "RAVI KUMAR". The booking app stored what you typed, " ravi kumar ", then removed the extra spaces with strip(), made it upper case with upper(), and printed it. It checked the PNR number with isdigit() and cut the coach number out of "B2-34" with a slice. Every one of these steps is a string method from this chapter.

Index of a characterExam favourite
0, 1, ..., len(s) − 1 from the left, and −1, −2, ..., −len(s) from the right
s[-k] is the same as s[len(s) − k].
SliceExam favourite
s[start:stop:step]
start is included, stop is not. Leave out start for "from the beginning" and stop for "to the end".
Length of a simple slice
len(s[a:b]) = b − a
when 0 ≤ a ≤ b ≤ len(s). "PYTHON"[1:4] is "YTH", 3 characters.
In the exam
A single index outside the string raises IndexError. A slice outside the string never fails: it just gives what is there, or an empty string.

Bottom line: keep text as str. If you need hundreds of edits in place, turn it into a list, edit, and join it back.

Going deeper: Why Python made strings immutable

Because a string cannot change, Python can work out its hash once and keep it, which makes strings fast dict keys. Two names can share the same string object without risk, and Python reuses (interns) many short strings. Use == to compare text. Never use is, because whether two equal strings are the same object depends on the interpreter.

Common mistake
Strings are compared letter by letter by code point, not by dictionary order. All upper case letters (65 to 90) come before all lower case letters (97 to 122), so "Zebra" < "apple" is True. "10" < "9" is True too, because "1" comes before "9". Turn text into numbers before comparing numbers.

Unicode, code points and UTF-8

Download this program (.py)Save it, open it in any editor and run it with python3 unicode.py.
What it is
Unicode gives every character of every language a number called a code point. "A" is 65, "₹" is 8377 (U+20B9). UTF-8 is the most common way to store those numbers as bytes.
Why we need it
Old ASCII had only 128 characters, enough for English but not for Hindi, Tamil, Chinese or emojis. Unicode covers more than 150,000 characters, so one program can handle every language.
How it works
A Python str holds code points, so len() counts characters. When you save to a file or send over a network, encode() turns the text into bytes and decode() turns bytes back into text. UTF-8 uses 1 byte for ASCII and 2, 3 or 4 bytes for other characters.
Code point rangeUTF-8 bytesExamples
0 to 1271A, z, 5, space
128 to 2,0472é, ñ, Greek and Arabic letters

Common mistake
Always say the encoding when you open a text file: open(name, encoding="utf-8"). Otherwise Python uses the system default, which is not UTF-8 on every Windows computer (Core 5.3).

Bottom line: use str for text inside your program, bytes only at the edges where data goes to a file or the network.

Going deeper: How CPython stores a str (PEP 393)

CPython looks at the largest code point in a string and picks 1, 2 or 4 bytes per character for the whole string. Pure ASCII text uses 1 byte each, a string with a rupee sign uses 2, and one emoji pushes it to 4. That is why sys.getsizeof("a") is 42 but sys.getsizeof of the emoji chr(128512) is 64 on Python 3.14. Indexing stays O(1) because every character in one string has the same width.

The maths of strings

Number of substrings of a text of length nExam favourite
n(n + 1) / 2
Pick a start and an end. "abc" has 6: a, b, c, ab, bc, abc.
Number of subsequences (keep or drop each letter)
2n
Including the empty one. "abc" has 8.
Number of different arrangements (anagrams)Exam favourite
n! / (c1! · c2! · ...)
ci is how often each letter repeats. "banana": 6! / (3! · 2! · 1!) = 60.
Caesar shift of a lower case letter
new = (ord(ch) − 97 + k) mod 26 + 97
mod 26 wraps z round to a.
Polynomial hash of a text (used in Rabin Karp search)
h = (c0·bn−1 + c1·bn−2 + ... + cn−1) mod m
Lets a program compare a window of text with a pattern in O(1) by sliding the hash one letter at a time.
Worked example: how many slices s[a:b] with a < b does "PYTHON" have?
  1. n = 6. A slice is fixed by a start a and an end b with 0 ≤ a < b ≤ 6.
  2. That is choosing 2 different numbers from the 7 numbers 0 to 6.
  3. C(7, 2) = 7 × 6 / 2 = 21
  4. This equals n(n + 1)/2 = 6 × 7 / 2 = 21, the number of substrings by position.

From beginner to expert

One idea, four depths

A string is text in quotes. You can read one character with s[i], cut a part with s[a:b] and join strings with +.

Strings are immutable, so methods return new strings. Use strip, split, join, replace, find and the is tests. Compare with ==, and know that comparison goes by code point.

A str is a sequence of Unicode code points. encode and decode move between text and bytes. Build large text with join, not +=. Use casefold() for case blind matching and say encoding="utf-8" for files.

CPython stores each string with a fixed width of 1, 2 or 4 bytes per character (PEP 393), caches its hash, and interns many identifiers. Real text processing must also think about Unicode normalisation (unicodedata.normalize, because "é" can be one or two code points) and grapheme clusters that look like one letter but are several code points.

Beginner
Make strings, index and slice them, and use upper, lower, strip and len.
Intermediate
Use split, join, find, replace and the is tests, loop over characters and compare strings correctly.
Expert
Explain code points, UTF-8 and the cost of +=, use slicing with negative steps without thinking, and handle text from any language.

Chapter summary

  1. A str is an ordered, immutable sequence of Unicode characters, written in single, double or triple quotes.
  2. A backslash starts an escape such as new line or tab. A raw string r"..." keeps backslashes.
  3. Indexing s[i] counts from 0 on the left and from −1 on the right. Slicing s[a:b:c] includes a, excludes b, and never fails.
  4. Strings cannot change. Methods such as upper, strip and replace return a new string.
  5. + joins, * repeats, in searches, and < compares by code point, so "Z" < "a" and "10" < "9".
  6. split cuts text into a list and "sep".join(list) glues it back. join is the fast way to build big text.
  7. ord and chr move between characters and code points. encode and decode move between str and UTF-8 bytes.
