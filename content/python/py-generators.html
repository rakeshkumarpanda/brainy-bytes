Lesson 1 of 10

Iterators and generators: one value at a time

Source: Python 3.14 glossary (iterable, iterator, generator), the iterator types and yield expressions documentation, inspect.getgeneratorstate, PEP 255, PEP 342, PEP 380, PCAP-31-03 block 5 and PCPP-32-101.

What it is
An iterable is anything you can loop over: a list, a string, a dict, a file, a range. An iterator is the object that walks through it and hands out the next value each time you call next(). A generator is the easiest way to write your own iterator: a normal function that uses yield instead of return.
Why we need it
Building a full list before you use it costs memory and time. A million lines from a log file, an endless stream of sensor readings or every possible password cannot all sit in memory. Often you also only need the first few results. Iterators make values only when asked, so memory stays small and work stops as soon as you stop asking.
How it works
Every for loop calls iter() once to get an iterator and then next() again and again until StopIteration is raised. A generator function returns a generator object. Each next() runs its body until the next yield, hands that value out and pauses, keeping all local variables. The next call continues from exactly that spot.

Common mistake
Raising StopIteration ends the loop. Do not raise it inside a generator body: since Python 3.7 (PEP 479) it is turned into RuntimeError. In a generator, simply return.

Remember
yield from other passes every value of other straight to whoever is asking, and when other finishes, its return value becomes the value of the yield from expression. It is the clean way to split a big generator into smaller ones, and it handles send and throw for you too.

Going deeper: Generators as coroutines

PEP 342 turned yield into an expression so generators could receive values, which made them simple coroutines. Early asyncio was built on yield from. Modern code uses async def and await (Advanced 5.2), which are coroutines designed for this job, but they follow the same idea of pausing and resuming a function.

list: about 8n bytes of pointers plus the items, generator: a constant (about 200 bytes)

Work done by a lazy searchExam favourite
items read = position of the first match (k), not n
Looking for the first even square above 50 in 1, 2, 3, ... reads 8 numbers and stops (8 × 8 = 64).

averagek = (x1 + x2 + ... + xk) / k
After 10, 20 and 60: (10 + 20 + 60) / 3 = 30.
Number of next() calls to see StopIteration
values + 1
countdown(4) gives 4 values, and the 5th call raises StopIteration.
Subsets and combinations (LeetCode 77 and 90)
subsets = 2n, combinations of k from n = n! / (k! (n − k)!)
From 5 numbers choose 2: 5! / (2! × 3!) = 10.
A pipeline of s stages over n items
time grows with n × s, memory with s only
106 lines through 4 stages: 4 × 106 stage steps, but only 4 paused generators in memory.
Worked example: how many lines does the error pipeline read for the first 2 errors?
  1. Line 1 is INFO: read, dropped.
  2. Line 2 is ERROR: read, passed on, first result.
  3. Line 3 is INFO: read, dropped. Line 4 is ERROR: read, second result, and islice stops asking.
  4. 4 lines read out of 6
Lesson 8 of 10

From beginner to expert

One idea, four depths

Loop over lists, strings, dicts and files. Use iter() and next() by hand, and know that StopIteration ends a for loop.

Write generator functions with yield, use them in for loops and with list(), sum() and islice(), and write iterator classes with __iter__ and __next__.

Build generator pipelines, use yield from to delegate and collect return values, and control generators with send, throw and close.

A generator object keeps a suspended frame: its local variables, its position (the last instruction) and its block stack. yield from forwards send and throw to the inner generator. PEP 479 turns StopIteration inside a generator into RuntimeError. These same suspended frames are what async def coroutines are built on.

Use the iterator protocol.

Chapter summary

  1. An iterable can give an iterator with iter(). An iterator gives values with next() and raises StopIteration at the end.
  2. A for loop is iter() once plus next() until StopIteration.
  3. An iterator class has __iter__ returning self and __next__. An iterable class returns a fresh iterator, so it can be looped over many times.
  4. A function with yield returns a generator. Each next() runs to the next yield and pauses, keeping its local variables.
  5. Generators use constant memory, can be endless and stop work early. Chain them into pipelines.
  6. yield from delegates to another generator and returns its return value. send, throw and close control a paused generator.
  7. range and dict views are lazy and reusable. zip, map, filter, enumerate and files are one shot iterators.
