What FastAPI is and why type hints matter

Source: FastAPI 0.162 documentation (tutorial, dependencies, security, background tasks, testing, async, lifespan, deployment) and Pydantic 2.14 documentation (models, fields, validators, JSON Schema).

What it is
FastAPI is a Python framework for building APIs. You write normal functions with type hints, such as book_id: int or book: BookIn, and FastAPI uses them to read the request, check it with Pydantic, write the JSON answer and produce live API docs.
Why we need it
In most frameworks the input rules live in one place (a serializer or form), the function signature in another and the docs in a third. They drift apart, and every endpoint repeats the same checking code. Many APIs also spend most of their time waiting for databases and other services.
How it works
The type hints are the single source: they check the input (422 when wrong), convert text to numbers and dates, filter the output with response_model and feed the OpenAPI docs at /docs. Depends gives shared parts such as the database and the user. async def endpoints let one process serve many waiting requests at once.

Download this program (.py)Run it with python3 pytest_api.py.
The pattern
  1. Keep the app in main.py and the tests in test_main.py.
  2. A fixture makes TestClient(app) and swaps the real store or database with dependency_overrides, so each test starts empty.
  3. Each test sends a request and checks the status code and the JSON with plain assert.
  4. pytest.mark.parametrize runs one test with many bodies, here three bad ones that must all give 422.
  5. Clear dependency_overrides after the test so it never leaks into the next one.
Real world scenario: a team that ships an API every day

A team runs a price API. Every pull request runs pytest in CI: about 300 tests with TestClient finish in a few seconds because no server or network is involved. The OpenAPI JSON is saved as a CI artifact, and the mobile team generates its client code from it, so a renamed field breaks the build at once instead of the app in production.

The maths: concurrency, workers and timeouts

Time with awaitExam favourite
total ≈ the longest single wait
10 requests that each wait 0.2 s: about 0.2 s.
Time with a blocked loopExam favourite
total ≈ n × wait
10 × 0.2 = 2.0 s.
Requests one process can hold (Little's law)Exam favourite
in flight = rate × time per request
500 requests a second at 0.2 s each: 100 in flight at once.
Thread pool limit
requests per second ≤ threads / time per request
40 threads at 0.2 s: at most 200 plain def requests a second per process.
Workers
workers ≈ 2 × CPU cores + 1 (a common start for sync servers)
4 cores: 9 workers. Async servers often use one worker per core.
Timeout budget
total ≤ sum of the calls in a row
Three calls of 0.3 s in a row: 0.9 s. In parallel with gather: about 0.3 s.
Worked example: one async worker or many threads?
  1. An endpoint calls a slow partner API that answers in 0.2 s, and the traffic is 500 requests a second.
  2. By Little's law 500 × 0.2 = 100 requests wait at the same time.
  3. A plain def endpoint has 40 threads per process, so one process manages at most 40 / 0.2 = 200 requests a second, and 3 processes are needed.
  4. An async def endpoint with httpx.AsyncClient keeps all 100 waiting requests on one event loop, so one process is enough, if the CPU work per request is small.
  5. waiting is cheap with await, and CPU work still needs more processes

Going deeper: ASGI, Starlette and Uvicorn

FastAPI is built on Starlette, a small ASGI toolkit that does the routing, requests, responses and WebSockets. ASGI is the async successor of WSGI: the server calls an async function with the request and awaits messages. Uvicorn is the ASGI server that speaks HTTP. FastAPI adds the type hint magic, Pydantic, dependencies and the docs on top.

Chapter summary

  1. FastAPI reads type hints: path, query, body and header values are converted and checked by Pydantic, and bad input gets 422 with locations.
  2. Pydantic models use Field limits, Literal, nested models and validators, and give model_dump and a JSON Schema for the docs.
  3. response_model shapes the answer, HTTPException sends errors, and /openapi.json, /docs and /redoc come for free.
  4. Depends shares the database, the user and paging. yield closes resources, and dependency_overrides swaps them in tests.
  5. Use async def only with awaitable libraries, plain def otherwise. A blocking call in async def stalls every request.
