Lesson 1 of 13

Inheritance: reuse a class

Source: Python 3.14 tutorial section 9.5 "Inheritance", the built-in functions super, isinstance and issubclass, the abc module documentation, M. Simionato "The Python 2.3 Method Resolution Order", and PCAP-31-03 section 3.

What it is
Inheritance lets a new class (the child, subclass or derived class) take all the attributes and methods of an existing class (the parent, superclass or base class) and then add to them or change them.
Why we need it
Many classes share most of their code: dogs and cats both have a name and can describe themselves. Writing that code again in each class means copies to keep in step. Inheritance writes it once in the parent, and each child only adds what is different.
How it works
class Dog(Animal): makes Dog a child of Animal. When you use rex.describe(), Python looks for describe in Dog, does not find it, and moves on to Animal. A method the child defines with the same name overrides the parent one.
Real world scenario: a family recipe

A family has a basic dal recipe. One cousin uses it exactly as it is. Another follows it but adds more chilli. A third keeps every step but swaps the last one for a coconut finish. Nobody rewrites the whole recipe: they inherit it and change only what they need.

Remember
The child is a special kind of the parent: a Dog is an Animal. If you cannot say "a Child is a Parent" in plain words, inheritance is probably the wrong tool (see composition below).

Overriding methods

How Python finds rex.speak()
  1. Look in rex.__dict__ (the object itself).
  2. Look in Dog, the class of rex. speak is there, so use it.
  3. Only if Dog had no speak would Python look in Animal, then in object.
  4. Not found anywhere: AttributeError.
In the exam
An overriding method normally keeps the same parameters as the parent one, so code that works with an Animal also works with a Dog. This rule is called the Liskov substitution principle.

Polymorphism and duck typing

Download this program (.py)Save it, open it in any editor and run it with python3 poly.py.
What it is
Polymorphism means one piece of code works with many types: make_noise(thing) calls thing.speak() without caring what thing is.
Why we need it
Without it you would write if type is Dog ... elif type is Cat ... everywhere, and add a branch for every new type.
How it works
Python does not check the type. It only looks up the method by name when the code runs. If the object has speak, it works. This is duck typing: if it walks like a duck and quacks like a duck, treat it as a duck.

Bottom line: Python mostly relies on duck typing. Use a common parent when the classes really share code.

The MRO and the diamond problem

Download this program (.py)Save it, open it in any editor and run it with python3 diamond.py.
C3 linearisationExam favourite
L[C] = C + merge(L[B1], ..., L[Bn], [B1, ..., Bn])
B1 ... Bn are the parents of C in the order written.
The merge rule
take the first head that is not in the tail of any list, remove it everywhere, repeat
If every head is in some tail, there is no valid order and Python raises TypeError.
Rules every MRO keeps
  1. A class comes before its parents.
  2. Parents keep the order you wrote them in: in D(B, C), B comes before C.
  3. Each class appears exactly once, so in the diamond A runs only once.
  4. object is always last.
Download this program (.py)Save it, open it in any editor and run it with python3 mroerror.py.
In the exam
super() does not mean "my parent". It means "the next class in the MRO of the object I am working on". Inside B, super().hello() went to C for a D object but to A for a B object. That is what lets every class in a diamond run exactly once.

The maths: areas, MROs and lookup cost

CircleExam favourite
A = πr2
Circle(2): 3.14159 × 4 = 12.57.
Heron for a triangleExam favourite
s = (a + b + c) / 2, A = √(s(s − a)(s − b)(s − c))
Triangle(3, 4, 5): s = 6, A = √(6 × 3 × 2 × 1) = 6.
Total area by polymorphism
total = sum of shape.area() for every shape
12.57 + 12 + 6 = 30.57, one loop for every kind of shape.
Length of an MRO
len(C.__mro__) = number of distinct ancestors + 1 (C itself), object included
Diamond D(B, C): D, B, C, A, object is 5.
Lookup cost
worst case one dict check per class in the MRO: O(len(MRO))
CPython caches the result per type, so repeated lookups are close to O(1).
Worked example: the MRO of the diamond with C3
  1. L[A] = [A, object]. L[B] = [B, A, object]. L[C] = [C, A, object].
  2. L[D] = D + merge([B, A, object], [C, A, object], [B, C]).
  3. Take B (in no tail). Next head A is in the tail of [C, A, object], so skip it and take C.
  4. Now A is free, then object.
  5. L[D] = [D, B, C, A, object]

From beginner to expert

One idea, four depths

Write class Child(Parent): to reuse the parent, override a method by writing it again, and call super().__init__ in the child __init__.

Use isinstance and issubclass, extend methods with super(), use polymorphism and duck typing, write abstract methods, and choose composition when "is a" does not fit.

Explain multiple inheritance, mixins, the MRO and the C3 rules, why super() follows the MRO of the object, and why some class orders raise TypeError.

C3 gives a linearisation that is monotonic (a class keeps the order of its parents in every child) and respects local precedence. super() is a proxy built from the type and the instance that searches the MRO after the given class. __init_subclass__ and metaclasses hook into class creation, and abc uses __subclasshook__ and register for virtual subclasses (Advanced 1.4).

Lesson 13 of 13

Chapter summary

  1. class Child(Parent): gives Child every attribute and method of Parent. Every class inherits from object in the end.
  2. Writing a method again in the child overrides it. Python looks in the object, then the class, then the parents in MRO order.
  3. super().__init__(...) runs the parent setup. A child __init__ without it skips the parent attributes. super().m() extends a method.
  4. isinstance(obj, C) counts children, type(obj) is C does not. issubclass, __bases__ and __mro__ show the family.
  5. Polymorphism: one call, many types. Duck typing needs only the right method name, not a shared parent.
  6. Abstract methods: raise NotImplementedError, or abc.ABC with @abstractmethod which blocks making the object.
  7. Multiple inheritance uses the C3 MRO: children before parents, parents in written order, each class once, object last. Impossible orders raise TypeError.
  8. Prefer composition (has a) to inheritance (is a) unless the child really is a kind of the parent.
