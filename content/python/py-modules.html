Lesson 1 of 15

Modules: code in many files

Source: Python 3.14 tutorial chapter 6, language reference chapter 5 "The import system", PCAP-31-03 section 1.

What it is
A module is a .py file whose functions, classes and variables other programs can use. A package is a folder of modules. import loads a module and gives you a name to reach what is inside.
Why we need it
One huge file is hard to read, test and share. Modules split a program into parts with clear jobs, let many programs reuse the same code, and give you the standard library: more than 200 modules for maths, dates, files, the web and much more, already installed. pip adds over half a million more from PyPI.
How it works
import name checks a cache (sys.modules). If the module is not loaded yet, Python searches the folders in sys.path, runs the file once from top to bottom in a new module object, stores it in the cache and binds the name. Later imports reuse the cached module.
Real world scenario: a toolbox with labelled drawers

A carpenter does not carry every tool in one heap. There is a drawer for measuring tools, one for saws, one for drills. "import math" opens the measuring drawer. "from math import sqrt" takes out just the one tool you need. The standard library is the toolbox that comes with Python, and pip is the shop where you buy new drawers.

Writing your own module

Download this program (.py)Save it, open it in any editor and run it with python3 makemod.py.
Common mistake
Any file name.py that Python can find is a module called name. Use lower case names with underscores, and never name your file after a standard module: a file called random.py in your folder hides the real random module, and import random gives you your own file.
Going deeper: __pycache__

When a module is imported, CPython compiles it to bytecode and saves it as __pycache__/name.cpython-314.pyc. The next import skips compiling if the .py file has not changed. The main script you run is compiled every time and never cached. You can delete __pycache__ folders safely, and they usually go in .gitignore.

if __name__ == "__main__"

Download this program (.py)Save it, open it in any editor and run it with python3 mainguard.py.
What it is
Every module has a name in __name__. When you run a file directly, its __name__ is "__main__". When it is imported, __name__ is the module name.
Why we need it
You often want one file to be both a library (functions others import) and a program (code that runs when you start it). Without the check, importing the file would also run the program part.
How it works
Put the program part in a main() function and call it under if __name__ == "__main__":. Importing the file then only defines the functions.

pip, PyPI and virtual environments

Installing packages (a typical session)shell
$ python3 -m venv .venv               # make a private environment for this project
$ source .venv/bin/activate          # Windows: .venv\Scripts\activate
(.venv) $ pip install requests       # download from PyPI and install
(.venv) $ pip list                   # what is installed
(.venv) $ pip show requests          # version, location, dependencies
(.venv) $ pip install "flask>=3.0"     # a version rule
(.venv) $ pip freeze > requirements.txt
(.venv) $ pip install -r requirements.txt
(.venv) $ pip uninstall requests
(.venv) $ deactivate
What it is
PyPI (the Python Package Index, pypi.org) hosts hundreds of thousands of packages. pip downloads and installs them. A virtual environment (venv) is a private folder of packages for one project.
Why we need it
Different projects need different versions: one app needs Django 4, another Django 5. Installing everything into the one system Python causes conflicts and can even break tools of your operating system.
How it works
python -m venv .venv makes the folder. Activating it puts its python and pip first on your PATH, so pip install goes into that project only. requirements.txt records exact versions so others can rebuild the same environment.
Remember
Run pip as python -m pip install ... when you are not sure which Python a plain pip belongs to. Modern projects describe their dependencies in a pyproject.toml file, and tools such as uv and poetry manage environments for you.

Maths you get from math and random

Combinations and permutationsExam favourite
C(n, k) = n! / (k!(n − k)!), P(n, k) = n! / (n − k)!
math.comb(5, 2) = 10, math.perm(5, 2) = 20.
Euclid: greatest common divisorExam favourite
gcd(a, b) = gcd(b, a mod b), gcd(a, 0) = a
gcd(84, 36) = gcd(36, 12) = gcd(12, 0) = 12. lcm(a, b) = a × b / gcd(a, b).
Change of base for logarithms
logb x = ln x / ln b
math.log(8, 2) = 3.0. Floats can make this 2.9999999999999996 for other numbers, so use log2 for base 2.
Expected value of a fair die (randint(1, 6))
E = (1 + 2 + ... + 6)/6 = 3.5
The mean of many rolls gets close to 3.5 (law of large numbers).
Monte Carlo estimate of π
π ≈ 4 × (points with x2 + y2 ≤ 1) / (all points)
Random points in a square, counted inside a quarter circle. The error shrinks like 1/√n.
Worked example: Euclid for gcd(1071, 462)
  1. 1071 mod 462 = 147, so gcd(1071, 462) = gcd(462, 147).
  2. 462 mod 147 = 21, so it equals gcd(147, 21).
  3. 147 mod 21 = 0, so it equals gcd(21, 0).
  4. gcd(1071, 462) = 21, which is what math.gcd(1071, 462) returns

From beginner to expert

One idea, four depths

import math gives you math.sqrt and friends. A .py file you write is a module you can import too.

Know every import form, the math, random and platform modules, packages with __init__.py, private _names, __all__, and if __name__ == "__main__". Install packages with pip inside a venv.

Imports are cached in sys.modules and searched along sys.path. Modules run once. Relative imports work inside packages. Avoid circular imports and file names that hide standard modules. Use secrets, not random, for security.

The import system is built from finders and loaders on sys.meta_path (importlib.machinery), which is how zip files, frozen modules and namespace packages are imported. Python 3.12 removed distutils, and packaging is now described by pyproject.toml (PEP 517, 518, 621) with build back ends such as setuptools and hatchling.

Beginner
Import a module three ways and use math and random.
Intermediate
Write your own module and package, use __name__ and __all__, and manage packages with pip and venv.
Expert
Explain sys.modules, sys.path, finders and loaders, and package a project with pyproject.toml.

Chapter summary

  1. A module is a .py file, a package is a folder of modules (usually with __init__.py).
  2. import math, import math as m, from math import sqrt, from math import sqrt as root. Avoid import *.
  3. import checks sys.modules, searches sys.path, runs the file once and caches it. importlib.reload runs it again.
  4. math: ceil, floor, trunc, sqrt, isqrt, hypot, factorial, comb, gcd, log, isclose. random: random, randint (both ends), randrange, choice, sample, shuffle, seed.
  5. A name starting with _ is private by convention. __all__ lists what import * takes.
  6. __name__ is "__main__" when a file is run directly. Guard the program part with if __name__ == "__main__":.
  7. pip installs packages from PyPI. Use a venv per project and record versions in requirements.txt.
