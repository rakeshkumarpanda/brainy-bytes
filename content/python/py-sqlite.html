Lesson 1 of 10

Databases and SQL from Python

Source: Python 3.14 documentation of sqlite3 and the SQLite documentation.

What it is
A database stores data in tables: rows of records with named columns, like a strict spreadsheet. You ask it questions in SQL (Structured Query Language). SQLite is a complete SQL database in one file, and Python ships with the sqlite3 module to use it, so there is nothing to install.
Why we need it
A JSON or CSV file must be read completely, changed in memory and written back completely. Two programs writing at once can destroy it, a crash halfway leaves half a file, and finding one record among millions means reading them all.
How it works
The database reads and writes only the pages it needs, finds rows fast with indexes, checks rules such as "balance may not be negative", and groups changes into transactions that are saved completely or not at all. SQL says WHAT you want and the database works out HOW to get it.

Bottom line: SQLite for one program or a small site, PostgreSQL for a web app with many users at once, pandas for analysis. The SQL you learn here works in all of them with small changes.

In the exam
The most common beginner bug: INSERT works, the program ends, and the data is gone. You forgot conn.commit(). Using "with conn:" commits for you.
Remember
SQL types in SQLite are flexible: INTEGER, REAL, TEXT, BLOB and NULL. Python int, float, str, bytes and None map to them. Store dates as ISO text such as "2026-11-07", because the automatic date converters are deprecated since Python 3.12.

Common mistake
Never put values into SQL with f-strings, +, % or .format(). Use ? or :name every time. Placeholders stop SQL injection, handle quotes in names like O'Neil, and let the database reuse the prepared statement.
In the exam
Placeholders are for VALUES only. A table or column name cannot be a ?. If a user picks the column to sort by, check it against a fixed list such as {"name", "price"} before you put it into the SQL.

Friendlier rows and fast lookups with indexes

Download this program (.py)Save it, open it in any editor and run it with python3 rows_index.py.
Remember
An index is a sorted copy of one column with a pointer to each row, kept in a B-tree. It turns a scan of every row into a few page reads. It costs disk space and makes INSERT and UPDATE a little slower, so index the columns you search, join or sort by often.
Going deeper: ORMs: databases without writing SQL

An ORM (object relational mapper) turns tables into classes and rows into objects. SQLAlchemy is the most used one, and Django has its own ORM, which the web part of this course uses. ORMs still create SQL for you, so knowing SQL helps you find slow queries and the "N+1 queries" problem, where a loop runs one query per row instead of one JOIN.

The maths: indexes, joins and estimates

Full scan
cost ≈ N rows read
Finding one user among 1,000,000 without an index reads 1,000,000 rows.
B-tree heightExam favourite
h = ⌈logf N⌉, f = keys per page (fan out)
N = 1,000,000 and f = 100: h = 3 page reads instead of a million rows.
Binary search in a sorted index
comparisons ≈ ⌈log2 N⌉
log2 1,000,000 ≈ 20.
Selectivity of WHERE a = vExam favourite
rows ≈ N / V(a), V(a) = number of different values
1,000,000 rows and 100 cities: about 10,000 rows per city.
Equi join size estimate
|R ⋈ S| ≈ |R| × |S| / max(V(R, a), V(S, a))
1000 customers, 5000 orders, joined on 1000 customer ids: 1000 × 5000 / 1000 = 5000 rows.
Cost of commits
time ≈ commits × time per disk sync
1000 inserts with 1000 commits at 5 ms each: 5 s. One commit: about 5 ms.
Worked example: how many page reads does an index save?
  1. A table has 2,000,000 rows. Each 4096 byte page holds 40 rows, so the table has 2,000,000 / 40 = 50,000 pages.
  2. A full scan reads all 50,000 pages.
  3. The index on the column holds about 200 keys per page, so its height is ⌈log200 2,000,000⌉ = 3, because 2002 = 40,000 is too small and 2003 = 8,000,000 is enough.
  4. Reading one row costs 3 index pages plus 1 table page.
  5. 4 page reads instead of 50,000: about 12,500 times fewer

Lesson 10 of 10

Chapter summary

  1. sqlite3 is a full SQL database in one file. connect, execute, commit, fetchone or fetchall, close.
  2. SQL runs in the order FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT. LEFT JOIN keeps rows without a partner.
  3. Always use ? or :name placeholders. f-strings in SQL cause SQL injection and break on quotes.
  4. "with conn:" makes a transaction: commit at the end, rollback on an exception. PRIMARY KEY, UNIQUE, NOT NULL, CHECK and foreign keys raise IntegrityError.
  5. sqlite3.Row gives rows by column name. Indexes turn a full scan into a few B-tree page reads, and EXPLAIN QUERY PLAN shows which one is used.
