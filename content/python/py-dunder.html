Special methods: make your class feel built in

Source: Python 3.14 data model reference section 3.3 "Special method names", the functools and fractions documentation, and PCPP-32-101 block 1.

What it is
Special methods (also called magic methods or dunder methods, for "double underscore") are methods with names like __add__ or __len__ that Python calls for you when you use an operator or a built in function on your object.
Why we need it
Built in types work with +, ==, len, in, for and print. Your own classes do not, unless you tell Python how. Without special methods you would write v.add(w) and v.equals(w), which is harder to read and does not work with sorted, sum, sets or dicts.
How it works
Python turns every operator into a method call on the type of the object: a + b becomes type(a).__add__(a, b), len(x) becomes type(x).__len__(x). Write those methods and your objects join in with every part of Python that uses them. Changing the meaning of an operator for your class is called operator overloading.
Real world scenario: a universal socket

A phone charger works in any socket because it has the standard plug shape. Python operators are the sockets. A special method is your class giving itself the standard plug, so + and len and for can use it like any built in type.

Arithmetic, reflected and unary operators

Download this program (.py)Save it, open it in any editor and run it with python3 vector.py.
What Python does for a + b
  1. Call type(a).__add__(a, b).
  2. If that method is missing or returns NotImplemented, call type(b).__radd__(b, a).
  3. If that is missing or returns NotImplemented too, raise TypeError: unsupported operand type(s).
  4. Special case: if b is an instance of a child class of type(a) that overrides __radd__, Python tries b first.
In the exam
Return the special value NotImplemented (not raise NotImplementedError) when your method cannot handle the other type. That gives the other object a chance to answer. Raising stops Python from trying.

The hash contract

Download this program (.py)Save it, open it in any editor and run it with python3 hashing.py.
The rules for __eq__ and __hash__
  1. If a == b, then hash(a) must equal hash(b). Otherwise sets and dicts will hold duplicates or lose items.
  2. Writing __eq__ sets __hash__ to None, so the class becomes unhashable until you write __hash__ too.
  3. Build the hash from the same fields that __eq__ compares, for example hash((self.x, self.y)).
  4. Only hash fields that never change. Changing a field after the object is in a set or dict hides it, as the last line shows.

Emulating containers

Remember
A class with only __len__ and __getitem__ already works with for, in, reversed and slicing. That is why Python calls this the sequence protocol. Inheriting from collections.abc.Sequence (or MutableSequence) also gives you index, count and more for free.
Going deeper: Slices are objects

p[1:3] passes a slice object slice(1, 3, None) to __getitem__. Its start, stop and step attributes, and its indices(len) method, let you handle any slice correctly. That is how NumPy supports a[1:3, ::2].

From beginner to expert

One idea, four depths

Write __repr__, __str__ and __eq__ so objects print nicely and compare by value.

Overload arithmetic and comparison operators, use total_ordering, keep __eq__ and __hash__ consistent, and make containers with __len__, __getitem__ and __contains__.

Return NotImplemented correctly, handle reflected and in place operators, accept slice objects, write __call__ and __format__, and use __getattr__ and __setattr__ without recursion.

Special methods are looked up on the type through slots (tp_as_number, tp_as_sequence in CPython), which is why setting them on an instance has no effect and why they are fast. Implicit lookups skip __getattribute__. The numbers and collections.abc hierarchies define which methods make a type a Number, a Sequence or a Mapping.

Beginner
Write __repr__, __str__ and __eq__.
Intermediate
Overload operators, comparisons, hashing and the container protocol.
Expert
Explain NotImplemented, reflected operands, slot lookup and the abc protocols.

Lesson 12 of 12

Chapter summary

  1. Operators and built in functions call special methods on the TYPE: a + b is type(a).__add__(a, b), len(x) is type(x).__len__(x).
  2. Return NotImplemented when you cannot handle the other operand. Python then tries the reflected method (__radd__ and friends) and finally raises TypeError.
  3. __repr__ for developers, __str__ for users, __format__ for format specs in f-strings.
  4. Comparisons: __eq__ and __lt__ plus functools.total_ordering. != comes free from __eq__.
  5. If a == b then hash(a) == hash(b). Writing __eq__ removes __hash__. Hash only fields that never change.
  6. Containers: __len__, __getitem__ (which may get a slice), __setitem__, __contains__, __iter__.
  7. __call__ makes objects callable. __iadd__ must return self. __getattr__ runs only when lookup fails, __setattr__ runs on every assignment.
