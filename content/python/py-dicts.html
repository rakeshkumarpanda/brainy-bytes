Lesson 1 of 16

What a dictionary is

Source: Python 3.14 tutorial section 5.5, the library reference section on dict, and PCEP-30-02 section 3.3.

What it is
A dictionary (type dict) stores key and value pairs. You look a value up by its key, not by a position: phone["Asha"] gives Asha's number.
Why we need it
With a list you must remember that Asha is at index 0 and Ravi at 1, and finding someone means checking every item. A dict lets you use a meaningful name as the index and finds it in one step, however many entries there are.
How it works
Each key is hashed to a number, and that number picks a slot in a table where the pair is stored. Keys must be unique and hashable. Values can be anything. Since Python 3.7 a dict also remembers the order in which keys were added.
Real world scenario: the contacts app on your phone

Your phone does not ask "which position is Ravi in?". You type the name and it shows the number. Names are keys and numbers are values. Two contacts cannot have exactly the same name, adding a new number for an old name replaces it, and the search is instant even with 2,000 contacts. That is a Python dict.

How a dict finds a key in one step

Download this program (.py)Save it, open it in any editor and run it with python3 internals.py.
What it is
A dict is a hash table. hash(key) gives a whole number, and that number decides where in the table the pair lives.
Why we need it
Looking up a name in a list of a million names may need a million checks. A hash table needs about one or two, so dict lookup, insert and delete take O(1) time on average.
How it works
CPython keeps two arrays. A small index table of size 8, 16, 32 ... holds entry numbers. An entries array holds (hash, key, value) in the order you added them, which is why dicts keep insertion order. The slot is hash mod size. If it is taken (a collision), Python probes other slots. When two thirds of the index table is used, the dict grows and every key is placed again.
Going deeper: Why hash(-1) is -2

Inside CPython, the C function that computes a hash returns −1 to say "an error happened". So no object may have the hash −1, and Python quietly uses −2 for the number −1. String hashes change every time Python starts (hash randomisation, PEP 456), to stop attackers from sending many keys that collide and make a web server slow.

The maths of hashing

Slot of a keyExam favourite
slot = hash(key) mod table size
Table sizes are powers of 2, so this is just the last few bits of the hash.
Load factorExam favourite
α = used slots / table size ≤ 2/3
A CPython dict with 8 slots holds at most 5 keys. The 6th key makes it grow.
New table size
smallest power of 2 ≥ 3 × (number of keys)
When the 6th key arrives, 5 keys are stored: 3 × 5 = 15, so the new size is 16.
Expected probes for a lookup that hits (uniform hashing)
about (1/α) ln(1/(1 − α))
At α = 2/3 this is about 1.6 probes, so lookups stay fast.
Chance that two of k keys share a slot of m (birthday problem)
1 − e−k(k − 1)/(2m)
With 23 people and 365 days the chance of a shared birthday is above 50 percent. Collisions are normal, so tables must handle them.
Worked example: when does a dict grow?
  1. Start with 8 slots. The limit is 2/3 of 8 = 5.33, so 5 keys fit.
  2. The 6th key finds the table full and it grows to 16 slots (limit 10).
  3. The 11th key grows it to 32 slots (limit 21), and the 22nd key to 64.
  4. Growth at keys 6, 11 and 22, which matches the sizes printed by the program above

From beginner to expert

One idea, four depths

A dict maps keys to values. d[key] reads, d[key] = value writes, and for key in d loops over the keys.

Use get with a default, pop, update and items(). Count with get(k, 0) + 1 and group with a dict of lists. Keys must be hashable and unique.

Use Counter and defaultdict, merge with |, build with comprehensions, never change the size while looping, and know that views are live. A nested dict is JSON.

CPython dicts are compact, ordered hash tables with a separate sparse index and a dense entry array (Raymond Hettinger, Python 3.6), open addressing with perturbed probing, and key sharing between instances of the same class. Hash flooding attacks are why string hashes use SipHash with a random key.

Beginner
Make a dict, read, add and change values, and loop over keys and items.
Intermediate
Count and group with a dict, use get and setdefault, and work with nested dicts and JSON.
Expert
Explain hashing, collisions, load factor and growth, choose Counter, defaultdict or OrderedDict, and reason about the cost of every operation.

Chapter summary

  1. A dict maps unique, hashable keys to any values. Write it as {key: value, ...}.
  2. d[k] reads (KeyError if missing), d.get(k, default) reads safely, d[k] = v adds or replaces.
  3. Remove with del, pop and popitem. Merge with update, | and |=.
  4. for k in d gives keys. Use values() and items() for the rest. Views are live, and changing the size while looping is an error.
  5. Count with d[k] = d.get(k, 0) + 1 or Counter. Group with a dict of lists or defaultdict(list).
  6. A dict is a hash table: lookup, insert and delete are O(1) on average. It grows when two thirds full and keeps insertion order.
  7. 1, 1.0 and True are the same key. Lists cannot be keys.
