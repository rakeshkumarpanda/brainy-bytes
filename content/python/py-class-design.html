Lesson 1 of 10

Designing classes well

Source: Python 3.14 documentation of classmethod, staticmethod, property, functools.cached_property, abc and dataclasses, the data model sections on __slots__ and descriptors, the Descriptor HowTo Guide, and PCPP-32-101 block 1.

What it is
Python gives you tools to say exactly what each part of a class is: methods that work on an object, on the class, or on neither, attributes that check their values (properties), classes that only describe a shape (abstract classes), and classes that are mostly data (dataclasses).
Why we need it
A class written with only plain methods and attributes lets callers store bad values, repeats boilerplate like __init__ and __repr__, and gives no clear contract for child classes. These tools fix each of those problems with one decorator.
How it works
@classmethod passes the class, @staticmethod passes nothing, @property turns attribute access into method calls, @abstractmethod blocks objects until children fill the gaps, and @dataclass writes __init__, __repr__ and __eq__ from type annotated fields.

Abstract base classes

Download this program (.py)Save it, open it in any editor and run it with python3 abc.py.
Remember
An abstract base class is a contract: "every Payment can pay and has a name". Python refuses to create an object until every abstract method is filled in, so a forgotten method fails at once instead of in front of a customer. collections.abc gives ready made contracts like Sized, Iterable, Sequence and Mapping.
Going deeper: Virtual subclasses

Payment.register(SomeClass) makes isinstance(SomeClass(), Payment) True without inheritance and without any checks. collections.abc uses __subclasshook__ instead, which is why Box counts as Sized just because it has __len__.

__slots__ and descriptors

Download this program (.py)Save it, open it in any editor and run it with python3 slots.py.
Remember
__slots__ removes the per object __dict__, so objects are smaller and adding a misspelt attribute fails at once. In Python 3.14 a normal object already keeps its attributes compactly until you touch __dict__, so the saving is smaller than older guides say: about a third in this run. Use slots for classes with very many objects.

In the exam
A descriptor is an object with __get__, __set__ or __delete__, stored as a class attribute. property, classmethod, staticmethod and every normal method are descriptors. Write your own when the same rule (like "must be positive") applies to many attributes in many classes.

The maths: conversions, ordering and memory

Celsius to Fahrenheit (a computed property)Exam favourite
F = C × 9 / 5 + 32
25 °C is 25 × 1.8 + 32 = 77 °F.
The other way
C = (F − 32) × 5 / 9
212 °F is 180 × 5 / 9 = 100 °C.
Absolute zero
C ≥ −273.15, so F ≥ −459.67
The setter rejects anything colder.
order=True compares as tuplesExam favourite
(a1, a2, ...) < (b1, b2, ...) at the first position where they differ
Version(3, 9, 7) < Version(3, 14, 0) because 9 < 14, even though "9" > "14" as text.
Memory for n objects
total ≈ n × bytes per object
1,000,000 objects at 40 bytes less each save about 40 MB.
Age from a birth year (ignoring the birthday)
age = current year − birth year
2026 − 1996 = 30.
Worked example: sorting Version(3, 14), Version(3, 9, 7), Version(3, 10, 2)
  1. As tuples: (3, 14, 0), (3, 9, 7), (3, 10, 2).
  2. All start with 3, so compare the second numbers: 14, 9, 10.
  3. 9 < 10 < 14, so the order is 3.9.7, 3.10.2, 3.14.0

From beginner to expert

One idea, four depths

Use @classmethod for alternative constructors, @staticmethod for helpers, and @property for computed or checked attributes.

Write setters and read only properties, abstract base classes with @abstractmethod, and dataclasses with defaults, default_factory, frozen and order.

Use cached_property, __post_init__, kw_only and slots, collections.abc contracts, and write descriptors with __set_name__ for rules shared by many attributes.

Attribute lookup: data descriptors on the class (property, slots) beat the instance __dict__, which beats non data descriptors (functions, cached_property) and plain class attributes. That order explains why a property cannot be hidden by vars(obj) while cached_property can store its answer in the instance dict. dataclass builds its methods with exec at class creation.

Beginner
Use class methods, static methods and properties.
Intermediate
Design with abstract classes and dataclasses.
Expert
Explain the descriptor protocol and the attribute lookup order.

Lesson 10 of 10

Chapter summary

  1. Instance methods get self, @classmethod gets cls (use it for alternative constructors), @staticmethod gets nothing.
  2. @property turns reads and writes into method calls: computed values, checks in a setter, read only attributes. Store the real value under _name.
  3. @cached_property computes once and stores the answer in the instance dict.
  4. Abstract base classes (ABC with @abstractmethod) are contracts: objects cannot be made until every abstract method exists.
  5. @dataclass writes __init__, __repr__ and __eq__. Use field(default_factory=list), frozen, order, __post_init__, kw_only and slots as needed.
  6. __slots__ removes the instance dict to save memory and stop new attributes.
  7. Descriptors (__get__, __set__, __set_name__) are the machinery behind property and methods, and let one rule serve many attributes.
