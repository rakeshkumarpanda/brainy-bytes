Lesson 1 of 16

What a list is

Source: Python 3.14 tutorial section 5.1 and PCEP-30-02 section 3.1.

What it is
A list is an ordered collection of items in square brackets, such as [72, 45, 91]. The items can be of any type and a list can change: you can add, remove and replace items.
Why we need it
With one variable per value, 500 student marks would need 500 names. A list keeps all of them under one name, keeps their order, and lets a loop visit each one. It is the most used collection in Python.
How it works
Like a string, each item has an index from 0, and you can slice. Unlike a string, a list is mutable: methods such as append and sort change the list itself. In CPython a list is an array of references to objects, with some spare room at the end so adding is fast.
Real world scenario: a shopping list on the fridge

Your family keeps one shopping list on the fridge. Anyone can add "milk" at the bottom (append), squeeze "eggs" in at the top (insert), cross out "sugar" (remove) or put it in shop order (sort). Everyone looks at the same paper, so a change by one person is seen by all. That last point is exactly how two names for one Python list behave.

Bottom line: use sorted() when you want to keep the original, sort() when you do not need it and want to save memory.

Going deeper: Timsort and stability

Python sorts with Timsort (Powersort since Python 3.11), which finds runs that are already in order and merges them. It takes O(n log n) time in the worst case and O(n) when the data is already sorted. It is stable: items with equal keys keep their old order. That is why sorted(words, key=len) keeps "banana" before "cherry": both have 6 letters and "banana" came first.

Names, aliases and copies

Download this program (.py)Save it, open it in any editor and run it with python3 alias.py.
What it is
A variable does not hold the list. It holds a reference to the list. b = a gives the same list a second name (an alias).
Why we need it
Copying a big list each time you pass it around would waste time and memory. Sharing is fast and lets a function change a list for its caller.
How it works
Use a[:], a.copy() or list(a) when you really want a second, separate list. Use is to check if two names point to the same object, and == to check if two lists have equal items.

Bubble sort, step by step

Download this program (.py)Save it, open it in any editor and run it with python3 bubble.py.
What it is
Bubble sort walks through the list and swaps any two neighbours that are in the wrong order. After each pass the largest item left "bubbles" to the end.
Why we need it
It is the easiest sort to understand, which is why the PCEP exam asks about it. It shows the ideas behind every sort: compare, swap, and repeat until nothing is out of order.
How it works
Pass k compares n − 1 − k pairs. If a whole pass makes no swap, the list is sorted and we stop.
Comparisons in the worst caseExam favourite
(n − 1) + (n − 2) + ... + 1 = n(n − 1)/2
5 items need at most 10 comparisons, 1,000 items about 500,000. That is O(n2).
Best case with the early stop
n − 1 comparisons
An already sorted list needs one pass.
Remember
Never use bubble sort in real code. sorted() is far faster. Learn it to understand sorting and to answer exam questions.

How CPython makes append fast

Download this program (.py)Save it, open it in any editor and run it with python3 growth.py.
What it is
A CPython list keeps a block of memory with more slots than it needs right now. len() is the number of slots in use, and the capacity is the number of slots it has.
Why we need it
If the list grew by exactly one slot on every append, each append would copy every item into new memory: n appends would cost about n2/2 copies.
How it works
When the list is full, CPython grows the capacity to about 1.125 times the new length plus a little (the rule in listobject.c is new = (n + n // 8 + 6) rounded down to a multiple of 4). Copies happen rarely, so the average cost of one append is O(1). This is called amortised O(1).

The maths of lists

Average cost of an append (amortised)Exam favourite
(n + total copies) / n < a small constant
With growth by a factor g > 1 the copies form a geometric series n/g + n/g2 + ... < n/(g − 1).
Bubble sort comparisonsExam favourite
n(n − 1)/2
The same sum as the triangle loop of Core 2.2.
Number of slices items[a:b] with a < b
C(n + 1, 2) = n(n + 1)/2
Choose 2 of the n + 1 cut points.
Mean of a list
sum(items) / len(items)
Undefined for an empty list: guard against ZeroDivisionError.
Binary search steps on a sorted list
⌊log2 n⌋ + 1
A sorted list of 1,000,000 items needs at most 20 checks with bisect (Advanced 4.2).
Worked example: total copies for 1,000 appends with doubling
  1. With doubling, copies happen when the list has 1, 2, 4, 8, ..., 512 items.
  2. The copies add up to 1 + 2 + 4 + ... + 512.
  3. 210 − 1 = 1,023 copies, about 1 per append
  4. CPython grows by about 1.125 instead of 2, which uses less memory and may copy up to about 8 items per append on average. Still a constant, so still O(1).

From beginner to expert

One idea, four depths

A list holds many items in order under one name. Use index and slice to read, append to add, and a for loop to visit every item.

Lists change in place. Know append vs extend, remove vs pop vs del, sort vs sorted, and that b = a shares one list. Copy with a[:].

Copies are shallow unless you use deepcopy. Never build a grid with [[0] * n] * n. Know the cost of each method and choose deque, set or dict when a list is slow.

A CPython list is a dynamic array of PyObject pointers with geometric over allocation, giving amortised O(1) append. Sorting uses an adaptive, stable merge sort (Timsort, with the Powersort merge policy since 3.11). Comparison sorts cannot beat Ω(n log n) comparisons in the worst case, because n! orders need log2(n!) yes or no answers to tell apart.

Beginner
Make lists, read items with index and slice, add with append and loop over them.
Intermediate
Use every list method correctly, copy lists safely, work with 2D lists and write bubble sort by hand.
Expert
Explain references, shallow and deep copies, the cost of each operation and the amortised analysis of append.

Chapter summary

  1. A list is an ordered, changeable collection in square brackets. Items can be of any type.
  2. Add with append, insert and extend. Remove with remove (by value), pop and del (by index) and clear.
  3. Find with in, index and count. All three walk the list, so they take O(n).
  4. sort() changes the list and returns None. sorted() returns a new list. Both take key and reverse and are stable.
  5. b = a shares one list. a[:], a.copy() and list(a) make a shallow copy, copy.deepcopy makes a full copy.
  6. Build grids with [[0] * n for _ in range(m)], never [[0] * n] * m.
  7. Bubble sort makes at most n(n − 1)/2 comparisons. append is amortised O(1) because CPython keeps spare room.
