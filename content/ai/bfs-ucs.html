Lesson 1 of 8

Uninformed search and breadth first search

Source: slide Set 2, slides 25 to 31, and the classes of 24 and 25 January 2026.

Uninformed (or blind) search uses a fixed rule to choose the next node. The rule is the same for every problem and uses no knowledge about where the goal is. The five uninformed methods of the course are breadth first, uniform cost, depth first, depth limited and iterative deepening search.

What it is
Breadth first search (BFS) expands the shallowest node first. It looks at every path of length 1, then every path of length 2, and so on, level by level.
Why we need it
When every action costs the same, the shallowest goal is also the cheapest. BFS is guaranteed to find it, and it never gets lost down one long branch.
How it works
Keep the frontier as a first in, first out queue. Take the oldest path out, and add its children at the back. Because children always go to the back, all short paths are taken out before any longer one.

Breadth first search (graph version)
function BFS(problem):
    node = start node
    if GOAL-TEST(node.STATE): return node
    frontier = FIFO queue with node
    reached = { start state }
    while frontier is not empty:
        node = POP the oldest node
        for each child of node:
            if child.STATE not in reached:
                if GOAL-TEST(child.STATE): return child      # early goal test
                add child.STATE to reached
                push child at the back of frontier
    return failure

Is BFS complete and optimal, and what does it cost

Complete: yes, if b is finite. The length of the path taken out of OPEN never goes down, because each expanded path is replaced by paths one step longer. So all paths of length d are examined before any of length d + 1, and a goal at depth d is found.

Optimal: it finds the solution with the fewest actions. That is the cheapest only if every action costs the same. On Romania, BFS returns Arad, Sibiu, Fagaras, Bucharest (cost 140 + 99 + 211 = 450), but the cheapest route is Arad, Sibiu, Rimnicu Vilcea, Pitesti, Bucharest (140 + 80 + 97 + 101 = 418).

Time of BFSExam favourite
1 + b + b² + ... + bd = O(bd)
With the goal test when a node is generated. If you test only when a node is taken out, the last level is generated too and the time is O(bd+1).
Space of BFSExam favourite
O(bd−1) explored + O(bd) frontier = O(bd)
Every node stays in memory. Memory, not time, is the real limit of BFS.

Common mistake

Worked example: goal test at generation against at expansion
  1. b = 2, goal at depth d = 3, and the goal is the last node of its level.
  2. Test at generation: we stop when the goal is generated, after 1 + 2 + 4 + 8 = 15 nodes at most.
  3. Test at expansion: every node of depth 3 is expanded before the goal is popped, so depth 4 is generated too: up to 15 + 16 = 31 nodes.
  4. early test: O(bd) late test: O(bd+1)
Lesson 3 of 8

Uniform cost search

Source: slide Set 2, slides 32 to 35.

What it is
Uniform cost search (UCS) always expands the path with the lowest path cost g(n). It is breadth first search ordered by cost instead of by depth.
Why we need it
Real actions have different costs. Roads have different lengths, flights have different prices. BFS ignores costs. UCS returns the cheapest path.
How it works
Keep the frontier as a priority queue ordered by g(n). Take out the cheapest path. Do the goal test only when a path is taken out, because a cheaper path to the goal may still be waiting. If a cheaper path to a state already in the frontier appears, replace the old one.

The Sibiu example of slide 34

Uniform cost search from Sibiu to Bucharest
  1. Expand Sibiu. Its children Rimnicu Vilcea (80) and Fagaras (99) go into the frontier.
  2. The cheapest is Rimnicu Vilcea (80). Expand it and add Pitesti with cost 80 + 97 = 177.
  3. The cheapest is now Fagaras (99). Expand it and add Bucharest with cost 99 + 211 = 310.
  4. A goal is in the frontier, but UCS does not stop. It takes out the cheapest, Pitesti (177), and finds a second path to Bucharest with cost 177 + 101 = 278.
  5. 278 is less than 310, so the old Bucharest path is discarded.
  6. Bucharest (278) is taken out next, so the answer is Sibiu, Rimnicu Vilcea, Pitesti, Bucharest, cost 278

From Arad, UCS takes cities out in this order of cost: Arad 0, Zerind 75, Timisoara 118, Sibiu 140, Oradea 146, Rimnicu Vilcea 220, Lugoj 229, Fagaras 239, Mehadia 299, Pitesti 317, Craiova 366, Drobeta 374 and finally Bucharest 418. It spreads out in all directions like a growing circle of equal cost, because it has no idea where Bucharest is.

Complete and optimal
if every action cost C(x, a, y) ≥ ε > 0
With zero cost actions UCS can loop for ever on a zero cost cycle.
Time and space of UCSExam favourite
O(b1 + ⌊C*⁄ε⌋)
C* is the cost of the optimal solution and ε the smallest action cost. The search may go about C*⁄ε levels deep. When all costs are equal this is bd+1.

Why uniform cost search is optimal: the three lemmas

Source: slide Set 2, slides 36 to 38.

Let c(n) be the cost of the path of node n. Assume every action costs at least ε > 0.

Lemma 1: costs taken out never go down
  1. Claim: if n2 is expanded immediately after n1, then c(n1) ≤ c(n2).
  2. Case 1, n2 was already on OPEN when n1 was chosen. Then c(n1) ≤ c(n2), or else UCS would have chosen n2.
  3. Case 2, n2 was added when n1 was expanded. Then n2 extends n1 by one action, so c(n2) ≥ c(n1) + ε > c(n1).
  4. either way c(n1) ≤ c(n2)
Lemma 2: every cheaper path is expanded first
  1. Claim: when n is expanded, every path with cost strictly less than c(n) has already been expanded.
  2. Take such a path nk = ⟨Start, s1, ..., sk⟩ with c(nk) < c(n), and its prefixes n0, n1, ..., nk.
  3. Let ni be the last prefix already expanded. Then ni+1 is on OPEN, and c(ni+1) ≤ c(nk) < c(n), since a prefix costs no more than the whole path.
  4. Then UCS would have expanded ni+1 instead of n, a contradiction. So the whole path nk was already expanded.
Lemma 3: the first path to a state is the cheapest
  1. Claim: the first time UCS expands a node n ending at state S, it has found a cheapest path to S.
  2. By Lemma 2, all cheaper paths were already expanded, and none of them ended at S.
  3. By Lemma 1, every path expanded later costs at least c(n).
  4. so the first goal path taken out is optimal
In the exam
This is why UCS tests the goal when a path is taken OUT, not when it is generated. In the Sibiu example, Bucharest was generated with cost 310 before the 278 path existed. Testing at generation would have returned the wrong answer.

The maths: geometric series and the cost bound

Geometric seriesExam favourite
∑i=0d bi = (bd+1 − 1) ⁄ (b − 1) ≤ bd · b ⁄ (b − 1)
The last level holds most of the nodes. For b = 10 it is about 90 percent of them.
Fraction of nodes in the last level
bd ⁄ ((bd+1 − 1) ⁄ (b − 1)) → (b − 1) ⁄ b
For b = 2 half the nodes are in the last level. For b = 10, 90 percent.
UCS depth bound
depth ≤ ⌊C* ⁄ ε⌋
A path of more than C*⁄ε actions costs more than C*, so UCS never needs to expand it before the goal.
Worked example: the UCS bound
  1. All road lengths are at least ε = 70 (the shortest Romania road is 70, Lugoj to Mehadia). The optimal cost is C* = 418.
  2. ⌊418 ⁄ 70⌋ = 5. A path of 6 roads costs at least 6 × 70 = 420 > 418, so UCS never expands a path with more than 5 roads.
  3. With b = 4 it generates at most about 41 + 5 = 4,096 nodes.
  4. the real search expands only 13 cities, so the bound is loose but safe
Worked example: BFS memory
  1. b = 10, d = 8, and each node needs 1 KB.
  2. Nodes up to depth 8: (10⁹ − 1) ⁄ 9 ≈ 1.11 × 10⁸.
  3. memory ≈ 1.11 × 10⁸ KB ≈ 111 GB

Bottom line: UCS is Dijkstra's algorithm with an early stop and lazy generation of the graph. That matters when the graph is huge or infinite, like a puzzle.

Real world scenario: a delivery app

A food delivery app finds the fastest route from the restaurant to you. Road segments take different times, so it cannot use BFS. A plain UCS from the restaurant spreads out in every direction. Real apps add a heuristic (chapter 3.1) to point the search toward you, and precompute shortcuts, so they answer in milliseconds on a country sized map.

Lesson 7 of 8

From intuition to research

One idea, four depths

BFS is like ripples in a pond: it checks everything one step away, then two steps away. UCS is the same but the ripples are measured in cost, like kilometres, not in steps.

BFS uses a FIFO queue, is complete and optimal for equal costs, and costs O(bd) time and space. UCS uses a priority queue on g(n), tests the goal at expansion, and is complete and optimal when costs are at least ε, with cost O(b1 + ⌊C*⁄ε⌋).

The proof of UCS optimality rests on one fact: the g values taken out of the queue never decrease. The same argument proves Dijkstra correct, and A* with a consistent heuristic (chapter 3.1) is UCS on modified costs C'(x, y) = C(x, y) − h(x) + h(y).

Bidirectional and frontier search variants cut memory by not storing the explored set. Research on very large graphs uses external memory BFS (on disk), parallel BFS on GPUs (the Graph500 benchmark), and bucket based priority queues (Dial's algorithm) when costs are small integers.

Going deeper: why A* with a consistent h is a special case of UCS

Define new costs C'(x, a, y) = C(x, a, y) − h(x) + h(y). Consistency h(x) ≤ C(x, a, y) + h(y) makes every C' ≥ 0. Along a path from s to n the new costs telescope: g'(n) = g(n) − h(s) + h(n) = f(n) − h(s). So ordering by g' is ordering by f = g + h, and UCS on C' expands exactly what A* expands on C. The three lemmas above then prove A* optimal for free.

Chapter summary

  1. Uninformed search uses a fixed selection rule and no knowledge about the goal.
  2. BFS: FIFO queue, level by level. Complete for finite b. Finds the fewest actions, which is cheapest only when all costs are equal. Time and space O(bd). Memory is the real limit.
  3. Test the goal when a node is generated in BFS (saves a whole level), but when it is taken out in UCS.
  4. UCS: priority queue on g(n). Complete and optimal when every cost is at least ε > 0. Cost O(b1 + ⌊C*⁄ε⌋).
  5. The proof: costs taken out never decrease (Lemma 1), so every cheaper path is expanded first (Lemma 2), so the first path to a state is the cheapest (Lemma 3).
  6. On Romania, BFS gives 450 with 3 roads and UCS gives 418 with 4 roads.
