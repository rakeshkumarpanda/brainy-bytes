Lesson 1 of 9

When dice decide part of the game

Source: slide Set 3, slide 11, and the class of 8 February 2026.

Minimax and alpha beta assume the opponent always picks the move that is worst for us. Many games are not like that. In backgammon, Ludo or snakes and ladders, a dice roll decides which moves are possible. In real life the "opponent" is often not clever at all: the weather, traffic, or a customer who acts at random with some known pattern. In class we said: the world does not always play optimally against you.

What it is
Expectimax is a game tree search where some nodes are chance nodes. A chance node does not choose. Its value is the average of its children, each weighted by its probability: the expected value.
Why we need it
If the next event is random, planning for the worst case (minimax) is too careful, and ignoring the randomness is wrong. The expected value tells you what you will get on average if you play the same move many times.
How it works
Build the tree with MAX nodes for your moves, chance nodes for random events, and (in expectiminimax) MIN nodes for the opponent. Leaves give utilities. Back the values up: max at MAX, min at MIN, and probability times value, added up, at chance nodes.
Expectimax value (slide 11)Exam favourite
V(s) = maxs′ ∈ successors(s) V(s′) for agent controlled states. V(s) = ∑s′ ∈ successors(s) p(s′ | s) V(s′) for chance states. V(s) = known for terminal states
The same recursion as minimax, with the MIN rule replaced by an expectation.
Expectimax (slide 11)
def value(state):
    if the state is a terminal state: return the state's utility
    if the agent is MAX: return max-value(state)
    if the agent is EXP: return exp-value(state)

def max-value(state):
    initialize v = −∞
    for each successor of state: v = max(v, value(successor))
    return v

def exp-value(state):
    initialize v = 0
    for each successor of state:
        p = probability(successor)
        v += p × value(successor)
    return v
Lesson 2 of 9

The expectimax example of the slides

Source: slide Set 3, slide 11.

MAX has three moves. Each leads to a chance node with three outcomes, each with probability 1/3. The outcome values are 3, 12, 9 for the first move, 2, 4, 6 for the second, and 15, 6, 0 for the third.

Back up the values
  1. First chance node: 1/3 × 3 + 1/3 × 12 + 1/3 × 9 = 24 ⁄ 3 = 8.
  2. Second chance node: 1/3 × 2 + 1/3 × 4 + 1/3 × 6 = 12 ⁄ 3 = 4.
  3. Third chance node: 1/3 × 15 + 1/3 × 6 + 1/3 × 0 = 21 ⁄ 3 = 7.
  4. MAX = max(8, 4, 7) = 8, so MAX takes the first move
Remember
If the same tree had MIN nodes instead of chance nodes, minimax would give min values 3, 2 and 0, and MAX would still pick the first move, but with value 3. The third move looks worst to minimax (0) and second best to expectimax (7). The two methods can choose different moves when the risk differs.

Expectiminimax: chance and an opponent

Source: slide Set 3, slide 12, and the class of 8 February 2026.

In backgammon both players roll dice. So the tree has four kinds of layers in turn: MAX, CHANCE (my roll), MIN, CHANCE (the opponent's roll). This is expectiminimax.

ExpectiminimaxExam favourite
EMM(s) = UTILITY(s) if terminal, maxa EMM(RESULT(s, a)) if MAX, mina EMM(RESULT(s, a)) if MIN, ∑r P(r) EMM(RESULT(s, r)) if CHANCE
r is a chance outcome, such as a dice roll.
The middle branch of slide 12
  1. The chance node has three outcomes with probabilities 0.5, 0.4 and 0.1. Each leads to a MIN node.
  2. MIN node 1 over 5, 4, 2 takes 2. MIN node 2 over 1, 7, 2 takes 1. MIN node 3 over 3, 4, 5 takes 3.
  3. Chance node: 0.5 × 2 + 0.4 × 1 + 0.1 × 3 = 1 + 0.4 + 0.3.
  4. = 1.7

The slide labels the bottom row CHANCE too. That row stands for the next chance layer of the game. Here we read its circles as the values that the search below returns.

What problems do you see here?

Source: slide Set 3, slides 11 and 12 ask these questions. The answers come from the class of 8 February 2026 and AIMA section 5.5.

ProblemWhy it hurtsSolution strategies
We must know the probabilitiesIn class: a coin tossed 1,000 times is never exactly 50:50, a coin may be biased, and probabilities from experience are skewed towards what we have seenEstimate from data, update the estimates as you play, or test how much the decision changes when the probabilities change a little
The tree is much biggerTime O(bm nm), where n is the number of chance outcomes. Backgammon has 21 distinct rolls of two dice and about 20 moves per rollDepth limit with an evaluation function, or sample a few rolls instead of all (Monte Carlo)
The size of the values mattersMinimax only cares about the order of the leaves. Expectimax averages, so stretching some values can change the choice (see below)The evaluation must be a positive linear function of the true expected payoff, for example the chance of winning
Pruning is harderOne unseen child of a chance node can change the average by any amountIf the values are bounded, say between 0 and 10, a chance node gets an upper bound after a few children, and alpha beta style pruning works again
The model of the opponent mattersExpectimax against a clever opponent can walk into a trap. Minimax against a random opponent is too carefulPick the model that fits: MIN nodes for an adversary, chance nodes for random behaviour
Why the size of the values matters (AIMA, chance 0.9 and 0.1)
  1. Move 1 leads to values 2 (chance 0.9) and 3 (chance 0.1). Move 2 leads to values 1 (0.9) and 4 (0.1).
  2. Move 1: 0.9 × 2 + 0.1 × 3 = 2.1. Move 2: 0.9 × 1 + 0.1 × 4 = 1.3. Choose move 1.
  3. Now change the values to 20, 30, 1, 400. The order of the four values is the same.
  4. Move 1: 0.9 × 20 + 0.1 × 30 = 21. Move 2: 0.9 × 1 + 0.1 × 400 = 40.9. Now choose move 2.
  5. the order is kept, but the choice flips: expectimax needs values on the right scale
Lesson 5 of 9

Monte Carlo tree search

Source: the class of 8 February 2026 ("certain advanced algorithms also come like Monte Carlo simulation") and Kocsis and Szepesvari, 2006.

What it is
Monte Carlo tree search (MCTS) chooses a move by playing many quick random games (rollouts) and keeping a win record for each move. It grows a search tree only where the results look promising.
Why we need it
For Go, b is about 250, and no one could write a good evaluation function by hand. Alpha beta cannot go deep enough. Random games need no evaluation function: the result of a finished game is the evaluation.
How it works
Repeat four steps. Selection: from the root, pick children by UCB1 until you reach a node with untried moves. Expansion: add one new child. Simulation: play random moves from it to the end. Back up: add the result to the win and visit counts of every node on the path. Finally play the root move with the most visits.
UCB1 (upper confidence bound)Exam favourite
UCB1(i) = wi ⁄ ni + C √(ln N ⁄ ni)
wi wins in ni visits of move i, N visits of the parent, C balances the two parts. The first part is exploitation (how good the move looks), the second is exploration (how unsure we still are). C = √2 ≈ 1.4 is the usual start.

With seed 2 the search gives move 2 (the truly best move, 60% wins) 9 of the 20 visits. Change the seed: with seed 1 it ends on move 1 after 20 rounds. Twenty random games are few. Real programs play thousands per move.

Remember
MCTS also handles chance naturally: a dice roll in a rollout is just one more random step. That is one reason it replaced expectimax in many games with dice and cards.
Lesson 6 of 9

The maths: expected value, UCB1 and cost

Expected valueExam favourite
E[X] = ∑x P(x) × x
The average result over many plays. The probabilities of the outcomes of one chance node add up to 1.
Linearity
E[a X + b] = a E[X] + b for a > 0
This is why a positive linear change of all values keeps the expectimax choice, while other changes may not.
Cost of expectiminimax
O(bm nm)
b moves and n chance outcomes per level, m levels of each.
Where UCB1 comes from
P(true mean > sample mean + ε) ≤ e−2 n ε² (Hoeffding)
Choose ε so the chance of being wrong falls like 1 ⁄ N⁴: ε = √(2 ln N ⁄ n). That is UCB1 with C = √2.
Worked example: dice in backgammon
  1. Two dice give 36 ordered results. A double such as 3 and 3 happens 1 way in 36.
  2. A mixed roll such as 3 and 5 happens 2 ways (3 then 5, or 5 then 3), so 2 in 36 = 1 in 18.
  3. Distinct rolls: 6 doubles + 15 mixed pairs = 21.
  4. n = 21 chance outcomes: 6 with p = 1/36 and 15 with p = 1/18
Worked example: one UCB1 value
  1. Move i: 3 wins in 5 visits. The root has N = 10 visits. C = 1.4.
  2. Exploitation: 3 ⁄ 5 = 0.6.
  3. Exploration: 1.4 × √(ln 10 ⁄ 5) = 1.4 × √(2.303 ⁄ 5) = 1.4 × √0.4605 = 1.4 × 0.679 = 0.950.
  4. UCB1 = 0.6 + 0.950 ≈ 1.55
Going deeper: Pruning chance nodes when values are bounded

Suppose every leaf lies between 0 and 10, and a chance node has three children with probability 1/3 each. After reading the first child, say 2, the largest the node can still become is (2 + 10 + 10) ⁄ 3 ≈ 7.33. If MAX above already has a move worth 8, this chance node can never win, so its other children can be skipped. This idea is called *-minimax (star minimax), due to Ballard (1983). It needs known bounds on the values.

Bottom line: use minimax with alpha beta for a clever opponent and no chance, expectimax when the other side is random, expectiminimax when both happen, and MCTS when b is huge or no good evaluation function exists.

Real world scenario: TD-Gammon and AlphaGo

TD-Gammon (Tesauro, 1992) played backgammon with a shallow expectiminimax search and a neural network evaluation learned by playing against itself, and reached the level of top human players. AlphaGo (2016) beat Lee Sedol at Go using MCTS guided by deep networks for move choice and position value. AlphaZero (2017) learned chess, shogi and Go from self play alone, with the same MCTS.

Lesson 8 of 9

From intuition to research

One idea, four depths

When luck is involved, think about the average result of a move, not only the worst one. If a move gives 3, 12 or 9 with equal chance, on average it gives 8.

Expectimax adds chance nodes whose value is ∑ p × value. Expectiminimax mixes MAX, MIN and chance layers. Cost O(bm nm). Values must be on the right scale. MCTS replaces exact backup by random rollouts and UCB1 selection.

UCB1 comes from the multi armed bandit problem: its regret grows only like log N (Auer, Cesa-Bianchi and Fischer, 2002). UCT applies UCB1 at every tree node and converges to the minimax value as the number of rollouts grows (Kocsis and Szepesvari, 2006). Expectimax is the same backup as the Bellman equation of a Markov decision process, which chapter 10 builds on.

AlphaZero uses PUCT, which adds a prior from a policy network to the exploration term, and replaces random rollouts by a value network. MuZero learns the game model itself. For hidden information (poker), counterfactual regret minimisation and its deep variants beat top professionals (Libratus, Pluribus).
