Lesson 1 of 8

What a constraint satisfaction problem is

Source: slide Set 4, slides 1 to 4, and the class of 8 February 2026.

In ordinary search a state is a black box: the algorithm can only ask "is this the goal?" and "what are the successors?". In a constraint satisfaction problem (CSP) the state has an inner structure, a set of variables with values, and the goal is described by rules, so the algorithm can look inside and reason.

What it is
A CSP has a set of variables X = {X1, ..., Xn}, a domain Di of allowed values for each variable, and a set of constraints C that say which combinations of values are allowed. A solution is a complete assignment that breaks no constraint.
Why we need it
Only the final assignment matters, not the path. Writing the problem as variables and constraints lets general methods prune huge parts of the space at once: one rule like "WA and NT differ" removes every assignment that breaks it.
How it works
Assign values one variable at a time, and after each choice use the constraints to remove values that can no longer work (constraint propagation). When a variable has no value left, go back (backtracking, chapter 5.2).

Example 1: colouring the map of Australia

PartValue
VariablesWA, NT, SA, Q, NSW, V, T
DomainsDi = {red, green, blue}
ConstraintsNeighbouring regions differ: WA ≠ NT, WA ≠ SA, NT ≠ SA, NT ≠ Q, SA ≠ Q, SA ≠ NSW, SA ≠ V, Q ≠ NSW, NSW ≠ V

The constraint graph has a node for each variable and an edge for each binary constraint. Tasmania (T) has no edges, so it is an independent sub problem: any colour works.

Node and arc consistency

Source: slide Set 4, slide 6.

What it is
Constraint propagation removes values from domains that cannot be part of any solution, before or during search. Node consistency handles unary constraints and arc consistency handles binary ones.
Why we need it
Every value removed now is a whole branch the search never has to try. Sometimes propagation alone solves the problem or proves it impossible, with no search at all.
How it works
A variable is node consistent if every value in its domain satisfies its unary constraints, so dom(B) = {1, 2, 3, 4} is not node consistent under B ≠ 3. An arc ⟨X, r(X, Y)⟩ is arc consistent if for each value x in dom(X) there is some y in dom(Y) with r(x, y) true. If not, delete the values of X that have no partner.
Arc consistencyExam favourite
∀ x ∈ dom(X) ∃ y ∈ dom(Y): r(x, y)
Every value of X has a supporting value of Y. A network is arc consistent when all its arcs are.
The three outcomes (slide 6)
a domain is empty ⇒ no solution. Every domain has one value ⇒ the unique solution. Some domains have several values ⇒ search is still needed
Arc consistency alone does not always decide the problem.

The constraint network of the slides has one node per variable, one node per constraint, and an edge between a variable and each constraint it appears in. Each binary constraint gives two arcs, one in each direction.

The AC-3 algorithm

Source: slide Set 4, slide 7.

AC-3
function AC-3(csp):
    queue = all arcs (X, Y) of the csp
    while queue is not empty:
        (X, Y) = remove the first arc
        if REVISE(X, Y):
            if dom(X) is empty: return false          # no solution
            for each neighbour Z of X except Y: add (Z, X) to queue
    return true

function REVISE(X, Y):
    revised = false
    for each x in dom(X):
        if no y in dom(Y) satisfies the constraint with x:
            delete x from dom(X) and set revised = true
    return revised
AC-3 on the slide network A < B < C with domains {1, 2, 3}
  1. Arc (A, B): A = 3 has no larger B. Remove 3 from A. dom(A) = {1, 2}.
  2. Arc (B, A): B = 1 has no smaller A. Remove 1 from B. dom(B) = {2, 3}.
  3. Arc (B, C): B = 3 has no larger C. Remove 3. dom(B) = {2}. Add (A, B) to the queue again.
  4. Arc (C, B): C must be larger than 2, so C = 3. dom(C) = {3}.
  5. Arc (A, B) again: A must be less than 2, so A = 1.
  6. A = 1, B = 2, C = 3: every domain has one value, the unique solution, found with no search
Cost of AC-3Exam favourite
O(c d³)
c binary constraints, domains of size at most d. Each arc can be added to the queue at most d times (once per value deleted from its head), and REVISE costs d² checks.

Forward checking against arc consistency

Source: slide Set 4, slide 7.

Two kinds of inference
Forward checkingArc consistency (AC-3)
What it checksOnly arcs from the variable just assigned to its unassigned neighboursEvery arc in the network, again and again until nothing changes
StrengthWeakerStronger: it also catches conflicts between two unassigned variables
Cost per stepCheap: O(d) per neighbourHeavier: up to O(c d³)
Australia, after WA = red and Q = greenNT = {blue}, SA = {blue}, and no failure is seen yetChecks NT against SA, finds both must be blue, empties a domain: failure detected at once

Bottom line: forward checking is cheap and often enough. Running AC-3 after each choice (MAC, chapter 5.2) prunes more and is the usual choice for hard problems.

Stronger consistency

LevelMeaning
Node (1 consistency)Each value meets its unary constraints
Arc (2 consistency)Each value of a variable has a partner in every neighbour
Path (3 consistency)Each consistent pair (x, y) can be extended to any third variable z
k consistencyAny consistent assignment to k − 1 variables extends to any k-th variable
Strong n consistencyk consistent for every k ≤ n: then a solution can be found with no backtracking, but reaching it costs exponential time in general
Common mistake
Arc consistency cannot see that 2 colours are not enough for a triangle WA, NT, SA: each arc on its own is fine ({red, blue} against {red, blue}). Path consistency catches it.

The maths: counting assignments and solutions

Number of complete assignmentsExam favourite
dn
n variables, domain size d. Australia: 37 = 2,187.
Naive search treeExam favourite
n! · dn leaves
If any unassigned variable can be chosen at each level: n d choices at the top, (n − 1) d next, and so on. Fixing the variable order (assignments commute) brings it back to dn.
Solutions of the Australia map
3 × 2 × 3 = 18
Pick SA (3 ways). WA, NT, Q, NSW, V form a chain around SA and must alternate the other two colours (2 ways). T is free (3 ways).
Worked example: why fixing the order matters
  1. Australia has n = 7 and d = 3.
  2. Naive tree: 7! × 3⁷ = 5,040 × 2,187 = 11,022,480 leaves.
  3. With a fixed order: 3⁷ = 2,187 leaves.
  4. assignments commute (WA = red then NT = green is the same as the reverse), so a CSP search needs only dn
Worked example: Boolean N queens
  1. 4 queens with Xij: 16 Boolean variables.
  2. Complete assignments: 2¹⁶ = 65,536.
  3. With one variable per column (domain size 4): 4⁴ = 256.
  4. a good formulation shrinks the space 256 times
Lesson 7 of 8

From intuition to research

One idea, four depths

A CSP is like a seating plan: everyone needs a seat (a value), and some people cannot sit next to each other (constraints). You fill seats one by one and cross out seats that would break a rule.

A CSP is (X, D, C). Constraints can be unary, binary, global or soft. Node consistency fixes unary constraints, arc consistency makes every value have a partner. AC-3 runs in O(c d³) and ends with an empty domain (no solution), single values (unique solution) or a need to search.

Any finite CSP can be turned into a binary CSP using auxiliary variables (dual graph). Global constraints have special propagators, for example Alldiff with matching gives stronger pruning than pairwise ≠. Strong k consistency removes the need to backtrack but costs exponential time in k.

Modern solvers mix constraint propagation with SAT style clause learning (lazy clause generation), and constraint programming is used for industrial scheduling, rostering and chip verification. Research studies tractable classes by the structure of the constraint graph (tree width) and by the type of constraints (CSP dichotomy theorem, proved in 2017).

Real world scenario: university exam timetabling

Each exam is a variable, its domain is the set of time slots, and two exams that share a student must not be in the same slot (a binary ≠ constraint, like map colouring). Room capacity gives global constraints, and "no student has two exams in one day" gives more. Universities solve this every term with constraint solvers that combine propagation and search.

Chapter summary

  1. A CSP is variables X, domains D and constraints C. A solution assigns every variable with no constraint broken. Only the final assignment matters.
  2. Examples: Australia map colouring (37 = 2,187 assignments, 18 solutions), N queens (Boolean Xij or one variable per column), and car assembly scheduling with precedence and disjunctive constraints.
  3. Constraints are unary, binary, global (Alldiff) or soft (preferences).
  4. Arc consistency: every value of X has a partner in Y. AC-3 repeats REVISE until no arc changes, in O(c d³).
  5. Outcomes: an empty domain means no solution, single values give the unique solution, otherwise search is needed. A < B < C with {1, 2, 3} gives A = 1, B = 2, C = 3.
  6. Forward checking only looks at the arcs from the variable just assigned. Arc consistency looks at all arcs and finds failures earlier.
