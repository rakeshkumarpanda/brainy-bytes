Lesson 1 of 8

Two heuristics for the 8 puzzle

Source: slide Set 2, slides 54 to 56 (food for thought IV), and AIMA 4th ed., section 3.6.

The 8 puzzle has 8 numbered tiles and one blank on a 3 × 3 board. A move slides a tile into the blank. The average solution of a random puzzle is about 22 moves, and there are 9! ⁄ 2 = 181,440 reachable states. Two classic heuristics:

h1: misplaced tiles
h1(n) = number of tiles not in their goal square
Every misplaced tile needs at least one move.
h2: Manhattan distanceExam favourite
h2(n) = ∑tiles (|row − goal row| + |column − goal column|)
Every tile needs at least as many moves as its distance in rows plus columns.

For the textbook start state, all 8 tiles are misplaced, so h1 = 8, and h2 = 3 + 1 + 2 + 2 + 2 + 3 + 3 + 2 = 18. The true solution needs 26 moves. Both heuristics are admissible, and h2 is closer to the truth.

What it is
A good heuristic is admissible (never too big) and as large as possible, so it is close to the true cost h*.
Why we need it
The closer h is to h*, the fewer nodes A* expands. With h = h* A* walks straight to the goal. With h = 0 it is uniform cost search.
How it works
Find h by solving an easier version of the problem exactly (a relaxed problem), or by storing exact costs of sub problems (pattern databases), and take the max of several admissible heuristics.
Lesson 2 of 8

Relaxed problems: where heuristics come from

A relaxed problem has fewer rules than the real one. Every solution of the real problem is still a solution of the relaxed one, so the cost of the optimal relaxed solution can never be larger than the real optimal cost. That makes it an admissible heuristic. It is also consistent, because it is an exact cost in a real (relaxed) problem.

Real world scenario: food for thought V from the slides

Making a cup of tea: a relaxation lets you do every step at once, so h = number of steps not done yet (water not boiled, no tea, no milk, ...). It is admissible because every step must still be done at least once. For buying a book, h = number of checkout stages left. For a doctor, h might be the number of tests still needed to separate the remaining possible diseases.

Dominance and combining heuristics

DominanceExam favourite
h2 dominates h1 if h2(n) ≥ h1(n) for every n, and both are admissible
Then A* with h2 expands no more nodes than A* with h1 (apart from ties).
Why
A* surely expands every n with f(n) < C*, that is h(n) < C* − g(n)
A node with h2(n) < C* − g(n) also has h1(n) < C* − g(n). So every node expanded with h2 is also expanded with h1.
CombiningExam favourite
h(n) = max(h1(n), ..., hk(n))
The max of admissible heuristics is admissible, and it dominates each of them. The max of consistent heuristics is consistent.
Worked example: Manhattan dominates misplaced
  1. A misplaced tile is at distance at least 1 from its goal square.
  2. So each misplaced tile adds 1 to h1 and at least 1 to h2. A tile in place adds 0 to both.
  3. So h2(n) ≥ h1(n) for every n.
  4. the start state: h2 = 18 ≥ h1 = 8

Lesson 4 of 8

Pattern databases and learned heuristics

What it is
A pattern database (PDB) stores the exact cost to solve a sub problem, for example to put tiles 1 to 4 in place while the other tiles count as "don't care", for every possible position of those tiles.
Why we need it
Manhattan distance treats tiles as independent, so it misses how tiles block each other. A PDB captures those interactions exactly for a group of tiles, giving a much larger admissible h.
How it works
Before the search, run a backward BFS from the goal in the abstract space of the pattern tiles and store each cost in a table. During the search, look up the pattern of the current state. Take the max over several PDBs.
Disjoint pattern databasesExam favourite
h = PDB(tiles 1 to 4) + PDB(tiles 5 to 8)
Adding two PDBs is admissible only if each counts only the moves of its own tiles. Then no move is counted twice.
Size of a PDB
for k pattern tiles plus the blank on 9 squares: 9! ⁄ (9 − k − 1)! entries
For k = 4: 9 × 8 × 7 × 6 × 5 = 15,120 entries.
Going deeper: learning heuristics from data

A heuristic can be learned: solve many random instances, record features of each state (Manhattan distance, linear conflicts, number of tiles in the right row) and the true cost, and fit a model such as a linear regression h(n) = c1 x1(n) + c2 x2(n). A learned h is usually not admissible, so A* loses its guarantee, but it can find near optimal answers much faster. DeepCubeA (2019) learned a neural network heuristic for the Rubik's cube with reinforcement learning and solved it with weighted A*.

The maths: effective branching factor

Effective branching factor b*Exam favourite
N + 1 = 1 + b* + (b*)² + ... + (b*)d
N nodes generated for a solution at depth d. b* is the branching factor a uniform tree of depth d would need to hold N + 1 nodes. A good heuristic has b* close to 1.
Worked example: N = 52, d = 5
  1. We need 1 + b + b² + b³ + b⁴ + b⁵ = 53.
  2. b = 1.9: 1 + 1.9 + 3.61 + 6.86 + 13.03 + 24.76 = 51.2, a bit low.
  3. b = 1.92: 1 + 1.92 + 3.69 + 7.08 + 13.59 + 26.09 = 53.4, a bit high.
  4. b* ≈ 1.92
Worked example: what one heuristic is worth
  1. At d = 20, b* = 1.63 for BFS and 1.29 for A*(h2).
  2. 1.63²⁰ ≈ 17,500 and 1.29²⁰ ≈ 163.
  3. a smaller b* compounds over every level, which is why a good h wins by orders of magnitude

Bottom line: pick the largest admissible heuristic that is cheap to compute. Dominance tells you which is better without running anything.

Common mistake
Larger is better only while h stays admissible. 2 × h2 is larger, but it overestimates, so A* may then return a longer solution.
Lesson 7 of 8

From intuition to research

One idea, four depths

A heuristic is a smart guess. For the sliding puzzle, count how far each tile is from home. The better the guess, the less you need to try.

Get admissible heuristics from relaxed problems. If h2 ≥ h1 everywhere, A* with h2 expands no more nodes. Measure a heuristic with the effective branching factor b*. Combine heuristics with max.

Pattern databases store exact abstract costs, disjoint PDBs can be added, and the 15 puzzle is solved optimally in milliseconds with them. The time to compute h must be weighed against the nodes saved.

Research looks at heuristics from abstraction hierarchies, landmark heuristics in planning (chapter 8.2), cost partitioning to add many heuristics safely, and neural heuristics trained by self play (DeepCubeA), with work on keeping bounded suboptimality when h is learned.

Chapter summary

  1. 8 puzzle: h1 = misplaced tiles, h2 = Manhattan distance. The textbook start has h1 = 8, h2 = 18 and needs 26 moves.
  2. A relaxed problem removes rules. Its exact cost is an admissible and consistent heuristic (h1, h2, straight line distance).
  3. Dominance: if h2 ≥ h1 and both are admissible, A* with h2 expands no more nodes. The max of admissible heuristics is admissible.
  4. Effective branching factor b* solves N + 1 = 1 + b* + ... + (b*)d. At d = 20 we measured 1.63 for BFS, 1.45 for h1 and 1.29 for h2.
  5. Pattern databases store exact costs of sub problems. Disjoint ones can be added.
