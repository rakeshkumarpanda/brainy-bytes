Lesson 1 of 8

Backtracking search

Source: slide Set 4, slide 5, and the class of 8 February 2026.

What it is
Backtracking search is depth first search that assigns one variable at a time and goes back as soon as a constraint is broken.
Why we need it
Arc consistency alone often leaves several values per variable. Plain search over complete assignments tries all dn of them. Backtracking checks constraints after each single choice, so a bad partial assignment is abandoned at once, together with every completion of it.
How it works
Pick an unassigned variable, try each value in its domain, and keep a value only if it fits with the values already chosen. Recurse. If no value works, undo the last choice and try that variable's next value.
BACKTRACKING-SEARCH (AIMA figure 6.5)
function BACKTRACK(assignment, csp):
    if assignment is complete: return assignment
    var = SELECT-UNASSIGNED-VARIABLE(csp, assignment)        # MRV, degree
    for each value in ORDER-DOMAIN-VALUES(var, assignment):  # LCV
        if value is consistent with assignment:
            add {var = value} to assignment
            inferences = INFERENCE(csp, var, value)          # forward checking or MAC
            if inferences is not failure:
                add inferences to csp
                result = BACKTRACK(assignment, csp)
                if result is not failure: return result
                remove inferences from csp
            remove {var = value} from assignment
    return failure

Backtracking only needs to consider one variable per level, because assignments commute: WA = red then NT = green is the same as NT = green then WA = red. That shrinks the tree from n! dn to dn leaves.

In the fixed order WA, NT, NSW, Q, SA, V, T, the choices WA = red, NT = green, NSW = red force Q = blue, and then SA has no colour left. Backtracking undoes Q and then NSW, tries NSW = green, and succeeds.

Which variable next, which value first

Source: slide Set 4, slide 5.

HeuristicRuleWhy it helpsSlide example
Minimum remaining values (MRV), also "most constrained variable" or "fail first"Choose the variable with the fewest legal values leftIf some variable has no values left, MRV picks it and the failure is found at once, before wasting time on othersAfter WA and NT are coloured, SA has only one colour left, so colour SA next
Degree heuristicChoose the variable involved in the most constraints on other unassigned variablesLowers the branching factor of future choices. Used to break ties of MRV, and at the very start when all domains are equalChoose SA first: it has degree 5
Least constraining value (LCV)Try first the value that rules out the fewest choices for neighbouring variablesLeaves the most room for the rest, so a solution is found soonerAfter WA = red and NT = green, Q = blue would remove SA's last value, so LCV prefers Q = red
In the exam
Variable ordering is fail first: pick the hardest variable so a dead end shows up early. Value ordering is succeed first: pick the value most likely to work. When you want all solutions, or none exists, value ordering does not matter, because every value gets tried anyway.

With MRV, degree tie breaking, LCV and forward checking, SA is chosen first and the map is coloured with no backtracking at all.

Lesson 3 of 8

Forward checking and maintaining arc consistency

What it is
Inference during search removes values from the domains of unassigned variables right after each choice.
Why we need it
Without inference, backtracking only notices a problem when it reaches the stuck variable, possibly many levels later. Inference notices it immediately, when a domain becomes empty.
How it works
Forward checking: after X = x, remove x (or any value in conflict with it) from the domain of each unassigned neighbour of X. MAC (maintaining arc consistency): after X = x, run AC-3 starting with the arcs (Y, X) for the unassigned neighbours Y, so the removals spread through the whole network.
Forward checking on Australia (fixed order)
  1. WA = red. Remove red from NT and SA.
  2. NT = green. Remove green from SA and Q. SA = {blue}.
  3. NSW = red. Remove red from Q and V. Q = {blue}.
  4. Q = blue. Remove blue from SA. SA = { } is empty, so this branch fails at once, without trying SA.
  5. forward checking spots the dead end one level earlier than plain backtracking
Common mistake
Forward checking misses conflicts between two unassigned variables. After WA = red and Q = green, NT and SA both have only blue left and are neighbours. Forward checking does not see it. MAC does, because it also checks the arc NT, SA.
Lesson 4 of 8

Smarter backtracking: backjumping and learning

Plain backtracking goes back to the most recent variable (chronological backtracking), even if that variable had nothing to do with the failure.

Example: why chronological backtracking wastes time
  1. Fixed order Q, NSW, V, T, SA, WA, NT. Assign Q = red, NSW = green, V = blue, T = red.
  2. SA neighbours Q, NSW and V, which use all three colours, so SA has no value.
  3. Chronological backtracking goes back to T and tries T = green, then T = blue. Neither helps: T is not connected to SA.
  4. backjumping goes straight back to V, the most recent variable in SA's conflict set {Q, NSW, V}
MethodIdea
BackjumpingJump back to the most recent variable in the conflict set of the failed variable (the assigned variables that removed its values)
Conflict directed backjumpingWhen jumping back from X to Y, add X's conflict set (minus Y) to Y's, so the next jump from Y can also skip unrelated variables
Constraint learning (no goods)Record the smallest set of assignments that caused the failure, for example {Q = red, NSW = green, V = blue}, and never try that combination again
Symmetry breakingIn map colouring, any solution with colours permuted is also a solution. Fix WA = red at the start to cut the work by 3! = 6
Remember
Forward checking already finds every conflict that simple backjumping would jump over, so backjumping adds little to forward checking. Conflict directed backjumping and learning do add power, and they are the core of modern SAT solvers.

The maths: branching and pruning

Worst case of backtrackingExam favourite
O(dn)
Every partial assignment may be extended until the last variable. General CSPs are NP complete (3 colouring is), so no method avoids this in the worst case.
Forward checking cost per assignment
O(e d) at most, e = number of neighbours
Each neighbour loses at most the conflicting values.
Symmetry
k colours ⇒ k! equivalent solutions
Fixing the first colour divides the search by k, fixing an ordering of all colours by k!.
Worked example: nodes visited in the fixed order
  1. Plain backtracking on Australia in the fixed order tries 17 colours in total (the code prints this count).
  2. With MRV, degree, LCV and forward checking, 7 choices are made and none is undone.
  3. The full space has 3⁷ = 2,187 complete assignments.
  4. good ordering and inference turn search into almost straight line decisions
Worked example: LCV counts
  1. After WA = red and NT = green, Q can be red or blue.
  2. Q = red removes red from NSW (and SA has no red). Remaining values for SA and NSW: SA {blue}, NSW {green, blue}: total 3.
  3. Q = blue removes blue from SA and NSW. Remaining: SA { }, NSW {red, green}: total 2, and SA is empty.
  4. LCV prefers Q = red, which leaves more choices

Bottom line: the structure of a CSP gives general purpose heuristics for free. That is the big win of formulating a problem as a CSP.

Real world scenario: Sudoku

A Sudoku is a CSP with 81 variables, domains {1, ..., 9}, and 27 Alldiff constraints (rows, columns, boxes). Newspaper puzzles are usually solved by arc consistency alone. Harder ones need search, and MRV picks the cell with the fewest candidates first, which is exactly what a human expert does when they look for a cell with only one or two possible digits.

Lesson 7 of 8

From intuition to research

One idea, four depths

To colour a map, start with the hardest region (the one touching the most others), pick the colour that blocks the fewest neighbours, and cross out colours as you go. If you get stuck, rub out the last choice and try again.

Backtracking assigns one variable per level. MRV and degree choose the variable, LCV the value. Forward checking and MAC remove values ahead and catch dead ends early. Backjumping and learning avoid repeating the same mistake.

CSPs are NP complete in general, so the worst case stays exponential, but heuristics change the average case enormously. Conflict directed backjumping and no good learning give the same kind of power as clause learning in SAT solvers. Random restarts with heavy tailed run times make solvers far more robust.

State of the art constraint solvers (for example Google OR-Tools CP-SAT) combine propagation, clause learning, restarts and linear relaxations. Research studies phase transitions in random CSPs (hard instances sit at a critical ratio of constraints to variables) and learned branching heuristics.

Chapter summary

  1. Backtracking is DFS that assigns one variable at a time and undoes a choice as soon as a constraint breaks. Commutativity means one variable per level, dn leaves.
  2. MRV (fail first): fewest legal values. Degree: most constraints on unassigned variables (SA first). LCV: the value that rules out the fewest neighbour values (Q = red, not blue).
  3. Forward checking removes conflicting values from neighbours after each choice. MAC runs AC-3 and also catches conflicts between unassigned variables.
  4. Australia in the fixed order needs 2 backtracks. MRV with degree, LCV and forward checking needs 0.
  5. Backjumping, conflict directed backjumping and no good learning avoid going back to variables that did not cause the failure.
