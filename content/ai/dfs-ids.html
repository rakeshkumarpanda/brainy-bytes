Lesson 1 of 8

Depth first search

Source: slide Set 2, slides 40 to 44, and the class of 25 January 2026.

What it is
Depth first search (DFS) always expands the deepest node in the frontier. It goes down one branch as far as it can, and only when it hits a dead end does it go back and try the next branch.
Why we need it
BFS keeps whole levels in memory. DFS keeps only the current path and the untried brothers of its nodes, so it needs very little memory. It also matches how people solve mazes and puzzles: try a way, and back up when stuck.
How it works
Keep the frontier as a stack (last in, first out), or write it as a recursive function. Take out the newest path, and push its children on top. The nodes left on the stack are the backtrack points.

On slide 43 DFS on the water jugs goes (0,0) → (3,0) → (0,0) → (3,0) → ... for ever in tree search, because Fill-3 then Empty-3 makes a cycle. The other children, (0,4), (3,4) and (0,3), wait on OPEN as backtrack points. This is why DFS needs a cycle check.

PropertyDFSWhy
CompleteNo on infinite or cyclic spaces (tree search). Yes on finite spaces with graph search or a path check.It can follow an infinite branch for ever.
OptimalNoIt returns the first goal it meets, which may be deep and costly.
TimeO(bm)m is the largest depth. It may explore the whole tree, and m can be much bigger than d.
SpaceO(b m)Only one path plus the untried children of each node on it.
Remember
Backtracking search, a version of DFS that generates one child at a time and undoes changes when it goes back, needs only O(m) memory. It is the basis of CSP solvers (chapter 5.2) and Prolog.
Lesson 2 of 8

Path checking and cycle checking

Source: slide Set 2, slide 52, food for thought III.

DFS without memory can loop. There are two cheap fixes and one expensive one.

CheckWhat it doesMemoryWhat it misses
Parent checkDo not go straight back to the state you came fromNoneLonger cycles like A → B → C → A
Path checkDo not add a child whose state is already on the current pathO(m), the path is already storedTwo different paths to the same state (redundant paths)
Full cycle check (graph search)Do not add a child whose state was ever exploredO(number of states)Nothing, but memory grows like BFS
Worked example: path checking on the jugs
  1. DFS is at path (0,0), (3,0). The children of (3,0) are (3,4), (0,0) and (0,3).
  2. (0,0) is already on the path, so the path check drops it.
  3. DFS goes on to (3,4), whose children are (0,4) and (3,0). (3,0) is on the path, dropped.
  4. the cycle Fill-3, Empty-3 is gone and DFS keeps moving forward
In the exam
A path check makes DFS complete on any finite state space, while keeping memory at O(b m). It can still visit the same state many times along different paths, so the time may be much more than the number of states.
Lesson 3 of 8

Depth limited and iterative deepening search

Source: slide Set 2, slides 45 to 51.

What it is
Depth limited search (DLS) is DFS that never goes deeper than a limit D. Iterative deepening search (IDS) runs DLS with D = 0, 1, 2, ... until it finds a goal.
Why we need it
BFS has memory problems and DFS can run down an endless path. DLS stops the endless path. IDS also removes the need to guess D, and gets the best of both: the low memory of DFS and the completeness and shortest answer of BFS.
How it works
In DLS, a node at depth D is treated as if it had no children. On the slides the root is depth 0, and no path longer than D + 1 states is put on OPEN. IDS repeats DLS with a bigger limit each time. It stops when a goal is found, or when a DLS finishes without cutting off any node, which proves that no solution exists.
DLS resultMeaning
A solutionA goal was found at depth ≤ D
FailureNo solution exists at all (nothing was cut off)
CutoffNo solution within the limit, but deeper nodes were cut off, so one may exist deeper
Remember
IDS is the preferred uninformed method when the search space is large and the depth of the solution is not known (slide 49).
Lesson 4 of 8

Is iterative deepening wasteful

IDS regenerates the top levels again in every iteration. That sounds wasteful, but it is not, because almost all nodes are in the last level.

Nodes generated by IDSExam favourite
N(IDS) = (d + 1)·1 + d·b + (d − 1)·b² + ... + 1·bd = ∑i=0d (d + 1 − i) bi
Level i is generated in every iteration from i to d, that is d + 1 − i times.
Overhead of IDS over BFSExam favourite
N(IDS) ⁄ N(BFS) ≈ b ⁄ (b − 1)
For b = 10 that is 1.11, only 11 percent more work. For b = 2 it is 2 times.
Cost of IDS
time O(bd), space O(b d)
Complete when b is finite, and optimal when all actions cost the same.
Worked example: b = 10, d = 5
  1. IDS: 6 × 1 + 5 × 10 + 4 × 100 + 3 × 1,000 + 2 × 10,000 + 1 × 100,000.
  2. = 6 + 50 + 400 + 3,000 + 20,000 + 100,000 = 123,456.
  3. BFS (tested at generation): 1 + 10 + 100 + 1,000 + 10,000 + 100,000 = 111,111.
  4. 123,456 ⁄ 111,111 ≈ 1.11
Going deeper: iterative lengthening search

The cost version of IDS uses a limit on g(n) instead of depth: run a cost limited DFS, and raise the limit to the smallest cost that was cut off. It is optimal with costs, but with many different cost values it may need one iteration per distinct cost, which can be very slow. IDA* (chapter 3.3) uses the same idea with f = g + h, where it works much better.

Lesson 5 of 8

Bidirectional search

What it is
Bidirectional search runs two searches at once: one forward from the start and one backward from the goal. It stops when the two frontiers meet.
Why we need it
Two searches of depth d ⁄ 2 are far smaller than one search of depth d, because the cost is exponential in depth.
How it works
Alternate one step of each search. Each time a node is generated, check whether its state is already in the other search. The backward search needs predecessors, so the actions must be reversible or easy to undo, and the goal must be one explicit state.
Cost of bidirectional searchExam favourite
2 · bd⁄2 = O(bd⁄2) instead of O(bd)
For b = 10 and d = 6 that is 2,000 nodes against 1,000,000.
Worked example: b = 10, d = 8
  1. One BFS: about 10⁸ = 100,000,000 nodes in the last level.
  2. Two BFS of depth 4: about 2 × 10⁴ = 20,000 nodes.
  3. 5,000 times less work
Common mistake
When the frontiers first meet, the joined path is not always the shortest. With uniform costs, finish the current level before stopping, then pick the best meeting point.

Bottom line: IDS is the best default when costs are equal and the depth is unknown. UCS is the choice when costs differ. Bidirectional search wins when you can search backward from a single goal.

Real world scenario: finding a friend of a friend

A social network wants to show how you are linked to a stranger. Each person has about 300 friends. A forward BFS of depth 6 would touch 300⁶ ≈ 7 × 10¹⁴ people, more than exist. Searching 3 steps from each side touches about 2 × 300³ = 54 million, and real systems go further with indexes. This meet in the middle idea is how "degrees of separation" features work.

Lesson 7 of 8

From intuition to research

One idea, four depths

DFS is walking through a maze, keeping one hand on the wall: go as far as you can, then go back to the last turn you did not take. IDS does this with a rope that gets longer each time, so you never get lost too far away.

DFS: stack, O(b m) space, not complete or optimal. DLS: DFS with a depth limit, returns solution, failure or cutoff. IDS: DLS with limits 0, 1, 2, ..., complete and optimal for equal costs, O(bd) time, O(b d) space, about b ⁄ (b − 1) times the work of BFS. Bidirectional: O(bd⁄2).

IDS is asymptotically optimal among uninformed tree searches that use linear memory: any such method must look at the bd nodes of the last level in the worst case, and IDS adds only a constant factor. Choosing between path checking and full duplicate detection is a trade of memory against repeated work.

Front to front bidirectional heuristic search, and the meet in the middle algorithm MM (Holte and others, 2016), guarantee that the two searches meet in the middle. Research on breadth first heuristic search and frontier search shows how to drop the explored set while still detecting duplicates, using the structure of the graph.

Going deeper: why IDS is complete but DFS is not, in one line each

DFS can pick an infinite branch first and never return. IDS bounds every iteration, so each iteration finishes, and the iteration with limit d finds a goal at depth d.

Lesson 8 of 8

Chapter summary

  1. DFS expands the deepest node (a stack or recursion). Space O(b m), time O(bm). Not optimal, and not complete on infinite or cyclic spaces.
  2. A path check drops children already on the current path. It makes DFS complete on finite spaces without extra memory.
  3. DLS stops at depth D and returns a solution, failure or cutoff.
  4. IDS runs DLS with D = 0, 1, 2, .... Complete, optimal for equal costs, O(bd) time and O(b d) space. It does about b ⁄ (b − 1) times the work of BFS (123,456 against 111,111 for b = 10, d = 5).
  5. Bidirectional search meets in the middle in O(bd⁄2), but needs reversible actions and one explicit goal.
