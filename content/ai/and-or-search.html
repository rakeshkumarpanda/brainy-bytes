AND OR search and AO*

When an action can end in several states, a list of actions is not enough. AND OR trees describe the agent's choices and nature's outcomes, AND OR search builds a plan with if then branches, and AO* finds the cheapest one.

Lesson 1 of 8

When actions do not always do the same thing

Source: slide Set 2, slide 88, and the classes of 1 and 7 February 2026.

So far every action had exactly one result. In many real problems an action can end in several states, and the agent only learns which one after acting. A floor cleaning robot's suction may also clean the next square, or may drop dirt. A delivery may arrive or get lost. Such actions are non deterministic.

What it is
An AND OR search tree has two kinds of nodes. At an OR node the agent chooses one action (at least one child must work). At an AND node nature chooses the outcome, so every child must be solved.
Why we need it
With non deterministic actions a single sequence of actions is not enough. The agent needs a contingency plan (a conditional plan) that says what to do for each outcome: "Suck, and if the other square is still dirty then go Right and Suck".
How it works
Search the AND OR tree depth first. At an OR node, try actions until one gives a plan. At an AND node, find a plan for every outcome, and fail if any one fails. Stop a branch when it reaches a state already on its path.
Real world scenario: getting a television, from the class

You need a television. One way is to steal it. The other way is to earn money AND buy it. "Get a TV" is an OR node with two choices. "Earn money and buy" is an AND node: you must do both parts. An AND OR tree like this describes a problem broken into sub problems, also called problem reduction. The tree only describes the search space. You can search it depth first, breadth first or best first.

Lesson 2 of 8

The erratic vacuum world and AND OR search

The vacuum world has 8 states: the robot is in square A or B, and each square is dirty or clean. States 7 and 8 (both clean) are goals. In the erratic version, Suck on a dirty square cleans it and sometimes also cleans the other square, and Suck on a clean square sometimes drops dirt on it.

AND-OR-SEARCH (AIMA figure 4.11)
function OR-SEARCH(state, path):
    if GOAL-TEST(state): return the empty plan
    if state is on path: return failure
    for each action:
        plan = AND-SEARCH(RESULTS(state, action), [state] + path)
        if plan is not failure: return [action] + plan
    return failure

function AND-SEARCH(states, path):
    for each s_i in states:
        plan_i = OR-SEARCH(s_i, path)
        if plan_i is failure: return failure
    return [if s_1 then plan_1 else if s_2 then plan_2 ... else plan_n]

From state 1 the plan is [Suck, if State = 5 then [Right, Suck] else []]. If Suck cleaned both squares we are in state 7 and done. If it cleaned only A we are in state 5, so go Right and Suck.

Remember
Failing on a state already on the path does not miss solutions: if a plan exists from a repeated state, it also exists from its first occurrence. That keeps AND OR search complete on finite state spaces.
Lesson 3 of 8

Slippery worlds and cyclic plans

In the slippery vacuum world, Right and Left sometimes fail and leave the robot where it is. Then every plan from state 5 can come back to state 5, which is on its path, so AND OR search finds no plan. But there is an obvious working plan: keep trying Right until it works.

A cyclic planExam favourite
[Suck, L1: Right, if State = 5 then L1 else Suck]
L1 is a label. "if State = 5 then L1" means go back to the label and try Right again. In code it is a while loop: while State = 5: Right.
When a cyclic plan is a solution
every leaf is a goal, and a goal can be reached from every point of the plan
Each try must succeed with some chance. If the floor is so slippery that Right never works, no plan helps.
Common mistake
A cyclic plan only works under a fairness assumption: an action that can succeed will succeed if you try it often enough. If the failure has a hidden cause (the wheel is broken), trying again is useless and the agent must learn the cause instead.
Lesson 4 of 8

AO*: best first search on AND OR graphs

Source: slide Set 2, slides 89 to 92, worked in the class of 7 February 2026.

What it is
AO* is the AND OR version of A*. It keeps a best partial solution graph, expands one of its unexpanded nodes, and revises the costs back up to the root.
Why we need it
AND OR search finds some plan. When the parts of a plan have costs, we want the cheapest solution graph, and AO* uses heuristic estimates to find it without expanding everything.
How it works
Cost of an OR choice: the cheapest connector. Cost of an AND connector: the sum of its edges and children. After each expansion, propagate the new cost to the ancestors, mark the best connector at each node, and mark a node solved when every child on its best connector is solved. Stop when the root is solved.
The slide example (every edge costs 1)
  1. Expand A. Through B: 1 + h(B) = 1 + 5 = 6. Through C AND D: 1 + 2 + 1 + 4 = 8. The best is B (6).
  2. Expand B. B → E costs 1 + 7 = 8 and B → F costs 1 + 9 = 10. So h(B) becomes 8.
  3. Revise A. Through B: 1 + 8 = 9. Through C AND D: still 8. Now C AND D is better, so A switches.
  4. Expand C. C → G costs 1 + 3 = 4 and C → H AND I costs 1 + 0 + 1 + 0 = 2. h(C) = 2 and C is solved (H and I are goals).
  5. Expand D. D → J costs 1 + 0 = 1. h(D) = 1 and D is solved.
  6. revise A: through C AND D = 1 + 2 + 1 + 1 = 5. A is solved with cost 5: A → C + D, C → H + I, D → J
Common mistake
Look closely at the slide numbers: h(D) = 4 but D really costs only 1 (D → J). So this h overestimates and is not admissible. Here AO* still ends at the best answer 5, but try the second tip (h(H) = 6): AO* stops at 9 while the true best is 7. Like A*, AO* is only guaranteed optimal when h never overestimates.
AO* (outline)
G = graph with only the start node, marked unsolved
loop until start is solved or its cost is ∞:
    follow the marked best connectors from the start and pick an unexpanded tip n
    expand n: add its successors, estimate each new node with h
    S = { n }
    while S is not empty:
        take a node m from S that has no descendant in S
        cost(m) = min over connectors of ∑ (edge cost + cost(child))
        mark that connector. m is solved if all its children on it are solved
        if cost(m) changed or m became solved: add the parents of m to S

The maths: cost of a solution graph and complexity

Cost at an OR node
cost(n) = minconnectors k cost(n, k)
The agent picks the cheapest way.
Cost of an AND connectorExam favourite
cost(n, k) = ∑children c of k (C(n, c) + cost(c))
All parts must be done, so their costs add.
Admissibility for AO*
h(n) ≤ the true cost of the best solution graph below n
With such an h, AO* returns an optimal solution graph (on graphs without cycles).
Worked example: food for thought VII, the complexity of AO*
  1. Like A*, AO* may need to expand every node in the worst case, so time and memory are exponential in the depth: O(bd).
  2. Each revision walks up to the root through the ancestors, which costs O(d) per expansion on a tree, more on a graph with shared nodes.
  3. Data structures: a dictionary from node to its list of connectors, its cost, its marked connector and a solved flag, plus a parent list for each node to propagate costs upward.
  4. time and space O(bd), with an O(d) revision after each expansion on a tree
Worked example: the size of a conditional plan
  1. Each AND node with k outcomes multiplies the number of branches by k.
  2. A plan of 3 actions, each with 2 possible outcomes, may need 2³ = 8 branches.
  3. conditional plans can be exponentially larger than plain action sequences

Lesson 7 of 8

From intuition to research

One idea, four depths

Sometimes you cannot be sure what happens after you act. So you plan for every case: "if it rains, take the bus, otherwise walk". An AND OR tree writes down all those cases.

OR nodes are the agent's choices, AND nodes are nature's outcomes. AND OR search returns a conditional plan, failing a branch that repeats a state on its path. Slippery worlds need cyclic plans. AO* finds the cheapest solution graph by expanding the best partial graph and revising costs upward.

AO* is optimal with an admissible h on acyclic graphs. Plans can grow exponentially with the number of uncertain steps. For partially observable worlds the same search runs over belief states (sets of possible states), and sensing actions split a belief state into AND branches.

LAO* extends AO* to cyclic graphs and is a bridge to MDP solvers. Fully observable non deterministic (FOND) planners such as PRP find strong cyclic plans for large planning benchmarks, and AND OR search is used in game solving and in proof search for theorem provers.

Going deeper: belief states

If the agent cannot see the state, it tracks the set of states it might be in, its belief state. With 8 vacuum states there are 2⁸ = 256 belief states. A sensorless agent can still solve the vacuum world: [Right, Suck, Left, Suck] cleans both squares from any start, moving the belief state from all 8 states to {7}.

Chapter summary

  1. With non deterministic actions, the agent needs a contingency (conditional) plan, not a single sequence.
  2. In an AND OR tree, OR nodes are the agent's choices (one child must work) and AND nodes are nature's outcomes (every child must work).
  3. AND OR search is a depth first search that fails a branch when a state repeats on its path. Erratic vacuum from state 1: [Suck, if State = 5 then [Right, Suck] else []].
  4. In a slippery world no plan without loops exists. A cyclic plan such as [Suck, L1: Right, if State = 5 then L1 else Suck] works if each try can succeed.
  5. AO*: expand the best partial solution graph, add costs at AND connectors, take the min at OR nodes, and revise upward. The slide example ends at 5 via C AND D.
