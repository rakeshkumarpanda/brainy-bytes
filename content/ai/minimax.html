Lesson 1 of 8

Games as search problems

Source: slide Set 3, slides 1 and 2, and the class of 8 February 2026.

In a game, other agents act too, and they want something different. Each agent tries to raise its own utility or cut its loss, and one agent's move changes what the others can get. Uncertainty comes from not knowing what the opponent will do, which is called strategic uncertainty. Searching in such a setting is called adversarial search.

This chapter covers deterministic, two player, turn taking, zero sum games with perfect information: what one player wins, the other loses, so one number, the utility for MAX, describes both.

Lesson 2 of 8

The minimax algorithm

Source: slide Set 3, slides 3 and 4.

What it is
Minimax computes, for every node of the game tree, the best utility MAX can guarantee against an opponent who plays perfectly. MAX nodes take the largest child value and MIN nodes take the smallest.
Why we need it
You cannot pick a move by looking only at your own options: the opponent answers. Minimax assumes the worst sensible answer, so the move it picks is safe against any opponent.
How it works
Generate the game tree down to terminal states. Give each terminal its utility. Back the values up: max at MAX nodes, min at MIN nodes. The root value is what MAX can guarantee, and the move leading to it is the optimal move.
Minimax valueExam favourite
MINIMAX(s) = UTILITY(s) if s is terminal, maxa MINIMAX(RESULT(s, a)) if MAX moves, mina MINIMAX(RESULT(s, a)) if MIN moves
A recursive definition, computed depth first.
The slide example (three levels, 27 leaves)
  1. C nodes are MAX nodes over 3 leaves each: C1 = 5, C2 = 11, C3 = 8, C4 = 4, C5 = 12, C6 = 2, C7 = 3, C8 = 11, C9 = 5.
  2. B nodes are MIN nodes: B1 = min(5, 11, 8) = 5 (from C1), B2 = min(4, 12, 2) = 2 (from C6), B3 = min(3, 11, 5) = 3 (from C7).
  3. A is a MAX node: A = max(5, 2, 3) = 5.
  4. MAX plays towards B1 and is guaranteed at least 5
MINIMAX-DECISION
function MINIMAX-DECISION(state):
    return the action a in ACTIONS(state) with the largest MIN-VALUE(RESULT(state, a))

function MAX-VALUE(state):
    if TERMINAL-TEST(state): return UTILITY(state)
    v = −∞
    for each a in ACTIONS(state): v = max(v, MIN-VALUE(RESULT(state, a)))
    return v

function MIN-VALUE(state):
    if TERMINAL-TEST(state): return UTILITY(state)
    v = +∞
    for each a in ACTIONS(state): v = min(v, MAX-VALUE(RESULT(state, a)))
    return v
Lesson 3 of 8

The tic-tac-toe example of the slides

Source: slide Set 3, slide 5.

The board is O X O on top, X _ X in the middle and _ O _ at the bottom. O is MAX and moves now. Three squares are free: the centre (square 4), bottom left (6) and bottom right (8).

Minimax on this position (the slide numbers the boards 1 to 14)
  1. Board 2: O takes the centre. X can answer in either corner (boards 5 and 6), but O then takes the last square and wins with a diagonal (boards 11 and 12). Value +1, whatever X does: X's choice is irrelevant.
  2. Board 3: O takes bottom left. X takes the centre and completes the middle row (board 7). Value −1.
  3. Board 4: O takes bottom right. X takes the centre and wins the same way (board 9). Value −1.
  4. Level 1 is X's decision, a MIN level. Level 0 is O's decision, a MAX level.
  5. O chooses board 2 (the centre), the only move that wins
Remember
Boards 8, 10, 13 and 14 show what happens if X does not take the centre: O wins. Minimax ignores those lines because a perfect X would not play them.

Properties, and what to do when the tree is too big

Source: slide Set 3, slide 6, food for thought.

PropertyMinimax
CompleteYes, if the tree is finite
OptimalYes, against an optimal opponent. Against a weak one it is safe but may miss chances
TimeO(bm): it visits the whole tree to depth m
SpaceO(b m) when it explores depth first and generates all moves at once, O(m) when it generates one move at a time
Data structuresA recursion stack (or explicit stack) of states, the list of moves at each level, and the best value and move so far

For chess, b ≈ 35 and a game lasts m ≈ 100 plies (moves by one player), so the tree has about 35100 ≈ 10154 nodes. Real programs stop early and estimate.

Depth limited minimaxExam favourite
replace TERMINAL-TEST by CUTOFF-TEST(s, d) and UTILITY by EVAL(s)
Search to a fixed depth d, then use a heuristic evaluation of the position.
Weighted linear evaluation
EVAL(s) = w1 f1(s) + w2 f2(s) + ... + wn fn(s)
Chess material: pawn 1, knight 3, bishop 3, rook 5, queen 9, counted for MAX minus for MIN.
Problem with cutting offFix
Non quiet positions: the evaluation changes wildly in the next move (a capture is about to happen)Quiescence search: keep searching captures until the position is quiet
Horizon effect: a delaying move pushes an unavoidable loss beyond the search depth, so it looks avoidedSingular extensions: search a clearly best move one level deeper
Too many moves to searchForward pruning: skip moves that look bad (beam search on moves). Risky but used in practice

The maths: zero sum games and evaluation

Zero sumExam favourite
UTILITY(s, MAX) + UTILITY(s, MIN) = constant
Chess: 1 + 0, 0 + 1 or ½ + ½. So MIN minimising MAX's utility is the same as maximising its own.
Multiplayer games
each node holds a vector (u1, ..., uk), and the player to move picks the child with the best uown
With three players, alliances can appear and break, which plain minimax cannot express.
Size of a game tree
bm
Tic-tac-toe has at most 9! = 362,880 move sequences (fewer, because games end early), and only 5,478 legal positions.
Worked example: a material evaluation
  1. White has 8 pawns, 2 knights, 1 bishop, 2 rooks and 1 queen. Black has 7 pawns, 1 knight, 2 bishops, 2 rooks and 1 queen.
  2. White: 8 + 2 × 3 + 3 + 2 × 5 + 9 = 36.
  3. Black: 7 + 3 + 2 × 3 + 2 × 5 + 9 = 35.
  4. EVAL = 36 − 35 = +1 for White (a pawn up)
Worked example: tree size
  1. A game with b = 10 and depth m = 6.
  2. Leaves: 10⁶ = 1,000,000.
  3. At 1 million leaves a second, about 1 second. At depth 8, 100 seconds.
  4. every two extra plies cost 100 times more for b = 10

Bottom line: minimax is the right tool for two player zero sum games of skill. Alpha beta pruning (chapter 6.2) gives the same answer much faster.

Real world scenario: food for thought: real uses of minimax

Chess and checkers engines (Chinook solved checkers in 2007: perfect play is a draw). Security games, where a defender places guards against an attacker who adapts, use the same max min reasoning. Robust planning treats nature as an opponent: "choose the plan whose worst case is best", for example when a power grid operator plans for the worst line failure. The utility function must capture what matters: in chess material, king safety and mobility, in security the value of each target.

Lesson 7 of 8

From intuition to research

One idea, four depths

Minimax is thinking "if I do this, what is the worst my opponent can do to me?", for every move, and choosing the move whose worst case is best.

A game has S0, PLAYER, ACTIONS, RESULT, TERMINAL-TEST and UTILITY. Minimax backs up max at MAX nodes and min at MIN nodes. It is complete and optimal against a perfect opponent, O(bm) time and O(b m) space. Real programs cut off at a depth and use an evaluation function.

The minimax value of a zero sum game equals the value from von Neumann's minimax theorem for mixed strategies when moves are simultaneous. For turn taking perfect information games, backward induction (Zermelo, 1913) shows a pure strategy optimum exists. The horizon effect and quiescence show why a static evaluation is fragile.

Modern engines replace hand tuned evaluation with neural networks (Stockfish NNUE) or replace minimax by Monte Carlo tree search guided by networks (AlphaZero). Game theory research extends this to imperfect information (counterfactual regret minimisation in poker) and to many players.

Chapter summary

  1. A game is a search problem with S0, PLAYER, ACTIONS, RESULT, TERMINAL-TEST and UTILITY. Two player zero sum games with perfect information are the classic case.
  2. Minimax: MAX nodes take the max of their children, MIN nodes the min, terminals give their utility. The root value is what MAX can guarantee.
  3. Slide example: C = 5, 11, 8, 4, 12, 2, 3, 11, 5, then B1 = 5, B2 = 2, B3 = 3, and A = 5. Slide tic-tac-toe: O takes the centre and wins.
  4. Complete for finite trees, optimal against a perfect opponent, O(bm) time and O(b m) space. Chess has about 10154 nodes.
  5. Cut off at a depth with an evaluation function, and watch for quiet positions and the horizon effect.
