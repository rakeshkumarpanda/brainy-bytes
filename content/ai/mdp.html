Lesson 1 of 7

Markov decision processes

Source: Bellman (1957), Howard (1960), and AIMA 3rd ed., sections 17.1 to 17.3 (4th ed., 16.1 and 16.2). The 4 × 3 world is AIMA figure 17.1. The racing car example is from Berkeley CS188. The uploaded slides and transcripts do not cover this step.

What it is
A Markov decision process (MDP) is a problem where an agent acts again and again in a world with chance. It has states, actions, a transition model P(s′ | s, a), a reward for each state (or each move), and usually a discount γ. The Markov property says the next state depends only on the current state and action, not on the past.
Why we need it
Search assumed every action has one sure result. Real robots slip, markets move, opponents surprise. A plan as a fixed list of actions breaks the first time something unexpected happens.
How it works
Instead of a plan, find a policy π(s): the action to take in every state. The best policy π* gets the highest expected total discounted reward from every state. It is found with the Bellman equation.

Why discount: a reward now is worth more than the same reward later, an agent may stop at any time, and with γ < 1 infinite sums stay finite. γ close to 1 means a patient agent.
Lesson 2 of 7

The Bellman equation and value iteration

Source: Bellman (1957), and AIMA 3rd ed., section 17.2.

What it is
The Bellman equation says the utility of a state is its reward plus the discounted expected utility of the next state, if the agent then acts optimally. Value iteration solves it by repeating the equation as an update until the values stop changing.
Why we need it
There is one equation per state, but the max makes them non linear, so they cannot be solved like ordinary linear equations. Repeating the update always works and is simple.
How it works
Start with U(s) = 0. In each sweep, set every U(s) to R(s) + γ max over a of Σ P(s′ | s, a) U(s′), using the old values. Stop when the largest change is small. Then read the policy from the values.
Bellman equationExam favourite
U(s) = R(s) + γ max over a of Σ over s′ of P(s′ | s, a) U(s′)
One equation per state.
Bellman update
U_(i+1)(s) ← R(s) + γ max over a of Σ P(s′ | s, a) U_i(s′)
Value iteration repeats this.
Contraction
‖U_(i+1) − U‖ ≤ γ ‖U_i − U‖
Each sweep shrinks the error by at least γ (in the max norm), so value iteration always converges for γ < 1.
Stopping rule
if ‖U_(i+1) − U_i‖ < ε (1 − γ) ÷ γ then ‖U_(i+1) − U‖ < ε
A safe test for "close enough".
Worked example: the first sweep for square (3,3) of the 4 × 3 world
  1. All utilities start at 0, except the end squares: +1 and −1.
  2. Action Right: 0.8 × U(4,3) + 0.1 × U(3,3) + 0.1 × U(3,2) = 0.8 × 1 + 0 + 0 = 0.8.
  3. No other action does better.
  4. U₁(3,3) = −0.04 + 1 × 0.8 = 0.76
Lesson 3 of 7

Policy iteration and Q-values

Source: Howard (1960), Puterman and Shin (1978) for modified policy iteration, and AIMA 3rd ed., section 17.3.

What it is
Policy iteration works with policies, not values. It alternates two steps: policy evaluation (find U^π for the current policy) and policy improvement (change the action in each state to the best one under those values). A Q-value Q(s, a) is the expected utility of taking action a in state s and acting optimally afterwards.
Why we need it
Often the policy becomes optimal long before the values stop changing. Policy iteration stops as soon as the policy stops changing, usually after very few rounds. Q-values let an agent pick the best action without a transition model, which is the key to Q-learning in chapter 10.3.
How it works
Evaluation: with the action in each state fixed, the Bellman equations lose the max and become linear, so solve them exactly (or with a few sweeps, as in modified policy iteration). Improvement: π(s) ← argmax over a of Σ P(s′ | s, a) U(s′). Stop when nothing changes.
Policy evaluationExam favourite
U^π(s) = R(s) + γ Σ P(s′ | s, π(s)) U^π(s′)
n linear equations, O(n³) to solve exactly.
Q-value
Q(s, a) = Σ P(s′ | s, a) [R(s, a, s′) + γ max over a′ of Q(s′, a′)]
U(s) = max over a of Q(s, a).
Termination
there are |A|^|S| policies and each round is at least as good as the last
So policy iteration ends after a finite number of rounds.
Worked example: evaluate the policy (cool: fast, warm: slow) of the racing car with γ = 0.9
  1. V(cool) = 0.5 (2 + 0.9 V(cool)) + 0.5 (2 + 0.9 V(warm)) = 2 + 0.45 V(cool) + 0.45 V(warm).
  2. V(warm) = 0.5 (1 + 0.9 V(cool)) + 0.5 (1 + 0.9 V(warm)) = 1 + 0.45 V(cool) + 0.45 V(warm).
  3. Subtract: V(cool) − V(warm) = 1. Put V(cool) = V(warm) + 1 into the second line: V(warm) = 1.45 + 0.9 V(warm).
  4. V(warm) = 14.5, V(cool) = 15.5
Going deeper: Partially observable MDPs

When the agent cannot see the state, it keeps a belief state b(s), a probability for each state, and updates it with Bayes’s rule after each action and percept. A POMDP is an MDP over belief states, which are continuous, so it is much harder: finding optimal POMDP policies is PSPACE-hard even for finite horizons (Papadimitriou and Tsitsiklis, 1987). Point based value iteration and online search such as POMCP make large POMDPs practical.

The maths: bounds and counts

Bound on utilitiesExam favourite
|U(s)| ≤ R_max ÷ (1 − γ)
Geometric series: R_max (1 + γ + γ² + ...).
Sweeps needed
N = ⌈log(2 R_max ÷ (ε (1 − γ))) ÷ log(1 ÷ γ)⌉
Enough sweeps for error below ε, starting from 0. It grows fast as γ nears 1.
Policy loss
if ‖U_i − U‖ < ε then ‖U^(π_i) − U‖ < 2 ε γ ÷ (1 − γ)
The greedy policy is good even before the values have fully converged.
Number of policies
|A|^|S|
4 × 3 world: 4⁹ = 262,144 policies for the 9 squares where a choice matters.
Worked example: two sweeps of value iteration on the racing car (γ = 0.9)
  1. Sweep 1 (from 0): cool: slow gives 1, fast gives 2, so 2. warm: slow gives 1, fast gives −10, so 1.
  2. Sweep 2, cool, fast: 0.5 (2 + 0.9 × 2) + 0.5 (2 + 0.9 × 1) = 1.9 + 1.45 = 3.35. Slow: 1 + 0.9 × 2 = 2.8. So 3.35.
  3. Sweep 2, warm, slow: 0.5 (1 + 1.8) + 0.5 (1 + 0.9) = 1.4 + 0.95 = 2.35. Fast: −10. So 2.35.
  4. V₂(cool) = 3.35, V₂(warm) = 2.35

Bottom line: value iteration is the easiest to write, and policy iteration usually needs fewer rounds. All of them need the full model, which reinforcement learning (next chapters) does without.

Real world scenario: MDPs in the real world

MDPs plan maintenance (when to repair a machine as it wears), stock control (how much to order each week), medical treatment plans (when to change a drug), and robot navigation with wheel slip. Airline seat pricing and the energy grid also use dynamic programming over MDP models.

Lesson 6 of 7

From intuition to research

One idea, four depths

A policy is a rule book: in this situation, do this. The value of a situation is how much reward you expect from it on average if you follow the best rule book.

MDP = states, actions, P(s′ | s, a), R, γ. Bellman equation, value iteration (contraction by γ), policy iteration (evaluate, improve), Q-values.

Bounds: utilities at most R_max ÷ (1 − γ), stopping rule ε (1 − γ) ÷ γ, policy loss 2εγ ÷ (1 − γ). MDPs are P-complete (Papadimitriou and Tsitsiklis, 1987), POMDPs are much harder.

Research: approximate dynamic programming with function approximation, factored MDPs that exploit structure, safe and constrained MDPs, and large scale planning with learned models (as in MuZero, Schrittwieser and others, 2020).

Lesson 7 of 7

Chapter summary

  1. An MDP has states, actions, P(s′ | s, a), rewards and a discount γ. A solution is a policy π(s).
  2. Bellman equation: U(s) = R(s) + γ max over a of Σ P(s′ | s, a) U(s′).
  3. Value iteration repeats the Bellman update. It converges because each sweep shrinks the error by γ. In the 4 × 3 world U(1,1) = 0.705.
  4. Policy iteration alternates exact evaluation (linear equations) and greedy improvement, and stops after a few rounds.
  5. Q(s, a) = Σ P(s′ | s, a) [R + γ max Q(s′, a′)] gives the best action without a model, the bridge to reinforcement learning.
