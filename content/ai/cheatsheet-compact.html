Step 1Core AI · Intelligence, agents and problems

1.1What AI is and intelligent agents

  • Definition AI builds agents that perceive and act. This course uses the acting rationally view: choose the action with the best expected performance.
  • PEAS Describe any task by Performance measure, Environment, Actuators, Sensors.
  • Environment types Fully or partially observable, deterministic or stochastic, episodic or sequential, static or dynamic, discrete or continuous, single or multi agent.
  • Agent programs Simple reflex, model based, goal based, utility based, learning. Table driven needs ∑ |P|t rows, so it is impossible.
  • Rational, not perfect Rationality depends on the performance measure, prior knowledge, available actions and percepts so far. Bad luck is not irrational.
  • Social machine Needs etiquette, intuitive psychology, common sense, intuitive physics and layers from instinctive to self conscious (Minsky, Society of Mind).
  • Agent functionf : P* → A
  • Rational agentchoose a* = argmaxa E[performance | percepts so far, a]
  • Expected performance of an actionE[U | a] = ∑s′ P(s′ | a) U(s′)
  • Size of a table driven agentrows = ∑t=1T |P|t = |P|(|P|T − 1) ⁄ (|P| − 1)
  • Trap A table driven agent stores one action for every possible percept sequence. With 4 percepts and a lifetime of T steps it needs 4 + 4² + ... + 4T rows. For a taxi camera this number is larger than the atoms in the universe. Agent programs exist to produce good behaviour from a small program instead of a huge table.
  • Exam A rational agent is not one that is always right. It is one that chooses the best action given what it knows. Bad luck does not make a choice irrational.

1.2Problems as search

  • Search problem State space, actions with costs C(x, a, y) ≥ ε > 0, initial state, goal test (a condition). Heuristics are optional.
  • Node STATE, PARENT, ACTION, PATH-COST g(n). Follow PARENT links to rebuild the path.
  • Tree against graph search Tree search can loop on cycles. Graph search keeps an explored set and skips seen states.
  • Four properties Completeness, optimality, time and space, measured with b, d and m. Full tree: (bd+1 − 1) ⁄ (b − 1) nodes.
  • Water jugs 14 of 20 states reachable from (0, 0). (1, 2) unreachable. Getting 2 gallons in the 4 gallon jug takes 6 actions.
  • Formulation Search cannot choose the states for you. A good abstraction can shrink the space enormously (8 queens: 1.8 × 10¹⁴ to 2,057).
  • Successor functionS(x) = {⟨y, a⟩ : action a takes x to y}
  • Path costg(n) = ∑i C(si, ai, si+1)
  • Nodes in a full tree1 + b + b² + ... + bd = (bd+1 − 1) ⁄ (b − 1) = O(bd)
  • 8 puzzle reachable states9! ⁄ 2 = 181,440
  • Paths are much bigger than statestree nodes up to depth d ≈ bd while states may be few
  • Trap Cycles can cause non termination. Arad → Sibiu → Arad → Sibiu ... is a valid path in tree search, so a search may never stop. Graph search fixes this by remembering explored states.
  • Exam Exam questions often ask you to formulate a problem. Always list all four parts: states, actions (with costs), initial state, goal test. Say how big the state space is.

Step 2Core AI · Uninformed search

2.1Breadth first and uniform cost search

  • BFS FIFO queue. Complete (finite b). Fewest actions, optimal only for equal costs. Time and space O(bd).
  • UCS Priority queue on g(n). Complete and optimal if every cost ≥ ε > 0. O(b1 + ⌊C*⁄ε⌋).
  • Goal test timing BFS: test at generation. UCS: test at expansion (Sibiu: 310 is replaced by 278).
  • Romania BFS 450 via Fagaras. UCS 418 via Rimnicu Vilcea and Pitesti, after taking out 13 cities.
  • Optimality proof Lemma 1: costs taken out never decrease. Lemma 2: cheaper paths come first. Lemma 3: first path to a state is cheapest.
  • Memory b = 10, d = 10 needs about 10 TB. Memory runs out before time.
  • Time of BFS1 + b + b² + ... + bd = O(bd)
  • Space of BFSO(bd−1) explored + O(bd) frontier = O(bd)
  • Time and space of UCSO(b1 + ⌊C*⁄ε⌋)
  • Geometric series∑i=0d bi = (bd+1 − 1) ⁄ (b − 1) ≤ bd · b ⁄ (b − 1)
  • Trap Two lessons from the table. Memory runs out long before time does. And no amount of faster hardware saves you: each extra level multiplies the cost by b.
  • Exam This is why UCS tests the goal when a path is taken OUT, not when it is generated. In the Sibiu example, Bucharest was generated with cost 310 before the 278 path existed. Testing at generation would have returned the wrong answer.

2.2Depth first, iterative deepening and bidirectional search

  • DFS Stack. O(b m) space, O(bm) time. Not complete on infinite or cyclic spaces, not optimal.
  • DLS DFS with depth limit D. Returns solution, failure, or cutoff. Complete only if d ≤ D.
  • IDS DLS with D = 0, 1, 2, .... Complete, optimal for equal costs, O(bd) time, O(b d) space.
  • IDS overhead ∑ (d + 1 − i) bi, about b ⁄ (b − 1) times BFS. b = 10, d = 5: 123,456 against 111,111.
  • Path check Drop a child already on the current path. Removes cycles, keeps O(b m) memory.
  • Bidirectional Search from both ends, O(bd⁄2). Needs reversible actions and one explicit goal.
  • Nodes generated by IDSN(IDS) = (d + 1)·1 + d·b + (d − 1)·b² + ... + 1·bd = ∑i=0d (d + 1 − i) bi
  • Overhead of IDS over BFSN(IDS) ⁄ N(BFS) ≈ b ⁄ (b − 1)
  • Cost of bidirectional search2 · bd⁄2 = O(bd⁄2) instead of O(bd)
  • Exam A path check makes DFS complete on any finite state space, while keeping memory at O(b m). It can still visit the same state many times along different paths, so the time may be much more than the number of states.
  • Trap When the frontiers first meet, the joined path is not always the shortest. With uniform costs, finish the current level before stopping, then pick the best meeting point.

Step 3Core AI · Informed search

3.1Greedy best first and A* search

  • Greedy best first Order by h. Not optimal (Romania 450, slide 58 trap 110). Can loop in tree search.
  • A* Order by f = g + h. Romania: Arad 366, Sibiu 393, RV 413, Fagaras 415, Pitesti 417, Bucharest 418.
  • Admissible h(n) ≤ h*(n). Makes A* tree search optimal.
  • Consistent h(n1) ≤ C(n1, a, n2) + h(n2). f never decreases, graph search optimal, implies admissible.
  • Optimally efficient A* expands every node with f < C* and none with f > C*. No optimal method with the same h does better.
  • Weighted A* f = g + w h, cost ≤ w C*.
  • Evaluation function of A*f(n) = g(n) + h(n)
  • Admissibleh(n) ≤ h*(n) for every n
  • Consistent (monotone)h(n1) ≤ C(n1, a, n2) + h(n2) for every action a from n1 to n2
  • Optimally efficientno other optimal algorithm using the same h expands fewer nodes (up to ties)
  • Bounded suboptimalitycost found ≤ w · C*
  • Exam Food for thought IV asks for necessary and sufficient conditions. For optimal A*: admissibility is sufficient for tree search, consistency is sufficient for graph search. Neither is necessary: a slightly overestimating h can still return the optimal path by luck, but then nothing is guaranteed.
  • Trap The time of A* is still exponential in general, and the memory is its real weak point: it keeps every generated node. That is why chapter 3.3 builds IDA*, RBFS and SMA*.

3.2Designing and comparing heuristics

  • 8 puzzle heuristics h1 misplaced tiles, h2 Manhattan distance. Textbook start: h1 = 8, h2 = 18, true cost 26.
  • Relaxed problem Remove rules. The exact relaxed cost is admissible and consistent.
  • Dominance h2 ≥ h1 and both admissible: A* with h2 expands no more nodes.
  • Combining max of admissible heuristics is admissible and dominates each one.
  • Effective branching factor N + 1 = 1 + b* + ... + (b*)d. Close to 1 is good.
  • Pattern database Exact costs of a sub problem, looked up during search. Disjoint PDBs can be added.
  • h2: Manhattan distanceh2(n) = ∑tiles (|row − goal row| + |column − goal column|)
  • Dominanceh2 dominates h1 if h2(n) ≥ h1(n) for every n, and both are admissible
  • Combiningh(n) = max(h1(n), ..., hk(n))
  • Disjoint pattern databasesh = PDB(tiles 1 to 4) + PDB(tiles 5 to 8)
  • Effective branching factor b*N + 1 = 1 + b* + (b*)² + ... + (b*)d
  • Trap Larger is better only while h stays admissible. 2 × h2 is larger, but it overestimates, so A* may then return a longer solution.

3.3Memory bounded heuristic search: IDA*, RBFS and SMA*

  • Why A* stores every node and runs out of memory first. Memory bounded methods trade memory for repeated work.
  • IDA* DFS with an f cutoff, next cutoff = smallest f over the old one. Romania: 366, 393, 413, 415, 417, 418.
  • RBFS f-limit = min(limit, best alternative). Unwind when best f > limit and back up that f. Linear memory.
  • SMA* A* until memory is full, then drop the highest f leaf and back up its f. Optimal if the solution fits.
  • Costs IDA* and RBFS: O(b d) memory. IDA* worst case O(N²) time with many distinct f values.
  • Iterations of IDA*one per distinct f value up to C*
  • MemoryA*: O(bd) IDA*, RBFS: O(b d) SMA*: M, the memory you give it
  • Exam The minor exam of this course was announced as a coding task, such as writing RBFS. The code in lesson 3 is short enough to learn by heart, and the notebook lets you practise it.

3.4AND OR search and AO*

  • AND and OR nodes OR: the agent chooses, one child must work. AND: nature chooses, every child must work.
  • Contingency plan Erratic vacuum from state 1: [Suck, if State = 5 then [Right, Suck] else []].
  • AND OR search DFS that fails a branch on a state already on its path. Complete on finite spaces.
  • Cyclic plan Slippery world: [Suck, L1: Right, if State = 5 then L1 else Suck]. Needs fairness.
  • AO* Expand the best partial graph, AND = sum, OR = min, revise upward. Slide example: 6, then 9 against 8, ends at 5. Optimal only with admissible h.
  • A cyclic plan[Suck, L1: Right, if State = 5 then L1 else Suck]
  • Cost of an AND connectorcost(n, k) = ∑children c of k (C(n, c) + cost(c))
  • Trap A cyclic plan only works under a fairness assumption: an action that can succeed will succeed if you try it often enough. If the failure has a hidden cause (the wheel is broken), trying again is useless and the agent must learn the cause instead.
  • Trap Look closely at the slide numbers: h(D) = 4 but D really costs only 1 (D → J). So this h overestimates and is not admissible. Here AO* still ends at the best answer 5, but try the second tip (h(H) = 6): AO* stops at 9 while the true best is 7. Like A*, AO* is only guaranteed optimal when h never overestimates.

Step 4Core AI · Local and evolutionary search

4.1Local search: hill climbing and simulated annealing

  • Local search One current state, an objective, neighbours. No path, constant memory, works on huge spaces.
  • Hill climbing Best neighbour until none is better. Stuck at local maxima, ridges and plateaux. 8 queens: about 14 percent solved.
  • Fixes Sideways moves (about 94 percent), random restarts (1 ⁄ p runs), stochastic and first choice, local beam search.
  • Simulated annealing Accept worse with eΔE⁄T. High T explores, low T exploits.
  • Cooling schedules Geometric T ← αT (0.8 ≤ α ≤ 1), linear T0 − kΔT, logarithmic C ⁄ ln(k + 2), constant, exponential T0 αk.
  • Random restartexpected restarts = 1 ⁄ p
  • Acceptance probabilityP(accept) = eΔE ⁄ T for ΔE < 0, and 1 for ΔE ≥ 0
  • Gradient ascent for continuous statesx ← x + η ∇f(x)

4.2Genetic algorithms

  • GA words Gene, chromosome, population, fitness, selection, crossover, mutation.
  • Roulette wheel P(i) = fi ⁄ ∑f. Expected copies fi ⁄ f̄.
  • Slide example Fitness 169, 576, 64, 361, total 1170, average 292.5. Children 01100, 11001, 11011 (729), 10000.
  • Other selections Tournament, rank, elitism. Rank and tournament ignore the scale of fitness.
  • When GAs help When good solutions are built from blocks crossover can combine. Watch diversity to avoid premature convergence.
  • Roulette wheel probabilityP(i) = fi ⁄ ∑j fj
  • Trap The slide table lists x = 10 for the string 10000. In binary 10000 is 16, and 16² = 256 matches the f column, so x should read 16.
  • Trap For problems like the travelling salesperson, plain one point crossover makes invalid tours (a city twice). Use order crossover or swap mutation, which always give valid permutations.

Step 5Core AI · Constraint satisfaction

5.1Constraint satisfaction problems and arc consistency

  • CSP Variables X, domains D, constraints C. Solution: complete and consistent assignment.
  • Examples Australia: 37 = 2,187 assignments, 18 solutions. N queens with Xij ∈ {0, 1}. Car assembly with precedence T1 + d1 ≤ T2 and disjunctive constraints.
  • Arc consistency ∀ x ∈ dom(X) ∃ y ∈ dom(Y): r(x, y). AC-3 costs O(c d³).
  • Three outcomes Empty domain: no solution. All singletons: unique solution. Otherwise search.
  • Forward checking against AC-3 FC checks arcs from the newly assigned variable only. AC-3 checks every arc and finds failures earlier.
  • Arc consistency∀ x ∈ dom(X) ∃ y ∈ dom(Y): r(x, y)
  • Cost of AC-3O(c d³)
  • Number of complete assignmentsdn
  • Naive search treen! · dn leaves
  • Trap Arc consistency cannot see that 2 colours are not enough for a triangle WA, NT, SA: each arc on its own is fine ({red, blue} against {red, blue}). Path consistency catches it.

5.2Backtracking search for CSPs

  • Backtracking DFS, one variable per level (assignments commute), undo on a broken constraint. dn leaves.
  • MRV and degree MRV: fewest legal values (fail first). Degree: most constraints on unassigned variables, breaks ties. SA first.
  • LCV Value ruling out fewest neighbour values first. WA = red, NT = green: Q = red, not blue.
  • FC and MAC FC prunes neighbours of the assigned variable. MAC runs AC-3 and catches more.
  • Backjumping and learning Jump to the latest variable in the conflict set. Record no goods so the same failure never repeats.
  • Worst case of backtrackingO(dn)
  • Exam Variable ordering is fail first: pick the hardest variable so a dead end shows up early. Value ordering is succeed first: pick the value most likely to work. When you want all solutions, or none exists, value ordering does not matter, because every value gets tried anyway.
  • Trap Forward checking misses conflicts between two unassigned variables. After WA = red and Q = green, NT and SA both have only blue left and are neighbours. Forward checking does not see it. MAC does, because it also checks the arc NT, SA.

5.3Local search for CSPs and problem structure

  • Min-conflicts Complete random assignment, move a random conflicted variable to its least conflicting value. About 50 steps for a million queens (AIMA).
  • Escaping traps Sideways moves, tabu search, constraint weighting, restarts. Local search cannot prove no solution.
  • Tree CSP O(n d²): directional arc consistency backward, then assign forward, no backtracking.
  • Cutset conditioning O(dc(n − c)d²). Australia: cutset {SA}.
  • Tree decomposition O(n dw+1), w = tree width.
  • Independent sub problemsconnected components solved separately: O(dc · n ⁄ c) instead of O(dn)
  • Tree structured CSPsolvable in O(n d²)
  • Cutset conditioningO(dc · (n − c) d²)
  • Trap Local search cannot prove that a CSP has no solution. It just fails to find one. Backtracking with propagation can prove it, for example that 2 colours are not enough for Australia.

Step 6Core AI · Adversarial search

6.1Games and minimax

  • Game S0, PLAYER, ACTIONS, RESULT, TERMINAL-TEST, UTILITY. Zero sum: one player's gain is the other's loss.
  • Minimax MAX takes max, MIN takes min, terminals give utility. Root value = what MAX can guarantee.
  • Slide examples 27 leaves: B1 = 5, B2 = 2, B3 = 3, A = 5. Tic-tac-toe: O takes the centre.
  • Cost Complete (finite), optimal against perfect play, O(bm) time, O(b m) space. Chess ≈ 10154.
  • Cutoffs Depth limit with EVAL = ∑ wi fi. Quiescence search, horizon effect.
  • Minimax valueMINIMAX(s) = UTILITY(s) if s is terminal, maxa MINIMAX(RESULT(s, a)) if MAX moves, mina MINIMAX(RESULT(s, a)) if MIN moves
  • Depth limited minimaxreplace TERMINAL-TEST by CUTOFF-TEST(s, d) and UTILITY by EVAL(s)
  • Zero sumUTILITY(s, MAX) + UTILITY(s, MIN) = constant

6.2Alpha beta pruning

  • α and β α = best MAX can guarantee so far (starts −∞). β = best MIN can guarantee so far (starts +∞).
  • Rule α, β go parent to child. Values go child to parent. Prune when α ≥ β. Root value = minimax.
  • Slide example Leaves 2 3 5 9 0 1 7 5. Prune the 9 under E and all of G. A = 3 after 5 of 8 leaves.
  • Cost Best O(bm/2), random about O(b3m/4), worst O(bm). Space O(b m). Same time, twice the depth.
  • Ordering Best first: b⌈d/2⌉ + b⌊d/2⌋ − 1 leaves. Iterative deepening, killer moves, transposition tables.
  • Fewest leaves alpha beta can read (Knuth and Moore)b⌈d/2⌉ + b⌊d/2⌋ − 1
  • Best order costO(bm/2) = O((√b)m)
  • Trap The slide text says "the initial value of alpha is +∞" in the line about beta. That is a typing slip: it is β that starts at +∞, and α starts at −∞.
  • Exam A pruned node gets a bound, not an exact value: E is "at least 5" and C is "at most 1". These bounds are enough to choose the move, which is all we need at the root.

6.3Games with chance: expectimax and Monte Carlo tree search

  • Chance node V(s) = ∑ p(s′ | s) V(s′). exp-value starts at v = 0 and adds p × value.
  • Slide 11 3 12 9, 2 4 6, 15 6 0 with 1/3 each: 8, 4, 7. MAX = 8.
  • Slide 12 MIN 2, 1, 3 with 0.5, 0.4, 0.1: 1.7. Layers MAX, CHANCE, MIN, CHANCE.
  • Problems Need probabilities, cost O(bm nm), value scale matters (only a x + b with a > 0 is safe), pruning needs bounds.
  • MCTS Select by UCB1 = w ⁄ n + C √(ln N ⁄ n), expand, simulate, back up. Play the most visited move.
  • Expectimax value (slide 11)V(s) = maxs′ ∈ successors(s) V(s′) for agent controlled states. V(s) = ∑s′ ∈ successors(s) p(s′ | s) V(s′) for chance states. V(s) = known for terminal states
  • ExpectiminimaxEMM(s) = UTILITY(s) if terminal, maxa EMM(RESULT(s, a)) if MAX, mina EMM(RESULT(s, a)) if MIN, ∑r P(r) EMM(RESULT(s, r)) if CHANCE
  • UCB1 (upper confidence bound)UCB1(i) = wi ⁄ ni + C √(ln N ⁄ ni)
  • Expected valueE[X] = ∑x P(x) × x

Step 7Core AI · Logic and knowledge

7.1Knowledge, logic and propositional logic

  • KB agent TELL percepts, ASK for an action, TELL the action. Inference happens inside ASK.
  • Entailment KB ⊨ α iff M(KB) ⊆ M(α). Sound: derives only entailed. Complete: derives all entailed.
  • Connectives ¬ ∧ ∨ ⇒ ⇔, in that order of precedence. P ⇒ Q false only for P = T, Q = F.
  • Wumpus KB R1 ¬P11, R2 B11 ⇔ (P12 ∨ P21), R3 B21 ⇔ (P11 ∨ P22 ∨ P31), R4 ¬B11, R5 B21. 3 of 128 models. Entails ¬P12.
  • Validity KB ⊨ α iff KB ⇒ α is valid iff KB ∧ ¬α is unsatisfiable. SAT is NP-complete.
  • EntailmentKB ⊨ α if and only if M(KB) ⊆ M(α)
  • Deduction theoremKB ⊨ α if and only if (KB ⇒ α) is valid
  • Proof by contradiction (refutation)KB ⊨ α if and only if (KB ∧ ¬α) is unsatisfiable
  • Number of models2n for n symbols
  • Trap P ⇒ Q is true whenever P is false. "If 5 is even, then Sam is smart" is true in propositional logic, whatever Sam is like. Implication does not mean that P causes Q.

7.2Reasoning patterns: rules, resolution and chaining

  • Rules Modus Ponens: α ⇒ β, α ⊢ β. And-Elimination. Equivalences as rules. Monotonic.
  • Resolution ℓ ∨ α, ¬ℓ ∨ β ⊢ α ∨ β. One pair at a time. Refutation complete.
  • CNF steps Remove ⇔, remove ⇒, move ¬ in (De Morgan, double negation), distribute ∨ over ∧.
  • Chaining Definite clause: exactly one positive literal. Forward from facts, backward from goal. Linear time.
  • SAT DPLL: early termination, pure symbol, unit clause. WalkSAT: local search, incomplete. CDCL in practice.
  • The resolution rulefrom ℓ1 ∨ ... ∨ ℓk and m1 ∨ ... ∨ mn, where ℓi and mj are opposite literals, conclude the clause of all the other literals
  • Possible clauses over n symbols3n
  • Exam The ground resolution theorem: if a set of clauses is unsatisfiable, resolution will reach the empty clause. So resolution is a complete refutation procedure for propositional logic. It cannot list every entailed sentence directly, but it can always confirm or refute a given one.

7.3First order logic: syntax and semantics

  • Syntax Constants, predicates, functions, variables. Terms name objects, atoms are true or false.
  • Semantics Model = domain + interpretation. Infinitely many models, so no truth tables.
  • Quantifier traps ∀ with ⇒, ∃ with ∧. ∀x ∃y ≠ ∃y ∀x. ¬∀x P ≡ ∃x ¬P.
  • Equality x = y means same object. Needed for "at least two". Database semantics: unique names, closed world, domain closure.
  • Engineering Questions, knowledge, vocabulary, general axioms, instance facts, queries, debug.
  • De Morgan for quantifiers∀x ¬P ≡ ¬∃x P, ¬∀x P ≡ ∃x ¬P, ∀x P ≡ ¬∃x ¬P, ∃x P ≡ ¬∀x ¬P
  • Interpretations over a fixed domain of d objectsdc × (2d)u × (2d²)b
  • Trap First order logic has infinitely many models: any domain size from 1 upwards, and every interpretation of every symbol. So entailment cannot be checked by listing models, as we did with truth tables.

7.4Inference in first order logic: unification, chaining and resolution

  • UI and EI UI: any ground term, many times. EI: new Skolem constant, once. Propositionalisation: kv copies. Semidecidable.
  • Unify {x/Jane}, {y/John, x/Bill}, {y/John, x/Mother(John)}, fail for Knows(x, Elizabeth). Occurs check. Standardise apart. MGU.
  • GMP and FC Generalised Modus Ponens with θ. Crime: round 1 Weapon, Sells, Hostile, round 2 Criminal(West). Datalog stops.
  • BC Goal driven, depth first, left to right (Prolog). Left recursion loops. Negation as failure.
  • FOL resolution CNF: remove ⇒, ¬ in, standardise, Skolemise (∃y inside ∀x gives F(x)), drop ∀, distribute. Refutation complete.
  • Generalised Modus Ponens (GMP)from p1′, ..., pn′ and (p1 ∧ ... ∧ pn ⇒ q), infer SUBST(θ, q), where SUBST(θ, pi′) = SUBST(θ, pi) for every i
  • Binary resolutionfrom ℓ1 ∨ ... ∨ ℓk and m1 ∨ ... ∨ mn with UNIFY(ℓi, ¬mj) = θ, infer SUBST(θ, all other literals)
  • Ground instances of one rulekv
  • Trap The occurs check (does the variable appear inside the term?) makes unification cost quadratic in the size of the terms. Prolog leaves it out for speed, so Prolog can unify x with F(x) and build an endless term.

Step 8Core AI · Planning

8.1Situation calculus and deductive planning

  • Situations S0, Result(a, s). Fluents take s as last argument. Atemporal predicates do not.
  • Axioms Possibility: Poss(a, s) ⇔ preconditions. Effect: Poss(a, s) ⇒ effect in Result(a, s).
  • Frame problem Effect axioms do not say what stays. A × F frame axioms, or F successor state axioms (Reiter).
  • SSA form F(Result(a, s)) ⇔ a made F true ∨ (F(s) ∧ a did not make F false). Needs unique action axioms.
  • Deductive planning Green 1969: prove ∃s Goal(s), extract s. Slow, so STRIPS (1971).
  • Successor state axiom (one per fluent F)Poss(a, s) ⇒ [F(Result(a, s)) ⇔ (a made F true) ∨ (F(s) ∧ a did not make F false)]
  • Frame axioms neededA × F
  • Successor state axioms neededF

8.2STRIPS planning and sub goals

  • STRIPS State = set of facts. Action = PRE, ADD, DEL. RESULT = (s − DEL) ∪ ADD. Unmentioned facts stay.
  • Regression g′ = (g − ADD) ∪ PRE, for actions that add part of g and delete none of it.
  • Heuristics Ignore preconditions, ignore delete lists (h+ admissible, hFF greedy), sub goal independence.
  • Sussman anomaly C on A, goal A on B and B on C. Either sub goal order undoes the other. Shortest plan 3: C to table, B on C, A on B.
  • Complexity STRIPS planning is PSPACE-complete. Blocks world states: 13 for 3 blocks, 73 for 4.
  • Applying an actionRESULT(s, a) = (s − DEL(a)) ∪ ADD(a), if PRE(a) ⊆ s
  • Regressiong′ = (g − ADD(a)) ∪ PRE(a)
  • Ground actions in the blocks world with n blocksn(n − 1) MoveToTable + n(n − 1) Move from the table + n(n − 1)(n − 2) Move between blocks
  • Trap Regressing On(A, B) ∧ On(B, C) through Move(B, Table, C) gives a goal with both On(A, B) and Clear(B), which no state can satisfy. Backward planners need extra rules (state constraints) to throw such goals away early.

8.3Partial order planning

  • Partial plan Steps, orderings A ≺ B, causal links A →p→ B, open preconditions. Start gives the initial state, Finish needs the goal.
  • Threat C deletes p and could run between A and B of the link A →p→ B.
  • Fixes Demotion: C ≺ A. Promotion: B ≺ C. Keep the orderings free of cycles, else go back.
  • Solution No open preconditions, no threats, no cycles. Every linearization then reaches the goal.
  • Counting Independent chains n₁, ..., n_k give (Σ n_i)! ÷ Π n_i! linearizations. Socks and shoes: 6.
  • Sussman by POP MoveToTable(C, A) ≺ Move(B, Table, C) ≺ Move(A, Table, B), found by two promotions.
  • ThreatC deletes p, and neither C ≺ A nor B ≺ C follows from the orderings
  • Linearizations of independent chains(n₁ + n₂ + ... + n_k)! ÷ (n₁! n₂! ... n_k!)

Step 9Core AI · Probability and Bayesian networks

9.1Probability for AI agents

9.2Bayesian networks and Markov networks

9.3Inference in Bayesian networks

  • Enumeration P(X | e) = α Σ_y Π P(xᵢ | parents). O(2ⁿ) time, O(n) space. P(b | j, m) ≈ 0.284.
  • Variable elimination Factors from CPTs with evidence. Multiply factors with X, sum out X. Cost exponential in the largest factor (treewidth). Drop non ancestors.
  • Complexity Polytree: linear. General: #P-hard (Cooper 1990).
  • Samplers Rejection: N(x, e) ÷ N(e). LW: w = Π P(eᵢ | parents). Gibbs: sample from P(x | mb(X)). Error ≈ √(p(1 − p) ÷ N).
  • Key numbers LW sample weight 0.1 × 0.99 = 0.099. P(Rain | s, w) = 0.3204. P(Rain | s) = 0.3.
  • EnumerationP(B | j, m) = α Σ_e Σ_a P(B) P(e) P(a | B, e) P(j | a) P(m | a)
  • Summing outh(X, Z) = Σ_y f(X, y, Z)
  • Likelihood weightw = Π over evidence variables Eᵢ of P(eᵢ | parents(Eᵢ))
  • Likelihood weighting is consistentS_WS(z, e) w(z, e) = Π P(zᵢ | parents) × Π P(eᵢ | parents) = P(z, e)
  • Trap Enumeration repeats work: P(j | a) P(m | a) is computed again for each value of e. Variable elimination stores such parts once.
  • Trap Likelihood weighting suffers when evidence comes late in the order (at the leaves): the samples ignore it while choosing the earlier variables, so most of them get tiny weights.

9.4Causality: seeing, doing and imagining

  • Ladder Seeing P(y | x), doing P(y | do(x)), imagining counterfactuals.
  • do operator Cut arrows into X, drop its CPT (truncated product). Root X: do equals see.
  • Back door Z has no descendant of T and blocks all T ← ... paths: P(r | do(t)) = Σ_z P(r | t, z) P(z).
  • Simpson's paradox Kidney stones: seeing A 0.78 < B 0.826, doing A 0.833 > B 0.779. Adjust for confounders, not mediators or colliders.
  • Counterfactual Abduction (find U), action (set X), prediction (recompute Y). Front door: Σ_m P(m | x) Σ_x′ P(y | m, x′) P(x′).
  • Sprinkler P(Rain | s) = 0.3 but P(Rain | do(s)) = 0.5. P(WetGrass | do(s)) = 0.945.
  • Truncated factorisationP(v | do(x)) = Π over i with Vᵢ not X of P(vᵢ | parents(Vᵢ)), with X = x

  • Back doorP(y | do(x)) = Σ_z P(y | x, z) P(z)
  • Trap A plain Bayesian network can be read in a non causal order and still give the right P(y | x). It can only answer rung 2 questions when its arrows are causal.
  • Trap Simpson’s paradox is not a fault in arithmetic. Which answer is right, the pooled one or the one inside groups, depends on the causal graph. With stone size as a confounder, the group answer (A is better) is right. If Z were a mediator, the pooled answer would be right.

Step 10Core AI · Reinforcement learning

10.1Markov decision processes

  • MDP States, actions, P(s′ | s, a), R, γ. Solution: policy π(s). Utility = E[Σ γᵗ Rₜ] ≤ R_max ÷ (1 − γ).
  • Bellman U(s) = R(s) + γ max_a Σ P(s′ | s, a) U(s′). Q(s, a) = Σ P [R + γ max Q(s′, a′)]. U = max_a Q.
  • Value iteration Repeat the update. Contraction by γ. Stop when δ < ε(1 − γ) ÷ γ. 4 × 3: U(1,1) = 0.705.
  • Policy iteration Evaluate (linear equations, O(n³)), improve greedily, stop when unchanged. Few rounds.
  • Racing car γ = 0.9: V₁ = (2, 1), V₂ = (3.35, 2.35). Optimal: cool fast, warm slow, V = (15.5, 14.5).
  • Utility of a reward sequenceU = R₀ + γ R₁ + γ² R₂ + ... = Σ γᵗ Rₜ
  • Bellman equationU(s) = R(s) + γ max over a of Σ over s′ of P(s′ | s, a) U(s′)
  • Policy evaluationU^π(s) = R(s) + γ Σ P(s′ | s, π(s)) U^π(s′)
  • Bound on utilities|U(s)| ≤ R_max ÷ (1 − γ)

10.2Passive reinforcement learning

  • Passive RL Fixed π, unknown P and R, learn U^π from trials. Direct estimation, ADP, TD.
  • TD(0) U(s) ← U(s) + α (R(s) + γ U(s′) − U(s)). δ = TD error. Robbins Monro: Σα = ∞, Σα² < ∞.
  • ADP P̂(s′ | s, a) = N(s, a, s′) ÷ N(s, a), then policy evaluation. Fewest trials, most work per step.
  • Bias and variance Monte Carlo return: unbiased, high variance. TD target: biased, low variance. TD(λ) mixes.
  • Key numbers Three trials: U(1,1) ≈ 0.0933 (true 0.705). P̂((2,3) | (1,3)) = 2/3. Random walk values k ÷ 6.
  • TD(0) updateU(s) ← U(s) + α (R(s) + γ U(s′) − U(s))
  • Learned modelP̂(s′ | s, a) = N(s, a, s′) ÷ N(s, a)
  • TD targetRₜ + γ U(Sₜ₊₁)

10.3Active reinforcement learning

  • Explore or exploit ε-greedy, exploration function f(u, n) = R⁺ if n < N_e else u, UCB1 x̄ + √(2 ln n ÷ nᵢ). GLIE.
  • Q-learning Q ← Q + α [r + γ max Q(s′, a′) − Q]. Off policy, model free. Converges with every pair tried and Robbins Monro α.
  • SARSA Q ← Q + α [r + γ Q(s′, a′) − Q] with the a′ actually taken. On policy. Safer path on the cliff.
  • Approximation θ ← θ + α [target − Q̂] ∇Q̂. DQN: replay buffer + target network. Deadly triad.
  • Key numbers ε-greedy best action: 1 − ε + ε/|A|. Corridor Q*: 1, 0.9, 0.81. Cliff: Q-learning path 13 steps.
  • Exploration function (AIMA)f(u, n) = R⁺ if n < N_e, else u
  • Q-learning updateQ(s, a) ← Q(s, a) + α [r + γ max over a′ of Q(s′, a′) − Q(s, a)]
  • Gradient TD updateθᵢ ← θᵢ + α [target − Q̂(s, a)] ∂Q̂ ÷ ∂θᵢ
  • Bellman optimality for QQ*(s, a) = Σ P(s′ | s, a) [R(s, a, s′) + γ max over a′ of Q*(s′, a′)]
  • Trap With function approximation, Q-learning can diverge: off policy data, bootstrapping and approximation together (the deadly triad). DQN’s replay buffer and target network were added to keep training stable.

10.4Policy search and policy gradients

  • Policy search Parameterise π_θ, maximise ρ(θ) = E[Σ γᵗ Rₜ]. Use stochastic (softmax) policies so ρ is smooth.
  • Policy gradient ∇ρ = E[∇ log π_θ(a | s) Q^π(s, a)]. Softmax: ∂ log π(a) ÷ ∂θ_k = 1[k = a] − π(k).
  • REINFORCE θ ← θ + α (G − b) ∇ log π(a | s). Baseline unbiased since E[∇ log π] = 0.
  • Actor critic δ = r + γV(s′) − V(s). Actor θ += α δ ∇ log π, critic w += β δ ∇V. PPO clips the ratio.
  • From experts Behaviour cloning copies actions. Inverse RL learns the reward (Ng and Russell 2000).
  • Policy valueρ(θ) = E[Σ γᵗ Rₜ | actions from π_θ]
  • Policy gradient theorem∇ρ(θ) = E[∇_θ log π_θ(a | s) Q^π(s, a)]
  • Actor criticδ = r + γ V(s′) − V(s), θ ← θ + α δ ∇ log π_θ(a | s)
  • Log derivative trick∇ π(a) = π(a) ∇ log π(a)
  • Trap With a greedy policy (always the best action under some score) ρ(θ) jumps when the best action changes, so its gradient is zero almost everywhere. That is why policy gradient methods use stochastic policies.

4.3Solution concepts and Pareto optimality

  • Solution concept Narrows profiles to reasonable ones. Its pick is an equilibrium. Not a physics equilibrium.
  • Four assumptions Rational (maximize), intelligent (know the game), common knowledge of both, self enforcement (no outside enforcer).
  • Good concept Existence, uniqueness, invariance. "Anything can happen" exists but is not unique.
  • Pareto s dominates s′: ≥ for all, > for one. PD: only (C, C) fails. Marketing War: (L,L), (L,M), (M,L). Zero sum: all optimal.
  • Altruism vᵢ + ½vⱼ gives (−3,−3), (−5.5,−3.5), (−3.5,−5.5), (−6,−6). Mum becomes best. Pareto is not fairness.
  • Pareto dominances Pareto dominates s′ ⟺ vi(s) ≥ vi(s′) for all i, and > for at least one j
  • Pareto optimals′ is not Pareto dominated by any profile
  • Altruistic payoffvialt(s) = vi(s) + ½ vj(s)
  • Trap Pareto optimality says nothing about fairness. (2, 8) and (8, 2) are Pareto optimal next to the balanced (6, 6). It only rules out waste.
  • Trap Pareto optimal and fair are different ideas. Pareto says nothing about how the total is shared.

Step 5Advanced AI · Dominance and iterated elimination

5.1Dominance and the dominant strategy equilibrium

  • Strict domination sᵢ ▷ s′ᵢ: vᵢ(sᵢ, s₋ᵢ) > vᵢ(s′ᵢ, s₋ᵢ) for every s₋ᵢ. Row player: first numbers across columns. Column player: second numbers down rows.
  • Vocabulary Dominating/dominated: beats/is beaten by at least one. Dominant/submissive: beats/is beaten by all. One dominator is enough to delete.
  • Partial order ▷ is irreflexive, asymmetric, transitive, not complete (RPS, M and H in the Marketing War). Weak: ≥ (textbook adds > once).
  • DSE Everyone plays a strictly dominant strategy. Unique if it exists. PD (C, C), altruistic PD (M, M), RPS and Marketing War none.
  • Rationality A rational player never plays a strictly dominated strategy under any belief. Increasing transforms and h(s₋ᵢ) do not change dominance.
  • Strict dominationsi ▷i s′i ⟺ vi(si, s−i) > vi(s′i, s−i) for every s−i
  • Strict dominant strategy equilibriumsD with siD strictly dominant for every player i
  • Rational players and dominated strategiesEμ[vi(si)] − Eμ[vi(s′i)] = ∑ μ(s−i)[vi(si, s−i) − vi(s′i, s−i)] > 0
  • Trap The mistake made twice in class: checking player 1 by mixing in the second number of each cell, or by moving down a column. Rule: for the row player compare first numbers, moving across columns. For the column player compare second numbers, moving down rows. Moving along the other player's strategies is exactly "for every s₋ᵢ".
  • Trap Strict and weak dominance behave differently. Removing weakly dominated strategies can remove equilibria and depends on the order of removal.

5.2Iterated elimination of dominated strategies

  • Algorithm Each round delete every strictly dominated strategy of every player, comparing only survivors. Stop when nothing is dominated.
  • Common knowledge Round k uses k layers of "I know that you know". Real people manage about 1 to 3 layers.
  • Slide 11 R ▷ C, then U ▷ M and D, then L ▷ R. Outcome (U, L) = (4, 3), self enforcing but Pareto dominated by (9, 6).
  • Theorems DSE found in one round. Every NE survives. Unique survivor = unique NE. Strict IESDS is order independent.
  • Limits Marketing War leaves {M, H}², RPS deletes nothing. Weak IESDS depends on order: (2, 1) or (1, 1).
  • IESDS, round kDSik = {{ si ∈ Sik : some s′i ∈ Sik beats it against every s−i ∈ S−ik }}
  • UpdateSik+1 = Sik ∖ DSik
  • Nash equilibrium (preview)vi(si*, s*−i) ≥ vi(si, s*−i) for every i and every si
  • Trap IESDS does not always leave one outcome. In many games, such as the restaurant game, nothing is dominated and every strategy survives.

5.3Dominance at work: Cournot, auctions and voting
