Lesson 1 of 8

Local search: forget the path, improve the state

Source: slide Set 2, slides 77 to 80, and the class of 1 February 2026.

The search methods so far explore paths systematically. They can handle spaces of up to roughly 10100 states (about 500 binary variables, a ballpark number). Some real problems are far bigger, for example 1030,000 states. And in many problems, like 8 queens or timetabling, only the final state matters, not the path to it.

What it is
Local search keeps one current state (or a few) and moves to a neighbouring state that is better, judged by an objective function. It does not store paths.
Why we need it
It uses very little memory, usually a constant amount, and it can find good solutions in huge or even continuous spaces where systematic search is hopeless.
How it works
Start from a guess (often random, maybe not even valid). Measure its quality. Make a small local change using a neighbourhood function. Repeat until a goal is found, time runs out, or the result is good enough.

Picture the state space landscape: each state is a location, and its objective value is the height. Maximising means finding the highest peak (the global maximum). Minimising a cost means finding the lowest valley (the global minimum). The same ideas work for both by flipping the sign.

Feature of the landscapeWhat it isWhy it is a problem
Local maximumA peak higher than all its neighbours but lower than the global maximumEvery move goes down, so a greedy climber stops
RidgeA narrow line of peaks with slopes on both sidesNo single move goes up along the ridge, so the climber zig zags slowly
Plateau: flat local maximumA flat area with no uphill exitNo neighbour is better
Plateau: shoulderA flat area from which you can still go up laterThe climber cannot see that, and stops unless it may move sideways
Lesson 2 of 8

Hill climbing

What it is
Steepest ascent hill climbing moves to the best neighbour, as long as it is better than the current state. It stops when no neighbour is better.
Why we need it
It is the simplest local search: fast, almost no memory, and often good enough. Each step uses only the current state.
How it works
Compute the objective of every neighbour. If the best one is higher, move there. Otherwise stop and return the current state, which is a peak, but maybe only a local one.
Steepest ascent hill climbing
function HILL-CLIMBING(problem):
    current = initial state
    loop:
        neighbour = the highest valued successor of current
        if VALUE(neighbour) <= VALUE(current): return current
        current = neighbour

8 queens

States: 8 queens, one per column. A move: move one queen within its column, so each state has 8 × 7 = 56 neighbours. The cost h is the number of attacking pairs, which we want to bring down to 0.

Random restartExam favourite
expected restarts = 1 ⁄ p
p is the chance one run succeeds. For 8 queens p ≈ 0.148, so about 7 runs: 6 failures (about 3 steps each) and 1 success (about 4 steps), roughly 22 steps in all.
Remember
Local beam search is not k independent restarts. If one state finds a great region, its children can fill all k places, so the search moves its effort to where the progress is.
Lesson 4 of 8

Simulated annealing

Source: slide Set 2, slides 82 and 83.

What it is
Simulated annealing is hill climbing that sometimes accepts a worse move. The chance of accepting a worse move depends on how much worse it is and on a temperature T that slowly goes down.
Why we need it
A pure climber never goes down, so it gets stuck on the first peak. A random walk explores but never settles. Annealing starts like a random walk (exploration) and ends like a climber (exploitation), so it can escape local peaks early and settle on a good one later.
How it works
Pick a random neighbour. If it is better, move. If it is worse by ΔE < 0, move with probability eΔE⁄T. Lower T after each step by the cooling schedule.
Acceptance probabilityExam favourite
P(accept) = eΔE ⁄ T for ΔE < 0, and 1 for ΔE ≥ 0
High T: P near 1, almost any move is accepted. Low T: P near 0, only uphill moves.
Why the slide table
as T grows, ΔE ⁄ T → 0 and eΔE⁄T → e0 = 1
The slide lists ex for x = 1, 1⁄2, 1⁄4, ..., 1⁄1024: 2.718, 1.649, 1.284, ..., 1.001. As the exponent shrinks, the value approaches 1.
Cooling schedule (slide 83)FormulaComment
GeometricTk+1 = α Tk, 0.8 ≤ α ≤ 1The most common. α near 1 cools slowly and explores longer.
LinearTk = T0 − k ΔTDrops by the same amount each step.
LogarithmicTk = C ⁄ ln(k + 2)C = the highest energy barrier to cross. Very slow, but with it annealing finds the global optimum with probability approaching 1.
ConstantTk = CThis is the Metropolis algorithm, no cooling.
ExponentialTk = T0 αkThe closed form of geometric cooling.
Remember
Choose T0 so that most worse moves are accepted at the start, often from the average cost difference between neighbours. Too fast cooling turns annealing into plain hill climbing.
Lesson 5 of 8

The maths: acceptance, restarts and gradients

Worked example: acceptance probability
  1. A worse move with ΔE = −2.
  2. At T = 10: e−2⁄10 = e−0.2 ≈ 0.819. Accepted about 82 percent of the time.
  3. At T = 1: e−2 ≈ 0.135.
  4. at T = 0.2: e−10 ≈ 0.0000454, almost never
Worked example: geometric cooling
  1. T0 = 100, α = 0.9. After k steps T = 100 × 0.9k.
  2. We want T < 1: 0.9k < 0.01, so k > ln 0.01 ⁄ ln 0.9 = 4.605 ⁄ 0.1054 ≈ 43.7.
  3. 44 steps to cool from 100 to below 1
Gradient ascent for continuous statesExam favourite
x ← x + η ∇f(x)
In continuous spaces, move a small step η along the gradient. Too big η overshoots, too small is slow.
Newton Raphson step
x ← x − Hf(x)−1 ∇f(x)
Uses the second derivatives (Hessian H) to choose the step. Very fast near an optimum.
Probability of success with r restarts
1 − (1 − p)r
p = 0.148, r = 10: 1 − 0.852¹⁰ ≈ 0.80.

Comparing local search methods

Bottom line: start with hill climbing and random restarts. Move to annealing when restarts keep landing on poor peaks, and to a genetic algorithm when solutions have reusable building blocks.

Real world scenario: chip layout and timetabling

Placing millions of logic cells on a chip so that wires are short is a huge optimisation problem. Simulated annealing was one of the first methods to do it well (Kirkpatrick and others, 1983), and annealing style placers are still used. University timetabling uses local search too: start with any timetable, then repeatedly move one lecture to a different room or time if it reduces clashes.

Lesson 7 of 8

From intuition to research

One idea, four depths

Hill climbing is like walking up a hill in fog: you only feel the ground at your feet, so you always step uphill. You may end on a small hill. Annealing is like shaking a tray of marbles: shake hard at first, then gently, so the marbles settle into the deepest holes.

Local search keeps one state and an objective. Hill climbing stops at local maxima, ridges and plateaux. Fixes: sideways moves, random restarts (1 ⁄ p runs), beam search. Annealing accepts worse moves with eΔE⁄T and cools T by a schedule.

With logarithmic cooling Tk = C ⁄ ln(k + 2), annealing converges to a global optimum with probability 1, because it is a Markov chain whose stationary distribution concentrates on the optima as T → 0. The price is an impractically slow schedule, so real systems use geometric cooling and restarts.

Research looks at parallel tempering (many temperatures that swap states), tabu search (forbid recent moves), large neighbourhood search that solves a sub problem exactly at each step, and quantum annealing hardware that uses tunnelling to cross energy barriers.

Lesson 8 of 8

Chapter summary

  1. Local search keeps one state, moves to better neighbours, and stores no path. It uses constant memory and works on huge spaces.
  2. Hill climbing takes the best neighbour until none is better. It stops at local maxima, ridges and plateaux. On 8 queens it solves about 14 percent of boards in about 4 steps.
  3. Sideways moves raise that to about 94 percent. Random restarts need about 1 ⁄ p runs. Local beam search keeps the best k states.
  4. Simulated annealing accepts a worse move with probability eΔE⁄T. High T explores, low T exploits.
  5. Cooling schedules: geometric α T, linear T0 − kΔT, logarithmic C ⁄ ln(k + 2), constant, exponential T0 αk.
