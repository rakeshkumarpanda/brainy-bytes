Lesson 1 of 8

Why search, and what a search problem is

Source: slide Set 2 (Searching Techniques), slides 1 to 24, and the class of 24 January 2026.

You are on holiday in Edinburgh and your flight leaves from London tomorrow. You think: "If I take the 6 am train, where will I be at 2 pm? Will I still reach the airport on time?" This is hypothetical reasoning: you imagine what state you will be in after some actions, and look for a sequence of actions that brings you to a state you want. Search is the computer's way of doing exactly this.

What it is
A general method that tries out sequences of actions, on paper, to find one that turns the start state into a goal state.
Why we need it
Many problems have no special formula, but they can be written as states and actions. Search then solves them all with one method. It is the hidden engine inside route finders, puzzle solvers, game players and planners.
How it works
Write the problem as a state space with actions, a start and a goal test. Keep a list of paths still to explore (the frontier, also called OPEN). Repeatedly take a path out, check if it ends at a goal, and if not, extend it by every action.

Why search works well, and where it stops

Why searchLimits of search
Game playing programs based on search beat world champions.Search does not tell you how to formulate the problem. Choosing the states and actions is up to you.
Many problems have no special algorithm. Casting them as search is often the easiest way.Search only solves a problem once it is correctly formulated.
Local search gives good approximations for huge optimisation problems.Without good knowledge (heuristics) it can be very slow.
Problem specific heuristics let search use extra knowledge, and planning can be cast as search.
Real world scenario: a teacher in class

In class the professor described her own lecture as a search problem. The start state is "I have just said something and five of you look confused". The goal state is "everybody understands". Each transition is a new example or a new explanation. The heuristic is her sense of which example will help most, and a constraint is the time left in the class. Because students keep asking questions, the next state is never fully known in advance, so she keeps choosing again. That is a search through states, done live.

The formalism: states, actions, start, goal

To turn a problem into a search problem, write down four things.

PartMeaningRomania tripWater jugs
State spaceAll configurations the problem can be in, kept as computer dataThe city you are inPairs (gal3, gal4), gallons in each jug
Actions (transitions)Moves from one state to anotherDrive to a neighbouring cityFill, empty, or pour one jug into the other
Initial state and goalWhere you start and the condition you wantIn Arad, goal: be in BucharestStart (0, 0), goal e.g. (0, 2) or (*, 3)
HeuristicsHints that guide the searchStraight line distance to BucharestHow far each jug is from the target amount

Abstraction means leaving out details that do not matter. For Romania we ignore the radio, the weather and where exactly on the road the car is. We keep only the city. A good abstraction keeps what you need to find a valid plan and nothing more.

Observations from the slides about the jugs: from whole numbers you only ever reach whole numbers. Some states, for example (1, 2), can never be reached from (0, 0). Some actions do not change the state at all, for example emptying an empty jug. Of the 4 × 5 = 20 possible pairs, only 14 can be reached from (0, 0).

Remember
The goal can be a condition, not one state. "(*, 3)" means any state where the 4 gallon jug holds 3, whatever the 3 gallon jug holds. The goal test is a function that returns true or false.
Lesson 3 of 8

Inputs, outputs and nodes of a search algorithm

Every search algorithm in this course gets the same inputs and returns the same kind of answer.

Successor functionExam favourite
S(x) = {⟨y, a⟩ : action a takes x to y}
All states one action away from x, each tagged with the action used. Two different actions may reach the same state.
Action cost
C(x, a, y) ≥ ε > 0
The cost of going from x to y with action a. C = ∞ if a does not lead from x to y. Every cost is at least a small positive ε.
Path costExam favourite
g(n) = ∑i C(si, ai, si+1)
Add the costs along the path from the start to node n.

The output is a sequence of states (or actions) from the start to a state that passes the goal test. Some algorithms promise the cheapest path, some the shortest, some promise nothing.

A node is a path

A node is a bookkeeping record for one path. It has four fields: n.STATE (the state it ends in), n.PARENT (the node it came from), n.ACTION (the action that made it) and n.PATH-COST, written g(n). Following PARENT links back to the start rebuilds the whole path.

The search template (slide 18)
function TREE-SEARCH(problem):
    frontier = { node(initial state) }
    loop:
        if frontier is empty: return failure
        n = take a node out of the frontier      # the selection rule
        if GOAL-TEST(n.STATE): return the path of n
        add every child of n to the frontier

function GRAPH-SEARCH(problem):
    same, but keep an explored set:
    add n.STATE to explored after taking n out,
    and add a child only if its state is not in the frontier or explored
Common mistake
Cycles can cause non termination. Arad → Sibiu → Arad → Sibiu ... is a valid path in tree search, so a search may never stop. Graph search fixes this by remembering explored states.
Lesson 4 of 8

The selection rule and the four properties

Every search algorithm in chapters 2 to 4 follows the template above. They differ in one thing only: which node they take out of the frontier next (the selection rule). This choice decides whether a solution is found, how much it costs, and the time and memory needed.

PropertyQuestion it answers
CompletenessIf a solution exists, will the algorithm always find one?
OptimalityWill it find the cheapest solution (when actions have costs)?
Time complexityHow many nodes does it generate before it finds a solution?
Space complexityWhat is the largest number of nodes it must keep in memory?
Branching factor and depth
b = most children of any node, d = depth of the shallowest goal, m = largest depth
These three numbers measure every algorithm.
Nodes in a full treeExam favourite
1 + b + b² + ... + bd = (bd+1 − 1) ⁄ (b − 1) = O(bd)
The number of nodes up to depth d. It grows exponentially with d.
Worked example: how big is a search tree?
  1. Take b = 10 and d = 5.
  2. 1 + 10 + 100 + 1,000 + 10,000 + 100,000 = 111,111 nodes
  3. At 1 million nodes a second this takes about 0.1 seconds.
  4. With d = 10 it is about 1.1 × 10¹⁰ nodes, which takes about 3 hours. One more level multiplies the work by b.

Food for thought from the slides

Try to write each of these as a search problem with states, actions, start and goal: making a cup of tea, buying a book online, picking an example to explain a doubt in class, and a doctor's differential diagnosis. For tea, a state could be (water boiled?, tea in cup?, milk added?, sugar added?), and actions boil, add tea, add milk, add sugar, stir.

The maths behind search problems

Size of a state space
|S| = product of the number of values of each part of the state
Jugs: 4 values for gal3 (0 to 3) × 5 for gal4 (0 to 4) = 20 states, of which 14 are reachable from (0, 0).
8 puzzle reachable statesExam favourite
9! ⁄ 2 = 181,440
Nine tiles (with the blank) in 9! orders, but only half can be reached from a given start, because a move never changes the parity of the arrangement.
Paths are much bigger than statesExam favourite
tree nodes up to depth d ≈ bd while states may be few
In a grid with 4 moves, a tree search to depth d makes 4d paths but only about 2d² distinct cells are within d steps. This is why graph search remembers explored states.
Worked example: why repeated states matter in a grid
  1. Robot on an open grid, 4 moves: up, down, left, right. b = 4.
  2. Tree search to depth 10: 1 + 4 + ... + 4¹⁰ = (4¹¹ − 1) ⁄ 3 = 1,398,101 nodes.
  3. Cells within 10 steps (a diamond): 2 × 10² + 2 × 10 + 1 = 221.
  4. Graph search touches at most 221 states, about 6,000 times fewer

How problem formulation choices compare

Tree search against graph search
Tree searchGraph search
Remembers explored states?NoYes (explored set)
Can loop for ever on cycles?YesNo, on a finite state space
MemoryOnly the frontierFrontier plus every explored state
Best whenThe space is a true tree, or memory is very tightMany paths lead to the same state (maps, puzzles)

Bottom line: use graph search when states repeat, which is almost always. Use tree search with a path check when memory is the problem (as in depth first search, chapter 2.2).

Lesson 7 of 8

From intuition to research

One idea, four depths

Search is trying out moves in your head before you make them, like planning a train trip by checking which trains connect.

A search problem has a state space, actions with costs, a start and a goal test. Nodes are paths with STATE, PARENT, ACTION and PATH-COST. Algorithms differ only in the selection rule, and are judged on completeness, optimality, time and space in terms of b, d and m.

Graph search removes repeated states but needs memory for the explored set. The size of the reachable state space, not the tree, then bounds the work. Choosing the abstraction (what to keep in a state) can shrink a problem by many orders of magnitude.

Automatically finding good abstractions and problem formulations is still open. Modern planners learn state representations and action models from data, and large language models are used to propose formulations that a classical search then solves exactly.

Going deeper: why the 8 puzzle has exactly 9! ⁄ 2 reachable states

Read the tiles in row order, ignoring the blank, and count inversions (pairs in the wrong order). A sideways move does not change this order. An up or down move jumps a tile over two others, which changes the number of inversions by 0 or ±2. So the parity of the inversion count never changes. Half of the 9! arrangements have each parity, and every arrangement with the right parity can be reached, so exactly 9! ⁄ 2 = 181,440 states are reachable.

In the exam
Exam questions often ask you to formulate a problem. Always list all four parts: states, actions (with costs), initial state, goal test. Say how big the state space is.

Chapter summary

  1. Search is hypothetical reasoning: imagine sequences of actions and look for one that reaches the goal.
  2. A search problem has a state space, actions with costs C(x, a, y) ≥ ε > 0, an initial state and a goal test. Heuristics are optional hints.
  3. A node is a path: STATE, PARENT, ACTION, PATH-COST g(n). The frontier (OPEN) holds paths waiting to be extended.
  4. Tree search can loop on cycles. Graph search keeps an explored set and never expands a state twice.
  5. Algorithms differ only in the selection rule. Judge them by completeness, optimality, time and space, using b, d and m. A full tree to depth d has (bd+1 − 1) ⁄ (b − 1) nodes.
