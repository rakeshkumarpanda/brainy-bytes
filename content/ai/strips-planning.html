Lesson 1 of 8

STRIPS: actions with preconditions, add lists and delete lists

Source: Fikes and Nilsson, 1971, and Russell and Norvig, AIMA 3rd ed., section 10.1 (4th ed., section 11.1).

What it is
STRIPS describes a state as a set of ground facts, such as On(C, A) and Clear(B). An action schema lists its preconditions (facts that must hold), its add list (facts it makes true) and its delete list (facts it makes false).
Why we need it
Situation calculus needs a theorem prover and frame axioms. STRIPS is a small language where the frame problem disappears and states can be searched directly, which made fast planners possible.
How it works
An action can run in state s when every precondition is in s. The new state is (s − delete list) ∪ add list. Any fact not mentioned stays as it was: this is the STRIPS assumption. Facts not listed in a state are false (closed world).
Applying an actionExam favourite
RESULT(s, a) = (s − DEL(a)) ∪ ADD(a), if PRE(a) ⊆ s
Delete first, then add.
DomainAction schema (PDDL style)
Blocks worldMove(b, x, y): PRE On(b, x) ∧ Clear(b) ∧ Clear(y). ADD On(b, y) ∧ Clear(x). DEL On(b, x) ∧ Clear(y)
Blocks worldMoveToTable(b, x): PRE On(b, x) ∧ Clear(b). ADD On(b, Table) ∧ Clear(x). DEL On(b, x)
Air cargoFly(p, from, to): PRE At(p, from) ∧ Plane(p) ∧ Airport(from) ∧ Airport(to). ADD At(p, to). DEL At(p, from)
Air cargoLoad(c, p, a): PRE At(c, a) ∧ At(p, a) ∧ Cargo(c) ∧ Plane(p) ∧ Airport(a). ADD In(c, p). DEL At(c, a)
Spare tyrePutOn(t, Axle): PRE Tire(t) ∧ At(t, Ground) ∧ ¬At(Flat, Axle). ADD At(t, Axle). DEL At(t, Ground)

Schemas have variables. A ground action replaces every variable with a constant: Move(C, A, Table) is not allowed (y must be a block), but MoveToTable(C, A) is.

Remember
PDDL (Planning Domain Definition Language, 1998) is the modern form of STRIPS. It adds types, negative preconditions, equality and more, and is used in the International Planning Competition.

Searching forwards and backwards

Source: AIMA 3rd ed., section 10.2.

Forward (progression) searchBackward (regression) search
Starts fromthe initial statethe goal
A stepapply an action whose preconditions holdregress the goal through a relevant action
Branchingevery applicable action, often many irrelevant onesonly actions that achieve part of the goal
Search nodescomplete statessets of goal facts (partial descriptions)
Heuristicseasy to compute from a full stateharder, since nodes are sets of states
RegressionExam favourite
g′ = (g − ADD(a)) ∪ PRE(a)
a is relevant if it adds some fact of g, and consistent if it deletes none.
Common mistake
Regressing On(A, B) ∧ On(B, C) through Move(B, Table, C) gives a goal with both On(A, B) and Clear(B), which no state can satisfy. Backward planners need extra rules (state constraints) to throw such goals away early.
Lesson 3 of 8

Heuristics for planning

Source: AIMA 3rd ed., section 10.2.3, and Hoffmann and Nebel, 2001 (the FF planner).

What it is
Planning heuristics are made automatically from the action schemas by relaxing the problem: removing some of its rules so that it becomes easy to solve. The cost of the relaxed plan estimates the real cost.
Why we need it
Without a heuristic, forward search tries every applicable action. With a good one, planners like FF and Fast Downward solve problems with thousands of actions.
How it works
Ignore preconditions: every action can always run, so count how many actions are needed to make each goal fact true. Ignore delete lists: actions never undo anything, so facts only grow, and a relaxed plan can be found fast. The length of that relaxed plan is the heuristic.
RelaxationHeuristicAdmissible
Ignore preconditionsnumber of unsatisfied goal facts (when each action adds one goal fact), or a set coverYes in its exact form, the set cover version is hard to compute exactly
Ignore delete listsh+, the cost of the best relaxed planYes, but finding h+ is NP-hard
Ignore delete lists, greedy relaxed planhFF (FF planner)No, but very informative
Sub goal independencesum (or max) of the costs of the goals solved one at a timeMax is admissible, sum is not
Heuristics for the Sussman anomaly (true cost 3)
  1. Unsatisfied goals: On(A, B) and On(B, C). Ignore preconditions: h = 2.
  2. Ignore delete lists: MoveToTable(C, A) gives Clear(A). Move(A, Table, B) gives On(A, B). Clear(B) is never deleted, so Move(B, Table, C) still runs and gives On(B, C).
  3. Relaxed plan length: 3.
  4. h = 2 with ignore preconditions, h+ = 3 with ignore delete lists, true cost 3
Lesson 4 of 8

Sub goals and the Sussman anomaly

Source: Sussman, 1975, and AIMA 3rd ed., section 10.4.4.

What it is
A conjunctive goal such as On(A, B) ∧ On(B, C) has sub goals. A linear (non interleaved) planner solves the sub goals one at a time, in some order, and puts the plans one after the other. The original STRIPS planner worked this way with a goal stack.
Why we need it
Splitting a goal into parts makes each part easy. If the parts do not interact (they are independent), this is fast and gives a good plan.
How it works
Pick a sub goal, plan for it from the current state, run the plan, then move to the next sub goal. If a later plan undoes an earlier sub goal (clobbers it), go back and achieve it again.
The Sussman anomaly: start C on A, A and B on the table. Goal On(A, B) ∧ On(B, C)
  1. Order 1, On(A, B) first: move C to the table, put A on B. Now B is under A. To get On(B, C), A must come off B, which undoes On(A, B).
  2. Order 2, On(B, C) first: put B on C. Now A is under C, which is under B. To get On(A, B), C must come off A, so B must come off C first, which undoes On(B, C).
  3. Either order undoes the first sub goal. A linear planner without going back gives a longer plan than needed (5 or 7 actions here).
  4. The best plan interleaves the two sub goals: MoveToTable(C, A) (for On(A, B)), Move(B, Table, C) (for On(B, C)), Move(A, Table, B) (for On(A, B)).
  5. sub goals interact, so plans for them must be interleaved: 3 actions

Interleaving can be done by searching over partial plans instead of states, where steps for different sub goals can be ordered freely. That is the partial order planner of chapter 8.3.

The maths: how big planning problems are

Ground actions in the blocks world with n blocksExam favourite
n(n − 1) MoveToTable + n(n − 1) Move from the table + n(n − 1)(n − 2) Move between blocks
n = 3: 6 + 6 + 6 = 18. n = 4: 12 + 12 + 24 = 48.
States of the blocks world
1, 3, 13, 73, 501, ... for n = 1, 2, 3, 4, 5
The ways to arrange n named blocks into stacks. It grows faster than n!.
Complexity
PlanSAT (is there any plan?) is PSPACE-complete for STRIPS
Bylander, 1994. Bounded PlanSAT (is there a plan of length ≤ k?) is also PSPACE-complete in general, and NP-complete for many restricted forms.
Worked example: regress On(A, B) through Move(A, Table, B)
  1. ADD = {On(A, B)}, so the action is relevant. DEL = {On(A, Table), Clear(B)} does not touch the goal, so it is consistent.
  2. g − ADD = { }.
  3. Add PRE = {On(A, Table), Clear(A), Clear(B)}.
  4. g′ = On(A, Table) ∧ Clear(A) ∧ Clear(B)

Bottom line: heuristic forward search is the usual choice today. Partial order planning still matters when a flexible plan is needed, for example when people or several robots carry out the steps.

Real world scenario: Planning in practice

NASA's Remote Agent planned and controlled the Deep Space 1 spacecraft in 1999. The Mars rovers use planning tools to build each day's list of actions. Logistics companies, video games (the F.E.A.R. game used STRIPS style goal planning for its enemies) and cloud systems that set up servers all use STRIPS style planners.

Lesson 7 of 8

From intuition to research

One idea, four depths

Each action is a card: "you need these things", "you get these things", "you lose these things". A planner chains cards from where you are to what you want.

STRIPS states are sets of facts. RESULT(s, a) = (s − DEL) ∪ ADD. Forward search uses full states, backward search regresses goals through relevant actions. Heuristics come from relaxations. Linear sub goal planning fails on the Sussman anomaly.

Planning with STRIPS is PSPACE-complete. The planning graph (Blum and Furst, 1995) gives admissible heuristics with mutual exclusion links. Landmarks (facts every plan must make true) and abstraction heuristics such as pattern databases power modern optimal planners.

Current research: learning heuristics and generalised policies with neural networks, planning with large language models checked by a classical planner, and temporal and numeric planning (PDDL 2.1) for real time and resources.

Lesson 8 of 8

Chapter summary

  1. STRIPS: states are sets of ground facts, actions have preconditions, an add list and a delete list. Facts not mentioned stay the same.
  2. Forward search applies actions to states. Backward search regresses goals: g′ = (g − ADD) ∪ PRE through relevant, consistent actions.
  3. Heuristics come from relaxed problems: ignore preconditions, ignore delete lists (h+, hFF), sub goal independence.
  4. Solving sub goals one at a time fails when they interact. The Sussman anomaly needs the steps for On(A, B) and On(B, C) to be interleaved.
  5. STRIPS planning is PSPACE-complete, yet heuristic planners solve large real problems.
