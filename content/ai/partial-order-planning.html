Lesson 1 of 7

Partial plans: steps, orderings and causal links

Source: Russell and Norvig, AIMA 3rd ed., section 10.4.4, and AIMA 2nd ed., section 11.3, which gives the full algorithm used here. Sacerdoti (1975) and Tate (1977) built the first planners of this kind.

What it is
A partial order plan is a set of steps with only the orderings that are really needed. It has four parts: the steps, ordering constraints (A ≺ B means A comes before B), causal links (A gives fact p to B, written A →p→ B), and open preconditions (facts some step needs that no link supplies yet).
Why we need it
State space planners fix the full order of every action, even when the order does not matter. Fixing an order too early can force the planner to undo work later. Leaving steps unordered until a clash appears is called least commitment, and it handles sub goals that interact, such as the Sussman anomaly.
How it works
Start with two dummy steps. Start has the initial state as its effects. Finish has the goal as its preconditions. Then repeat: pick an open precondition, add or reuse a step that achieves it, record a causal link and an ordering, and protect every link from steps that could undo it.
PartMeaningSocks and shoes example
Stepsactions in the plan, plus Start and FinishRightSock, RightShoe, LeftSock, LeftShoe
Ordering A ≺ BA must run before BRightSock ≺ RightShoe
Causal link A →p→ BA makes p true for B, and nothing may undo p between themRightSock →RightSockOn→ RightShoe
Open preconditiona precondition with no causal link yetat the start: RightShoeOn and LeftShoeOn of Finish

The finished plan says only that each sock goes on before its shoe. Any total order that keeps those two rules is a valid plan. Such a total order is called a linearization of the partial plan.

Remember
A partial plan is consistent when its orderings have no cycle (A ≺ B and B ≺ A cannot both hold) and no causal link is threatened. A consistent plan with no open preconditions is a solution: every linearization of it reaches the goal.
Lesson 2 of 7

Threats, promotion and demotion

Source: AIMA 2nd ed., section 11.3, and McAllester and Rosenblitt, 1991 (SNLP).

What it is
A step C threatens the causal link A →p→ B when C deletes p and the orderings allow C to run after A and before B. If C ran there, B would no longer have p.
Why we need it
Causal links are the promises a partial plan makes. A threat can break a promise, so the plan would fail in some of its linearizations.
How it works
Fix a threat by adding one ordering. Demotion puts C before A (C ≺ A). Promotion puts C after B (B ≺ C). Keep the fix only if the orderings still have no cycle. If neither works, the planner goes back and tries another choice.
ThreatExam favourite
C deletes p, and neither C ≺ A nor B ≺ C follows from the orderings
C could sit between A and B.
Demotion
add C ≺ A
C runs before p is made.
Promotion
add B ≺ C
C runs after p is used.
Worked example from the Sussman anomaly animation
  1. Link: Start →Clear(C)→ MoveToTable(C, A). MoveToTable(C, A) needs C to be clear.
  2. New step Move(B, Table, C) deletes Clear(C), and nothing yet orders it.
  3. Demotion would put Move(B, Table, C) before Start, which is not allowed: Start is always first.
  4. Promotion puts it after MoveToTable(C, A). The orderings stay free of cycles.
  5. MoveToTable(C, A) ≺ Move(B, Table, C)
Remember
Some textbooks add a third fix for lifted plans with variables: separation, a constraint such as x ≠ C that stops the threatening step from deleting this exact fact.
Lesson 3 of 7

The POP algorithm

Source: AIMA 2nd ed., section 11.3, Penberthy and Weld, 1992 (UCPOP), and Weld, 1994, An Introduction to Least Commitment Planning.

POP (partial order planner)
plan = steps {Start, Finish}, orderings {Start ≺ Finish}, links { }
agenda = every precondition of Finish
loop:
    if the agenda is empty: return plan
    pick an open precondition p of step B from the agenda
    choose a step A that adds p (an old step, or a new one from the schemas)
        if A is new: add A, add Start ≺ A ≺ Finish, put the preconditions of A on the agenda
        add the causal link A →p→ B and the ordering A ≺ B
    for every threat C to any link A →q→ B:
        choose demotion (C ≺ A) or promotion (B ≺ C) if it keeps the orderings free of cycles
        if neither works: fail and go back to the last choice

There are two kinds of choices. Picking which open precondition to work on next does not need going back: every one must be solved in the end. Choosing the achieving step and the threat fix does need going back, so POP is a search over partial plans.

Why POP solves the Sussman anomaly
  1. It adds Move(A, Table, B) for On(A, B) and MoveToTable(C, A) to clear A, with no order against the B steps yet.
  2. It adds Move(B, Table, C) for On(B, C). This step deletes Clear(C), which MoveToTable(C, A) needs, so it is promoted after MoveToTable(C, A).
  3. Move(A, Table, B) deletes Clear(B), which Move(B, Table, C) needs, so it is promoted after Move(B, Table, C).
  4. plan: MoveToTable(C, A), Move(B, Table, C), Move(A, Table, B), 3 actions
Remember
POP is sound (every plan it returns works) and complete (it finds a plan if one exists) when the step and threat choices are searched fully, for example breadth first or with iterative deepening on the number of steps. The animation uses iterative deepening, so it reports the step limit it needed.

The maths: counting orders and checking threats

Linearizations of independent chainsExam favourite
(n₁ + n₂ + ... + n_k)! ÷ (n₁! n₂! ... n_k!)
k chains of steps, chain i has n_i steps in a fixed order, and the chains do not constrain each other. This is the multinomial coefficient.
Two chains of length 2
4! ÷ (2! × 2!) = 24 ÷ 4 = 6
The socks and shoes plan allows 6 total orders.
Steps with no orderings at all
n!
Every order is allowed.
Causal links in a finished plan
number of links = total number of preconditions of all steps (including Finish)
Each precondition gets exactly one link.
Cost of one threat check
links × steps pairs, each needing a reachability test in the ordering graph
Reachability is a graph search, about O(steps + orderings) each time.
Worked example: count the causal links in the finished Sussman plan
  1. Finish needs On(A, B) and On(B, C): 2 preconditions.
  2. Move(A, Table, B) needs On(A, Table), Clear(A), Clear(B): 3.
  3. MoveToTable(C, A) needs On(C, A), Clear(C): 2.
  4. Move(B, Table, C) needs On(B, Table), Clear(B), Clear(C): 3.
  5. 2 + 3 + 2 + 3 = 10 causal links
Worked example: socks, shoes and gloves
  1. Sock then shoe on the right is a chain of 2 steps. Sock then shoe on the left is another chain of 2. The two gloves need no order, so each glove is a chain of 1 step.
  2. Chains have lengths 2, 2, 1, 1. Total steps: 6.
  3. 6! = 720. Divide by 2! × 2! × 1! × 1! = 4.
  4. 720 ÷ 4 = 180 total orders

Bottom line: POP lost the speed race in the late 1990s, but RePOP (Nguyen and Kambhampati, 2001) showed that state space heuristics make it competitive again. Its plans are easy to explain and to run with several agents.

Real world scenario: Where partial order plans are used

NASA spacecraft and rover planners such as the Remote Agent on Deep Space 1 (1999) used plans with flexible timing, a direct descendant of partial order planning. Plans that people carry out, such as maintenance procedures and project schedules, keep only the orderings that matter so that work can run in parallel. Multi robot systems use partial orders so that each robot can move as soon as its own steps are ready.

Lesson 6 of 7

From intuition to research

One idea, four depths

Getting dressed: you must put a sock on before its shoe, but you can do the left or right foot first. A partial order plan writes down only the "before" rules that matter.

A partial plan has steps, orderings, causal links and open preconditions. POP closes open preconditions with causal links and fixes threats by demotion or promotion. A plan is a solution when it has no open preconditions, no threats and no ordering cycles.

Chapman (1987) gave the Modal Truth Criterion for his planner TWEAK, an exact test of when a fact must hold at a point of a partial plan, and showed that such tests become intractable for richer action languages. SNLP (McAllester and Rosenblitt, 1991) made the search systematic, so no partial plan is visited twice. UCPOP (Penberthy and Weld, 1992) added variables, conditional effects and universal quantifiers.

Research: temporal planners with simple temporal networks keep flexible start times. Plan repair and plan explanation reuse causal links. Large language models are now tested on producing partial order plans, with a classical planner or validator such as VAL used to check them.

Chapter summary

  1. A partial order plan has steps, ordering constraints, causal links and open preconditions. Start gives the initial state and Finish needs the goal.
  2. POP picks an open precondition, adds or reuses a step that achieves it, and records a causal link and an ordering.
  3. A step threatens a causal link A →p→ B if it deletes p and could run between A and B. Fix it by demotion (before A) or promotion (after B).
  4. Least commitment: steps stay unordered until a threat forces an order. This solves the Sussman anomaly with 3 actions.
  5. A finished plan stands for all its linearizations. Independent chains of lengths n₁, ..., n_k give (Σ n_i)! ÷ Π n_i! orders.
