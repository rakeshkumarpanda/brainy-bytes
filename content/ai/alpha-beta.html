Lesson 1 of 9

Why we can skip parts of the tree

Source: slide Set 3, slide 7, and the class of 8 February 2026.

What it is
Alpha beta pruning is minimax with two extra numbers, α and β, that let it skip branches which cannot change the final decision. It always returns the same root value as minimax.
Why we need it
Minimax looks at every leaf, and the tree grows as bm. Often one look at a branch already shows that a player will never let the game go there. Reading the rest of that branch is wasted work.
How it works
Search depth first, as minimax does. Carry α (the best value MAX can already guarantee on the path, a lower bound) and β (the best value MIN can already guarantee, an upper bound) down to the children. Send node values back up and update α at MAX nodes and β at MIN nodes. As soon as α ≥ β at a node, stop looking at its remaining children.
Value (slide 7)MeaningStarts atChanged at
αThe highest value MAX can guarantee so far on the path to this node. A lower bound−∞MAX nodes: α = max(α, value)
βThe lowest value MIN can guarantee so far on the path to this node. An upper bound+∞MIN nodes: β = min(β, value)
Direction (slide 7)What moves
Parent to childThe current α and β values
Child to parentThe node value, which then updates α (at a MAX parent) or β (at a MIN parent)

The rule to prune: if at any point α ≥ β, the current branch cannot affect the final decision, because the opponent will avoid this path for a better one. So the branch is pruned and the search moves to the next branch.

Common mistake
The slide text says "the initial value of alpha is +∞" in the line about beta. That is a typing slip: it is β that starts at +∞, and α starts at −∞.
Lesson 2 of 9

The worked example of the slides

Source: slide Set 3, slides 8 and 9.

A is MAX. Its children B and C are MIN. Their children D, E (under B) and F, G (under C) are MAX. The leaves are 2, 3 (under D), 5, 9 (under E), 0, 1 (under F) and 7, 5 (under G). In the animation the same nodes are called B1, B2 and C1 to C4.

Step by step
  1. Start at A with α = −∞ and β = +∞. Pass them down to B and then to D.
  2. D is MAX. It reads 2 (α = 2), then 3 (α = 3). D = 3. Send 3 up to B.
  3. B is MIN: β = min(+∞, 3) = 3. Pass α = −∞ and β = 3 down to E.
  4. E is MAX. It reads 5, so α = 5. Now α = 5 ≥ β = 3. MIN at B already has 3 and will never let play reach E, whatever the 9 is. Prune the 9. E = 5 (at least 5).
  5. B = min(3, 5) = 3. Send 3 up to A: α = max(−∞, 3) = 3.
  6. Pass α = 3 and β = +∞ down to C, then to F. F reads 0, then 1. F = 1.
  7. C is MIN: β = min(+∞, 1) = 1. Now α = 3 ≥ β = 1. MAX at A already has 3 and C can give at most 1. Prune the whole of G (7 and 5).
  8. A = max(3, 1) = 3, the same as minimax, after reading only 5 of the 8 leaves
In the exam
A pruned node gets a bound, not an exact value: E is "at least 5" and C is "at most 1". These bounds are enough to choose the move, which is all we need at the root.
Lesson 3 of 9

The algorithm

ALPHA-BETA-SEARCH
function ALPHA-BETA-SEARCH(state):
    v = MAX-VALUE(state, −∞, +∞)
    return the action in ACTIONS(state) whose child has value v

function MAX-VALUE(state, α, β):
    if TERMINAL-TEST(state): return UTILITY(state)
    v = −∞
    for each a in ACTIONS(state):
        v = max(v, MIN-VALUE(RESULT(state, a), α, β))
        if v ≥ β: return v          (prune: MIN above will not allow this)
        α = max(α, v)
    return v

function MIN-VALUE(state, α, β):
    if TERMINAL-TEST(state): return UTILITY(state)
    v = +∞
    for each a in ACTIONS(state):
        v = min(v, MAX-VALUE(RESULT(state, a), α, β))
        if v ≤ α: return v          (prune: MAX above will not allow this)
        β = min(β, v)
    return v

The test "v ≥ β" at a MAX node is the same as "α ≥ β" after updating α, so the slide rule and this code agree. Our Python code uses the slide form.

PropertyAlpha beta
Same answer as minimaxYes, always, at the root. Pruning never changes the decision
Complete and optimalSame as minimax: complete for finite trees, optimal against a perfect opponent
Time, best orderO(bm/2)
Time, random orderAbout O(b3m/4) for moderate b
Time, worst orderO(bm), no pruning at all
SpaceO(b m), like depth first minimax. Only the current path and its α, β values are stored
Data structuresThe recursion stack. Each frame holds a state, its list of moves, v, α and β. Real programs add a transposition table (a hash map of positions already searched)

Move ordering decides how much is pruned

Source: the class of 8 February 2026 ("arrangement of nodes also matter") and Knuth and Moore, 1975.

Alpha beta prunes most when each node looks at its best child first. Then α and β get tight early and many later children fail the test at once. If the worst child always comes first, nothing is pruned.

TreeLeavesRead by alpha betaPruned
Slide example, slide order (b = 2, depth 3)853

Both slide trees are already in the best possible order: no order can read fewer leaves. We checked this by running alpha beta on every tree, and it matches the formula below.

Fewest leaves alpha beta can read (Knuth and Moore)Exam favourite
b⌈d/2⌉ + b⌊d/2⌋ − 1
For a uniform tree with branching b and depth d, with perfect ordering. b = 2, d = 3: 4 + 2 − 1 = 5. b = 3, d = 3: 9 + 3 − 1 = 11.
How real programs get a good orderIdea
Iterative deepeningSearch depth 1, 2, 3 and so on. The best move found at depth d − 1 is tried first at depth d
Killer movesA move that caused a prune at the same depth elsewhere is tried early, since it is likely good again
Captures firstIn chess, try captures and threats before quiet moves
Transposition tableStore each searched position with its value and best move, so a position reached by a different move order is not searched twice
Lesson 5 of 9

The maths: how much faster, and how much deeper

Best order costExam favourite
O(bm/2) = O((√b)m)
The effective branching factor drops from b to √b. Chess: √35 ≈ 5.9.
Depth for the same work
bd = (√b)2d
In the time minimax searches depth d, alpha beta with good ordering searches depth 2d.
Random order cost
about O(b3m/4)
Still a big saving: the depth grows by about a third.
Negamax form
max(a, b) = −min(−a, −b)
So one function can serve both players: value = max over children of −value(child), with the window (−β, −α).
Worked example: chess
  1. Say a computer can look at 10⁹ positions per move. With b = 35, minimax reaches depth d where 35d = 10⁹.
  2. d = 9 ⁄ log₁₀ 35 = 9 ⁄ 1.544 ≈ 5.8, so about 5 to 6 plies.
  3. Alpha beta with near perfect ordering: (√35)d = 10⁹ gives d ≈ 11.7.
  4. about twice as deep: roughly 11 plies instead of 5 or 6
Worked example: the best case formula for b = 10, d = 4
  1. b⌈d/2⌉ = 10² = 100.
  2. b⌊d/2⌋ = 10² = 100.
  3. 100 + 100 − 1 = 199 leaves.
  4. 199 instead of 10⁴ = 10,000 leaves, about 50 times fewer
Going deeper: Why the best case is b⌈d/2⌉ + b⌊d/2⌋ − 1

To prove that the root value is v, MAX must show "I can get at least v" and "I cannot get more than v". For the first, MAX needs only one good move at each of its levels, but all of MIN's replies. For the second, MIN needs one good reply at each of its levels, but all of MAX's moves. So one proof tree branches only at MIN levels (about b⌊d/2⌋ leaves), the other only at MAX levels (about b⌈d/2⌉ leaves). They share one leaf, the principal variation, which gives the −1. With perfect ordering alpha beta reads exactly these leaves and no more.

Food for thought from the slides

Source: slide Set 3, slide 10.

Question (slide 10)Answer
Time and space complexityTime O(bm/2) with best ordering, about O(b3m/4) with random ordering, O(bm) in the worst case. Space O(b m)
Data structuresA recursion stack with α and β per frame, a move list per level, and in practice a hash table of positions (transposition table) and a small table of killer moves per depth
Real life usesChess, checkers, Othello and Connect Four engines. Adversarial planning such as security patrols, where the attacker answers the defender. Puzzle game AI in mobile apps
Utility functionsChess: material, king safety, mobility, pawn structure, weighted and added. Connect Four: number of open lines of 2 and 3. Security: value of each target minus the cost of guarding it
Real world scenario: IBM Deep Blue, 1997

Deep Blue beat the world chess champion Garry Kasparov in 1997. It used alpha beta search on special chess chips that could examine about 200 million positions a second, with a hand written evaluation of about 8,000 features. Today Stockfish still uses alpha beta (in the form called principal variation search), now with a neural network evaluation called NNUE. Alpha beta is the reason chess programs became strong long before deep learning.

Remember
In class we noted that when the order of nodes is poor, or when you add your own thresholds to prune more, you may cut away a good move. Plain alpha beta never does that: its pruning is exact. Only extra rules such as forward pruning or chance thresholds can lose the best move.

Bottom line: alpha beta is free speed: same answer as minimax, often twice the depth. Use it for any two player zero sum game with a good evaluation function, and switch to Monte Carlo tree search when b is huge or no good evaluation exists.

Lesson 8 of 9

From intuition to research

One idea, four depths

If one reply already shows that a move is worse than a move you have, you do not need to check the other replies to that move. Alpha beta is minimax with this common sense built in.

α is the best MAX can force so far, β the best MIN can force so far. They pass down, values pass up, and a branch is pruned when α ≥ β. The root value equals minimax. Time is O(bm/2) with best ordering, about O(b3m/4) with random ordering, and O(bm) in the worst case.

Knuth and Moore (1975) proved the minimal tree has b⌈d/2⌉ + b⌊d/2⌋ − 1 leaves and that alpha beta reads exactly it with perfect ordering. Pearl (1982) showed alpha beta is asymptotically optimal among game tree search algorithms with random leaf values. Iterative deepening, killer moves and transposition tables get close to the best order in practice.

Research went on with best first methods such as SSS* and MTD(f), which can read fewer leaves than alpha beta by using null windows and memory. Modern engines combine alpha beta with learned evaluation (NNUE) and learned move ordering, and AlphaZero showed a different path with Monte Carlo tree search and deep networks.

Lesson 9 of 9

Chapter summary

  1. α is the best value MAX can guarantee so far (starts at −∞), β the best value MIN can guarantee so far (starts at +∞).
  2. α and β pass from parent to child. Node values pass from child to parent and update α at MAX nodes and β at MIN nodes.
  3. When α ≥ β, the rest of the branch cannot change the decision, so it is pruned. The root value is always the same as minimax.
  4. Slide example: leaves 2 3 5 9 0 1 7 5. The 9 under E and the whole subtree G are pruned, and A = 3 after reading 5 of 8 leaves.
  5. Good move ordering is key: best case O(bm/2), so the same time searches about twice as deep. Worst case O(bm).
