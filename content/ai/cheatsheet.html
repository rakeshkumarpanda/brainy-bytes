1.1

What AI is and intelligent agents

Open chapter

The four approaches to AI, rational agents, PEAS, environment types, the social machine and the five kinds of agent program.

Key ideas

  • Definition AI builds agents that perceive and act. This course uses the acting rationally view: choose the action with the best expected performance.
  • PEAS Describe any task by Performance measure, Environment, Actuators, Sensors.
  • Environment types Fully or partially observable, deterministic or stochastic, episodic or sequential, static or dynamic, discrete or continuous, single or multi agent.
  • Agent programs Simple reflex, model based, goal based, utility based, learning. Table driven needs ∑ |P|t rows, so it is impossible.
  • Rational, not perfect Rationality depends on the performance measure, prior knowledge, available actions and percepts so far. Bad luck is not irrational.
  • Social machine Needs etiquette, intuitive psychology, common sense, intuitive physics and layers from instinctive to self conscious (Minsky, Society of Mind).

Maps every percept sequence (everything the agent has sensed so far, P*) to an action in the set A. It is the mathematical description of behaviour.

Tips and traps

  • Remember
    In class the four boxes were explained like this: thinking humanly is how we think, thinking rationally is making correct decisions in our head, acting humanly is doing what we think, and acting rationally is working it out so that it leads to a real, measurable result.Lesson: What intelligence and AI mean
  • Common mistake
    A table driven agent stores one action for every possible percept sequence. With 4 percepts and a lifetime of T steps it needs 4 + 4² + ... + 4T rows. For a taxi camera this number is larger than the atoms in the universe. Agent programs exist to produce good behaviour from a small program instead of a huge table.Lesson: Kinds of environment and kinds of agent

    A rational agent is not one that is always right. It is one that chooses the best action given what it knows. Bad luck does not make a choice irrational.Lesson: From intuition to research

Problems as search

Open chapter

States, actions, start and goal, nodes and the frontier, tree against graph search, and the four properties of search.

Key ideas

  • Search problem State space, actions with costs C(x, a, y) ≥ ε > 0, initial state, goal test (a condition). Heuristics are optional.
  • Node STATE, PARENT, ACTION, PATH-COST g(n). Follow PARENT links to rebuild the path.
  • Tree against graph search Tree search can loop on cycles. Graph search keeps an explored set and skips seen states.
  • Four properties Completeness, optimality, time and space, measured with b, d and m. Full tree: (bd+1 − 1) ⁄ (b − 1) nodes.
  • Water jugs 14 of 20 states reachable from (0, 0). (1, 2) unreachable. Getting 2 gallons in the 4 gallon jug takes 6 actions.
  • Formulation Search cannot choose the states for you. A good abstraction can shrink the space enormously (8 queens: 1.8 × 10¹⁴ to 2,057).

Successor functionExam favourite
S(x) = {⟨y, a⟩ : action a takes x to y}
All states one action away from x, each tagged with the action used. Two different actions may reach the same state.

Action cost
C(x, a, y) ≥ ε > 0
The cost of going from x to y with action a. C = ∞ if a does not lead from x to y. Every cost is at least a small positive ε.

Path costExam favourite
g(n) = ∑i C(si, ai, si+1)
Add the costs along the path from the start to node n.

Branching factor and depth
b = most children of any node, d = depth of the shallowest goal, m = largest depth
These three numbers measure every algorithm.

|S| = product of the number of values of each part of the state

2.1

Breadth first and uniform cost search

Open chapter

BFS with a FIFO queue, UCS with a priority queue on g(n), when each is optimal, their cost, and why UCS tests the goal late.

Key ideas

  • BFS FIFO queue. Complete (finite b). Fewest actions, optimal only for equal costs. Time and space O(bd).
  • UCS Priority queue on g(n). Complete and optimal if every cost ≥ ε > 0. O(b1 + ⌊C*⁄ε⌋).
  • Goal test timing BFS: test at generation. UCS: test at expansion (Sibiu: 310 is replaced by 278).
  • Romania BFS 450 via Fagaras. UCS 418 via Rimnicu Vilcea and Pitesti, after taking out 13 cities.
  • Optimality proof Lemma 1: costs taken out never decrease. Lemma 2: cheaper paths come first. Lemma 3: first path to a state is cheapest.
  • Memory b = 10, d = 10 needs about 10 TB. Memory runs out before time.

Formulas

Time of BFSExam favourite
1 + b + b² + ... + bd = O(bd)
With the goal test when a node is generated. If you test only when a node is taken out, the last level is generated too and the time is O(bd+1).
Lesson: Is BFS complete and optimal, and what does it cost
Space of BFSExam favourite
O(bd−1) explored + O(bd) frontier = O(bd)
Every node stays in memory. Memory, not time, is the real limit of BFS.
Lesson: Is BFS complete and optimal, and what does it cost

if every action cost C(x, a, y) ≥ ε > 0

2.2

Depth first, iterative deepening and bidirectional search

Open chapter

DFS, DLS, IDS and bidirectional search, their memory and time, path checking, and the full comparison table.

Key ideas

  • DFS Stack. O(b m) space, O(bm) time. Not complete on infinite or cyclic spaces, not optimal.
  • DLS DFS with depth limit D. Returns solution, failure, or cutoff. Complete only if d ≤ D.
  • IDS DLS with D = 0, 1, 2, .... Complete, optimal for equal costs, O(bd) time, O(b d) space.
  • IDS overhead ∑ (d + 1 − i) bi, about b ⁄ (b − 1) times BFS. b = 10, d = 5: 123,456 against 111,111.
  • Path check Drop a child already on the current path. Removes cycles, keeps O(b m) memory.
  • Bidirectional Search from both ends, O(bd⁄2). Needs reversible actions and one explicit goal.

Formulas

Nodes generated by IDSExam favourite
N(IDS) = (d + 1)·1 + d·b + (d − 1)·b² + ... + 1·bd = ∑i=0d (d + 1 − i) bi
Level i is generated in every iteration from i to d, that is d + 1 − i times.
Lesson: Is iterative deepening wasteful
Overhead of IDS over BFSExam favourite
N(IDS) ⁄ N(BFS) ≈ b ⁄ (b − 1)
For b = 10 that is 1.11, only 11 percent more work. For b = 2 it is 2 times.
Lesson: Is iterative deepening wasteful
Cost of IDS
time O(bd), space O(b d)
Complete when b is finite, and optimal when all actions cost the same.
Lesson: Is iterative deepening wasteful
Cost of bidirectional searchExam favourite
2 · bd⁄2 = O(bd⁄2) instead of O(bd)
For b = 10 and d = 6 that is 2,000 nodes against 1,000,000.

3.1

Greedy best first and A* search

Open chapter

Greedy best first, A*, admissible and consistent heuristics, why A* is optimal, and weighted A*.

Key ideas

  • Greedy best first Order by h. Not optimal (Romania 450, slide 58 trap 110). Can loop in tree search.
  • A* Order by f = g + h. Romania: Arad 366, Sibiu 393, RV 413, Fagaras 415, Pitesti 417, Bucharest 418.
  • Admissible h(n) ≤ h*(n). Makes A* tree search optimal.
  • Consistent h(n1) ≤ C(n1, a, n2) + h(n2). f never decreases, graph search optimal, implies admissible.
  • Optimally efficient A* expands every node with f < C* and none with f > C*. No optimal method with the same h does better.
  • Weighted A* f = g + w h, cost ≤ w C*.

Formulas

Evaluation function of A*Exam favourite
f(n) = g(n) + h(n)
g(n) is the cost of the path of node n, h(n) the estimate from n to a goal. With h = 0 A* is UCS. With g ignored it is greedy.
Lesson: A* search: f(n) = g(n) + h(n)
AdmissibleExam favourite
h(n) ≤ h*(n) for every n
h*(n) is the true cost of an optimal path from n to a goal (∞ if there is none). An admissible h never overestimates: it is optimistic. Also h(goal) = 0.
Lesson: Admissible and consistent heuristics
Consistent (monotone)Exam favourite
h(n1) ≤ C(n1, a, n2) + h(n2) for every action a from n1 to n2
A triangle inequality: the estimate cannot drop by more than the cost of a step. It must hold for every action between n1 and n2.
Lesson: Admissible and consistent heuristics
Consistency implies admissibility
(∀ n1, n2, a) h(n1) ≤ C(n1, a, n2) + h(n2) ⇒ (∀ n) h(n) ≤ h*(n)
Proof by induction on the number of steps to the goal (below). The other direction is false.
Lesson: Admissible and consistent heuristics
What A* expands
surely every n with f(n) < C*, maybe some with f(n) = C*, never any with f(n) > C*
With a consistent h.
Lesson: Is A* optimal, and how fast is it
Optimally efficientExam favourite
no other optimal algorithm using the same h expands fewer nodes (up to ties)
Any algorithm that skips a node with f(n) < C* risks missing a cheaper solution.
Lesson: Is A* optimal, and how fast is it
Effective branching factor
N + 1 = 1 + b* + (b*)² + ... + (b*)d
If A* generates N nodes for a solution at depth d, b* measures how well h focuses the search. b* close to 1 is ideal.
Lesson: Is A* optimal, and how fast is it
Weighted A*
f(n) = g(n) + w · h(n), w ≥ 1
w = 1 is A*. A larger w trusts h more, so the search is faster and greedier.
Lesson: The maths: weighted A* and the cost of a bad h
Bounded suboptimalityExam favourite
cost found ≤ w · C*
With an admissible h, weighted A* is at most w times worse than the optimum. w = 1.5 means at most 50 percent more cost.
Lesson: The maths: weighted A* and the cost of a bad h
Error and work
if |h* − h| ≤ c for a constant c, the work is about bc, not bd
Constant absolute error still costs exponential in c. Relative error ε = (h* − h) ⁄ h* gives about bε d.

Key ideas

Key ideas

Key ideas

  • Rules Modus Ponens: α ⇒ β, α ⊢ β. And-Elimination. Equivalences as rules. Monotonic.

Open chapter

Key ideas
