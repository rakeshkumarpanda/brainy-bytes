Lesson 1 of 9

Why we need more than propositional logic

Source: Russell and Norvig, AIMA 4th ed., section 8.1. The uploaded slides do not cover logic, so this step follows the textbook.

What it is
First order logic (FOL, also called predicate logic) talks about objects, the relations between them and functions that map objects to objects. Quantifiers let one sentence speak about all objects, or about some object.
Why we need it
Propositional logic has no way to say "a room is breezy if and only if a neighbouring room has a pit" once. It needs a separate sentence for every room: 16 rooms, 16 sentences, and a new set for every cave size. Natural language and mathematics talk about objects and their relations all the time.
How it works
Replace fixed symbols like P1,2 by atoms such as Pit([1,2]) built from a predicate and terms, and add ∀ (for all) and ∃ (there exists). One sentence, ∀s Breezy(s) ⇔ ∃r Adjacent(r, s) ∧ Pit(r), now covers every room of every cave.

Remember
In this course and in the animations, names that start with a lower case letter are variables, and names that start with a capital letter are constants, predicates or functions. Prolog uses the opposite convention.

Semantics: models and interpretations

Source: AIMA 4th ed., section 8.2.1 and figure 8.2.

A model of first order logic has a domain, the set of objects, and an interpretation that says which object each constant names, which tuples of objects each predicate holds for, and what each function returns.

The textbook model (figure 8.2)
  1. Domain: Richard the Lionheart, King John, the left legs of each, and a crown. Five objects.
  2. Relations: the brother relation holds for (Richard, John) and (John, Richard). OnHead holds for (crown, John). Person holds for Richard and John. King holds for John only. Crown holds for the crown.
  3. Function: LeftLeg maps Richard to Richard's left leg and John to John's left leg.
  4. Brother(Richard, John) is true here, King(Richard) is false.
  5. an atom is true when the objects named by its terms are in the relation named by its predicate

The animation below uses this model without the two legs, to keep the picture small.

Common mistake
First order logic has infinitely many models: any domain size from 1 upwards, and every interpretation of every symbol. So entailment cannot be checked by listing models, as we did with truth tables.

Quantifiers and their traps

Source: AIMA 4th ed., section 8.2.6.

SentenceRead asTrue when
∀x King(x) ⇒ Person(x)all kings are personsfor every object, if it is a king then it is a person
∃x Crown(x) ∧ OnHead(x, John)some crown is on John's headat least one object is a crown and on John's head
∀x ∃y Loves(x, y)everybody loves somebodyfor each x there is a y (maybe different for each x)
∃y ∀x Loves(x, y)there is someone whom everybody lovesone y works for all x
Rule of thumbWhy
∀ goes with ⇒∀x King(x) ∧ Person(x) says everything is a king and a person, which is far too strong
∃ goes with ∧∃x Crown(x) ⇒ OnHead(x, John) is true as soon as one object is not a crown, so it says almost nothing
Order matters for mixed quantifiers∀x ∃y and ∃y ∀x mean different things
The same kind can be swapped∀x ∀y ≡ ∀y ∀x, ∃x ∃y ≡ ∃y ∃x
De Morgan for quantifiersExam favourite
∀x ¬P ≡ ¬∃x P, ¬∀x P ≡ ∃x ¬P, ∀x P ≡ ¬∃x ¬P, ∃x P ≡ ¬∀x ¬P
"Nobody likes parsnips" = "everybody dislikes parsnips".
∀ as a big AND, ∃ as a big OR
∀x P(x) ≡ P(o1) ∧ P(o2) ∧ ..., ∃x P(x) ≡ P(o1) ∨ P(o2) ∨ ...
Over a finite domain with objects o1, o2, ...

Equality: t1 = t2 is true when both terms name the same object. "Richard has at least two brothers" is ∃x, y Brother(x, Richard) ∧ Brother(y, Richard) ∧ ¬(x = y). Without ¬(x = y), x and y could be the same brother.

Going deeper: Database semantics

Databases and Prolog assume three extra things: unique names (different constants name different objects), the closed world assumption (an atom not known to be true is false), and domain closure (there are no objects other than those named). Under these rules "Richard has two brothers, John and Geoffrey" is simply Brother(John, Richard) ∧ Brother(Geoffrey, Richard). In full first order logic you must add ¬(John = Geoffrey) and say that no one else is a brother.

The knowledge engineering process (AIMA 8.4)
  1. Identify the questions the KB must answer.
  2. Assemble the relevant knowledge, often by talking to experts.
  3. Decide on a vocabulary of predicates, functions and constants (an ontology).
  4. Encode general knowledge about the domain as axioms.
  5. Encode the specific problem instance as facts.
  6. Pose queries to an inference procedure and get answers.
  7. debug the KB: a wrong answer means a missing or wrong axiom

The maths: counting interpretations

Interpretations over a fixed domain of d objectsExam favourite
dc × (2d)u × (2d²)b
c constants (each names one of d objects), u unary predicates (each is any subset of the d objects), b binary predicates (any subset of the d² pairs). Functions add more.
A k-ary relation
2dk possible extensions
There are dk tuples, each in or out.
Grounding ∀
∀x P(x) becomes d ground sentences
Over a finite domain, FOL can be turned into propositional logic. Functions make the set of ground terms infinite.
Worked example: 2 constants, 1 binary predicate, d = 2 objects
  1. Constants: 2² = 4 ways to map 2 constants to 2 objects.
  2. Binary predicate: d² = 4 pairs, so 2⁴ = 16 possible relations.
  3. 4 × 16 = 64.
  4. 64 interpretations for d = 2, and more for every larger d
Worked example: ∀x ∃y Loves(x, y) over d = 3 people
  1. Grounded, it is (L(a, a) ∨ L(a, b) ∨ L(a, c)) ∧ (L(b, a) ∨ ...) ∧ (L(c, a) ∨ ...).
  2. That is 3 clauses of 3 literals each.
  3. Each person needs at least one person they love.
  4. 3 × 3 = 9 ground atoms involved

Bottom line: first order logic is the usual choice: rich enough for most knowledge, with sound and complete proof methods (chapter 7.4), at the price that a proof search for a false query may not stop.

Real world scenario: SQL is first order logic

A relational database query is a first order formula. SELECT name FROM person p WHERE EXISTS (SELECT * FROM parent q WHERE q.child = p.name) asks for all x with ∃y Parent(y, x). Codd built the relational model on this link in 1970, and database query languages still follow it.

Lesson 8 of 9

From intuition to research

One idea, four depths

Instead of a separate yes or no fact for every room, say things about all rooms at once: "every room next to a pit is breezy". First order logic gives you words for things (objects), how they relate, and "all" and "some".

Terms name objects, atoms are predicates on terms, sentences combine atoms with connectives, ∀ and ∃. A model has a domain and an interpretation. Use ∀ with ⇒ and ∃ with ∧. Quantifier order matters. Equality and database semantics change what a list of facts means.

Gödel's completeness theorem (1929): every entailed sentence has a proof, so entailment is semidecidable. Church and Turing (1936): entailment is not decidable. Löwenheim and Skolem: a set of sentences with an infinite model has models of every infinite size, so FOL cannot pin down the natural numbers exactly.

Research uses decidable fragments of FOL (the two variable fragment, guarded fragments, description logics), SMT solvers that combine SAT with theories such as arithmetic, and the encoding of commonsense knowledge (Cyc, knowledge graphs) in first order style.

Lesson 9 of 9

Chapter summary

  1. First order logic talks about objects, relations and functions, and quantifies over objects with ∀ and ∃.
  2. Terms (constants, variables, functions of terms) name objects. Atoms apply predicates to terms. Sentences combine atoms.
  3. A model has a domain and an interpretation. There are infinitely many models, so we cannot list them.
  4. Use ∀ with ⇒ and ∃ with ∧. ∀x ∃y differs from ∃y ∀x. ¬∀x P ≡ ∃x ¬P.
  5. Knowledge engineering: questions, knowledge, vocabulary, general axioms, instance facts, queries, debugging.
