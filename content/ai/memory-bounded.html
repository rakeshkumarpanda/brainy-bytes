Why A* runs out of memory

Source: slide Set 2, slides 71 to 74, and the classes of 31 January and 1 February 2026.

A* keeps every node it generates, in the frontier or the explored set. Its time is often fine, but its memory grows exponentially, and on hard problems it runs out of memory long before it runs out of time. Memory bounded methods keep the optimality of A* while using far less memory, at the price of repeating some work.

Lesson 2 of 8

IDA*: iterative deepening A*

What it is
IDA* runs a depth first search that stops whenever f = g + h is above a limit. If no goal is found, it raises the limit and starts again.
Why we need it
Iterative deepening saves memory, but on its own it ignores costs and h. Using f as the cutoff keeps the low memory and makes the search follow the A* contours, so it is optimal with an admissible h.
How it works
Start with limit = f(start) = h(start). In each iteration, remember the smallest f that went over the limit. That value is the next limit. Stop when a goal is taken out within the limit.
IDA* from Arad to Bucharest
  1. Limit 366 = h(Arad). Every child of Arad is over: Sibiu 393, Timisoara 447, Zerind 449. Next limit: 393.
  2. Limit 393. Sibiu is expanded. Its children are over: Rimnicu Vilcea 413, Fagaras 415, Oradea 671. Next limit: 413.
  3. Limit 413. Rimnicu Vilcea is expanded. Pitesti 417 and Craiova 526 are over. Fagaras 415 is over too. Next limit: 415.
  4. Limit 415. Fagaras is expanded, Bucharest via Fagaras is 450, over. Pitesti 417 is still over. Next limit: 417.
  5. Limit 417. Pitesti is expanded, Bucharest via Pitesti is 418, over. Next limit: 418.
  6. limit 418: Bucharest is reached with f = 418, the optimal cost, after 6 iterations
Iterations of IDA*Exam favourite
one per distinct f value up to C*
With integer costs and a good h that is few. With many different real valued costs, each iteration may add only one new node, and IDA* can take about N² time for N nodes A* would expand.
Lesson 3 of 8

RBFS: recursive best first search

What it is
RBFS is a recursive search that acts like best first search but stores only the current path and, for each node on it, the f value of its best alternative (the f-limit).
Why we need it
It keeps the best first order of A*, so it wastes less work than IDA*, while still using linear memory.
How it works
At a node, sort its children by f. Go into the best child with f-limit = min(the limit from above, f of the second best child). If the best child's f goes over the limit, unwind (backtrack) and replace the f of that node with the best f found below it (the backed up value). Then the alternative may become the best, and the search switches there.
RBFS on Romania, as in the slide figure
  1. At Arad. Children: Sibiu 393, Timisoara 447, Zerind 449. Go to Sibiu with limit 447 (the best alternative, Timisoara).
  2. At Sibiu. Children: Rimnicu Vilcea 413, Fagaras 415, Oradea 671, Arad 646. Go to Rimnicu Vilcea with limit min(447, 415) = 415.
  3. At Rimnicu Vilcea. Best child Pitesti has f = 417 > 415. Unwind, and Rimnicu Vilcea gets the backed up value 417.
  4. At Sibiu again. Now Fagaras 415 is best. Go there with limit min(447, 417) = 417.
  5. At Fagaras. Best child Bucharest has f = 450 > 417. Unwind, and Fagaras gets 450.
  6. At Sibiu. Rimnicu Vilcea (417) is best again. Go there with limit min(447, 450) = 447, then Pitesti (417), then Bucharest (418).
  7. the path Arad, Sibiu, Rimnicu Vilcea, Pitesti, Bucharest with cost 418
RBFS (AIMA style)
function RBFS(node, f_limit):
    if GOAL-TEST(node): return node, f(node)
    children = expand(node)
    if no children: return failure, ∞
    for each child s: s.f = max(g(s) + h(s), node.f)
    loop:
        best = child with the lowest f
        if best.f > f_limit: return failure, best.f
        alt = second lowest f among the children
        result, best.f = RBFS(best, min(f_limit, alt))
        if result is not failure: return result, best.f
Lesson 4 of 8

SMA*: use all the memory you have

What it is
SMA* (simplified memory bounded A*) behaves like A* until memory is full. Then, to add a new node, it drops the worst leaf, the one with the highest f (and the oldest among ties).
Why we need it
IDA* and RBFS use too little memory: they forget almost everything and must regenerate it. SMA* remembers as much as memory allows, so it repeats much less work.
How it works
When a leaf is dropped, its f value is backed up into its parent. The parent then knows how good the best path through the forgotten subtree was, and regenerates it only if every other path looks worse.
PropertySMA*
CompleteYes, if the depth of the shallowest goal is less than the memory size (the path must fit)
OptimalYes, if an optimal solution fits in memory. Otherwise it returns the best solution that fits.
Weak pointWhen memory is very tight, it can thrash: switch back and forth between paths and regenerate them many times
Remember
All three methods are a trade between time and memory. In practice, SMA* style methods are the most robust when memory is limited but not tiny.

The maths: memory and repeated work

MemoryExam favourite
A*: O(bd) IDA*, RBFS: O(b d) SMA*: M, the memory you give it
b branching factor, d solution depth.
IDA* number of iterations
k = number of distinct f values in (h(start), C*]
Romania: 366, 393, 413, 415, 417, 418 gives 6 iterations.
Worst case of IDA*
1 + 2 + ... + N = N(N + 1) ⁄ 2 = O(N²)
If each iteration adds just one new node to the N nodes A* expands.
Worked example: memory of A* against IDA*
  1. b = 3, d = 20, 100 bytes a node.
  2. A* may store about 3²⁰ ≈ 3.5 × 10⁹ nodes, 350 GB.
  3. IDA* stores about b × d = 60 nodes, 6 KB.
  4. the price: re expanding the top of the tree once per iteration
Worked example: IDA* worst case
  1. A* would expand N = 1,000 nodes, all with different f values.
  2. IDA* then needs 1,000 iterations, the k-th one expanding k nodes.
  3. 1,000 × 1,001 ⁄ 2 = 500,500 node expansions, about 500 times more than A*

Bottom line: IDA* is simplest and works well with few distinct f values (unit costs, puzzles). RBFS wastes less when f values vary. SMA* is best when you have a fixed amount of memory to fill.

Real world scenario: solving the 15 puzzle

The 15 puzzle has about 10¹³ states. A* with Manhattan distance runs out of memory on hard instances, but IDA* with Manhattan distance (Korf, 1985) solves random instances optimally using a few kilobytes, because all costs are 1 and f takes few distinct values. Adding pattern databases makes it fast enough to solve the 24 puzzle too.

Lesson 7 of 8

From intuition to research

One idea, four depths

If your notebook is small, you cannot write down every road you have looked at. So you remember only the road you are on and the best other choice, and you come back to it when your road gets too long.

IDA*: DFS with an f cutoff that grows to the smallest f over the last limit. RBFS: recursion with an f-limit equal to the best alternative, and backed up values when it unwinds. SMA*: A* that drops the worst leaf. All optimal with an admissible h. IDA* and RBFS use O(b d) memory.

IDA* repeats work when f values are many and different, up to O(N²). RBFS also repeats work when it switches between paths. Both cannot detect repeated states without extra memory, so on graphs with many cycles they may explore exponentially many paths to the same state. Transposition tables fix this with a fixed memory budget.

Modern variants include IDA* with transposition tables and pattern databases, frontier search that drops the closed list, breadth first heuristic search, and external memory A* that keeps the frontier on disk, which solved problems with more than 10¹² states.

Lesson 8 of 8

Chapter summary

  1. A* runs out of memory before time, because it stores every node.
  2. IDA*: DFS with an f cutoff. The next cutoff is the smallest f over the old one. Romania: 366, 393, 413, 415, 417, 418. Linear memory, optimal with admissible h.
  3. RBFS: go into the best child with f-limit = min(limit, best alternative). When the best f goes over the limit, unwind and back up that f. Linear memory, optimal.
  4. SMA*: A* until memory is full, then drop the worst leaf and back up its f to the parent. Optimal if the solution fits.
  5. The trade: less memory means more repeated work. IDA* can take O(N²) when every f is different.
