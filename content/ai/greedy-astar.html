Greedy best first and A* search

Use a heuristic h(n), a guess of the cost still to go, to point the search at the goal. Greedy best first trusts h alone and can be fooled. A* adds the cost already paid and finds the cheapest path when h never overestimates.

Lesson 1 of 9

Heuristics: knowing roughly where the goal is

Source: slide Set 2, slides 53 to 57, and the class of 31 January 2026.

Uniform cost search expands the cheapest path so far, but it never asks how far that path still is from the goal. It spreads out in every direction. Often we know something about the "merit" of a node, for example the straight line distance from a city to Bucharest. A search that uses such knowledge is called informed or heuristic search.

What it is
A heuristic function h(n) is an estimate of the cost of the cheapest path from the state of node n to a goal. It must be non negative and h(n) = 0 at every goal.
Why we need it
It lets the search look ahead. If h(n1) < h(n2), n1 is probably closer to the goal, so the search can try it first and skip much useless work.
How it works
Design h from knowledge of the problem, often by solving a simpler version of it (chapter 3.2). Then use h to order the frontier: alone (greedy best first) or added to g (A*).

A heuristic is a practical rule from experience that is "good enough" as an approximation, even if it is not perfect. The straight line distance to Bucharest, hSLD, is a classic example: Arad 366, Sibiu 253, Fagaras 176, Rimnicu Vilcea 193, Pitesti 100, Bucharest 0.

In the exam
Food for thought IV asks for necessary and sufficient conditions. For optimal A*: admissibility is sufficient for tree search, consistency is sufficient for graph search. Neither is necessary: a slightly overestimating h can still return the optimal path by luck, but then nothing is guaranteed.
Lesson 2 of 9

Greedy best first search

Source: slide Set 2, slides 58 and 59.

What it is
Greedy best first search always expands the node with the lowest h(n), the one that looks closest to the goal.
Why we need it
It often reaches a goal very quickly, expanding few nodes, because it heads straight for the goal.
How it works
Order the frontier by h(n) only. Ignore g(n), the cost already paid.

On Romania, greedy goes Arad → Sibiu (253 is lower than Zerind 374 and Timisoara 329) → Fagaras (176) → Bucharest. It expands only nodes on its path, so the search cost is minimal, but the route costs 450, not 418.

The trap of slide 58
  1. From S there are two ways: S → n1 → n2 → Goal (10 + 10 + 10 = 30) and S → n3 → Goal (100 + 10 = 110).
  2. h(n1) = 20 and h(n3) = 10. Greedy takes n3 because it looks closer.
  3. From n3 the goal is one step away, so greedy returns S, n3, Goal with cost 110.
  4. greedy pays 110 while the best path costs 30, because it ignores the 100 it paid to reach n3

From Iasi to Fagaras greedy first goes to Neamt (closest by straight line), which is a dead end. In tree search Neamt puts Iasi back on the frontier, and the search loops for ever between them.

PropertyGreedy best first
CompleteNo in tree search (Iasi, Neamt loop). Yes in graph search on a finite space.
OptimalNo (450 against 418, 110 against 30)
Time and spaceO(bm) in the worst case, but often far less with a good h
Lesson 3 of 9

A* search: f(n) = g(n) + h(n)

Source: slide Set 2, slides 60 to 66.

What it is
A* expands the node with the lowest f(n) = g(n) + h(n): the cost paid so far plus the estimated cost still to go.
Why we need it
Greedy ignores the past (g) and UCS ignores the future (h). A* adds them, so f(n) estimates the cost of the cheapest solution through n. With a good h it is both optimal and much faster than UCS.
How it works
Keep the frontier as a priority queue on f. Take out the lowest f, test for the goal, and add the children with their f values. Replace a frontier entry if a cheaper g to the same state appears.
Evaluation function of A*Exam favourite
f(n) = g(n) + h(n)
g(n) is the cost of the path of node n, h(n) the estimate from n to a goal. With h = 0 A* is UCS. With g ignored it is greedy.
A* from Arad to Bucharest, as in the slide figures
  1. Expand Arad (f = 0 + 366 = 366). Add Sibiu 140 + 253 = 393, Timisoara 118 + 329 = 447, Zerind 75 + 374 = 449.
  2. Expand Sibiu (393). Add Rimnicu Vilcea 220 + 193 = 413, Fagaras 239 + 176 = 415, Oradea 291 + 380 = 671, and Arad again 280 + 366 = 646.
  3. Expand Rimnicu Vilcea (413). Add Pitesti 317 + 100 = 417, Craiova 366 + 160 = 526, Sibiu 300 + 253 = 553.
  4. Expand Fagaras (415). Add Bucharest 450 + 0 = 450 and Sibiu 338 + 253 = 591. A goal is on the frontier, but not with the lowest f.
  5. Expand Pitesti (417). Add Bucharest 418 + 0 = 418, Rimnicu Vilcea 607 and Craiova 615.
  6. take out Bucharest with f = 418: Arad, Sibiu, Rimnicu Vilcea, Pitesti, Bucharest, the optimal route

A* takes out 6 cities. Uniform cost search takes out 13 for the same answer (chapter 2.1).

Admissible and consistent heuristics

Source: slide Set 2, slides 67 to 69.

AdmissibleExam favourite
h(n) ≤ h*(n) for every n
h*(n) is the true cost of an optimal path from n to a goal (∞ if there is none). An admissible h never overestimates: it is optimistic. Also h(goal) = 0.
Consistent (monotone)Exam favourite
h(n1) ≤ C(n1, a, n2) + h(n2) for every action a from n1 to n2
A triangle inequality: the estimate cannot drop by more than the cost of a step. It must hold for every action between n1 and n2.
Consistency implies admissibility
(∀ n1, n2, a) h(n1) ≤ C(n1, a, n2) + h(n2) ⇒ (∀ n) h(n) ≤ h*(n)
Proof by induction on the number of steps to the goal (below). The other direction is false.
Proof that consistent implies admissible
  1. Take an optimal path n = n0, n1, ..., nk = goal. Induction on k.
  2. k = 0: n is a goal, h(n) = 0 = h*(n).
  3. Step: by consistency h(n0) ≤ C(n0, n1) + h(n1). By induction h(n1) ≤ h*(n1).
  4. h(n0) ≤ C(n0, n1) + h*(n1) = h*(n0)
Why consistency makes f never decrease along a path
  1. Let n2 be a child of n1 by action a. Then g(n2) = g(n1) + C(n1, a, n2).
  2. f(n2) = g(n1) + C(n1, a, n2) + h(n2).
  3. By consistency C(n1, a, n2) + h(n2) ≥ h(n1).
  4. f(n2) ≥ g(n1) + h(n1) = f(n1)

Because f never decreases, A* with a consistent h expands nodes in rings of growing f, called contours. The first time it takes out a state, it has found the cheapest path to that state, just like UCS (Lemma 3 of chapter 2.1). So graph search never needs to reopen a closed state.

Lesson 5 of 9

Is A* optimal, and how fast is it

A* tree search with an admissible h is optimal
  1. Let the optimal cost be C*. Suppose a suboptimal goal G2 with g(G2) > C* is on the frontier.
  2. Some node n on an optimal path is also on the frontier (the start is, and its optimal child replaces it, and so on).
  3. Admissibility gives f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C*.
  4. And f(G2) = g(G2) + 0 > C*. So f(n) < f(G2), and n is expanded before G2.
  5. every node on the optimal path is expanded before G2, so the first goal taken out costs C*

In graph search, an admissible but inconsistent h can fail if closed states are never reopened. In the example below the search reaches B first by the expensive road (g = 4), closes it, and later ignores the cheaper road through A (g = 2).

What A* expands
surely every n with f(n) < C*, maybe some with f(n) = C*, never any with f(n) > C*
With a consistent h.
Optimally efficientExam favourite
no other optimal algorithm using the same h expands fewer nodes (up to ties)
Any algorithm that skips a node with f(n) < C* risks missing a cheaper solution.
Effective branching factor
N + 1 = 1 + b* + (b*)² + ... + (b*)d
If A* generates N nodes for a solution at depth d, b* measures how well h focuses the search. b* close to 1 is ideal.
Common mistake
The time of A* is still exponential in general, and the memory is its real weak point: it keeps every generated node. That is why chapter 3.3 builds IDA*, RBFS and SMA*.

The maths: weighted A* and the cost of a bad h

Weighted A*
f(n) = g(n) + w · h(n), w ≥ 1
w = 1 is A*. A larger w trusts h more, so the search is faster and greedier.
Bounded suboptimalityExam favourite
cost found ≤ w · C*
With an admissible h, weighted A* is at most w times worse than the optimum. w = 1.5 means at most 50 percent more cost.
Error and work
if |h* − h| ≤ c for a constant c, the work is about bc, not bd
Constant absolute error still costs exponential in c. Relative error ε = (h* − h) ⁄ h* gives about bε d.
Worked example: weighted A* bound
  1. An optimal route costs C* = 418. We run weighted A* with w = 1.2 and an admissible h.
  2. The guarantee is cost ≤ 1.2 × 418.
  3. cost ≤ 501.6, so the 450 route via Fagaras is allowed, and is in fact what a greedy enough search returns
Worked example: effective branching factor
  1. A* finds a solution at depth d = 2 after generating N = 6 nodes.
  2. Solve 6 + 1 = 1 + b* + (b*)², so (b*)² + b* − 6 = 0.
  3. (b* + 3)(b* − 2) = 0.
  4. b* = 2

Bottom line: A* is the right default when you have an admissible heuristic. Greedy is useful only when any solution will do and speed matters most.

Real world scenario: route planning in a game

Units in a strategy game move across a grid with walls and forests. Game engines use A* with the Manhattan or octile distance as h, because it is admissible on grids and gives the shortest path. When thousands of units move at once, they switch to weighted A* (w around 1.5) or precomputed paths, trading a little path quality for a large saving in time.

Lesson 8 of 9

From intuition to research

One idea, four depths

A* is like a hiker who adds the distance walked so far to a guess of the distance still to go, and always continues from the spot with the smallest total. If the guess is never too big, the hiker finds the shortest way.

f = g + h. Admissible h ≤ h* makes A* tree search optimal. Consistent h(n1) ≤ C + h(n2) makes f non decreasing, so graph search is optimal without reopening. Consistent implies admissible. A* is optimally efficient but needs exponential memory.

A* with a consistent h is UCS on reduced costs C − h(x) + h(y) ≥ 0. Weighted A* gives cost ≤ w C*. With inconsistent h, graph search must reopen closed states (or use pathmax), and the number of re expansions can be exponential in the worst case (Martelli 1977).

Research directions include anytime A* variants (ARA*, which lowers w over time), real time search (LRTA*) for robots that must move before planning ends, multi agent path finding (CBS), and learned heuristics from neural networks that keep or relax admissibility guarantees.

Going deeper: pathmax

If an admissible h is inconsistent, you can make f non decreasing by using f(n2) = max(f(n1), g(n2) + h(n2)) for a child n2 of n1. This keeps admissibility, because the true cost through n2 is at least f(n1), which is a lower bound on any solution through n1.

Lesson 9 of 9

Chapter summary

  1. A heuristic h(n) estimates the cost from n to a goal. It is non negative and 0 at goals.
  2. Greedy best first orders by h only. Fast but not optimal (450 on Romania, 110 on the slide 58 trap) and can loop in tree search.
  3. A* orders by f = g + h. On Romania it takes out 6 cities and finds 418.
  4. Admissible: h ≤ h*. Enough for optimal tree search. Consistent: h(n1) ≤ C(n1, a, n2) + h(n2). Enough for optimal graph search, and it implies admissible.
  5. With consistent h, f never decreases along a path, and A* is optimally efficient. Its weak point is memory.
  6. Weighted A* with f = g + w h finds a cost at most w C*.
