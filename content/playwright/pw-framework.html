package com.brainy.shop.config;

import java.io.IOException;
import java.io.InputStream;
import java.util.Properties;

// Settings that change between machines (a laptop, CI, staging) live here and nowhere else.
// Order: -DbaseUrl=..., then the BASE_URL environment variable, then config.properties.
public final class Config {
  private static final Properties FILE = new Properties();

  static {
    try (InputStream in = Config.class.getResourceAsStream("/config.properties")) {
      if (in != null) FILE.load(in);
    } catch (IOException e) {
      throw new IllegalStateException("Cannot read config.properties", e);
    }
  }

  private Config() {}

  public static String get(String key, String envName) {
    String value = System.getProperty(key);
    if (value == null) value = System.getenv(envName);
    if (value == null) value = FILE.getProperty(key);
    return value;
  }

  public static String baseUrl() {
    return get("baseUrl", "BASE_URL");
  }

  public static boolean headless() {
    return Boolean.parseBoolean(get("headless", "HEADLESS"));
  }
}

What happens

The runner found all seven tests in the folders it was told to look in, before running any of them. That is the first thing to check in a new framework. Every setting that changes between a laptop and CI, here the shop address, comes from one place: an environment variable if it is set, otherwise a default. The Java project compiled, and its test classes sit in one package per feature.

🏢
Commit a .env.example with the names of the settings and no values. A new team member copies it to .env and fills it in. The real .env is listed in .gitignore.

📄 src/main/java/com/brainy/shop/api/ShopApi.java
package com.brainy.shop.api;

import com.brainy.shop.data.User;
import com.microsoft.playwright.APIRequestContext;
import com.microsoft.playwright.APIResponse;
import com.microsoft.playwright.options.RequestOptions;

import java.util.Map;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

// Fast set up through the API, so UI tests only click what they are testing
public class ShopApi {
  private final APIRequestContext request;

  public ShopApi(APIRequestContext request) {
    this.request = request;
  }

  public String signIn(User user) {
    APIResponse response = request.post("/api/login",
        RequestOptions.create().setData(Map.of("email", user.email(), "password", user.password())));
    if (!response.ok()) throw new IllegalStateException("Sign in failed for " + user.email() + ": " + response.status());
    Matcher token = Pattern.compile("\"token\":\"(\\w+)\"").matcher(response.text());
    if (!token.find()) throw new IllegalStateException("No token in " + response.text());
    return token.group(1);
  }

  public void addToCart(String token, int productId, int qty) {
    APIResponse response = request.post("/api/cart", RequestOptions.create()
        .setData(Map.of("productId", productId, "qty", qty))
        .setHeader("Authorization", "Bearer " + token));
    if (!response.ok()) throw new IllegalStateException("Could not add product " + productId + ": " + response.status());
  }
}

📄 src/test/java/com/brainy/shop/base/BaseTest.java
package com.brainy.shop.base;

import com.brainy.shop.api.ShopApi;
import com.brainy.shop.config.Config;
import com.brainy.shop.data.User;
import com.brainy.shop.data.Users;
import com.brainy.shop.pages.CartPage;
import com.brainy.shop.pages.LoginPage;
import com.brainy.shop.pages.ProductsPage;
import com.microsoft.playwright.APIRequest;
import com.microsoft.playwright.APIRequestContext;
import com.microsoft.playwright.Browser;
import com.microsoft.playwright.BrowserContext;
import com.microsoft.playwright.BrowserType;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.Playwright;
import com.microsoft.playwright.Tracing;
import org.testng.ITestResult;
import org.testng.annotations.AfterClass;
import org.testng.annotations.AfterMethod;
import org.testng.annotations.BeforeClass;
import org.testng.annotations.BeforeMethod;

import java.nio.file.Paths;

// Every test class extends BaseTest. TestNG runs classes in parallel, and each class has its own
// Playwright and browser, so nothing is shared between threads.
public abstract class BaseTest {
  private Playwright playwright;
  private Browser browser;
  private APIRequestContext request;
  private BrowserContext context;
  protected Page page;
  protected ShopApi api;
  protected LoginPage loginPage;
  protected ProductsPage productsPage;
  protected CartPage cartPage;

  @BeforeClass(alwaysRun = true)        // alwaysRun: also when a group such as smoke is chosen
  public void launchBrowser() {
    playwright = Playwright.create();
    browser = playwright.chromium().launch(new BrowserType.LaunchOptions().setHeadless(Config.headless()));
    request = playwright.request().newContext(new APIRequest.NewContextOptions().setBaseURL(Config.baseUrl()));
    api = new ShopApi(request);
  }

  @BeforeMethod(alwaysRun = true)
  public void openPage() {
    context = browser.newContext(new Browser.NewContextOptions().setBaseURL(Config.baseUrl()));
    context.tracing().start(new Tracing.StartOptions().setScreenshots(true).setSnapshots(true));
    page = context.newPage();
    loginPage = new LoginPage(page);
    productsPage = new ProductsPage(page);
    cartPage = new CartPage(page);
  }

  // A fresh session made through the API: fast, and no two tests share a cart
  protected String signInThroughApi(User user) {
    String token = api.signIn(user);
    context.addInitScript("window.localStorage.setItem('token', '" + token + "')");
    return token;
  }

  protected String signInThroughApi() {
    return signInThroughApi(Users.ASHA);
  }

  // Report listeners call this when a test fails. TestNG calls them before closePage(), so the page is still open.
  public byte[] screenshot() {
    return page.screenshot();
  }

  @AfterMethod(alwaysRun = true)
  public void closePage(ITestResult result) {
    if (result.isSuccess()) {
      context.tracing().stop();
    } else {                                      // keep a trace only for a failed test
      String name = getClass().getSimpleName() + "." + result.getMethod().getMethodName();
      context.tracing().stop(new Tracing.StopOptions().setPath(Paths.get("traces", name + ".zip")));
    }
    context.close();
  }

  @AfterClass(alwaysRun = true)
  public void closeBrowser() {
    request.dispose();
    playwright.close();
  }
}

class ShopApi:
    def __init__(self, request: APIRequestContext):
        self.request = request

    def sign_in(self, user: User) -> str:
        response = self.request.post("/api/login", data={"email": user.email, "password": user.password})
        assert response.ok, f"Sign in failed for {user.email}: {response.status}"
        return response.json()["token"]

    def add_to_cart(self, token: str, product_id: int, qty: int = 1):
        response = self.request.post("/api/cart", data={"productId": product_id, "qty": qty},
                                     headers={"Authorization": f"Bearer {token}"})
        assert response.ok, f"Could not add product {product_id}: {response.status}"

export class ShopApi {
  constructor(request) {
    this.request = request;
  }

  async signIn(user) {
    const response = await this.request.post('/api/login', { data: { email: user.email, password: user.password } });
    if (!response.ok()) throw new Error(`Sign in failed for ${user.email}: ${response.status()}`);
    return (await response.json()).token;
  }

  async addToCart(token, productId, qty = 1) {
    const response = await this.request.post('/api/cart', {
      data: { productId, qty },
      headers: { Authorization: `Bearer ${token}` },
    });
    if (!response.ok()) throw new Error(`Could not add product ${productId}: ${response.status()}`);
  }
}

What happens

All seven tests passed in every language. Each layer has one job. Data holds the users and products. The API helper signs in and fills a cart in a fraction of a second. Components and page objects hold every locator. The fixtures, or BaseTest in Java, give each test fresh page objects and its own session, so no two tests share a cart, even when they run at the same time.

💡
The session fixture signs in through the API and puts the token in the page before it loads. Each test gets its own session, so its cart is its own, and parallel tests cannot disturb each other. This is the isolation rule from the parallel runs chapter, built into the framework.
⚠️
Java has no fixtures like Playwright Test or pytest. BaseTest plays that part: TestNG runs @BeforeClass, @BeforeMethod and @AfterMethod around every test, and with parallel="classes" each class keeps its own Playwright on its own thread. Playwright objects are not safe to share between threads.

What happens

Only the three smoke tests ran: the two sign in checks and the checkout. Tests live in one folder per feature and contain no locators at all, only steps and checks. Playwright Test filters by tag with --grep, pytest by marker with -m, and TestNG by group in its own suite file. In TestNG the set up methods need alwaysRun = true, or they are skipped when a group is chosen.

📈How the framework grows

A framework starts small and grows with the product. These are the additions teams usually make next, and the chapter that covers each.

When you needAddCovered in
several environmentsone .env per environment, or CI variables per jobthis chapter, step 1
many signed in rolesa setup step that saves storage state per roleAPI testing
a run on every pull requesta CI workflow with shards and a merged reportCI/CD
reports for managers and testersAllure, pytest-html or ExtentReports next to the built-in reportsReporting labs
visual and accessibility checkstoHaveScreenshot, aria snapshots and axe in their own folderVisual, accessibility and time
lots of varied test datasmall factory functions that build users and orders with unique namesParallel runs

Grow the framework when the tests ask for it. A layer nobody needs yet is code to maintain. The best frameworks are the ones where a new test takes ten lines and needs no new helper.
