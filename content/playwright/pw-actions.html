Part 1

⏳Auto-waiting: no more sleeps

🧒 Beginner friendly

Pages are slow in many small ways. A button is disabled until a price loads, a cover hides the page while it gets ready, a panel slides in. Before every action, Playwright checks that the element is ready and waits until it is. You do not write any waiting code for this.

Click a button that is covered, disabled and moving · ✅ mvn test ran
📄 src/test/java/com/brainy/AutoWaitTest.java
package com.brainy;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class AutoWaitTest {
  @Test
  void actionsWaitUntilTheElementIsReady(Page page) {
    page.navigate("/widgets");
    // A loading cover hides the page for 0.8 s, and Pay now is disabled for 1 s.
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Pay now")).click();
    assertThat(page.getByText("Payment done")).isVisible();

    // The offer appears 1.2 s after the click. The check waits for it.
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Load offers")).click();
    assertThat(page.getByTestId("offer")).hasText("Buy 2 mugs, get 1 free");

    // This button slides in when the page opens. click waits until it stops moving.
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Catch me")).click();
    assertThat(page.getByText("Caught it")).isVisible();
  }
}

What happens

The test has no sleep anywhere. Each click waited exactly as long as the page needed: until the cover was gone, the button was enabled, and the moving button stood still. A fixed wait would either be too short and fail, or too long and waste time on every run.

The checks depend on the action. This table comes from the Playwright documentation. Click, check and fill also make sure the element is not inert, which means not blocked by an open modal dialog.

ActionVisibleStableReceives eventsEnabledEditable

🌍
Think of a lift. You press the button and wait until the doors open. You do not stand there counting to ten first. Playwright waits for the doors, not for the clock.
Part 2

🧾When waiting is not enough

Sometimes the element never becomes ready, because of a real bug or a wrong locator. Then the action fails with a TimeoutError after its timeout, and the message includes a call log of every check it tried.

A click that can never happen, and its call log · ✅ mvn test ran
📄 src/test/java/com/brainy/CallLogTest.java
package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.TimeoutError;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;
import java.util.stream.Collectors;

import static org.junit.jupiter.api.Assertions.assertThrows;

@UsePlaywright(ShopOptions.class)
public class CallLogTest {
  @Test
  void whenItNeverGetsReadyTheErrorSaysWhy(Page page) {
    page.navigate("/products");
    Locator soldOut = page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Out of stock"));

    TimeoutError error = assertThrows(TimeoutError.class, () -> soldOut.click(new Locator.ClickOptions().setTimeout(2000)));
    System.out.println(error.getClass().getSimpleName());
    String message = error.getMessage();
    // Java wraps the driver error and its stack, so print from the call log on.
    System.out.println(message.substring(message.indexOf("Call log:")).lines().limit(6).collect(Collectors.joining("\n")));
  }
}

What happens

The button stays disabled, so the click gave up after the 2 second timeout. The call log under the message tells you which check kept failing: here, element is not enabled. When a test times out in your project, this log is the first thing to read. In Java the message also carries the stack of the driver, so the Java example prints from the call log on.

Two options change the checks, and both are worth knowing even if you rarely use them.

OptionWhat it doesWhen to use it
setForce(true)force=Trueforce: trueforce: trueskips the checks that are not essential, such as receives eventsa custom widget that hides its real input under a styled label

⚠️
Reaching for force is often a sign the test found the wrong element, or that a real user could not click it either. Read the call log first.

package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class HoverTest {
  @Test
  void hoverAndFocusShowTheTooltip(Page page) {
    page.navigate("/forms");
    Locator help = page.getByText("❓ Help");
    Locator tooltip = page.getByRole(AriaRole.TOOLTIP);
    assertThat(tooltip).isHidden();

    help.hover();                            // the mouse rests on it
    assertThat(tooltip).hasText("We reply within two working days");

    page.mouse().move(0, 0);                 // move the mouse away
    assertThat(tooltip).isHidden();

    help.focus();                            // keyboard users reach it with Tab
    assertThat(tooltip).isVisible();
    System.out.println("tooltip: " + tooltip.textContent());
  }
}

Part 4

⌨️Typing and keys

Most of the time you only need fill. It clears the box and puts the new text in, like pasting. Use the slower ways only when the page reacts to single key presses.

fill, pressSequentially and keyboard shortcuts · ✅ mvn test ran
📄 src/test/java/com/brainy/KeysTest.java
package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class KeysTest {
  @Test
  void fillTypeKeyByKeyAndPressShortcuts(Page page) {
    page.navigate("/products");
    Locator search = page.getByPlaceholder("Search products");
    assertThat(page.getByRole(AriaRole.LISTITEM)).hasCount(5);

    search.fill("desk");                                   // sets the whole value at once
    System.out.println("after fill: " + search.inputValue() + " | " + page.getByRole(AriaRole.LISTITEM).count() + " card");

    search.clear();
    search.pressSequentially("mug", new Locator.PressSequentiallyOptions().setDelay(50));   // one key at a time
    System.out.println("after typing: " + search.inputValue());

    search.press("Control+A");
    search.press("Backspace");
    System.out.println("after select all and delete: " + search.inputValue().length() + " characters");

    page.navigate("/forms");
    page.keyboard().press("Control+K");                    // a shortcut for the whole page
    assertThat(page.getByText("Search opened")).isVisible();
  }
}

What happens

fill sets the value in one go and fires the input event, which is enough for almost every box. pressSequentially sends one key at a time for boxes that react to each key, such as an auto complete list. press takes a key name or a combination such as Control+A.

MethodSendsUse for
fill(text)the whole value at oncealmost every text box
pressSequentially(text)one key event per characterauto complete, masks that format as you type
press(key)one key or a combinationEnter, Tab, Escape, ArrowDown, Control+A
keyboard.press(key)a key to whatever has focuspage shortcuts such as Control+K
clear()an empty valueemptying a box
🆕
Old tutorials use type(). It was renamed pressSequentially in Playwright 1.38 and the old name is deprecated. If you see it in a code base, it does the same thing.

🧲Drag and drop and the mouse

Kanban boards, sliders, sortable lists and file drop zones all need dragging. dragTo does it in one line. The mouse object gives you every step for widgets that need more control.

Drag and drop with dragTo, and by hand with the mouse · ✅ mvn test ran

package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class DragTest {
  @Test
  void dragTasksToTheDoneLane(Page page) {
    page.navigate("/forms");
    Locator todo = page.getByRole(AriaRole.LIST, new Page.GetByRoleOptions().setName("To do"));
    Locator done = page.getByRole(AriaRole.LIST, new Page.GetByRoleOptions().setName("Done"));

    todo.getByText("Pack the order").dragTo(done);
    assertThat(done.getByRole(AriaRole.LISTITEM)).hasText(new String[] {"Pack the order"});

    // The same by hand with the mouse, for widgets that need finer control.
    todo.getByText("Print the label").hover();
    page.mouse().down();
    done.hover();
    done.hover();            // a second move, so the page gets its dragover event
    page.mouse().up();

    assertThat(done.getByRole(AriaRole.LISTITEM)).hasCount(2);
    System.out.println("Done lane: " + done.getByRole(AriaRole.LISTITEM).allTextContents());
    System.out.println("To do lane: " + todo.getByRole(AriaRole.LISTITEM).count() + " tasks");
  }
}

Part 7

🚫Waiting without sleeping

Fixed waits such as page.waitForTimeout(3000) or Thread.sleep(3000)page.wait_for_timeout(3000) or time.sleep(3)page.waitForTimeout(3000)page.waitForTimeout(3000) are the most common reason for slow and flaky tests. When an action or a check is not enough, wait for the exact thing you need.

Wait for a response, an element or a condition · ✅ mvn test ran
📄 src/test/java/com/brainy/WaitTest.java
package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.Response;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import com.microsoft.playwright.options.WaitForSelectorState;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class WaitTest {
  @Test
  void waitForWhatYouNeedNeverForAFixedTime(Page page) {
    // Start waiting for the API answer before the page asks for it.
    Response answer = page.waitForResponse(r -> r.url().contains("/api/products"), () -> page.navigate("/products"));
    System.out.println("API answered with status " + answer.status());

    page.getByText("Loading products…").waitFor(new Locator.WaitForOptions().setState(WaitForSelectorState.DETACHED));
    System.out.println("cards now: " + page.getByRole(AriaRole.LISTITEM).count());

    page.navigate("/widgets");
    page.waitForFunction("() => !document.querySelector('#cover')");
    System.out.println("loading cover left: " + page.locator("#cover").count());
    assertThat(page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Pay now"))).isEnabled();
  }
}
