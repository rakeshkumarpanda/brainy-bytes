Part 1

📊What a test report is for

🧒 Beginner friendly

A report tells people and machines what happened in a test run: which tests ran, which failed, why, and how long it took. Different readers want different things, so a run usually writes several reports at once.

ReaderWantsReport
you, at the terminalpass or fail, right nowlist, line or dot in Playwright Test, -v or -q in pytest, the Surefire summary in Maven
the CI servercounts and historyJUnit XML, which every CI server reads
a tester fixing a failurethe error, the screenshot, the tracethe Playwright HTML report, pytest-html, Allure, ExtentReports
a managera dashboard: how many passed, trends, which featuresAllure, ExtentReports
your own toolsdata in a known shapeJSON, or a custom reporter
💡
The labs in this chapter all use the framework from the framework chapter, plus one test that fails on purpose: it still expects the lamp to cost ₹1,199 after a price change to ₹1,299. A report is only interesting when something fails.

1️⃣Lab 1: built-in reporters and JUnit XML

Every runner has reporters built in. Start with the ones that need nothing installed.

Playwright Test reporterWhat it gives
listone line per test, the default on a laptop
lineone line that updates, and failures in full
dotone character per test, for long runs on CI
htmla web page with every test, its steps, screenshots, videos and traces
jsonall results as JSON, for your own tools
junitJUnit XML for CI servers
blobraw results of one shard, merged later with merge-reports
githuberror notes on the right lines of a GitHub pull request

Maven Surefire prints a summary and always writes XML files to target/surefire-reports. TestNG adds its own testng-results.xml.In pytest the terminal output is set with -v, -q and -rA, and --junitxml writes JUnit XML.Choose reporters with --reporter or in the config. What happens

One test now fails on purpose: the lamp costs ₹1,299, not ₹1,199. Every runner printed a short result for people and wrote JUnit XML for machines. The XML line is what Jenkins, GitLab and Azure DevOps read to count passed and failed tests: eight tests, one failure. Playwright Test also wrote JSON, whose stats say 7 expected and 1 unexpected. Several reporters can run at once, here dot, json and junit.

📄 src/test/java/com/brainy/shop/reporting/ExtentReporter.java
package com.brainy.shop.reporting;

import com.aventstack.extentreports.ExtentReports;
import com.aventstack.extentreports.ExtentTest;
import com.aventstack.extentreports.MediaEntityBuilder;
import com.aventstack.extentreports.reporter.ExtentSparkReporter;
import org.testng.IReporter;
import org.testng.ISuite;
import org.testng.ITestResult;
import org.testng.xml.XmlSuite;

import java.util.ArrayList;
import java.util.Base64;
import java.util.Comparator;
import java.util.Date;
import java.util.List;

// TestNG calls generateReport once, after the whole suite. It writes target/extent/index.html
public class ExtentReporter implements IReporter {
  @Override
  public void generateReport(List<XmlSuite> xmlSuites, List<ISuite> suites, String outputDirectory) {
    ExtentSparkReporter spark = new ExtentSparkReporter("target/extent/index.html");
    spark.config().setDocumentTitle("Brainy Shop tests");
    spark.config().setReportName("Brainy Shop, nightly run");
    ExtentReports extent = new ExtentReports();
    extent.attachReporter(spark);
    extent.setSystemInfo("Browser", "Chromium");

    List<ITestResult> all = new ArrayList<>();
    for (ISuite suite : suites) {
      suite.getResults().values().forEach(r -> {
        all.addAll(r.getTestContext().getPassedTests().getAllResults());
        all.addAll(r.getTestContext().getFailedTests().getAllResults());
        all.addAll(r.getTestContext().getSkippedTests().getAllResults());
      });
    }
    all.sort(Comparator.comparingLong(ITestResult::getStartMillis));
    for (ITestResult result : all) add(extent, result);
    extent.flush();
  }

  private void add(ExtentReports extent, ITestResult result) {
    ExtentTest test = extent.createTest(result.getMethod().getMethodName())
        .assignCategory(result.getTestClass().getRealClass().getSimpleName());
    for (String group : result.getMethod().getGroups()) test.assignCategory(group);
    test.getModel().setStartTime(new Date(result.getStartMillis()));   // the real times, not the report time
    test.getModel().setEndTime(new Date(result.getEndMillis()));
    switch (result.getStatus()) {
      case ITestResult.SUCCESS -> test.pass("Passed");
      case ITestResult.SKIP -> test.skip("Skipped");
      default -> {
        test.fail(result.getThrowable());
        if (result.getAttribute("screenshot") instanceof byte[] png) {
          String base64 = Base64.getEncoder().encodeToString(png);
          test.fail("Screenshot at failure", MediaEntityBuilder.createScreenCaptureFromBase64String(base64).build());
        }
      }
    }
  }
}
📄 src/test/java/com/brainy/shop/reporting/EvidenceListener.java
package com.brainy.shop.reporting;

import com.brainy.shop.base.BaseTest;
import org.testng.ITestListener;
import org.testng.ITestResult;

// TestNG calls onTestFailure while the page is still open, so the screenshot shows the failure
public class EvidenceListener implements ITestListener {
  @Override
  public void onTestFailure(ITestResult result) {
    if (result.getInstance() instanceof BaseTest test) {
      result.setAttribute("screenshot", test.screenshot());   // ExtentReporter reads it at the end
    }
  }
}

What happens

Each language wrote raw results into an allure-results folder: allure-playwright for Playwright Test, allure-pytest for pytest and allure-testng for TestNG. The same Allure command line then built the same kind of report from them. The labels and steps in the test show up as severity, feature and a step list, and the failure carries its screenshot.

🆕
This page uses Allure Report 3, which installs from npm and needs Node.js, even for Python and Java projects: npx allure generate allure-results. Allure Report 2 is a Java program installed separately, with the command allure generate. Both read the same allure-results folder.
🏢
Keep the allure-results of earlier runs, or the history folder of the last report, and Allure shows trends and flaky tests across runs.

package com.brainy.shop.reporting;

import org.testng.ITestContext;
import org.testng.ITestListener;
import org.testng.ITestResult;

// One line per test, then a short summary when the run ends
public class SummaryListener implements ITestListener {
  @Override
  public void onTestSuccess(ITestResult result) { line("PASS", result); }

  @Override
  public void onTestFailure(ITestResult result) { line("FAIL", result); }

  @Override
  public void onTestSkipped(ITestResult result) { line("SKIP", result); }

  @Override
  public void onFinish(ITestContext context) {
    System.out.printf("%d passed, %d failed, %d skipped%n", context.getPassedTests().size(),
        context.getFailedTests().size(), context.getSkippedTests().size());
    context.getFailedTests().getAllResults()
        .forEach(r -> System.out.println("  to look at: " + r.getMethod().getMethodName()));
  }

  private void line(String status, ITestResult r) {
    double seconds = (r.getEndMillis() - r.getStartMillis()) / 1000.0;
    System.out.printf("%s  %s (%.1f s)%n", status, r.getMethod().getMethodName(), seconds);
  }
}

import pytest

results = []


# pytest reports each test three times: setup, call and teardown. The call holds the result,
# and a failure while setting up is reported in the setup instead.
def pytest_runtest_logreport(report):
    if report.when == "call" or (report.when == "setup" and not report.passed):
        results.append(report)


def pytest_terminal_summary(terminalreporter):
    tr = terminalreporter
    tr.section("shop summary")
    for r in results:
        name = r.nodeid.split("::")[-1]
        tr.write_line(f"{'PASS' if r.passed else 'FAIL'}  {name} ({r.duration:.1f} s)")
    failed = [r.nodeid.split("::")[-1] for r in results if r.failed]
    tr.write_line(f"{len(results) - len(failed)} passed, {len(failed)} failed")
    for name in failed:
        tr.write_line(f"  to look at: {name}")

// One line per test, then a short summary that a team could also send to chat or a dashboard
export default class SummaryReporter {
  passed = 0;
  failed = [];

  onBegin(config, suite) {
    console.log(`Starting ${suite.allTests().length} tests on ${config.workers} workers`);
  }

  onTestEnd(test, result) {
    const seconds = (result.duration / 1000).toFixed(1);
    if (result.status === 'passed') {
      this.passed++;
      console.log(`PASS  ${test.title} (${seconds} s)`);
    } else {
      this.failed.push(test.title);
      console.log(`FAIL  ${test.title} (${seconds} s)`);
    }
  }

  onEnd(result) {
    console.log(`${this.passed} passed, ${this.failed.length} failed, run ${result.status}`);
    for (const title of this.failed) console.log(`  to look at: ${title}`);
  }
}

A reporter is a class or a set of hooks that the runner calls as the run goes: once at the start, once per finished test and once at the end. Playwright Test calls onBegin, onTestEnd and onEnd. pytest calls pytest_runtest_logreport for every phase and pytest_terminal_summary at the end. TestNG calls ITestListener methods. The run still fails with exit code 1, so CI marks it red whatever the reporter prints.

Playwright TestpytestTestNG
at the startonBegin(config, suite)pytest_sessionstartonStart(context)
after each testonTestEnd(test, result)pytest_runtest_logreport(report)onTestSuccess, onTestFailure, onTestSkipped
at the endonEnd(result)pytest_terminal_summaryonFinish(context), or IReporter.generateReport
turn it on--reporter=./my-reporter.ts or the config-p module, or code in conftest.pya listener in testng.xml
⚠️
A reporter must not change whether the run passed. It only describes the run, so CI still sees exit code 1 when a test failed.

What happens

Two shards each wrote a blob report, and merge-reports built one HTML report from both: the same playwright-report folder a single run makes, with all eight tests and the failure from shard 1. This is the last job of the sharded workflow in the CI/CD chapter.

WhereHow
GitHub Actionsupload the report folder as an artifact, or publish it to GitHub Pages
Jenkinsthe junit step for counts and history, and the HTML Publisher or Allure plugin for the page
GitLab CIartifacts: reports: junit, and the report folder as an artifact or GitLab Pages
Azure DevOpsPublishTestResults for JUnit XML, and PublishPipelineArtifact for the HTML
💡
Python and Java shards each write their own JUnit XML file. CI servers read many files at once, for example target/surefire-reports/*.xml in Jenkins, so they do not need merging first. Allure also reads several allure-results folders in one command.
