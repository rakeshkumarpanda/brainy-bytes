Part 1

🎯What a locator is

🧒 Beginner friendly

A locator is a way to find an element on the page, written as a short description such as the button called Sign in. It does not hold the element. Every time you use it, Playwright searches the page again, at that moment. This is why a locator never goes stale when the page changes, which was a common problem in older tools.

A locator is found again every time you use it · ✅ mvn test ran
📄 src/test/java/com/brainy/LazyTest.java
package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class LazyTest {
  @Test
  void aLocatorIsARecipeNotAnElement(Page page) {
    page.navigate("/products");
    Locator cards = page.getByRole(AriaRole.LISTITEM);          // nothing is searched yet
    assertThat(cards).hasCount(5);
    System.out.println("before search: " + cards.count());

    page.getByPlaceholder("Search products").fill("o");
    System.out.println("after \"o\": " + cards.count());       // the same locator, found again

    page.getByPlaceholder("Search products").fill("bottle");
    assertThat(cards).hasCount(1);
    System.out.println("after \"bottle\": " + cards.count());
    System.out.println(cards.describe("product cards"));
  }
}

What happens

One locator gave three different counts, because it searches the page again at the moment it is used. A search for the letter o keeps the three products whose names contain it. describe gives the locator a readable name that shows up in reports and in the trace viewer. Python prints the whole locator, with the name inside the selector.

Playwright gives you locators that describe what a person sees: a role and a name, a label, a placeholder, some text. Try them in the locator lab. Type your own in any of the four languages.

🌍
A real life example: you tell a friend press the green Pay button, not press the third button in the second box. The first instruction still works when the page is redesigned. Good locators work the same way.
Part 2

🧑‍🦯getByRole: the first choice

🧒 Beginner friendly

Every element has a role that tells assistive technology what it is: button, link, heading, textbox, checkbox, row and many more. Most of them come from the HTML tag itself, so developers get them for free. The name is what a person reads: the button text, the label of a box, or an aria-label.

getByRole with names, levels and states · ✅ mvn test ran
📄 src/test/java/com/brainy/RoleTest.java
package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class RoleTest {
  @Test
  void findThingsTheWayAUserSeesThem(Page page) {
    page.navigate("/products");
    assertThat(page.getByRole(AriaRole.LISTITEM)).hasCount(5);   // waits for the list

    System.out.println("headings: " + page.getByRole(AriaRole.HEADING).allTextContents());
    System.out.println("level 1 heading: " + page.getByRole(AriaRole.HEADING, new Page.GetByRoleOptions().setLevel(1)).textContent());

    // The name is matched ignoring case, and part of the name is enough.
    System.out.println("\"add to cart\": " + page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("add to cart")).count());
    // setExact(true) wants the whole name with the same case.
    System.out.println("\"add to cart\" exact: " + page.getByRole(AriaRole.BUTTON,
        new Page.GetByRoleOptions().setName("add to cart").setExact(true)).count());
    System.out.println("disabled buttons: " + page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setDisabled(true)).count());

    page.getByRole(AriaRole.SEARCHBOX, new Page.GetByRoleOptions().setName("Search")).fill("lamp");
    page.getByRole(AriaRole.COMBOBOX, new Page.GetByRoleOptions().setName("Sort by")).selectOption("high");
    assertThat(page.getByRole(AriaRole.LISTITEM)).hasCount(1);
    System.out.println("left after search: " + page.getByRole(AriaRole.LISTITEM).getByRole(AriaRole.HEADING).textContent());
  }
}

What happens

The list is sorted by name, so Coffee mug comes first. A search box has the role searchbox, a drop down list has the role combobox, and a heading knows its level. By default the name matches ignoring case and part of it is enough, so add to cart finds all four buttons. With exact it finds none, because the real name starts with a capital A.

HTMLRoleExample locator
<button>, <input type=submit>buttongetByRole('button', { name: 'Sign in' })
<a href>linkgetByRole('link', { name: 'Orders' })
<h1> to <h6>headinggetByRole('heading', { level: 1 })
<input type=text>, <textarea>textboxgetByRole('textbox', { name: 'Email' })
<input type=search>searchboxgetByRole('searchbox')
<select>comboboxgetByRole('combobox', { name: 'Sort by' })
<input type=checkbox> and radiocheckbox, radiogetByRole('checkbox', { checked: true })
<li>, <tr>, <td>listitem, row, cellgetByRole('row').filter(...)

Options narrow it further: setName, setExact, setLevel, setChecked, setDisabled, setExpanded, setPressed, setSelected and setIncludeHidden on GetByRoleOptionsname, exact, level, checked, disabled, expanded, pressed, selected and include_hiddenname, exact, level, checked, disabled, expanded, pressed, selected and includeHiddenname, exact, level, checked, disabled, expanded, pressed, selected and includeHidden. The name can also be a regular expression.

🏢
If getByRole cannot find a button that you can see, the page is probably missing a role or a name, and a screen reader user cannot use it either. That is a real accessibility bug worth reporting.

🏷️Labels, placeholders, text, alt text, titles and test ids

🧒 Beginner friendly

The other built in locators cover the cases where a role is not enough.

package com.brainy;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;
import java.util.regex.Pattern;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class GetByTest {
  @Test
  void labelsPlaceholdersTextTitlesAndTestIds(Page page) {
    page.navigate("/login");
    page.getByLabel("Email").fill("asha@shop.example");
    page.getByLabel("Password").fill("s3cret");
    page.getByText("Remember me").click();          // clicking a label ticks its box
    assertThat(page.getByLabel("Remember me")).isChecked();
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Sign in")).click();

    assertThat(page.getByText("Hello, Asha")).isVisible();
    assertThat(page.getByTestId("cart-count")).hasText("0");
    assertThat(page.getByPlaceholder("Search products")).isEditable();
    assertThat(page.getByTestId(Pattern.compile("^product-"))).hasCount(5);   // all product cards

    page.navigate("/frames");
    System.out.println("iframes by title: " + page.getByTitle("Payment form").count());
  }
}

What happens

The form boxes are found by the words of their labels. Clicking the text Remember me clicks its label, and the browser ticks the box, just as it would for a person. The cart counter has a data-testid, and a regular expression finds all five product cards by theirs.

Text matching works like names: ignoring case, part of the text is enough, and runs of spaces count as one. Use exact for a full, case sensitive match, or a regular expression.

Part 4

🧩CSS and XPath

locator() takes a CSS selector or an XPath. They are useful for old pages without good labels, but they describe how the page is built, not what the user sees.

What happens

Playwright decides by the first characters: a string that starts with // or .. is XPath, everything else is CSS. CSS also gets extras such as :has-text(). These locators work, but they break when a developer renames a class or moves a tag, which a user never notices.

You wantBetter choiceFragile choice
the Sign in buttongetByRole('button', { name: 'Sign in' })locator('#login > button.btn-primary')

the price of the muggetByRole('listitem').filter({ hasText: 'Coffee mug' }).getByText(/₹/)locator('li:nth-child(1) span:nth-child(3)')
⚠️
Long XPaths copied from the browser tools, such as /html/body/div[2]/div/form/input, break as soon as one box is added to the page. Recorded tests from older tools are full of them, and they are the first thing to replace when a team moves to Playwright.

What happens

filter keeps the cards that contain some text, or that contain (or do not contain) another locator. Chaining, such as soldOut.getByRole('heading'), searches only inside the cards that are left. nth counts from 0, so nth(2) is the third card. or matches either locator, and and keeps only elements both locators match.

setHasNotText("x")has_not_text="x"hasNotText: 'x'hasNotText: 'x'elements that do not contain the text

⚠️
first(), last() and nth() depend on the order of the page. When the order changes, they quietly pick another element. Prefer a filter by text when you can.

🚦Strict mode

import { test, expect } from '@playwright/test';

test('read a table and act on one row', async ({ page }) => {
  await page.goto('/orders');
  const rows = page.getByRole('row').filter({ has: page.getByRole('cell') });   // skip the header row
  await expect(rows).toHaveCount(5);

  for (const row of await rows.all()) {
    console.log(await row.getByRole('cell').allTextContents());
  }

  const meera = rows.filter({ hasText: 'Meera' });
  await meera.getByRole('button', { name: 'Delete' }).click();
  await expect(page.getByRole('status')).toHaveText('Order #1003 deleted');
  await expect(rows.filter({ hasText: 'Meera' })).toHaveCount(0);
});

What happens

Table cells have the role cell and header cells have the role columnheader, so filtering rows that have a cell skips the header. all() turns the locator into a list you can loop over. It does not wait, so the count check comes first. The Delete button of Meera's row is found inside that row only.

🌍
A bank or an admin portal often has tables with paging and sorting. A test that finds a row by position breaks the day someone adds an order. A test that finds the row by its order number keeps working.
