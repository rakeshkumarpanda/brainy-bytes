🧰What you need before you start

🧒 Beginner friendly

Part 2

📦Install Playwright in your language

🧒 Beginner friendly

Choose your language below. Each tab shows the commands you type, in order.

Java. Add one dependency to pom.xml. Add JUnit 5 too if you want the @UsePlaywright annotation that gives each test a page.

<dependency>
  <groupId>com.microsoft.playwright</groupId>
  <artifactId>playwright</artifactId>
  <version>1.63.0</version>
</dependency>

Maven downloads the jar the first time you build. The first time your code calls Playwright.create(), it downloads the browsers too. To download them yourself, for example in a CI image, run the command line tool through Maven:

mvn exec:java -e -D exec.mainClass=com.microsoft.playwright.CLI -D exec.args="install --with-deps"

Python. Make a virtual environment, install the pytest plugin, then download the browsers.

python -m venv .venv
source .venv/bin/activate        # on Windows: .venv\Scripts\activate
pip install pytest-playwright     # installs playwright and pytest too
playwright install --with-deps    # downloads the browsers and the system libraries they need

JavaScript and TypeScript. One command creates the project, asks four questions and downloads the browsers.

npm init playwright@latest

It asks: TypeScript or JavaScript (TypeScript is the default), the name of the tests folder, whether to add a GitHub Actions workflow, and whether to install the browsers. In an existing project the same command adds Playwright to your package.json.

Now check what you have. These commands ran on the build machine of this page.

What happens

The Java and Python packages carry the same driver as the npm package, so all three print the same Playwright version. In Java the command line tool is the class com.microsoft.playwright.CLI, which Maven runs for you.

Playwright downloads its own browsers so that every machine tests with exactly the same versions. The --with-deps option also installs the operating system libraries the browsers need on Linux, which is what you want on a CI server.

What happens

--dry-run shows what would be downloaded and where, without downloading. On this build machine the variable PLAYWRIGHT_BROWSERS_PATH points to /opt/pw-browsers. On your own computer the default is ~/.cache/ms-playwright on Linux, ~/Library/Caches/ms-playwright on macOS and %USERPROFILE%\AppData\Local\ms-playwright on Windows. Since version 1.57, Chromium means a Chrome for Testing build, and headless runs use the smaller Chrome Headless Shell.

⚠️
Keep one Playwright version per project and update on purpose. Each Playwright release expects its own browser builds. After you update the package, run the install command again, or the tests stop with an error that says the browser executable does not exist.

import { test, expect } from '@playwright/test';

test('has title', async ({ page }) => {
  await page.goto('/');

  // Expect a title "to contain" a substring.
  await expect(page).toHaveTitle(/Brainy Shop/);
});

test('get started link', async ({ page }) => {
  await page.goto('/');

  // Click the products link.
  await page.getByRole('link', { name: 'Products' }).first().click();

  // Expects page to have a heading with the name of Products.
  await expect(page.getByRole('heading', { name: 'Products' })).toBeVisible();
});

What happens

The two starter tests visit playwright.dev, so here they were changed to visit the shop, and the config got a baseURL. The Firefox and WebKit projects were removed for this run because only Chromium is installed on the build machine. With all three projects, each test runs three times, once per browser.

Three ideas are the same in every language:

  • Tests live in their own folder: tests/, or src/test/java in Maven.
  • A naming rule tells the runner what is a test: *.spec.ts, test_*.py, or a class ending in Test.
  • Settings live in one file: playwright.config.ts, pytest.ini and conftest.py, or an options class in Java.

🎬Record a test with codegen

🧒 Beginner friendly

Codegen opens a browser and a second window called the Playwright Inspector. Everything you do in the browser is written down as code, in the language you choose. It is the fastest way to find good locators for a page you do not know yet.

mvn exec:java -e -D exec.mainClass=com.microsoft.playwright.CLI -D exec.args="codegen --target java-junit http://localhost:4173/login"playwright codegen --target python-pytest http://localhost:4173/loginnpx playwright codegen http://localhost:4173/loginnpx playwright codegen http://localhost:4173/login

These pictures are real. The build started codegen on a virtual screen, then clicked into the boxes and typed, exactly as you would.

🏢

Part 6

🧑‍💻Your editor

🧒 Beginner friendly

You can write Playwright tests in any editor, but these make life easier:

  • VS Code with the Playwright Test extension (JavaScript and TypeScript). It adds a Testing panel to run or debug one test with a click, a Show browser option, Pick locator to hover the page and copy a locator, and Record new to start codegen inside the editor. Since version 1.56 it can also set up the Playwright test agents.
  • IntelliJ IDEA (Java). JUnit and TestNG tests get a green run button next to every method. Add PWDEBUG=1 to the run configuration to open the Inspector.
  • PyCharm or VS Code with the Python extension (Python). Both understand pytest, so every test_ function gets a run button. Set the interpreter to the project's .venv.
🏢
Turn on format on save and a linter in your editor from day one. In TypeScript, the ESLint rule @typescript-eslint/no-floating-promises catches a missing await, the bug from chapter 1, before you even run the test.
Part 7

🔄Updating Playwright safely

Playwright ships a new minor version about once a month. Update on a branch, run the whole suite, read the release notes, then merge.

LanguageUpdate the packageThen
☕ Javachange <version> in pom.xmlrun the tests. The new browsers download on first use, or run the CLI install command
🐍 Pythonpip install -U pytest-playwright playwrightplaywright install --with-deps
🟨🔷 JavaScript and TypeScriptnpm install -D @playwright/test@latestnpx playwright install --with-deps
💡
Pin exact versions in your project (no ^ in package.json, == in requirements.txt). Then a teammate and the CI server always run the same Playwright, and an update is a change you can see and review.
