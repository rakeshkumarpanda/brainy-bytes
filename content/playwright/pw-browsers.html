Part 1

🏢Browser, context and page

🧒 Beginner friendly

Playwright gives you three levels of objects, and it helps to picture them as real things:

  • Browser: the browser program that is running, such as Chromium. Starting it is slow, about half a second, so you start one and reuse it.
  • Browser context: a brand new, empty browser profile inside that browser. It has its own cookies, storage, cache and permissions, like a fresh incognito window. Creating one takes a few milliseconds.
  • Page: one tab inside a context. A context can have many pages, and they share the context's login.
🧒
Picture a shop with one building and many changing rooms. The building is the browser. Each changing room is a context: what one customer leaves in their room never appears in another room. The pages are the hangers in the room, all belonging to the same customer.

Build them yourself below. Add contexts and pages, sign a context in, and watch what is shared and what is not.

This is why test runners create a new context for every test. Two tests can never see each other's cookies, so they pass in any order and can run in parallel.

Part 2

🚀Launching a browser

🧒 Beginner friendly

In a script you launch the browser yourself. In a test runner the runner launches it for you, and you only set the options.

Launch a browser with options · ✅ ran for real
📄 src/main/java/com/brainy/Main.java
package com.brainy;

import com.microsoft.playwright.*;
import java.util.List;

public class Main {
  public static void main(String[] args) {
    try (Playwright playwright = Playwright.create()) {
      Browser browser = playwright.chromium().launch(new BrowserType.LaunchOptions()
          .setHeadless(true)          // no window. Use false to watch it work
          .setSlowMo(100)             // wait 100 ms before every action
          .setArgs(List.of("--lang=en-GB")));
      System.out.println("Browser type: " + browser.browserType().name());
      System.out.println("Version: " + browser.version());
      System.out.println("Connected: " + browser.isConnected());
      System.out.println("Contexts so far: " + browser.contexts().size());
      browser.close();
      System.out.println("Connected after close: " + browser.isConnected());
    }
  }
}

🧳Contexts keep tests apart

One browser can hold many contexts at the same time. This test signs Asha in inside one context and checks that a second context, in the same browser, is still a guest.

Two shoppers in one browser, kept apart · ✅ mvn test ran
📄 src/test/java/com/brainy/ContextTest.java
package com.brainy;

import com.microsoft.playwright.*;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class ContextTest {
  @Test
  void twoShoppersInOneBrowser(Browser browser) {
    // Each context is a separate, empty browser profile.
    BrowserContext ashaContext = browser.newContext();
    BrowserContext guestContext = browser.newContext();
    Page asha = ashaContext.newPage();
    Page guest = guestContext.newPage();

    asha.navigate("http://localhost:4173/login");
    asha.getByLabel("Email").fill("asha@shop.example");
    asha.getByLabel("Password").fill("s3cret");
    asha.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Sign in")).click();
    assertThat(asha.getByText("Hello, Asha")).isVisible();

    guest.navigate("http://localhost:4173/products");
    assertThat(guest.getByRole(AriaRole.LINK, new Page.GetByRoleOptions().setName("Sign in"))).isVisible();
    System.out.println("Asha cookies: " + ashaContext.cookies().size());
    System.out.println("Guest cookies: " + guestContext.cookies().size());

    ashaContext.close();
    guestContext.close();
  }
}

What happens

Asha signed in inside her own context and got a session cookie. The guest context, in the same browser, has no cookie and still sees the Sign in link. In Playwright Test, a context you create from the browser fixture gets the same use options as the built in one, such as baseURL. The Python new_context fixture does the same and closes the contexts for you. In Java, a context you create yourself starts with default options, so the Java version uses full addresses.

🏢
Real projects use two contexts in one test for features with two people: a chat between a customer and a support agent, an admin approving an order while the customer waits, or two players in a game. Each person gets their own context.

🎭Pretend to be another user

Context options change what the website sees about the browser. You can test a German user in India on a small screen in dark mode, without leaving your desk. The shop's About you page prints what it sees.

Pretend to be a German phone user in India · ✅ mvn test ran
📄 src/test/java/com/brainy/EmulationTest.java
package com.brainy;

import com.microsoft.playwright.*;
import com.microsoft.playwright.junit.Options;
import com.microsoft.playwright.junit.OptionsFactory;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.ColorScheme;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(EmulationTest.GermanPhone.class)
public class EmulationTest {
  public static class GermanPhone implements OptionsFactory {
    @Override
    public Options getOptions() {
      return new Options().setHeadless(true).setBaseUrl("http://localhost:4173")
          .setContextOptions(new Browser.NewContextOptions()
              .setViewportSize(390, 844)
              .setLocale("de-DE")
              .setTimezoneId("Asia/Kolkata")
              .setColorScheme(ColorScheme.DARK)
              .setHasTouch(true));
    }
  }

  @Test
  void theShopSeesAGermanPhoneUserInIndia(Page page) {
    page.navigate("/about-you");
    for (String id : new String[] {"width", "lang", "tz", "price", "touch"}) {
      System.out.println(String.format("%-6s ", id) + page.locator("#" + id).textContent());
    }
    Object dark = page.evaluate("matchMedia('(prefers-color-scheme: dark)').matches");
    System.out.println("dark   " + dark);
    assertThat(page.locator("#lang")).hasText("de-DE");
  }
}

Location and permissions · ✅ mvn test ran
📄 src/test/java/com/brainy/LocationTest.java
package com.brainy;

import com.microsoft.playwright.*;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class LocationTest {
  @Test
  void findsStoresNearNewDelhi(Browser browser) {
    BrowserContext context = browser.newContext(new Browser.NewContextOptions()
        .setGeolocation(28.6139, 77.209)                 // New Delhi
        .setPermissions(java.util.List.of("geolocation")));
    Page page = context.newPage();
    page.navigate("http://localhost:4173/about-you");
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Find stores near me")).click();
    assertThat(page.locator("#where")).hasText("28.6139, 77.2090");
    context.close();
  }

  @Test
  void locationBlockedWhenPermissionIsNotGranted(Page page) {
    page.navigate("/about-you");
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Find stores near me")).click();
    assertThat(page.locator("#where")).containsText("blocked");
  }
}

📱Phones and tablets

Playwright ships a list of more than 200 device profiles, such as iPhone 15, Pixel 7 and Galaxy S24. Each profile is a set of context options. This is emulation inside a desktop browser engine: it gets the size, the touch input and the user agent right, but it is not a real phone.

Part 6

🗂️New tabs and pop ups

When a click opens a new tab or window, Playwright gives you a new page object for it. The trick is to start waiting before the click, so the event cannot be missed.

New tabs and pop up windows · ✅ mvn test ran
📄 src/test/java/com/brainy/TabsTest.java
package com.brainy;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class TabsTest {
  @Test
  void helpOpensInANewTab(Page page) {
    page.navigate("/widgets");
    // waitForPopup runs the click and waits for the new tab it opens.
    Page help = page.waitForPopup(() ->
        page.getByRole(AriaRole.LINK, new Page.GetByRoleOptions().setName("Open help in a new tab")).click());

    assertThat(help).hasTitle("Help · Brainy Shop");
    System.out.println("Tabs open: " + page.context().pages().size());
    help.close();
    System.out.println("Tabs open: " + page.context().pages().size());
  }

  @Test
  void theChatWindowIsAPopup(Page page) {
    page.navigate("/widgets");
    Page chat = page.waitForPopup(() ->
        page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Open chat window")).click());
    assertThat(chat.getByRole(AriaRole.HEADING)).hasText("Chat with us");
  }
}

Part 8

♻️Profiles, closing and remote browsers

Most of the time a fresh context per test is right. Two other ways to get a browser are worth knowing.

A persistent profile that survives a restart · ✅ ran for real
📄 src/main/java/com/brainy/Main.java
package com.brainy;

import com.microsoft.playwright.*;
import java.nio.file.Files;
import java.nio.file.Path;

public class Main {
  public static void main(String[] args) throws Exception {
    Path profile = Files.createTempDirectory("shop-profile-");
    try (Playwright playwright = Playwright.create()) {
      // First visit: a real profile folder on disk, like a person's Chrome profile.
      BrowserContext context = playwright.chromium().launchPersistentContext(profile, new BrowserType.LaunchPersistentContextOptions());
      Page page = context.pages().get(0);
      page.navigate("http://localhost:4173/");
      page.evaluate("localStorage.setItem('theme', 'dark')");
      context.close();

      // Second visit with the same folder: the data is still there.
      context = playwright.chromium().launchPersistentContext(profile, new BrowserType.LaunchPersistentContextOptions());
      page = context.pages().get(0);
      page.navigate("http://localhost:4173/");
      System.out.println("theme = " + page.evaluate("localStorage.getItem('theme')"));
      context.close();
    }
  }
}

What happens

A persistent context keeps cookies and storage in a folder on disk, like a real Chrome profile. Tests normally avoid this, because a fresh context per test is what keeps tests independent. It is useful for browser extensions and for scripts that must stay signed in.

  • Connect to a browser that is already running. chromium.connectOverCDP(url) attaches to a Chrome started with a remote debugging port, for example to automate a browser that a person already signed into.
  • Run browsers on another machine. launchServer() starts a browser that others connect to with browserType.connect(wsEndpoint). Cloud grids and the Playwright Docker image use this.
💡
Close what you open. In a test runner the fixtures close contexts and pages for you. In a script, close the browser at the end, or use try with resources in Java and a with block in Python, so a crash does not leave browser processes running on the machine.
