Part 1

🎭What Playwright is

🧒 Beginner friendly

Playwright is a free tool, made by Microsoft, that controls a real web browser from code. Your code can open a page, click buttons, type into boxes, wait for things to appear and check that the page shows the right result. It does this in Chromium (the engine of Google Chrome and Microsoft Edge), Firefox and WebKit (the engine of Apple Safari).

🧒
Think of a shop that hires a careful helper. Every morning the helper opens the shop website, signs in, adds a pen to the cart and checks that the total is right. Playwright is that helper, written in code. It never gets bored, it checks the same steps in three browsers, and it finishes in seconds.

Teams use Playwright for three jobs:

  • End to end tests. A test acts like a user, from opening the site to placing an order, and checks every important step.
  • API tests. Playwright can also send HTTP requests without a browser, so the same project can test the server directly.
  • Automation. Filling forms, taking screenshots, making PDFs and collecting data from pages.

Playwright has official versions for four language families, all made and released together by the Playwright team:

⚠️
People often ask for Playwright in C, C++ or Go. There is no official Playwright for C or C++. For Go there is a community project, playwright-go, which is not made by the Playwright team. This subject sticks to the official languages so that every example is supported and up to date.
Part 2

⚖️Why teams pick Playwright

🧒 Beginner friendly

Before Playwright, most teams used Selenium, and many front end teams used Cypress. All three are good tools. This table shows the facts that differ, so you can explain the choice in an interview or a team meeting.

PlaywrightSelenium WebDriverCypress
LanguagesJava, Python, JavaScript, TypeScript, C#Java, Python, JavaScript, C#, RubyJavaScript and TypeScript
BrowsersChromium, Firefox, WebKitChrome, Firefox, Edge, Safari through their driversChromium family, Firefox, WebKit (experimental)
How it talks to the browserBrowser debugging protocols, through one driver processThe W3C WebDriver protocol, through a driver per browserRuns inside the browser next to your app
WaitingAutomatic before every action and in every checkYou add waits yourselfAutomatic retries for commands and checks
Several tabs, windows and domains in one testYesYesLimited
Parallel runsBuilt in, freeWith Selenium Grid or a test runnerPaid cloud service, or plugins
DebuggingTrace viewer, UI mode, inspector, codegenLogs and screenshots you addTime travel in the runner

The biggest daily difference is waiting. In Selenium, a click on a button that is still loading fails, so people add waits. Playwright checks that the element is visible, stable and enabled before it acts, and every expect check keeps trying until it passes or times out. This removes most flaky tests, the ones that pass and fail at random.

🏢
In many companies you will join a project that already uses Selenium. Knowing both is useful. Many teams move to Playwright one test suite at a time, because the ideas are close: find an element, act on it, check the result.
Part 3

👀Your first script

🧒 Beginner friendly

A script is the simplest way to use Playwright. It starts a browser, opens a page, does something and closes the browser. Read it line by line in your language.

Your first Playwright script · ✅ ran for real
📄 src/main/java/com/brainy/FirstScript.java
package com.brainy;

import com.microsoft.playwright.*;

public class FirstScript {
  public static void main(String[] args) {
    try (Playwright playwright = Playwright.create()) {        // start the Playwright driver
      Browser browser = playwright.chromium().launch();         // start a real Chromium, with no window
      Page page = browser.newPage();                             // open a new tab
      page.navigate("http://localhost:4173/products");
      System.out.println("Title: " + page.title());
      page.screenshot(new Page.ScreenshotOptions()
          .setPath(java.nio.file.Paths.get("products.png")));  // save a picture of the page
    }                                                            // closing Playwright closes the browser too
  }
}

What happens

Each version starts a real Chromium without a window, opens the products page, prints its title and saves products.png. Node.js 22.18 and later can run a .ts file directly, and the build checks the types with tsc first.

Three objects appear in every language:

  • Browser: one running browser program. Starting it takes about half a second.
  • Page: one tab inside the browser. Almost everything you do, such as goto, click and fill, is done on a page.
  • Playwright: the object you create with Playwright.create(). It starts the driver. Closing it with try with resources closes everything.sync_playwright(): starts the driver. The with block stops it at the end, even after an error.chromium: the browser type you import. firefox and webkit are imported the same way.chromium: the browser type you import. firefox and webkit are imported the same way.

Java calls the method navigate, while the other languages call it goto, because goto is a reserved word in Java.Python uses snake case names, such as new_page and get_by_role, where JavaScript writes newPage and getByRole. The meaning is the same.JavaScript and TypeScript need await before every Playwright call, because each call sends a message and waits for the answer. When your test says click, a lot happens in a few milliseconds. Knowing these layers helps you understand error messages, timeouts and why the same features exist in every language.

Now follow one click through every layer. Pick your language and a browser, then press Play.

package com.brainy;

import com.microsoft.playwright.*;

Part 5

✅From a script to a test

🧒 Beginner friendly

A script does things. A test does things and then checks the result, and a test runner runs many tests, gives each one a fresh page and reports which passed. Here is the same sign in, as a real test, in four languages.

Your first test, in four languages · ✅ mvn test ran
📄 src/test/java/com/brainy/SignInTest.java
package com.brainy;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class SignInTest {
  @Test
  void aCustomerCanSignIn(Page page) {
    page.navigate("/login");
    page.getByLabel("Email").fill("asha@shop.example");
    page.getByLabel("Password").fill("s3cret");
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Sign in")).click();
    assertThat(page.getByText("Hello, Asha")).isVisible();
  }
}

What happens

All four are the same test. Each test runner gives the test a fresh page, opens the shop, signs in and checks the greeting. Java uses JUnit 5 with the @UsePlaywright annotation, Python uses pytest with the pytest-playwright plugin, and JavaScript and TypeScript use Playwright Test, the runner made by the Playwright team.

Step through the same test below. Each picture was taken from a real Chromium run when this page was built.

Notice what the test does not do. It never waits for a number of seconds and never looks for an element by its position on the screen. It finds things the way a person does, by their label and their role, and it lets Playwright wait.
