Part 1

🪝Before and after hooks

🧒 Beginner friendly

Hooks run code around your tests: before and after each test, or once before and after all the tests in a file or class. They are the simplest way to share set up.

Before and after hooks, and the order they run in · ✅ mvn test ran
📄 src/test/java/com/brainy/HooksTest.java
package com.brainy;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.*;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
@TestMethodOrder(MethodOrderer.OrderAnnotation.class)
public class HooksTest {
  @BeforeAll
  static void onceForThisClass() {
    System.out.println("@BeforeAll: once for this class");
  }

  @BeforeEach
  void openProducts(Page page, TestInfo info) {
    System.out.println("@BeforeEach: open the products page for " + info.getDisplayName());
    page.navigate("/products");
  }

  @AfterEach
  void done(TestInfo info) {
    System.out.println("@AfterEach: " + info.getDisplayName() + " done");
  }

  @AfterAll
  static void atTheEnd() {
    System.out.println("@AfterAll: once at the end");
  }

  @Test
  @Order(1)
  void showsFiveProducts(Page page) {
    assertThat(page.getByRole(AriaRole.LISTITEM)).hasCount(5);
  }

  @Test
  @Order(2)
  void findsTheLamp(Page page) {
    page.getByPlaceholder("Search products").fill("lamp");
    assertThat(page.getByRole(AriaRole.LISTITEM)).hasCount(1);
  }
}

What happens

The once per file hook ran before the first test and after the last one. The each hooks wrapped every test, so both tests started on the products page without a goto of their own. In pytest the same thing is written as fixtures that yield: the code before yield is the set up, the code after it is the tear down.

🧩Fixtures: set up on demand

🧒 Beginner friendly

You can write your own. A signed in page is the classic first one.

A signed in page for every test that asks for it · ✅ mvn test ran
📄 src/test/java/com/brainy/SignedInTest.java
package com.brainy;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

// Every test class that extends this one starts signed in as Asha.
@UsePlaywright(ShopOptions.class)
public abstract class SignedInTest {
  @BeforeEach
  void signIn(Page page) {
    page.navigate("/login");
    page.getByLabel("Email").fill("asha@shop.example");
    page.getByLabel("Password").fill("s3cret");
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Sign in")).click();
    assertThat(page.getByText("Hello, Asha")).isVisible();
    System.out.println("set up: signed in");
  }

  @AfterEach
  void emptyCart(Page page) {
    page.request().delete("/api/cart");
    System.out.println("tear down: cart emptied");
  }
}

What happens

The test only says what it checks. Signing in happened in the fixture before it, and emptying the cart happened after it, even though the test never mentioned either. Any test that asks for the signed in page gets the same set up, and a test that does not ask for it pays nothing. Java has no custom fixtures in the same sense, so the common pattern is a base class with @BeforeEach and @AfterEach.

🏢
Hooks run for every test in the file. Fixtures run only for tests that ask for them, and they can depend on other fixtures. As a suite grows, teams move set up from hooks into fixtures.
Part 3

🛡️Automatic fixtures

An automatic fixture runs for every test without being asked. It is the right place for checks and recordings that every test should have, such as failing on JavaScript errors.

An automatic fixture that fails a test when the page throws an error · 💥 mvn test ran, fails on purpose
📄 src/test/java/com/brainy/NoPageErrorsTest.java
package com.brainy;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import java.util.ArrayList;
import java.util.List;

import static org.junit.jupiter.api.Assertions.assertEquals;

// Every test class that extends this one fails when its page throws an error.
@UsePlaywright(ShopOptions.class)
public abstract class NoPageErrorsTest {
  private final List<String> errors = new ArrayList<>();

  @BeforeEach
  void listen(Page page) {
    page.onPageError(error -> errors.add(error.split("\n")[0]));
  }

  @AfterEach
  void noErrors(Page page) {
    page.waitForTimeout(100);   // Java hands over browser events only while a Playwright call runs
    assertEquals(List.of(), errors, "the page threw errors");
  }
}

What happens

Neither test asked for the fixture, yet both got it. The products page had no errors and passed. The widgets test did everything right, but the page threw Price service is down, so the fixture failed it after the test body finished. pytest reports this as an error in the tear down, which still fails the run. The Java check calls page.waitForTimeout first, because the synchronous Java API delivers browser events only while a Playwright method is running.

  @Override
  public Options getOptions() {
    return new Options()
        .setHeadless(true)
        .setBaseUrl("http://localhost:4173")
        .setApiRequestOptions(new APIRequest.NewContextOptions().setBaseURL("http://localhost:4173"));
  }
}

What happens

The set up ran once, before the tests, and created one person through the API. In Playwright Test it is a project that the other projects depend on, so it shows up in the report and the trace like any test. pytest uses a session fixture, and JUnit a static @BeforeAll method. For a whole Maven run, JUnit also offers a LauncherSessionListener. Note ApiOptions in the Java version: setBaseUrl only covers pages, so the request fixture gets its own base URL through setApiRequestOptions.
