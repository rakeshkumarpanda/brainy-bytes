Part 1

📜Read the error first

🧒 Beginner friendly

Most failures explain themselves. Before you open any tool, read what the runner printed. A Playwright error has four parts, and you will find them in every language.

PartWhat it tells you
the locatorwhich element the check or action looked for
expected and receivedwhat the test wanted and what the page had, side by side
the timeouthow long Playwright kept trying before it gave up
the call logeach try: did the locator find an element, was it visible, enabled and stable, what did it contain

What happens

Every runner names the same four things: the locator it checked, the text it expected, the text it received and how long it kept trying. The difference is one exclamation mark. The call log underneath shows that the check found the element straight away and retried until the 5 s limit, so the element was there and only the text was wrong. Playwright Test also prints the source line with a marker under the failing call.

The error saysIt usually means
received a different text or countthe page changed, or the expected value in the test is out of date
element(s) not found, or waiting for locatorthe locator is wrong, a step before it did not happen, or the page did not load
strict mode violation, resolved to 2 elementsthe locator is too loose, so narrow it with a role, a name or a parent
element is not enabled, or is not visiblethe app has not finished something, such as loading data or validating a form
Test timeout of 30000ms exceededone call waited for something that never happened, and the call log names it
💡
Read the received value carefully. A missing full stop, an extra space or a different currency sign is the most common cause of a red check, and the error shows it to you directly.
Part 2

📸Screenshots, videos and traces on failure

A failure in CI happens on a machine you cannot watch. Turn on evidence so every failed test leaves behind what it saw. Keeping it only for failures saves disk space, because passing tests need none.

A screenshot, a video and a trace when a test fails · 💥 mvn test ran, fails on purpose
📄 src/test/java/com/brainy/EvidenceOptions.java
package com.brainy;

import com.microsoft.playwright.Browser;
import com.microsoft.playwright.junit.Options;
import com.microsoft.playwright.junit.OptionsFactory;

import java.nio.file.Paths;

public class EvidenceOptions implements OptionsFactory {
  @Override
  public Options getOptions() {
    return new Options()
        .setHeadless(true)
        .setBaseUrl("http://localhost:4173")
        .setTrace(Options.Trace.RETAIN_ON_FAILURE)          // keep the trace only when a test fails
        .setOutputDir(Paths.get("test-results"))
        .setContextOptions(new Browser.NewContextOptions()
            .setRecordVideoDir(Paths.get("videos")));       // a video of every test
  }
}

package com.brainy;

import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(EvidenceOptions.class)
public class CartTest {
  @BeforeEach
  void signIn(Page page) {
    page.navigate("/login");
    page.getByLabel("Email").fill("asha@shop.example");
    page.getByLabel("Password").fill("s3cret");
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Sign in")).click();
    assertThat(page.getByRole(AriaRole.LISTITEM)).hasCount(5);
  }

  @Test
  void addTheLampToTheCart(Page page) {
    page.getByTestId("product-3").getByRole(AriaRole.BUTTON, new Locator.GetByRoleOptions().setName("Add to cart")).click();
    assertThat(page.getByTestId("cart-count")).hasText("1");
  }

  @Test
  void addTheNotebookToTheCart(Page page) {
    // the Notebook is out of stock, so this button never appears
    page.getByTestId("product-4").getByRole(AriaRole.BUTTON, new Locator.GetByRoleOptions().setName("Add to cart"))
        .click(new Locator.ClickOptions().setTimeout(3000));
  }
}

What happens

The lamp test passed and left nothing behind. The notebook test failed, and its folder holds the evidence: a screenshot of the page at the moment of failure, a video of the whole test and a trace.zip to open in the trace viewer. pytest-playwright has the same three options as command line flags, so they sit in pytest.ini. The JUnit fixture keeps traces with setTrace, and records a video of every test, passed or failed, into the folder set by setRecordVideoDir. It has no screenshot on failure option.

SettingPlaywright Testpytest-playwrightJUnit fixture
screenshotscreenshot: 'only-on-failure'--screenshot only-on-failurenot built in, call page.screenshot() yourself
videovideo: 'retain-on-failure'--video retain-on-failuresetRecordVideoDir(...), every test
tracetrace: 'retain-on-failure'--tracing retain-on-failuresetTrace(Options.Trace.RETAIN_ON_FAILURE)
wheretest-results/test-results/setOutputDir(...)
other values'on', 'off', 'on-first-retry', 'retain-on-first-failure'on, offON, OFF
🏢
Teams often use trace: 'on-first-retry' in CI. A first run that fails is retried with tracing on, so the trace is recorded only for tests that failed at least once.
Part 3

🧭The trace viewer

A trace is a zip file with everything that happened in one test: each action, a copy of the page before and after it, the network calls, the console messages and the test source. The trace viewer plays it back. These screenshots come from the notebook test above.

Open a traceCommand

package com.brainy;

import com.microsoft.playwright.BrowserContext;
import com.microsoft.playwright.Locator;
import com.microsoft.playwright.Page;
import com.microsoft.playwright.Tracing;
import com.microsoft.playwright.junit.UsePlaywright;
import com.microsoft.playwright.options.AriaRole;
import org.junit.jupiter.api.Test;

import java.nio.file.Paths;

import static com.microsoft.playwright.assertions.PlaywrightAssertions.assertThat;

@UsePlaywright(ShopOptions.class)
public class MugTest {
  @Test
  void buyAMug(BrowserContext context, Page page) {
    context.tracing().start(new Tracing.StartOptions().setScreenshots(true).setSnapshots(true));

    context.tracing().group("sign in");
    page.navigate("/login");
    page.getByLabel("Email").fill("asha@shop.example");
    page.getByLabel("Password").fill("s3cret");
    page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Sign in")).click();
    assertThat(page.locator("#hello")).hasText("Hello, Asha");
    context.tracing().groupEnd();

    context.tracing().group("add the mug");
    page.getByTestId("product-2").getByRole(AriaRole.BUTTON, new Locator.GetByRoleOptions().setName("Add to cart")).click();
    assertThat(page.getByTestId("cart-count")).hasText("1");
    context.tracing().groupEnd();

    context.tracing().stop(new Tracing.StopOptions().setPath(Paths.get("traces/buy-a-mug.zip")));
  }
}

What happens

Each language saved a trace in which the actions sit under two names, sign in and add the mug, so a long test reads like a short list. Playwright Test does this with test.step, and the same steps also show up in the HTML report. In Python and Java the test starts and stops the trace itself with context.tracing, and tracing.group names the steps. Open any of the files with show-trace.

💡
Inside the trace viewer, click an action and then use the Before and After tabs to compare the page. The Pick locator button lets you try a new locator on the saved page.
Part 4

📊The HTML report and UI mode

Playwright Test writes an HTML report with every test, its steps, its errors and its evidence. It opens by itself after a failed local run, and npx playwright show-report opens it any time.

UI mode is a window for running and watching tests. You pick tests from a tree, run them, and step through each action with the same views as the trace viewer. It can also rerun tests when you save a file. Start it with npx playwright test --ui.

⚠️
UI mode, the HTML report and the VS Code extension are part of Playwright Test, so they are there for JavaScript and TypeScript. Python teams usually add pytest-html, and Java teams add Allure or ExtentReports. The reporting chapter builds each of them.
Part 5

🕵️Step through a test with the Inspector

When the evidence is not enough, run the test yourself and stop it at the line that fails. In debug mode Playwright opens a real browser and the Inspector, which shows the test source, highlights the current line and lets you step one action at a time. Debug mode also turns off timeouts, so you can take as long as you need.

Next to the toolbar is the locator field. Type a locator there and the matching elements light up in the browser, which is the quickest way to fix a locator that finds nothing or finds too much.

⚠️
Remove page.pause() before you commit. It needs a headed browser and is only useful while you debug.
Part 6

🧾Verbose logs

On a CI machine there is no window to open. The DEBUG environment variable makes Playwright print what every call does, in any language, so the CI log shows the last thing a stuck test was doing.

What happens

With DEBUG=pw:api, Playwright writes a line for each step inside every call: the navigation, the element a locator found, the fill and the check. In JavaScript and TypeScript the client adds a line when each call ends, with the time since the line before, so you can see where the test spent its time. Python and Java run the same driver, so they print the same steps. The full log also has a line for every wait inside a call, which we cut here to keep it short.

VariableWhat it prints
DEBUG=pw:apievery Playwright call and the steps inside it
DEBUG=pw:browserwhat the browser process prints, useful when it will not start
DEBUG=pw:protocolevery message between Playwright and the browser, very long
PWDEBUG=consolea playwright object in the browser DevTools, to try locators in the console
💡
Browser console messages and page errors are a different stream. Collect them with page.on("console") and page.on("pageerror"), as the fixtures chapter does, or read them in the Console tab of the trace.
