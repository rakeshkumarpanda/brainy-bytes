LVM: storage pools made of disks

A partition is fixed in size and stuck on one disk. The Logical Volume Manager (LVM) adds a layer in between, so volumes can grow, span several disks and move between them while they are in use.

LayerWhat it isMade withListed with

Volume group (VG)a pool of extents from one or more PVsvgcreate vgdata /dev/sdcvgs, vgdisplay
Logical volume (LV)a block device cut from the pool, used like a partitionlvcreate -n web -L 10G vgdatalvs, lvdisplay

The same volume has three names: /dev/vgdata/web and /dev/mapper/vgdata-web are links to the device-mapper device /dev/dm-0, which has the major number 253. In the Attr column, w means writable, i means inherited allocation, a means active, and an o appears once the volume is open, for example mounted.
With plain partitions, every file system is stuck inside one fixed piece of one disk. L V M, the logical volume manager, adds a flexible layer. First you turn disks or partitions into physical volumes with p v create. L V M cuts each one into small extents of four mebibytes. Then you collect physical volumes into a volume group, a pool of extents, with v g create. Finally you cut logical volumes out of the pool with l v create, giving a name and a size. A logical volume behaves like a partition: you make a file system on it and mount it. The commands p v s, v g s and l v s list each layer. The -r option calls resize2fs (through fsadm) after the volume has grown, and ext4 grows while mounted. Without -r you must run resize2fs, or xfs_growfs for xfs, yourself.
Replace an old disk without downtime
  1. Add the new disk to the pool: sudo vgextend vgdata /dev/sde.
  2. Move every extent off the old disk while the volumes stay mounted: sudo pvmove /dev/sdc.
  3. Take the empty disk out of the pool: sudo vgreduce vgdata /dev/sdc.
  4. Remove its LVM label with sudo pvremove /dev/sdc, then take it out of the machine.
Remember
A snapshot made with lvcreate -s freezes a volume at one moment, so a backup can copy a consistent state while the original keeps changing. Only changed blocks use space in the snapshot, and a classic snapshot becomes invalid when that space (-L) fills up, so remove it after the backup. Thin pools (lvmthin) allow cheaper snapshots and overcommitted volumes.
The big win of L V M is growing storage without downtime. When a volume is almost full and the pool still has free extents, one command does it all: l v extend dash r dash capital L plus five G grows the volume by five gibibytes, and dash r grows the file system on it too, while it stays mounted. When the pool itself is full, add a new disk with v g extend, and grow again. To replace an old disk, add the new one, move all data off the old one with p v move while everything keeps running, then remove the empty disk from the group. Snapshots freeze a volume at one moment, which lets a backup copy a consistent state. Remember one danger: a volume spread over two disks without RAID is lost if either disk dies.

RAID: surviving a broken disk

RAID (redundant array of independent disks) combines several disks so the data survives when one fails, or so it is faster. On Linux, mdadm builds software RAID arrays such as /dev/md0, and the kernel reports their state in /proc/mdstat.

LevelHow it worksUsable space with n disks of size sDisks that may fail
RAID 0stripes data across the disks for speedn × snone: one failure loses everything
RAID 1mirrors: every disk holds the same datasall but one
RAID 5stripes with one parity block per stripe (at least 3 disks)(n − 1) × sone
RAID 6stripes with two parity blocks (at least 4 disks)(n − 2) × stwo
RAID 10stripes over mirrored pairs (at least 4 disks)n × s ÷ 2one in each pair
RAID 5 usable = (n − 1) × s, RAID 6 usable = (n − 2) × s

A degraded mirror shows [2/1] [U_], and a failed member is marked (F). The first resync copies one disk onto the other in the background, and the array can be used meanwhile.
Replace a failed disk in /dev/md0
  1. Find the failed member in cat /proc/mdstat or sudo mdadm --detail /dev/md0.
  2. Mark it failed if the kernel has not, and remove it: sudo mdadm /dev/md0 --fail /dev/sdd1 --remove /dev/sdd1.
  3. Fit the new disk and copy the partition table from the good disk, for example sudo sfdisk -d /dev/sdc | sudo sfdisk /dev/sdd.
  4. Add the new partition: sudo mdadm /dev/md0 --add /dev/sdd1, and watch the rebuild in /proc/mdstat.
  5. Save the array in the config with sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf and run sudo update-initramfs -u once, after creating an array.
Common mistake
RAID is not a backup. A mirror copies a deleted file, a ransomware encryption or a broken update to every disk at once. RAID keeps a server running when a disk dies, and backups bring back data that is gone.
Disks fail, and RAID keeps the data alive when one of them does. RAID zero only stripes data over disks for speed, so one broken disk loses everything. RAID one mirrors, every disk holds the same data, so you keep the space of one disk and can lose all but one. RAID five spreads one parity block over each stripe and survives one failed disk, and RAID six keeps two parity blocks and survives two. RAID ten mirrors pairs and stripes across them, fast and safe but using half the space. On Linux, m d a d m builds software arrays, and slash proc slash m d stat shows their state: U for a working disk, an underscore for a missing one. When a disk fails, remove it, add the new one, and the array rebuilds. But RAID is never a backup, because a deleted file is deleted on every disk.

Swap: room for memory pages on disk

When RAM runs short, the kernel can move memory pages that have not been used for a while to swap space on disk, and bring them back when they are needed. Swap can be a partition or a file. It is far slower than RAM, so it is a safety net, not extra memory. Hibernation also writes RAM into swap.

mkswap keeps the first 4 KiB page for its header, so 256 MiB of file gives 268431360 bytes of swap. The priority -2 was chosen by the kernel, because the swap area had none set. swapoff moves any swapped pages back into RAM before it lets go. A swappiness of 60 is the kernel default.
Common mistake
Without chmod 600, mkswap warns about insecure permissions, because any user could read memory contents of other programs from the file. A file with holes (made by truncate) can be rejected by swapon, so use fallocate or dd.
Swap is disk space the kernel uses when memory runs short. Pages of memory that have not been used for a while move out to swap, which frees RAM for programs that need it now. Swap is far slower than RAM, so a machine that swaps all the time is too small for its work, but a bit of swap keeps it from crashing when memory is tight. You can use a partition or a simple file. For a file, create it with f allocate, make it readable only by root with chmod six hundred, write the swap signature with m k swap, and switch it on with swap on. Swap on dash dash show lists the active areas, and free shows how much is used. Add a line to f s tab to keep it after a reboot. The setting swappiness, sixty by default, controls how eagerly the kernel swaps.

Backups with tar and rsync

A backup is a copy you can restore after a mistake, a broken disk, ransomware or a fire. The 3-2-1 rule: keep 3 copies of the data, on 2 different kinds of storage, with 1 copy in another place. A backup you have never restored is only a hope, so test restores.

KindWhat it copiesRestore needs
Fulleverything, every timethe one full backup
Incrementalwhat changed since the last backup of any kindthe full backup and every incremental after it, in order
Differentialwhat changed since the last full backupthe full backup and the newest differential
Snapshot (rsync --link-dest)a complete folder tree each day, unchanged files are hard linksjust copy the folder of that day back

Backups protect you from deleted files, broken disks, ransomware and even fire. Follow the three two one rule: three copies of your data, on two kinds of storage, and one copy somewhere else. A full backup copies everything. An incremental backup copies only what changed since the last backup, which saves space but needs every piece in order to restore. Tar with dash dash listed incremental makes both kinds, using a small snapshot file to remember what it saved. Rsync copies only the differences between two folders, locally or over s s h, and dash dash delete makes the copy an exact mirror, so test it with dash dash dry run first. With dash dash link dest, each day becomes a complete folder, but unchanged files are hard links that use no extra space. Tools such as restic and borg add encryption and deduplication. Most important of all, practise restoring, because an untested backup may not work when you need it.

Practice: grow storage with LVM and add swap

The web server needs a volume that can grow, and more swap. The practice server has two empty disks, /dev/sdc (20 GB) and /dev/sdd (10 GB).

Now build flexible storage yourself. Turn the twenty gigabyte disk into a physical volume, make a volume group called v g data from it, and cut a fifteen gibibyte logical volume called web. Format it with ext4, create the folder slash s r v slash web, and mount it. Then the web site grows, so add the second disk to the group with v g extend, and grow the volume by eight gibibytes with l v extend dash r, which grows the file system too. Df shows the new size. Finally, add a one gibibyte swap file: create it with f allocate, protect it with chmod six hundred, write the swap signature and switch it on. Free shows three gibibytes of swap, the two the server already had plus your new file.
Lesson 7 of 7

Storage safety from school to research

One idea, four depths

Keep important files in more than one place, for example on a laptop and on a USB disk or a cloud drive, and check now and then that you can open the copies.

Use LVM for volumes that will grow, RAID 1 or RAID 10 on servers that must survive a disk failure, a swap file sized to the workload, and automatic backups with rsync, restic or borg on a timer. Watch /proc/mdstat and SMART health, and test a restore every few months.

Snapshots (LVM, btrfs, ZFS) give consistent backups of running systems. ZFS and btrfs join volume management, RAID and checksums in one file system, so they detect silent corruption. Cloud setups use replicated block storage, object storage with versioning and object lock against ransomware, and off-site copies in another region. Recovery time objective (RTO) and recovery point objective (RPO) set how fast and how recent a restore must be.

Research on large disk fleets studies failure rates, latent sector errors and silent data corruption, and erasure codes such as Reed-Solomon, used in big storage systems, keep data safe with far less extra space than mirroring. Deduplication research shapes tools like borg and restic, which split data into content-defined chunks so a small change only stores a small new piece.

Real world scenario: the RAID that was mistaken for a backup

A small company kept its files on a RAID 1 server and saw no need for backups. Ransomware encrypted the shared folder, and the mirror copied every encrypted block to the second disk within seconds. Both disks were healthy and the data was gone. The new setup kept RAID 1 for uptime, added nightly restic snapshots to a disk that is only mounted during the backup, and a weekly copy to object storage with object lock, following the 3-2-1 rule. The first restore test found that the database needed pg_dump instead of a file copy.

Here is how storage safety grows with experience. At school, keep important files in two places and check that the copies open. Professionals use L V M so volumes can grow, RAID so a server survives a broken disk, and automatic backups on a timer, and they test restores regularly. Larger systems use snapshots for consistent backups, file systems like Z F S and B T R F S that check every block for silent corruption, and off-site copies with object lock that ransomware cannot delete. They plan how fast and how recent a restore must be. Researchers study how disks fail across huge fleets, and use erasure codes and deduplication to keep data safe with less space.
