nano: the friendly editor

Servers usually have no mouse and no windows, so you edit configuration files right inside the terminal. nano is the easiest editor to start with: you type and the text appears, and the main commands are listed at the bottom of the screen. In that list ^ means the Ctrl key and M- means the Alt key.

Edit a file with nano
  1. Open it: nano notes.txt.
  2. Move with the arrow keys and type your change.
  3. Press Ctrl+O, check the file name at the bottom, press Enter.
  4. Press Ctrl+X to leave.
If you have never edited a file in a terminal, start with nano. It works like a basic notepad. You open a file, move with the arrow keys, type, and the text appears. The only new thing is that commands use the Control key, and nano lists them at the bottom of the screen, where a small hat symbol means Control. Control O writes the file to disk, which nano calls write out. Control X exits, and if you forgot to save, nano asks you first. Control K cuts a whole line and Control U pastes it back, which is the quickest way to move lines around. nano began in 1999 as a free copy of an older editor called Pico, and today it is installed by default on Ubuntu and many other distributions, so it is a safe choice on almost any server you log into.

vim: the editor with modes

vim (Vi IMproved) is on nearly every Unix system, often also as vi. It looks strange at first because it has modes. In Normal mode every key is a command: j moves down, dd deletes a line. In Insert mode keys type text. You switch between them all the time, and once your fingers know the keys, editing becomes very fast.

Stuck in vim with keys doing strange things? Press Esc two times, then type :q! and Enter to leave without saving. Run vimtutor for a free 30 minute lesson inside vim itself.
Going deeper: Why vim keys combine like words

Most Normal mode commands are an operator followed by a motion. d is delete, c is change, y is yank. w is a word, $ is the end of the line, G is the end of the file. So dw deletes a word, d$ deletes to the end of the line, yG copies everything to the end of the file and cw changes a word. A number repeats: 3dd deletes three lines. Once you know 5 operators and 10 motions you have 50 commands without learning each one.

vim is famous for being hard to quit. A question on Stack Overflow called how do I exit the vim editor has been viewed millions of times. The reason is modes. When vim opens, it is in Normal mode, where letters are commands, not text. Press i to enter Insert mode and type normally. Press Escape to go back. To save and quit, type colon w q and press Enter. To quit and throw away changes, type colon q exclamation mark. The original vi was written by Bill Joy at Berkeley in 1976, for slow terminals where every keystroke mattered. Bram Moolenaar released vim in 1991 and looked after it for over thirty years. Why learn it? Because vi or vim is present on almost every Unix machine, even tiny rescue systems, and because its keys work like a small language. d means delete and w means word, so d w deletes a word.

Choosing an editor and editing without one

Programs such as crontab -e, git commit and visudo open an editor for you. They look at the VISUAL and EDITOR variables to decide which one. On Debian and Ubuntu, select-editor asks you once and remembers the answer.

CommandWhat it doesExample
export EDITOR=nanoUse nano from now on in this shell (add it to ~/.bashrc to keep it)export EDITOR=vim
select-editorDebian and Ubuntu: pick your editor from a numbered listselect-editor
sudoedit FILEEdit a root owned file safely: your editor works on a copy, sudo writes it backsudoedit /etc/hosts

>> adds a line at the end of a file, and cat with a here document writes several lines at once. Both are explained fully in Shell Power Tools. The vim line runs vim with no screen: it replaces milk with oat milk and saves, which is handy in scripts.
Common mistake
Never edit /etc/sudoers with a normal editor. Use visudo, which checks the file before saving. A typing mistake in that file can stop sudo working for everyone.
Some commands open an editor on their own. When you run crontab dash e to schedule a job, or git commit without a message, the program needs to know which editor you like. It checks a variable called VISUAL, then one called EDITOR, and falls back to a default, often nano or vi. Set EDITOR in your bashrc file and every program follows your choice. Also remember that many small edits need no editor at all. Two arrows add a line to the end of a file. cat with a here document writes several lines at once. Even vim can be told to make a change and save without showing a screen, which is useful in scripts. And for the system file that controls sudo, always use visudo, because it refuses to save a broken file that could lock everyone out.
Lesson 4 of 4

Editors from school to research

One idea, four depths

nano is the easy editor: type, Ctrl+O to save, Ctrl+X to exit. vim has modes: i to type, Esc to stop typing, :wq to save and quit, :q! to quit without saving.

Terminal editors read the file into a buffer, let you change it, and write the buffer back on save. vim is modal and composes operators (d, c, y) with motions (w, $, G, text objects such as iw). Programs pick an editor from VISUAL, then EDITOR, and Debian also offers the sensible-editor command.

Editors draw the screen through terminal escape codes described by the terminfo database (TERM). Safe saving writes a new file and renames it over the old one, or writes in place with a backup, which vim controls with the backupcopy option. vim keeps a swap file (.notes.txt.swp) so a crash or a lost SSH connection does not lose work, and warns when another vim already edits the same file.

Text editors are a research subject in human computer interaction, from studies of modal versus modeless editing (Larry Tesler argued against modes at Xerox PARC in the 1970s) to the data structures that hold the text, such as gap buffers, piece tables and ropes, and to CRDTs that let several people edit the same file at once without a central server.

Real world scenario: the lost SSH session

An admin edits /etc/nginx/nginx.conf in vim over a slow connection and the session drops. On logging back in, vim says a swap file .nginx.conf.swp exists. Pressing R recovers the unsaved changes, and after checking them the admin deletes the swap file. nano saves a similar emergency copy named nginx.conf.save.

Under the surface, an editor is a program that loads a file into memory, lets you change that copy, and writes it back when you save. The screen is drawn with special character codes that the terminal understands, and the TERM variable tells the editor which codes to use. vim protects you with a swap file. If your connection drops in the middle of editing, the swap file still holds your changes, and vim offers to recover them the next time you open the file. Researchers have studied editors for decades. Larry Tesler at Xerox famously argued that modes confuse people, while vim users argue that modes make editing faster once learned. Inside, editors use clever structures such as piece tables and ropes to change large files quickly, and modern collaborative editors use special data types called CRDTs so many people can type in the same document at once.
