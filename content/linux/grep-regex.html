Finding lines: grep

grep PATTERN FILE prints every line of FILE that contains PATTERN. With no file it reads stdin, so it fits at the end of any pipeline. The name comes from the old ed editor command g/re/p: globally search for a regular expression and print.

Remember
Put the pattern in single quotes. Then the shell leaves * ? $ and spaces alone and grep receives exactly what you typed.
grep is the command engineers type more than almost any other. It reads lines and prints the ones that match a pattern. The name is a fossil from the earliest Unix editor, called ed, where the command g slash r e slash p meant search globally for a regular expression and print. Ken Thompson turned that editor command into a separate program in 1973, and it has been on every Unix system since. The basic use is simple: grep ERROR followed by a log file shows only the error lines. Options make it sharper. Dash i ignores case, dash v shows lines that do not match, dash c counts, dash n numbers the lines and dash r searches a whole folder tree. Dash A and dash B show a few lines after or before each match, which is perfect for seeing what happened just before an error.

Regular expressions: the basic building blocks

A regular expression (regex) is a pattern that describes text. Most characters match themselves, and a few have special meanings.

.Exam favourite
any one character
h.t matches hat, hot and h9t.
*
the item before, 0 or more times
lo*l matches ll, lol and loooool.
^ and $Exam favourite
start and end of the line
^ERROR matches lines that begin with ERROR. ^$ matches empty lines.
[abc] [a-z] [^0-9]
one character from a set
[aeiou] any vowel. [^0-9] any character that is not a digit.
[[:digit:]] [[:alpha:]] [[:space:]]
named classes
Work the same in every language setting.
backslash
make a special character plain
A backslash before a dot makes it a real dot, so the pattern 1 backslash dot 5 matches 1.5 but not 125.

^$ counts empty lines (there are none in poem.txt). The last command prints only the "30s" at the end of the timeout line.
Common mistake
A regex star is not the shell star. In a file pattern *.txt means "anything". In a regex * means "repeat the item before it", so .* is the regex for "anything".
Regular expressions are a tiny language for describing text, and they are worth learning once, because grep, sed, awk, vim, Python, JavaScript and almost every editor understand them. The idea comes from mathematics. In the nineteen fifties Stephen Kleene described patterns with a star meaning repeat, and in 1968 Ken Thompson published a way to search text with them on a computer. The basics are few. A dot means any one character. A star means repeat the thing before me zero or more times. A hat at the start ties the match to the beginning of the line, and a dollar at the end ties it to the end. Square brackets list a set of allowed characters, such as zero to nine for any digit. One warning: the regex star is not the same as the shell star you met with file names. In a regex, dot star is how you say anything at all.

Extended regular expressions: grep -E

With grep -E (extended syntax) a few more symbols become special, which makes patterns shorter and easier to read. In plain grep the same features exist, but need a backslash in front: \+ \? \| \( \) \{ \}.

Going deeper: Greedy matching and grep -P

Repetition is greedy: a.*b on "a1b2b" matches the whole "a1b2b", not just "a1b". GNU grep also offers grep -P for Perl compatible expressions with extras such as \d for a digit, lazy repeats like .*? and look ahead. It is very common in scripts written by Python and JavaScript programmers, but it is not part of POSIX and may be missing on other systems.

Extended regular expressions add a handful of symbols that make patterns much shorter. Plus means one or more, question mark means optional, curly braces give an exact number of repeats, a vertical bar means or, and round brackets group things together. With grep dash E these symbols work directly. In plain grep they exist too, but you must put a backslash in front of each one, which quickly becomes hard to read. So most people simply use grep dash E. With these tools you can describe a date, a time, an order number or an email address in one pattern. For example, four digits, a dash, two digits, a dash, two digits matches a date like the ones in our log file. When you see a long pattern, do not panic. Read it piece by piece from left to right, exactly as the animation in this lesson does.
Lesson 4 of 4

grep and regex from school to research

One idea, four depths

grep finds lines that contain a pattern. A dot means any character, a star means repeat, ^ is the start of the line and $ the end. grep -E adds + ? | and braces for counts.

POSIX defines basic (BRE) and extended (ERE) regular expressions. grep selects lines matching any of its patterns, with options for inversion, counting, context and recursion. Matching uses leftmost longest semantics for ERE in POSIX, while Perl style engines use leftmost first with backtracking.

Regular expressions without back references describe regular languages and can be matched by finite automata in time linear in the input. Thompson built an NFA in 1968. GNU grep compiles patterns to a DFA, skips quickly to candidate lines with a Boyer and Moore style search for fixed strings, and avoids splitting input into lines until a match is found. Back references (\1) are not regular and force a slower backtracking matcher.

Backtracking engines can take exponential time on patterns like (a+)+$, which caused real outages, for example the Stack Overflow outage of July 2016 and a Cloudflare outage in July 2019 (ReDoS, regular expression denial of service). Research and modern engines such as RE2 and Rust regex guarantee linear time, and tools such as ripgrep combine them with SIMD string search and parallel directory walking.

Real world scenario: the 2019 regex outage

On 2 July 2019 a single new firewall rule containing the regex fragment .*(?:.*=.*) made CPUs on Cloudflare servers worldwide hit 100 percent, and sites behind it returned errors for about 27 minutes. The pattern caused heavy backtracking. Cloudflare later moved its rules to engines that guarantee linear time. Simple patterns and engines like GNU grep or RE2 avoid this class of bug.

Inside, a regular expression is turned into a small machine called a finite automaton, which reads the text one character at a time and never has to go back. Ken Thompson described how to build such a machine in 1968, and GNU grep still uses this approach, together with clever tricks to jump quickly over text that cannot match. That is why grep can search gigabytes in seconds. Some regex engines in programming languages work differently. They try one possibility, and if it fails, go back and try another. For most patterns that is fine, but certain patterns make them try an enormous number of possibilities. In July 2019, one such pattern in a firewall rule pushed Cloudflare servers around the world to full processor load for about twenty seven minutes. Modern engines such as RE2 and the Rust regex library are designed so this cannot happen.
