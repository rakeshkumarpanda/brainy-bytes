Lesson 1 of 5

tar: many files in, one archive out

An archive is one file that holds many files and folders, with their names, permissions, owners and times. tar (short for tape archive, from Unix Version 7 in 1979) is the standard archiver on Linux. On its own it only glues files together, it does not make them smaller.

CommandWhat it doesExample

--sort=name makes the order stable, without it tar uses the order the file system returns. The archive is 10240 bytes even though the two logs hold under 400 bytes, the next lesson explains why. Asking for a member that is not inside gives exit status 2.
Common mistake
The f option takes the next word as the archive name, so keep f last in a bundle: tar -cvf out.tar works, tar -cfv out.tar makes an archive called v. The dash is optional for the first bundle, so tar cvf is the same as tar -cvf.
tar takes many files and folders and writes them into a single file called an archive, keeping each name, permission, owner and time. The three main modes are dash c to create, dash t to list the table of contents and dash x to extract. Dash v makes tar print each name as it works, and dash f tells tar which archive file to use. Keep the f last in the bundle of letters, because the word after it is taken as the file name. When you extract, tar writes into the current folder unless you give dash capital C with another folder. A good habit is to list an archive with dash t before extracting it, so you know whether it unpacks into a tidy folder or spills hundreds of files into your current one. The name tar comes from tape archive, because it was first used to write backups to magnetic tape, and its file format still reflects that history.

Compression: gzip, bzip2, xz and zstd

A compressor rewrites a file so repeated patterns take less space. It works on one stream of bytes, so to compress a folder you first tar it and then compress the tar. tar can call the compressor for you with one letter.

ToolSuffixtar letterSpeed and size
gzip.gz, .tgz-zfast, good, available everywhere (DEFLATE, RFC 1951)
bzip2.bz2-jslower, a bit smaller than gzip (Burrows-Wheeler blocks of 900 kB)
xz.xz-Jslowest to pack, smallest, quick to unpack (LZMA2)
zstd.zst--zstdvery fast at both ends, size close to xz at high levels
CommandWhat it doesExample
gzip FILEReplace FILE with FILE.gzgzip access.log
gzip -k FILEKeep the original toogzip -k report.csv
gunzip FILE.gzDecompress (same as gzip -d)gunzip access.log.gz
zcat FILE.gzPrint the decompressed text, file untouchedzcat access.log.gz | grep ERROR
gzip -l FILE.gzShow compressed and original sizesgzip -l backup.tar.gz
gzip -t FILE.gzTest that the file is not damagedgzip -t backup.tar.gz
gzip -9 FILEBest compression (-1 fastest, -6 default)gzip -9 big.sql
xz -T0 FILExz using every CPU corexz -T0 -k dump.sql

Remember
Text, logs and databases compress very well, often to a fifth of their size or less. Photos (JPEG), videos and zip files are already compressed and hardly shrink, so do not waste CPU on them.
Compression finds patterns that repeat and stores them only once. The classic tool on Linux is gzip, from nineteen ninety two, which uses the DEFLATE method, the same one inside zip files and PNG images. bzip2 usually gives smaller files but is slower. xz is slower still when packing but gives the smallest files and unpacks quickly, which is why the Linux kernel source is published as tar dot xz. zstd, made at Facebook in twenty sixteen, is very fast in both directions and is now used by many distributions for their packages. Each of these tools works on a single stream of bytes, so to compress a folder you combine them with tar. tar can call the compressor for you: dash z for gzip, dash j for bzip2 and capital J for xz. When extracting, GNU tar looks at the file and picks the right tool on its own, so tar dash x f works for all of them. By default gzip replaces the original file, so add dash k to keep it.
Lesson 3 of 5

zip and unzip: the format everyone can open

A zip file is an archive and a compressor in one. Each file inside is compressed on its own, and a table at the end of the file lists every member, so one file can be extracted without reading the rest. Windows and macOS open zip files with no extra software, which makes zip the right choice when you send files to people who do not use Linux.

Common mistake
unzip asks before replacing an existing file. In a script, use -o to overwrite or -n to never overwrite, so it does not stop and wait for an answer.
Zip is both an archive and a compressor in one format. It was created by Phil Katz in nineteen eighty nine, and today every operating system opens zip files without extra software. That makes zip the polite choice when you send files to Windows or Mac users. Inside a zip file each member is compressed on its own, and a central directory at the end of the file lists all of them, so a program can pull out a single file quickly. tar dot gz compresses everything as one stream, which usually gives a smaller result but means reading from the start to reach the last file. Use zip dash r to include folders, unzip dash l to look inside and unzip dash d to choose where the files go. The password option of zip uses an old method that can be broken easily, so do not rely on it for real secrets.

Real backups: pipes, ssh, increments and safety

Because tar can read and write standard input and output with -f -, it fits into pipelines. That is how administrators copy whole folder trees between machines, or stream a backup without a temporary file.

CommandWhat it doesExample
tar -czf - DIR | ssh HOST "cat > DIR.tgz"Stream a backup to another machinetar -czf - site | ssh backup@vault 'cat > site.tgz'
ssh HOST "tar -czf - DIR" | tar -xzf -Pull a folder from a server and unpack it heressh web1 'tar -czf - /etc/nginx' | tar -xzf -
tar -cf - DIR | tar -xf - -C DESTCopy a tree and keep every permission and timetar -cf - project | tar -xf - -C /mnt/usb
tar -xf NAME.tar --strip-components=1Drop the top folder of each member when extractingtar -xf app-2.1.tar.gz --strip-components=1
tar -g snap.file -czf FULL.tgz DIRIncremental: the next run with the same snap file stores only changestar -g home.snar -czf mon.tgz /home
sha256sum NAME.tar.gzFingerprint the archive to check it latersha256sum backup.tar.gz > backup.sha256

The first tar writes a compressed stream to its standard output and the second reads it from standard input. --strip-components=1 removed the logs/ prefix, so the files landed straight inside flat.
A backup you can trust
  1. Archive with paths relative to a known folder, for example tar -czf home.tgz -C / home, so restores land where you expect.
  2. Run tar -tzf on the result (or gzip -t) to prove the file is readable.
  3. Store a sha256sum next to it and check it after every copy.
  4. Keep at least one copy on another machine or disk. A backup on the same disk dies with it.
  5. Practise a restore into an empty folder. A backup that was never restored is only a hope.
Real backups use a few extra tricks. Writing dash f dash, a single dash as the file name, makes tar write to standard output or read from standard input, so you can pipe an archive straight into ssh and store it on another machine without a temporary file. The same trick copies a folder tree with every permission and time kept, by piping one tar into another. Dash dash strip components drops the top folder of each path while extracting, which is handy for downloads that unpack into a folder named after the version. GNU tar can also make incremental backups with dash g and a snapshot file, so each new run stores only what changed since the last one. Whatever you do, check your archives. List them with dash t, keep a sha two five six checksum beside them, keep a copy on another disk, and practise restoring, because a backup that was never restored is only a hope.
Lesson 5 of 5

Archives and compression from school to research

One idea, four depths

tar puts many files into one. gzip, xz and zip make files smaller by storing repeated parts only once. Always look inside an archive before unpacking it.

A tar file is a sequence of 512 byte blocks: a header block per member (name, mode, owner, size, time, checksum) followed by its data padded to whole blocks, then two zero blocks. GNU tar writes in records of 20 blocks, 10240 bytes. DEFLATE combines LZ77 back references (a 32 KiB window) with Huffman codes. xz uses LZMA2 with windows of many megabytes, which is why it compresses better and needs more memory.

The POSIX pax format (ustar plus extended headers) removes the old 100 character name and 8 GiB size limits, and GNU tar can write it with --format=pax. Compressed tarballs are not seekable, so extracting the last member reads the whole stream, while zip seeks through its central directory. zstd adds long range matching and trained dictionaries that compress many tiny similar files (such as JSON records) far better than any general method. Reproducible builds need stable archives: --sort=name, --mtime and --owner=0 --group=0 --numeric-owner give byte identical tarballs.

Compression research balances ratio, speed and memory. Asymmetric numeral systems (ANS, Jarek Duda, 2009) give entropy coding as tight as arithmetic coding at the speed of Huffman, and power zstd and Apple LZFSE. Neural compressors using learned probability models now beat classic tools on text and images but are far too slow for daily use. Supply chain security joined the field in 2024 when CVE-2024-3094 showed a backdoor hidden in the build scripts of xz-utils 5.6.0 and 5.6.1, caught by Andres Freund through a half second slowdown in ssh logins.

Real world scenario: the 4 a.m. restore

A developer deletes a customer table by mistake. The nightly job has run pg_dump shop | zstd -T0 > /backup/shop-2026-11-22.sql.zst and copied it to another region, with a sha256 file beside it. The on-call engineer checks the checksum, runs zstd -dc shop-2026-11-22.sql.zst | psql shop_restore into a fresh database, copies the missing rows back, and the shop is fixed before customers wake up.

Inside, a tar file is simple. Each member gets a five hundred and twelve byte header block holding its name, size, permissions, owner and time, followed by its data rounded up to whole blocks, and two empty blocks mark the end. GNU tar writes whole records of ten thousand two hundred and forty bytes, which is why a tiny archive is still ten kilobytes before compression. gzip uses DEFLATE, which replaces repeated text with short references back to an earlier copy, then codes the result with Huffman codes, giving short codes to common symbols. xz looks much further back, many megabytes, so it finds more repeats and makes smaller files. Modern tools such as zstd use a newer coding method called asymmetric numeral systems, which is both tight and fast. Compression even became a security story in twenty twenty four, when an engineer at Microsoft noticed ssh logins were half a second slower and uncovered a backdoor hidden in the xz library. That event changed how open source projects review their build scripts.
