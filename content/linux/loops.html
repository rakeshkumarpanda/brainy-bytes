for loops: one pass per item

A for loop runs its body once for every word in a list. bash builds the whole list first, using all the usual expansions, and then sets the loop variable to each word in turn.

Two kinds of for loopThe general form
for NAME in WORD1 WORD2 ...; do
  ...                  # $NAME is each word in turn
done

for (( INIT; TEST; STEP )); do
  ...                  # runs while TEST is not 0
done

Common mistake
Do not loop over $(ls) or $(cat file). File names with spaces are split into pieces. Use a glob for files and while read for lines.
A for loop repeats its body once for every item in a list. Bash builds the list first with all the usual expansions, so you can give plain words, a wildcard pattern that becomes file names, a brace range such as one dot dot ten, or dollar at sign in quotes for every argument of the script. Then the loop variable takes each item in turn, and the body between do and done runs once per item. There is also a second form borrowed from the C language, with double parentheses and three parts: a start, a test and a step, which is handy for counting. One surprise: if a pattern such as star dot x y z matches no file, bash keeps the pattern as plain text and the loop runs once with it. The nullglob option fixes that by removing patterns that match nothing. Try the animation with your own list and body to watch every pass.

while and until, and reading files line by line

while repeats as long as its condition command succeeds. until repeats as long as it fails. The most common use of while is reading input one line at a time.

CommandWhat it doesExample
while CMD; do ...; doneRepeat while CMD exits with 0while (( n < 5 )); do ...; done

IFS= keeps leading spaces and -r keeps backslashes, so each line arrives exactly as written. The header line of marks.csv was skipped with continue. After the pipe the count was still 0, because every part of a pipeline runs in its own subshell and its variables are lost. Process substitution kept the loop in the current shell.
Remember
The last line of a file without a final newline is still read into the variable, but read returns 1, so the loop skips it. Write while IFS= read -r line || [ -n "$line" ] to keep it.
A while loop keeps going as long as its condition command succeeds. Until is the mirror image: it keeps going as long as the command fails, which reads nicely for waiting, such as until the server answers. The most important pattern of all is reading a file line by line. Write while I F S equals nothing, read dash r line, and put the file after done with a less than sign. The empty IFS keeps spaces at the start of the line, and dash r keeps backslashes as they are. To split each line into fields, set IFS to a comma and give read several variable names, which turns a CSV file into variables in one step. One famous trap: if you pipe into a while loop, the loop runs in a subshell, so counters you change inside are lost when it ends. Feed the loop with a less than sign and process substitution instead, and the variables survive.

break, continue and whole-loop redirection

CommandEffect
breakleave the loop now, continue after done

select prints the menu to stderr, shows PS3 as the prompt and reads a number. An invalid number leaves the variable empty.
Two small commands give you full control inside a loop. Break leaves the loop at once and carries on after done. Continue skips the rest of the current pass and jumps to the next one. In nested loops, add a number: break two leaves both loops, and continue two moves straight to the next pass of the outer loop. You can also treat the whole loop as one command. Put a greater than sign and a file name after done, and the output of every pass goes into that file, which is opened only once. Or pipe the whole loop into sort. For file names that may contain spaces or even new lines, the safe pattern is find with dash print zero, read with dash d and an empty delimiter, and an empty IFS. Finally, select builds a numbered menu for interactive scripts and keeps asking until you break out.
Lesson 4 of 4

Loops from school to research

One idea, four depths

A loop repeats work. for goes through a list of items, while keeps going while something is true, and until keeps going until it becomes true. break stops a loop and continue skips to the next round.

The for list is expanded once, before the first pass, so changing a variable inside the loop does not change the list. while runs its condition before every pass. Each part of a pipeline runs in a subshell, so variables set in cmd | while read are lost, while done < file and done < <(cmd) keep the loop in the current shell.

Shell loops start a new process for every external command inside them, so a loop over a million lines that calls sed or cut each time is slow. Move the whole job into awk, or use parameter expansion and builtins inside the loop. read is slow too, since it reads one byte at a time from a pipe to avoid reading past the newline. mapfile -t arr < file reads all lines into an array in one step. shopt -s lastpipe (with job control off, as in scripts) runs the last part of a pipeline in the current shell.

Studies of shell scripts in package repositories and CI pipelines find that loops over unquoted command output and word-split file names are common sources of bugs, which tools such as ShellCheck flag (SC2045 for looping over ls, SC2013 for reading lines with for). Research systems such as PaSh (EuroSys 2021) parallelise data-parallel shell pipelines automatically, and GNU parallel and xargs -P run loop bodies on many cores.

Real world scenario: the nightly image resize

A photo site resizes every new upload at night. The first script was for f in $(ls uploads) and failed on names with spaces. The fixed script uses for f in uploads/*.jpg with nullglob, skips files that already have a thumbnail with [ -e "thumbs/${f##*/}" ] && continue, and logs each pass with done >> resize.log. Later the team replaced the loop body with find uploads -name "*.jpg" -print0 | xargs -0 -P 4 to use four cores.

Here is what experienced script writers know about loops. The list of a for loop is built only once, before the first pass. While checks its condition before every pass. A pipe into while puts the loop in a subshell, which is why counters vanish, and redirecting a file or process substitution into done avoids it. Speed matters too. Every external command inside a loop starts a new process, so calling sed or cut a million times is slow. It is far faster to hand the whole file to awk, or to use parameter expansion and other builtins inside the loop. To load every line of a file into an array at once, use mapfile. Researchers have built systems such as PaSh that split shell pipelines across many processor cores automatically, and everyday tools such as xargs with dash capital P and GNU parallel let you run the body of a loop on many cores at once.
