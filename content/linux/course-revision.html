With umask 027 a new file gets 640 and a new folder 750, and the shell arithmetic shows the same: 666 with the bits of 027 taken away is 640. A sleep killed with signal 9 reports 128 + 9 = 137, and a command that is not found reports 127.
Read a permission string in five seconds
  1. Take -rwxr-x---. The first character is the type: - file, d folder, l link.
  2. Split the rest into three groups: rwx, r-x, ---.
  3. Add r 4, w 2, x 1 in each group: 7, 5, 0.
  4. So it is 750: the owner may do everything, the group may read and run, others nothing.
  5. An s in the user group means SUID, in the group group SGID, and a t in the last group the sticky bit.
Some numbers come back in every exam and on every server. Permission digits add read four, write two and execute one, for user, group and others, so six four zero is read and write for the owner and read for the group. The umask takes bits away from six six six for files and seven seven seven for folders. Exit status zero is success, one hundred twenty seven means command not found, and one hundred twenty eight plus n means killed by signal n, so a kill minus nine gives one hundred thirty seven. The box checks three of these rules on a real shell.

Read and build pipelines

Exams love a pipeline with a question “what does it print?”. Read it from left to right and write down what each stage hands to the next.

Three classic pipelines on the practice filesRun for real on Linux while this page was built
sort fruits.txt | uniq -c | sort -rn | head -n 3
      3 apple
      2 mango
      1 kiwi
awk -F, 'NR > 1 { sum[$2] += $3; n[$2]++ } END { for (s in sum) printf "%s %.1f\n", s, sum[s] / n[s] }' marks.csv | sort
english 67.0
maths 82.7
science 83.0
grep ERROR logs/app.log | cut -d' ' -f2,4-
09:02:40 payment failed for order 1042
09:04:18 database timeout after 30s
ls -l | awk 'NR > 1 { total += $5 } END { print total, "bytes in", NR - 1, "entries" }'
16708 bytes in 9 entries
First: sort puts equal lines next to each other, uniq -c counts each run, sort -rn puts the biggest count first, head keeps three. Second: awk splits marks.csv at commas, skips the header, adds up the scores and counts per subject, and prints the average. Third: grep keeps the error lines and cut keeps the time and the message. Fourth: awk adds up the size column of ls -l.

Common mistake
Filenames with spaces break xargs and unquoted loops. Use find -print0 | xargs -0, and always quote "$var" in scripts.
Pipelines are the heart of the shell and a favourite exam question. Read one from left to right and note what each stage passes on. In the first, sort groups equal lines, uniq minus c counts them, sort minus r n puts the biggest count first and head keeps three. The second uses awk to average the scores per subject. The third keeps error lines and cuts out the fields you need, and the fourth adds up a column. The table lists the patterns that solve most daily tasks, and the chapter that teaches each one.

Real world scenario: the full disk at midnight

A monitoring alert said the root file system was at 100 %. df -h confirmed it, but du found only 20 GB of the 40 GB. sudo lsof +L1 showed a 19 GB debug log that someone had deleted while the app still wrote to it. Restarting the app gave the space back. The team then added a logrotate rule with copytruncate, a disk alert at 80 %, and a note in the runbook. Three chapters (disks, files inside, logs) solved one incident.

Real problems cross chapters. In the animation, pick a problem and see the commands an admin would use, with the chapter each comes from. For a full disk, look with d f, find the big folder with d u, and remember that a deleted file still open keeps its space. For a service that will not start, read systemctl status and the journal. For network trouble, go from the bottom up: address, route, port, firewall. For permission denied, check every folder on the path. Fix the cause, then make sure it cannot happen again.

Lesson 6 of 6

Where to go from here

One idea, four depths

You can move around the file tree, make, copy and delete files, read them, set permissions, and string commands together with pipes. That is enough to use any Linux computer, a Raspberry Pi or a phone’s terminal app with confidence.

You can write robust Bash scripts, schedule them, run a server with users, packages, services, logs, disks, backups, SSH and a firewall, and find out why something fails or is slow. That covers LPIC-1, Linux+ and most of RHCSA and LFCS.

Next steps for a job: configuration management with Ansible, containers with Docker and Kubernetes, CI/CD pipelines (the Git and CI/CD subject on this site), monitoring with Prometheus and Grafana, and cloud servers. Practise on a spare VM and break it on purpose.

For depth: read the kernel source and its documentation, write a small kernel module or an eBPF program, study the C standard library and system calls (Advanced 1.1), and follow LWN.net for kernel development. Research topics include schedulers, file systems, memory tiering, and secure isolation.

Real world scenario: the intern who learned by breaking things

An intern got a spare cloud VM and one rule: break it, then fix it, and write down how. Week one, a chmod -R 700 / on a test copy taught how much depends on permissions. Week two, a full disk and a deleted open file. Week three, a wrong firewall rule that locked out SSH, fixed through the cloud console. After two months the notes were the team’s best runbook, and the intern passed RHCSA.

You have reached the end of the course. At school level you can use any Linux computer with confidence. As a professional you can script, run and repair a server, which covers the common certifications. For a job in operations, learn Ansible, containers, Kubernetes, pipelines, monitoring and the cloud, and practise on a spare virtual machine that you break on purpose. For depth, read the kernel source, write an e B P F program, and follow kernel news on L W N. Keep using the practice shell and the labs to stay fast.
