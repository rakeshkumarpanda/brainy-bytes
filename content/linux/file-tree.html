Lesson 1 of 5

One tree for everything

Windows gives every disk its own letter: C:, D:, E:. Linux does it differently. There is one single tree of folders, and it starts at the top folder called the root, written as a single slash /. Every file on every disk, USB stick and network share appears somewhere inside that tree. A USB stick does not get a letter, it gets a folder, for example /media/learner/USB.

Linux people say directory where Windows says folder. They are the same thing. Paths use a forward slash / between names, never a backslash.

The top of the tree on a typical Ubuntu machineTypical output, yours will differ
ls /
bin   dev  home  lib64  mnt  proc  run   srv  tmp  var
boot  etc  lib   media  opt  root  sbin  sys  usr
Your list may have a few more names, such as snap or lost+found. The build machine of this page is a container with extra folders, so this is a typical desktop listing.
Common mistake
The word root means two different things. / is the root directory, the top of the tree. root is also the name of the administrator user, whose home folder is /root. Context tells you which one is meant.
Unix chose a single tree in the early 1970s, and the idea turned out to be powerful. Every disk, every USB stick and even special things like running programs appear as folders somewhere in one tree that starts at slash. When you plug in a USB stick, Linux attaches its files at a folder such as slash media, and this is called mounting. A program never needs to know which physical disk a file is on. It only needs the path. That is why a big company can move its data to a bigger disk, or to a network storage box, without changing a single program, only the place where the disk is attached. Windows took a different path from MS-DOS, giving each disk its own letter. Neither is wrong, but on Linux you will always think in one tree, and every path you write starts from slash or from where you stand.

What lives where: the standard folders

Linux distributions agree on what each top folder is for. The rules are written in the Filesystem Hierarchy Standard (FHS), version 3.0 from 2015. Once you know them, you can find your way around any Linux machine.

Remember
A quick memory aid: /etc for settings, /var for things that vary, /usr for installed programs, /home for people, /tmp for throw away files, /dev for devices.
Going deeper: Why /bin and /usr/bin both exist

In early Unix the first disk was small, so the programs needed to start the system lived in /bin and everything else went on a second disk mounted at /usr. That reason disappeared long ago. Fedora (2012), Debian 12 (2023) and Ubuntu now keep everything in /usr and make /bin, /sbin and /lib links to it, so old scripts that call /bin/sh still work.

The folder names of Linux look strange at first, but each one has a story. The name etc comes from the early Unix manuals, where it held miscellaneous files, and today it holds almost every setting of the system as readable text. var means variable, for data that changes while the system runs, like log files and databases. The split between slash bin and slash usr slash bin is a famous accident of history. In 1971 the first disk of the Unix computer at Bell Labs filled up, so Ken Thompson and Dennis Ritchie moved part of the system onto a second disk mounted at slash usr. Fifty years later the reason is gone, and modern distributions such as Fedora, Debian and Ubuntu have merged them back together, keeping links so old scripts still work. The Filesystem Hierarchy Standard writes all of this down so every distribution looks familiar.
Lesson 3 of 5

Absolute and relative paths, . .. and ~

A path tells the system how to reach a file. There are two kinds.

Absolute pathExam favourite
starts with /
The full route from the root. It means the same thing wherever you are: /home/learner/logs/app.log.
Relative pathExam favourite
does not start with /
A route from the folder you are in now. From /home/learner, logs/app.log means /home/learner/logs/app.log.
Special names
. this folder, .. the parent, ~ your home, - the previous folder (only for cd)
They can be mixed into any path: ../asha, ~/logs, ./script.sh.
Work out where logs/../scripts/./hello.sh points, starting in /home/learner
  1. Start: /home/learner (the path does not start with /, so it is relative).
  2. logs: go into /home/learner/logs.
  3. ..: go up to the parent, back to /home/learner.
  4. scripts: go into /home/learner/scripts.
  5. .: stay where you are.
  6. hello.sh: the file /home/learner/scripts/hello.sh

Remember
Every folder contains . and .., even the root. In / the parent .. points back to / itself, so cd .. at the top stays at the top.
Paths are like directions to a house. An absolute path is like a full postal address: country, city, street and house number. It works from anywhere in the world. A relative path is like telling a neighbour, two doors down on the left. It is shorter, but only makes sense from where you are standing. On Linux, an absolute path always starts with a slash, and a relative path never does. There are a few handy shortcuts. A single dot means here, two dots mean one folder up, and the tilde means your home folder. The tilde shortcut comes from an old terminal called the Lear Siegler ADM-3A from 1976, whose Home key also had a tilde printed on it. Bill Joy used that terminal while writing software at Berkeley, so the tilde came to mean home. Many programmers still type cd tilde every day without knowing that story.

Remember
Files whose names start with a dot are hidden. It is only a naming habit, not a security feature: ls -a shows them. Settings files like .bashrc are hidden so they do not clutter your home folder.
The ls command is probably the most typed command in the history of Unix. Its name is short for list, and it was in the very first edition of Unix in 1971. The long listing with dash l packs a lot into one line: what kind of thing it is, who may use it, who owns it, how big it is and when it last changed. Learn to read that line slowly once, and you will read it in a glance forever. Hidden files have a funny origin. In early Unix, ls was written to skip the dot and dot dot entries, and the quick way to do that was to skip every name starting with a dot. People then noticed they could hide their settings files by starting their names with a dot, and the habit stuck. It was a small bug that became a feature, and it is why your home folder has files like dot bashrc that you never see unless you ask.
Lesson 5 of 5

The file tree from school to research

One idea, four depths

All the files in Linux live in one big upside down tree. The top is called root and written /. Folders hold files and other folders. A path is the list of folder names you walk through to reach a file.

Linux presents a single hierarchical namespace rooted at /. Other filesystems are mounted onto directories. The FHS assigns roles to top level directories. Paths are absolute or relative to the process working directory, and the kernel resolves them component by component.

Path resolution (namei) walks each component through the dentry cache, checks execute permission on every directory crossed, follows symbolic links (up to 40 in a path), and crosses mount points. Each process has its own current directory and root directory, which chroot and mount namespaces change, so two processes can see different trees.

Current work includes per process views of the tree in containers (mount namespaces, overlay filesystems), safer path lookup with openat2() and its RESOLVE_ flags (Linux 5.6, 2020) against symlink race attacks, and union and network filesystems. Older research systems such as Plan 9 from Bell Labs pushed the one tree idea further, with every resource as a file in a per process namespace.

Real world scenario: a web server

On a Linux web server, the website files usually live in /var/www, the settings of the web server in /etc/nginx, its logs in /var/log/nginx, and the program itself in /usr/sbin/nginx. An engineer who has never seen that server can still find everything in a minute, because every machine follows the same layout.

The one tree idea has been pushed very far. In the late 1980s the same Bell Labs team that created Unix built a research system called Plan 9, where every resource, even the network and the windows on the screen, was a file in a tree, and every program could have its own private view of that tree. Linux borrowed some of those ideas. Today, when you start a container with Docker, the container gets its own private file tree through a kernel feature called mount namespaces, so it sees a slash that is really just a folder on the host. Security researchers also study path tricks, where an attacker swaps a folder for a link at just the right moment, and in 2020 Linux added a safer way to open paths called openat2. All of this still rests on the simple idea you learned here: one tree, starting at slash.
