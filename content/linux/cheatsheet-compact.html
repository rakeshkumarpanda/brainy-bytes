Step 1Foundations · Meet Unix and Linux

1.1Meet Unix and Linux

  • Operating system The manager of the computer: it shares the CPU, memory, disk and devices between programs and users.
  • Unix and Linux Unix: Bell Labs, 1969, rewritten in C in 1973. Linux: a free Unix-like kernel by Linus Torvalds, 1991, licensed under the GPL.
  • Layers Hardware, kernel (kernel space), libraries, shell and tools, apps (user space). Programs ask the kernel for help with system calls.
  • Distributions Kernel plus GNU tools plus a package manager. Debian family uses apt, Red Hat family uses dnf. Commands are the same everywhere.
  • Standards and names POSIX (IEEE 1003.1) keeps Unix-like systems compatible. UNIX is a trademark for certified systems such as macOS.
  • Case matters Commands and file names are case sensitive: ls is not LS, notes.txt is not Notes.txt.
  • Exam Linux is not Unix code. Linus wrote the kernel from scratch. It is called Unix-like because it follows the same ideas and the POSIX standard.
  • Trap Commands are case sensitive. ls works, LS gives "command not found". File names are case sensitive too: notes.txt and Notes.txt are two different files.

1.2The terminal and the shell

  • Terminal and shell The terminal is the window. The shell (bash, zsh) reads commands and starts programs.
  • Prompt user@host:folder$. ~ is your home folder. # means root, so be careful.
  • Command shape command -options arguments. Short options join (-la), long options use -- (--all). Quote names with spaces.
  • Finding commands Order: alias, function, builtin, then PATH left to right. type and which tell you. Run local files with ./name.
  • Keys Tab completes, Up and Down walk history, Ctrl R searches it, Ctrl C stops a program, Ctrl L clears, !! repeats.
  • Command linecommand -options arguments
  • Trap Seeing # instead of $ means you are root. Every command you type can change or delete anything on the system. Slow down, and leave root as soon as you have finished.
  • Trap If you get "command not found", either the program is not installed, the name is misspelled, or its folder is not in PATH. To run a program in the current folder you must write ./name, because the current folder is not in PATH on purpose.

1.3Getting help: man, --help and friends

  • man man COMMAND opens the manual. Space next, b back, /word search, n next match, q quit.
  • Sections 1 commands, 2 system calls, 3 library, 5 file formats, 7 overviews, 8 admin. man 5 passwd picks a section.
  • Searching apropos word (man -k) finds pages by description, whatis gives one line. mandb builds the index.
  • Quick help COMMAND --help for options, help BUILTIN for bash builtins, --version before trusting a web answer.
  • Read errors command not found, No such file or directory, Permission denied and Is a directory each point to a clear first step.
  • A page from one sectionman 5 passwd
  • Search page descriptionsman -k word = apropos word
  • Exam When people write ls(1) or crontab(5) in a book or chat, the number is the manual section. Read crontab(5) as: run man 5 crontab.
  • Trap Options that work on Linux may not work on macOS, because macOS uses BSD versions of many tools. When an example from the web fails, check --version and the local man page.

Step 2Foundations · Files and folders

2.1The file tree and paths

  • One tree Everything hangs from / (the root). Disks are mounted onto folders, there are no drive letters.
  • FHS /etc settings, /home people, /var changing data and /var/log logs, /usr programs, /tmp temporary, /dev devices, /proc live kernel info.
  • Paths Absolute starts with /. Relative starts from pwd. . here, .. parent, ~ home, cd - previous folder.
  • ls -l long, -a hidden, -h human sizes, -t newest first, -r reverse, -R recursive, -d the folder itself.
  • Hidden files A name starting with a dot is hidden from plain ls. It is a convention, not security.
  • Absolute pathstarts with /
  • Relative pathdoes not start with /
  • Trap The word root means two different things. / is the root directory, the top of the tree. root is also the name of the administrator user, whose home folder is /root. Context tells you which one is meant.

2.2Working with files and folders

  • Make mkdir (with -p for parents) makes folders. touch makes empty files or updates times.
  • Copy and move cp copies, cp -r or -a for folders. mv moves and renames. Both overwrite silently, use -i or -n.
  • Delete rm deletes for good, rm -r for folders, rmdir only empty folders. List first, then delete.
  • Globs * any text, ? one character, [abc] one from a set. The shell expands them. * skips hidden names.
  • Braces {a,b} and {1..5} make words even without files: mkdir day{1..3}.
  • Copycp SOURCE DEST
  • Copy a foldercp -r FOLDER DEST
  • Move or renamemv OLD NEW
  • *any text, even none
  • {a,b} {1..5}brace expansion, not a match
  • Trap mkdir a/b fails with "No such file or directory" when a does not exist yet. Add -p to create every missing parent.
  • Trap cp and mv overwrite an existing destination file without asking. Use -i while you learn, or -n when you never want to overwrite.
  • Trap GNU rm refuses rm -r / and needs --no-preserve-root to do it (protection added in coreutils 6.4, 2006). But it will happily delete everything with rm -rf ~/* or with a typo such as a space in rm -rf ./ folder. There is no protection for those.

2.3Reading and inspecting files

  • cat and less cat prints whole files (cat -n numbers lines, cat -A shows hidden characters). less pages through big files: Space, b, /word, n, q.
  • head and tail Both default to 10 lines. -n N chooses another number, tail -n +N starts at line N.
  • Follow tail -f watches a growing file. tail -F also survives log rotation. Ctrl+C stops.
  • Measure wc counts lines, words and bytes. wc -l counts newline characters. file reads magic numbers, not names. stat shows metadata.
  • Compare diff shows changed lines (c change, a add, d delete, or - and + with -u). cmp finds the first differing byte.
  • head -n Nfirst N lines
  • tail -n Nlast N lines
  • Trap Logs are often rotated: app.log is renamed to app.log.1 and a new app.log starts. tail -f keeps reading the old renamed file and goes quiet. tail -F follows the name, notices the new file and continues with it.

Step 3Foundations · Permissions and editing

3.1Users, groups and permissions

  • Mode string Type, then owner, group and others, each rwx. r 4, w 2, x 1. 644 files, 755 programs and folders, 600 secrets.
  • One class The kernel uses only the first class that matches: root, owner, group, others. You also need x on every folder in the path.
  • chmod Numbers set everything (chmod 750). Letters change parts (u+x, go-w, u=rw). -R for trees, X for folders only.
  • Ownership chown needs root. chgrp works for groups you belong to. Deleting needs w and x on the folder.
  • umask and special bits umask removes bits from new files (022 gives 644 and 755). setuid 4000, setgid 2000, sticky 1000 as on /tmp.
  • -rw-r--r--the mode string
  • 644the same mode in numbers
  • mode = request AND NOT umaskumask removes bits
  • Trap chmod 777 to make an error go away is a classic mistake. It lets every user and every hacked service on the machine change the file. Find which user needs access and give only that.

3.2Editing text: nano and vim

  • nano Type to edit. Ctrl+O and Enter saves, Ctrl+X exits, Ctrl+K cuts a line, Ctrl+U pastes, Ctrl+W searches.
  • vim modes Normal for commands, Insert (i a o) for typing, Esc to go back, : for the command line.
  • vim survival :w save, :q quit, :wq save and quit, :q! quit without saving. When lost, Esc Esc then :q!.
  • vim editing x, dd, yy, p, u, /word, :%s/old/new/g. Operators plus motions: dw, d$, cw. Learn with vimtutor.
  • Editor choice Programs use VISUAL then EDITOR. Use visudo for sudoers and sudoedit for root files. >> and here documents edit without an editor.
  • Normalthe starting mode
  • Command linestarts with :
  • Trap Never edit /etc/sudoers with a normal editor. Use visudo, which checks the file before saving. A typing mistake in that file can stop sudo working for everyone.

Step 1Shell Power Tools · Streams and pipes

1.1Streams and redirection

  • Streams 0 stdin (keyboard), 1 stdout (results), 2 stderr (errors). Both outputs show on the terminal until redirected.
  • Output > replaces, >> appends, 2> catches errors, &> or > f 2>&1 catches both. The file is emptied before the command runs.
  • Order Redirections run left to right. 2>&1 copies where stdout points at that moment, so write it after > file.
  • Input < file feeds a file, << END is a here document (quote END to stop expansion), <<< is a here string.
  • tee and /dev/null tee shows and saves (tee -a appends, sudo tee writes root files). /dev/null throws output away.
  • Trap A classic accident: sort data.txt > data.txt leaves an empty file. The shell empties data.txt before sort starts reading it. Write to a new name and rename it afterwards.
  • Trap sudo echo hi > /etc/motd fails with Permission denied, because the redirection is done by your own shell before sudo runs. echo hi | sudo tee /etc/motd works, because tee runs as root and opens the file itself.

1.2Pipes and filters

  • Pipe A | B feeds stdout of A into stdin of B. Errors still go to the terminal unless you add 2>&1 before the |.
  • sort and uniq sort (-n numbers, -r reverse, -t, -k3 by field, -u unique, -h sizes). uniq needs sorted input, -c counts.
  • Top N recipe sort | uniq -c | sort -rn | head -n N finds the most common lines.
  • cut and tr cut -d, -f2 picks fields, cut -c1-8 characters. tr a-z A-Z translates, -d deletes, -s squeezes.
  • Status $? is 0 for success. A pipeline reports its last command. PIPESTATUS shows all, set -o pipefail catches any failure.
  • A | Bpipe
  • Trap cut uses exactly one character as the separator. Columns separated by several spaces, as in ps or ls -l output, need squeezing with tr -s first, or awk, which is covered two chapters later.

Step 2Shell Power Tools · Searching and editing text

2.1grep and regular expressions

  • grep grep PATTERN FILE prints matching lines. -i case, -v invert, -c count, -n numbers, -w words, -o only the match.
  • Searching wider -r searches folders, -l lists file names, -A -B -C add context, -q only sets the exit status.
  • Basic regex . any char, * repeat, ^ start, $ end, [abc] set, [^abc] not in set, a backslash makes a special character plain. Quote patterns.
  • Extended regex grep -E: + one or more, ? optional, {n,m} counts, | or, ( ) groups. Basic grep needs backslashes.
  • Regex is not glob The shell * means anything, the regex * means repeat. .* is "anything" in a regex.
  • .any one character
  • ^ and $start and end of the line
  • Trap A regex star is not the shell star. In a file pattern *.txt means "anything". In a regex * means "repeat the item before it", so .* is the regex for "anything".

2.2sed: the stream editor

  • Cycle sed reads a line into the pattern space, runs the script, prints it (unless -n), and repeats. The file is not changed without -i.
  • Substitute s/old/new/ first match, /g all, /2 the second, /I ignore case. & is the match. With -E, ( ) capture groups that a backslash and a number put back.
  • Addresses 3, $, /regex/, 2,5 and /a/,/b/ ranges, ! to invert. sed -n '/x/p' works like grep.
  • Commands d delete, p print, q quit, i a c insert, append, change, y translate, = line number. Give several with -e or separate them with a semicolon.
  • In place sed -i edits the file, sed -i.bak keeps a backup. macOS needs sed -i ''. Preview without -i first.

2.3awk: columns, patterns and reports

  • Fields $0 whole line, $1 first field, $NF last, NF field count, NR line number. -F, or -F: change the separator.
  • Rules pattern { action }. No pattern: every line. No action: print. BEGIN before input, END after it.
  • Patterns Comparisons ($3 >= 80), regex (/ERROR/, $2 ~ /x/), NR > 1 to skip a header, ranges NR==2,NR==4, && || !.
  • Numbers Variables start at 0. Sum in a rule, print in END. Arrays with text keys count or total per group.
  • Programs printf for neat columns, if and loops, -v to pass values, -f for program files, $1=$1 with OFS to rebuild lines.
  • $0the whole line
  • -F,field separator

Step 3Shell Power Tools · Finding and packing files

3.1Finding files: find, xargs and locate

  • find find WHERE TESTS. -name (quote it), -iname, -type f/d/l, -size +100M, -mtime -7, -mmin, -empty, -user, -perm, -maxdepth.
  • Logic Tests side by side mean and. -o is or, ! is not, quoted brackets group, and binds tighter than or. -prune skips a folder.
  • Actions -exec cmd {} with the backslash semicolon ending runs per file, -exec cmd {} + in batches, -delete (preview first, keep it last).
  • xargs Turns input into arguments. -n count, -I{} placement, -0 with find -print0 for safe names, -P parallel.
  • Lookups locate uses a daily database (sudo updatedb to refresh). which, type and command -v tell what a command name runs.
  • Trap Always quote the pattern: find . -name "*.txt". Without quotes the shell expands *.txt in the current folder first, and find then searches for those exact names only.

3.2Archives and compression: tar, gzip, xz and zip

  • tar tar -cvf make, -tvf list, -xvf extract, -C DIR to choose the folder. Keep f last, the next word is the archive name.
  • Compress tar -z gzip, -j bzip2, -J xz, --zstd. GNU tar detects the method when extracting. gzip replaces the file, -k keeps it.
  • Read packed files zcat, xzcat and bzcat print without unpacking. gzip -l shows sizes, gzip -t tests the file.
  • zip zip -r out.zip dir, unzip -l to look, unzip -d DIR to place, -o to overwrite. Best for sharing with Windows and Mac users.
  • Backups Stream with -f - over ssh, strip a top folder with --strip-components, check with tar -t and sha256sum, test a restore.
  • Trap The f option takes the next word as the archive name, so keep f last in a bundle: tar -cvf out.tar works, tar -cfv out.tar makes an archive called v. The dash is optional for the first bundle, so tar cvf is the same as tar -cvf.
  • Trap unzip asks before replacing an existing file. In a script, use -o to overwrite or -n to never overwrite, so it does not stop and wait for an answer.

Step 4Shell Power Tools · Processes and the shell environment

4.1Processes, jobs and signals

  • Process A running program. PID and parent PPID, created by fork then exec. States R S D T Z. $$ is this shell, $! the last background job.
  • Watch ps for your terminal, ps aux or ps -ef for all, ps -o to pick columns, top live, pgrep -a NAME for PIDs.
  • Signals kill sends SIGTERM (15). kill -9 SIGKILL cannot be caught. Ctrl+C is SIGINT, Ctrl+Z SIGTSTP. Death by signal N gives status 128 + N.
  • Jobs CMD & background, Ctrl+Z stop, jobs list, fg and bg with %N, wait for all. nohup or tmux for work that must survive logout.
  • Priority nice -n 10 CMD starts politely, renice changes a running process. -20 most favoured, 19 least, only root lowers it.
  • Trap Closing a terminal sends SIGHUP to its shell, which passes it on to its jobs. Use nohup, disown, or better a terminal multiplexer such as tmux or screen for long work over ssh, so a dropped connection does not kill it.

4.2The shell environment: variables, PATH and startup files

  • Variables NAME=value with no spaces, read with "$NAME". export passes it to children, as a copy. NAME=value CMD sets it for one command.
  • PATH Colon separated folders, searched left to right after aliases, functions and builtins. Add with PATH="$HOME/bin:$PATH", never without $PATH.
  • Startup ~/.bashrc for aliases, functions and prompt. Login shells read ~/.profile. source ~/.bashrc applies edits now.
  • Alias and function alias ll='ls -alF' for short names. A function takes arguments and runs in the current shell.
  • History history, !! and sudo !!, !N, !$, Ctrl+R to search. PS1 sets the prompt with codes for user, host, folder and time.
  • Trap city = Pune with spaces is not an assignment. bash runs a command called city with the arguments = and Pune, and prints city: command not found.
  • Trap Never put . (the current folder) in PATH, and never write PATH=~/bin without $PATH. The first lets a file called ls in a shared folder run instead of the real ls. The second leaves you with no commands at all until you open a new terminal.

Step 1Shell Scripting · Writing scripts

1.1Your first shell scripts

  • Script basics First line #!/bin/bash, then chmod +x and run with ./name.sh. bash name.sh needs no x bit, source runs it in the current shell.
  • Arguments $0 name, $1..$9 and ${10}, $# count, "$@" all as separate words, shift moves them down, ${1:-default} for a fallback.
  • Exit status 0 is success. $? holds the last status. exit N ends the script. 127 not found, 126 not executable, 128+N killed by signal N.
  • Output printf for exact formats, echo for simple lines, errors to stderr with >&2.
  • Input read -r VAR (add -p "prompt"), read -r a b rest splits words. Here documents: <
  • Trap Use #!/bin/bash when the script uses bash features such as [[ ]] or arrays. #!/bin/sh asks for a plain POSIX shell, which on Debian and Ubuntu is dash, and many bash features fail there.
  • Trap Always quote "$1" and "$@". Without quotes a file name like My Report.pdf becomes two words, and an empty argument disappears completely.

1.2Quoting and expansions

  • Quoting Single quotes keep everything literal, double quotes keep spaces and wildcards but expand $ and $( ), a backslash protects one character, $'...' understands codes like a tab.
  • Order Brace, tilde, then parameter, arithmetic and command substitution, then word splitting, pathname expansion and quote removal.
  • Quote variables Write "$var" and "$(cmd)". Unquoted results are split at IFS and globbed, so spaces and * in data break the command.
  • Parameter expansion ${#v} length, ${v:-d} default, ${v:?msg} required, ${v#p} ${v##p} cut from the start, ${v%p} ${v%%p} cut from the end, ${v//a/b} replace, ${v:s:n} slice, ${v^^} ${v,,} case.
  • Substitution $(cmd) output (trailing newlines removed), $((expr)) whole number maths, <(cmd) output as a file name, IFS sets where splitting and read cut.
  • Trap Globbing happens after variables are expanded, so a file name inside a variable can turn into a list of other files. That is why rm $f is dangerous and rm -- "$f" is safe.

Step 2Shell Scripting · Decisions and loops

2.1Decisions: if, test and case

  • if if CMD; then ...; elif CMD; then ...; else ...; fi. The condition is a command, status 0 is true, ! reverses it.
  • test and [ ] Spaces inside the brackets. Files -e -f -d -r -w -x -s, text = != -z -n, numbers -eq -ne -lt -le -gt -ge. Quote every variable.
  • [[ ]] No splitting or globbing inside. == with an unquoted pattern, =~ with a regular expression and BASH_REMATCH, && and || inside.
  • (( )) Whole number maths with < > == % and friends. True when the result is not 0. A leading 0 means octal.
  • case case "$v" in pat1|pat2) ... ;; *) ... ;; esac. First match wins. ;& falls through, ;;& keeps testing.
  • Trap a && b || c is not a full if. If b itself fails, c runs too. Use a real if when the middle command can fail.
  • Trap Write [ "$x" = y ], always with quotes. Use = and != for text, -eq and -lt for whole numbers. [ 9 > 10 ] is not a comparison at all: it redirects output into a file called 10.

2.2Loops: for, while and until

  • for for x in LIST; do ...; done. LIST may be words, a glob, a brace range or "$@". for (( i=0; i<n; i++ )) counts. shopt -s nullglob removes unmatched patterns.
  • while and until while CMD repeats while CMD succeeds, until while it fails, while true with break for a loop you leave from the inside.
  • Reading lines while IFS= read -r line; do ...; done < file. Set IFS=, and give several names to split fields. Use < <(cmd) rather than cmd | while to keep variables.
  • Control break leaves the loop, continue skips to the next pass, add a number for nested loops. done > file and done | cmd redirect the whole loop.
  • Safe names Loop over globs, never over $(ls). For any name use find -print0 | while IFS= read -r -d '' f.
  • Trap Do not loop over $(ls) or $(cat file). File names with spaces are split into pieces. Use a glob for files and while read for lines.

Step 3Shell Scripting · Functions and data

3.1Functions, scope and libraries

  • Define and call name() { ...; } or function name { ...; }. Call it like a command. Inside, $1, $# and "$@" are the call’s own arguments.
  • Results Status with return N (0 to 255) for yes or no. Text and numbers by printing and catching with v=$(fn). printf -v NAME to set a variable.
  • Scope Variables are global unless declared local. Scope is dynamic, so a function sees its caller’s locals. $( ) and pipelines run functions in a subshell.
  • Libraries Keep helpers in a file and load it with source. Guard it against double loading. log to stderr, die to log and exit 1.
  • Layout Settings, then functions, then main() and a last line main "$@".
  • Trap return is for statuses, not data. return 1000 or return "text" cannot carry a result. Print the value and capture it with $( ) instead.

3.2Arrays and command-line options

  • Indexed arrays a=(x "y z"), ${a[i]} from 0, ${a[-1]} last, "${a[@]}" all as words, ${#a[@]} count, ${!a[@]} indexes, a+=(v), unset "a[i]".
  • Associative arrays declare -A m first. m[key]=v, ${m[key]}, "${!m[@]}" keys in no order, [[ -v m[key] ]] to test.
  • Filling and joining files=(*.txt), mapfile -t lines < file, read -ra parts <<< "$s". "${a[*]}" joins with the first character of IFS.
  • getopts while getopts ":vn:" opt with case, $OPTARG for values, : and ? for errors, then shift $(( OPTIND - 1 )).
  • Usage A usage function that prints to stderr and exits with 2. Long options need a while and case loop.
  • Trap ${#a[@]} counts elements, it is not the highest index plus one. Loop over "${a[@]}" for values or over "${!a[@]}" for indexes, never from 0 to the length minus 1, because arrays can have gaps.
  • Trap Without declare -A, phone[asha]=1 creates an indexed array, and the text asha is read as arithmetic, which gives index 0. Every key then overwrites the same element.

Step 4Shell Scripting · Robust and scheduled scripts

4.1Robust scripts: errors, traps and debugging

  • Strict mode set -euo pipefail near the top. -e stops on failures, -u on unset variables, pipefail on any failing pipe part.
  • Exceptions set -e ignores if, while and until tests, && and || lists except the last command, and ! commands. (( n++ )) from 0 fails.
  • trap trap cleanup EXIT for tidying up, trap '...' ERR with $LINENO and $BASH_COMMAND, INT and TERM for Ctrl+C and kill.
  • Temporary files tmp=$(mktemp) or $(mktemp -d), then trap 'rm -rf -- "$tmp"' EXIT. Never fixed names in /tmp.
  • Debugging bash -n checks syntax, bash -x or set -x traces, PS4 sets the trace prefix, ShellCheck finds common mistakes.
  • Trap set -e is ignored in a function called from a condition such as if myfunc or myfunc || ..., for the whole function body. Check important steps explicitly with || die "...".
  • Trap Never use a fixed name such as /tmp/myscript.tmp. Another user can create it first, as a symbolic link to one of your files, and your script would overwrite that file. mktemp picks a new random name every time.

4.2Scheduled jobs: cron, at and systemd timers

  • Five fields minute hour day-of-month month day-of-week, then the command. * any, , list, - range, / step, @daily and @reboot shortcuts.
  • Either rule When both day of month and day of week are set, cron runs the job when either matches.
  • crontab crontab -e edits, -l lists, FILE installs, -r removes everything without asking. A bad line refuses the whole file.
  • Environment SHELL=/bin/sh, PATH=/usr/bin:/bin, no .bashrc. Use full paths, redirect output to a log, escape % in crontab lines.
  • Other schedulers at, atq and atrm for one-off jobs, anacron for machines that are switched off, systemd timers with OnCalendar and Persistent=true.
  • Trap When both day of month and day of week are restricted, cron runs the job when either one matches. 0 0 13 * 5 runs on every 13th and on every Friday, not only on Friday the 13th.
  • Trap Always redirect output in a cron line, for example >> /var/log/myjob.log 2>&1. Without it the output is mailed, and on a server without mail it is lost, so you never see the error.

Step 1System Administration · Users and software

1.1Users, groups and sudo

  • Account files /etc/passwd (7 fields, readable), /etc/shadow (hashes and ageing, root only), /etc/group. getent reads them.
  • UIDs 0 is root, 1 to 999 system accounts, 1000 and up people. The kernel checks numbers, not names.
  • Managing users useradd -m -s /bin/bash, passwd or chpasswd, usermod -aG (never -G alone), chage, userdel -r.
  • sudo sudo CMD, sudo -i, sudo -u NAME, sudo -l. Edit rules only with visudo, keep them narrow in /etc/sudoers.d.
  • Logs sudo and logins go to /var/log/auth.log on Debian and Ubuntu, /var/log/secure on RHEL, and to the journal.
  • Trap usermod -G web dev1 without -a replaces the whole list of extra groups, so dev1 silently leaves sudo, docker and every other group. Always write -aG.
  • Trap A sudoers file with a syntax error can stop sudo from working for everyone. Never edit it with a plain editor. visudo refuses to save a broken file.

1.2Installing software: apt, dpkg and other package managers

  • apt sudo apt update, then upgrade. install, remove, purge (also config), autoremove, search, show, list --installed.
  • dpkg dpkg -l lists, -L files of a package, -S owner of a file, -i installs a .deb without dependencies.
  • Repositories Listed in /etc/apt/sources.list.d, signed with keys. Add third-party ones only when you trust them.
  • Other families dnf and rpm (Fedora, RHEL), pacman (Arch), zypper (SUSE). snap and Flatpak bundle apps.
  • Safe habits Read the plan before Y, use apt-get in scripts, hold critical packages, automatic security updates, build from source into /usr/local.
  • Trap The Signed-By key in the sources file is how apt knows that the package lists are genuine. Only add a third-party repository when you trust its owner, because its packages run their scripts as root.
  • Trap Read the plan before you answer Y. Upgrades and removals can list far more packages than you expect, for example when a library change removes a desktop or a database server.

Step 2System Administration · Boot, services and logs

2.1Boot and services: GRUB, systemd and systemctl

  • Boot order Firmware (UEFI or BIOS), GRUB, kernel, initramfs, systemd as PID 1, targets, login.
  • Targets multi-user.target for servers, graphical.target for desktops, rescue and emergency for repairs.
  • Unit files /usr/lib/systemd/system from packages, /etc/systemd/system yours and stronger. systemctl edit for overrides, daemon-reload after changes.
  • systemctl status, start, stop, restart, reload, enable --now, disable, mask, is-active, --failed.
  • Your service Full path in ExecStart, stays in the foreground, User=, Restart=on-failure, WantedBy=multi-user.target, sandbox options.
  • Trap enable and start are different. enable only creates a link so the unit starts at the next boot. start runs it now. A new service usually needs both, which is what enable --now does.

2.2Logs and health checks: journalctl, /var/log and logrotate

  • Two log systems The journal (journalctl) and text files in /var/log (syslog, auth.log, kern.log, dpkg.log). Many need sudo or the adm group.
  • journalctl filters -u unit, -p err, -b boot, --since and --until, -g pattern, -k kernel, -f follow, _COMM=name.
  • Text logs grep, awk, sort, uniq -c and sort -rn answer most questions. zgrep for rotated files, logger to write your own lines.
  • logrotate Rules in /etc/logrotate.d: daily or size, rotate N, compress, postrotate reload. Test with -d, force with -f.
  • Health uptime and nproc for load, free -h available, df -h and df -i, du for big folders, vmstat, dmesg for the kernel and OOM kills.
  • Trap When memory runs out, the kernel’s OOM killer stops a process to save the system. The journal then has a line like “Out of memory: Killed process 2261 (java)”. Find it with sudo journalctl -k -g "out of memory" or sudo dmesg -T | grep -i oom.

Step 3System Administration · Storage

3.1Disks and file systems: partitions, mkfs, mount and fstab

  • Names Disks are /dev/sda, /dev/nvme0n1, /dev/vda, with partitions sda1 or nvme0n1p1. lsblk -f and blkid show types, labels and UUIDs.
  • Partitions GPT for new disks (MBR stops at 2 TiB and 4 primaries). parted mklabel gpt, mkpart NAME TYPE 1MiB 100%, print. mklabel erases the table.
  • File systems mkfs.ext4 -L, mkfs.xfs, mkfs.vfat -F 32. Inodes are fixed at mkfs, ext4 reserves 5 percent for root, xfs cannot shrink.
  • Mounting mount DEV DIR hides what DIR held. umount fails while busy (fuser -vm). df -hT and findmnt show mounts.
  • fstab UUID or LABEL, mount point, type, options (defaults, noatime, nofail), 0, fsck order. findmnt --verify, daemon-reload and mount -a before any reboot.
  • Trap Names like sda and sdb follow the order in which the kernel finds the disks, and that order can change when a disk is added or a USB stick is plugged in. Never rely on them in configuration. Use the UUID or LABEL of the file system, which blkid shows, or the links in /dev/disk/by-uuid and /dev/disk/by-id.
  • Trap mklabel replaces the whole partition table, and the partitions on the disk are lost with it. Check the device name twice with lsblk before you run it, especially when a USB stick and a data disk have similar sizes.
  • Trap A broken line in /etc/fstab can stop the boot and drop the machine into emergency mode (chapter 2.1). Add nofail for disks that may be missing, such as USB drives and network shares, and always test with findmnt --verify and mount -a before you reboot a server you cannot reach physically.
  • Trap Never run fsck on a mounted file system: repairs made under a running system can destroy data. e2fsck refuses, and the root file system is checked at boot instead, when fs_passno in /etc/fstab is 1.

3.2LVM, RAID, swap and backups

  • LVM layers pvcreate makes PVs, vgcreate pools them into a VG, lvcreate cuts LVs. pvs, vgs, lvs list them. Extents are 4 MiB.
  • Growing lvextend -r -L +SIZE grows the volume and its file system online. vgextend adds a disk, pvmove empties one, snapshots freeze a moment.
  • RAID 0 stripes, 1 mirrors, 5 survives one failure with (n − 1) × s, 6 survives two with (n − 2) × s, 10 mirrors pairs. mdadm and /proc/mdstat. RAID is not a backup.
  • Swap fallocate, chmod 600, mkswap, swapon, a line in /etc/fstab. swapon --show and free -h. vm.swappiness sets how eagerly the kernel swaps.
  • Backups 3-2-1 rule. tar --listed-incremental for full and incremental archives, rsync -a --delete (with --dry-run first), --link-dest snapshots, restic or borg. Test restores.
  • Trap RAID is not a backup. A mirror copies a deleted file, a ransomware encryption or a broken update to every disk at once. RAID keeps a server running when a disk dies, and backups bring back data that is gone.
  • Trap Without chmod 600, mkswap warns about insecure permissions, because any user could read memory contents of other programs from the file. A file with holes (made by truncate) can be rejected by swapon, so use fallocate or dd.

Step 4System Administration · Networking and security

4.1Networking: addresses, routes, DNS and sockets

  • Basics Address with prefix (192.168.1.50/24), default gateway, DNS server, ports (22, 53, 80, 443), TCP and UDP. Private ranges 10/8, 172.16/12, 192.168/16.
  • ip ip -br addr, ip -br link, ip route, ip route get, ip neigh. ip addr add, ip link set up, ip route add default via GW last only until reboot.
  • Names /etc/hosts first, then DNS through systemd-resolved at 127.0.0.53. getent hosts resolves like programs, dig asks DNS only. A, AAAA, CNAME, MX, NS, TXT, PTR.
  • Sockets sudo ss -tlnp shows listeners and programs. 0.0.0.0 is every address, 127.0.0.1 is local only. curl -I and -v, nc -zv HOST PORT.
  • Method Bottom up: interface, gateway, outside address, DNS, port, application, then tcpdump. Permanent settings in netplan (netplan try) or nmcli.
  • Trap Changes made with ip addr, ip link and ip route are lost at the next reboot. That is useful for tests, and the permanent settings go into netplan or NetworkManager (lesson 7). On a remote server, never take down the interface you are connected through.

4.2SSH: keys, remote work, tunnels and a safe sshd

  • The login Key exchange, then the host key checked against known_hosts, then user authentication with a key from authorized_keys, then the session. A changed host key stops the login.
  • Keys ssh-keygen -t ed25519 -C, a passphrase, ssh-agent and ssh-add. Private key 600, ~/.ssh 700, authorized_keys 600. One key per device.
  • Daily use ssh-copy-id HOST, ssh HOST CMD, aliases in ~/.ssh/config, scp, sftp and rsync over ssh, ssh -v for debugging.
  • Tunnels -L local:host:port, -R, -D, -N -f, ProxyJump (-J) through a bastion.
  • sshd PasswordAuthentication no, PermitRootLogin no, AllowUsers, a file in sshd_config.d, sshd -t and -T, systemctl reload ssh, keep a session open.
  • Trap Never copy your private key to a server or into a chat. Give out only the .pub file. Use one key per device, so you can remove a lost laptop’s key from authorized_keys without touching the others.

4.3Firewall and hardening: ufw, nftables and a safer server

  • How it decides netfilter in the kernel, input, output and forward hooks, conntrack lets established traffic pass, first matching rule wins, then the policy. Default deny on servers.
  • ufw default deny incoming, allow OpenSSH first, allow PORT/PROTO, allow from NET to any port P, limit, insert 1, status numbered and verbose, delete N, enable.
  • nftables table inet filter, a base chain on hook input with policy drop, ct state established,related accept, sets in braces, counters, nft -c -f, nft -f, nftables.service.
  • Hardening unattended-upgrades, ssh keys only, ss -tulpn and disable unused services, bind internal services to 127.0.0.1, find -perm -4000, sysctl.d settings.
  • Watching fail2ban jails with maxretry, findtime and bantime, auditctl -w with ausearch -k, AppArmor profiles with aa-status.
  • Trap Always allow ssh before you run ufw enable on a remote server. ufw warns “Command may disrupt existing ssh connections” for this reason. Keep your session open and test a new login, as in chapter 4.2. Cloud consoles have a serial console for the day it still goes wrong.

Step 1Internals and Advanced · Kernel and processes

1.1The kernel and system calls: strace, /proc, /sys and modules

  • Two worlds The kernel runs in kernel mode with full control. Programs run in user space and ask with system calls, wrapped by libc. Errors return -1 with errno (ENOENT, EACCES, EPERM).
  • strace strace -e trace=file|network|process, -f for children, -c to count, -o FILE, -p PID. Look for -1 ENOENT to find missing files.
  • /proc /proc/PID/status, cmdline, environ, fd/, cwd, exe. /proc/self. meminfo, loadavg, uptime, cmdline. /proc/sys equals sysctl.
  • /sys Devices and drivers as small files, for example /sys/class/net/IFACE/mtu and operstate.
  • Modules uname -r, lsmod, modinfo, modprobe and modprobe -r, /etc/modprobe.d (options, blacklist), /etc/modules-load.d, dmesg and journalctl -k.

1.2How processes live: fork, exec, wait, states and threads

  • Birth and death fork copies (returns 0 in the child), execve replaces the program (PID and open files stay), exit leaves a status, wait collects it. Builtins such as cd run without fork.
  • Tree and status pstree -p, ps -o pid,ppid,stat,cmd. PID 1 is systemd. Status 0 ok, 126 not executable, 127 not found, 128+N killed by signal N (130, 137, 143).
  • States R running, S sleeping, D waiting for I/O (cannot be killed), T stopped, Z zombie. Orphans get PID 1 as parent.
  • Threads Share memory and files. TID shown as LWP in ps -L, folders in /proc/PID/task, l in STAT.
  • Scheduler EEVDF since 6.6. nice and renice -20 to 19, chrt for policies (SCHED_OTHER, FIFO, BATCH, IDLE), taskset for CPUs, ionice for disks.
  • Trap PID 1 is special. On Ubuntu it is systemd, which starts every service. The kernel never lets PID 1 die (if it exits, the kernel panics), it does not get signals it has no handler for, and it becomes the parent of every orphaned process. In a container, your own program may be PID 1, which is why containers use a small init such as tini or docker run --init.

Step 2Internals and Advanced · Files and memory inside

2.1Files inside: inodes, links, open descriptors and the page cache

  • Inodes Name in the folder, everything else in the inode (type, owner, mode, size, times, link count, blocks). ls -i, stat, df -i. Running out of inodes gives No space left on device.
  • File types - regular, d folder, l symlink, p FIFO, c and b devices, s socket.
  • Links ln: same inode, count +1, one file system, no folders. ln -s: own inode with a path, can dangle. readlink -f, find -samefile, find -xtype l.
  • Open files Descriptors in /proc/PID/fd, data freed only when no name and no open descriptor are left. lsof +L1, : > file to empty in place.
  • Page cache write lands in RAM as dirty pages, written back within about 30 s. fsync and sync force it. Safe write: temp file, fsync, rename.
  • Trap A relative symbolic link is resolved from the folder the link is in, not from your current folder. ln -s ../shared/config.yml app/config.yml works, ln -s shared/config.yml app/config.yml from the parent folder makes a link that points to app/shared/config.yml.

2.2Memory: virtual memory, page faults, swap and the OOM killer

  • Virtual memory Own address space per process, 4 KiB pages, page tables and the MMU. VSZ is mapped, RSS is in RAM. Minor and major page faults. /proc/PID/maps, ASLR.
  • Sharing fork shares pages copy on write, code and libraries are shared, the page cache holds a file once. PSS in smaps_rollup divides shared pages.
  • Reading memory free -h: watch available. /proc/meminfo, vmstat si and so, /proc/pressure/memory, ps aux --sort=-rss.
  • Settings sysctl vm.swappiness (60), vm.overcommit_memory (0), sysctl -w as root, files in /etc/sysctl.d.
  • OOM Reclaim, then the OOM killer sends SIGKILL (status 137, kernel log). oom_score_adj -1000 to 1000. Per service limits with MemoryMax= and MemoryHigh= (cgroup memory.max).
  • Trap Java, Node.js and databases manage their own heaps. Set their limits (for example -Xmx for Java, --max-old-space-size for Node.js, shared_buffers for PostgreSQL) below the cgroup limit, or the kernel will kill them before they get a chance to clean up.

Step 3Internals and Advanced · Containers and performance

3.1Containers under the hood: namespaces, cgroups, layers and capabilities

  • What a container is A process with namespaces, a root file system, cgroup limits, fewer capabilities and a seccomp filter, sharing the host kernel.
  • Namespaces mnt, uts, ipc, pid, net, user, cgroup, time. /proc/PID/ns links, unshare to create, nsenter to join, lsns to list.
  • Images Read-only layers joined by overlayfs with a writable upper layer. Copy up on change, whiteouts for deletes.
  • cgroups One v2 tree in /sys/fs/cgroup on Ubuntu 24.04, memory.max, cpu.max, pids.max, /proc/PID/cgroup, systemd-cgls, systemd-cgtop, systemd-run -p.
  • Least privilege Capabilities (getcap, setcap, capsh --decode), --cap-drop ALL, no-new-privileges, non-root user, rootless with user namespaces, never --privileged. Docker: dockerd, containerd, runc.
  • Trap Containers share the host’s kernel. A container cannot run a different kernel, a kernel bug can be a way out of every container, and a container built for x86-64 does not run on ARM. Virtual machines each run their own kernel, which is stronger isolation at a higher cost.

3.2Performance: find the bottleneck with USE, vmstat, iostat, perf and sar

  • Method Turn “slow” into latency, throughput, utilization and saturation. USE: Utilization, Saturation, Errors for CPU, memory, disk and network. The 60 second checklist.
  • CPU Load average counts running, runnable and D state tasks: compare with nproc. vmstat r, us, sy, wa, st. mpstat -P ALL for one hot CPU, pidstat and top for the process.
  • Disks iostat -xz: r/s, w/s, kB/s, r_await and w_await, aqu-sz, %util. On SSDs %util 100 is not saturation, watch await and the queue.
  • Where time goes time: real, user, sys. strace -c counts system calls but slows the program. perf stat, top, record and report, flame graphs, eBPF tools from bpfcc-tools.
  • History and fixes sysstat with ENABLED="true", sar -u -r -q -d -n DEV and -f for an earlier day. Change one thing, measure again with the same tool.
  • Trap A load of 8 on a 2 CPU machine with id near 0 means CPU saturation. A load of 8 with id high and wa high means tasks in state D, waiting for disk or a hung NFS server, so adding CPUs would not help.
  • Trap On devices that serve many requests in parallel, such as RAID arrays and NVMe or SATA SSDs, %util at 100 does not mean the device is at its limit, as iostat(1) itself warns. Watch await and aqu-sz instead: if the wait times grow while throughput stays flat, the device is saturated.
  • Trap Change one thing at a time and measure again with the same tool. A fix that is not measured is a guess, and a tuning value copied from the internet without a measurement often makes things worse.
