Indexed arrays: many values under one name

An array holds a list of values under one name. Each value has an index, starting at 0. Arrays keep values with spaces intact, which plain strings cannot do.

CommandWhat it doesExample
a=(x "y z" w)Create an array with three elementscolours=(red "dark green" blue)
${a[i]}One element (index from 0, negative counts from the end)echo "${colours[-1]}"
"${a[@]}"All elements, each as its own wordfor c in "${colours[@]}"; do ...

unset "a[i]"Remove one element (the others keep their index)unset "colours[1]"

Quoted "${colours[@]}" kept dark green as one item, the unquoted form split it. Index 9 was allowed even though 4 to 8 do not exist. After unset the other indexes stayed where they were. Copying into a new array packed the values into 0, 1, 2 and 3. declare -p prints an array in a form you could paste back into bash.
Common mistake
${#a[@]} counts elements, it is not the highest index plus one. Loop over "${a[@]}" for values or over "${!a[@]}" for indexes, never from 0 to the length minus 1, because arrays can have gaps.
An array stores a list of values under a single name. You create one with an equals sign and round brackets around the values, and quotes keep a value with spaces as one element. Each element has a number called its index, and the first index is zero. To read one element, write dollar, a brace, the name, the index in square brackets, and a closing brace. A negative index counts from the end, so minus one is the last element. Dollar brace name, square brackets with an at sign, all inside double quotes, gives every element as a separate word, which is the safe way to loop. A hash in front gives the number of elements, and an exclamation mark gives the indexes. Plus equals appends, and unset removes one element. Bash arrays can have gaps: removing an element does not move the others, and you may set index nine on a four element array. The animation draws the boxes so you can watch this happen.
Lesson 2 of 5

Associative arrays: values looked up by name

An associative array uses text keys instead of numbers, like a dictionary. It must be declared with declare -A first. bash does not keep the keys in any particular order.

A phone book and a word counterRun for real on Linux while this page was built
declare -A phone=([asha]=98450 [ravi]=99001)
phone[meera]=97300
echo "Ravi: ${phone[ravi]}"
Ravi: 99001
echo "${#phone[@]} entries"
3 entries
for name in "${!phone[@]}"; do echo "$name -> ${phone[$name]}"; done | sort
asha -> 98450
meera -> 97300
ravi -> 99001
[[ -v phone[john] ]] || echo "no number for john"
no number for john
unset "phone[asha]"
echo "keys now: $(printf '%s\n' "${!phone[@]}" | sort | tr '\n' ' ')"
keys now: meera ravi 
declare -A count=()
while read -r fruit; do (( count[$fruit]++ )); done < fruits.txt
for f in "${!count[@]}"; do echo "${count[$f]} $f"; done | sort -rn
3 apple
2 mango
1 kiwi
1 cherry
1 banana
Keys can be any text. The loop over keys was piped into sort because bash returns keys in its own order. [[ -v ]] tests whether a key exists. (( count[$fruit]++ )) counts every word, starting from nothing, which is the classic way to tally items in bash.
Common mistake
Without declare -A, phone[asha]=1 creates an indexed array, and the text asha is read as arithmetic, which gives index 0. Every key then overwrites the same element.
An associative array works like a dictionary or a phone book. Instead of numbers, the keys are words, so you can look up a value by name. You must create it with declare dash capital A before using it. Then you set a value with the name, the key in square brackets and an equals sign, and read it back with dollar and braces. Exclamation mark with the at sign lists the keys, and a hash counts them. Keys come back in no particular order, so pipe the output to sort when order matters. To check if a key exists, use double brackets with dash v. A classic use is counting. Read words one by one and add one to the count for that word, and at the end you have a tally of every word, which you can sort to find the most common. If you forget declare dash capital A, bash quietly makes a normal indexed array and all your keys land in the same box.

mapfile read the poem into one element per line. read -ra split the CSV row at commas. With IFS set to a plus sign inside the $( ) subshell, "${nums[*]}" became 4+8+15+16+23+42, and $(( )) added it up. The script’s own IFS was not touched. A function receives an array as its normal arguments. Sorting goes through printf, sort and mapfile.
There are several ways to fill an array. A wildcard pattern in round brackets gives the matching file names. Mapfile dash t reads a whole file, one line per element, and is the fastest and safest way to load lines. Read dash r a splits a single line into words, and with IFS set to a comma it splits a CSV row into fields. To join an array into one string, use the star form in double quotes. It puts the first character of IFS between the elements, so with IFS set to a plus sign you get a sum you can hand to arithmetic. Most parameter expansion tricks work on every element at once, for example percent dot t x t removes the extension from every file name. Bash cannot pass an array to a function as a single thing, so you pass its elements as the arguments and the function reads them with dollar at sign. To sort an array, print it one per line, sort it, and read it back with mapfile.

Command-line options with getopts

Real tools accept options such as -v or -n 5. The builtin getopts reads them one at a time, following the POSIX rules: options come first, can be grouped as -vn5, and -- ends them.

The getopts loopThe general form
usage() { echo "usage: ${0##*/} [-v] [-n COUNT] FILE..." >&2; exit 2; }
verbose=0 count=10
while getopts ":vn:" opt; do     # n: means -n takes a value
  case $opt in
    v)  verbose=1 ;;
    n)  count=$OPTARG ;;
    :)  echo "-$OPTARG needs a value" >&2; usage ;;
    \?) echo "unknown option -$OPTARG" >&2; usage ;;
  esac
done
shift $(( OPTIND - 1 ))          # now "$@" holds only the files
PartMeaning
":vn:"the option letters. A colon after a letter means it takes a value. A leading colon means you print the errors yourself
$optthe letter found, : when a value is missing, ? for an unknown option
$OPTARGthe value of an option, or the bad letter in the : and ? cases
$OPTINDthe index of the next argument to read, so shift $(( OPTIND - 1 )) drops the options
getopts in a real scriptRun for real on Linux while this page was built
cat > head2.sh <<'EOF'
#!/bin/bash
usage() { echo "usage: ${0##*/} [-v] [-n COUNT] FILE..." >&2; exit 2; }
verbose=0 count=3
while getopts ":vn:" opt; do
  case $opt in
    v)  verbose=1 ;;
    n)  [[ $OPTARG =~ ^[0-9]+$ ]] || { echo "-n needs a number" >&2; usage; }
        count=$OPTARG ;;
    :)  echo "-$OPTARG needs a value" >&2; usage ;;
    \?) echo "unknown option -$OPTARG" >&2; usage ;;
  esac
done
shift $(( OPTIND - 1 ))
(( $# )) || usage
for f in "$@"; do
  (( verbose )) && echo "== $f (first $count lines) =="
  head -n "$count" -- "$f"
done
EOF

-v and -n 2 were read in order, then shift left only the two files. Grouped -vn1 worked as well. A missing value, an unknown letter and a non-number each gave a clear message and status 2. After --, getopts stopped, so -v was treated as a file name.
Long options with a while and case loopThe general form
while (( $# )); do
  case $1 in
    -v|--verbose)   verbose=1 ;;
    -n|--count)     count=$2; shift ;;
    --count=*)      count=${1#*=} ;;
    --)             shift; break ;;
    -*)             echo "unknown option $1" >&2; exit 2 ;;
    *)              break ;;
  esac
  shift
done
getopts reads only one-letter options. For --long options, scripts loop over the arguments with case and shift, as here. The external getopt program from util-linux can also parse long options.
Professional tools take options, such as dash v for verbose or dash n five for a count. Bash has a builtin called getopts that reads them one at a time inside a while loop. You give it a string of option letters, and a colon after a letter means that option needs a value. Each time round the loop, getopts puts the letter it found in your variable, and the value, if there is one, in OPTARG. A colon at the very start of the string tells getopts to stay quiet, so your script can print its own friendly error messages: the variable then holds a colon when a value is missing, and a question mark for an unknown option. After the loop, shift by OPTIND minus one removes all the options, and dollar at sign holds just the file names. Getopts only knows single letters, so for double dash long options, scripts loop over the arguments themselves with a case statement and shift.
Lesson 5 of 5

Arrays and options from school to research

One idea, four depths

An array is a numbered list of values under one name, starting at 0. An associative array uses words as keys. getopts reads options such as -v and -n 5 so a script behaves like a real tool.

bash arrays are one-dimensional and sparse: indexes need not be consecutive, and ${#a[@]} counts only the elements that exist. Arrays cannot be exported to child processes, and a function receives an array only as its arguments. "${a[@]}" expands to one word per element, exactly like "$@".

Associative arrays need bash 4.0 or later (macOS still ships bash 3.2, so scripts there use other tools or a newer bash). local -n gives a function a reference to the caller’s array. mapfile -d "" with find -print0 reads any file name safely, and -C with -c runs a callback every few lines. getopts follows POSIX: options before operands, -- ends them, and OPTIND must be reset to 1 before parsing a second list.

Arrays in bash came from the Korn shell, and POSIX sh still has no arrays, so portable scripts use "$@" with set -- as their only list. Command-line conventions themselves are standardised in the POSIX Utility Syntax Guidelines (XBD chapter 12), and the GNU Coding Standards add long options. Research tools that generate argument parsers and shell completions from one description, such as docopt and argbash, aim to keep usage text, parsing and documentation in sync.

Real world scenario: the log summary tool

An operations team needed a tool to summarise error counts per service. logsum.sh -s 2026-11-20 -t 10 /var/log/app/*.log parses -s for the start date and -t for the top N with getopts, reads every log with mapfile, counts errors per service in an associative array, and prints the top entries through sort. A usage function and status 2 for bad options make it safe to call from cron and CI jobs.

Here is the deeper view. Bash arrays have one dimension and can have gaps, so the count of elements is not the same as the highest index. Arrays cannot travel to child processes through the environment, and a function only sees an array if you pass its elements as arguments or give it a name reference with local dash n. Associative arrays arrived in bash four, so the very old bash three point two on macOS does not have them. For truly safe file name handling, mapfile can split on the zero byte that find dash print zero writes. Getopts follows the POSIX rules: options come before other arguments, and a double dash ends them. Interestingly, POSIX sh has no arrays at all, so portable scripts use dollar at sign together with set double dash as their only list. Researchers and tool builders have created generators such as docopt and argbash, which build the option parser, the help text and shell completion from a single description.
