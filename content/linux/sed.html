A stream editor: how sed works

sed (stream editor) changes text as it flows past, without opening an editor. It reads its input one line at a time into a working area called the pattern space, runs your script on that line, prints the result and moves on. By default it prints to stdout and leaves the file untouched.

One sed cycle, repeated for every line
  1. Read the next line into the pattern space (without its newline).
  2. Run each command of the script in order, if its address selects this line.
  3. At the end of the script print the pattern space, unless -n was given.
  4. Empty the pattern space and start again with the next line.

sed is short for stream editor. Lee McMahon wrote it at Bell Labs in the early nineteen seventies, so that the editing commands people typed by hand in the ed editor could be applied automatically to text flowing through a pipe. The idea is a loop. sed reads one line into a working area called the pattern space, runs your little script on it, prints the result, and moves on to the next line. It never needs the whole file in memory, so it handles huge files easily. By default it prints to the screen and leaves the original file alone, which makes it safe to experiment. Watch the animation in this lesson closely, because once you understand the cycle, every sed command becomes easy to predict.

Find and replace: the s command

The command you will use most is s for substitute: s/OLD/NEW/FLAGS. OLD is a regular expression, NEW is the replacement text.

CommandWhat it doesExample
s/cat/dog/Replace the first cat on each linesed 's/cat/dog/' pets.txt
s/cat/dog/gReplace every cat on each line (global)sed 's/a/A/g' notes.txt
s/cat/dog/2Replace only the second match on each linesed 's/a/X/2' fruits.txt
s/cat/dog/IIgnore case (GNU)sed 's/error/ERR/I' app.log
s/milk/oat &/& in NEW stands for the whole matchsed 's/[0-9]*%/(&)/' app.log
s|/usr|/opt|Any character can be the delimiter, handy for pathssed 's|/home|/srv|' file
s/^/# /Insert text at the start of every linesed 's/^/# /' config
s/ *$//Remove spaces at the end of linessed 's/ *$//' file
-E 's/(a)(b)/\2\1/'With -E, ( ) capture groups, \1 and \2 put them backsed -E 's/(.*),(.*)/\2 \1/' f

Remember
Put sed scripts in single quotes, so the shell does not touch $, * or backslashes. If the replacement itself contains the delimiter, choose another one: s|a/b|c/d| is easier to read than escaping every slash with a backslash.
The s command, for substitute, is the heart of sed. You write s, slash, what to find, slash, what to put instead, slash. That replaces the first match on each line. Add g at the end, for global, and every match on the line is replaced. The part you search for is a regular expression, so everything from the grep chapter works here. Two tricks make s very powerful. An ampersand in the replacement means the whole text that matched, so you can wrap or extend it instead of retyping it. And with dash capital E, round brackets capture parts of the match, which you can put back in any order with backslash one, backslash two and so on. That is how people reformat dates or swap columns in thousands of lines in one go. If your text contains slashes, such as file paths, use a different delimiter, like a vertical bar.

Choosing lines: addresses, d, p and friends

Any command can have an address in front of it, which chooses the lines it works on. Without an address the command runs on every line.

AddressSelectsExample
3line 3sed '3d'
$the last linesed -n '$p'
/regex/lines matching the regexsed '/^#/d' drops comment lines
2,5lines 2 to 5sed -n '2,5p'
/start/,/end/from a line matching start to the next line matching endsed '/BEGIN/,/END/d'
addr!every line NOT selectedsed '/maths/!d' keeps maths lines
CommandWhat it doesExample

/WARN/,/ravi/d deletes a block from the WARN line down to the line with ravi. sed -n '$=' prints the number of the last line, which is the line count.
Every sed command can be aimed at certain lines with an address. A number picks that line, and a dollar sign picks the last one. A regular expression between slashes picks every line that matches. Two addresses with a comma make a range, for example from the line containing BEGIN to the line containing END, which is perfect for removing a whole block from a configuration file. An exclamation mark after the address flips it, so the command runs on all the other lines. The commands themselves are short letters. d deletes the line, p prints it, q stops sed early, and i, a and c insert, append or change whole lines. A very common pair is dash n with p. Dash n turns off the automatic printing, and p prints only the lines you chose, which makes sed work like grep, but with ranges and line numbers as well.

Editing files in place: sed -i

sed normally writes to stdout. sed -i writes the result back into the file instead. GNU sed does this by writing a temporary file and renaming it over the original, so the old content is gone unless you ask for a backup.

CommandWhat it doesExample
sed -i 's/a/b/' FILEChange FILE in place (GNU sed)sed -i 's/8080/9090/' app.conf
sed -i.bak 's/a/b/' FILEChange FILE and keep the original as FILE.baksed -i.bak 's/old/new/' site.conf
sed -i '' 's/a/b/' FILEThe same on macOS and BSD, where -i needs a suffix argument (empty here)sed -i '' 's/x/y/' f
sed -i '/^#/d' FILEDelete all comment lines from FILEsed -i '/^#/d' list.txt

The .bak file holds the version from before the change. Two -e scripts run one after the other on each line.
A safe routine for editing real configuration files
  1. Run the sed command without -i first and read the output.
  2. Check that only the intended lines changed, for example with diff: sed 's/a/b/' f | diff f -.
  3. Run it again with -i.bak, so a copy of the original remains.
  4. Test the service, then delete the .bak file when you are happy.
When you are sure the output is right, dash i makes sed write the change back into the file itself. GNU sed does this safely by writing a new file and renaming it over the old one, but the old content is then gone. So it is good practice to write dash i dot bak, which keeps a copy of the original next to it. Watch out for one difference between systems. On macOS and BSD, dash i must be followed by a suffix, so people write dash i and an empty pair of quotes there. A script written on Linux can therefore fail on a Mac. Professionals use a simple routine: run the command without dash i, compare the result, then run it again with a backup, and test the service before removing the backup. That habit has saved many production servers.
Lesson 5 of 5

sed from school to research

One idea, four depths

sed changes text line by line. s/old/new/ replaces the first match, s/old/new/g every match, d deletes lines, -n with p prints chosen lines, and -i saves the change into the file.

sed applies a script to each input line in the pattern space. Commands take zero, one or two addresses (line numbers, $, regular expressions, ranges, negation). The s command supports flags g, p, N and I, & and back references, and -E selects extended regular expressions.

Besides the pattern space sed has a hold space, a second buffer. h and H copy or append the pattern space to it, g and G copy it back, x swaps them, and N appends the next input line. With branches (b, t, labels) sed is Turing complete: people have written a calculator and even games in it. GNU sed -i writes to a temporary file in the same folder and renames it, so the file gets a new inode and hard links to the old one keep the old content.

sed belongs to the family of line based editors that started with QED and ed in the 1960s and 1970s. Structural regular expressions (Rob Pike, 1987, used in the sam editor) generalised the idea from lines to arbitrary text structure. Research on program synthesis, such as FlashFill in Excel (Gulwani, 2011), learns such text transformations from a few examples instead of a hand written script.

Real world scenario: the domain move

A company moves its website from http to https and from old.example.com to example.com. An engineer previews the change on 300 HTML files with grep -rl old.example.com site/ | xargs sed -n 's|http://old.example.com|https://example.com|gp', checks the result, then runs the same with sed -i.bak. Five minutes of work instead of opening 300 files by hand.

Most people only ever use the substitute and delete commands of sed, but there is more inside. Besides the pattern space, sed has a second buffer called the hold space, where it can keep text while it reads further lines. With commands that copy between the two buffers and simple jumps, sed can carry out any computation at all. Hobbyists have written a calculator and even small games in it, just to prove the point. A practical detail matters for system administrators: sed dash i writes a fresh file and renames it, so the edited file is technically a new file. sed comes from a long line of editors that started with QED and ed in the nineteen sixties and seventies. Today researchers go a step further with programs that learn a text transformation from just a few examples, like the Flash Fill feature in Excel, created by Sumit Gulwani at Microsoft Research.
