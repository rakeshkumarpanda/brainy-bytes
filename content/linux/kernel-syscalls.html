User space, kernel space and the system call

The kernel is the one program that runs with full control of the hardware. Everything else, from bash to a web browser, runs in user space with limited rights. When a program needs anything the kernel controls, it makes a system call.

The kernel managesWhat that meansSystem calls you meet
processesstarts and stops programs and shares the CPUs between themfork, execve, wait4, exit_group, kill
memorygives each process its own address spacemmap, brk, munmap
filesone tree of names over many file systems (the VFS)openat, read, write, close, stat
devicesdrivers for disks, network cards, keyboardsioctl, plus read and write on device files
networkingTCP/IP, sockets, the firewallsocket, connect, accept, sendto
securityusers, permissions, capabilities, namespacessetuid, capset, unshare
What happens in one call such as read()
  1. The program calls read(fd, buf, n), a normal C function in the C library (glibc on Ubuntu).
  2. glibc puts the system call number and the arguments in CPU registers and runs the syscall instruction. The CPU switches to kernel mode.
  3. The kernel checks the arguments (is fd open, may this process write to buf), does the work, and puts the result in a register.
  4. The CPU returns to user mode. On error the kernel returns a negative number, and glibc turns it into -1 plus a code in the variable errno.
The kernel is the heart of the operating system, and the only program with full control of the hardware. All other programs run in user space with limited rights, so they cannot touch the disk, the network or the screen directly. Instead they ask the kernel with a system call, such as open, read, write or fork. The C library wraps each system call in a normal function, and a special C P U instruction switches into the kernel and back. If something goes wrong, the call returns minus one and sets an error code called errno, for example E N O E N T for a missing file. These are the codes behind messages you see every day. EPERM and EACCES both mean “not allowed”: EPERM for actions only privileged processes may do, EACCES for missing file permissions. The full list is in man 3 errno, and the numbers are the same in every language.
Remember
strace slows a program down a lot, because the kernel stops it at every call. Use it to find out what a program does, not to measure how fast it is. On production servers, perf trace or eBPF tools such as opensnoop from bpfcc-tools watch the same calls with much less cost.
Strace shows every system call a program makes, with its arguments and its result. That makes it one of the best debugging tools on Linux, because programs cannot hide what they ask the kernel. With dash e trace, you pick which calls to see, for example only file calls. Dash f follows child processes, dash c counts the calls, and dash o writes the trace to a file. In the demo, a script only says no config found. Strace shows the two exact paths it looked for, both ending in E N O E N T, no such file. That is how admins find missing config files, libraries and certificates in minutes instead of hours.

/proc and /sys: the kernel as files

The kernel shows its own state as files. /proc (procfs) has a folder for every process and many system-wide files. /sys (sysfs) has the devices, drivers and kernel objects. The files take no disk space: the kernel writes their content at the moment you read them.

PathWhat it shows
/proc/PID/statusname, state, parent, user ids, memory, capabilities of a process
/proc/PID/cmdline, environthe command line and the environment, separated by NUL bytes
/proc/PID/fd/one link per open file descriptor
/proc/PID/cwd, exelinks to the current folder and the program file
/proc/selfa link to the folder of whoever reads it
/proc/meminfo, loadavg, uptimememory, load average, seconds since boot (free, uptime and top read these)
/proc/cmdlinethe kernel command line from the boot loader
/proc/sys/kernel settings, the same as sysctl names with dots instead of slashes
/sys/class/net/, /sys/block/network interfaces and block devices with their properties

/proc/self is a different folder for every reader. When grep reads it, the status is grep’s own: its name, state R (running), its process id and its parent, the shell. ls shows its own open descriptors: 0, 1 and 2, plus 3 for the folder it is reading. Here 0, 1 and 2 are a socket and pipes, because this page is built by a program, not in a terminal. In a terminal all three point to /dev/pts/N. cmdline separates the words with NUL bytes, which xargs -0 reads. pid_max is the highest process id before numbers start again from the bottom. The build container uses the kernel default 32768, while Ubuntu 24.04 raises it to 4194304 at boot with /usr/lib/sysctl.d/50-pid-max.conf.

The kernel publishes its state as files, so you can read it with cat. Slash proc has a folder for every running process, named after its process id. Inside are the status, the command line, the open file descriptors and links to the program and its current folder. Slash proc slash self always points to the process that reads it. Slash proc also holds system wide files such as meminfo and loadavg, which is where free, uptime and top get their numbers, and slash proc slash sys holds the kernel settings that sysctl changes. Slash sys describes devices and drivers, for example one folder per network interface with its M T U and its state. None of these files exist on a disk: the kernel writes their content at the moment you read them.

How Linux grows without a reboot
  1. Linux is a monolithic kernel: drivers and file systems run inside the kernel, in kernel space. To keep the kernel small, most of them are built as loadable modules, files ending in .ko (or .ko.zst, compressed) under /lib/modules/$(uname -r)/.
  2. When the system finds new hardware, udev asks the kernel to load the matching module. modprobe looks the name up in modules.dep and loads the modules it depends on first.
  3. Settings for a module go in a file in /etc/modprobe.d/, such as options kvm_intel nested=1. A blacklist NAME line stops automatic loading.
  4. The kernel package (linux-image on Ubuntu) brings the kernel and its modules for one release. Old releases stay installed until apt autoremove, so you can boot an older one from the GRUB menu if a new one fails.

Remember
Kernel messages are key in a crisis: “Out of memory: Killed process”, I/O errors from a failing disk, a driver that crashed. dmesg shows them since boot. On Ubuntu reading it needs sudo (kernel.dmesg_restrict = 1). journalctl -k -b -1 shows the kernel messages of the boot before, which helps after a crash.
Linux is a monolithic kernel, which means drivers and file systems run inside the kernel itself. To stay small, most of them are loadable modules, files ending in dot k o that the kernel loads when it needs them. Lsmod lists the loaded modules, modinfo describes one, and modprobe loads a module together with the modules it depends on. Files in slash etc slash modprobe dot d give options or blacklist a module, and files in modules load dot d load modules at every boot. Uname dash r shows the kernel release you are running, and the kernel log, read with dmesg or journalctl dash k, shows what drivers and disks have been doing, including out of memory kills.

Practice: explore the kernel through /proc

Use /proc to answer questions about the practice server and about your own shell.

Time to explore the kernel yourself. Print the kernel release and the version line, and the boot options the kernel received. Count the C P Us, find the total memory in meminfo and read the load averages. Then look at processes: print the process id of your shell, read the status of slash proc slash self, and list the open file descriptors of your shell, including two five five, which bash keeps for itself. Finally, see which program reads slash proc slash self slash exe, and how high process ids can go.
Lesson 6 of 6

The kernel from school to research

One idea, four depths

The kernel is the boss of the computer: it decides which program runs, keeps programs from touching each other’s memory, and talks to the hardware. Programs ask it for help with system calls.

Use strace to see what programs ask for, read process and system state in /proc, devices in /sys, settings with sysctl, and manage modules with modprobe. Read the kernel log after crashes and keep at least one older kernel installed.

Kernel and platform teams build their own kernels with extra patches, tune scheduler and memory settings, use live patching (Canonical Livepatch, kpatch) to fix security holes without a reboot, and observe production with perf and eBPF tools such as bpftrace. Container platforms rely on namespaces, cgroups and seccomp filters that limit which system calls a program may make.

Research looks at new kernel designs (microkernels such as seL4, which is formally verified, unikernels and library operating systems), Rust in the Linux kernel (merged in 6.1), io_uring, which queues system calls in shared memory to avoid the cost of crossing into the kernel, and the security of the user and kernel border after attacks such as Meltdown and Spectre.

Real world scenario: the program that hung at start-up

After a move to new servers, an in-house reporting tool hung for exactly 30 seconds every time it started, and then worked. Its logs showed nothing. An admin ran it under strace -f -tt -e trace=network and saw a connect() to an old licence server address that no longer existed, which waited until the timeout. The address came from a forgotten line in /etc/hosts. Fixing that line made the tool start in under a second.

Here is how understanding the kernel grows. At school you learn that the kernel is the boss of the computer, and that programs ask it for help. Professionals use strace, slash proc, slash sys, sysctl and the kernel log every week to find out why something fails. Platform teams patch kernels while they run, observe production servers with e B P F, and limit which system calls containers may make. Researchers design verified microkernels, bring the Rust language into Linux, and invent faster ways to cross the border between programs and the kernel, such as io uring.
