Disks, partitions and their names

Linux shows every disk as a block device, a file in /dev that programs read and write in blocks. A disk is split into partitions, and each partition usually holds one file system, the structure that turns raw blocks into folders and files.

truncate makes a 1 GB sparse file that uses no space until something is written, which is why du reports 0. losetup -f picks the first free loop device and --show prints its name, which the script keeps in a variable. From then on that device behaves like a 1 GB disk, so you can practise partitioning and formatting without touching a real one. losetup -d detaches it again.
Common mistake
Names like sda and sdb follow the order in which the kernel finds the disks, and that order can change when a disk is added or a USB stick is plugged in. Never rely on them in configuration. Use the UUID or LABEL of the file system, which blkid shows, or the links in /dev/disk/by-uuid and /dev/disk/by-id.
Linux treats every disk as a block device, a special file in slash dev. SATA and USB disks are called s d a, s d b and so on. NVMe drives have longer names, such as n v m e zero n one, and their partitions add a p and a number. Virtual machines often show v d a, and SD cards show m m c b l k zero. A disk is divided into partitions, and each partition holds a file system, which organises the raw blocks into folders and files. Lsblk draws the tree of disks and partitions, and lsblk dash f adds the file system type, the label and the U U I D, a unique ID written when the file system was made. Device names can change when you add a disk, so configuration should always use the U U I D or the label instead. A loop device lets a normal file act like a disk, which is perfect for safe practice.

Partition tables: MBR, GPT and parted

The first sectors of a disk hold a partition table, a list that says where each partition starts and ends. There are two kinds.

MBR (msdos)GPT
Age1983, IBM PCpart of the UEFI standard, around 2000
Partitions4 primary, or 3 plus an extended one that holds logical partitions128 by default
Largest disk2 TiB with 512 byte sectors (sector numbers are 32 bit)far beyond any real disk (64 bit sector numbers)
Safetyone copy at the start of the diska backup copy at the end of the disk, with checksums
Boots withBIOSUEFI (needs an EFI System Partition), and BIOS through GRUB

Common mistake
mklabel replaces the whole partition table, and the partitions on the disk are lost with it. Check the device name twice with lsblk before you run it, especially when a USB stick and a data disk have similar sizes.
Before a disk can hold files, it needs a partition table, a small list at the start of the disk that says where each partition begins and ends. The old format is called M B R or msdos. It allows only four primary partitions and cannot use more than two tebibytes. The modern format is G P T. It allows one hundred and twenty eight partitions, works with huge disks, and keeps a backup copy at the end of the disk. U E F I computers boot from G P T disks. The tool parted creates the table with mklabel and adds partitions with mkpart, a name, a type hint, a start and an end. Starting the first partition at one mebibyte keeps it aligned for fast S S D access. Be very careful, because mklabel erases the old table. Always check the device name with lsblk first.

Making a file system: ext4, xfs and vfat

A new partition is just empty blocks. mkfs writes a file system onto it: a superblock with the settings, an inode table where each file gets one inode (its owner, mode, size and block list), the blocks for the data, and on ext4 and xfs a journal that keeps the file system consistent after a crash.

File systemUse it forGood to know
ext4the default on Debian and Ubuntu, a safe choice for most diskscan grow and shrink (shrink only while unmounted). 5 percent of blocks are reserved for root by default
xfsthe default on RHEL, Rocky and Fedora Server, large files and big parallel workloadscan grow while mounted, but can never shrink
vfat (FAT32)USB sticks and the EFI System Partition, readable by every systemno Linux owners or permissions, and no single file of 4 GiB or more
exfatlarge USB drives and SD cards shared with Windows and macOSno 4 GiB file limit
btrfssnapshots, checksums and compression (default on Fedora Workstation and openSUSE)more features, more to learn
swapnot a file system: space for memory pages, made with mkswap (chapter 3.2)
CommandWhat it doesExample
mkfs.ext4 -L LABEL DEVext4 with a labelsudo mkfs.ext4 -L data /dev/sdc1
mkfs.xfs -L LABEL DEVxfs (labels up to 12 characters)sudo mkfs.xfs -L logs /dev/sdc2
mkfs.vfat -F 32 -n LABEL DEVFAT32 for a USB stick or the EFI partitionsudo mkfs.vfat -F 32 -n USB /dev/sdb1
tune2fs -l DEVRead the settings of an ext file systemsudo tune2fs -l /dev/sdc1 | less
tune2fs -L NAME, -m PERCENTChange the label, change the reserved spacesudo tune2fs -m 1 /dev/sdc1

On a big data disk, tune2fs -m 1 gives most of that space back.
A partition holds nothing until you make a file system on it with mkfs. The file system writes a superblock with its settings, a table of inodes, where every file gets one inode that stores its owner, permissions, size and where its data is, and on modern file systems a journal that keeps everything consistent after a power cut. Ext4 is the default on Ubuntu and a safe choice. X F S is the default on Red Hat systems and is great for large files, but it can never be made smaller. V fat, also called FAT32, works on every computer, which is why USB sticks and the E F I boot partition use it, but it has no Linux permissions and cannot store a file of four gibibytes or more. Give each file system a label with dash capital L, so you can recognise it later. Ext4 reserves five percent of the space for root, which you can change with tune2fs.

Mounting: attaching a file system to the tree

Linux has one tree of folders that starts at /. A file system becomes visible only when it is mounted on a folder, the mount point. From then on every path under that folder leads into the file system. Whatever the folder held before is hidden until the file system is unmounted.

CommandWhat it doesExample
mount DEV DIRMount a file system (the type is detected)sudo mount /dev/sdb1 /mnt/usb
mount -o OPTIONSMount with options: ro, noexec, nosuid, nodev, noatimesudo mount -o ro /dev/sdb1 /mnt/usb
mount -o remount,rw /Change the options of a mounted file systemsudo mount -o remount,ro /data
umount DIRUnmount (the command is umount, with no n)sudo umount /mnt/usb

Remember
Unmount a USB stick before you pull it out. Linux keeps writes in memory for a short while, and umount (or the eject button of a desktop) makes sure they reach the stick.
Windows gives each disk a letter, such as D colon. Linux has a single tree that starts at the root, slash, and every other file system is attached to a folder somewhere in it. This is called mounting, and the folder is the mount point. Run sudo mount, the device and the folder, and from then on every path under that folder leads into the device. Anything the folder held before is hidden, not deleted, and comes back after you unmount. Df dash h T shows the size and type of each mounted file system, and findmnt shows the mount tree. To detach a file system, use umount, spelled without the letter n. It fails with target is busy while a program has a file open there or a shell is inside the folder. Fuser dash v m tells you who is using it. Try the animation to watch a folder change when a USB stick is mounted on it.

Mounting at boot with /etc/fstab

A mount made by hand is gone after a reboot. Lines in /etc/fstab tell the system what to mount at boot. systemd reads the file and makes a mount unit for each line.

A line of /etc/fstabThe general form
UUID=36cdba49-be45-4fa8-a8bb-106f1ceb90ef  /data  ext4  defaults,noatime  0  2
   (1) what to mount                       (2) where (3) type (4) options (5) dump (6) fsck order
Fields are separated by spaces or tabs, and lines starting with # are comments.
FieldMeaningCommon values
1 fs_specthe file systemUUID=..., LABEL=data, /dev/sdc1 (avoid), server:/export for NFS
2 fs_filethe mount point/data, or none for swap
3 fs_vfstypethe typeext4, xfs, vfat, swap, nfs, auto
4 fs_mntopsoptions, separated by commasdefaults (rw, suid, dev, exec, auto, nouser, async), noatime, ro, nofail, noauto, x-systemd.automount
5 fs_freqused by the old dump backup toolalmost always 0
6 fs_passnoorder for fsck at boot1 for /, 2 for other local file systems, 0 to skip
Add a disk to /etc/fstab safely
  1. Find the UUID with sudo blkid /dev/sdc1 and create the mount point with sudo mkdir /data.
  2. Add the line with an editor, or append it with echo "UUID=... /data ext4 defaults 0 2" | sudo tee -a /etc/fstab.
  3. Check the file with sudo findmnt --verify.
  4. Run sudo systemctl daemon-reload so systemd reads the new file, then sudo mount -a to mount everything that is not mounted yet.
  5. Confirm with findmnt /data. Only reboot after these checks pass.

--tab-file checks a file other than /etc/fstab, which is handy for testing. One wrong character in the UUID is an error, because the system could not find the disk at boot. Writing xfs for an ext4 file system is a warning. Only the summary line goes to standard error, which is why it may print first here.
Common mistake
A broken line in /etc/fstab can stop the boot and drop the machine into emergency mode (chapter 2.1). Add nofail for disks that may be missing, such as USB drives and network shares, and always test with findmnt --verify and mount -a before you reboot a server you cannot reach physically.
Mounts you make by hand disappear at the next reboot. To mount a file system every time the machine starts, add a line to slash etc slash f s tab. Each line has six fields. The first says what to mount, and the best choice is U U I D equals and the U U I D from blkid, because device names can change. The second is the mount point, the third the type, such as ext4. The fourth holds options separated by commas, and defaults is a good start. Noatime saves writes, and nofail lets the boot go on if the disk is missing. The fifth field is almost always zero, and the sixth sets the order of the file system check at boot: one for the root file system, two for the others, zero to skip. After editing, check the file with findmnt dash dash verify, reload systemd, and run mount dash a. A typo here can stop the next boot, so never skip the check.

Making the image file larger is like growing a virtual disk in the cloud. resize2fs then grows the file system into the new space, from 131072 to 262144 blocks.
Grow the root disk of a cloud server
  1. Increase the volume size in the cloud console.
  2. Check that the kernel sees the larger disk with lsblk.
  3. Grow the partition with sudo growpart /dev/vda 1.
  4. Grow the file system: sudo resize2fs /dev/vda1 for ext4 or sudo xfs_growfs / for xfs. Both work while mounted.
  5. Confirm the new size with df -h /.
Common mistake
Never run fsck on a mounted file system: repairs made under a running system can destroy data. e2fsck refuses, and the root file system is checked at boot instead, when fs_passno in /etc/fstab is 1.
File systems can be checked and repaired with fsck, which calls the right tool for each type, such as e2fsck for ext4 or x f s repair for X F S. It must only run on a file system that is not mounted, because repairing files while programs use them can destroy data. Dash n checks without changing anything. The boot runs the check for you on file systems whose last field in f s tab is one or two. Disks fill up over time, and in the cloud you can simply make a disk larger. After that, grow the partition with growpart, and then grow the file system, with resize2fs for ext4 or x f s growfs for X F S. Both work while the system is running. Smartctl reads the health counters a disk keeps about itself, which can warn you before it fails.
Lesson 7 of 8

Practice: set up a new data disk in the practice shell

The practice server has a new, empty 20 GB disk, /dev/sdc, and a USB stick. Partition and format the disk, mount it at /mnt/data, and make the mount survive a reboot.

Time to do the job an admin does whenever a new disk arrives. First look at the disks with lsblk dash f, and find the empty one, s d c. Give it a G P T table and one partition that fills the disk, using parted. Check the new partition with lsblk, then make an ext4 file system on it with the label data. Create the mount point and mount it, and check the free space with df. To make the mount permanent, add a line to f s tab that uses the label, verify the file with findmnt, then unmount and run mount dash a, which mounts everything listed in f s tab. If findmnt shows the disk again, the next reboot will mount it too.
Lesson 8 of 8

Storage from school to research

One idea, four depths

A disk is split into partitions, each with a file system, and Linux shows them all in one tree starting at /. lsblk shows the disks, df -h shows the free space, and a USB stick must be unmounted before you pull it out.

Partition with GPT, use ext4 or xfs, mount by UUID in /etc/fstab with nofail for optional disks, and test with findmnt --verify. Watch free space and inodes, and grow cloud disks with growpart and resize2fs or xfs_growfs. Put data that grows, such as /var/lib/postgresql or /var/log, on its own file system so it cannot fill /.

LVM and RAID make storage flexible and safe (chapter 3.2). Mount options such as noexec, nosuid and nodev harden /tmp and removable media. Network file systems (NFS, SMB) and systemd automount join storage from other machines. Cloud block storage (EBS, Persistent Disk), object storage (S3) and Kubernetes persistent volumes build on the same ideas.

Research looks at how file systems survive crashes and how fast they run on new hardware: journaling and copy on write designs (ext4, xfs, btrfs, ZFS), log-structured file systems for flash (F2FS), and testing tools that crash file systems on purpose to find bugs. Studies of disk failures in large data centres, such as the drive statistics Backblaze publishes, show why every serious setup has redundancy and backups.

Real world scenario: the server that would not boot after a new disk

An admin added a data disk, wrote /dev/sdb1 /data ext4 defaults 0 2 into /etc/fstab and rebooted. A USB stick was also plugged in, the kernel named the data disk sdc instead, and the boot stopped in emergency mode because /dev/sdb1 was the stick, with a vfat file system. The fix was a line with UUID= from blkid and the nofail option, a check with findmnt --verify, and a team rule to test every fstab change with mount -a before a reboot.

Here is how storage work grows with experience. Beginners learn that disks hold partitions with file systems, all joined in one tree, and that lsblk and df show what is there. Professionals partition with G P T, mount by U U I D, add nofail for disks that may be missing, test every change to f s tab, and keep fast growing data on its own file system so the root disk never fills up. Larger systems use L V M and RAID for flexible and safe storage, harden mounts with options like noexec, and use network and cloud storage. Researchers study how file systems survive crashes and run on flash memory, and large studies of failing disks remind everyone that backups are never optional.
