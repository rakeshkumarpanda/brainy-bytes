Lesson 1 of 5

Lines, fields and the pattern { action } idea

awk is a small programming language made for text in columns. It reads its input one record (normally one line) at a time and splits it into fields. Then it runs your program, which is a list of pattern { action } rules.

$0Exam favourite
the whole line
$1 is the first field, $2 the second, $NF the last one.
NR and NF
counters
NR is the number of the current line (record), NF the number of fields in it.
-F,Exam favourite
field separator
Default: runs of spaces and tabs. -F, splits at commas, -F: at colons.
pattern { action }
a rule
If the pattern is true for a line, the action runs. No pattern: every line. No action: print the line.

The comma in print puts a space (the output separator) between values. Without the comma, values are glued together.
Remember
Unlike cut, awk treats several spaces in a row as one separator, so it handles the columns of ps, df or ls -l output without trouble.
awk is named after its three authors, Alfred Aho, Peter Weinberger and Brian Kernighan, who wrote it at Bell Labs in 1977. It is a complete little programming language, but you can start using it in seconds. awk reads text one line at a time, splits each line into fields, and calls them dollar one, dollar two and so on, with dollar zero for the whole line. So awk with print dollar one prints the first column of anything. A program is a list of rules. Each rule is a pattern followed by an action in curly braces. If the pattern is true for a line, the action runs. Leave out the pattern and the action runs on every line. Leave out the action and awk simply prints the matching lines. Unlike cut, awk treats several spaces in a row as a single separator, which is exactly what the output of commands like ps and df needs.

$3 == 0 compares the user ID field with 0, the superuser.
Remember
awk compares two values as numbers when both look like numbers (fields count as "looks like a number" when their text is numeric), and as text otherwise. So $3 >= 80 compares scores numerically, while $1 == "Asha" compares text.
Patterns decide which lines an action runs on. The most useful ones are comparisons, such as dollar three greater or equal to eighty, which keeps only the rows with high scores. A regular expression between slashes keeps lines that match, just like grep, and the tilde operator tests a single field against a regex. NR greater than one is the classic way to skip a header line. Two special patterns run outside the normal loop. BEGIN runs once before any input is read, which is the place to print a heading or set options. END runs once after the last line, which is where totals and averages are printed. With these few pieces you can already answer most questions about a log file or a spreadsheet export.

Variables start as 0 (or empty text), so sum += $3 needs no setup. An array such as count[$2] uses text as the index. The order of for (k in array) is not fixed, which is why the output goes through sort.
Going deeper: printf formats in one table

%s text, %d whole number, %f decimal (%.2f two decimals), %e scientific, %x hexadecimal, %c one character, %% a percent sign. A number after % sets the width, - aligns left, 0 pads with zeros: %-10s, %05d, %8.2f. printf never adds a newline by itself, so end the format with \n.

awk really shines when you need numbers from text. Variables start at zero automatically, so adding up a column is one short rule: for every line, add dollar three to sum, and in the END block print it. Divide by the number of lines and you have an average. Keep the largest value seen so far and you have a maximum. The most powerful feature is the associative array. An array in awk can use any text as its index, so count of dollar two plus plus counts how many rows each subject has, in a single pass over the file. This is the same idea as a group by in SQL or a pivot table in a spreadsheet. For neat reports, printf lets you set widths and decimal places, for example percent minus ten s for a left aligned name and percent five point one f for a number with one decimal.

cond ? x : y picks x when cond is true. Assigning a field ($1 = $1) makes awk rebuild the line with OFS. gsub replaces every match in the line, like sed s///g.
Remember
Ubuntu and Debian install mawk as awk, many other distributions use GNU awk (gawk), and macOS uses the original "one true awk". Everything in this chapter works in all of them. gawk adds extras such as asort(), strftime() and --csv for quoted CSV fields.
As your tasks grow, awk grows with you. It has if and else, while and for loops, its own functions, and built in functions for text such as length, substr, split and gsub. Longer programs are best kept in a file and run with dash f, so they can be read, tested and stored in version control. Use dash v to pass a value from the shell into awk, rather than gluing shell variables into the program text, because that is safer and easier to read. One detail can surprise you: assigning to a field, even dollar one equals dollar one, makes awk rebuild the whole line using the output separator OFS, which is a neat way to turn commas into tabs. Different systems ship different awk programs, mawk on Ubuntu, GNU awk on many others, and the original version on macOS, but everything in this chapter works in all of them.
Lesson 5 of 5

awk from school to research

One idea, four depths

awk splits each line into numbered columns. print $1 shows the first column, a pattern such as $3 > 50 chooses lines, END prints totals at the end, and arrays count things per group.

An awk program is a sequence of pattern action pairs applied to each record. Fields split by FS, variables are untyped (string or number by context), arrays are associative, and BEGIN and END run outside the input loop. Comparisons are numeric when both sides are numeric strings.

Implementations compile the program to an internal tree or byte code. mawk (Mike Brennan) is known for speed, gawk adds network sockets, profiling, namespaces and arbitrary precision with -M. Splitting records is the hot path, so fast implementations avoid creating fields that the program never reads. For very large files awk is often limited by disk speed, not by the CPU.

awk inspired Perl (Larry Wall, 1987) and the idea of "little languages" described by Jon Bentley in 1986. The second edition of The AWK Programming Language (2023) added UTF-8 and CSV support to the one true awk. Data tools such as Miller, xsv and DuckDB command line queries continue the idea of querying text tables directly, now with typed columns and SQL.

Real world scenario: the disk alert

A monitoring alert says a disk is almost full. The engineer runs df -P | awk 'NR>1 && $5+0 > 80 {print $6, $5}' to list every file system above 80 percent use, then du -sk /var/log/* | sort -n | tail -n 5 to find the biggest logs. $5+0 turns "85%" into the number 85.

awk turned out to be far more influential than its authors expected. Larry Wall created Perl in 1987 partly to go beyond what awk and sed could do, and Jon Bentley used awk as the main example when he wrote about little languages, small special purpose languages that solve one kind of problem very well. Inside, every awk reads the program, turns it into an internal form and then runs it once per line. The mawk version used on Ubuntu is known for its speed, while GNU awk adds features such as network connections and arbitrary precision numbers. Remarkably, the original authors were still improving it decades later. The second edition of their book, published in 2023, added proper support for UTF-8 text and CSV files. Modern tools such as Miller and DuckDB continue the same idea of asking questions directly of text tables.
