The manual: man pages

Every Linux system carries its own manual. Type man followed by a command name and you get its manual page: what it does, every option, examples and related commands. It works without internet, and it describes the exact version installed on that machine.

Open the manual page of lsTypical output, yours will differ
man ls
LS(1)                         User Commands                         LS(1)

NAME
       ls - list directory contents

SYNOPSIS
       ls [OPTION]... [FILE]...

DESCRIPTION
       List  information  about  the FILEs (the current directory by default).
       Sort entries alphabetically if none of -cftuvSUX nor --sort is specified.

       -a, --all
              do not ignore entries starting with .
This build machine has no manual pages installed, so this is how the top of the page looks on Ubuntu 24.04. The (1) means section 1, user commands.

The page is shown by a pager, usually less, which is why the keys are the same as in less.

HeadingWhat you find there

SYNOPSISHow to call it. [ ] means optional, ... means can repeat, so ls [OPTION]... [FILE]... means zero or more options then zero or more files

The Unix manual is older than most of the commands in it. The first edition of the Unix Programmer’s Manual was written by Ken Thompson and Dennis Ritchie in November 1971, and it already had a page for every command, with a name, a synopsis and a description, exactly the layout you still see today. When Unix spread to universities, the manual came on the same tape, so every machine carried its own documentation. That habit is very useful. A web page might describe a newer or older version of a command, but the man page on the machine describes exactly the version installed there. Engineers who work on servers without internet access depend on it. Learn four keys and you can read any page: Space to go down, slash to search, n for the next match, and q to quit.

Manual sections and searching the manual

The manual is split into numbered sections, because the same name can mean different things. passwd is a command you run, and it is also a file format.

SectionContainsExample
1User commandsls(1), passwd(1)
2System calls, the kernel’s servicesopen(2), fork(2)
3Library functions, mostly Cprintf(3)
4Special files, usually in /devnull(4)
5File formats and configuration filespasswd(5), crontab(5)
6Gamesfortune(6)
7Overviews and conventionsman-pages(7), signal(7), regex(7)
8System administration commands, usually for rootmount(8), useradd(8)
A page from one sectionExam favourite
man 5 passwd
Without the number, man shows the first section that has the page, here passwd(1), the command.
Search page descriptionsExam favourite
man -k word = apropos word
Lists every page whose NAME line contains the word, with its section.
One line summary
whatis ls = man -f ls
Prints only the NAME line.
Find commands when you do not know their nameTypical output, yours will differ
apropos "copy files"
cp (1)               - copy files and directories
cpio (1)             - copy files to and from archives
install (1)          - copy files and set attributes
rsync (1)            - a fast, versatile, remote (and local) file-copying tool
apropos searches a small database that is rebuilt by mandb, usually every day. On a fresh system run sudo mandb once if apropos finds nothing.
In the exam
When people write ls(1) or crontab(5) in a book or chat, the number is the manual section. Read crontab(5) as: run man 5 crontab.
The idea of numbered sections comes straight from the printed Unix manuals of the 1970s, which were real books with chapters. Chapter one held the commands, chapter two the system calls, chapter three the library functions, and so on. When the manual moved onto the computer, the numbers stayed. They are still useful, because one word can name different things. For example, passwd is a command that changes your password, and it is also the file slash etc slash passwd, which lists the users. man passwd shows the command, man 5 passwd shows the file format. The other great trick is searching. If you remember what you want to do but not the name of the command, apropos looks through the one line descriptions of every page. Typing apropos copy shows cp, rsync and other tools you may never have heard of.

Quick help: --help, help, info and tldr

A full manual page is long. Often you only need a reminder.

CommandWhat it doesExample
COMMAND --helpPrints a short summary of the options straight into the terminal. Almost every GNU program has it.ls --help | head
help BUILTINHelp for commands built into bash, which have no man page of their ownhelp cd
COMMAND --versionShows which version you have, useful before you read a web page about itls --version
info COMMANDThe GNU manual, longer and with chapters and links. Move with Tab and Enter, q quitsinfo coreutils
tldr COMMANDCommunity written short examples (install the tldr client first)tldr tar
Quick help, run for realRun for real on Linux while this page was built
ls --help | head -n 4
Usage: ls [OPTION]... [FILE]...
List information about the FILEs (the current directory by default).
Sort entries alphabetically if none of -cftuvSUX nor --sort is specified.
help cd | head -n 3
cd: cd [-L|[-P [-e]] [-@]] [dir]
    Change the shell working directory.
    
ls --version | head -n 1
ls (GNU coreutils) 9.4
The GNU coding standards ask every GNU program to support --help and --version, which is why they work almost everywhere on Linux.
Remember
help only knows shell builtins (cd, echo, export, type, history). For a builtin, man cd usually opens the long bash manual instead, so try help first.
Common mistake
Options that work on Linux may not work on macOS, because macOS uses BSD versions of many tools. When an example from the web fails, check --version and the local man page.
Here is a habit used by experienced engineers. Before typing a command they have not used for a while, they run it with dash dash help and pipe it into head, to see the first few lines of options. It takes two seconds and avoids guesses. The dash dash help and dash dash version options are a promise from the GNU coding standards, written in the 1990s by the Free Software Foundation, so nearly every Linux tool supports them. The help command is different. It explains commands that live inside bash itself, like cd and history. In 2013 a group of volunteers started the tldr pages project, short for too long, did not read, which gives a few practical examples for each command instead of the full manual. It is popular with beginners. A good order to remember is help or dash dash help first, then man, then the web.
Lesson 4 of 5

Getting unstuck, step by step

Here is a routine that solves most "how do I" moments, in order.

From stuck to solved
  1. Do you know the command name? If not, run apropos word with a word that describes the job.
  2. Need a reminder of one option? Run COMMAND --help | less or help COMMAND for a builtin.
  3. Need the full story? Run man COMMAND, press / and type the option or word you need.
  4. Got an error message? Read it slowly. Linux errors usually name the file and the reason, for example "No such file or directory" or "Permission denied".
  5. Still stuck? Search the web with the exact error text in quotes and the name of your distribution, and check that the answer matches your version.
Common errorWhat it meansFirst thing to try
command not foundThe program is not installed, misspelled, or not in PATHCheck spelling, then type, then install the package
No such file or directoryThe path is wrongpwd and ls to see where you are, Tab to complete the name
Permission deniedYou lack the right to read, write or run itls -l to see the permissions, sudo only if it is a system file you mean to change
Is a directoryYou gave a folder to a command that wants a fileUse ls for folders, or the -r option where it exists
Usage: ...The options or arguments are wrongRead the usage line, it is a short SYNOPSIS
Every expert gets stuck. The difference is that they have a routine for getting unstuck. The most important step is the cheapest one: read the error message. Linux error messages are short but precise. No such file or directory almost always means a typo or the wrong folder, and permission denied means the file exists but you are not allowed to touch it. Many beginners skip the message and paste the whole problem into a search engine. Try the manual first. The answers there match your exact version, and you will learn options you did not know about. When you do search the web, put the exact error text in quotation marks and add the name of your distribution, for example Ubuntu 24.04. And check the date of the answer, because a command explained in 2012 may have changed since then.
Lesson 5 of 5

Documentation from school to research

One idea, four depths

Linux has a book of instructions built in. Type man and the name of a command, and it tells you how to use it. Press q to close the book.

Manual pages are grouped into sections (1 commands, 2 system calls, 3 library calls, 5 file formats, 8 admin commands). man -k searches descriptions. Builtins are explained by help, GNU programs answer --help and --version, and info holds longer GNU manuals.

Man pages are written in the roff typesetting language with the man or mdoc macros and rendered by groff or mandoc. mandb indexes them for whatis and apropos. The Linux man-pages project documents the kernel and glibc interfaces in sections 2, 3, 4, 5 and 7, and is the reference for system programmers alongside POSIX.

Research on documentation includes studies of how developers search for help, automatic generation of examples from manuals, checking that documentation matches code behaviour, and using language models to explain commands. Projects such as explainshell map each word of a command line to the matching part of its man page.

Real world scenario: a job interview

An interviewer asks how you would find the option that makes cp keep file times. A strong answer is not a guess: "I would run man cp and search for time with /time, which shows --preserve, or check cp --help." Showing how you find answers is valued as much as remembering them.

Man pages are written in a very old typesetting language called roff, which dates back to the early 1970s and was one of the first programs used at Bell Labs. In fact, the Unix team got money for a new computer partly by promising to build a system for preparing patent documents, and roff was part of that work. Today the Linux man pages project, led for many years by Michael Kerrisk, documents the system calls and library functions of Linux, and programmers around the world rely on it. At the research end, people study how developers search for help, and tools like explainshell take a whole command line and show which part of the manual explains each word. Whatever level you reach, the skill stays the same. Good engineers know how to find a reliable answer quickly, and the manual on the machine is the most reliable place to start.
