Lesson 1 of 6

Terminal, console and shell are three different things

People mix these words up, so let us fix them first.

WordWhat it really isExamples
Terminal (terminal emulator)The window that shows text and sends your key presses. It does not understand commands at all.GNOME Terminal, Konsole, macOS Terminal, Windows Terminal, iTerm2
ShellThe program inside the terminal that reads your command, understands it and starts other programs.bash, zsh, sh (dash on Ubuntu), fish
ConsoleThe screen and keyboard plugged straight into the machine, or the text screens you reach with Ctrl Alt F3 on many Linux desktops.A server room monitor, a virtual console tty3
Command line (CLI)The general idea of working by typing text commands, instead of clicking.Everything in this subject

The name terminal comes from history. In the 1970s a terminal was a real machine with a keyboard and a printer or screen, wired to a big shared computer. The tty you still see in Linux comes from teletypewriter, the printing machines used as the first Unix terminals.

Remember
bash (the Bourne Again SHell) is the default shell on most Linux distributions. macOS switched its default to zsh with macOS Catalina in 2019. The commands in this subject work in both, and scripts are written for bash.
In the 1970s, using Unix meant sitting at a teletype, a noisy machine like an electric typewriter joined to the computer by a cable. You typed a command, and the answer was printed on a roll of paper. Ken Thompson and Dennis Ritchie wrote early Unix on exactly such machines, which is why commands are so short. Typing ls instead of list saved time and paper. Later the paper became a glass screen, and today the screen is a window on your desktop, but Linux still calls these devices tty, short for teletypewriter. The shell is a separate program that runs inside that window. The first Unix shell was written by Ken Thompson, then Stephen Bourne wrote the Bourne shell in 1979, and in 1989 Brian Fox wrote bash for the GNU project. The name means Bourne Again Shell, a little joke about the older shell it replaced.
Lesson 2 of 6

Reading the prompt

When the shell is ready for you, it prints a prompt and waits. A typical bash prompt on Ubuntu looks like this:

PartExampleMeaning
User namelearnerWho you are logged in as
@ and host name@brainyThe name of the computer, useful when you are logged in to several
Colon and folder:~/logsThe folder you are in. ~ is short for your home folder
Last sign$ or #$ for an ordinary user, # for root, the all powerful administrator

So learner@brainy:~/logs$ means: user learner, on computer brainy, in the folder logs inside the home folder, as an ordinary user. The prompt text comes from a shell variable called PS1, so it can be changed. In PS1, \u is the user, \h the host, \w the folder and \$ prints # for root and $ for everyone else.

Find the facts the prompt showsRun for real on Linux while this page was built
whoami
learner
hostname
vm
pwd
/home/learner
echo "$HOME"
/home/learner
The host name here is the name of the machine that built this page.
Common mistake
Seeing # instead of $ means you are root. Every command you type can change or delete anything on the system. Slow down, and leave root as soon as you have finished.
Remember
When you copy commands from a web page, do not copy the $ or # at the start. They are the prompt, not part of the command.
The prompt is the shell saying I am ready, your turn. Engineers who manage many servers rely on it every day. Imagine a person logged in to a test server and a live shop server in two windows at the same time. The only visible difference is the host name in the prompt, and a command meant for the test machine typed into the wrong window can take a real shop offline. Many companies colour the prompt red on production machines for exactly this reason. The last character matters too. A dollar sign means an ordinary user, and a hash sign means root, the administrator who can do anything. Get into the habit of glancing at the prompt before you press Enter, especially before commands that delete or change things. It takes half a second and has saved many careers.
Lesson 3 of 6

The shape of every command

Almost every command line has the same shape:

Command lineExam favourite
command -options arguments
The command is the program to run. Options (flags) change its behaviour and start with - or --. Arguments say what to work on, often file names. Words are separated by spaces.
Short and long options
ls -l -a = ls -la = ls -l --all
Short options are one letter after one dash and can be joined. Long options are whole words after two dashes and cannot be joined.
An option with a value
head -n 3 notes.txt = head -n3 = head --lines=3
Some options need a value right after them.
One command, three spellings of the same optionsRun for real on Linux while this page was built

Spaces matter. ls -la is one option word, but ls - la passes the strange arguments - and la. If a file name contains a space, put it in quotes: cat "my notes.txt", otherwise the shell sees two files called my and notes.txt.

Every command you will ever type follows one simple pattern. First the name of the program, then options that change how it behaves, then the things it should work on. In 1971, the first Unix manual already described commands this way. Options with one dash and one letter come from those early days, when every keystroke was precious. Long options with two dashes, such as dash dash all, were added later by the GNU project because they are easier to read and remember. You can usually use either. One mistake trips up nearly every beginner: file names with spaces. The shell splits a line at spaces, so a file called my notes becomes two separate words. Put such a name in quotes, or better, avoid spaces in file names altogether and use a dash or an underscore instead.
Lesson 4 of 6

Where commands come from: builtins, PATH and type

When you type a command, the shell looks for it in this order: an alias you defined, a shell function, a builtin (a command built into the shell itself, such as cd and echo), and finally a program file in one of the folders listed in the PATH variable, searched from left to right.

Ask the shell what a name meansRun for real on Linux while this page was built
type cd
cd is a shell builtin
type ls
ls is /usr/bin/ls
type -a echo
echo is a shell builtin
echo is /usr/bin/echo
echo is /bin/echo
echo "$PATH"
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
which ls
/usr/bin/ls
cd has to be a builtin: a separate program could only change its own folder, not the shell's. echo exists both as a builtin and as a program, and the builtin wins.
CommandWhat it doesExample
type NAMESays whether NAME is an alias, function, builtin or a file, and wheretype ls
type -a NAMELists every match, in the order the shell would try themtype -a echo
which NAMEPrints the path of the program file found in PATHwhich python3
echo $PATHShows the folders searched for programs, separated by colonsecho $PATH
command -v NAMEPOSIX way to test if a command exists, useful in scriptscommand -v git
Common mistake
If you get "command not found", either the program is not installed, the name is misspelled, or its folder is not in PATH. To run a program in the current folder you must write ./name, because the current folder is not in PATH on purpose.
Going deeper: Why the current folder is not in PATH

If . were in PATH, someone could leave a file called ls in a shared folder like /tmp. The next person to type ls there would run that file instead of the real ls, with their own rights. Leaving . out of PATH and typing ./script makes it explicit that you are running something from here.

Here is a question that surprises people. Where does the command ls actually live? It is not magic inside the terminal. It is an ordinary program file, usually stored in the folder slash usr slash bin, and the shell finds it by searching a list of folders kept in a variable called PATH. A few commands are different. cd, which changes your folder, must be built into the shell itself, because a separate program can only change its own folder, and the change would vanish the moment it finished. The type command tells you which kind each name is. Security people care about PATH too. In the 1980s, a classic trick on shared Unix machines was to leave a fake program in a public folder, hoping someone with more rights would run it by accident. That is why the current folder is deliberately left out of PATH today.

History, Tab completion and shortcuts that save hours

Experienced users rarely type a whole command. They let the shell do the work.

KeysWhat they do
TabCompletes a command or file name. Press it twice to list every choice when there is more than one.
Up and DownWalk back and forward through commands you typed before
Ctrl RSearch your history: type a few letters of an old command, press Ctrl R again for older matches, Enter to run it
Ctrl CStop the program that is running now (sends the interrupt signal)
Ctrl DEnd of input. At an empty prompt it closes the shell
Ctrl LClear the screen, the same as the clear command
Ctrl A and Ctrl EJump to the start or the end of the line
Ctrl U and Ctrl KCut from the cursor to the start, or to the end, of the line
Ctrl WDelete the word before the cursor
!!The whole previous command, for example sudo !! to repeat it as root
!$The last word of the previous command, often a file name
The history listRun for real on Linux while this page was built
# history is on by itself in an interactive shell. This box runs as a script, so it switches it on first
set -o history
echo first
first
echo second
second
history | tail -n 3
    1  echo first
    2  echo second
    3  history | tail -n 3
history numbers every command. !N runs number N again. In an interactive bash the list is saved to ~/.bash_history when the shell exits.
Remember
Tab completion is not only for speed. If Tab does not complete a file name, the file is not where you think it is, so you catch the mistake before pressing Enter.
Bash gets its comfortable editing keys from a library called GNU Readline, written by Brian Fox around 1989, the same person who wrote bash. Many of the shortcuts, like Control A to jump to the start of a line and Control E for the end, come from the Emacs text editor, which was popular with the GNU developers. Control C is even older. It sends an interrupt signal that tells the running program to stop, and it has worked that way on Unix since the 1970s. The history list is a real time saver. Engineers who fix servers at night often press Control R, type three letters, and find the long command they used last month. Learn Tab, the arrow keys, Control R and Control C today. Those four alone will make you twice as fast, and Tab will quietly stop you from typing the wrong file name.
Lesson 6 of 6

The shell from school to research

One idea, four depths

The terminal is a window where you talk to the computer by typing. The shell is the listener inside it. You type a short order, press Enter, and the shell finds the right program, runs it, and shows you the answer.

A shell is a command interpreter and a programming language. It reads a line, splits it into words, performs expansions, looks up the command (alias, function, builtin, PATH), creates a process to run external programs and waits for it, then reports the exit status in $?. bash follows POSIX sh and adds arrays, [[ ]], history and Readline editing.

Under the hood an external command runs through fork() and execve(): the shell clones itself, and the child replaces its program with the one found in PATH, inheriting open file descriptors 0, 1 and 2 connected to the terminal device (a pseudo terminal, /dev/pts/N, managed by the terminal emulator). The kernel tty layer handles line editing in canonical mode and turns Ctrl C into SIGINT for the foreground process group.

Research and engineering topics include shell language semantics and formal specifications of POSIX sh (the Smoosh project, 2020), static analysis of scripts (ShellCheck), safe parallel shell pipelines (PaSh, 2021), new structured shells such as Nushell and PowerShell that pass objects instead of text, and terminal protocols beyond the 1970s VT100 escape codes.

Real world scenario: a night shift fix

A website is slow at 2 am. The on call engineer logs in to a Linux server with SSH, presses Ctrl R to find the command that shows the busiest processes, sees one stuck program, stops it, and the site recovers. No mouse, no desktop, about one minute of typing. This is why the shell is still the main tool for servers.

Why do professionals still type commands when we have beautiful graphical apps? The answer is control and speed. A graphical app shows only the buttons its designers chose. The shell lets you combine any program with any other, repeat a task for ten thousand files, and save your steps as a script that runs again tomorrow. It also works over a slow network connection to a server on another continent, where a graphical desktop would crawl. In 2019 Microsoft built the new Windows Terminal and added a real Linux kernel to Windows through WSL 2, because so many developers wanted a proper Unix shell. At the research end, people now study the shell language formally, build tools that check scripts for bugs before they run, and design new shells that pass structured data instead of plain text.
