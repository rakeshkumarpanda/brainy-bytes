Printing a whole file: cat and friends

cat prints files to the screen. Its name comes from concatenate, which means joining things end to end. Give it two files and it prints the first one followed by the second one, with nothing in between.

Seeing the invisibleRun for real on Linux while this page was built
printf 'one\ttwo\nthree  \n' > odd.txt
cat odd.txt
one	two
three  
cat -A odd.txt
one^Itwo$
three  $
The file holds a tab and two spaces at the end of a line. On screen they look the same as ordinary spaces, but cat -A shows the tab as ^I and puts a $ where each line ends, so the two trailing spaces become visible.
Remember
cat is fine for short files. For a file with thousands of lines the text flies past and only the end stays on screen. Use less for that, as the next lesson shows.
The first command most people learn for reading a file is cat. It sounds like the animal, but it is short for concatenate, which simply means joining things together. Ken Thompson wrote it for the very first version of Unix in 1971, and it has barely changed since. If you give cat one file, it prints that file. If you give it two, it prints them one after the other, which is handy for joining parts of a document. Two small options are worth remembering. Dash n puts a number in front of every line, which helps when someone says the problem is on line forty. Dash capital A shows characters you normally cannot see, such as tabs and spaces at the end of a line. Those invisible characters cause real bugs, for example in configuration files where a tab and a space mean different things.

Reading long files page by page: less

less opens a file one screen at a time and lets you move around and search. It reads only what it needs, so it opens a huge log instantly. It never changes the file. The name is a joke on the older pager more, which could only move forwards: less can do more than more.

Remember
When the output of less goes to a pipe or a file instead of a screen, less behaves like cat and copies everything. The man command uses less to show manual pages, so the same keys work there.
Imagine a log file with two million lines. cat would pour all of it across your screen in a few seconds, and you would only see the very end. less solves this. It shows one screen, then waits for you. Space goes forward, b goes back, and slash followed by a word searches, which is what you will use most. Press n to jump to the next match and q to quit. The program was written by Mark Nudelman, starting in 1983, because the older pager called more could only move forwards. So less can do more than more, and the joke name stuck. You have already used less without knowing it, because the man command shows manual pages inside it. One more useful key is capital F. It keeps the end of the file on screen and shows new lines as they arrive, which is perfect for watching a server log while you test a web page.

The start and the end: head and tail

Often you only need a few lines. head prints the start of a file and tail prints the end. Both show 10 lines unless you say otherwise.

head -n NExam favourite
first N lines
head -n 3 logs/app.log shows the oldest three log lines.
tail -n NExam favourite
last N lines
tail -n 2 logs/app.log shows the two newest entries.
tail -n +N
from line N to the end
tail -n +2 marks.csv skips the header line of a CSV file.
tail -f
keep watching
Prints new lines as they are added, until you press Ctrl+C.

Common mistake
Logs are often rotated: app.log is renamed to app.log.1 and a new app.log starts. tail -f keeps reading the old renamed file and goes quiet. tail -F follows the name, notices the new file and continues with it.
head and tail are two of the most used commands on any server. head shows the beginning of a file, tail shows the end, and both default to ten lines. The dash n option chooses another number. A trick worth remembering is tail with a plus sign. tail dash n plus two means start at line two and print everything after it, which is the standard way to drop the header row of a spreadsheet file. The most loved option is dash f, for follow. An engineer who is testing a website runs tail dash f on the web server log and watches each visit appear the moment it happens. If something breaks, the error appears right there in the terminal. Use capital F on servers whose logs are rotated each night, because it notices when a fresh log file replaces the old one.

file never trusts the name. It reads the first bytes and compares them with a list of known signatures called magic numbers, for example every PNG image starts with the bytes 89 50 4E 47. stat shows the inode number and three times: Access (last read), Modify (content changed) and Change (details such as permissions changed). The Birth line appears only on file systems that record creation time.

In the normal format, 2c2 means line 2 changed into line 2, and 3a4 means a line was added after line 3. Lines starting with < come from the first file and lines with > from the second. The -u unified format with - and + is what Git and code review tools show.

od shows that a line end is one byte, written \n. Files from Windows often end lines with two bytes, carriage return then newline (\r\n), which is why some scripts break after a file is copied from Windows.
Sometimes you need facts about a file rather than its words. wc counts lines, words and bytes. Engineers use wc dash l all the time, for example to count how many errors happened today or how many users are in a list. The file command answers the question what is this thing. It ignores the name and reads the first few bytes, because most formats begin with a fixed signature, called a magic number. A picture renamed to report dot txt is still reported as a picture. stat prints the details the system keeps about a file, such as owner, size, permissions and times. Finally, diff compares two text files and prints only the lines that changed. The original diff was written for Unix in the early nineteen seventies, and its descendants power every code review today. When you see minus and plus lines in Git, you are looking at diff output.
Lesson 5 of 5

Reading files from school to research

One idea, four depths

cat prints a file, less lets you scroll and search, head shows the start, tail shows the end, wc counts lines and words, and diff shows what changed between two versions.

These tools read files as streams of bytes divided into lines by the newline character. head and tail select by line or byte count, tail -f polls or watches the file for growth, file identifies formats by magic numbers in magic(5), and diff computes a shortest edit script between two line sequences.

cat loops over read() and write() system calls. GNU tail on a seekable file seeks near the end and reads backwards in blocks, so tail -n 5 on a 50 GB log is instant. On Linux tail -f uses inotify to sleep until the file changes. less keeps an index of line positions and reads only the regions it displays. GNU diff uses the O(ND) algorithm published by Eugene Myers in 1986, where D is the number of differences, so similar files are compared quickly.

Research topics include diff algorithms that produce more readable results (patience and histogram diff in Git), structural diffs that compare syntax trees instead of lines, file type identification with machine learning when magic numbers are missing (Google Magika, 2024), and log analysis at scale, where systems such as the ELK stack index billions of lines that tail could never handle alone.

Real world scenario: the 3 a.m. incident

A shopping site starts failing at night. The on-call engineer logs in and runs tail -n 50 /var/log/app/error.log to see the latest errors, then grep -c timeout on the same file to count them, and finally tail -F to watch whether new errors keep coming after a restart. Every command here is in this chapter or the next one.

How does tail show the last five lines of a fifty gigabyte file without reading all fifty gigabytes. GNU tail jumps straight to the end of the file and reads backwards in blocks until it has found enough line endings. That is why it answers instantly. When you follow a file, modern Linux lets tail sleep until the kernel says the file has changed, using a feature called inotify, instead of checking again and again. diff hides clever mathematics too. In 1986 Eugene Myers published an algorithm whose cost depends mostly on how many differences there are, so two nearly identical files are compared very fast. That algorithm still sits inside GNU diff and inside Git. Researchers keep improving the ideas, for example with diffs that understand program structure, and with machine learning models that recognise file types when the usual signatures are missing.
